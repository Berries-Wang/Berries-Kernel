## 编译流程<sup>从资料中总结</sup>

```
 hello.c ──(cpp 预处理)──► hello.i ──(cc1 编译)──► hello.s ──(as 汇编)──► hello.o
             #include/宏展开      词法/语法/语义/优化      指令选择/汇编器        ELF 可重定位
   ┌─────────────────────────────────────────────────────────────────────────┘
   │  + 库例程(.a 静态库 / .so 动态库)
   ▼
 链接器 ld: 符号解析 + 重定位(把多个 .o 缝合成 a.out, 布局由链接脚本指挥)
   │
   ▼  a.out(可执行文件) ── 引用全部解析, 静态部分地址已回填;
                          动态部分(.so 的引用)留待运行期由 ld.so 经 GOT/PLT 解析
   │
   ▼
 装载器(loader)/动态链接器(ld.so): 运行期把可执行文件(及依赖)映射进地址空间, 跳 e_entry
```

| 阶段 | 工具(命令行视角) | 输入 → 输出 | 干什么 | 观察 |
| - | - | - | - | - |
| 预处理 | `cpp`（`clang -E`） | `.c` → `.i` | `#include` 展开、宏替换、条件编译；**纯文本变换** | `clang -E hello.c \| tail` |
| 编译（微观） | `cc1`（`clang -S`） | `.i` → `.s` | 词法→语法→语义→优化→指令选择；**唯一懂 C 的阶段** | `clang -S -O2 hello.c` 看 `.s` |
| 汇编 | `as`（`clang -c`） | `.s` → `.o` | 汇编指令→机器码（**地址未定的引用留 0 + 重定位记录**） | `llvm-objdump -d -r hello.o` |
| 链接 | `ld` | `*.o + *.a/.so` → 可执行 | **符号解析 + 重定位**；布局由链接脚本指挥 | `llvm-nm`，详见 [链接器篇](../../001.UNIX-DOCS/028.编译原理/000.链接器/README.md) |
| 加载 | loader（内核 `execve`） | 可执行 → 进程 | 建 VM、铺栈、PC 置 `e_entry` | 见 [程序是怎么运行的](../../001.UNIX-DOCS/037.内核基础/001.程序是怎么运行的/001.execve与ELF加载：内核侧.md) |

> 一条命令看全四个中间产物：`clang -E x.c -o x.i && clang -S x.i -o x.s && clang -c x.s -o x.o`——平时 `clang x.c` 把这些一步跑完。

### 目标文件格式

```
 ELF(可重定位 .o)按 section 组织(示意图):
 ┌─────────────────────────────────────────────┐
 │ .text   代码(.init 启动代码也在此类)        │ ← 汇编器产出
 │ .rodata 只读数据(字符串常量)                │
 │ .data   已初始化的全局/静态变量             │
 │ .bss    未初始化全局/静态(不占文件,加载清0) │
 ├─────────────────────────────────────────────┤
 │ .symtab/.strtab  符号表+名字                │ ← 链接器消费
 │ .rela.text/.rela.data 重定位记录            │ ← 链接器消费
 │ .debug_* 调试信息 / .comment/.note.* 元信息 │
 └─────────────────────────────────────────────┘
 (.plt/.got 属于动态链接场景,由链接器生成、运行期由 ld.so 填)
```

- 上图六类段的角色: .data<sub>数据段，用于存放已初始化的全局变量和静态变量</sub> 、.init<sub>存储初始化代码，在程序启动时自动执行</sub> 、.text<sub>代码段，用于存放程序可执行指令</sub> , 其他段:.bss<sub>存储未初始化的全局/静态变量（实际不占用磁盘空间，运行时初始化为0）</sub>、.rodata<sub>存储只读数据（如字符串常量）</sub>、.plt/.got<sub>用于动态链接（共享库）</sub>
  （原配图 `wechat_2025-11-11_224437_501.png` 已随 `999.REF_DOCS` 目录清理移除，2026-11 复核时以上图替代）

UNIX 系统中的目标文件通常包含以下六个不同的部分（ELF 把它们做成 section）：
- 目标文件头，描述目标文件其他部分的大小和位置。
- 代码段，包含机器语言代码。
- 静态数据段，包含在程序生命周期内分配的数据 。 (UNIX 系统允许程序使用存在于整个程序中的静态数据，也允许随程序的需要而增长或减少的动态数据 。 见图 2-14。 )
- 重定位信息，标记了一些在程序加载进内存时依赖于绝对地址的指令和数据 。
- 符号表，包含剩余未定义的标签，如外部引用 。
- 调试信息，包含一份简明描述，说明模块如何编译，以便调试器能够将机器指令关联到 C 源文件，并使数据结构也变得可读

六个部分与前四阶段的对应：**汇编器产出一、二、三（+五、六），链接器消费四、五、完成"缝合"，加载器按一、二、三建 VM**——所以六大部分里最值得盯的是四、五两块，它们是"为链接器准备的接口"（[链接器篇 §1](../../001.UNIX-DOCS/028.编译原理/000.链接器/README.md)）。

而链接器的任务，就是将多个目标文件(.o)进行缝合，最终生成计算机上的可执行文件。
