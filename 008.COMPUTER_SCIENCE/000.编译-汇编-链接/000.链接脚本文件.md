# 链接脚本文件
> 例如: arch/arm64/kernel/vmlinux.lds.S  &  学习: [2.6　Linux内核汇编代码分析](../../007.BOOKs/Run%20Linux%20Kernel%20%282nd%20Edition%29%20Volume%201:%20Infrastructure.epub)

## 功能
将目标文件，按照"目标文件格式"，将多个目标文件合并成一个可执行文件。在"编译、汇编、链接过程概述"资料（原 `./999.REF_DOCS/000.编译、汇编、链接过程概述/`，已随目录清理移除）的说法中，链接脚本文件可以指定程序执行起始地址。

更完整地说，链接脚本是**给链接器的排版指令**：段怎么合并、各组从哪开始、入口是谁、哪些段丢弃。链接器的两大任务（符号解析+重定位）里，它管的是重定位的**第 1 步——地址分配**（[链接器篇 §3.1](../../001.UNIX-DOCS/028.编译原理/000.链接器/README.md)）。

## 最小集：四个关键字看懂任何脚本

| 关键字 | 作用 | 用户程序示例 | 内核（vmlinux.lds.S）实例 |
| - | - | - | - |
| `ENTRY(sym)` | 程序入口写入 ELF 头 `e_entry` | `ENTRY(_start)` | `ENTRY(_text)`（lds.S:94） |
| `.`（位置计数器） | "当前地址"，可读可推进 | `. = 0x400000;` | `. = KIMAGE_VADDR;`（lds.S:189） |
| `SECTIONS { ... }` | 输出段定义与归并规则 | `.text : { *(.text) }` | 同左，几十段（lds.S:174 起） |
| `/DISCARD/ : {...}` | 丢弃不要的输入段 | —— | `*(.interp .dynamic)` 等（lds.S:183） |

一个最小用户程序脚本与它排出来的内存：

```
 ENTRY(_start)                  /* e_entry = _start 的最终地址 */
 SECTIONS
 {
   . = 0x400000;                /* 链接基址:从这里开始"铺" */
   .text : { *(.text .text.*) } /* 所有输入的 .text 顺序拼接 */
   . = ALIGN(4096);
   .rodata : { *(.rodata) }
   .data : { *(.data) }
   .bss  : { *(.bss)  *(COMMON) }
 }

 排出来的内存(= 第 1 步地址分配的结果):
 0x400000 ┌──────────────┐
          │ .text (合并) │ ← 各 .o 的 .text 依出现顺序拼接
          ├──────────────┤
 0x...    │ .rodata      │
          ├──────────────┤
          │ .data        │
          ├──────────────┤
          │ .bss (占位)  │ ← 无文件内容,只有大小,加载器清零
          └──────────────┘
 之后链接器第 2 步:按新地址回填所有重定位记录(028/000 §3)
```

## 内核实例：vmlinux.lds.S（7.1.3 实测节选）

内核脚本是同一套语法的放大版——多了段围栏符号（`_text/_etext/_edata/_end`，`System.map` 里都能查到）、`ASSERT` 布局校验和丢弃动态段（内核不用 ELF 加载器）：

```c
// arch/arm64/kernel/vmlinux.lds.S:93
OUTPUT_ARCH(aarch64)
ENTRY(_text)                        // 入口=映像头(head.S _head),不是 C 函数

// arch/arm64/kernel/vmlinux.lds.S:174
SECTIONS
{
	/DISCARD/ : {                   // :183 内核不需要动态链接的段
		*(.interp .dynamic)
		*(.dynsym .dynstr .hash .gnu.hash)
	}

	. = KIMAGE_VADDR;               // :189 链接基址(KIMAGE_VADDR 的定义
	                                //     见 asm/memory.h 第 46 行)
	.head.text : {
		_text = .;                  // :192 围栏符号:由链接器"合成",
		HEAD_TEXT                   //        不来自任何 .o
	}
	.text : ALIGN(SEGMENT_ALIGN) {	/* Real text segment		*/
		_stext = .;		/* Text and read-only data	*/
		IRQENTRY_TEXT
		SOFTIRQENTRY_TEXT
		ENTRY_TEXT
		TEXT_TEXT
		SCHED_TEXT
		LOCK_TEXT
		KPROBES_TEXT
		HYPERVISOR_TEXT
		STATIC_CALL_TEXT
		*(.gnu.warning)
	}

	. = ALIGN(SEGMENT_ALIGN);
	_etext = .;			/* End of text section */
	...
```

逐段深潜（围栏符号怎么用、`__init_begin` 围栏与 initcall 表、`ASSERT` 都校验什么）见 [028.编译原理/002.链接脚本走读：vmlinux.lds.S](../../001.UNIX-DOCS/028.编译原理/002.链接脚本走读：vmlinux.lds.S.md)。

## 与链接器两任务的对应

| 链接脚本控制的事 | 不控制的事 |
| - | - |
| 入口地址（`e_entry`） | 符号解析规则（强弱选择，见 [链接器篇 §2](../../001.UNIX-DOCS/028.编译原理/000.链接器/README.md)） |
| 每个输出段的位置与对齐 | 重定位公式本身（`S+A` 由重定位类型决定） |
| 输入段→输出段的归并 | 库成员的按需拉取顺序（命令行决定） |
| 丢弃/保留哪些段 | —— |
