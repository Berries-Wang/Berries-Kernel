# ADRP
> 阅读:[ADRP](https://developer.arm.com/documentation/ddi0602/2025-09/Base-Instructions/ADRP--Form-PC-relative-address-to-4KB-page-) 或 [ADRP:pdf](../../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/) & [000.微指令-SignExtend.md](./000.微指令-SignExtend.md)

## 0. 一句话总结

**`ADRP Xd, label` = 把 `label` 所在 4KB 页的"页基址"装进 `Xd`**——页基址 = `PC` 清掉低 12 位后加上一个 21 位有符号立即数（单位是**页**，所以叫 "Form PC-relative address to 4KB **Page**"）。页内偏移留给下一条指令（`ADD :lo12:` / `LDR` offset）补齐。

## 1. 它解决什么问题：64 位地址装不进一条指令

A64 定长 32 位（见 [机器指令编码&解码](../001.机器指令编码&解码/README.md)），一条指令要塞下 opcode + 寄存器号 + 立即数，**不可能再塞 64 位绝对地址**。三条路对比：

| 方案 | 指令数 | 依赖 | 典型场景 |
| - | - | - | - |
| `MOVZ/MOVK` 序列（`MOVL` 宏展开 3~4 条） | 3~4 | **绝对地址已知**（链接/加载后） | 已重定位的代码装常数 |
| `LDR Xd, =imm`（literal pool） | 1+一次访存 | pool 与指令 ≤±1MB | 任意常数 |
| **`ADRP+ADD` 对** | 2 | 目标在 **PC±4GB** 内 | 访问本模块的数据（内核/Glibc 的默认选择） |

PC 相对分页的好处：**链接器只需回填 21 位页差**（重定位类型 `R_AARCH64_ADR_PREL_PG_HI21`，见 [028.编译原理/000.链接器 §4](../../../001.UNIX-DOCS/028.编译原理/000.链接器/README.md) 的实测），KASLR/ASLR 整体搬移代码也不破坏 adrp 的正确性——搬移时 PC 和目标一起搬，差值不变。

## 2. 编码格式

```
  31   30 29  28     24 23                5   4   0
┌────┬───────┬─────────┬─────────────────────┬──────┐
│ op │ immlo │ 1 0 0 0 0 │       immhi         │  Rd  │
└────┴───────┴─────────┴─────────────────────┴──────┘
  op=1: ADRP(页粒度)   immlo = imm21<1:0>       immhi = imm21<20:2>
  op=0: ADR (字节粒度, offset imm21 直接 PC 相对, 不清页)
```

立即数一共 21 位（immhi 19 + immlo 2），**单位是 4KB 页**，有符号 → 寻址范围 `PC ± 4GB`（2^20 页 × 4KB = 4GB，双向）。

## 3. 官方伪代码走读（配合 [SignExtend](./000.微指令-SignExtend.md)）

```txt
constant integer d    = UInt(Rd);
constant bits(64) imm = SignExtend(immhi:immlo:Zeros(12), 64);   // ① 拼接+符号扩展
constant bits(64) base = PC<63:12> : Zeros(12);                  // ② PC 清页内偏移
X[d, 64] = base + imm;                                           // ③ 相加, 结果是页基址
```

| 步 | 干什么 | 易错点 |
| - | - | - |
| ① | `immhi:immlo` 是 21 位拼接，再**左拼 12 个 0 变 33 位**，再符号扩展到 64 位 | **imm 的单位是页不是字节**：编码里的 21 位是 `字节差 >> 12` |
| ② | 取 PC 的高 52 位（清低 12 位） | `PC` 是**本指令自己的地址**，不是下一条 |
| ③ | 页基址必然 4KB 对齐 | 想要完整地址必须再 `ADD Rd, Rd, :lo12:label` |

## 4. 实测：从占位到回填（两段真实输出）

### 4.1 可重定位 `.o` 里：立即数是 0，账记在重定位表上

```shell
$ clang -target aarch64-linux-gnu -c 018.adrp_encoding.S -o adrp.o   # 实验源码见
$ llvm-objdump -d -r adrp.o                        # 003.TEST-SPACE/018.adrp_encoding.S
0000000000000000 <_start>:
       0: 90000000      adrp x0, 0x0 <_start>      ← imm21=0 占位!
                0000000000000000:  R_AARCH64_ADR_PREL_PG_HI21  .text+0x3008
       4: 91000000      add  x0, x0, #0x0          ← 同样占位(add 低12位)
                0000000000000004:  R_AARCH64_ADD_ABS_LO12_NC  .text+0x3008
                ...
```

汇编器不知道链接后 `target` 落在哪页，只能发占位编码 `0x90000000` + 一条重定位记录（`target` 是局部符号，重定位里显示为 `节名+0x3008`）（这正是 [链接器 §4](../../../001.UNIX-DOCS/028.编译原理/000.链接器/README.md) 里那张"账本"的又一笔）。

### 4.2 链接后形态（手工算 + `.inst` 反向验证）

实验里 `_start`=0、`target`=0x3008：页差 = `(0x3008 & ~0xFFF) - (0 & ~0xFFF)` = `0x3000`，故 `imm21 = 0x3000 >> 12 = 3` → `immlo = 3 & 3 = 3`（bits30:29=11）、`immhi = 3 >> 2 = 0`：

```
 0xF0000000 = 1    11     10000     0000000000000000000     00000
              op │ immlo │固定码 │         immhi        │   Rd=x0
```

用 `.inst`（"按原始编码发射一条指令"的伪指令）反向验证，objdump 解回我们的预期：

```shell
$ printf '\t.inst 0xF0000000\n' | clang -target aarch64-linux-gnu -c -x assembler - -o v.o
$ llvm-objdump -d v.o
       0: f0000000      adrp x0, 0x3000        ✓ (PC=0, imm21=3 → 0+0x3000)
```

> 坑（本人实测踩过）：`imm21` 是 **immhi:immlo 拼接**，不是 immhi 本身——若想编码 imm21=3 却把 3 塞进 immhi（`0x90000060`），解码出来是 `adrp x0, 0xc000`（imm21=12）。先 `imm21 = 字节差>>12`，再 `immlo=imm21&3, immhi=imm21>>2`。

## 5. `adrp + add/:lo12:` 与 `:got:` 修饰

```asm
	adrp	x0, symbol          // 页基址
	add	x0, x0, :lo12:symbol // 补低12位 → 完整地址 (:lo12: = symbol&0xFFF)
	// 若 symbol 在别的模块/PIE 下不可直取, 走 GOT:
	adrp	x0, :got:symbol         // 取"GOT 表项所在页"
	ldr	x0, [x0, #:got_lo12:symbol]  // 表项里才是真地址
```

真实用例——glibc `_start` 取 `main`（[sysdeps/aarch64/start.S:81](../../../000.SOURCE_CODE/002.GLIBC/000.GLIBC-2.40/sysdeps/aarch64/start.S)）：

```asm
	adrp	x0, :got:main
	ldr	x0, [x0, #:got_lo12:main]
```

对应重定位 `R_AARCH64_ADR_GOT_PAGE` + `R_AARCH64_LD64_GOT_LO12_NC`（[链接器 §4](../../../001.UNIX-DOCS/028.编译原理/000.链接器/README.md) 默认 PIC 编译的实测输出），是 [037.程序是怎么运行的/002](../../../001.UNIX-DOCS/037.内核基础/001.程序是怎么运行的/002.从_start到main：用户态的接力.md) §2 的第一行代码。

## 6. 内核真实用例（7.1.3 实测）

```asm
// arch/arm64/kernel/head.S:374
	adrp	x1, swapper_pg_dir      // 内核页表基址——MMU 语境的"一切起点"
// arch/arm64/kernel/head.S:521
	adrp	x0, KERNEL_START        // 源码原注释即 __pa(KERNEL_START)——
	                                // adrp 取符号 VA, 后续配 __pa 算物理基址
```

启动代码偏爱 ADRP 的原因：**在重定位完成/KASLR 定案之前，"PC 相对"是唯一永远正确的参照系**——head.S 里所有页表/全局量取址几乎全是 adrp 家族（`head.S:89/92/104/114/233/291/374/375/509/510/513/521`，可自行 `grep -n adrp` 对照）。

## 7. 常见坑清单

| 坑 | 说明 |
| - | - |
| imm 单位是页 | 21 位指的是 `字节差>>12`，不是字节 |
| 结果只到页基址 | 不补 `:lo12:` 就用，等于把 symbol 当成页对齐的 |
| ±4GB 超限 | 内核模块距核心符号 >2GB 时要 `-mcmodel=large`/movk 序列（内核构建见 [028/001](../../../001.UNIX-DOCS/028.编译原理/001.从C到Image：内核构建流水线.md) 的 `-fno-PIE` 与模块段位置） |
| `adrp` 不是 `adr` | `adr`（op=0）是字节粒度、±1MB，两者固定码相同但语义不同 |
| 符号扩展 | imm21 最高位是符号位，负偏移（向下找页）完全合法 |
