# 编译内核
基于[000.使用BusyBox制作最小文件系统](./000.使用BusyBox制作最小文件系统.md) , 开始编译内核

## 开始编译内核(32)<sub>内涵arm64操作逻辑</sub>
0. 将 [000.使用BusyBox制作最小文件系统](./000.使用BusyBox制作最小文件系统.md) 生成的_install 目录复制到内核文件的根目录下

1. 编译内核
   ```txt
    #1. 需要在内核文件目录
    wei@Berries-Wang:~/OPEN_SOURCE/Berries-Kernel/000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9$ export ARCH=arm  # arm64: export ARCH=arm64 
    wei@Berries-Wang:~/OPEN_SOURCE/Berries-Kernel/000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9$ export CROSS_COMPILE=arm-linux-gnueabi-  # arm64: export CROSS_COMPILE=aarch64-linux-gnu-
    wei@Berries-Wang:~/OPEN_SOURCE/Berries-Kernel/000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9$ make vexpress_defconfig # arm64 替换为 make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- defconfig
    wei@Berries-Wang:~/OPEN_SOURCE/Berries-Kernel/000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9$ make menuconfig // 执行之后，可以使用git diff对比一下，看看那些配置修改了 # arm64: make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-  menuconfig -j4
   ```

4. 编译内核

      wei@Berries-Wang:~/OPEN_SOURCE/Berries-Kernel/000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9$ make bzImage ARCH=arm CROSS_COMPILE=arm-linux-gnueabi-  # arm64: make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j4

5. 运行 QEMU 来模拟 4 核 Cortex-A9 的 Versatile Express 开发平台。
   ```txt
      # 显式指定设备树文件（32 位 ARM，vexpress-a9 开发板）
      sudo qemu-system-arm -M vexpress-a9 -smp 4 -m 1024M -kernel arch/arm/boot/zImage -append "rdinit=/linuxrc console=ttyAMA0 loglevel=8" -dtb arch/arm/boot/dts/vexpress-v2p-ca9.dtb -nographic

      # 查询支持的CPU类型
      # wei@Berries-Wang:~$ qemu-system-aarch64 -M virt -cpu help

      # arm64 启动命令
      sudo qemu-system-aarch64 -M virt -cpu cortex-a57 -smp 4 -m 1024M -kernel arch/arm64/boot/Image -append "rdinit=/linuxrc console=ttyAMA0 loglevel=8"  -nographic
   ```

   > **关于 arm64 的设备树**
   > 1. `vexpress-v2p-ca9.dts` 属于 32 位的 vexpress-a9 机器，只在第一条命令里用到（编译产物是 `arch/arm/boot/dts/vexpress-v2p-ca9.dtb`）。
   > 2. arm64 的 `virt` 机器由 QEMU 在启动时自动生成一份设备树：QEMU 会根据 `-cpu cortex-a57`、`-smp 4`、`-m 1024M` 动态构造好内存、GIC、PL011 串口、virtio 设备等节点，直接把指针放进 x0 寄存器传给内核。所以你既不需要 build 这个 dtb，也不能把 vexpress 的 dtb 硬塞给它（型号都对不上）。
   > 3. 设备树 = 给内核看的硬件描述书；上面这本写的是 vexpress-a9 板子，而 arm64 命令用的是 QEMU 现写的一本新书。

   **arm64 启动命令参数**

   | 参数 | 含义 |
   | --- | --- |
   | `-M virt` | 指定模拟的机器类型为 virt，这是 QEMU 为 ARM 系统提供的一种通用虚拟化平台。 |
   | `-cpu cortex-a57` | 指定模拟的 CPU 型号为 cortex-a57，这是 ARM 的 ARMv8-A（64 位 AArch64）架构处理器。 |
   | `-smp 4` | smp 指对称多处理器（Symmetric Multi-Processing），4 表示模拟 4 个 CPU 核心（对应内核启动日志中的 4 个 CPU）。 |
   | `-m 1024M` | 指定虚拟机内存大小为 1024MB（1GB），QEMU 会据此在自动生成的设备树中构造 memory 节点。 |
   | `-kernel arch/arm64/boot/Image` | 指定要加载的内核镜像路径。这里是 ARM64 编译产物 arch/arm64/boot/Image（未压缩、可直接被 QEMU 加载的内核镜像）。 |
   | `-append "rdinit=/linuxrc console=ttyAMA0 loglevel=8"` | 向内核追加启动参数（bootargs），相当于把字符串传给内核的命令行 cmdline。 |
   | `rdinit=/linuxrc` | 内核挂载根文件系统后，直接运行 /linuxrc 作为第一个用户空间进程（跳过 /sbin/init）。这里的 initramfs 由 busybox 构建，/linuxrc 就是 busybox 的程序入口。 |
   | `console=ttyAMA0` | 指定控制台为串口 ttyAMA0（PL011 串口），内核把启动日志打印到这里，配合 QEMU 的 -nographic 才能在终端看到输出。 |
   | `loglevel=8` | 设置内核 printk 日志级别为 8，即打印所有级别的内核日志，方便调试。 |
   | `-nographic` | 禁用图形界面（不弹出 QEMU 窗口），把虚拟机的串口控制台直接重定向到当前终端。 |

   **QEMU 导出 virt 机器自动生成的设备树**

   先用 QEMU 把 virt 机器自动生成的 DTB 导出，再用 dtc 反编译成可读文本（`-cpu/-smp/-m/-kernel/-nographic` 与上表相同，不再重复）：

   ```txt
      sudo qemu-system-aarch64 -M virt,dumpdtb=/tmp/virt.dtb -cpu cortex-a57 -smp 4 -m 1024M -kernel arch/arm64/boot/Image -nographic
      dtc -I dtb -O dts /tmp/virt.dtb -o /tmp/virt.dts
   ```

   | 参数 | 含义 |
   | --- | --- |
   | `-M virt` | 指定模拟的机器类型为 virt，这是 QEMU 为 ARM 系统提供的一种通用虚拟化平台。 |
   | `dumpdtb=/tmp/virt.dtb` | 在启动时，将当前机器生成的设备树二进制文件（DTB）导出并保存到宿主机的 /tmp/virt.dtb 路径下。 |
   | `dtc` | Device Tree Compiler，设备树编译器，把二进制的 .dtb 反编译成可读的 .dts 文本。 |
   | `-I dtb` | -I 指定输入文件格式（Input）为 dtb（二进制设备树 blob）。 |
   | `-O dts` | -O 指定输出文件格式（Output）为 dts（设备树源文本）。 |
   | `/tmp/virt.dtb` | 位置参数，输入文件，即 QEMU 刚才导出的设备树二进制。 |
   | `-o /tmp/virt.dts` | -o 指定输出文件路径，把反编译结果保存为 /tmp/virt.dts。 |
