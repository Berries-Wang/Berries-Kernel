# QEMU 调试 ARM Linux 内核-内存管理(memblock / node / zone / zonelist)

> 承接 [002.QEMU调试ARM-Linux内核.md](./002.QEMU调试ARM-Linux内核.md),专注于跟踪内核启动时**内存管理数据结构**是如何一步步构建出来的:
>
> ```
> memblock(原始内存清单)
>   → node_data[](NUMA 节点)[arch/arm64/include/asm/mmzone.h]
>   → node_zones[](zone: DMA/DMA32/NORMAL/...)
>   → node_zonelists[](取页优先级表)
> ```

## 环境准备

- 宿主机:x86_64 Linux(构建机,已配好交叉工具链)
- 交叉工具链:`arm-gnu-toolchain-14.3.rel1`(**自带 `aarch64-none-linux-gnu-gdb`**)
- QEMU:`sudo apt install qemu-system-arm`(提供 `qemu-system-aarch64`)
- **不需要 rootfs**:内存初始化在挂载根文件系统**之前**就全部完成,裸内核 `-nographic` 就能调试到;最后会因 "VFS: Unable to mount root fs" panic,不影响本方案

## 一、内核配置(debug 必需)

在 `defconfig` 基础上:

```shell
make ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu- defconfig
make ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu- menuconfig   # 勾选下面几项
# Kernel hacking → Compile-time checks → [*] Compile the kernel with debug info   (CONFIG_DEBUG_INFO=y)
# Kernel hacking → [*] Kernel debugging                                          (CONFIG_DEBUG_KERNEL=y)
# Kernel hacking > Compile-time checks and compiler options → [*] Provide GDB scripts for kernel debugging (CONFIG_GDB_SCRIPTS=y)
# Kernel Features  → [ ] Randomize the address of the kernel image (KASLR)  ← 取消勾选 (CONFIG_RANDOMIZE_BASE=n)
make ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu- -j8
```

- `CONFIG_NUMA=y`、`CONFIG_ZONE_DMA=y`(固定 1G DMA zone)、`CONFIG_ZONE_DMA32=y` 在 arm64 defconfig 里**默认已开**,不用手动加
- 两个产物:`vmlinux`(带符号,给 gdb)、`arch/arm64/boot/Image`(给 qemu)

## 二、QEMU 启动配置:单核 + 2×4G 双内存条

```bash
qemu-system-aarch64 \
  -machine virt \
  -cpu cortex-a72 \
  -smp 1,sockets=1,cores=1,threads=1 \
  -m 8G \
  -object memory-backend-ram,size=4G,id=mem0 \
  -object memory-backend-ram,size=4G,id=mem1 \
  -numa node,nodeid=0,memdev=mem0,cpus=0 \
  -numa node,nodeid=1,memdev=mem1 \
  -append "numa=off" \
  -nographic -s -S \
  -kernel arch/arm64/boot/Image
```

### 为什么这样写

- **单核 = 一个内存控制器 = 一个 NUMA 节点**;两根 4G 条子挂在同一个内存控制器上
- QEMU 里**一个 NUMA 节点只能挂一个 memdev**,所以要造出两段独立内存,必须在 QEMU 层面声明两个节点
- `-append "numa=off"`(`arch/arm64/mm/numa.c:37`):让 `arm64_numa_init()` 直接跳过、不建立 node1 → 内核把两段内存都归 node 0,正好是"单核 + 双条"的真实模型
- 若去掉 `numa=off`,就变成"两个内存控制器"(双路)的模型,node1 成为纯内存节点

### 内核看到的布局

| 项 | 值 |
|---|---|
| CPU | 1 个(在 node0) |
| `nr_node_ids` | **1**(单节点) |
| `memblock.memory.cnt` | **2**(两根条子 = 两段区间) |
| zone | 见下表:8G 跨过 4G 边界,三个普通 zone 并存 |

arm64 5.9 的 zone 边界由 `zone_sizes_init`(init.c:195)设定:

| zone | 边界 | 本配置大小(≈,取决于 QEMU 地址布局) |
|---|---|---|
| ZONE_DMA | 固定 1G(`ARM64_ZONE_DMA_BITS=30`,对齐到 DRAM 起点) | ≈1G |
| ZONE_DMA32 | 4G 以下剩余 | ≈2G |
| ZONE_NORMAL | 4G 以上 | ≈5G |

**zonelist 顺序**:`build_zonerefs_node`(page_alloc.c:5977)从**高 zone 往低 zone** 遍历 → `[ZONE_NORMAL, ZONE_DMA32, ZONE_DMA]`。这正体现了那句经典注释——"**优先用普通内存,耗尽 Normal 之前不轻易动用珍贵的 DMA 内存**"。单节点下没有跨节点回退,zonelist 只包含本地 zone。

## 三、GDB 调试

```bash
aarch64-none-linux-gnu-gdb vmlinux     # 用工具链自带的 gdb
```

```gdb
(gdb) target remote :1234
(gdb) hb start_kernel                  # 早期用硬件断点 hb 更稳
(gdb) c
```

### 断点清单(按内存结构构建顺序)

```gdb
# 1) memblock 阶段
hb arm64_memblock_init                 # init.c:294
hb memblock_cap_memory_range           # memblock.c:1761

# 2) node 划分(arm64 特有;加了 numa=off 会在这里提前返回)
hb arm64_numa_init                     # init.c:486,解析 DT 的 numa-node-id

# 3) zone 阶段
hb zone_sizes_init                     # init.c:195,由 memblock 反推每个 zone 的边界
hb free_area_init                      # page_alloc.c:7792,入口
hb find_zone_movable_pfns_for_nodes    # ZONE_MOVABLE 计算
hb free_area_init_node                 # page_alloc.c:7328,每个 node 进来一次
hb free_area_init_core                 # page_alloc.c:7201,真正逐字段填充 struct zone

# 4) zonelist 阶段
hb build_all_zonelists                 # init/main.c:879
hb build_zonelists                     # page_alloc.c:6150,节点排序
hb build_zonelists_in_node_order       # page_alloc.c:6090
hb build_zonerefs_node                 # page_alloc.c:5971,单个 node 内按 zone 排优先级
```

### 常用观察命令

```gdb
(gdb) ptype struct pglist_data          # node 结构体定义
(gdb) ptype struct zone
(gdb) ptype struct zonelist
(gdb) ptype struct zoneref

(gdb) p nr_node_ids                     # 1,单节点
(gdb) p *node_data[0]                   # ⚠ arm64 的 node_data 是指针数组,必须解引用
(gdb) p node_data[0]->node_id

# zone 大小(spanned_pages = 覆盖的页数)
(gdb) p node_data[0]->node_zones[ZONE_DMA].spanned_pages     # ≈1G
(gdb) p node_data[0]->node_zones[ZONE_DMA32].spanned_pages   # ≈2G
(gdb) p node_data[0]->node_zones[ZONE_NORMAL].spanned_pages  # ≈5G

# zonelist:单节点下 [NORMAL, DMA32, DMA],高 zone 优先
(gdb) p node_data[0]->node_zonelists[0]._zonerefs
(gdb) p node_data[0]->node_zonelists[0]._zonerefs[0]   # 最高优先级 = ZONE_NORMAL

# memblock:两根条子 = 两段区间
(gdb) p memblock.memory.cnt               # 2
(gdb) p memblock.memory.regions[0]        # 第一根 4G
(gdb) p memblock.memory.regions[1]        # 第二根 4G
```

## 四、内存结构构建流程(5.9 实际调用链)

```
start_kernel()                              init/main.c
└─ setup_arch(&command_line)                init/main.c:867
   ├─ arm64_memblock_init()                 init.c:294        ← memblock 原始清单
   └─ bootmem_init()                        setup.c:366
      ├─ arm64_numa_init()                  init.c:486        ← numa=off 时在此返回(单节点)
      └─ zone_sizes_init(min, max)          init.c:502        ← 由 memblock 算出各 zone 边界
         └─ free_area_init(max_zone_pfns)   page_alloc.c:7792
            ├─ find_zone_movable_pfns_for_nodes()
            └─ free_area_init_node(nid)     page_alloc.c:7328
               └─ free_area_init_core()     page_alloc.c:7201 ← 填充 node_zones[ZONE_x]
                                                                  (free_area 伙伴链表 / watermark / per_cpu_pageset)
└─ build_all_zonelists(NULL)                init/main.c:879
   └─ build_zonelists(pgdat)                page_alloc.c:6150
      ├─ find_next_best_node()              (node 排序)
      └─ build_zonelists_in_node_order()    page_alloc.c:6090
         └─ build_zonerefs_node()           page_alloc.c:5971 ← 填充 node_zonelists[]._zonerefs
```

一句话记忆:**memblock 是"原料清单" → zone_sizes_init 划出 zone 边界 → free_area_init_core 填满 zone 骨架 → build_zonelists 排好取页优先级(高 zone 优先)。**

## 五、常见坑速查

| 现象 | 原因 / 解法 |
|---|---|
| 断点打了不停 | KASLR 没关(`CONFIG_RANDOMIZE_BASE=n`),或 `CONFIG_RELOCATABLE` 需加 `nokaslr` |
| `p node_data[0]` 看着不对 | arm64 的 `node_data` 是**指针数组**,要用 `node_data[0]->xxx` |
| QEMU 报 `total memory mismatch` | `-m` 必须等于各 `memory-backend-ram` 之和 |
| 看到 2 个 node、node1 是纯内存 | 忘了加 `-append "numa=off"`;那对应"双内存控制器"模型 |
| dmesg 只有 1 段内存 | QEMU 太老不支持 virt 的 NUMA/memdev;升级 QEMU(建议 6.0+) |
