==============================
LSM BPF Programs(LSM BPF 程序)
==============================

These BPF programs allow runtime instrumentation of the LSM hooks by privileged
users to implement system-wide MAC (Mandatory Access Control) and Audit
policies using eBPF.
(这些 BPF 程序允许特权用户对 LSM 钩子进行运行时插桩，以使用 eBPF 实现
系统级的 MAC（强制访问控制）和审计策略。)

Structure(结构)
---------------

The example shows an eBPF program that can be attached to the ``file_mprotect``
LSM hook:
(示例展示了一个可以挂接到 ``file_mprotect`` LSM 钩子的 eBPF 程序：)

.. c:function:: int file_mprotect(struct vm_area_struct *vma, unsigned long reqprot, unsigned long prot);

Other LSM hooks which can be instrumented can be found in
``security/security.c``.
(其他可以插桩的 LSM 钩子可以在 ``security/security.c`` 中找到。)

eBPF programs that use Documentation/bpf/btf.rst do not need to include kernel
headers for accessing information from the attached eBPF program's context.
They can simply declare the structures in the eBPF program and only specify
the fields that need to be accessed.
(使用 Documentation/bpf/btf.rst 的 eBPF 程序不需要包含内核头文件就能访问
所挂接 eBPF 程序上下文中的信息。它们可以简单地在 eBPF 程序中声明结构体，
只指定需要访问的字段。)

.. code-block:: c

	struct mm_struct {
		unsigned long start_brk, brk, start_stack;
	} __attribute__((preserve_access_index));

	struct vm_area_struct {
		unsigned long start_brk, brk, start_stack;
		unsigned long vm_start, vm_end;
		struct mm_struct *vm_mm;
	} __attribute__((preserve_access_index));


.. note:: The order of the fields is irrelevant.
	  (注意：字段的顺序无关紧要。)

This can be further simplified (if one has access to the BTF information at
build time) by generating the ``vmlinux.h`` with:
(如果能在构建时访问 BTF 信息，这还可以进一步简化：用以下命令生成
``vmlinux.h``：)

.. code-block:: console

	# bpftool btf dump file <path-to-btf-vmlinux> format c > vmlinux.h

.. note:: ``path-to-btf-vmlinux`` can be ``/sys/kernel/btf/vmlinux`` if the
	  build environment matches the environment the BPF programs are
	  deployed in.
	  (注意：如果构建环境与部署 BPF 程序的环境一致，
	  ``path-to-btf-vmlinux`` 可以是 ``/sys/kernel/btf/vmlinux``。)

The ``vmlinux.h`` can then simply be included in the BPF programs without
requiring the definition of the types.
(然后，``vmlinux.h`` 就可以简单地包含在 BPF 程序中，而无需再定义那些
类型。)

The eBPF programs can be declared using the``BPF_PROG``
macros defined in `tools/lib/bpf/bpf_tracing.h`_. In this
example:
(eBPF 程序可以用 `tools/lib/bpf/bpf_tracing.h`_ 中定义的 ``BPF_PROG``
宏来声明。在本示例中：)

	* ``"lsm/file_mprotect"`` indicates the LSM hook that the program must
	  be attached to
	  (``"lsm/file_mprotect"`` 表示程序必须挂接到的 LSM 钩子)
	* ``mprotect_audit`` is the name of the eBPF program
	  (``mprotect_audit`` 是 eBPF 程序的名称)

.. code-block:: c

	SEC("lsm/file_mprotect")
	int BPF_PROG(mprotect_audit, struct vm_area_struct *vma,
		     unsigned long reqprot, unsigned long prot, int ret)
	{
		/* ret is the return value from the previous BPF program
		 * or 0 if it's the first hook.
		 */
		if (ret != 0)
			return ret;

		int is_heap;

		is_heap = (vma->vm_start >= vma->vm_mm->start_brk &&
			   vma->vm_end <= vma->vm_mm->brk);

		/* Return an -EPERM or write information to the perf events buffer
		 * for auditing
		 */
		if (is_heap)
			return -EPERM;
	}

The ``__attribute__((preserve_access_index))`` is a clang feature that allows
the BPF verifier to update the offsets for the access at runtime using the
Documentation/bpf/btf.rst information. Since the BPF verifier is aware of the
types, it also validates all the accesses made to the various types in the
eBPF program.
(``__attribute__((preserve_access_index))`` 是一个 clang 特性，它允许 BPF
验证器在运行时使用 Documentation/bpf/btf.rst 信息更新访问的偏移量。由于
BPF 验证器了解这些类型，它还会验证 eBPF 程序中对各个类型的所有访问。)

Loading(加载)
-------------

eBPF programs can be loaded with the :manpage:`bpf(2)` syscall's
``BPF_PROG_LOAD`` operation:
(eBPF 程序可以用 :manpage:`bpf(2)` 系统调用的 ``BPF_PROG_LOAD`` 操作
加载：)

.. code-block:: c

	struct bpf_object *obj;

	obj = bpf_object__open("./my_prog.o");
	bpf_object__load(obj);

This can be simplified by using a skeleton header generated by ``bpftool``:
(可以通过使用 ``bpftool`` 生成的骨架头文件来简化这一过程：)

.. code-block:: console

	# bpftool gen skeleton my_prog.o > my_prog.skel.h

and the program can be loaded by including ``my_prog.skel.h`` and using
the generated helper, ``my_prog__open_and_load``.
(然后通过包含 ``my_prog.skel.h`` 并使用生成的 helper
``my_prog__open_and_load`` 来加载程序。)

Attachment to LSM Hooks(挂接到 LSM 钩子)
----------------------------------------

The LSM allows attachment of eBPF programs as LSM hooks using :manpage:`bpf(2)`
syscall's ``BPF_RAW_TRACEPOINT_OPEN`` operation or more simply by
using the libbpf helper ``bpf_program__attach_lsm``.
(LSM 允许使用 :manpage:`bpf(2)` 系统调用的 ``BPF_RAW_TRACEPOINT_OPEN``
操作把 eBPF 程序作为 LSM 钩子挂接；更简单的方式是使用 libbpf helper
``bpf_program__attach_lsm``。)

The program can be detached from the LSM hook by *destroying* the ``link``
link returned by ``bpf_program__attach_lsm`` using ``bpf_link__destroy``.
(可以使用 ``bpf_link__destroy`` 销毁 (destroy) ``bpf_program__attach_lsm``
返回的 ``link`` 链接，从而把程序从 LSM 钩子上分离。)

One can also use the helpers generated in ``my_prog.skel.h`` i.e.
``my_prog__attach`` for attachment and ``my_prog__destroy`` for cleaning up.
(也可以使用 ``my_prog.skel.h`` 中生成的 helper，即用 ``my_prog__attach``
进行挂接，用 ``my_prog__destroy`` 进行清理。)
