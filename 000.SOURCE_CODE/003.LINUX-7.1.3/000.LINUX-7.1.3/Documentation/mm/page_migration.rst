========================
Page migration(页面迁移)
========================

Page migration allows moving the physical location of pages between
nodes in a NUMA system while the process is running. This means that the
virtual addresses that the process sees do not change. However, the
system rearranges the physical location of those pages.
(页面迁移允许在进程运行时把页在 NUMA 系统的各节点之间移动其物理位置。这意味着进程看到的虚拟地址不会改变，但系统会重新安排这些页的物理位置。)

Also see Documentation/mm/hmm.rst for migrating pages to or from device
private memory.
(关于在设备私有内存之间迁入/迁出页的内容，另见 Documentation/mm/hmm.rst。)

The main intent of page migration is to reduce the latency of memory accesses
by moving pages near to the processor where the process accessing that memory
is running.
(页面迁移的主要目的是把页移动到访问该内存的进程所在处理器附近，从而降低内存访问的延迟。)

Page migration allows a process to manually relocate the node on which its
pages are located through the MF_MOVE and MF_MOVE_ALL options while setting
a new memory policy via mbind(). The pages of a process can also be relocated
from another process using the sys_migrate_pages() function call. The
migrate_pages() function call takes two sets of nodes and moves pages of a
process that are located on the from nodes to the destination nodes.
Page migration functions are provided by the numactl package by Andi Kleen
(a version later than 0.9.3 is required. Get it from
https://github.com/numactl/numactl.git). numactl provides libnuma
which provides an interface similar to other NUMA functionality for page
migration.  cat ``/proc/<pid>/numa_maps`` allows an easy review of where the
pages of a process are located. See also the numa_maps documentation in the
proc(5) man page.
(页面迁移允许进程在通过 mbind() 设置新内存策略时，借助 MF_MOVE 与 MF_MOVE_ALL 选项手动重定位其页所在的节点。进程的页也可以由另一个进程通过 sys_migrate_pages() 函数调用来重定位。migrate_pages() 函数调用接受两组节点，并把位于源节点上的进程页移动到目标节点。页面迁移功能由 Andi Kleen 的 numactl 软件包提供(需要 0.9.3 之后的版本，可从 https://github.com/numactl/numactl.git 获取)。numactl 提供了 libnuma，为页面迁移提供与其他 NUMA 功能类似的接口。cat ``/proc/<pid>/numa_maps`` 可以方便地查看进程的页位于何处。另请参阅 proc(5) 手册页中的 numa_maps 文档。)

Manual migration is useful if for example the scheduler has relocated
a process to a processor on a distant node. A batch scheduler or an
administrator may detect the situation and move the pages of the process
nearer to the new processor. The kernel itself only provides
manual page migration support. Automatic page migration may be implemented
through user space processes that move pages. A special function call
"move_pages" allows the moving of individual pages within a process.
For example, A NUMA profiler may obtain a log showing frequent off-node
accesses and may use the result to move pages to more advantageous
locations.
(例如，当调度器把一个进程重定位到远端节点上的处理器时，手动迁移就很有用。批处理调度器或管理员可以检测到这种情况，并把进程的页移动到离新处理器更近的位置。内核本身只提供手动页面迁移支持。自动页面迁移可以通过移动页的用户空间进程来实现。一个特殊的函数调用 "move_pages" 允许在进程内移动单独的页。例如，NUMA 分析器可以获得一份显示频繁跨节点访问的日志，并利用结果把页移动到更有利的位置。)

Larger installations usually partition the system using cpusets into
sections of nodes. Paul Jackson has equipped cpusets with the ability to
move pages when a task is moved to another cpuset (See
:ref:`CPUSETS <cpusets>`).
Cpusets allow the automation of process locality. If a task is moved to
a new cpuset then also all its pages are moved with it so that the
performance of the process does not sink dramatically. Also the pages
of processes in a cpuset are moved if the allowed memory nodes of a
cpuset are changed.
(较大规模的部署通常使用 cpuset 把系统划分为若干节点分区。Paul Jackson 为 cpuset 增加了在任务被移动到另一个 cpuset 时一并移动页的能力(参见 :ref:`CPUSETS <cpusets>`)。cpuset 使进程局部性的管理可以自动化。如果一个任务被移动到新的 cpuset，那么它的所有页也会随之移动，这样进程的性能就不会大幅下降。此外，当 cpuset 允许的内存节点发生变化时，其中进程的页也会被移动。)

Page migration allows the preservation of the relative location of pages
within a group of nodes for all migration techniques which will preserve a
particular memory allocation pattern generated even after migrating a
process. This is necessary in order to preserve the memory latencies.
Processes will run with similar performance after migration.
(对于所有迁移技术而言，页面迁移可以保持页在一组节点内的相对位置，从而即使在进程迁移之后也能保持特定的内存分配模式。这对于保持内存延迟是必要的。迁移之后进程将以相近的性能运行。)

Page migration occurs in several steps. First a high level
description for those trying to use migrate_pages() from the kernel
(for userspace usage see the Andi Kleen's numactl package mentioned above)
and then a low level description of how the low level details work.
(页面迁移分几个步骤进行。首先给出面向试图从内核中使用 migrate_pages() 的人的高级描述(用户空间的使用参见上文提到的 Andi Kleen 的 numactl 软件包)，然后给出底层细节如何工作的低级描述。)

In kernel use of migrate_pages()(内核中对 migrate_pages() 的使用)
=================================================================

1. Remove folios from the LRU.
   (把 folio 从 LRU 中移除。)

   Lists of folios to be migrated are generated by scanning over
   folios and moving them into lists. This is done by
   calling folio_isolate_lru().
   Calling folio_isolate_lru() increases the references to the folio
   so that it cannot vanish while the folio migration occurs.
   It also prevents the swapper or other scans from encountering
   the folio.
   (通过扫描 folio 并把它们移入列表，生成待迁移的 folio 列表。这是通过调用 folio_isolate_lru() 完成的。调用 folio_isolate_lru() 会增加对该 folio 的引用，使其在 folio 迁移期间不会消失。它还可以防止换出进程(swapper)或其他扫描遇到该 folio。)

2. We need to have a function of type new_folio_t that can be
   passed to migrate_pages(). This function should figure out
   how to allocate the correct new folio given the old folio.
   (我们需要一个 new_folio_t 类型的函数，它可以传递给 migrate_pages()。该函数应当能够根据旧 folio 确定如何分配正确的新 folio。)

3. The migrate_pages() function is called which attempts
   to do the migration. It will call the function to allocate
   the new folio for each folio that is considered for moving.
   (随后调用 migrate_pages() 函数尝试执行迁移。对每个被考虑移动的 folio，它都会调用该函数来分配新 folio。)

How migrate_pages() works(migrate_pages() 的工作方式)
=====================================================

migrate_pages() does several passes over its list of folios. A folio is moved
if all references to a folio are removable at the time. The folio has
already been removed from the LRU via folio_isolate_lru() and the refcount
is increased so that the folio cannot be freed while folio migration occurs.
(migrate_pages() 会对它的 folio 列表进行若干轮处理。如果某个 folio 的所有引用在当时都是可移除的，该 folio 就会被移动。该 folio 已经通过 folio_isolate_lru() 从 LRU 中移除，并且引用计数已被增加，因此在 folio 迁移期间它不会被释放。)

Steps:
(步骤如下：)

1. Lock the page to be migrated. (锁定要迁移的页。)

2. Ensure that writeback is complete. (确保回写(writeback)已完成。)

3. Lock the new page that we want to move to. It is locked so that accesses to
   this (not yet up-to-date) page immediately block while the move is in progress.
   (锁定我们想要移入的新页。锁定它，使得在移动进行期间，对这一(尚未更新的)页的访问会立即阻塞。)

4. All the page table references to the page are converted to migration
   entries. This decreases the mapcount of a page. If the resulting
   mapcount is not zero then we do not migrate the page. All user space
   processes that attempt to access the page will now wait on the page lock
   or wait for the migration page table entry to be removed.
   (所有指向该页的页表引用都被转换为迁移条目。这会减少页的 mapcount。如果最终 mapcount 不为零，则不迁移该页。所有试图访问该页的用户空间进程此时都会等待页锁，或等待迁移页表条目被移除。)

5. The i_pages lock is taken. This will cause all processes trying
   to access the page via the mapping to block on the spinlock.
   (获取 i_pages 锁。这会使所有试图通过该映射访问页的进程在自旋锁上阻塞。)

6. The refcount of the page is examined and we back out if references remain.
   Otherwise, we know that we are the only one referencing this page.
   (检查页的引用计数，如果仍有引用则退出。否则，我们知道自己是唯一引用该页的一方。)

7. The radix tree is checked and if it does not contain the pointer to this
   page then we back out because someone else modified the radix tree.
   (检查基数树(radix tree)，如果它不包含指向该页的指针，则退出，因为其他人修改了基数树。)

8. The new page is prepped with some settings from the old page so that
   accesses to the new page will discover a page with the correct settings.
   (用旧页的一些设置来预备新页，使得对新页的访问会发现一个具有正确设置的页。)

9. The radix tree is changed to point to the new page.
   (修改基数树，使其指向新页。)

10. The reference count of the old page is dropped because the address space
    reference is gone. A reference to the new page is established because
    the new page is referenced by the address space.
    (由于地址空间引用已消失，旧页的引用计数被减少。由于新页被地址空间引用，会为新页建立引用。)

11. The i_pages lock is dropped. With that lookups in the mapping
    become possible again. Processes will move from spinning on the lock
    to sleeping on the locked new page.
    (释放 i_pages 锁。此后映射中的查找重新变得可能。进程将从在锁上自旋转为在已锁定的新页上休眠。)

12. The page contents are copied to the new page.
    (把页内容复制到新页。)

13. The remaining page flags are copied to the new page.
    (把其余的页标志复制到新页。)

14. The old page flags are cleared to indicate that the page does
    not provide any information anymore.
    (清除旧页的页标志，以表明该页不再提供任何信息。)

15. Queued up writeback on the new page is triggered.
    (触发新页上已排队的回写。)

16. If migration entries were inserted into the page table, then replace them
    with real ptes. Doing so will enable access for user space processes not
    already waiting for the page lock.
    (如果页表中插入了迁移条目，则用真正的 pte 替换它们。这样做可以让尚未在等待页锁的用户空间进程恢复访问。)

17. The page locks are dropped from the old and new page.
    Processes waiting on the page lock will redo their page faults
    and will reach the new page.
    (释放旧页与新页上的页锁。等待页锁的进程将重新执行缺页处理，并到达新页。)

18. The new page is moved to the LRU and can be scanned by the swapper,
    etc. again.
    (新页被移回 LRU，可以再次被换出进程(swapper)等扫描。)

movable_ops page migration(movable_ops 页面迁移)
================================================

Selected typed, non-folio pages (e.g., pages inflated in a memory balloon,
zsmalloc pages) can be migrated using the movable_ops migration framework.
(选定的有类型、非 folio 的页(例如在内存气球中膨胀的页、zsmalloc 页)可以使用 movable_ops 迁移框架来迁移。)

The "struct movable_operations" provide callbacks specific to a page type
for isolating, migrating and un-isolating (putback) these pages.
("struct movable_operations" 为隔离、迁移以及取消隔离(放回，putback)这些页提供了特定于页类型的回调。)

Once a page is indicated as having movable_ops, that condition must not
change until the page was freed back to the buddy. This includes not
changing/clearing the page type and not changing/clearing the
PG_movable_ops page flag.
(一旦一个页被标明拥有 movable_ops，在该页被释放回伙伴系统之前，这一状态不得改变。这包括不改变/清除页类型，以及不改变/清除 PG_movable_ops 页标志。)

Arbitrary drivers cannot currently make use of this framework, as it
requires:
(目前任意驱动都不能使用该框架，因为它要求：)

(a) a page type
    (一个页类型)
(b) indicating them as possibly having movable_ops in page_has_movable_ops()
    based on the page type
    (在 page_has_movable_ops() 中根据页类型把它们标明为可能拥有 movable_ops)
(c) returning the movable_ops from page_movable_ops() based on the page
    type
    (在 page_movable_ops() 中根据页类型返回相应的 movable_ops)
(d) not reusing the PG_movable_ops and PG_movable_ops_isolated page flags
    for other purposes
    (不把 PG_movable_ops 与 PG_movable_ops_isolated 页标志挪作他用)

For example, balloon drivers can make use of this framework through the
balloon-compaction infrastructure residing in the core kernel.
(例如，气球驱动可以通过驻留在核心内核中的 balloon-compaction 基础设施来使用该框架。)

Monitoring Migration(监控迁移)
==============================

The following events (counters) can be used to monitor page migration.
(以下事件(计数器)可用于监控页面迁移。)

1. PGMIGRATE_SUCCESS: Normal page migration success. Each count means that a
   page was migrated. If the page was a non-THP and non-hugetlb page, then
   this counter is increased by one. If the page was a THP or hugetlb, then
   this counter is increased by the number of THP or hugetlb subpages.
   For example, migration of a single 2MB THP that has 4KB-size base pages
   (subpages) will cause this counter to increase by 512.
   (PGMIGRATE_SUCCESS：普通页面迁移成功。每计一次表示一个页被迁移。如果该页既不是 THP 也不是 hugetlb 页，该计数器加一。如果该页是 THP 或 hugetlb，该计数器按 THP 或 hugetlb 子页的数量增加。例如，迁移一个由 4KB 基础页(子页)组成的 2MB THP 会使该计数器增加 512。)

2. PGMIGRATE_FAIL: Normal page migration failure. Same counting rules as for
   PGMIGRATE_SUCCESS, above: this will be increased by the number of subpages,
   if it was a THP or hugetlb.
   (PGMIGRATE_FAIL：普通页面迁移失败。计数规则与上文 PGMIGRATE_SUCCESS 相同：如果失败的是 THP 或 hugetlb，该计数器按子页的数量增加。)

3. THP_MIGRATION_SUCCESS: A THP was migrated without being split.
   (THP_MIGRATION_SUCCESS：一个 THP 未被拆分即完成迁移。)

4. THP_MIGRATION_FAIL: A THP could not be migrated nor it could be split.
   (THP_MIGRATION_FAIL：一个 THP 既无法迁移也无法拆分。)

5. THP_MIGRATION_SPLIT: A THP was migrated, but not as such: first, the THP had
   to be split. After splitting, a migration retry was used for its sub-pages.
   (THP_MIGRATION_SPLIT：一个 THP 被迁移，但并非以 THP 形式：首先该 THP 必须被拆分。拆分之后对其子页重试迁移。)

THP_MIGRATION_* events also update the appropriate PGMIGRATE_SUCCESS or
PGMIGRATE_FAIL events. For example, a THP migration failure will cause both
THP_MIGRATION_FAIL and PGMIGRATE_FAIL to increase.
(THP_MIGRATION_* 事件也会更新相应的 PGMIGRATE_SUCCESS 或 PGMIGRATE_FAIL 事件。例如，一次 THP 迁移失败会同时使 THP_MIGRATION_FAIL 与 PGMIGRATE_FAIL 增加。)
