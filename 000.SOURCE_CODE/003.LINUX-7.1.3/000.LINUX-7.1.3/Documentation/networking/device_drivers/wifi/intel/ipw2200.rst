The current release (1.1.2) supports the following features:

+ BSS mode (Infrastructure, Managed)
  (BSS 模式 (基础结构，受管))
+ IBSS mode (Ad-Hoc)
  (IBSS 模式 (Ad-Hoc))
+ WEP (OPEN and SHARED KEY mode)
  (WEP (OPEN 和 SHARED KEY 模式))

  (发送功率控制)
+ S state support (ACPI suspend/resume)
  (S 状态支持 (ACPI 挂起/恢复))

1.2. Command Line Parameters
(1.2. 命令行参数)
----------------------------

Like many modules used in the Linux kernel, the Intel(R) PRO/Wireless
2915ABG Driver for Linux allows configuration options to be provided
as module parameters.  The most common way to specify a module parameter
is via the command line.
(与 Linux 内核中使用的许多模块一样，Linux 的 Intel(R) PRO/Wireless 2915ABG 驱动程序允许以模块参数的形式提供配置选项。指定模块参数最常见的方式是通过命令行。)

The general form is::
(一般形式为：)

    % modprobe ipw2200 parameter=value

Where the supported parameter are:
(支持的参数如下：)

  associate
  (associate：自动扫描与关联)

	Set to 0 to disable the auto scan-and-associate functionality of the
	driver.  If disabled, the driver will not attempt to scan
	for and associate to a network until it has been configured with
	one or more properties for the target network, for example configuring
	the network SSID.  Default is 0 (do not auto-associate)
	(设为 0 可禁用驱动程序的自动扫描并关联功能。如果禁用，驱动程序在针对目标网络配置了一个或多个属性 (例如配置网络 SSID) 之前，不会尝试扫描并关联到网络。默认值为 0 (不自动关联))

	Example: % modprobe ipw2200 associate=0
	(示例： % modprobe ipw2200 associate=0)

  auto_create
  (auto_create：自动创建)

	Set to 0 to disable the auto creation of an Ad-Hoc network
	matching the channel and network name parameters provided.
	Default is 1.
	(设为 0 可禁用自动创建与所提供的信道和网络名称参数相匹配的 Ad-Hoc 网络。默认值为 1。)

  channel
  (channel：信道)

	channel number for association.  The normal method for setting
	the channel would be to use the standard wireless tools
	(i.e. `iwconfig eth1 channel 10`), but it is useful sometimes
	to set this while debugging.  Channel 0 means 'ANY'
	(用于关联的信道编号。设置信道的常规方法是使用标准无线工具 (即 `iwconfig eth1 channel 10`)，但有时在调试时设置它会很有用。信道 0 表示 'ANY' (任意))

  debug
  (debug：调试)

	If using a debug build, this is used to control the amount of debug
	info is logged.  See the 'dvals' and 'load' script for more info on
	how to use this (the dvals and load scripts are provided as part
	of the ipw2200 development snapshot releases available from the
	SourceForge project at http://ipw2200.sf.net)
	(如果使用调试版本，此参数用于控制记录的调试信息数量。有关其用法的更多信息，请参阅 'dvals' 和 'load' 脚本 (这两个脚本作为 ipw2200 开发快照版本的一部分提供，可从 http://ipw2200.sf.net 上的 SourceForge 项目获取))

  led
  (led：LED)

	Can be used to turn on experimental LED code.
	0 = Off, 1 = On.  Default is 1.
	(可用于打开实验性的 LED 代码。0 = 关，1 = 开。默认值为 1。)

  mode
  (mode：模式)

	Can be used to set the default mode of the adapter.
	0 = Managed, 1 = Ad-Hoc, 2 = Monitor
	(可用于设置适配器的默认模式。0 = 受管 (Managed)，1 = Ad-Hoc，2 = 监听 (Monitor))


1.3. Wireless Extension Private Methods
(1.3. 无线扩展私有方法)
---------------------------------------

As an interface designed to handle generic hardware, there are certain
capabilities not exposed through the normal Wireless Tool interface.  As
such, a provision is provided for a driver to declare custom, or
private, methods.  The Intel(R) PRO/Wireless 2915ABG Driver for Linux
defines several of these to configure various settings.
(作为一个为处理通用硬件而设计的接口，某些能力并未通过常规的无线工具接口暴露出来。因此，提供了让驱动程序声明自定义 (即私有) 方法的机制。Linux 的 Intel(R) PRO/Wireless 2915ABG 驱动程序定义了其中若干方法，用于配置各种设置。)

The general form of using the private wireless methods is::
(使用私有无线方法的一般形式为：)

	% iwpriv $IFNAME method parameters

Where $IFNAME is the interface name the device is registered with
(typically eth1, customized via one of the various network interface
name managers, such as ifrename)
(其中 $IFNAME 是设备注册时使用的接口名称 (通常为 eth1，可通过各种网络接口名称管理器 (如 ifrename) 之一进行自定义))

The supported private methods are:
(支持的私有方法如下：)

  get_mode
  (get_mode：获取模式)

	Can be used to report out which IEEE mode the driver is
	configured to support.  Example:
	(可用于报告驱动程序被配置为支持哪种 IEEE 模式。示例：)

	% iwpriv eth1 get_mode
	eth1	get_mode:802.11bg (6)
	(输出示例：eth1 的 get_mode 结果为 802.11bg (6))

  set_mode
  (set_mode：设置模式)

	Can be used to configure which IEEE mode the driver will
	support.
	(可用于配置驱动程序将支持哪种 IEEE 模式。)

	Usage::
	(用法：)

	    % iwpriv eth1 set_mode {mode}

	Where {mode} is a number in the range 1-7:
	(其中 {mode} 是 1-7 范围内的数字：)

	==	=====================
	1	802.11a (2915 only) (仅限 2915)
	2	802.11b
	3	802.11ab (2915 only) (仅限 2915)
	4	802.11g
	5	802.11ag (2915 only) (仅限 2915)
	6	802.11bg
	7	802.11abg (2915 only) (仅限 2915)
	==	=====================

  get_preamble
  (get_preamble：获取前导码)

	Can be used to report configuration of preamble length.
	(可用于报告前导码长度的配置。)

  set_preamble
  (set_preamble：设置前导码)

	Can be used to set the configuration of preamble length:
	(可用于设置前导码长度的配置：)

	Usage::
	(用法：)

	    % iwpriv eth1 set_preamble {mode}

	Where {mode} is one of:
	(其中 {mode} 为以下之一：)

	==	========================================
	1	Long preamble only (仅长前导码)
	0	Auto (long or short based on connection) (自动 (根据连接选择长或短))
	==	========================================


1.4. Sysfs Helper Files
(1.4. Sysfs 辅助文件)
-----------------------

The Linux kernel provides a pseudo file system that can be used to
access various components of the operating system.  The Intel(R)
PRO/Wireless 2915ABG Driver for Linux exposes several configuration
parameters through this mechanism.
(Linux 内核提供了一个伪文件系统，可用于访问操作系统的各种组件。Linux 的 Intel(R) PRO/Wireless 2915ABG 驱动程序通过此机制暴露了若干配置参数。)

An entry in the sysfs can support reading and/or writing.  You can
typically query the contents of a sysfs entry through the use of cat,
and can set the contents via echo.  For example::
(sysfs 中的条目可以支持读和/或写。通常可以使用 cat 查询 sysfs 条目的内容，并可以通过 echo 设置内容。例如：)

    % cat /sys/bus/pci/drivers/ipw2200/debug_level

Will report the current debug level of the driver's logging subsystem
(only available if CONFIG_IPW2200_DEBUG was configured when the driver
was built).
(将报告驱动程序日志子系统的当前调试级别 (仅当构建驱动程序时配置了 CONFIG_IPW2200_DEBUG 时可用)。)

You can set the debug level via::
(可以通过以下方式设置调试级别：)

    % echo $VALUE > /sys/bus/pci/drivers/ipw2200/debug_level

Where $VALUE would be a number in the case of this sysfs entry.  The
input to sysfs files does not have to be a number.  For example, the
firmware loader used by hotplug utilizes sysfs entries for transferring
the firmware image from user space into the driver.
(对于这个 sysfs 条目，$VALUE 是一个数字。写入 sysfs 文件的输入不一定是数字。例如，hotplug 使用的固件加载器利用 sysfs 条目将固件映像从用户空间传输到驱动程序中。)

The Intel(R) PRO/Wireless 2915ABG Driver for Linux exposes sysfs entries
at two levels -- driver level, which apply to all instances of the driver
(in the event that there are more than one device installed) and device
level, which applies only to the single specific instance.
(Linux 的 Intel(R) PRO/Wireless 2915ABG 驱动程序在两个级别上暴露 sysfs 条目 -- 驱动程序级别 (适用于驱动程序的所有实例，以应对安装了多于一个设备的情况) 和设备级别 (仅适用于单个特定实例)。)


1.4.1 Driver Level Sysfs Helper Files
(1.4.1 驱动程序级别的 Sysfs 辅助文件)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

For the driver level files, look in /sys/bus/pci/drivers/ipw2200/
(驱动程序级别的文件请查看 /sys/bus/pci/drivers/ipw2200/)

  debug_level
  (debug_level：调试级别)

	This controls the same global as the 'debug' module parameter
	(它控制与 'debug' 模块参数相同的全局变量)



1.4.2 Device Level Sysfs Helper Files
(1.4.2 设备级别的 Sysfs 辅助文件)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

For the device level files, look in::
(设备级别的文件请查看：)

	/sys/bus/pci/drivers/ipw2200/{PCI-ID}/

For example:::
(例如：)

	/sys/bus/pci/drivers/ipw2200/0000:02:01.0

For the device level files, see /sys/bus/pci/drivers/ipw2200:
(设备级别的文件位于 /sys/bus/pci/drivers/ipw2200，内容如下：)

  rf_kill
  (rf_kill：射频禁用)

	read -
	(读 -)

	==  =========================================
	0   RF kill not enabled (radio on) (RF kill 未启用 (无线电开启))
	1   SW based RF kill active (radio off) (基于软件的 RF kill 生效 (无线电关闭))
	2   HW based RF kill active (radio off) (基于硬件的 RF kill 生效 (无线电关闭))
	3   Both HW and SW RF kill active (radio off) (硬件和软件 RF kill 均生效 (无线电关闭))
	==  =========================================

	write -
	(写 -)

	==  ==================================================
	0   If SW based RF kill active, turn the radio back on (如果基于软件的 RF kill 生效，重新打开无线电)
	1   If radio is on, activate SW based RF kill (如果无线电开启，激活基于软件的 RF kill)
	==  ==================================================

	.. note::

	   If you enable the SW based RF kill and then toggle the HW
	   based RF kill from ON -> OFF -> ON, the radio will NOT come back on
	   (注意：如果你启用了基于软件的 RF kill，然后将基于硬件的 RF kill 从 开 -> 关 -> 开 切换，无线电将不会重新开启)

  ucode
  (ucode：微码)

	read-only access to the ucode version number
	(对 ucode 版本号的只读访问)

  led
  (led：LED)

	read -

	==  =================
	0   LED code disabled (LED 代码禁用)
	1   LED code enabled (LED 代码启用)
	==  =================

	write -
	(写 -)

	==  ================
	0   Disable LED code (禁用 LED 代码)
	1   Enable LED code (启用 LED 代码)
	==  ================


	.. note::

	   The LED code has been reported to hang some systems when
	   running ifconfig and is therefore disabled by default.
	   (注意：据报道，LED 代码在运行 ifconfig 时会使某些系统挂起，因此默认禁用)

2.  Ad-Hoc Networking
(2. Ad-Hoc 网络)
=====================

When using a device in an Ad-Hoc network, it is useful to understand the
sequence and requirements for the driver to be able to create, join, or
merge networks.
(在 Ad-Hoc 网络中使用设备时，了解驱动程序能够创建、加入或合并网络的流程和要求是很有用的。)

The following attempts to provide enough information so that you can
have a consistent experience while using the driver as a member of an
Ad-Hoc network.
(以下内容试图提供足够的信息，使你在作为 Ad-Hoc 网络成员使用该驱动程序时能够获得一致的体验。)

2.1. Joining an Ad-Hoc Network
(2.1. 加入 Ad-Hoc 网络)
------------------------------

3. Interaction with Wireless Tools
(3. 与无线工具的交互)
==================================

3.1 iwconfig mode
(3.1 iwconfig 模式)
-----------------

When configuring the mode of the adapter, all run-time configured parameters
are reset to the value used when the module was loaded.  This includes
channels, rates, ESSID, etc.
(配置适配器模式时，所有运行时配置的参数都会重置为模块加载时所使用的值。这包括信道、速率、ESSID 等。)

3.2 iwconfig sens
(3.2 iwconfig sens)
-----------------

The 'iwconfig ethX sens XX' command will not set the signal sensitivity
threshold, as described in iwconfig documentation, but rather the number
of consecutive missed beacons that will trigger handover, i.e. roaming
to another access point. At the same time, it will set the disassociation
threshold to 3 times the given value.
('iwconfig ethX sens XX' 命令不会像 iwconfig 文档所描述的那样设置信号灵敏度阈值，而是设置将触发切换 (即漫游到另一个接入点) 的连续丢失信标数量。同时，它还会将解除关联阈值设置为给定值的 3 倍。)


4.  About the Version Numbers
(4. 关于版本号)
=============================

Due to the nature of open source development projects, there are
frequently changes being incorporated that have not gone through
a complete validation process.  These changes are incorporated into
development snapshot releases.
(由于开源开发项目的性质，经常会纳入一些尚未经过完整验证过程的更改。这些更改会被纳入开发快照版本中。)

Releases are numbered with a three level scheme:
(版本采用三级编号方案：)

	major.minor.development
	(主版本.次版本.开发版本)

Any version where the 'development' portion is 0 (for example
1.0.0, 1.1.0, etc.) indicates a stable version that will be made
available for kernel inclusion.
(任何 'development' 部分为 0 的版本 (例如 1.0.0、1.1.0 等) 表示稳定版本，将可用于内核纳入。)

Any version where the 'development' portion is not a 0 (for
example 1.0.1, 1.1.5, etc.) indicates a development version that is
being made available for testing and cutting edge users.  The stability
and functionality of the development releases are not know.  We make
efforts to try and keep all snapshots reasonably stable, but due to the
frequency of their release, and the desire to get those releases
available as quickly as possible, unknown anomalies should be expected.
(任何 'development' 部分不为 0 的版本 (例如 1.0.1、1.1.5 等) 表示开发版本，提供给测试和前沿用户使用。开发版本的稳定性和功能尚不可知。我们努力尝试让所有快照保持合理的稳定性，但由于发布频繁，且希望尽快提供这些版本，应当预期会出现未知异常。)

The major version number will be incremented when significant changes
are made to the driver.  Currently, there are no major changes planned.
(当对驱动程序进行重大更改时，主版本号将会递增。目前没有计划进行重大更改。)
