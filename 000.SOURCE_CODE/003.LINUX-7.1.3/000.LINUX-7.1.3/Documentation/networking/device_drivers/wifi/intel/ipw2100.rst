3. Command Line Parameters
(3. 命令行参数)
==========================

If the driver is built as a module, the following optional parameters are used
by entering them on the command line with the modprobe command using this
syntax::
(如果驱动程序被构建为模块，可在命令行中使用 modprobe 命令按以下语法
输入以下可选参数：)

	modprobe ipw2100 [<option>=<VAL1><,VAL2>...]

For example, to disable the radio on driver loading, enter:
(例如，要在驱动加载时禁用无线电，请输入：)

	modprobe ipw2100 disable=1

The ipw2100 driver supports the following module parameters:
(ipw2100 驱动程序支持以下模块参数：)

=========	==============	============  ==============================
Name		Value		Example       Meaning (含义)
=========	==============	============  ==============================
debug		0x0-0xffffffff	debug=1024    Debug level set to 1024 (调试级别设为 1024)
mode		0,1,2		mode=1        AdHoc (自组网模式)
channel		int		channel=3     Only valid in AdHoc or Monitor (仅在 AdHoc 或 Monitor 模式下有效)
associate	boolean		associate=0   Do NOT auto associate (不要自动关联)
disable		boolean		disable=1     Do not power the HW (不要给硬件上电)
=========	==============	============  ==============================


4. Sysfs Helper Files
(4. Sysfs 辅助文件)
=====================

There are several ways to control the behavior of the driver.  Many of the
general capabilities are exposed through the Wireless Tools (iwconfig).  There
are a few capabilities that are exposed through entries in the Linux Sysfs.
(控制驱动程序行为有多种方式。许多通用能力通过 Wireless Tools（iwconfig）
暴露出来，另有一些能力则通过 Linux Sysfs 中的条目暴露。)


**Driver Level**
(驱动程序级)

For the driver level files, look in /sys/bus/pci/drivers/ipw2100/
(驱动程序级文件位于 /sys/bus/pci/drivers/ipw2100/ 中)

  debug_level
	This controls the same global as the 'debug' module parameter.  For
	information on the various debugging levels available, run the 'dvals'
	script found in the driver source directory.
	(它控制的与 'debug' 模块参数控制的是同一个全局变量。有关可用的各类
	调试级别，请运行驱动程序源代码目录中的 'dvals' 脚本。)

	.. note::

	      'debug_level' is only enabled if CONFIG_IPW2100_DEBUG is turn on.
	      (注意：只有在开启 CONFIG_IPW2100_DEBUG 时 'debug_level' 才会被
	      启用。)

**Device Level**
(设备级)

For the device level files look in::
(设备级文件位于以下目录中：)

	/sys/bus/pci/drivers/ipw2100/{PCI-ID}/

For example::
(例如：)

	/sys/bus/pci/drivers/ipw2100/0000:02:01.0

For the device level files, see /sys/bus/pci/drivers/ipw2100:
(设备级文件详见 /sys/bus/pci/drivers/ipw2100：)

  rf_kill
	read
	(读)

	==  =========================================
	0   RF kill not enabled (radio on) (RF kill 未启用，无线电开启)
	1   SW based RF kill active (radio off) (基于软件的 RF kill 生效，无线电关闭)
	2   HW based RF kill active (radio off) (基于硬件的 RF kill 生效，无线电关闭)
	3   Both HW and SW RF kill active (radio off) (硬件与软件 RF kill 均生效，无线电关闭)
	==  =========================================

	write
	(写)

	==  ==================================================
	0   If SW based RF kill active, turn the radio back on (若基于软件的 RF kill 生效，则重新打开无线电)
	1   If radio is on, activate SW based RF kill (若无线电开启，则激活基于软件的 RF kill)
	==  ==================================================

	.. note::

	   If you enable the SW based RF kill and then toggle the HW
	   based RF kill from ON -> OFF -> ON, the radio will NOT come back on
	   (注意：如果先启用基于软件的 RF kill，然后将基于硬件的 RF kill 从
	   ON -> OFF -> ON 切换，无线电不会重新开启。)


5. Radio Kill Switch
(5. 无线电禁用开关)
====================

Most laptops provide the ability for the user to physically disable the radio.
Some vendors have implemented this as a physical switch that requires no
software to turn the radio off and on.  On other laptops, however, the switch
is controlled through a button being pressed and a software driver then making
calls to turn the radio off and on.  This is referred to as a "software based
RF kill switch"
(大多数笔记本电脑都允许用户物理性地禁用无线电。一些厂商将其实现为无需
软件参与即可开关无线电的物理开关。但在另一些笔记本电脑上，该开关通过
按压按键来控制，再由软件驱动程序调用相关操作来开关无线电。这被称为
"基于软件的 RF kill 开关"。)

See the Sysfs helper file 'rf_kill' for determining the state of the RF switch
on your system.
(要确定您系统上 RF 开关的状态，请参阅 Sysfs 辅助文件 'rf_kill'。)


6. Dynamic Firmware
(6. 动态固件)
===================

As the firmware is licensed under a restricted use license, it can not be
included within the kernel sources.  To enable the IPW2100 you will need a
firmware image to load into the wireless NIC's processors.
(由于该固件按照受限使用许可授权，无法包含在内核源码中。要启用 IPW2100，
您需要一个固件镜像，加载到无线网卡的处理器中。)

You can obtain these images from <http://ipw2100.sf.net/firmware.php>.
(您可以从 <http://ipw2100.sf.net/firmware.php> 获取这些镜像。)

See INSTALL for instructions on installing the firmware.
(固件安装说明参见 INSTALL。)


7. Power Management
(7. 电源管理)
===================

The IPW2100 supports the configuration of the Power Save Protocol
through a private wireless extension interface.  The IPW2100 supports
the following different modes:
(IPW2100 支持通过私有的无线扩展接口配置省电协议（Power Save Protocol）。
IPW2100 支持以下几种不同模式：)

	===	===========================================================
	off	No power management.  Radio is always on. (无电源管理。无线电始终开启。)
	on	Automatic power management (自动电源管理)
	1-5	Different levels of power management.  The higher the
		number the greater the power savings, but with an impact to
		packet latencies. (不同的电源管理级别。数字越大越省电，但会对数据包延迟造成影响。)
	===	===========================================================

Power management works by powering down the radio after a certain
interval of time has passed where no packets are passed through the
radio.  Once powered down, the radio remains in that state for a given
period of time.  For higher power savings, the interval between last
packet processed to sleep is shorter and the sleep period is longer.
(电源管理的工作方式是：当一段时间内没有数据包经过无线电时，就把无线电
断电。断电后，无线电会在该状态保持一段给定的时间。省电要求越高，从
最后一个数据包处理完毕到进入休眠的间隔就越短，休眠时间则越长。)

When the radio is asleep, the access point sending data to the station
must buffer packets at the AP until the station wakes up and requests
any buffered packets.  If you have an AP that does not correctly support
the PSP protocol you may experience packet loss or very poor performance
while power management is enabled.  If this is the case, you will need
to try and find a firmware update for your AP, or disable power
management (via ``iwconfig eth1 power off``)
(当无线电处于休眠状态时，向该工作站发送数据的接入点必须在 AP 侧缓冲
数据包，直到工作站唤醒并请求这些被缓冲的数据包。如果您的 AP 不能正确
支持 PSP 协议，那么在电源管理开启期间可能出现丢包或性能极差的情况。
若是如此，您需要尝试为 AP 寻找固件更新，或者禁用电源管理（通过
``iwconfig eth1 power off``）。)

To configure the power level on the IPW2100 you use a combination of
iwconfig and iwpriv.  iwconfig is used to turn power management on, off,
and set it to auto.
(要配置 IPW2100 的电源级别，需要结合使用 iwconfig 与 iwpriv。iwconfig
用于开启、关闭电源管理以及将其设为自动。)

	=========================  ====================================
	iwconfig eth1 power off    Disables radio power down (禁用无线电压降)
	iwconfig eth1 power on     Enables radio power management to
				   last set level (defaults to AUTO) (启用无线电电源管理至最后设定的级别（默认为 AUTO）)
	iwpriv eth1 set_power 0    Sets power level to AUTO and enables
				   power management if not previously
				   enabled. (将电源级别设为 AUTO，并在电源管理尚未启用时启用它。)
	iwpriv eth1 set_power 1-5  Set the power level as specified,
				   enabling power management if not
				   previously enabled. (按指定值设置电源级别，并在电源管理尚未启用时启用它。)
	=========================  ====================================

You can view the current power level setting via::
(可以使用以下命令查看当前电源级别设置：)

	iwpriv eth1 get_power

It will return the current period or timeout that is configured as a string
in the form of xxxx/yyyy (z) where xxxx is the timeout interval (amount of
time after packet processing), yyyy is the period to sleep (amount of time to
wait before powering the radio and querying the access point for buffered
packets), and z is the 'power level'.  If power management is turned off the
xxxx/yyyy will be replaced with 'off' -- the level reported will be the active
level if `iwconfig eth1 power on` is invoked.
(它将以 xxxx/yyyy (z) 形式的字符串返回当前配置的周期或超时值：xxxx 为
超时间隔（数据包处理之后的时长），yyyy 为休眠周期（在对无线电断电并向
接入点查询缓冲数据包之前等待的时长），z 为"电源级别"。如果电源管理被
关闭，xxxx/yyyy 将被替换为 'off'——若随后调用 `iwconfig eth1 power on`，
报告的级别将是活动级别。)
