Command Line Parameters(命令行参数)
===================================

If the driver is built as a module, the following optional parameters are used
by entering them on the command line with the modprobe command using this
syntax::
(如果驱动程序以模块形式构建，则可以通过 modprobe 命令在命令行中按以下语法输入使用这些可选参数：)

    modprobe e1000e [<option>=<VAL1>,<VAL2>,...]

There needs to be a <VAL#> for each network port in the system supported by
this driver. The values will be applied to each instance, in function order.
For example::
(该驱动程序所支持的系统中的每个网络端口都需要有一个对应的 <VAL#>。这些值会按功能顺序依次应用到每个实例。例如：)

    modprobe e1000e InterruptThrottleRate=16000,16000

In this case, there are two network ports supported by e1000e in the system.
The default value for each parameter is generally the recommended setting,
unless otherwise noted.
(在本例中，系统中有两个由 e1000e 支持的网络端口。除非另有说明，各参数的默认值通常就是推荐的设置。)

NOTE: A descriptor describes a data buffer and attributes related to the data
buffer. This information is accessed by the hardware.
(注意：描述符 (descriptor) 描述一个数据缓冲区以及与该数据缓冲区相关的属性。硬件会访问这些信息。)

InterruptThrottleRate(中断节流率)
---------------------------------

:Valid Range: 0,1,3,4,100-100000
  (有效范围：0,1,3,4,100-100000)
:Default Value: 3
  (默认值：3)

Interrupt Throttle Rate controls the number of interrupts each interrupt
vector can generate per second. Increasing ITR lowers latency at the cost of
increased CPU utilization, though it may help throughput in some circumstances.
(中断节流率 (Interrupt Throttle Rate) 控制每个中断向量每秒可以产生的中断数量。提高 ITR 会以增加 CPU 占用率为代价降低延迟，但在某些情况下可能有助于提升吞吐量。)

Setting InterruptThrottleRate to a value greater or equal to 100
will program the adapter to send out a maximum of that many interrupts
per second, even if more packets have come in. This reduces interrupt
load on the system and can lower CPU utilization under heavy load,
but will increase latency as packets are not processed as quickly.
(将 InterruptThrottleRate 设为大于等于 100 的值，会使适配器每秒最多发出该数量的中断，即使有更多数据包到来也是如此。这可以减少系统的中断负载，并在高负载下降低 CPU 占用率，但由于数据包不能被尽快处理，会增加延迟。)

The default behaviour of the driver previously assumed a static
InterruptThrottleRate value of 8000, providing a good fallback value for
all traffic types, but lacking in small packet performance and latency.
The hardware can handle many more small packets per second however, and
for this reason an adaptive interrupt moderation algorithm was implemented.
(驱动程序此前的默认行为假定 InterruptThrottleRate 为 8000 的静态值，这对所有流量类型都是一个不错的后备值，但在小数据包性能和延迟方面表现欠佳。然而，硬件每秒实际可处理的小数据包要多得多，因此实现了自适应中断调节算法。)

The driver has two adaptive modes (setting 1 or 3) in which
it dynamically adjusts the InterruptThrottleRate value based on the traffic
that it receives. After determining the type of incoming traffic in the last
timeframe, it will adjust the InterruptThrottleRate to an appropriate value
for that traffic.
(驱动程序有两种自适应模式 (设置为 1 或 3)，会根据接收到的流量动态调整 InterruptThrottleRate 值。在确定上一时间段内入站流量的类型后，它会将 InterruptThrottleRate 调整为适合该流量的值。)

The algorithm classifies the incoming traffic every interval into
classes.  Once the class is determined, the InterruptThrottleRate value is
adjusted to suit that traffic type the best. There are three classes defined:
"Bulk traffic", for large amounts of packets of normal size; "Low latency",
for small amounts of traffic and/or a significant percentage of small
packets; and "Lowest latency", for almost completely small packets or
minimal traffic.
(该算法每隔一个时间间隔就把入站流量归入相应类别。一旦确定了类别，就会把 InterruptThrottleRate 值调整到最适合该流量类型。共定义了三个类别："Bulk traffic" (大流量)，指大量正常尺寸的数据包；"Low latency" (低延迟)，指流量较少和/或小数据包占比很高；"Lowest latency" (最低延迟)，指几乎全是小数据包或流量极少的情况。)

 - 0: Off
      Turns off any interrupt moderation and may improve small packet latency.
      However, this is generally not suitable for bulk throughput traffic due
      to the increased CPU utilization of the higher interrupt rate.
      (关闭所有中断调节，可能改善小数据包延迟。但由于中断率更高导致 CPU 占用率增加，通常不适合大流量吞吐型业务。)
 - 1: Dynamic mode
      This mode attempts to moderate interrupts per vector while maintaining
      very low latency. This can sometimes cause extra CPU utilization. If
      planning on deploying e1000e in a latency sensitive environment, this
      parameter should be considered.
      (此模式尝试在每个向量维持极低延迟的同时调节中断。这有时会造成额外的 CPU 占用。如果打算在延迟敏感的环境中部署 e1000e，应考虑此参数。)
 - 3: Dynamic Conservative mode (default)
      In dynamic conservative mode, the InterruptThrottleRate value is set to
      4000 for traffic that falls in class "Bulk traffic". If traffic falls in
      the "Low latency" or "Lowest latency" class, the InterruptThrottleRate is
      increased stepwise to 20000. This default mode is suitable for most
      applications.
      (在动态保守模式下，对于属于 "Bulk traffic" 类别的流量，InterruptThrottleRate 值被设为 4000。如果流量属于 "Low latency" 或 "Lowest latency" 类别，InterruptThrottleRate 会逐步提高到 20000。此默认模式适合大多数应用。)
 - 4: Simplified Balancing mode
      In simplified mode the interrupt rate is based on the ratio of TX and
      RX traffic.  If the bytes per second rate is approximately equal, the
      interrupt rate will drop as low as 2000 interrupts per second.  If the
      traffic is mostly transmit or mostly receive, the interrupt rate could
      be as high as 8000.
      (在简化模式下，中断率基于 TX 与 RX 流量的比例。如果每秒字节数大致相等，中断率可低至每秒 2000 次中断。如果流量以发送或接收为主，中断率可能高达 8000。)
 - 100-100000:
      Setting InterruptThrottleRate to a value greater or equal to 100
      will program the adapter to send at most that many interrupts per second,
      even if more packets have come in. This reduces interrupt load on the
      system and can lower CPU utilization under heavy load, but will increase
      latency as packets are not processed as quickly.
      (将 InterruptThrottleRate 设为大于等于 100 的值，会使适配器每秒最多发出该数量的中断，即使有更多数据包到来也是如此。这可以减少系统的中断负载，并在高负载下降低 CPU 占用率，但由于数据包不能被尽快处理，会增加延迟。)

NOTE: InterruptThrottleRate takes precedence over the TxAbsIntDelay and
RxAbsIntDelay parameters. In other words, minimizing the receive and/or
transmit absolute delays does not force the controller to generate more
interrupts than what the Interrupt Throttle Rate allows.
(注意：InterruptThrottleRate 的优先级高于 TxAbsIntDelay 和 RxAbsIntDelay 参数。换言之，把接收和/或发送绝对延迟调到最小，并不会迫使控制器产生超过中断节流率所允许数量的中断。)

RxIntDelay(接收中断延迟)
------------------------

:Valid Range: 0-65535 (0=off)
  (有效范围：0-65535 (0=off))
:Default Value: 0
  (默认值：0)

This value delays the generation of receive interrupts in units of 1.024
microseconds. Receive interrupt reduction can improve CPU efficiency if
properly tuned for specific network traffic. Increasing this value adds extra
latency to frame reception and can end up decreasing the throughput of TCP
traffic. If the system is reporting dropped receives, this value may be set
too high, causing the driver to run out of available receive descriptors.
(此值以 1.024 微秒为单位延迟接收中断的产生。若针对特定网络流量进行恰当调优，减少接收中断可以提高 CPU 效率。增大此值会给帧接收带来额外延迟，并可能最终降低 TCP 流量的吞吐量。如果系统报告接收丢弃，则此值可能设置得过高，导致驱动程序的可用接收描述符耗尽。)

CAUTION: When setting RxIntDelay to a value other than 0, adapters may hang
(stop transmitting) under certain network conditions. If this occurs a NETDEV
WATCHDOG message is logged in the system event log. In addition, the
controller is automatically reset, restoring the network connection. To
eliminate the potential for the hang ensure that RxIntDelay is set to 0.
(注意：当把 RxIntDelay 设为非 0 值时，适配器在某些网络条件下可能会挂起 (停止发送)。如果发生这种情况，系统事件日志中会记录一条 NETDEV WATCHDOG 消息。此外，控制器会自动复位，恢复网络连接。要消除挂起的可能，请确保将 RxIntDelay 设为 0。)

RxAbsIntDelay(接收绝对延迟)
---------------------------

:Valid Range: 0-65535 (0=off)
  (有效范围：0-65535 (0=off))
:Default Value: 8
  (默认值：8)

This value, in units of 1.024 microseconds, limits the delay in which a
receive interrupt is generated. This value ensures that an interrupt is
generated after the initial packet is received within the set amount of time,
which is useful only if RxIntDelay is non-zero. Proper tuning, along with
RxIntDelay, may improve traffic throughput in specific network conditions.
(此值以 1.024 微秒为单位，限制接收中断产生前的延迟。此值确保在收到初始数据包之后的设定时间内会产生中断，仅在 RxIntDelay 非零时才有用。与 RxIntDelay 一起进行恰当调优，可能会在特定网络条件下改善流量吞吐量。)

TxIntDelay(发送中断延迟)
------------------------

:Valid Range: 0-65535 (0=off)
  (有效范围：0-65535 (0=off))
:Default Value: 8
  (默认值：8)

This value delays the generation of transmit interrupts in units of 1.024
microseconds. Transmit interrupt reduction can improve CPU efficiency if
properly tuned for specific network traffic. If the system is reporting
dropped transmits, this value may be set too high causing the driver to run
out of available transmit descriptors.
(此值以 1.024 微秒为单位延迟发送中断的产生。若针对特定网络流量进行恰当调优，减少发送中断可以提高 CPU 效率。如果系统报告发送丢弃，则此值可能设置得过高，导致驱动程序的可用发送描述符耗尽。)

TxAbsIntDelay(发送绝对延迟)
---------------------------

:Valid Range: 0-65535 (0=off)
  (有效范围：0-65535 (0=off))
:Default Value: 32
  (默认值：32)

This value, in units of 1.024 microseconds, limits the delay in which a
transmit interrupt is generated. It is useful only if TxIntDelay is non-zero.
It ensures that an interrupt is generated after the initial Packet is sent on
the wire within the set amount of time. Proper tuning, along with TxIntDelay,
may improve traffic throughput in specific network conditions.
(此值以 1.024 微秒为单位，限制发送中断产生前的延迟。仅在 TxIntDelay 非零时才有用。它确保在初始数据包发送到线路之后的设定时间内会产生中断。与 TxIntDelay 一起进行恰当调优，可能会在特定网络条件下改善流量吞吐量。)

copybreak(拷贝阈值)
-------------------

:Valid Range: 0-xxxxxxx (0=off)
  (有效范围：0-xxxxxxx (0=off))
:Default Value: 256
  (默认值：256)

The driver copies all packets below or equaling this size to a fresh receive
buffer before handing it up the stack.
This parameter differs from other parameters because it is a single (not 1,1,1
etc.) parameter applied to all driver instances and it is also available
during runtime at /sys/module/e1000e/parameters/copybreak.
(驱动程序会把小于或等于此尺寸的所有数据包先复制到新的接收缓冲区，然后再上交协议栈。此参数与其他参数不同：它是单一参数 (而不是 1,1,1 之类)，作用于所有驱动程序实例，并且还可以在运行时通过 /sys/module/e1000e/parameters/copybreak 进行设置。)

To use copybreak, type::
(要使用 copybreak，请输入：)

    modprobe e1000e.ko copybreak=128

IntMode(中断模式)
-----------------

:Valid Range: 0-2
  (有效范围：0-2)
:Default Value: 0
  (默认值：0)

   +-------+----------------+
   | Value | Interrupt Mode |
   |  值   |   (中断模式)   |
   +=======+================+
   |   0   |     Legacy     |
   +-------+----------------+
   |   1   |       MSI      |
   +-------+----------------+
   |   2   |      MSI-X     |
   +-------+----------------+

IntMode allows load time control over the type of interrupt registered for by
the driver. MSI-X is required for multiple queue support, and some kernels and
combinations of kernel .config options will force a lower level of interrupt
support.
(IntMode 允许在加载时控制驱动程序注册的中断类型。多队列支持需要 MSI-X，某些内核以及内核 .config 选项的组合会强制使用较低级别的中断支持。)

This command will show different values for each type of interrupt::
(此命令会为每种中断类型显示不同的值：)

  cat /proc/interrupts

CrcStripping(CRC 剥除)
----------------------

:Valid Range: 0,1
  (有效范围：0,1)
:Default Value: 1 (enabled)
  (默认值：1 (启用))

Strip the CRC from received packets before sending up the network stack. If
you have a machine with a BMC enabled but cannot receive IPMI traffic after
loading or enabling the driver, try disabling this feature.
(在把接收到的数据包上交网络协议栈之前剥除其 CRC。如果你的机器启用了 BMC，但在加载或启用驱动程序后无法接收 IPMI 流量，请尝试禁用此特性。)

WriteProtectNVM(NVM 写保护)
---------------------------

:Valid Range: 0,1
  (有效范围：0,1)
:Default Value: 1 (enabled)
  (默认值：1 (启用))

If set to 1, configure the hardware to ignore all write/erase cycles to the
GbE region in the ICHx NVM (in order to prevent accidental corruption of the
NVM). This feature can be disabled by setting the parameter to 0 during initial
driver load.
(如果设为 1，则配置硬件忽略对 ICHx NVM 中 GbE 区域的所有写入/擦除操作 (以防 NVM 意外损坏)。在驱动程序初次加载时把该参数设为 0 即可禁用此特性。)

NOTE: The machine must be power cycled (full off/on) when enabling NVM writes
via setting the parameter to zero. Once the NVM has been locked (via the
parameter at 1 when the driver loads) it cannot be unlocked except via power
cycle.
(注意：通过把该参数设为零来启用 NVM 写入时，必须对机器进行断电重启 (完全关机后再开机)。NVM 一旦被锁定 (驱动程序加载时参数为 1)，除非断电重启，否则无法解锁。)

Jumbo Frames(巨型帧)
--------------------

Jumbo Frames support is enabled by changing the Maximum Transmission Unit (MTU)
to a value larger than the default value of 1500.
(通过把最大传输单元 (MTU) 改为大于默认值 1500 的数值，即可启用巨型帧支持。)

Use the ifconfig command to increase the MTU size. For example, enter the
following where <x> is the interface number::
(使用 ifconfig 命令增大 MTU 值。例如，在 <x> 为接口号的地方输入以下命令：)

    ifconfig eth<x> mtu 9000 up

Alternatively, you can use the ip command as follows::
(或者，也可以按如下方式使用 ip 命令：)

    ip link set mtu 9000 dev eth<x>
    ip link set up dev eth<x>

This setting is not saved across reboots. The setting change can be made
permanent by adding 'MTU=9000' to the file:
(此设置在重启后不会保留。要使设置更改永久生效，可把 'MTU=9000' 添加到以下文件中：)

- For RHEL: /etc/sysconfig/network-scripts/ifcfg-eth<x>
  (适用于 RHEL：/etc/sysconfig/network-scripts/ifcfg-eth<x>)
- For SLES: /etc/sysconfig/network/<config_file>
  (适用于 SLES：/etc/sysconfig/network/<config_file>)

NOTE: The maximum MTU setting for Jumbo Frames is 8996. This value coincides
with the maximum Jumbo Frames size of 9018 bytes.
(注意：巨型帧的 MTU 最大设置值为 8996。该值与 9018 字节的最大巨型帧尺寸相对应。)

NOTE: Using Jumbo frames at 10 or 100 Mbps is not supported and may result in
poor performance or loss of link.
(注意：不支持在 10 或 100 Mbps 下使用巨型帧，否则可能导致性能不佳或链路丢失。)

NOTE: The following adapters limit Jumbo Frames sized packets to a maximum of
4088 bytes:
(注意：以下适配器把巨型帧尺寸的数据包限制为最大 4088 字节：)

  - Intel(R) 82578DM Gigabit Network Connection

  - Intel(R) 82577LM Gigabit Network Connection
    (Intel(R) 82577LM 千兆网络连接)

The following adapters do not support Jumbo Frames:
(以下适配器不支持巨型帧：)

  - Intel(R) PRO/1000 Gigabit Server Adapter
    (Intel(R) PRO/1000 千兆服务器适配器)
  - Intel(R) PRO/1000 PM Network Connection
    (Intel(R) PRO/1000 PM 网络连接)
  - Intel(R) 82562G 10/100 Network Connection
    (Intel(R) 82562G 10/100 网络连接)
  - Intel(R) 82562G-2 10/100 Network Connection
    (Intel(R) 82562G-2 10/100 网络连接)
  - Intel(R) 82562GT 10/100 Network Connection
    (Intel(R) 82562GT 10/100 网络连接)
  - Intel(R) 82562GT-2 10/100 Network Connection
    (Intel(R) 82562GT-2 10/100 网络连接)
  - Intel(R) 82562V 10/100 Network Connection
    (Intel(R) 82562V 10/100 网络连接)
  - Intel(R) 82562V-2 10/100 Network Connection
    (Intel(R) 82562V-2 10/100 网络连接)
  - Intel(R) 82566DC Gigabit Network Connection

  - Intel(R) 82566DC-2 Gigabit Network Connection

Speed and Duplex Configuration(速度与双工配置)
----------------------------------------------

In addressing speed and duplex configuration issues, you need to distinguish
between copper-based adapters and fiber-based adapters.
(在处理速度与双工配置问题时，需要区分铜缆适配器和光纤适配器。)

In the default mode, an Intel(R) Ethernet Network Adapter using copper
connections will attempt to auto-negotiate with its link partner to determine
the best setting. If the adapter cannot establish link with the link partner
using auto-negotiation, you may need to manually configure the adapter and link
partner to identical settings to establish link and pass packets. This should
only be needed when attempting to link with an older switch that does not
support auto-negotiation or one that has been forced to a specific speed or
duplex mode. Your link partner must match the setting you choose. 1 Gbps speeds
and higher cannot be forced. Use the autonegotiation advertising setting to
manually set devices for 1 Gbps and higher.
(在默认模式下，使用铜缆连接的 Intel(R) 以太网网络适配器会尝试与其链路伙伴自动协商以确定最佳设置。如果适配器无法通过自动协商与链路伙伴建立链路，可能需要手动把适配器和链路伙伴配置为相同的设置，才能建立链路并传送数据包。只有在尝试与不支持自动协商的旧式交换机建立链路，或与被强制设定为特定速度或双工模式的交换机建立链路时，才可能需要这样做。链路伙伴必须与你选择的设置相匹配。1 Gbps 及更高的速度无法强制设定。可使用自动协商通告 (autonegotiation advertising) 设置来手动配置 1 Gbps 及更高速度的设备。)

Speed, duplex, and autonegotiation advertising are configured through the
ethtool utility.
(速度、双工和自动协商通告通过 ethtool 工具进行配置。)

Caution: Only experienced network administrators should force speed and duplex
or change autonegotiation advertising manually. The settings at the switch must
always match the adapter settings. Adapter performance may suffer or your
adapter may not operate if you configure the adapter differently from your
switch.
(注意：只有经验丰富的网络管理员才应强制设定速度和双工，或手动更改自动协商通告。交换机上的设置必须始终与适配器设置相匹配。如果适配器的配置与交换机不同，适配器性能可能下降，甚至可能无法工作。)

An Intel(R) Ethernet Network Adapter using fiber-based connections, however,
will not attempt to auto-negotiate with its link partner since those adapters
operate only in full duplex and only at their native speed.
(不过，使用光纤连接的 Intel(R) 以太网网络适配器不会尝试与其链路伙伴自动协商，因为这类适配器只能以全双工方式、以其原生速度工作。)


Enabling Wake on LAN (WoL)(启用 Wake on LAN (WoL))
--------------------------------------------------

WoL is configured through the ethtool utility.
(WoL 通过 ethtool 工具进行配置。)

WoL will be enabled on the system during the next shut down or reboot. For
this driver version, in order to enable WoL, the e1000e driver must be loaded
prior to shutting down or suspending the system.
(下次关机或重启时系统将启用 WoL。对于此驱动程序版本，要启用 WoL，必须在关闭或挂起系统之前加载 e1000e 驱动程序。)

NOTE: Wake on LAN is only supported on port A for the following devices:
(注意：对于以下设备，仅端口 A 支持 Wake on LAN：)

- Intel(R) PRO/1000 PT Dual Port Network Connection
  (Intel(R) PRO/1000 PT 双端口网络连接)
- Intel(R) PRO/1000 PT Dual Port Server Connection
  (Intel(R) PRO/1000 PT 双端口服务器连接)
- Intel(R) PRO/1000 PT Dual Port Server Adapter
  (Intel(R) PRO/1000 PT 双端口服务器适配器)
- Intel(R) PRO/1000 PF Dual Port Server Adapter
  (Intel(R) PRO/1000 PF 双端口服务器适配器)
- Intel(R) PRO/1000 PT Quad Port Server Adapter
  (Intel(R) PRO/1000 PT 四端口服务器适配器)
- Intel(R) Gigabit PT Quad Port Server ExpressModule
  (Intel(R) Gigabit PT 四端口服务器 ExpressModule)
