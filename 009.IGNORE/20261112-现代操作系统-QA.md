## 4. 任务 A：L2 Cache、CPU 拓扑与 Linux 调度

### 4.1 核心问题

结合 R1 的 Figure 1-8，判断下列说法是否准确，给出适用条件与更严谨的表述：

> 缓存一致性的维护对内核是无感的（硬件搞定），但缓存拓扑结构对内核是有感的——内核会利用这些信息优化调度策略。

逐项回答：

1. **L2 处理**：内核是否对 L2 进行特殊处理？处理依据是“L2”这个层级，还是缓存属性、共享范围等信息？对应代码在哪里？
2. **拓扑建立**：CPU／缓存拓扑的信息来自哪里，经过哪些初始化路径和数据结构？
3. **调度使用**：拓扑如何影响任务放置、唤醒选核、迁移或负载均衡？对应代码、触发条件和适用范围是什么？
4. **硬件对照**：能否从 CPU／SoC 资料中找到实际拓扑，与 Linux 可见拓扑和调度器视图对应？R2 可作参考，具体芯片配置另行核验。

### 4.2 分析要求

- 限定“缓存一致性维护”和“内核无感”的范围，分别检查普通一致性共享内存、非一致性 DMA、指令与数据缓存同步等场景，区分缓存一致性、内存顺序和显式缓存维护操作。
- 覆盖私有 L2 与共享 L2，说明同一缓存层级在不同平台上可能对应不同共享范围，并解释 L2、cluster、LLC 等概念的关系。
- 从硬件信息／固件描述追踪到内核缓存信息、CPU 拓扑和调度拓扑，分别核对 ACPI/PPTT、Device Tree 等适用路径。
- 以 Linux 7.1.3 源码确认 `cacheinfo`、CPU 拓扑、`sched_domain`、`sched_group` 等检索起点的实际定义、关键字段与关联。
- 至少追踪缓存共享关系参与调度域构建，以及唤醒选核或负载均衡的一条实际路径，区分通用行为与配置／平台相关策略。
- 用有出处的硬件拓扑与内核视图对照；Arm AGI CPU 的具体参数采用任务 D 核验结果，异构场景补充 Cortex-A725／A520。教学 CPU 编号和数字显式标注为示例。

### 6.4 应用专题：全一致性加速器与共享内存
