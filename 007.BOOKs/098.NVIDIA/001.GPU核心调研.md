## 1. 整芯层级：GPU → GPC → TPC → SM → 分区

### 1.1 层级结构【原文+图】

```
GPU（GB202 满配，图形芯片；H100 的差异见树后说明）
 └─ GPC  Graphics Processing Cluster【B p.8–9 原文】
     ├─ Raster Engine（光栅引擎）【B p.9 原文】
     ├─ ROP 分区 ×2（每分区 8 个 ROP）【B p.9 原文】
     └─ TPC ×8  Texture Processing Cluster【B p.8–9 原文】
         ├─ PolyMorph Engine ×1【B p.9 原文】
         └─ SM ×2【B p.9 原文】
             └─ 处理分区 ×4（两代 SM 都是 4 分区；见图 7〔A p.21〕/ 图 5〔B p.11〕）
                 ├─ CUDA Core（标量计算列）：FP32/INT32 + FP64
                 │   （Blackwell：128 个 FP32/INT32 合一；Hopper：128 FP32 + 64 INT32 分列；
                 │     FP64 另有少量独立列——H100 64 个/SM，GB202 仅 2 个/SM）
                 ├─ Tensor Core ×1/分区 → 每 SM ×4
                 ├─ LD/ST ×8（H100 图 7）/ ×4（Blackwell 图 5）、SFU ×1（见图，正文未定义）
                 └─ 寄存器堆 16,384 × 32-bit/分区
             SM 级共享：L1 Data Cache/Shared Memory、Texture Unit ×4、
                        TMA（仅 H100 图中画出）、RT Core ×1（仅 Blackwell）
```

层级命名出处：GPC/TPC/SM 见 [A 物理页 18 · GH100 构成清单](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[B 物理页 8–9 · Blackwell GB202 GPU](nvidia-rtx-blackwell-gpu-architecture.pdf#page=8)。GPC 内 8 TPC、TPC=PolyMorph+2SM 见 [B 物理页 9](nvidia-rtx-blackwell-gpu-architecture.pdf#page=9)；A 侧 9 TPC/GPC 见 [A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)。
【原文】H100 侧差异：GH100 满配为 8 GPC / 72 TPC（9 TPC/GPC）/ 144 SM，且 "primarily built for executing datacenter and edge compute workloads for AI, HPC, and data analytics, but not graphics processing"（[A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)）——树里的 Raster Engine / ROP / PolyMorph Engine 是图形芯片的组成，A 白皮书未列出 H100 的对应单元【文档未说明】。
【推断】两份白皮书正文都没有用 "partition" 指代 SM 内的这 4 个分块（A 里的 partition 指 MIG 分区或 L2 crossbar 分区，B 里指 ROP 分区或 PTLAS 分区），4 分块结构只在图中呈现；Volta 白皮书称之为 "processing block (partition) within an SM"（见 §8.3），本文按图转述。

## 2. CUDA Core

### 2.1 一句话功能
【原文+推断】SM 内的标量通用计算核心，逐标量执行 FP32/INT32（部分场景 FP16/BF16）指令，是 GPU 上的"通用算力"；与做整块矩阵乘的 Tensor Core 分工（见 §3.1）。文档对 CUDA Core 没有独立定义章节，其职能由两处原文侧面给出：地址生成（[B 物理页 5](nvidia-rtx-blackwell-gpu-architecture.pdf#page=5)）与"为 Tensor Core 做数据预处理/后处理"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。

### 2.2 架构
- 数量：每 SM 128 个【A 物理页 18 / B 物理页 10 原文】；芯片级数量见 §1.2 表。
- 组织【图】：每分区一列计算单元；Hopper 图 7 里是 INT32、FP32、FP32、FP64 四列（INT32 一列、FP32 两列、FP64 一列）；Blackwell 图 5/图 6 里合成一整块 "FP32 / INT32"（图注："Ada SM was designed & optimized for standard shaders. Blackwell SM was designed & optimized for neural shaders."）【A p.21 / B p.11–12 已读图】。
- INT32 口径差异【原文】：H100 = 128 FP32 + **64** INT32（[A 物理页 39 Table 3](nvidia-h100-tensor-core-gpu-architecture.pdf#page=39)：表行 "INT32 Cores / SM" 的 H100 两列均为 64）；Blackwell = 128 全统一【B 物理页 12 原文】。
- FP64：独立小核。GB202 每 SM 2 个、全芯片 384 个，速率仅 FP32 的 1/64，目的是"ensure any programs with FP64 code operate correctly"【B 物理页 8 原文】；H100 则是正经 64 个/SM + FP64 Tensor Core（[A 物理页 39](nvidia-h100-tensor-core-gpu-architecture.pdf#page=39)）——数据中心卡仍保留 FP64 算力。

### 2.3 执行流程
【推断】两份白皮书都只给框图不给流水。按 CUDA 编程模型与图 7/图 5 转述：Warp Scheduler（32 thread/clk）每周期向 Dispatch Unit 送一条 warp 指令 → 进入某列计算单元执行；操作数来自本分区寄存器堆（16,384×32-bit）；访存指令经 LD/ST 单元走 L1 → L2 → 显存。发射宽度、双发射等细节【文档未说明】。warp 调度、顺序发射、占用率限制的 CUDA 指南原文见 §8.1。

### 2.4 使用场景
- 图形着色器、通用 CUDA kernel【推断：CUDA 平台常规用途】。
- 地址生成类整数负载【原文】："doubling of throughput per clock cycle for many integer math operations … increase the performance of address generation workloads that are crucial for neural shading"（[B 物理页 5](nvidia-rtx-blackwell-gpu-architecture.pdf#page=5)）。
- AI 管线的预处理/后处理【原文】：A p.17 "most other CUDA threads can be focused on general-purpose computations, such as pre-processing and post-processing data for the new generation of Tensor Cores"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。

### 2.5 对 AI 模型的支持
- **不承担主算力**：矩阵乘走 Tensor Core（"specialized high-performance compute cores for matrix multiply and accumulate (MMA) math operations"【A p.22 原文】）；"CUDA Core 不做矩阵乘"文档没有直接论断，标【推断】。
- **辅助角色有原文**：数据预处理/后处理（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）、地址生成（[B 物理页 5](nvidia-rtx-blackwell-gpu-architecture.pdf#page=5)）。【推断】大模型推理中的逐元素算子（激活、残差、norm 类）属于这类逐标量工作，落在 CUDA Core 上，文档未点名。
- FP64【原文+推断】：定位是程序正确性（B p.8），不参与 LLM 训练/推理主链路【推断】。

### 2.6 Hopper → RTX Blackwell 的变化
- FP32/INT32 **完全统一**：多数整数指令吞吐最高 ×2（up to）；同一周期只能当 FP32 或 INT32 之一；并非所有 INT 指令都能 2×（[B 物理页 12 原文](nvidia-rtx-blackwell-gpu-architecture.pdf#page=12)）。
- 体现在规格表：INT32 TOPS（non-Tensor）4090=41.3 → 5090=104.8，与 FP32 完全相等（[B 物理页 46–47 Table 3](nvidia-rtx-blackwell-gpu-architecture.pdf#page=46)）；H100 的 INT32 TOPS（25.6–33.5）只有 FP32 TFLOPS（51.2–66.9）的一半（[A 物理页 39–40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=39)）。
- 表行 "Peak FP32 TFLOPS (non-Tensor)" 与 "Peak TF32 Tensor TFLOPS" 的区别——数字【原文】：5090 前者为 104.8，后者为 104.8/209.5（稀疏）（[B 物理页 46–47 Table 3](nvidia-rtx-blackwell-gpu-architecture.pdf#page=46)）。解释【推断，背景知识，非文档内容】：FP32 行是 CUDA Core 的标量路径，TF32 行是 Tensor Core 的矩阵路径；TF32 是一种 19 位浮点格式（1 符号 + 8 指数 + 10 尾数），不是"19 位尾数"。文档未解释两者的关系（CUDA 指南对 TF32 的表述与这里的说法一致，见 §8.2④）。

### 2.7 文档缺口
寄存器堆/LD/ST/SFU 的定义（仅在图中出现）；每周期发射/双发射策略；CUDA Core 在 GEMM 前后的确切参与比例；FP16/BF16 在标量路径的速率语义：A Table 1 p.20 的 "Peak FP16" 行给 133.8，Table 3 的行名是 "Peak FP16 TFLOPS (non-Tensor)" 与 "Peak BF16 TFLOPS (non-Tensor)"，SXM5 列的值都是 133.8（[A 物理页 39](nvidia-h100-tensor-core-gpu-architecture.pdf#page=39)），即 H100 非 Tensor 路径的 FP16/BF16 峰值 = 2 × FP32（66.9）；RTX 5090 的对应三行（FP16/BF16/FP32 non-Tensor）都是 104.8（[B 物理页 47](nvidia-rtx-blackwell-gpu-architecture.pdf#page=47)），没有这个 2×。成因两份文档都没解释。发射机制、占用率限制与寄存器上限已由 §8.1 补上。

## 3. Tensor Core（重点）

### 3.1 一句话功能与本质区别
【原文】"Tensor Cores are specialized high-performance compute cores for matrix multiply and accumulate (MMA) math operations"（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）。
【推断，部分已有原文】与 CUDA Core 的本质区别：CUDA Core 一次算一对标量的 FMA；Tensor Core 一次完成一小块矩阵的乘加。"D=A×B+C" 这一点有原文——第一代就这么定义（§8.3），warp 级接口也写成 D=A*B+C（§8.2①）；"数据复用在硬件内部，单位面积吞吐高一个量级"仍是推断。

### 3.2 架构
- 数量：每 SM 4 个（两代同）【A p.18 / B p.10 原文】；每分区 1 个（图 7/图 5）。
- 代际：Hopper = 第 4 代，支持 FP8/FP16/BF16/TF32/FP64/INT8 MMA（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）；Blackwell = 第 5 代，在 Hopper 基础上**新增 FP4/FP6** 与第二代 FP8 Transformer Engine（[B 物理页 15](nvidia-rtx-blackwell-gpu-architecture.pdf#page=15)）。
- 每芯片：H100 SXM5 528 个、RTX 5090 680 个（§1.2 表）。
- MMA 切片形状、寄存器要求：两份白皮书未给；CUDA 指南、PTX ISA 与 Volta 白皮书的说法见 §8.2、§8.3。

### 3.3 执行流程
【推断，依据 A p.29–35 原文组件拼装】TMA 把下一块数据从显存异步搬进 shared memory（硬件生成地址）→ Cluster/DSMEM 在多 SM 间分摊数据 → warp 发出 MMA 指令，操作数从寄存器堆进入 Tensor Core → 结果写回寄存器/shared → 事务屏障同步下一批。整条链路"end-to-end asynchronous pipelines … completely overlapping and hiding data movement with computation"（[A 物理页 17 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。

### 3.4 使用场景
- AI 训练与推理【原文】："Tensor Cores provide groundbreaking performance for the matrix computations that are critical for both deep learning neural network training and inference operations."（[B 物理页 15](nvidia-rtx-blackwell-gpu-architecture.pdf#page=15)）；H100 侧的适用面写作 "AI and HPC applications"（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）。
- 图形内的 AI（Blackwell）【原文】：DLSS 4 的光流、帧生成以及 SR/RR/DLAA 模型都由 Tensor Core 执行（[B 物理页 36–37](nvidia-rtx-blackwell-gpu-architecture.pdf#page=36)）；经 Cooperative Vectors API，像素、光追等着色器也能直接访问 Tensor Core（[B 物理页 40](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)）。
- HPC【原文】：A 白皮书列有 FP64 Tensor Core（见 §3.5 表）。

|---|---|---|
| FP8（FP16 累加） | 1978.9 / 3957.8 TFLOPS | 838 / 1676 TFLOPS |

- 累加精度对速率的影响【原文数字】：RTX 5090 改用 FP32 累加时减半——FP8 为 419/838、FP16 为 209.5/419（[B 物理页 47 Table 3](nvidia-rtx-blackwell-gpu-architecture.pdf#page=47)）；H100 SXM5 的 FP8、FP16 在 FP16 与 FP32 两种累加下速率相同（[A 物理页 39 Table 3](nvidia-h100-tensor-core-gpu-architecture.pdf#page=39)）。【推断】对累加精度敏感的环节，两张卡的行为不同。

- 代际提速（H100 SXM5 对 A100，[A 物理页 26 Table 2](nvidia-h100-tensor-core-gpu-architecture.pdf#page=26)）：FP8 TC 6.3×（H100 FP8 TC 对 A100 FP16 TC——A100 没有 FP8）、FP16/BF16/TF32/INT8 TC 3.2×、FP64 TC 3.4×、FP32 标量 3.4×。

### 3.6 FP8 / FP4 解决什么问题
- **FP8（Hopper 引入）**【原文】：E4M3（4 指数 3 尾数，重精度）与 E5M2（5 指数 2 尾数，重动态范围）两种编码（[A 物理页 23](nvidia-h100-tensor-core-gpu-architecture.pdf#page=23)）；"FP8 halves data storage requirements and doubles throughput compared to FP16 or BF16"（同页）。
- **FP4（Blackwell 引入）**【原文】："Compared with FP16 precision — the default method that most models publish with — FP4 requires less than half of the memory, and 50 Series GPUs provide over 2x performance compared to the previous generation. FP4 allows virtually no loss in quality with advanced quantization methods offered by the NVIDIA TensorRT Model Optimizer"（[B 物理页 16](nvidia-rtx-blackwell-gpu-architecture.pdf#page=16)）。端到端实例：FLUX.dev 由 FP16 >23 GB 显存 → FP4 <10 GB；4090 FP16 15 秒 → 5090 FP4 5 秒出头（同页）。
- FP4 的累加精度：Table 3 只列了 FP32 累加一档（"Peak FP4 Tensor TFLOPS with FP32 Accumulate (FP4 AI TOPS)"，[B 物理页 47](nvidia-rtx-blackwell-gpu-architecture.pdf#page=47)）。FP4 的位级编码两份白皮书均未出现（常见说法 E2M1 属背景知识），NVIDIA 官方博客的说明见 §8.7。

### 3.7 Transformer Engine 逐层工作流程【原文+图 25 已读图】

```
第 N 层输入 → H100 Tensor Core 计算（当前精度）
                │ 输出统计值（statistics）
   下一层信息 ──┤   （下一层的类型 + 所需精度）
                ▼
        Range Analysis ──► 目标格式 + 缩放因子 ──► Adaptive Format Conversion
                （图例：橙=自适应精度，紫=高精度，黑=辅助数据；见图 25）
                ▼
        以自适应精度写回显存 → 供第 N+1 层读取
```

原文依据："the Transformer Engine analyzes the statistics of the output values produced by the Tensor Core. With knowledge about which type of neural network layer comes next and what precision it requires, the Transformer Engine also decides which target format to convert the tensor to before storing it to memory … dynamically scales tensor data into the representable range using scaling factors computed from the tensor statistics"（[A 物理页 46](nvidia-h100-tensor-core-gpu-architecture.pdf#page=46)）。
收益口径【原文】："up to 9x faster AI training and up to 30x faster AI inference speedups on large language models"（[A 物理页 11 / p.19](nvidia-h100-tensor-core-gpu-architecture.pdf#page=11)）。背景：Transformer 模型 5 年间每两年增长 275×（[A 物理页 44](nvidia-h100-tensor-core-gpu-architecture.pdf#page=44)）。Blackwell 侧为第二代 FP8 Transformer Engine【B 物理页 15 原文，一句带过，细节文档未说明】。

### 3.8 稀疏加速是什么
【原文】"The Sparsity feature exploits fine-grained structured sparsity in deep learning networks, doubling the performance of standard Tensor Core operations"（[A 物理页 11](nvidia-h100-tensor-core-gpu-architecture.pdf#page=11)）。【推断，背景知识，非文档内容】通常指 2:4 结构化稀疏：每 4 个元素至少 2 个为零（NVIDIA 官方博客的原始定义与压缩、元数据机制见 §8.8），故有效吞吐记为 ×2（各表"稀疏列"）。元数据位宽与存储布局【文档未说明】。

### 3.9 大模型证据（逐条原文）
- LLM 训练/推理收益最高 9×/30×（"up to"；A p.19 的写法是 "up to 9x … and 30x"）【A p.11、p.19 原文】。
- 万亿参数模型与并行需求【A p.8 原文："trillion parameter AI models"】；MT-NLG 训练曾需 2048×A100×8 周【A p.44 原文】。
- 消费卡侧生成式实例：DLSS 4 的 SR/RR/DLAA 全部转 Transformer 模型，"ingest 2x more parameters, while also using more Tensor Core processing power"（[B 物理页 37](nvidia-rtx-blackwell-gpu-architecture.pdf#page=37)）；MFG 每个传统渲染帧最多再生成 3 帧（"up to three additional frames"），帧生成模型快 40%、省 30% 显存（[B 物理页 35](nvidia-rtx-blackwell-gpu-architecture.pdf#page=35)）；FLUX.dev FP4 实例（[B 物理页 16](nvidia-rtx-blackwell-gpu-architecture.pdf#page=16)）。
- A Fig.3（p.9）H100 vs A100 各 workload 加速比图含 GPT-3/MT-NLG/MoE（未读图，仅目录定位）。

### 3.10 Hopper → RTX Blackwell 的变化
- 代际与数量【原文】：第 4 代 → 第 5 代，每 SM 仍是 4 个（[A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[B 物理页 10](nvidia-rtx-blackwell-gpu-architecture.pdf#page=10)）。
- 新增数据格式【原文】：在 FP16/BF16/TF32/INT8/FP8 之外新增 FP4、FP6（[B 物理页 15](nvidia-rtx-blackwell-gpu-architecture.pdf#page=15)）；FP4 的收益见 §3.6。
- Transformer Engine【原文】：Hopper 的 FP8 Transformer Engine → 第二代 FP8 Transformer Engine（同页 B p.15，B 白皮书仅一句带过）。
- 访问路径【原文】：此前神经渲染走 CUDA（"using CUDA to harness the Tensor Cores"），Blackwell 起图形着色器可经 Cooperative Vectors API 直接访问 Tensor Core（[B 物理页 40](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)）。
- 负载变化【原文】：DLSS 模型由 CNN 转 Transformer，参数量 2×、占用更多 Tensor Core 算力（[B 物理页 37](nvidia-rtx-blackwell-gpu-architecture.pdf#page=37)）。

- **数据中心级 Blackwell 的 TC 精度表**【原文·网页】：Tensor Core 支持 NVFP4、FP64、TF32、BF16、FP16、FP8/FP6、INT8；CUDA Core 支持 FP64、FP32、FP16、BF16（同页规格表，脚注 "Preliminary specifications"）。【推断】对照 B 白皮书：RTX Blackwell 的 TC 同样支持 FP4 与 FP6（[B 物理页 15](nvidia-rtx-blackwell-gpu-architecture.pdf#page=15)），两份资料在低精度格式上一致；差别在 FP64——GB202 只有 "a very minimal number of FP64 Tensor Cores"（[B 物理页 8](nvidia-rtx-blackwell-gpu-architecture.pdf#page=8)），而该规格表把 FP64 列为常规精度。另：网页称 NVFP4，B 白皮书只写 FP4——两者的关系见 §8.7。
- **FP32/FP64 的软件模拟路线**【原文·网页】："NVIDIA Blackwell and Rubin architectures can emulate FP32 and FP64 matrix operations by decomposing input values and leveraging high-throughput, lower-precision Tensor Cores … matching or even exceeding native IEEE754 accuracy."——在 FP64 硬件之外出现了"低精度 TC + 软件算法模拟高精度"的路线，关联 §2.5 与 §7.2 对 FP64 定位的讨论。
- **第二代 Transformer Engine 的改进点**（补 §3.11 缺口）【原文·网页】："The second-generation Transformer Engine uses custom NVIDIA Blackwell Tensor Core technology combined with NVIDIA® TensorRT™-LLM and NeMo™ Framework innovations to accelerate inference and training for large language models (LLMs) and mixture-of-experts (MoE) models. The Transformer Engine is fueled by the Tensor Cores’ FP4 precision, doubling performance and efficiency while maintaining high accuracy for current and next-generation MoE models."——第二代 TE 的核心变化是由 FP4 供料，并与 TensorRT-LLM、NeMo 框架协同（同页，2026-11-27 复核仍在）。
- **Blackwell 对 Hopper 的整代收益**【原文·网页】："The NVIDIA Blackwell architecture delivers a 30X speedup compared to the previous NVIDIA Hopper™ generation for massive models such as GPT-MoE-1.8T."——这是数据中心的 Blackwell，不能套到 GB202 上（同页）。
- **下一代 Rubin（超出两份白皮书时间线，仅作方向）**【原文·网页】：增强第 5 代 TC，优化 NVFP4/FP8，与 SM 中扩展的 SFU 紧密集成加速注意力与稀疏路径；单 GPU 50 PFLOPS Transformer Engine，Vera Rubin NVL72 系统级 3600 PFLOPS NVFP4 推理。

## 4. 其他核心与固定功能单元

### 4.1 RT Core（仅图形芯片）
1. **功能**【原文】：专用光线追踪硬件——BVH 遍历、光线-盒子求交、光线-三角形求交，"work is offloaded from the SM"（[B 物理页 17](nvidia-rtx-blackwell-gpu-architecture.pdf#page=17)）。
2. **架构**【原文+图】：每 SM 1 个（Blackwell）【B p.10】；H100/A100 **没有** RT Core（"they do not include … NVIDIA RT Cores"，[A 物理页 40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）。第 4 代含 5 个引擎（见图 9）：Box Intersection、**Triangle Cluster Intersection（新增）**、**Linear Swept Spheres（新增）**、Opacity Micromap（Ada 已有）、**Triangle Cluster Compression（新增）**（[B 物理页 17](nvidia-rtx-blackwell-gpu-architecture.pdf#page=17)）。
3. **流程**【原文改述】：应用建加速结构——Mega Geometry 以 CLAS（≤256 三角形的簇级结构）为一级原语构造 BVH，PTLAS 分区更新顶层【B p.18–21】→ 着色器发射光线 → RT Core 遍历求交 → 回 SM 着色。
4. **场景**【原文】：光追游戏/渲染器；Nanite 全精度光追（不再降级代理网格）；位移细分曲面；毛发/草（常见用例——如人物头发——LSS 比 DOTS 快约 2×、显存省约 5×，[B 物理页 23](nvidia-rtx-blackwell-gpu-architecture.pdf#page=23)）。
5. **AI 支持**：不参与大模型训练/推理【推断】。RT 应用中的神经着色加速由 Tensor Core 承担，SER 负责把成簇神经线程直送 TC（[B 物理页 24 原文](nvidia-rtx-blackwell-gpu-architecture.pdf#page=24)）——功劳记在 TC，不在 RT Core。
6. **变化**【原文】：光线-三角形求交 2×；簇压缩把 Nanite 类场景显存省几百 MB（[B 物理页 22](nvidia-rtx-blackwell-gpu-architecture.pdf#page=22)）；"RT TFLOPS" 指标（5090=317.5，[B p.47](nvidia-rtx-blackwell-gpu-architecture.pdf#page=47)）文档未给计算口径【文档未说明】。
7. **缺口**：RT TFLOPS 口径；Opacity Micromap 的具体解码流程（B 只给一句：该引擎 "evaluates Opacity Micromaps and directly alpha-tests geometry to significantly reduce shader-based alpha computations"，[B 物理页 17](nvidia-rtx-blackwell-gpu-architecture.pdf#page=17)）。

### 4.2 Texture Unit（纹理单元）
【原文】取 texel、过滤、坐标处理（[B 物理页 12](nvidia-rtx-blackwell-gpu-architecture.pdf#page=12)）；5090 有 680 个（4090 为 512）；点采样速率比 Ada 翻倍（[B 物理页 13](nvidia-rtx-blackwell-gpu-architecture.pdf#page=13)）。H100 也有 528 个（[A p.40 Table 3](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）——服务于 GPU 计算中的纹理缓存通路【推断】。AI 关联：随机纹理过滤（STF）为神经纹理压缩（NTC，相对块压缩最高 7:1，up to）服务（[B 物理页 40–42 原文](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)；"seven-to-one VRAM compression" 一句在 p.40）——属于图形内 AI 的配套，不参与 LLM【推断】。

### 4.3 ROP / Raster Engine / PolyMorph Engine
【原文】纯图形固定功能：GPC 内 1 个 Raster Engine + 2×8 ROP；TPC 带 1 个 PolyMorph Engine（[B 物理页 9](nvidia-rtx-blackwell-gpu-architecture.pdf#page=9)）。H100 无显示输出、定位非图形（[A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[A 物理页 40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）。不参与大模型【推断】。

### 4.4 Optical Flow Engine（光流引擎）
位于整芯图芯片前端（见图 3）。**被 AI 取代的现成案例**【原文】：DLSS 4 "replacing hardware optical flow with a very efficient AI model"（[B 物理页 35](nvidia-rtx-blackwell-gpu-architecture.pdf#page=35)）——上一代的专用固定功能单元，这一代由 Tensor Core 上的模型替代。不参与 LLM【推断】。

### 4.5 NVENC / NVDEC / NVJPG（视频与图像引擎）
- H100：**7×NVDEC + 7×NVJPG**，定位就是 DL 数据加载——视频解码跟不上训练就吃不满 GPU（[A 物理页 58 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=58)）；JPEG 解码是图像 DL 的基础瓶颈（[A 物理页 59 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=59)）；DALI 库自动调度【A p.59 原文】。每个 MIG 实例可以分到至少 1×NVDEC + 1×NVJPG（"can receive at least one"，[A 物理页 44 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=44)）。
- Blackwell：NVENC 第 9 代（AV1 UHQ、4:2:2）、NVDEC 第 6 代（H.264 解码 2×）（[B 物理页 28–30](nvidia-rtx-blackwell-gpu-architecture.pdf#page=28)）——面向创作/直播，非 AI【推断】。
- **AI 支持**：多模态输入侧（视频/图像 → 张量）参与训练与推理【原文 A p.58–59】。
- 注意：H100 **无 NVENC**（[A p.40 脚注原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）。

### 4.6 AMP（AI Management Processor）
【原文】"a fully programmable context scheduler on the GPU designed to offload scheduling of GPU contexts from the system CPU"，实现为 GPU 管线前端的专用 RISC-V 处理器（[B 物理页 25](nvidia-rtx-blackwell-gpu-architecture.pdf#page=25)）；对接 Windows HAGS 模型。对 AI 的直接收益【原文】："With LLMs, it does this by reducing the time to first response"（[B 物理页 26](nvidia-rtx-blackwell-gpu-architecture.pdf#page=26)）；AMP 改善 DLSS AI 处理、图形渲染与帧 pacing 算法的调度（原文是 "better scheduling of"，[B 物理页 36](nvidia-rtx-blackwell-gpu-architecture.pdf#page=36)）。Hopper 白皮书无对应单元【文档未说明其有无】；B 也未称 AMP 是 Blackwell 新增（[B 物理页 6](nvidia-rtx-blackwell-gpu-architecture.pdf#page=6) 的要点列表里，别的条目带 "New"，AMP 这条不带）。

### 4.7 GigaThread Engine / SFU / LD/ST
仅在框图出现：GigaThread Engine 在整芯图顶部（见 B 图 3、A 图 6〔p.19〕）；每分区 LD/ST 8 个（H100 图 7）或 4 个（Blackwell 图 5）+ SFU 1 个。职能正文均未定义【文档未说明】。【推断】GigaThread=全局线程块分发器；SFU=特殊函数单元（三角函数等）；LD/ST=访存单元。

### 4.8 DPX 指令（Hopper 新增）
【原文】动态规划指令，最多 7× 于 Ampere；代表算法 Smith-Waterman（基因测序）、Floyd-Warshall（机器人路径）（[A 物理页 11、p.27](nvidia-h100-tensor-core-gpu-architecture.pdf#page=11)；附录 C [A 物理页 68](nvidia-h100-tensor-core-gpu-architecture.pdf#page=68) 只展开 Smith-Waterman 的基因组应用）。属于 SM 指令集扩展而非独立单元【推断：由表述 "new dedicated hardware instructions" 推得，A p.68 原文】。不参与 LLM 主链路【推断】。

### 4.9 TMA / Thread Block Cluster / DSMEM / 异步事务屏障（Hopper 新增执行家族）
- **TMA**【原文】：global↔shared 的大块、多维（1D–5D）张量异步搬运；单线程发 copy descriptor，地址生成与搬运全硬件化（[A 物理页 32–33](nvidia-h100-tensor-core-gpu-architecture.pdf#page=32)）；定位 "To help feed the powerful new H100 Tensor Cores"（同页）——**AI 供数主通道**。A100 时代的 LDGSTS 需要线程自己算地址、循环搬运，TMA 全部接管【A p.33 原文】。CUDA 指南对 TMA 的定位与之一致（"The primary goal of the TMA is to provide an efficient data transfer mechanism from global memory to shared memory for multi-dimensional arrays."，[C 物理页 395](cuda-programming-guide.pdf#page=395)）。
- **Thread Block Cluster**【原文】：比 Thread Block 更大一层的局部性单元，"guaranteed to be concurrently scheduled onto a group of SMs"，在 GPC 内运行，最多 16 个 Thread Block/Cluster（[A 物理页 29、41](nvidia-h100-tensor-core-gpu-architecture.pdf#page=29)）；层级变为 Threads→Thread Blocks→Clusters→Grids。
- **DSMEM**【原文】：Cluster 内跨 SM 直读写对方 shared memory（load/store/atomic），比走全局内存快约 7×（[A 物理页 30](nvidia-h100-tensor-core-gpu-architecture.pdf#page=30)）。
- **异步事务屏障**【原文】：分裂屏障（Arrive/Wait）基础上加"事务计数"（字节数），Wait 等到所有 Arrive 且字节数达标（[A 物理页 34–35](nvidia-h100-tensor-core-gpu-architecture.pdf#page=34)）；Cluster 的 TB 间数据交换构建在其上。
- **AI 支持**【原文】：这几件合起来是 "the first truly asynchronous GPU"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）的支撑件，服务 Tensor Core 供数与多 SM 协作【推断：具体到 LLM kernel 的用法文档未展开】。

### 5.2 卡内互连：NVLink / NVSwitch / NVLink Switch System【原文】
- **NVLink4**：900 GB/s 总带宽 = 7× PCIe Gen5；对 all-reduce 3×；18 条链路（A100 为 12 条 600 GB/s）（[A 物理页 12、47](nvidia-h100-tensor-core-gpu-architecture.pdf#page=47)）。PCIe 版可用桥接两卡 600 GB/s（[A 物理页 15](nvidia-h100-tensor-core-gpu-architecture.pdf#page=15)）。**用途**【原文】：万亿参数模型的训练需要集群内每块 GPU 之间高速、无缝的通信，PCIe 带宽会成为瓶颈（"requires high-speed, seamless communication between every GPU in a server cluster. PCIe creates a bottleneck with its limited bandwidth"，[A 物理页 47](nvidia-h100-tensor-core-gpu-architecture.pdf#page=47)）；白皮书也点名 "workloads that require model parallelism across multiple GPU-accelerated nodes"（句子跨页，[A 物理页 8–9](nvidia-h100-tensor-core-gpu-architecture.pdf#page=8)）。具体的并行策略（张量并行、流水线并行的做法）文档未展开。
- **NVSwitch3**：节点内交换机，64 端口、13.6 Tbps；硬件卸载集合通信（multicast/SHARP），"significantly reduces the load on SMs"（[A 物理页 47–48](nvidia-h100-tensor-core-gpu-architecture.pdf#page=48)）——省出的 SM 可回计算【推断】。
- **NVLink Switch System**：节点间二级交换，最多 32 节点/256 GPU，57.6 TB/s all-to-all，可组 1 exaFLOP FP8 稀疏算力（[A 物理页 12、48](nvidia-h100-tensor-core-gpu-architecture.pdf#page=48)）；文中注明该系统当时尚未出货【原文脚注】。Blackwell 侧 5090 为 PCIe Gen5 单卡【B p.48 原文】；B 白皮书未提消费卡 NVLink【文档未说明】。
- **PCIe Gen5**：128 GB/s（双向各 64）；原生 PCIe 原子操作、SR-IOV（[A 物理页 49–50](nvidia-h100-tensor-core-gpu-architecture.pdf#page=49)）。
- **主机↔GPU 的另一条路**：Grace Hopper 的 NVLink-C2C（900 GB/s、硬件缓存一致），以及 GB300 NVL72 里 72 块 GPU 同属一个 NVLink 域的系统形态，见 §8.5、§8.6。

### 5.3 MIG（多实例 GPU）【原文】
最多 7 个 GPU Instance；每实例独占显存全通路（crossbar 端口、L2 bank、显存控制器、DRAM 地址总线），保证时延/吞吐可预测（[A 物理页 42–43](nvidia-h100-tensor-core-gpu-architecture.pdf#page=43)）；每个实例可以分到至少 1×NVDEC + 1×NVJPG（[A 物理页 44](nvidia-h100-tensor-core-gpu-architecture.pdf#page=44)）；比 A100 实例算力 ~3×、带宽 ~2×（[A 物理页 11–12](nvidia-h100-tensor-core-gpu-architecture.pdf#page=11)）。**AI 用途**【原文】：面向推理负载的多实例隔离（"uniquely positioned to accelerate inference workloads like image recognition, recommender systems, and natural language processing"，[A 物理页 14](nvidia-h100-tensor-core-gpu-architecture.pdf#page=14)）；"CSP" 出自 [A p.42](nvidia-h100-tensor-core-gpu-architecture.pdf#page=42) 的 "Example CSP MIG Configuration" 图。B 白皮书未提 RTX Blackwell 是否支持 MIG【文档未说明】。

【推断·总结】单次前向的瓶颈在两处：算（Tensor Core 的 MMA 吞吐）与供数（把权重位宽压到 FP8/FP4 正是为了缓解显存带宽/容量瓶颈——FP4 相对 FP16 "requires less than half of the memory"【B p.16 原文】+ FP8 存储减半吞吐翻倍【A p.23 原文】可佐证这一设计动机，因果归联标【推断】）。

## 7. 汇总

### 7.0 概念辨析：为什么是"CUDA 生态"而不是"Tensor 生态"

一句话【推断】：**Tensor Core 是 SM 里的硬件部件，CUDA 是驾驭全部部件（含 Tensor Core）的软件平台**——二者是上下层关系，不是并列的两个"核家族"。名字撞车源于营销命名：SM 里那 128 个 FP32 标量通道的部件名本可与 Tensor Core 并无关联，NVIDIA 将其命名为 "CUDA Core"（[A 物理页 18 "FP32 CUDA Cores"](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[B 物理页 10 "includes128 CUDA Cores"](nvidia-rtx-blackwell-gpu-architecture.pdf#page=10)），才造成"CUDA 和 Tensor 是两个核"的误会。

```
应用层：AI / 科学计算应用与领域框架【原文 A p.63 "application-specific libraries and frameworks"；A 点名的有 RAPIDS、DALI、Omniverse（p.63–64），PyTorch、NeMo、TensorFlow 全文未出现，TensorRT 只在 p.71 的商标声明里；Fig.31 未读图】
   │
CUDA 平台（"生态"的实体，纯软件）【原文：章节名】
   ├─ 语言与编译器：CUDA C++、Languages and Compilers【A p.65】
   ├─ 运行时/编程模型：thread → block → cluster → grid【A p.29 原文】
   └─ 库：High-Performance Libraries and Frameworks【A p.63：线性代数 cuBLAS、深度神经网络 cuDNN、集合通信 NCCL】——矩阵乘在此翻译成 MMA 指令【推断】
   │
硬件层：SM（两类部件共存于同一 SM）
   ├─ CUDA Core：标量 FP32/INT32 通道（§2）
   └─ Tensor Core：MMA 矩阵部件（§3，无独立指令流）
```

三个白皮书事实：

1. **CUDA 平台早于 Tensor Core 约十年**【原文 + 推断】："Over 15 years ago, NVIDIA introduced the CUDA parallel computing platform with the G80 GPU"（[A 物理页 6](nvidia-h100-tensor-core-gpu-architecture.pdf#page=6)）——G80 是纯 CUDA Core 时代；第一个 Tensor Core 到 Volta 才出现："Tensor Cores were first introduced in the NVIDIA Tesla® V100 GPU"（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）。【推断】"十年"是按 G80 于 2006 年、V100 于 2017 年推出推算的（年份属背景知识，A 未给）；是"Core"沾了平台的名，不是相反。
2. **Tensor Core 没有独立的大脑**【原文】：取指、调度、喂料、同步由 CUDA 编程模型的设施承担（以下引句为原文，归纳为【推断】）——TMA 由"single thread in a warp is elected to issue"发起（[A 物理页 33](nvidia-h100-tensor-core-gpu-architecture.pdf#page=33)），多数 CUDA 线程"focused on general-purpose computations, such as pre-processing and post-processing data for the new generation of Tensor Cores"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。B 白皮书一句最直白："using CUDA to harness the Tensor Cores"（[B 物理页 40](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)）。
3. **白皮书自己把生态归在 CUDA 名下**【原文】：库、系统软件、语言与编译器统一收录在 "Appendix B - NVIDIA CUDA Platform Update"（[A 物理页 63–67](nvidia-h100-tensor-core-gpu-architecture.pdf#page=63)）：线性代数 cuBLAS、深度神经网络 cuDNN、集合通信 NCCL（[A 物理页 63](nvidia-h100-tensor-core-gpu-architecture.pdf#page=63)），NVVM/PTX 编译栈（[A 物理页 65](nvidia-h100-tensor-core-gpu-architecture.pdf#page=65)）。A 的可检索正文里没有 PyTorch、NeMo，TensorRT 只出现在 p.71 的商标声明——软件栈以 CUDA 为名组织，而不是以 Tensor Core 为名。

为什么"生态"落在 CUDA 头上（"实体"一行有 A p.63–65 原文支撑，其余为【推断，归纳】）：

| 判断依据 | CUDA | Tensor Core |
|---|---|---|
| 实体 | 编程模型+编译器+运行时+库+工具链，横跨 GeForce/数据中心全线 | SM 里的一类矩阵部件 |
| 覆盖面 | 所有 NVIDIA GPU 都跑 CUDA（H100 无图形输出也照样是 CUDA 平台，[A p.40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)） | 可选加速件：G80~Pascal 没有；同代产品线也不都有 |
| 能否独立使用 | 是基底本身 | **不能脱离 CUDA 工具链**——Tensor Core 特性集只经 CUDA 编译工具链提供（内联 PTX），官方建议经 cuDNN/cuBLAS/cuFFT/CUTLASS 使用（CUDA 指南，见 §8.2⑤） |
| 壁垒所在 | 十年积累的库与框架集成、存量代码 | 无独立壁垒：可移植部分（WMMA 等）经同一套 CUDA API 暴露（compute capability 7.0→8.0→9.0，[A p.41 Table 4](nvidia-h100-tensor-core-gpu-architecture.pdf#page=41)）；但每代最新的 TC 指令是架构专属特性，要按计算能力单独编译（见 §8.2⑥） |

类比【推断】：如同说"x86 生态"而不说"AVX-512 生态"——扩展单元被平台收编，Tensor Core 就是 CUDA 世界里带独立硬件的"AVX-512"。对执行大模型而言两者都要在场（§7.2 的排序不变），但生态归属、软件粘性、迁移成本，全部记在 CUDA 一侧。

### 8.1 CUDA Core 怎么被调度执行（补 §2.3、§2.7）

| 原文摘录 | 说明 | 出处 |
|---|---|---|
| "Unlike CPU cores, SMs issue instructions in order and do not perform branch prediction or speculative execution." | SM 顺序发射，不做分支预测与推测执行 | [C 物理页 169](cuda-programming-guide.pdf#page=169) |
| "A warp executes one common instruction at a time, so full efficiency is realized when all 32 threads of a warp agree on their execution path." | SIMT：32 个线程走同一条路才满效率，分支发散有代价 | [C 物理页 169](cuda-programming-guide.pdf#page=169) |
| "The execution context (program counters, registers, etc.) for each warp processed by an SM is maintained on-chip throughout the warp's lifetime. Therefore, switching between warps incurs no cost. At each instruction issue cycle, a warp scheduler selects a warp with threads ready to execute its next instruction (the active threads of the warp) and issues the instruction to those threads." | warp 上下文常驻片上，切换零开销；每个发射周期，调度器挑一个就绪的 warp 发射一条指令 | [C 物理页 170](cuda-programming-guide.pdf#page=170) |
| "The number of blocks and warps that can reside and be processed concurrently on the SM for a given kernel depends on the amount of registers and shared memory used by the kernel, as well as the amount of registers and shared memory available on the SM. 对应关系【推断】：
- C 只说 "a warp scheduler"，不说每 SM 有几个；数量来自白皮书的图：H100 图 7 每个处理分区各画一个 Warp Scheduler 和一个 Dispatch Unit（[A p.21](nvidia-h100-tensor-core-gpu-architecture.pdf#page=21)），即每 SM 4 个；Blackwell 图 5〔[B p.11](nvidia-rtx-blackwell-gpu-architecture.pdf#page=11)〕把 L0 Cache、Warp Scheduler、Dispatch (32 thread/clk) 画在同一条里（图内标签，读图），同样是每分区一个。

### 8.2 Tensor Core 的软件视角：接口、矩阵形状、数据类型（补 §3.2、§3.11）

**① 接口是 warp 级的 D=A×B+C【原文】**
- "C++ warp matrix operations leverage Tensor Cores to accelerate matrix problems of the form D=A*B+C. These operations are supported on mixed-precision floating point data for devices of compute capability 7.0 or higher. This requires co-operation from all threads in a warp."（[C 物理页 681](cuda-programming-guide.pdf#page=681)）
- `mma_sync`："Waits until all warp lanes have arrived at mma_sync, and then performs the warp-synchronous matrix multiply-accumulate operation D=A*B+C."（[C 物理页 683](cuda-programming-guide.pdf#page=683)）
- 这把 §3.1 的【推断】（Tensor Core 做的是 D=A×B+C 的小块矩阵乘加）落到了原文上；调用必须整条 warp 协同。

**② 操作数放在寄存器里，布局不公开【原文】**
- fragment 的定义："An overloaded class containing a section of a matrix distributed across all threads in the warp. The mapping of matrix elements into fragment internal storage is unspecified and subject to change in future architectures."（[C 物理页 682](cuda-programming-guide.pdf#page=682)）
- "The m, n and k sizes describe the shape of the warp-wide matrix tiles participating in the multiply-accumulate operation. The dimension of each tile depends on its role. For matrix_a the tile takes dimension m x k; for matrix_b the dimension is k x n, and accumulator tiles are m x n."（[C 物理页 682](cuda-programming-guide.pdf#page=682)）
- 含义【推断】：这就是 §3.3 里"操作数从寄存器堆进入 Tensor Core"在软件上的样子——矩阵分片分布在 warp 的 32 个线程的寄存器里；分片内部的布局随架构变化，程序不能假定（C p.685 原文："fragments are architecture-specific"）。

**③ WMMA 的矩阵形状（warp 级，m-n-k）【原文，表格转录】**（[C 物理页 686–687](cuda-programming-guide.pdf#page=686)）

| Matrix A / Matrix B | Accumulator | 形状（m-n-k） |
|---|---|---|
| `__half` / `__half` | `float` 或 `__half` | 16x16x16、32x8x16、8x32x16 |
| `unsigned char` / `unsigned char`；`signed char` / `signed char` | `int` | 16x16x16、32x8x16、8x32x16 |
| `__nv_bfloat16` / `__nv_bfloat16` | `float` | 16x16x16、32x8x16、8x32x16 |
| `precision::tf32` / `precision::tf32` | `float` | 16x16x8 |
| `double` / `double` | `double` | 8x8x4 |
| `precision::u4`、`precision::s4`（实验性） | `int` | 8x8x32 |
| `precision::b1`（实验性） | `int` | 8x8x128 |

- 这是可移植的 warp 级接口（compute capability 7.0 起）的形状，不是硬件原语——第一代的硬件原语是 4×4（见 §8.3）。
- Hopper 的 `wgmma`、Blackwell 的 `tcgen05` 的形状 C 里没有，PTX ISA 文档有【原文·网页】：
  - `wgmma.mma_async`："Perform matrix multiply-and-accumulate operation across warpgroup"；"A warpgroup is a set of four contiguous warps such that the warp-rank of the first warp is a multiple of 4."；半精度形状从 `.m64n8k16` 到 `.m64n256k16`（N 以 8 为步长）；"Requires sm_90a."（PTX ISA 9.5 §9.7.17）
  - `tcgen05.mma`："Perform the 5th generation of matrix multiply and accumulate operation."（§9.7.18.10.10.1）；"The 5th generation TensorCore has dedicated on-chip memory that is specialized for use by TensorCore operations."（§9.7.18.1，即 Tensor Memory）
  （来源：[PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html)，Version 9.5，抓取 2026-11-27）
- 含义【推断】：三代接口的粒度逐级变粗——Volta 是 warp 级的 16×16；Hopper 提到 warpgroup（4 个 warp）级的 m64；Blackwell 的指令语法里，累加结果和 A 操作数可以直接放在 Tensor Memory 里（`[d-tmem], [a-tmem], b-desc`），不再只走线程寄存器。

**④ BF16 与 TF32 是什么【原文】**
- `__nv_bfloat16`："This data format is an alternate fp16 format that has the same range as f32 but reduced precision (7 bits)."（[C 物理页 683](cuda-programming-guide.pdf#page=683)）
- tf32："This data format is a special floating-point format supported by Tensor Cores, with the same range as f32 and reduced precision (>=10 bits). The internal layout of this format is implementation-defined."（[C 物理页 684](cuda-programming-guide.pdf#page=684)）——与 §2.6 的背景知识说法一致：范围同 FP32，尾数降到 10 位。

**⑤ 软件怎么走到 Tensor Core【原文】**
- "The Tensor Core feature set is available within the CUDA compilation toolchain through inline PTX. It is strongly recommended that applications use this feature set through CUDA-X libraries such as cuDNN, cuBLAS, and cuFFT, for example, or through CUTLASS, a collection of CUDA C++ template abstractions and Python domain-specific languages (DSLs) designed to enable high-performance matrix-matrix multiplication (GEMM) and related computations across all levels within CUDA."（[C 物理页 541](cuda-programming-guide.pdf#page=541)）
- 两条路：自己写内联 PTX，或走 cuDNN / cuBLAS / cuFFT / CUTLASS；官方建议走库。这补上 §7.0 图里"矩阵乘在此翻译成 MMA 指令"那一环【推断】。

**⑥ 每代最新的 MMA 指令是架构专属的【原文】**

### 8.7 FP4 的编码与缩放（NVIDIA 官方博客与 PTX ISA，补 §3.6）

- 【原文·网页】"Blackwell was the first architecture from NVIDIA to natively support FP4 formats."
- 【原文·网页】"Blackwell introduces native Tensor Core support for NVFP4, a 4-bit numerical format for both weights and activations that uses micro-block scaling—where each group of sixteen 4-bit elements shares a common scaling factor. - 【原文·网页】"Unlike MXFP4, which is limited to power-of-two scale factors (E8M0) and prone to high rounding errors, NVFP4 uses higher-precision E4M3 scale factors with additional mantissa bits."
- 【原文·网页】"Figure 1 below shows measured GEMM performance with Blackwell Ultra, revealing a 7x speedup over the Hopper generation. Modern LLMs fundamentally rely on matrix multiplication, particularly within their fully-connected or linear layers, as a core computational element."

（来源：[NVFP4 Trains with Precision of 16-bit and Speed and Efficiency of 4-bit](https://developer.nvidia.com/blog/nvfp4-trains-with-precision-of-16-bit-and-speed-and-efficiency-of-4-bit/)，NVIDIA Technical Blog，2025-08-25，抓取 2026-11-27）

位级编码出自 PTX ISA 文档：
- 【原文·网页】e2m1："This data format is a 4-bit floating point format with 2 bits for exponent and 1 bit for mantissa."
- 【原文·网页】块缩放 MMA："perform matrix multiplication with block scaling. This operation has the following form: (A * scale_A) * (B * scale_B) + D"；"where scale_A and scale_B are matrices residing in Tensor Memory"（带 `.kind::mxf4nvf4` 等限定符的 `tcgen05.mma`，PTX ISA 9.5 §9.7.18.10.7）

- B 白皮书只写 "FP4"；官方博客里的名字是 **NVFP4**：4-bit 元素 + 每 16 个元素共用一个 E4M3 缩放因子（微块缩放）。§3.12 留下的"网页称 NVFP4、B 称 FP4，是否同一格式"：GB10 白皮书把 Blackwell GPU 的算力写作 "1 PFLOP NVFP4 Sparse"（[F p.9](nvidia-gb10-superchip-whitepaper.pdf#page=9)），官网把 Blackwell 的 Tensor Core 精度列为 NVFP4，可推知 Blackwell 消费级/边缘产品的 FP4 就是 NVFP4【推断】。

### 8.8 2:4 结构化稀疏是什么（NVIDIA 官方博客，补 §3.8）

§3.8 把"2:4 结构化稀疏"标为背景知识；NVIDIA 官方博客有原始定义。

- 【原文·网页】"The NVIDIA Ampere architecture introduces fine-grained structured sparsity with a 2:4 pattern that reduces data footprint and bandwidth by 2x while doubling throughput on NVIDIA A100 GPUs."
- 【原文·网页】"On the NVIDIA A100 GPU, the structure manifests as a 2:4 pattern: out of every four elements, at least two must be zero. This reduces the data footprint and bandwidth of one matrix multiply (also known as GEMM) operand by 2x and doubles throughput by skipping the computation of the zero values using new NVIDIA Sparse Tensor Cores."
- 【原文·网页】"This matrix is compressed to be half the size of the original matrix with a small amount of metadata to keep track of where the nonzeros were in the original, uncompressed matrix. This metadata is used to select only the corresponding activations from the second input matrix"
- 【原文·网页】图 1 图注："Fine-grained structured sparsity results in even load balancing, regular memory accesses, and 2x math efficiency with no loss in network accuracy."

（来源：[Exploiting NVIDIA Ampere Structured Sparsity with cuSPARSELt](https://developer.nvidia.com/blog/exploiting-ampere-structured-sparsity-with-cusparselt/)，NVIDIA Developer Blog，2020-12-08，抓取 2026-11-27）

要点：
- 只有**一个**操作数（通常是权重）需要满足 2:4：它被压缩成一半大小并附带元数据，另一个操作数不变。§3.5 各表的"稀疏列 = 稠密 ×2"对应的就是这个机制。
- 这是 Ampere（A100）引入的；H100 与 RTX Blackwell 延续（A p.11、B p.48 的 Sparsity 说明），PTX 里对应 `wgmma.mma_async.sp` 与 `tcgen05.mma.sp`。
- 收益的前提是剪枝后精度不掉："with no loss in network accuracy" 是博客对当时网络的陈述，对具体模型要自己验证【推断】。
- 元数据的具体位宽、稀疏矩阵的存储布局，这篇博客和书库资料都没给【文档未说明】。

### 8.9 LLM 推理的两个阶段与 KV Cache（NVIDIA 官方博客，补 §6）

§6 开头的 ⚠ 说两份白皮书没讲 prefill/decode、KV Cache；NVIDIA 官方博客有定义。先引原文，再对应到本文的硬件单元。

- 【原文·网页】"Large language models require two distinct inference phases: a prefill phase that processes input tokens in parallel and a decode phase that generates output tokens autoregressively and is memory-bound."
- 【原文·网页】prefill："In the prefill phase, the LLM processes the input tokens to compute the intermediate states (keys and values), which are used to generate the “first” new token. Each new token depends on all the previous tokens, but because the full extent of the input is known, at a high level this is a matrix-matrix operation that’s highly parallelized. It effectively saturates GPU utilization."
- 【原文·网页】decode："In the decode phase, the LLM generates output tokens autoregressively one at a time, until a stopping criteria is met. … This is like a matrix-vector operation that underutilizes the GPU compute ability compared to the prefill phase. The speed at which the data (weights, keys, values, activations) is transferred to the GPU from memory dominates the latency, not how fast the computation actually happens. In other words, this is a memory-bound operation."
- 【原文·网页】KV cache："To avoid recomputing all these tensors for all tokens at each time step, it’s possible to cache them in GPU memory. Every iteration, when new elements are computed, they are simply added to the running cache to be used in the next iteration. In some implementations, there is one KV cache for each layer of the model."
- 【原文·网页】显存构成："In effect, the two main contributors to the GPU LLM memory requirement are model weights and the KV cache."
- 【原文·网页】容量公式："Total size of KV cache in bytes = (batch_size) * (sequence_length) * 2 * (num_layers) * (hidden_size) * sizeof(FP16)"；例子："with a Llama 2 7B model in 16-bit precision and a batch size of 1, the size of the KV cache will be 1 * 4096 * 2 * 32 * 4096 * 2 bytes, which is ~2 GB."

（来源：[Mastering LLM Techniques: Inference Optimization](https://developer.nvidia.com/blog/mastering-llm-techniques-inference-optimization/)，NVIDIA Developer Blog，2023-11-17，抓取 2026-11-27）

对应到本文的硬件单元【推断】：

| 阶段 | 主要做什么 | 瓶颈 | 吃重的是哪些单元 |
|---|---|---|---|
| prefill | 一次性处理整段输入，矩阵-矩阵运算，算力吃满 | 算力 | Tensor Core（§3）+ 供数链路 TMA / L2 / HBM（§4.9、§5.1） |
| decode | 每步生成 1 个 token，矩阵-向量运算，算力用不满 | 显存带宽 | HBM/GDDR7 的带宽（§5.1）：每一步都要把全部权重和 KV cache 读一遍 |
| 全程 | KV cache 常驻显存并随序列增长 | 显存容量 | 显存容量（§5）；§8.5、§8.6 的扩展内存针对的就是这一项 |

- 这把 §6 末尾"瓶颈在算与供数两处"的推断落实了：prefill 卡在"算"，decode 卡在"供数"。
- 也说明了 FP8/FP4 的价值落在哪：decode 每一步都要把全部权重读一遍，权重位宽减半，读带宽的需求就减半【推断】——A p.23 只说了 "halves data storage requirements and doubles throughput"。
- 博客还给了一组 decode 阶段的优化手段（批处理、多查询/分组查询注意力、Flash Attention、KV cache 分页管理、量化、in-flight batching），它们各自依赖哪些硬件特性，书库资料里没有对应说明【文档未说明】。
