## 1. 整芯层级：GPU → GPC → TPC → SM → 分区

### 1.1 层级结构【原文+图】

```
GPU（GB202 满配，图形芯片；H100 的差异见树后说明）
 └─ GPC  Graphics Processing Cluster【B p.9 原文】
     ├─ Raster Engine（光栅引擎）【B p.9 原文】
     ├─ ROP 分区 ×2（每分区 8 个 ROP）【B p.9 原文】
     └─ TPC ×8  Texture Processing Cluster【B p.9 原文】
         ├─ PolyMorph Engine ×1【B p.9 原文】
         └─ SM ×2【B p.9 原文】
             └─ 处理分区 ×4（两代 SM 都是 4 分区；见图 7〔A p.21〕/ 图 5〔B p.11〕）
                 ├─ CUDA Core（标量计算列）：FP32/INT32 + FP64
                 │   （Blackwell：128 个 FP32/INT32 合一；Hopper：128 FP32 + 64 INT32 分列；
                 │     FP64 另有少量独立列——H100 64 个/SM，GB202 仅 2 个/SM）
                 ├─ Tensor Core ×1/分区 → 每 SM ×4
                 ├─ LD/ST ×4、SFU ×1（见图，正文未定义）
                 └─ 寄存器堆 16,384 × 32-bit/分区
             SM 级共享：L1 Data Cache/Shared Memory、Texture Unit ×4、
                        TMA（仅 H100 图中画出）、RT Core ×1（仅 Blackwell）
```

层级命名出处：GPC/TPC/SM 见 [A 物理页 18 · GH100 构成清单](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[B 物理页 8–9 · Blackwell GB202 GPU](nvidia-rtx-blackwell-gpu-architecture.pdf#page=8)。GPC 内 8 TPC、TPC=PolyMorph+2SM 见 [B 物理页 9](nvidia-rtx-blackwell-gpu-architecture.pdf#page=9)；A 侧 9 TPC/GPC 见 [A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)。
【原文】H100 侧差异：GH100 满配为 8 GPC / 72 TPC（9 TPC/GPC）/ 144 SM，且 "primarily built for executing datacenter and edge compute workloads for AI, HPC, and data analytics, but not graphics processing"（[A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)）——树里的 Raster Engine / ROP / PolyMorph Engine 是图形芯片的组成，A 白皮书未列出 H100 的对应单元【文档未说明】。
【推断】"分区（partition/sub-partition）"一词两份白皮书正文都没用，是 4 分块结构在图中的呈现；CUDA 官方文档称之为 sub-partition，本文按图转述。

## 2. CUDA Core

### 2.1 一句话功能
【原文+推断】SM 内的标量通用计算核心，逐标量执行 FP32/INT32（部分场景 FP16/BF16）指令，是 GPU 上的"通用算力"；与做整块矩阵乘的 Tensor Core 分工（见 §3.1）。文档对 CUDA Core 没有独立定义章节，其职能由两处原文侧面给出：地址生成（[B 物理页 5](nvidia-rtx-blackwell-gpu-architecture.pdf#page=5)）与"为 Tensor Core 做数据预处理/后处理"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。

### 2.2 架构
- 数量：每 SM 128 个【A 物理页 18 / B 物理页 10 原文】；芯片级数量见 §1.2 表。
- 组织【图】：每分区一列计算单元；Hopper 图 7 里是 INT32、FP32、FP32、FP64 四列（INT32 一列、FP32 两列、FP64 一列）；Blackwell 图 5/图 6 里合成一整块 "FP32 / INT32"（图注："Ada SM was designed & optimized for standard shaders. Blackwell SM was designed & optimized for neural shaders."）【A p.21 / B p.11–12 已读图】。
- INT32 口径差异【原文】：H100 = 128 FP32 + **64** INT32（[A 物理页 39 Table 3](nvidia-h100-tensor-core-gpu-architecture.pdf#page=39)：表行 "INT32 Cores / SM" 的 H100 两列均为 64）；Blackwell = 128 全统一【B 物理页 12 原文】。
- FP64：独立小核。GB202 每 SM 2 个、全芯片 384 个，速率仅 FP32 的 1/64，目的是"ensure any programs with FP64 code operate correctly"【B 物理页 8 原文】；H100 则是正经 64 个/SM + FP64 Tensor Core（[A 物理页 39](nvidia-h100-tensor-core-gpu-architecture.pdf#page=39)）——数据中心卡仍保留 FP64 算力。

### 2.3 执行流程
【推断】两份白皮书都只给框图不给流水。按 CUDA 编程模型与图 7/图 5 转述：Warp Scheduler（32 thread/clk）每周期向 Dispatch Unit 送一条 warp 指令 → 进入某列计算单元执行；操作数来自本分区寄存器堆（16,384×32-bit）；访存指令经 LD/ST 单元走 L1 → L2 → 显存。发射宽度、双发射等细节【文档未说明】。

### 2.4 使用场景
- 图形着色器、通用 CUDA kernel【推断：CUDA 平台常规用途】。
- 地址生成类整数负载【原文】："doubling of throughput per clock cycle for many integer math operations … increase the performance of address generation workloads that are crucial for neural shading"（[B 物理页 5](nvidia-rtx-blackwell-gpu-architecture.pdf#page=5)）。
- AI 管线的预处理/后处理【原文】：A p.17 "most other CUDA threads can be focused on general-purpose computations, such as pre-processing and post-processing data for the new generation of Tensor Cores"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。

### 2.5 对 AI 模型的支持
- **不承担主算力**：矩阵乘走 Tensor Core（"specialized high-performance compute cores for matrix multiply and accumulate (MMA) math operations"【A p.22 原文】）；"CUDA Core 不做矩阵乘"文档没有直接论断，标【推断】。
- **辅助角色有原文**：数据预处理/后处理（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）、地址生成（[B 物理页 5](nvidia-rtx-blackwell-gpu-architecture.pdf#page=5)）。【推断】大模型推理中的逐元素算子（激活、残差、norm 类）属于这类逐标量工作，落在 CUDA Core 上，文档未点名。
- FP64【原文+推断】：定位是程序正确性（B p.8），不参与 LLM 训练/推理主链路【推断】。

### 2.6 Hopper → RTX Blackwell 的变化
- FP32/INT32 **完全统一**：多数整数指令吞吐 ×2；同一周期只能当 FP32 或 INT32 之一；并非所有 INT 指令都能 2×（[B 物理页 12 原文](nvidia-rtx-blackwell-gpu-architecture.pdf#page=12)）。
- 体现在规格表：INT32 TOPS（non-Tensor）4090=41.3 → 5090=104.8，与 FP32 完全相等（[B 物理页 46–47 Table 3](nvidia-rtx-blackwell-gpu-architecture.pdf#page=46)）；H100 的 INT32 TOPS（25.6–33.5）只有 FP32 TFLOPS（51.2–66.9）的一半（[A 物理页 40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）。
- 表行 "Peak FP32 TFLOPS (non-Tensor)" 与 "Peak TF32 Tensor TFLOPS" 的区别——数字【原文】：5090 前者为 104.8，后者为 104.8/209.5（稀疏）（[B 物理页 46–47 Table 3](nvidia-rtx-blackwell-gpu-architecture.pdf#page=46)）。解释【推断，背景知识，非文档内容】：FP32 行是 CUDA Core 的标量路径，TF32 行是 Tensor Core 的矩阵路径；TF32 是一种 19 位浮点格式（1 符号 + 8 指数 + 10 尾数），不是"19 位尾数"。文档未解释两者的关系。

### 2.7 文档缺口
寄存器堆/LD/ST/SFU 的定义（仅在图中出现）；每周期发射/双发射策略；CUDA Core 在 GEMM 前后的确切参与比例；FP16/BF16 在标量路径的速率语义（A Table 1 p.20 的 "Peak FP16" 行给 133.8，来由文档未解释）。

## 3. Tensor Core（重点）

### 3.1 一句话功能与本质区别
【原文】"Tensor Cores are specialized high-performance compute cores for matrix multiply and accumulate (MMA) math operations"（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）。
【推断】与 CUDA Core 的本质区别：CUDA Core 一次算一对标量的 FMA；Tensor Core 一次完成一小块矩阵的乘加（D=A×B+C），数据复用在硬件内部，因此单位面积吞吐高一个量级。

### 3.2 架构
- 数量：每 SM 4 个（两代同）【A p.18 / B p.10 原文】；每分区 1 个（图 7/图 5）。
- 代际：Hopper = 第 4 代，支持 FP8/FP16/BF16/TF32/FP64/INT8 MMA（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）；Blackwell = 第 5 代，在 Hopper 基础上**新增 FP4/FP6** 与第二代 FP8 Transformer Engine（[B 物理页 15](nvidia-rtx-blackwell-gpu-architecture.pdf#page=15)）。
- 每芯片：H100 SXM5 528 个、RTX 5090 680 个（§1.2 表）。
- MMA 切片形状、寄存器要求【文档未说明】（→ CUDA Programming Guide）。

### 3.3 执行流程
【推断，依据 A p.29–35 原文组件拼装】TMA 把下一块数据从显存异步搬进 shared memory（硬件生成地址）→ Cluster/DSMEM 在多 SM 间分摊数据 → warp 发出 MMA 指令，操作数从寄存器堆进入 Tensor Core → 结果写回寄存器/shared → 事务屏障同步下一批。整条链路"end-to-end asynchronous pipelines … completely overlapping and hiding data movement with computation"（[A 物理页 17 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。

### 3.4 使用场景
- AI 训练与推理【原文】："Tensor Cores provide groundbreaking performance for the matrix computations that are critical for both deep learning neural network training and inference operations."（[B 物理页 15](nvidia-rtx-blackwell-gpu-architecture.pdf#page=15)）；H100 侧的适用面写作 "AI and HPC applications"（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）。
- 图形内的 AI（Blackwell）【原文】：DLSS 4 的光流、帧生成以及 SR/RR/DLAA 模型都由 Tensor Core 执行（[B 物理页 36–37](nvidia-rtx-blackwell-gpu-architecture.pdf#page=36)）；经 Cooperative Vectors API，像素、光追等着色器也能直接访问 Tensor Core（[B 物理页 40](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)）。
- HPC【原文】：A 白皮书列有 FP64 Tensor Core（见 §3.5 表）。

### 3.5 吞吐对照表【原文数字】

| 每芯片峰值（稠密 / 稀疏） | H100 SXM5（A p.20 Table 1） | RTX 5090（B p.47 Table 3） |
|---|---|---|
| FP8（FP16 累加） | 1978.9 / 3957.8 TFLOPS | 838 / 1676 TFLOPS |
| **FP4（FP32 累加）** | —（无此格式） | **1676 / 3352 AI TOPS** |

### 3.6 FP8 / FP4 解决什么问题
- **FP8（Hopper 引入）**【原文】：E4M3（4 指数 3 尾数，重精度）与 E5M2（5 指数 2 尾数，重动态范围）两种编码（[A 物理页 23](nvidia-h100-tensor-core-gpu-architecture.pdf#page=23)）；"FP8 halves data storage requirements and doubles throughput compared to FP16 or BF16"（同页）。
- **FP4（Blackwell 引入）**【原文】："FP4 requires less than half of the memory, and 50 Series GPUs provide over 2x performance compared to the previous generation. FP4 allows virtually no loss in quality with advanced quantization methods offered by the NVIDIA TensorRT Model Optimizer"（[B 物理页 16](nvidia-rtx-blackwell-gpu-architecture.pdf#page=16)）。端到端实例：FLUX.dev 由 FP16 >23 GB 显存 → FP4 <10 GB；4090 FP16 15 秒 → 5090 FP4 5 秒出头（同页）。
- FP4 的位级编码与累加路径细节【文档未说明】（常见说法 E2M1 属背景知识，两份白皮书均未出现）。

### 3.7 Transformer Engine 逐层工作流程【原文+图 25 已读图】

```
第 N 层输入 → H100 Tensor Core 计算（当前精度）
                │ 输出统计值（statistics）
   下一层信息 ──┤   （下一层的类型 + 所需精度）
                ▼
        Range Analysis ──► 目标格式 + 缩放因子 ──► Adaptive Format Conversion
                （图例：橙=自适应精度，紫=高精度，黑=辅助数据；见图 25）
                ▼
        以自适应精度写回显存 → 供第 N+1 层读取
```

原文依据："the Transformer Engine analyzes the statistics of the output values produced by the Tensor Core. With knowledge about which type of neural network layer comes next and what precision it requires, the Transformer Engine also decides which target format to convert the tensor to before storing it to memory … dynamically scales tensor data into the representable range using scaling factors computed from the tensor statistics"（[A 物理页 46](nvidia-h100-tensor-core-gpu-architecture.pdf#page=46)）。
收益口径【原文】："up to 9x faster AI training and up to 30x faster AI inference speedups on large language models"（[A 物理页 11 / p.19](nvidia-h100-tensor-core-gpu-architecture.pdf#page=11)）。背景：Transformer 模型 5 年间每两年增长 275×（[A 物理页 44](nvidia-h100-tensor-core-gpu-architecture.pdf#page=44)）。Blackwell 侧为第二代 FP8 Transformer Engine【B 物理页 15 原文，一句带过，细节文档未说明】。

### 3.8 稀疏加速是什么
【原文】"The Sparsity feature exploits fine-grained structured sparsity in deep learning networks, doubling the performance of standard Tensor Core operations"（[A 物理页 11](nvidia-h100-tensor-core-gpu-architecture.pdf#page=11)）。【推断，背景知识，非文档内容】通常指 2:4 结构化稀疏：按固定模式剪枝后约一半权重不参与计算，故有效吞吐记为 ×2（各表"稀疏列"）。稀疏的硬件实现细节【文档未说明】。

### 3.9 大模型证据（逐条原文）
- LLM 训练/推理收益 9×/30×【A p.11、p.19 原文】。
- 万亿参数模型与并行需求【A p.8 原文："trillion parameter AI models"】；MT-NLG 训练曾需 2048×A100×8 周【A p.44 原文】。
- 消费卡侧生成式实例：DLSS 4 的 SR/RR/DLAA 全部转 Transformer 模型，"ingest 2x more parameters, while also using more Tensor Core processing power"（[B 物理页 37](nvidia-rtx-blackwell-gpu-architecture.pdf#page=37)）；MFG 每个渲染帧生成 3 帧，帧生成模型快 40%、省 30% 显存（[B 物理页 35](nvidia-rtx-blackwell-gpu-architecture.pdf#page=35)）；FLUX.dev FP4 实例（[B 物理页 16](nvidia-rtx-blackwell-gpu-architecture.pdf#page=16)）。
- A Fig.3（p.9）H100 vs A100 各 workload 加速比图含 GPT-3/MT-NLG/MoE（未读图，仅目录定位）。

### 3.10 Hopper → RTX Blackwell 的变化
- 代际与数量【原文】：第 4 代 → 第 5 代，每 SM 仍是 4 个（[A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[B 物理页 10](nvidia-rtx-blackwell-gpu-architecture.pdf#page=10)）。
- 新增数据格式【原文】：在 FP16/BF16/TF32/INT8/FP8 之外新增 FP4、FP6（[B 物理页 15](nvidia-rtx-blackwell-gpu-architecture.pdf#page=15)）；FP4 的收益见 §3.6。
- Transformer Engine【原文】：Hopper 的 FP8 Transformer Engine → 第二代 FP8 Transformer Engine（同页 B p.15，B 白皮书仅一句带过）。
- 访问路径【原文】：此前神经渲染走 CUDA（"using CUDA to harness the Tensor Cores"），Blackwell 起图形着色器可经 Cooperative Vectors API 直接访问 Tensor Core（[B 物理页 40](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)）。
- 负载变化【原文】：DLSS 模型由 CNN 转 Transformer，参数量 2×、占用更多 Tensor Core 算力（[B 物理页 37](nvidia-rtx-blackwell-gpu-architecture.pdf#page=37)）。

## 4. 其他核心与固定功能单元

### 4.1 RT Core（仅图形芯片）
1. **功能**【原文】：专用光线追踪硬件——BVH 遍历、光线-盒子求交、光线-三角形求交，"work is offloaded from the SM"（[B 物理页 17](nvidia-rtx-blackwell-gpu-architecture.pdf#page=17)）。
2. **架构**【原文+图】：每 SM 1 个（Blackwell）【B p.10】；H100/A100 **没有** RT Core（"they do not include … NVIDIA RT Cores"，[A 物理页 40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）。第 4 代含 5 个引擎（见图 9）：Box Intersection、**Triangle Cluster Intersection（新增）**、**Linear Swept Spheres（新增）**、Opacity Micromap（Ada 已有）、**Triangle Cluster Compression（新增）**（[B 物理页 17](nvidia-rtx-blackwell-gpu-architecture.pdf#page=17)）。
3. **流程**【原文改述】：应用建加速结构——Mega Geometry 以 CLAS（≤256 三角形的簇级结构）为一级原语构造 BVH，PTLAS 分区更新顶层【B p.18–21】→ 着色器发射光线 → RT Core 遍历求交 → 回 SM 着色。
4. **场景**【原文】：光追游戏/渲染器；Nanite 全精度光追（不再降级代理网格）；位移细分曲面；毛发/草（LSS 比 DOTS 快 2×、省 5× 显存，[B 物理页 23](nvidia-rtx-blackwell-gpu-architecture.pdf#page=23)）。
5. **AI 支持**：不参与大模型训练/推理【推断】。RT 应用中的神经着色加速由 Tensor Core 承担，SER 负责把成簇神经线程直送 TC（[B 物理页 24 原文](nvidia-rtx-blackwell-gpu-architecture.pdf#page=24)）——功劳记在 TC，不在 RT Core。
6. **变化**【原文】：光线-三角形求交 2×；簇压缩把 Nanite 类场景显存省几百 MB（[B 物理页 22](nvidia-rtx-blackwell-gpu-architecture.pdf#page=22)）；"RT TFLOPS" 指标（5090=317.5，[B p.47](nvidia-rtx-blackwell-gpu-architecture.pdf#page=47)）文档未给计算口径【文档未说明】。
7. **缺口**：RT TFLOPS 口径；Opacity Micromap 的具体解码流程。

### 4.2 Texture Unit（纹理单元）
【原文】取 texel、过滤、坐标处理（[B 物理页 12](nvidia-rtx-blackwell-gpu-architecture.pdf#page=12)）；5090 有 680 个（4090 为 512）；点采样速率比 Ada 翻倍（[B 物理页 13](nvidia-rtx-blackwell-gpu-architecture.pdf#page=13)）。H100 也有 528 个（[A p.40 Table 3](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）——服务于 GPU 计算中的纹理缓存通路【推断】。AI 关联：随机纹理过滤（STF）为神经纹理压缩（NTC，7:1 于块压缩）服务（[B 物理页 40–42 原文](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)；"seven-to-one VRAM compression" 一句在 p.40）——属于图形内 AI 的配套，不参与 LLM【推断】。

### 4.3 ROP / Raster Engine / PolyMorph Engine
【原文】纯图形固定功能：GPC 内 1 个 Raster Engine + 2×8 ROP；TPC 带 1 个 PolyMorph Engine（[B 物理页 9](nvidia-rtx-blackwell-gpu-architecture.pdf#page=9)）。H100 无显示输出、定位非图形（[A 物理页 18](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[A 物理页 40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）。不参与大模型【推断】。

### 4.4 Optical Flow Engine（光流引擎）
位于整芯图芯片前端（见图 3）。**被 AI 取代的现成案例**【原文】：DLSS 4 "replacing hardware optical flow with a very efficient AI model"（[B 物理页 35](nvidia-rtx-blackwell-gpu-architecture.pdf#page=35)）——上一代的专用固定功能单元，这一代由 Tensor Core 上的模型替代。不参与 LLM【推断】。

### 4.5 NVENC / NVDEC / NVJPG（视频与图像引擎）
- H100：**7×NVDEC + 7×NVJPG**，定位就是 DL 数据加载——视频解码跟不上训练就吃不满 GPU（[A 物理页 58 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=58)）；JPEG 解码是图像 DL 的基础瓶颈（[A 物理页 59 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=59)）；DALI 库自动调度【A p.59 原文】。每 MIG 实例至少配 1×NVDEC + 1×NVJPG（[A 物理页 44 原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=44)）。
- Blackwell：NVENC 第 9 代（AV1 UHQ、4:2:2）、NVDEC 第 6 代（H.264 解码 2×）（[B 物理页 28–30](nvidia-rtx-blackwell-gpu-architecture.pdf#page=28)）——面向创作/直播，非 AI【推断】。
- **AI 支持**：多模态输入侧（视频/图像 → 张量）参与训练与推理【原文 A p.58–59】。
- 注意：H100 **无 NVENC**（[A p.40 脚注原文](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)）。

### 4.6 AMP（AI Management Processor，Blackwell 新增）
【原文】"a fully programmable context scheduler on the GPU designed to offload scheduling of GPU contexts from the system CPU"，实现为 GPU 管线前端的专用 RISC-V 处理器（[B 物理页 25](nvidia-rtx-blackwell-gpu-architecture.pdf#page=25)）；对接 Windows HAGS 模型。对 AI 的直接收益【原文】："With LLMs, it does this by reducing the time to first response"（[B 物理页 26](nvidia-rtx-blackwell-gpu-architecture.pdf#page=26)）；DLSS 4 的 AI 处理、图形渲染与帧 pacing 由 AMP 统一调度（[B 物理页 36](nvidia-rtx-blackwell-gpu-architecture.pdf#page=36)）。Hopper 白皮书无对应单元【文档未说明其有无】。

### 4.7 GigaThread Engine / SFU / LD/ST
仅在框图出现：GigaThread Engine 在整芯图顶部（见图 3）；每分区 4×LD/ST + 1×SFU（见图 7/图 5）。职能正文均未定义【文档未说明】。【推断】GigaThread=全局线程块分发器；SFU=特殊函数单元（三角函数等）；LD/ST=访存单元。

### 4.8 DPX 指令（Hopper 新增）
【原文】动态规划指令，最多 7× 于 Ampere；代表算法 Smith-Waterman（基因测序）、Floyd-Warshall（机器人路径）（[A 物理页 27](nvidia-h100-tensor-core-gpu-architecture.pdf#page=27)、[A 物理页 68 附录 C](nvidia-h100-tensor-core-gpu-architecture.pdf#page=68)）。属于 SM 指令集扩展而非独立单元【推断：由表述 "new dedicated hardware instructions" 推得，A p.68 原文】。不参与 LLM 主链路【推断】。

### 4.9 TMA / Thread Block Cluster / DSMEM / 异步事务屏障（Hopper 新增执行家族）
- **TMA**【原文】：global↔shared 的大块、多维（1D–5D）张量异步搬运；单线程发 copy descriptor，地址生成与搬运全硬件化（[A 物理页 32–33](nvidia-h100-tensor-core-gpu-architecture.pdf#page=32)）；定位 "To help feed the powerful new H100 Tensor Cores"（同页）——**AI 供数主通道**。A100 时代的 LDGSTS 需要线程自己算地址、循环搬运，TMA 全部接管【A p.33 原文】。
- **Thread Block Cluster**【原文】：比 Thread Block 更大一层的局部性单元，"guaranteed to be concurrently scheduled onto a group of SMs"，在 GPC 内运行，最多 16 个 Thread Block/Cluster（[A 物理页 29、41](nvidia-h100-tensor-core-gpu-architecture.pdf#page=29)）；层级变为 Threads→Thread Blocks→Clusters→Grids。
- **DSMEM**【原文】：Cluster 内跨 SM 直读写对方 shared memory（load/store/atomic），比走全局内存快约 7×（[A 物理页 30](nvidia-h100-tensor-core-gpu-architecture.pdf#page=30)）。
- **异步事务屏障**【原文】：分裂屏障（Arrive/Wait）基础上加"事务计数"（字节数），Wait 等到所有 Arrive 且字节数达标（[A 物理页 34–35](nvidia-h100-tensor-core-gpu-architecture.pdf#page=34)）；Cluster 的 TB 间数据交换构建在其上。
- **AI 支持**【原文】：这几件合起来是 "the first truly asynchronous GPU"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）的支撑件，服务 Tensor Core 供数与多 SM 协作【推断：具体到 LLM kernel 的用法文档未展开】。

- **PCIe Gen5**：128 GB/s（双向各 64）；原生 PCIe 原子操作、SR-IOV（[A 物理页 49–50](nvidia-h100-tensor-core-gpu-architecture.pdf#page=49)）。

### 5.3 MIG（多实例 GPU）【原文】
最多 7 个 GPU Instance；每实例独占显存全通路（crossbar 端口、L2 bank、显存控制器、DRAM 地址总线），保证时延/吞吐可预测（[A 物理页 42–43](nvidia-h100-tensor-core-gpu-architecture.pdf#page=43)）；每实例至少 1×NVDEC + 1×NVJPG（[A 物理页 44](nvidia-h100-tensor-core-gpu-architecture.pdf#page=44)）；比 A100 实例算力 ~3×、带宽 ~2×（[A 物理页 11–12](nvidia-h100-tensor-core-gpu-architecture.pdf#page=11)）。**AI 用途**【原文】：CSP 多租户推理隔离。B 白皮书未提 RTX Blackwell 是否支持 MIG【文档未说明】。

## 7. 汇总

### 7.0 概念辨析：为什么是"CUDA 生态"而不是"Tensor 生态"

一句话【推断】：**Tensor Core 是 SM 里的硬件部件，CUDA 是驾驭全部部件（含 Tensor Core）的软件平台**——二者是上下层关系，不是并列的两个"核家族"。名字撞车源于营销命名：SM 里那 128 个 FP32 标量通道的部件名本可与 Tensor Core 并无关联，NVIDIA 将其命名为 "CUDA Core"（[A 物理页 18 "FP32 CUDA Cores"](nvidia-h100-tensor-core-gpu-architecture.pdf#page=18)、[B 物理页 10 "includes128 CUDA Cores"](nvidia-rtx-blackwell-gpu-architecture.pdf#page=10)），才造成"CUDA 和 Tensor 是两个核"的误会。

```
应用层：AI / 科学计算应用与领域框架【原文 A p.63 "application-specific libraries and frameworks"；具体框架名（如 PyTorch）A 正文未点名，Fig.31 未读图】
   │
CUDA 平台（"生态"的实体，纯软件）【原文：章节名】
   ├─ 语言与编译器：CUDA C++、Languages and Compilers【A p.65】
   ├─ 运行时/编程模型：thread → block → cluster → grid【A p.29 原文】
   └─ 库：High-Performance Libraries and Frameworks【A p.63：线性代数 cuBLAS、深度神经网络 cuDNN、集合通信 NCCL】——矩阵乘在此翻译成 MMA 指令【推断】
   │
硬件层：SM（两类部件共存于同一 SM）
   ├─ CUDA Core：标量 FP32/INT32 通道（§2）
   └─ Tensor Core：MMA 矩阵部件（§3，无独立指令流）
```

三个白皮书事实：

1. **CUDA 平台早于 Tensor Core 十年**【原文】："Over 15 years ago, NVIDIA introduced the CUDA parallel computing platform with the G80 GPU"（[A 物理页 6](nvidia-h100-tensor-core-gpu-architecture.pdf#page=6)）——G80 是纯 CUDA Core 时代；第一个 Tensor Core 到 Volta 才出现："Tensor Cores were first introduced in the NVIDIA Tesla® V100 GPU"（[A 物理页 22](nvidia-h100-tensor-core-gpu-architecture.pdf#page=22)）。【推断】是"Core"沾了平台的名，不是相反。
2. **Tensor Core 没有独立的大脑**【原文】：取指、调度、喂料、同步由 CUDA 编程模型的设施承担（以下引句为原文，归纳为【推断】）——TMA 由"single thread in a warp is elected to issue"发起（[A 物理页 33](nvidia-h100-tensor-core-gpu-architecture.pdf#page=33)），多数 CUDA 线程"focused on general-purpose computations, such as pre-processing and post-processing data for the new generation of Tensor Cores"（[A 物理页 17](nvidia-h100-tensor-core-gpu-architecture.pdf#page=17)）。B 白皮书一句最直白："using CUDA to harness the Tensor Cores"（[B 物理页 40](nvidia-rtx-blackwell-gpu-architecture.pdf#page=40)）。
3. **白皮书自己把生态归在 CUDA 名下**【原文】：库、系统软件、语言与编译器统一收录在 "Appendix B - NVIDIA CUDA Platform Update"（[A 物理页 63–67](nvidia-h100-tensor-core-gpu-architecture.pdf#page=63)）：线性代数 cuBLAS、深度神经网络 cuDNN、集合通信 NCCL（[A 物理页 63](nvidia-h100-tensor-core-gpu-architecture.pdf#page=63)），NVVM/PTX 编译栈（[A 物理页 65](nvidia-h100-tensor-core-gpu-architecture.pdf#page=65)）。A 的可检索正文里没有 PyTorch、NeMo，TensorRT 只出现在 p.71 的商标声明——软件栈以 CUDA 为名组织，而不是以 Tensor Core 为名。

为什么"生态"落在 CUDA 头上（"实体"一行有 A p.63–65 原文支撑，其余为【推断，归纳】）：

| 判断依据 | CUDA | Tensor Core |
|---|---|---|
| 实体 | 编程模型+编译器+运行时+库+工具链，横跨 GeForce/数据中心全线 | SM 里的一类矩阵部件 |
| 覆盖面 | 所有 NVIDIA GPU 都跑 CUDA（H100 无图形输出也照样是 CUDA 平台，[A p.40](nvidia-h100-tensor-core-gpu-architecture.pdf#page=40)） | 可选加速件：G80~Pascal 没有；同代产品线也不都有 |
| 能否独立使用 | 是基底本身 | **不能**——没有脱离 CUDA/库直接给 Tensor Core 编程的方式 |
| 壁垒所在 | 十年积累的库与框架集成、存量代码 | 无独立壁垒：每代新 TC 经同一套 CUDA API 透明暴露（compute capability 7.0→8.0→9.0，[A p.41 Table 4](nvidia-h100-tensor-core-gpu-architecture.pdf#page=41)） |

类比【推断】：如同说"x86 生态"而不说"AVX-512 生态"——扩展单元被平台收编，Tensor Core 就是 CUDA 世界里带独立硬件的"AVX-512"。对执行大模型而言两者都要在场（§7.2 的排序不变），但生态归属、软件粘性、迁移成本，全部记在 CUDA 一侧。

### 7.2 哪些核心有助于执行大模型（按作用排序）

1. **Tensor Core**——唯一主算力：MMA 专用【原文 A p.22】+ FP8/FP4 低精度带宽减负【原文 A p.23/B p.16】+ Transformer Engine 自动调精度【原文 A p.46】+ 稀疏 ×2【原文 A p.11】。
2. **供数链路**——HBM3 3TB/s 与 L2 缓存模型片段【原文 A p.36/37】、GDDR7 1.792TB/s【原文 B p.13】、TMA 异步喂 TC【原文 A p.32】、L1/SMEM+DSMEM 多 SM 协作【原文 A p.30】。
3. **卡间互连**——NVLink4 900GB/s（all-reduce 3×）【原文 A p.12/p.47】、NVSwitch 集合通信卸载【原文 A p.48】、NVLink Switch System 256 GPU【原文 A p.12】。
4. **调度与隔离**——AMP 缩短 LLM 首响应【原文 B p.26】、MIG 多租户隔离【原文 A p.42–43】、GigaThread【文档未说明】。
5. **输入侧**——NVDEC/NVJPG 让视频/图像数据供给跟上 GPU【原文 A p.58–59】。
6. **不参与**——RT Core、ROP/Raster/PolyMorph、Texture Unit、Display、NVENC（H100/A100 没有 RT Core、NVENC 和显示输出【原文 A p.40】；"不参与 LLM"为【推断】）。
