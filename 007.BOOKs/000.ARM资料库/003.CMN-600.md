# CoreLink CMN-600 Coherent Mesh Network
> 学习:<br/>- [Arm CoreLink CMN-600 Coherent Mesh Network Technical Reference Manual](../../007.BOOKs/corelink_cmn600_technical_reference_manual_100180_0302_01_en.pdf) <br/> - [Arm® Neoverse™ CMN‑700 Coherent Mesh Network Technical Reference Manual](../../007.BOOKs/arm_neoverse_cmn_700_trm_102308_0307_08_en.pdf)

> CMN = **Coherent Mesh Network**(一致性网状网络)。ARM 第二代顶层一致性互联,基于 AMBA 5 CHI 协议,面向 high-end networking / enterprise compute,可扩展 1–64 个处理器簇。取代 CCI-5xx(ACE 线)与 CCN-5xx(CHI 中端线)两条旧产品线。

---

## 一、缓存一致性实现原理

### 1. 节点模型(CHI 协议)

| 节点 | 全称 | 职责 |
|---|---|---|
| **RN** | Request Node | 发起请求的节点 |
| RN-F | Fully coherent RN | 带硬件一致缓存的请求节点(CHI 口,通常连 CPU 簇) |
| RN-I | I/O coherent RN | 无一致缓存的 I/O 请求节点(经 **RN-I bridge**,ACE-Lite 口) |
| **HN** | Home Node | 每个字节地址空间被分配给**唯一一个** HN,由其负责该地址所有事务的一致性处理 |
| HN-F | Fully coherent HN | 管理 DRAM 一致性内存,内含 **SLC + SF + PoS/PoC** |
| HN-I | I/O coherent HN | 桥接 ACE-Lite 外设子系统(无缓存、无 snoop) |
| SN / SBSX / CXG | Slave Node / CHI→AXI 桥 / CHI→CCIX 桥 | 从侧/桥接器件 |

- 关键:p.1-21 —— *"each byte of address space is assigned to a single Home Node"*。整个 DRAM 空间由所有 HN-F 分区共同覆盖。
- CMN-600 接受的 ACE 入口只有 **ACE-Lite(RN-I bridge 与 SBSX)**,且明确仅限"无硬件一致缓存的 I/O master";**不收 ACE 的一致性 snoop 通道**。

### 2. HN-F(完全一致性 Home Node)内部结构(p.2-37, 2.1.3)

- **SLC(System Level Cache)**:最后一级缓存。数据行**独占**分配,检测到跨簇共享时对代码行**伪包含**;同时充当 RN-I(IO 代理)的 DRAM 缓存。
- **PoS + PoC 合并点**:对发到该 HN-F 的所有内存请求**串行化排序**(Point-of-Serialization + Point-of-Coherency)。
- **Snoop Filter(SF)**:追踪 RN-F 缓存中存在的 cacheline,用**定向 snoop 取代广播 snoop**,大幅降低 snoop 响应流量。

### 3. Snoop Filter = 全局共享目录项(p.4-1089, 4.3)

> "The SF works with the SLC to track coherent lines that are present in the RN-F caches. **The SF is fully inclusive of all the lines present in the RN-F caches. SF eviction invalidates the lines from RN-F caches to maintain this inclusion.**"

- **有,但它是分布式的**:不是一张全局集中表,而是分布在 ≤64 个 HN-F 里,每个 HN-F 管理地址空间的一个切片。
- **目录项记录**:cacheline tag + **存在性向量**(snoop vector / LID 位向量,记录哪些 RN-F 持有拷贝)。
- **不记录 MESI 全状态**:一致性权威状态由 HN-F 的 PoS/PoC 点维护;SF 只记"谁有拷贝"(存在性目录)。
- **完全包含式**:SF 覆盖所有 RN-F 缓存里的行;SF 条目被替换(驱逐)时,向持有该行的 RN-F 发 **back-invalidation(反向失效)**,清掉该行以维持包含性。
- **容量建议**:SF 总量 = 2× 所有 RN-F 独占缓存总量(如 RN-F 缓存 32MB → SF 配 64MB)。

### 4. 一致性流程(目录怎么用)

1. RN-F 发来一致性请求(如 ReadUnique),进入 HN-F 的 **POCQ(Point-of-Coherency Queue)** 排队串行化(p.2-74)。
2. 按地址查 **SF**:
   - **未命中**(无 RN-F 持有)→ 直接从 SLC 或内存返回,**不发任何 snoop** → 零广播流量;
   - **命中** → 取出该行的 **snoop vector**,只向向量中标记的 RN-F **定向发 snoop**(directed snoop)。
3. 定向 snoop 寻址:SF 给出 LDID → LDID LUT → NodeID,支持跨片(CCIX,CXHA/CXRA)转发(p.2-138, 2.22.4 Snoop process flow)。
4. 各 RN-F 返回 snoop 响应,PoC 点汇总决定数据源与是否写回。
5. 目录维护:监控 RN-F 的分配/释放更新 SF 条目;SF 条目驱逐时触发 back-invalidation。

## 二、与 CCI-550 的关系

关系一句话:**两者是同一层级(顶层一致性互联)的"换代"关系——互不包含,CMN-600 是 CCI-550 的替代者/后继者。**

### 谁包含谁:互不包含

两者都是完整的、各自独立的顶层一致性 Fabric,都在 SoC 一致性域的"头部"位置,地位对等:

- **CCI-550** 自带完整一致性域:ACE 核 + ACE-Lite I/O + snoop filter + PoS 排他监视,本身就是一个自洽的 coherence island;
- **CMN-600** 也是完整一致性域:RN-F + HN-F/SF + SLC,自带分布式目录。

所以在一致性语义上谁也不是谁的组件。想把 CCI-550 "放进" CMN-600 只能**非一致地物理直通**(经 AXI4→HN-I/SBSX),那只是"接线相连",不是"包含";一致性在边界断开。真正的"包含关系"只发生在 CMN-600 内部——它包含的是 RN-F、RN-I、HN-F、HN-I、SBSX、CXG 这些**节点器件**,而 CCI-550 不在其器件清单里(p.1-13 Table 1-1 可验证)。

### 谁替代谁:CMN-600 取代 CCI-550(及 CCN 线)

ARM 一致性互联产品线谱系是清晰的世代更替:

| 世代 | 产品 | 协议 | 拓扑 | 规模 | 目录机制 |
|---|---|---|---|---|---|
| 第一代 | CCI-400/500/550 | ACE(AMBA 4) | 交叉开关 crossbar | 约 6-7 个 master | 单个 snoop filter(存在性) |
| 第一代 | CCN-504/508 | CHI | 环 Ring | 中等 | 分布式 SF/L3 |
| 第二代 | CMN-600(CMN-650/700 接续) | CHI(AMBA 5) | Mesh 网状 | 1–64 簇 | ≤64 个 HN-F,每个带 SF + SLC 切片 |

关键点:

1. **CMN-600 同时顶掉了两条旧线**:CCI-5xx(ACE 低端线)和 CCN-5xx(CHI 中端线)。CMN-600 手册自己定位为 *"scalable, configurable coherent interconnect ... for high-end networking and enterprise compute"*,面向高密度、多簇场景。
2. **产品名本身透露了换代方向**:CCI = **Cache Coherent Interconnect**(缓存一致性互连)→ CMN = **Coherent Mesh Network**(一致性网状网络)。"Mesh" 取代 "Interconnect",拓扑从 crossbar 升级为可扩展到 64 簇的 mesh。
3. **CCI-550 是 ACE 线的终点**:AMBA 4/ACE 时代没有后继,新设计直接用 CHI。Cortex-A72 那种 ACE/CHI 双接口的核,进 CMN-600 系统就走 CHI RN-F 口,不再需要 CCI-550 这层。

### 结论对照表

- **谁包含谁** → 谁也不包含谁;两者并列,都是顶层一致性互联。
- **谁替代谁** → CMN-600 替代 CCI-550(连同 CCN-504/508 一起,被 CMN 线统一取代)。
- **市场定位** → CCI-550 面向 mid-range big.LITTLE(少量 ACE 簇);CMN-600 面向 server/enterprise(1-64 簇)。不是上下级,是**换代 + 上探**。
