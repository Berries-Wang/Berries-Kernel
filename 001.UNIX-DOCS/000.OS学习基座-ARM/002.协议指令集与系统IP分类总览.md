## 1. 分类框架：怎么读这张总表

### 1.1 五条类别轴

| 类别轴 | 判断标准 | 本文清单中的对象 |
| --- | --- | --- |
| **总线/互连协议** | 规范文本（IHI 编号）定义事务、信号与状态机，本身不可综合 | AMBA CHI、AMBA CHI C2C、AMBA CXS、AMBA AXI、AMBA AHB、AMBA APB |
| **接口标准（跨厂商）** | 行业联盟或多厂商共同维护的开放标准，不止 Arm 一家 | UCIe、PCIe |
| **互连 IP（代际家族）** | Arm 授权、可综合的硬件 IP；按代际与一致性能力划分家族 | 一致性：CCI-400/CCI-550（CCI 家族）、CI-700、CMN-700、CMN S3；非一致：NI-700、NI-710AE、NoC S3；一体化系统互连：SI L1 |
| **系统组件 IP** | 在互连之外承担特定功能的 IP 或 IP 内子组件 | SCU（簇内组件）、DSU（簇级 IP）、DMC（内存控制器类别，具体型号如 DMC-620）、DMA-350（DMA 控制器） |
| **指令集扩展** | 架构级软件可见能力，属 ARM ARM 规范而非硬件 IP | SVE、SVE2 |

三类容易越界的对象特别说明：

- **SCU**：不是独立授权产品，而是**簇（cluster）内部的一致性维护子组件**——老一代 Cortex-A MPCore（A9/A15/A57/A72 等）里它与 L2 cache 耦合出现；DynamIQ 时代（A55/A75 起，A520/A725/V3 延续）它被并入 DSU（DSU 内部仍有 SCU 块）；而 Neoverse V3 这类 Direct connect 配置下连 SCU 逻辑都不存在（见 §4.1）。
- **DMC**：**类别名称与产品型号要用全称区分**——DMC = Dynamic Memory Controller（动态内存控制器）；具体产品如 CoreLink DMC-620。CSS 类平台里的 DDR5 内存控制器是第三方选型（[001 文档 §1.3](001.Arm-CSS-计算子系统.md) 的 R10 原句），见 §3-E 与 §7。
- **PCIe**：同一对象常见三种表述——"总线"（教材口径，如 MOS5 §1.3.5）、"接口"（按 lane 计数的物理接口）、"协议"（PCI-SIG 的规范文本）。它本质是**点对点串行互连标准**（规范定义协议+链路+电气），在 Arm SoC 里以"PCIe 子系统/PHY IP"形态接入（见 §3-B 与 §4.5）。

### 1.2 协议 vs 实现协议的 IP：本表的读法

AMBA 规范（IHI 文档）规定"消息与规则"，互连 IP（TRM 文档）实现这些规则。以 CHI 为例：

> "The CHI architecture is a scalable, coherent hub interface and on-chip interconnect used by multiple components."
> <sup>（CHI 架构是一个可扩展的一致性 hub 接口与片上互连，供多种组件使用。）——[AMBA CHI Architecture Specification IHI 0050 Issue H §B1.1，物理页 29](../../007.BOOKs/IHI0050H_amba_chi_architecture_spec.pdf#page=29)</sup>

而实现它的 IP 是另一层：

> "This chapter introduces CMN‑700 which is an AMBA® 5 CHI interconnect with a customizable mesh topology."
> <sup>（本章介绍 CMN‑700——一个采用可定制 mesh 拓扑的 AMBA 5 CHI 互连。）——[Arm Neoverse CMN-700 TRM 102308 §2，物理页 17](../../007.BOOKs/arm_neoverse_cmn_700_trm_102308_0307_08_en.pdf#page=17)</sup>

CHI 规范自己也把"实现者"列了出来——CHI 系统的组件可以是处理器、内存控制器、IO 桥、PCIe 子系统乃至互连本身：

> "The components of CHI-based systems can comprise of: Standalone processors / Processor clusters / Graphic processors / Memory controllers / IO bridges / PCIe subsystems / Interconnects"
> <sup>（CHI 系统的组件可包括：独立处理器／处理器簇／图形处理器／内存控制器／IO 桥／PCIe 子系统／互连。）——[IHI 0050H §B1.1.1，物理页 29](../../007.BOOKs/IHI0050H_amba_chi_architecture_spec.pdf#page=29)</sup>

读 §2 总表时按"**先问协议还是 IP，再问哪一代、什么拓扑、一致还是非一致**"三步定位每个对象。

### 3.1 AMBA CHI / CHI C2C / CXS（协议层）

**AMBA CHI 是什么、管多大规模**【协议规定】：

> "The CHI architecture is a scalable, coherent hub interface and on-chip interconnect used by multiple components."
> <sup>（CHI 架构是一个可扩展的一致性 hub 接口与片上互连，供多种组件使用。）——[IHI 0050H §B1.1 p29](../../007.BOOKs/IHI0050H_amba_chi_architecture_spec.pdf#page=29)</sup>

拓扑无关，crossbar/ring/mesh 均可，规模不同选型不同：

> "Crossbar topology is suitable for an interconnect with a small number of nodes. … Ring topology is suitable for a medium sized interconnect. … Mesh topology is suitable for a larger scale interconnect."
> <sup>（crossbar 适合节点较少的互连……ring 适合中等规模……mesh 适合更大规模的互连。）——[IHI 0050H §B1.2 p31](../../007.BOOKs/IHI0050H_amba_chi_architecture_spec.pdf#page=31)</sup>

节点模型（RN/HN/SN）是读 CMN/CI-700 节点名称的词典：

> "RN‑F Fully Coherent Request Node: – Includes a hardware-coherent cache." / "HN‑F Fully Coherent Home Node: – Includes a Point of Coherence (PoC) … – Could include a directory or snoop filter to reduce redundant snoops. Note: IMPLEMENTATION SPECIFIC, can include an integrated interconnect cache."
> <sup>（RN-F＝全一致请求节点：含硬件一致性缓存。HN-F＝全一致 Home 节点：含一致性点……可含目录或 snoop filter 以减少冗余 snoop。注：实现可选，可含集成互连缓存。）——[IHI 0050H §B1.6 p41](../../007.BOOKs/IHI0050H_amba_chi_architecture_spec.pdf#page=41)</sup>

**AMBA CHI C2C 的定义与分层**（详细分析见 [003 文档](003.AMBA-CHI-C2C架构-Figure1-3.md)，此处只给分类所需两句）：

> "AMBA CHI C2C, also referred to as AMBA C2C or CHI C2C, extends the on-chip AMBA CHI protocol for connecting chip-to-chip and chiplet-to-chiplet (C2C)."
> <sup>（AMBA CHI C2C，亦称 AMBA C2C 或 CHI C2C，扩展片上 AMBA CHI 协议以连接芯片到芯片、芯粒到芯粒。）——[R5 §1.4 物理页 9](../../007.BOOKs/learn_the_architecture_introduction_to_amba_chi_c2c_property_negotiation_112071_0100_01_en.pdf#page=9)</sup>

> "AMBA CHI C2C follows a layered approach, so it can be used with transports (data-link and PHY) such as UCIe, other industry standards, or even bespoke solutions."
> <sup>（CHI C2C 采用分层方法，可搭配 UCIe、其他行业标准乃至定制方案作为传输层。）——[R5 物理页 10](../../007.BOOKs/learn_the_architecture_introduction_to_amba_chi_c2c_property_negotiation_112071_0100_01_en.pdf#page=10)</sup>

**AMBA CXS 的规范身份**【协议规定 + 部分未确认】：

> "The CMN‑700 interconnect supports up to 32 CXS (CXL/CML_SMP) interfaces. Each CCG device has a CXS interface, which is compliant with CXS Issue B specification."
> <sup>（CMN‑700 互连支持最多 32 个 CXS（CXL/CML_SMP）接口。每个 CCG 设备有一个 CXS 接口，符合 CXS Issue B 规范。）——[CMN-700 TRM §2.5.1 物理页 24](../../007.BOOKs/arm_neoverse_cmn_700_trm_102308_0307_08_en.pdf#page=24)</sup>

即：CXS 是**有独立 Issue 代际的 AMBA 接口协议**（本文档将 "CXS Issue B" 作为其规范代际的官方说法；规范编号 IHI 0079 记为未确认，见 §7）。它出现在两处：CHI C2C 的 C2C interface 虚线处（Link 层与 Protocol 层之间的握手接口示例，R6 §B13.2 p153-154，见 [003 文档 §3.3](003.AMBA-CHI-C2C架构-Figure1-3.md)），以及 CMN-700 的 CCG（CHI↔CXL 桥）设备内部。

### 3.2 AMBA AXI / AHB / APB（协议层）

**AXI 的定位与版本边界**：

> "The AXI protocol supports high-performance, high-frequency system designs for communication between Manager and Subordinate components."
> <sup>（AXI 协议支持 Manager 与 Subordinate 组件之间通信的高性能、高频系统设计。）——[IHI 0022L §A1.1 物理页 21](../../007.BOOKs/IHI0022L_amba_axi_protocol_spec.pdf#page=21)</sup>

> "2023/Mar/01 J … Simplified document structure. AXI3, AXI4, AXI4-Lite, ACE, and ACE5 content removed. New content added for AXI5, AXI5-Lite, ACE5-Lite, ACE5-LiteDVM, and ACE5-LiteACP interface classes."
> <sup>（2023-03-01 Issue J：简化文档结构；移除 AXI3/AXI4/AXI4-Lite/ACE/ACE5 内容；新增 AXI5、AXI5-Lite、ACE5-Lite、ACE5-LiteDVM、ACE5-LiteACP 接口类。）——[IHI 0022L Release information 物理页 2](../../007.BOOKs/IHI0022L_amba_axi_protocol_spec.pdf#page=2)</sup>

即版本边界：**AXI3/AXI4（含 ACE/ACE5）属旧 Issue 口径；现行 Issue L 只保留 AXI5 系**；与旧文档对照时要先确认规范 Issue。

**AHB 的定位与典型使用位置**：

> "AMBA AHB is a bus interface suitable for high-performance synthesizable designs. It defines the interface between components, such as Managers, interconnects, and Subordinates."
> <sup>（AMBA AHB 是适合高性能可综合设计的总线接口，定义 Manager、互连与 Subordinate 等组件之间的接口。）——[IHI 0033C §1.1 物理页 14](../../007.BOOKs/IHI0033C_amba_ahb_protocol_spec.pdf#page=14)</sup>

> "The most common AHB Subordinates are internal memory devices, external memory interfaces, and high-bandwidth peripherals. Although low-bandwidth peripherals can be included as AHB Subordinates, for system performance reasons, they typically reside on the AMBA Advanced Peripheral Bus (APB). Bridging between the higher performance AHB and APB is done using an AHB Subordinate, known as an APB bridge."
> <sup>（最常见的 AHB Subordinate 是内部内存、外部内存接口与高带宽外设。低带宽外设也可作为 AHB Subordinate，但出于系统性能考虑通常挂在 AMBA APB 上；AHB 与 APB 之间用一个作为 AHB Subordinate 的 APB bridge 桥接。）——[IHI 0033C §1.1 物理页 14](../../007.BOOKs/IHI0033C_amba_ahb_protocol_spec.pdf#page=14)</sup>

**APB 的定位与典型使用位置**：

> "The APB protocol is a low-cost interface, optimized for minimal power consumption and reduced interface complexity. The APB interface is not pipelined and is a simple, synchronous protocol."
> <sup>（APB 协议是低成本接口，为最小功耗与最低接口复杂度优化；非流水线，是简单的同步协议。）——[IHI 0024E §1.1 物理页 14](../../007.BOOKs/IHI0024E_amba_apb_architecture_spec.pdf#page=14)</sup>

> "The APB interface is designed for accessing the programmable control registers of peripheral devices."
> <sup>（APB 接口用于访问外设的可编程控制寄存器。）——[IHI 0024E §1.1 物理页 14](../../007.BOOKs/IHI0024E_amba_apb_architecture_spec.pdf#page=14)</sup>

组件侧实例——内存控制器的配置口就是 APB：

> "It connects to the on-chip system through a single CHI interface, and to a processor through the programmers APB3 interface to program the DMC-620."
> <sup>（DMC-620 经单一 CHI 接口接入片上系统，经编程用的 APB3 接口连接处理器进行配置。）——[DMC-620 TRM §1.1 物理页 12](../../007.BOOKs/corelink_dmc620_dynamic_memory_controller_technical_reference_manual_100568_0100_00_en.pdf#page=12)</sup>

### 3.3 SCU 与 DSU（组件层，代际对比）

**SCU 在老代际 MPCore 里的位置**【具体芯片已实现规格，A72 为例】：

> "The L2 memory system consists of a tightly-coupled L2 cache and an integrated Snoop Control Unit (SCU), connecting up to four cores within a cluster and a configurable coherent external interface supporting AMBA4 (ACE) or CHI architectures."
> <sup>（L2 内存系统由紧耦合的 L2 cache 与集成 SCU 组成，连接簇内最多四个核，并有一个支持 AMBA4 ACE 或 CHI 架构的可配置一致外部接口。）——[Cortex-A72 MPCore TRM 100095 §7.1 物理页 299](../../007.BOOKs/cortex_a72_mpcore_trm_100095_0003_06_en.pdf#page=299)</sup>

**SCU 在 DynamIQ 代际并入 DSU**【IP 可配置能力】：

> "Within the DSU there is the L3 cache, the Snoop Control Unit (SCU), internal interfaces to the cores, and external interfaces to the SoC: … The Snoop Control Unit (SCU) maintains coherency between caches in the cores and L3. The SCU includes a snoop filter to optimize coherency maintenance operations."
> <sup>（DSU 内含 L3 cache、SCU、到核心的内部接口与到 SoC 的外部接口：……SCU 维护核心缓存与 L3 之间的一致性，并含一个优化一致性维护操作的 snoop filter。）——[DynamIQ Shared Unit TRM 100453 §2.1 物理页 17](../../007.BOOKs/dsu_trm_100453_0401_05_en.pdf#page=17)</sup>

DSU 本体的定义（r4p1，DSU-100/110 一代）：

> "The DynamIQ™ Shared Unit (DSU) comprises the L3 memory system, control logic, and external interfaces to support a DynamIQ™ cluster."
> <sup>（DSU 包含 L3 内存系统、控制逻辑与外部接口，用于支持一个 DynamIQ 簇。）——[DSU TRM §2.1 物理页 16](../../007.BOOKs/dsu_trm_100453_0401_05_en.pdf#page=16)</sup>

**DSU-120（现役代际）**【IP 可配置能力】：

> "The DynamIQ™ Shared Unit-120 (DSU-120) provides a shared L3 memory system, snoop control and filtering, and other control logic to support a cluster of A-class architecture cores. … A DSU-120 DynamIQ™ cluster consists of between one and 14 cores, with up to three diﬀerent types of cores in the same cluster. … The DSU-120 DynamIQ™ cluster also supports complexes where typically two cores are linked together and share logic."
> <sup>（DSU-120 提供共享 L3 内存系统、snoop 控制与过滤及其他控制逻辑，支持最多 14 核、最多三种核型组成的 A 类核簇；还支持通常由两个核组成一个 complex 的形态。PDF 中句子跨行处已按原句拼合；A520 的 complex 即由此而来。）——[DSU-120 TRM 102547 §2 物理页 17](../../007.BOOKs/arm_dsu_120_trm_102547_0201_07_en.pdf#page=17)</sup>

> "Snoop Control Unit (SCU) maintains coherency and consistency in the memory system internal to the cluster, and (optionally) external to the cluster. … SCU includes a set of snoop filters, automatically sized, one for each cache slice"
> <sup>（SCU 维护簇内内存系统的一致性与一致性语义，（可选地）也维护簇外；……SCU 含一组自动定长的 snoop filter，每个 cache slice 一个。）——[DSU-120 TRM §2.1 物理页 19](../../007.BOOKs/arm_dsu_120_trm_102547_0201_07_en.pdf#page=19)</sup>

接口代际（DSU-120 对外主口）：

> "Optional AMBA 5 CHI Issue E 256-bit coherent master bus interface, supports up to four CHI bus master ports."（另有 "Optional AMBA AXI5 Issue H 256-bit non-coherent master bus interface"）
> <sup>（可选 AMBA 5 CHI Issue E 256 位一致性主总线接口，最多四个 CHI 主口；另有可选 AMBA AXI5 Issue H 256 位非一致主口。）——[DSU-120 TRM §2.1 物理页 19](../../007.BOOKs/arm_dsu_120_trm_102547_0201_07_en.pdf#page=19)</sup>

**代际分界的第三个证据：Direct connect 模式**【具体芯片已实现规格，Neoverse V3】：

> "The Neoverse™ V3 core supports Direct connect only. … The following ﬁgure shows an example conﬁguration with one Neoverse™ V3 core that is implemented as a single core in a DSU cluster which is conﬁgured for Direct connect, without the L3 cache, snoop filter, or Snoop Control Unit (SCU) logic present."
> <sup>（Neoverse V3 核只支持 Direct connect。……示例配置中，V3 核以单核实现于配置为 Direct connect 的 DSU 簇中——该配置下不存在 L3 cache、snoop filter 与 SCU 逻辑。）——[Neoverse V3 Core TRM 107734 §1 物理页 18](../../007.BOOKs/arm_neoverse_v3_core_technical_reference_manual_107734_0002_06_en.pdf#page=18)</sup>

> "When DSU-110 or DSU-120 is in Direct connect mode, no L3 cache is present and no MPAM partitioning interface is implemented."
> <sup>（DSU-110/120 处于 Direct connect 模式时，不存在 L3 cache，也不实现 MPAM 分区接口。）——[MPAM Hardware Guide 109252 §3.2 物理页 16](../../007.BOOKs/learn_the_architecture_-_memory_system_resource_partitioning_and_monitoring_%28mpam%29_hardware_guide_109252_0101_01_en.pdf#page=16)</sup>

A725 一代从核侧证实 DSU-120 的角色（SVE 能力也在同一 TRM）：

> "The Cortex®-A725 core is implemented inside a DSU-120 DynamIQ™ cluster. It is connected to the DynamIQ™ Shared Unit-120 that behaves as a full interconnect with L3 cache and snoop control."

A520 的 complex 形态（对应 DSU-120 的 complexes 能力）与 SVE2 实现：

> "Cortex-A520 cores are implemented inside a block called a complex, which contains up to two cores. Within a dual-core complex, the Vector Processing Unit (VPU), the L2 Translation Lookaside Buﬀer (TLB), and the L2 cache logic are shared between cores."
> <sup>（A520 核实现于称为 complex 的块内，最多两核；双核 complex 内 VPU、L2 TLB 与 L2 cache 逻辑由两核共享。）——[Cortex-A520 Core TRM 102517 §2 物理页 23](../../007.BOOKs/arm_cortex_a520_core_trm_102517_0001_04_en.pdf#page=23)</sup>

> <sup>（SVE 与 SVE2 SIMD 指令集，提供 Advanced SIMD 与浮点架构支持。）——[A520 TRM §2.1 物理页 25](../../007.BOOKs/arm_cortex_a520_core_trm_102517_0001_04_en.pdf#page=25)</sup>

### 3.4 CCI 家族与 CI-700（互连 IP 层）

**CCI-550（CCI 家族代表）**【具体芯片已实现规格】：

> "The CCI-550 is a programmable high-bandwidth interconnect that enables hardware-coherent systems. … The CCI-550 is a configurable interconnect that supports connectivity of: Up to six AMBA 4 ACE masters, such as the Arm Cortex®-A57 or Cortex-A72 processors. Up to six AMBA 4 ACE-Lite masters, such as the Arm Mali™-T880 Graphics Processing Unit (GPU). Up to seven AMBA 4 AXI4 slaves, such as memory and system peripherals."
> <sup>（CCI-550 是可编程高带宽互连，支持硬件一致性系统……支持连接最多 6 个 AMBA 4 ACE 主设备（如 Cortex-A57/A72）、6 个 ACE-Lite 主设备（如 Mali-T880 GPU）、7 个 AMBA 4 AXI4 从设备（如内存与系统外设）。）——[CCI-550 TRM 100282 §1.1 物理页 12](../../007.BOOKs/corelink_cci550_cache_coherent_interconnect_technical_reference_manual_100282_0100_01_en.pdf#page=12)</sup>

> "Crossbar interconnect functionality between the masters and slaves. … A snoop filter to reduce snoop power and improve performance for snoop misses."

**UCIe 的定义、分层与承载范围**：

> "…covers the die-to-die I/O physical layer, Die-to-Die protocols, and software stack which leverage the well-established PCI Express® (PCIe®) and Compute Express Link® (CXL®) industry standards."

> "This system has many buses (e.g., cache, memory, PCIe, PCI, USB, SATA, and DMI), each with a different transfer rate and function. … The main bus is the PCIe (Peripheral Component Interconnect Express) bus. … In contrast, PCIe makes use of dedicated, point-to-point connections."
> <sup>（该系统有许多总线（缓存、内存、PCIe、PCI、USB、SATA、DMI），各有传输速率与功能……主总线是 PCIe（Peripheral Component Interconnect Express）总线……与之相对，PCIe 使用专用点对点连接。）——[MOS5 §1.3.5 物理页 62](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=62)（印刷页 33）</sup>

> <sup>（可用 32 条 lane 并行传 32 条消息……16 lane PCIe 4.0 提供 256 Gbps；PCIe 5.0 翻倍，6.0 再翻倍。）——[MOS5 §1.3.5 物理页 63](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=63)（印刷页 34）</sup>

## 4. 易混概念对照

### 4.1 SCU vs DSU：同一个位置，两代簇方案

| 维度 | SCU（老代际 MPCore） | DSU（DynamIQ 代际） |
| --- | --- | --- |
| 身份 | 簇内一致性**子组件** | 簇级 IP（DynamIQ cluster 的共享单元） |
| 所在 | MPCore 的 L2 memory system 内（如 A72：紧耦合 L2 + 集成 SCU，§3.3） | DSU 内部仍有一个 SCU 块（DSU TRM §2.1 p17；DSU-120 TRM §2.1 p19） |
| 连接对象 | 簇内 ≤4 核 + L2；簇外经 ACE/CHI 接口 | 簇内 1-14 核（可异构、可 complex）+ 可选 L3 + snoop filter；簇外 CHI Issue E/AXI5 master |
| 适用代际 | Cortex-A9/A15/A17（MPCore 时代）与 A53/A57/A72（前 DynamIQ 多核；以各核 TRM 的 L2 memory system 章节为准） | A55/A75 起（DynamIQ 引入）；现役 DSU-120 支持 Armv9.2-A 核（A520/A725/V3） |
| 代际边界易错点 | 把 DSU 说成"SCU 的别名" | ① DSU ≠ 只有 L3：还含 snoop filter、ACP、peripheral port、DebugBlock；② **Direct connect 模式下 DSU 无 L3 也无 SCU 逻辑**（V3 只支持 Direct connect，§3.3），此时一致性完全交给 mesh 的 HN-F |

一句话：**SCU 是"谁维护簇内一致性"的答案，DSU 是"DynamIQ 时代那个答案住在哪里"**；两代核的集群框图里 SCU 出现的位置不同（老代际独立可见，新代际藏在 DSU 里或 Direct connect 下干脆不存在）。

### 4.2 CCI vs CI-700 vs CMN：三个"一致性互连"命名系列

| 维度 | CCI 家族（CCI-400/500/550） | CI-700 | CMN 家族（CMN-600/700、CMN S3） |
| --- | --- | --- | --- |
| 全称 | Cache Coherent **Interconnect** | Coherent Interconnect（官方名 **CoreLink CI-700 Coherent Interconnect**） | Coherent **Mesh** Network |
| 产品线 | CoreLink（客户端/嵌入式） | CoreLink（客户端/移动） | **Neoverse**（基础设施） |
| 协议代际 | AMBA 4 ACE/ACE-Lite + AXI4（CCI-550 TRM §1.1-1.2） | **AMBA CHI Issue E + AXI Issue H**（产品页） | AMBA 5 CHI Issue E（CMN-700 TRM §2.1） |
| 拓扑 | crossbar（CCI-550 TRM §1.3） | 可配置互连 + 集成 SLC/snoop filter | mesh（1-256 簇，CMN-700 TRM §2.1） |
| 规模定位 | 两簇 big.LITTLE + 少量内存口 | 智能手机/笔记本一致性骨干（含 SLC） | 服务器/网络/CSS 主干（含 SLC、CXL 桥、芯片扩展） |
| 代际沿革 | 2011 起（CCI-400）→ CCI-550 | CI-700 为 CHI 代际的 CoreLink 一致性互连 | CMN-600 → CMN-700 → CMN S3（S3 = 第三代 Neoverse System IP，R2） |

关键结论：**"CI-700 属于 CCI 家族"是错误归类**——两者同属"一致性互连"能力类别（R7 产品入口把它们列在同一分组），但 CCI 是一个以 ACE 协议代际为特征的独立命名家族，CI-700 从命名（CI ≠ CCI）、协议（CHI 而非 ACE）到产品定位都是另一条产品线。

### 4.3 NI vs NoC：非一致互连的代际改名

| 维度 | NI 系列（NI-700、NI-710AE） | NoC S3 | （参考）NIC 系列 NIC-400/450 |
| --- | --- | --- | --- |
| 全称口径 | NI-700 = Network on Chip Interconnect（TRM 标题）；NI-710AE = 汽车非一致互连 | NoC S3 = 非一致 Arm 片上网络互连 | Network Interconnect（如 DMC-620 图 1-1 中 "NIC-400 Network Interconnect"） |
| 一致性边界 | **非一致**（自身不做 snoop）；NoC S3 支持 ACE5-Lite 即 IO 一致转发 | 同左，S3 代际 | 非一致 |
| 代际沿革 | NI-700（2021 前后）→ **NoC S3 built on NI-700**（R2） | S3 代际（与 CMN S3 同代） | 上一代（NIC-400 出现在 DMC-620 示例系统、NIC-450 出现在 N2 CSS） |
| 典型位置 | I/O Macro（NI-700+MMU-700+PHY，R10）；加速器/外设域 | Armv9-A SoC 非一致背板 | 老参考设计 |

易错点：① NI-700 名字里有 "Network on Chip"，容易误当成"一致性 NoC"——它的官方定位是非一致互连（§3.6）；② NoC S3 与 CMN S3 同属 S3 代际但**分工相反**：CMN S3 管一致性主干，NoC S3 管非一致域；③ SI L1 是把"一致性互连 + SLC + 非一致 NoC"打包成一体的新一代产品（Lumex CSS），不沿用 NI/CI 分立命名。

### 4.4 CHI vs CHI C2C vs UCIe：片上协议、芯粒封装、链路承载

沿用 [003 文档 §6.2](003.AMBA-CHI-C2C架构-Figure1-3.md) 的三分口径（依据均为协议规定）：

| 层 | 归属 | 一句话职责 |
| --- | --- | --- |
| 片上一致性域 | **AMBA CHI**（IHI 0050） | 定义 snoop/原子/DVM/缓存状态——事务语义 |
| 跨芯粒消息封装 | **AMBA CHI C2C**（IHI 0098） | Protocol 转换 + 把消息装进固定 256B 容器 + 流控/初始化/属性协商 |
| 跨芯粒链路承载 | **UCIe 或其他标准/定制** | D2D Adapter（CRC/重试）+ PHY 电气传输 |

常见误判的纠正口径："UCIe 只是把 AMBA 协议打包搬运到另一颗芯粒的物理高速通道"——**"打包搬运"的主体是 CHI C2C 的 Packetization 层（协议行为），UCIe 提供的是承载它的 Data-link/PHY（且 UCIe 自身也有 CRC/重试链路功能）**；把 UCIe 只说成"物理通道"会漏掉其链路层职责，把 UCIe 说成"打包协议"则会与 CHI C2C 职责重叠（完整分析见 [003 文档 §6.2](003.AMBA-CHI-C2C架构-Figure1-3.md)，具体芯片是否按此连接见 [005 文档](005.Arm-AGI-CPU架构核验.md)）。

## 6. 内核触点（arm64 主线，Linux 7.1.3 实测）

> 源码路径相对 `000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/`，行号均为 `grep -n`/`sed -n` 实测。

**DMA-350：内核有官方驱动**（`CONFIG_ARM_DMA350`，drivers/dma/Kconfig:95-101，"Enable support for the Arm DMA-350 controller."）。驱动以 platform driver 注册，按设备树 compatible `"arm,dma-350"` 匹配，probe 时读 IIDR 校验产品 ID：

```c
// drivers/dma/arm-dma350.c:3,32,526,543-544,643-644,656
// Arm DMA-350 driver
#define PRODUCTID_DMA350	0x3a0
static int d350_probe(struct platform_device *pdev)      // :526
	if (FIELD_GET(IIDR_IMPLEMENTER, reg) != IMPLEMENTER_ARM ||
	    FIELD_GET(IIDR_PRODUCTID, reg) != PRODUCTID_DMA350)
		return dev_err_probe(dev, -ENODEV, "Not a DMA-350!");   // :543-544
static const struct of_device_id d350_of_match[] __maybe_unused = {
	{ .compatible = "arm,dma-350" },                        // :643
module_platform_driver(d350_driver);                      // :656
```

要点：驱动验证了 DMA-350 是**平台设备（挂 platform bus）而非 AMBA(PrimeCell) 总线设备**；probe 从 `DMA_BUILDCFG0` 读出通道数/数据宽度/地址宽度（`drivers/dma/arm-dma350.c:546-549`，`DMA_CFG_NUM_CHANNELS` 等），从 `DMA_BUILDCFG1` 读出触发请求数（`:560-561`），与产品页"可配置通道/宽度"的描述一致（§3.7）。

一句话读法：**"协议 → IP → 内核触点"链条在本表是成立的**——CCI 驱动管理的是协议/IP 规定的端口行为（摘核时断开），CMN/NI/DSU/DMC-620 驱动消费的是各 IP 自带的性能监控设施；互连的**事务转发与缓存一致性完全由硬件实现**，内核不存在也不需要"转发/一致性"驱动——这正对应 §1.2 里"硬件实现协议"那一层，而不是内核触点缺失。另注意配置门控的代际含义：CCI 端口控制 `ARM_CCI400_PORT_CTRL` 为 `depends on ARM && OF && CPU_V7`（`drivers/bus/Kconfig:15-21`，32 位 ARM 才编译），arm64 平台的 CCI 触点主要是 PMU 侧（§6 上表）。

**SVE：内核按 CPU 特性位动态使能**。特性判定入口与上下文切换保存/恢复点：

```c
// arch/arm64/include/asm/cpufeature.h:757-760
static __always_inline bool system_supports_sve(void)
{
	return alternative_has_cap_unlikely(ARM64_SVE);
}

// arch/arm64/kernel/fpsimd.c:360-392  task_fpsimd_load(): 上下文切换时按任务状态装回
// FP_STATE_FPSIMD / FP_STATE_SVE 两种格式, SVE 状态含向量长度 sve_vl
	if (system_supports_sve() || system_supports_sme()) {          // :370
		switch (current->thread.fp_type) {
		case FP_STATE_FPSIMD:
			clear_thread_flag(TIF_SVE);                     // :374
			break;
		case FP_STATE_SVE:
			if (test_thread_flag(TIF_SVE))
				sve_set_vq(sve_vq_from_vl(task_get_sve_vl(current)) - 1);  // :380-381
```

要点：硬件是否实现 SVE（V3/A725/A520 均实现，§3.9）由 CPU 特性位 `ARM64_SVE` 反映；内核对 SVE 的全部管理（状态格式、向量长度、SME 交互）都发生在 `fpsimd.c` 的任务状态机里，**与互连/总线无关**——印证 §3.9 "指令集扩展不占互连栈层次" 的分类结论。

**AMBA 总线设备模型**：APB/AHB 时代的 PrimeCell 外设在内核有专属 bus_type（与 §3.2 的"APB 上挂外设"形成软件侧对照）：

```c
// drivers/amba/bus.c:436-447
const struct bus_type amba_bustype = {
	.name		= "amba",
	.match		= amba_match,
	.dma_configure	= amba_dma_configure,
	...
};
EXPORT_SYMBOL_GPL(amba_bustype);
```

要点：`amba_bustype` 以外设的 PrimeCell PERIPHID（`amba_read_periphid`，bus.c:134）匹配驱动，是 AMBA APB 外设生态在 Linux 设备模型里的直接残留。本表中的互连/组件 IP **不通过** `amba_bustype` 挂载——它们以 platform 设备加专属驱动接入（§6 的 CCI 端口控制表与 CMN/NI/DSU/DMC-620 PMU 表），"内核视图"是内存映射寄存器空间、设备树/ACPI 节点与 PMU 抽象。

### 7.2 对既有笔记的勘误

1. **[总线 BUS 学习资料索引](../053.总线-BUS/000.总线BUS-学习资料索引.md) "空白提醒"一节**称"仓库缺 AMBA 协议规范（AXI / ACE / CHI 协议文档）"。当前仓库 `007.BOOKs/` 已收录 AMBA 规范五份：IHI 0022L（AXI，2025-08-27）、IHI 0033C（AHB，2021）、IHI 0024E（APB，2023）、IHI 0050H（CHI，2025-09-17）、IHI 0098B（CHI C2C，2026-03-23）——该提醒已过时，可在索引复核时更新（本文档不改索引）。
2. **[000.ARM资料库：DynamIQ Shared Unit 笔记](../../007.BOOKs/000.ARM资料库/000.DynamIQ%20Shared%20Unit.md)** 中"跨簇一致性没有使用 MESI 协议"的表述可补充一条规范级证据：CHI 规范明确支持两种缓存状态模型——"Both MESI and MOESI cache models with forwarding of data from any cache state."（[IHI 0050H §B1.1.2 物理页 29](../../007.BOOKs/IHI0050H_amba_chi_architecture_spec.pdf#page=29)）。即 CHI 体系内缓存状态模型包含 MESI/MOESI 两种（另有部分/空行等扩展状态），"与 MESI 无关"的说法不成立；该勘误方向与 [001 文档 §7 勘误](001.Arm-CSS-计算子系统.md)一致，本文补充规范原文。
3. **易错口径提醒（非针对特定笔记）**："NI-700 是一致性互连"（实为非一致，§4.3）、"CI-700 是 CCI 家族成员"（实为独立 Coherent Interconnect 产品线，§4.2）、"DSU=簇内 L3 的别名"（Direct connect 模式下无 L3/SCU，§4.1）这三类说法在资料流转中常见，引用时以本表 §4 的口径为准。
