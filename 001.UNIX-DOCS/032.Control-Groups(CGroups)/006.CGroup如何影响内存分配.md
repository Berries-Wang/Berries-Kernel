## 0. 结论速览

memory cgroup（memcg）对内存的影响可以概括为一句话：**在"物理内存被实际占用"的每个入口记账（charge），账本超限则施加不同强度的反压（回收 / 减速 / OOM）**。

四层水位，四种反应：

| 接口文件(v2) | 写入函数 | 超限后的行为 | 强度 |
|---|---|---|---|
| `memory.min` | `memory_min_write()` mm/memcontrol.c:4620 | 即使全局缺页也**绝不回收**该组（硬保护） | 保护 |
| `memory.low` | `memory_low_write()` mm/memcontrol.c:4643 | 全局回收时**尽量跳过**该组（软保护） | 保护 |
| `memory.high` | `memory_high_write()` mm/memcontrol.c:4666 | 分配者被强制**回收 + 睡眠减速**（throttle），不杀进程 | 反压 |
| `memory.max` | `memory_max_write()` mm/memcontrol.c:4718 | 反复回收，无果则 **memcg OOM kill** | 终极 |

对 [README](./README.md) 中"系统运行时 cgroup 何时干预"表格的源码级验证结论（7.1.3）：

| 阶段 | 是否计费 | 证据 |
|---|---|---|
| `malloc`（只建 VMA） | **否** | 纯地址空间操作，无 charge 钩子 |
| 初次读写触发缺页 → 分配物理页 | **是** | `alloc_anon_folio()` mm/memory.c:5216 → `mem_cgroup_charge()` memory.c:5274 |
| 读文件装入 page cache | **是** | `filemap_add_folio()` mm/filemap.c:950 → charge 于 filemap.c:960 |
| 内核对象（slab/kmalloc） | **是** | `__memcg_slab_post_alloc_hook()` mm/memcontrol.c:3429 |
| 写已存在的页 | 否 | 物理页已计费，无新 charge |
| 从 swap 换入 | **是** | `mem_cgroup_swapin_charge_folio()` memcontrol.c:5093 |

`page_counter` 是一棵**沿 cgroup 层级向上串联的计数器树**——charge 永远"从叶子走到根"：

```c

	atomic_long_t usage;       // 本组用量
	struct page_counter *parent;   // 父组账本 (charge 沿此链上溯)
	unsigned long min, low, high, max;   // 四层水位 (单位: 页)

	unsigned long failcnt;
	...

```

两个性能设计值得记住：

1. **per-CPU stock（批发）**：charge 不逐页操作原子计数器，每 CPU 缓存 `MEMCG_CHARGE_BATCH = 64` 页（include/linux/memcontrol.h:334），先用本地库存 `consume_stock()`（memcontrol.c:2054），用完再一次性 `refill_stock()`（memcontrol.c:2152）。
2. **obj_cgroup（内核内存细粒度记账）**：slab 对象以 obj_cgroup 为单位挂账，页级账本仍是 memcg。

两段关键源码——**层级记账**（为什么父组的 limit 也会拦住子组）：

```c
/* mm/page_counter.c:118 完整函数体 */
bool page_counter_try_charge(struct page_counter *counter,
			     unsigned long nr_pages,
			     struct page_counter **fail)
{
	struct page_counter *c;
	bool protection = track_protection(counter);
	bool track_failcnt = counter->track_failcnt;

	for (c = counter; c; c = c->parent) {          // ← 从本组一路加到根
		long new;
		/*
		 * Charge speculatively to avoid an expensive CAS.  If
		 * a bigger charge fails, it might falsely lock out a
		 * racing smaller charge and send it into reclaim
		 * early, but the error is limited to the difference
		 * between the two sizes, which is less than 2M/4M in
		 * case of a THP locking out a regular page charge.
		 * ...
		 */
		new = atomic_long_add_return(nr_pages, &c->usage);
		if (new > c->max) {                    // 任何一层超 max
			atomic_long_sub(nr_pages, &c->usage);
			/*
			 * This is racy, but we can live with some
			 * inaccuracy in the failcnt which is only used
			 * to report stats.
			 */
			if (track_failcnt)
				data_race(c->failcnt++);       // memory.max 统计 failcnt
			*fail = c;
			goto failed;                   // 整体回滚
		}
		if (protection)
			propagate_protected_usage(c, new);

		/* see comment on page_counter_charge */
		if (new > READ_ONCE(c->local_watermark)) {          // memory.peak 水位
			WRITE_ONCE(c->local_watermark, new);
			if (new > READ_ONCE(c->watermark))
				WRITE_ONCE(c->watermark, new);
		}
	}
	return true;

failed:
	for (c = counter; c != *fail; c = c->parent)    // 已加过的层逐层撤销
		page_counter_cancel(c, nr_pages);

	return false;
}
```

**回收入口**：

```c
/* mm/vmscan.c:6806 完整函数体 */
unsigned long try_to_free_mem_cgroup_pages(struct mem_cgroup *memcg,
					   unsigned long nr_pages,
					   gfp_t gfp_mask,
					   unsigned int reclaim_options,
					   int *swappiness)
{
	unsigned long nr_reclaimed;
	unsigned int noreclaim_flag;
	struct scan_control sc = {
		.nr_to_reclaim = max(nr_pages, SWAP_CLUSTER_MAX),
		.proactive_swappiness = swappiness,
		.gfp_mask = (current_gfp_context(gfp_mask) & GFP_RECLAIM_MASK) |
				(GFP_HIGHUSER_MOVABLE & ~GFP_RECLAIM_MASK),
		.reclaim_idx = MAX_NR_ZONES - 1,
		.target_mem_cgroup = memcg,          // ← 只回收这个 memcg 的页
		.priority = DEF_PRIORITY,
		.may_writepage = 1,
		.may_unmap = 1,
		.may_swap = !!(reclaim_options & MEMCG_RECLAIM_MAY_SWAP),
		.proactive = !!(reclaim_options & MEMCG_RECLAIM_PROACTIVE),
	};
	/*
	 * Traverse the ZONELIST_FALLBACK zonelist of the current node to put
	 * equal pressure on all the nodes. This is based on the assumption that
	 * the reclaim does not bail out early.
	 */
	struct zonelist *zonelist = node_zonelist(numa_node_id(), sc.gfp_mask);

	set_task_reclaim_state(current, &sc.reclaim_state);
	trace_mm_vmscan_memcg_reclaim_begin(sc.gfp_mask, 0, memcg);
	noreclaim_flag = memalloc_noreclaim_save();

	nr_reclaimed = do_try_to_free_pages(zonelist, &sc);   // → shrink_node → 只扫
	                                                      //    target_mem_cgroup 子树
	memalloc_noreclaim_restore(noreclaim_flag);
	trace_mm_vmscan_memcg_reclaim_end(nr_reclaimed, memcg);
	set_task_reclaim_state(current, NULL);

	return nr_reclaimed;
}
```

与全局回收（[kswapd](./000.kswapd是什么.md)）的区别：**目标限定**——memcg 回收只扫该组自己的 LRU（每个 memcg 每个 NUMA 节点有独立 `lruvec`，经 `mem_cgroup_lruvec()` 获取），不会去抢别组的页；全局回收则遍历所有 memcg。这也是容器内存压力互相隔离的根源。

### 3.1 主流程完整源码：try_charge_memcg()（mm/memcontrol.c:2570）

```c
/* mm/memcontrol.c:2570 完整函数体 (≈190 行, 注释原样保留) */
static int try_charge_memcg(struct mem_cgroup *memcg, gfp_t gfp_mask,
			    unsigned int nr_pages)
{
	unsigned int batch = max(MEMCG_CHARGE_BATCH, nr_pages);   // 64 页批发
	int nr_retries = MAX_RECLAIM_RETRIES;                     // 16 (mm/internal.h:626)
	struct mem_cgroup *mem_over_limit;
	struct page_counter *counter;
	unsigned long nr_reclaimed;
	bool passed_oom = false;
	unsigned int reclaim_options;
	bool drained = false;
	bool raised_max_event = false;
	unsigned long pflags;
	bool allow_spinning = gfpflags_allow_spinning(gfp_mask);

retry:
	if (consume_stock(memcg, nr_pages))               // ★ 快路径: 本 CPU 库存 (011 §2.2)
		return 0;

	if (!allow_spinning)
		/* Avoid the refill and flush of the older stock */
		batch = nr_pages;

	reclaim_options = MEMCG_RECLAIM_MAY_SWAP;
	if (!do_memsw_account() ||
	    page_counter_try_charge(&memcg->memsw, batch, &counter)) {
		if (page_counter_try_charge(&memcg->memory, batch, &counter))
			goto done_restock;                    // ★ 成功
		if (do_memsw_account())
			page_counter_uncharge(&memcg->memsw, batch);
		mem_over_limit = mem_cgroup_from_counter(counter, memory);
	} else {
		mem_over_limit = mem_cgroup_from_counter(counter, memsw);
		reclaim_options &= ~MEMCG_RECLAIM_MAY_SWAP;
	}

	if (batch > nr_pages) {
		batch = nr_pages;         // 批量失败 → 缩到精确量再试一次
		goto retry;
	}

	/*
	 * Prevent unbounded recursion when reclaim operations need to
	 * allocate memory. This might exceed the limits temporarily,
	 * but we prefer facilitating memory reclaim and getting back
	 * under the limit over triggering OOM kills in these cases.
	 */
	if (unlikely(current->flags & PF_MEMALLOC))       // 回收者自身 → 放行 (防死锁)
		goto force;

	if (unlikely(task_in_memcg_oom(current)))         // 已在 OOM 流程中
		goto nomem;

	if (!gfpflags_allow_blocking(gfp_mask))           // 原子上下文不能睡
		goto nomem;

	__memcg_memory_event(mem_over_limit, MEMCG_MAX, allow_spinning);
	raised_max_event = true;                          // ← memory.events: max

	psi_memstall_enter(&pflags);                      // ← PSI 记账 (011 §4)
	nr_reclaimed = try_to_free_mem_cgroup_pages(mem_over_limit, nr_pages,
						    gfp_mask, reclaim_options, NULL);
	psi_memstall_leave(&pflags);

	if (mem_cgroup_margin(mem_over_limit) >= nr_pages)
		goto retry;                               // 回收见效 → 重试 charge

	if (!drained) {
		drain_all_stock(mem_over_limit);          // 收回各 CPU 库存零钱
		drained = true;
		goto retry;
	}

	if (gfp_mask & __GFP_NORETRY)
		goto nomem;
	/*
	 * Even though the limit is exceeded at this point, reclaim
	 * may have been able to free some pages.  Retry the charge
	 * before killing the task.
	 *
	 * Only for regular pages, though: huge pages are rather
	 * unlikely to succeed so close to the limit, and we fall back
	 * to regular pages anyway in case of failure.
	 */
	if (nr_reclaimed && nr_pages <= (1 << PAGE_ALLOC_COSTLY_ORDER))
		goto retry;

	if (nr_retries--)                                // 16 轮回收重试
		goto retry;

	if (gfp_mask & __GFP_RETRY_MAYFAIL)
		goto nomem;

	/* Avoid endless loop for tasks bypassed by the oom killer */
	if (passed_oom && task_is_dying())
		goto nomem;

	/*
	 * keep retrying as long as the memcg oom killer is able to make
	 * a forward progress or bypass the charge if the oom killer
	 * couldn't make any progress.
	 */
	if (mem_cgroup_oom(mem_over_limit, gfp_mask,
			   get_order(nr_pages * PAGE_SIZE))) {
		passed_oom = true;                       // OOM 杀出空间 → 带新额度重试
		nr_retries = MAX_RECLAIM_RETRIES;
		goto retry;
	}
nomem:
	/*
	 * Memcg doesn't have a dedicated reserve for atomic
	 * allocations. But like the global atomic pool, we need to
	 * put the burden of reclaim on regular allocation requests
	 * and let these go through as privileged allocations.
	 */
	if (!(gfp_mask & (__GFP_NOFAIL | __GFP_HIGH)))
		return -ENOMEM;                           // ← malloc 返回 NULL 的源头
force:
	/*
	 * If the allocation has to be enforced, don't forget to raise
	 * a MEMCG_MAX event.
	 */
	if (!raised_max_event)
		__memcg_memory_event(mem_over_limit, MEMCG_MAX, allow_spinning);

	/*
	 * The allocation either can't fail or will lead to more memory
	 * being freed very soon.  Allow memory usage go over the limit
	 * temporarily by force charging it.
	 */
	page_counter_charge(&memcg->memory, nr_pages);   // 强制记账 (允许暂时超限)
	if (do_memsw_account())
		page_counter_charge(&memcg->memsw, nr_pages);

	return 0;

done_restock:
	if (batch > nr_pages)
		refill_stock(memcg, batch - nr_pages);   // 用剩的入本地库存

	/*
	 * If the hierarchy is above the normal consumption range, schedule
	 * reclaim on returning to userland. ... (memory.high 检查, 见 §5)
	 */
	do {
		bool mem_high, swap_high;

		mem_high = page_counter_read(&memcg->memory) >
			READ_ONCE(memcg->memory.high);   // 逐级祖先检查是否超 high
		swap_high = page_counter_read(&memcg->swap) >
			READ_ONCE(memcg->swap.high);

		/* Don't bother a random interrupted task */
		if (!in_task()) {
			if (mem_high) {
				schedule_work(&memcg->high_work);  // 中断上下文: 交给工作队列
				break;
			}
			continue;
		}

		if (mem_high || swap_high) {
			/*
			 * The allocating tasks in this cgroup will need to do
			 * reclaim or be throttled to prevent further growth
			 * of the memory or swap footprints.
			 *
			 * Target some best-effort fairness between the tasks,
			 * and distribute reclaim work and delay penalties
			 * based on how much each task is actually allocating.
			 */
			current->memcg_nr_pages_over_high += batch;   // 记"欠账"
			set_notify_resume(current);   // 返回用户态时触发罚睡 (§5)
			break;
		}
	} while ((memcg = parent_mem_cgroup(memcg)));

	/*
	 * Reclaim is set up above to be called from the userland
	 * return path. But also attempt synchronous reclaim to avoid
	 * excessive overrun while the task is still inside the
	 * kernel. ...
	 */
	if (current->memcg_nr_pages_over_high > MEMCG_CHARGE_BATCH &&
	    !(current->flags & PF_MEMALLOC) &&
	    gfpflags_allow_blocking(gfp_mask))
		__mem_cgroup_handle_over_high(gfp_mask);        // 同步兜底回收
	return 0;
}

/* mm/memcontrol.c:2763: 根组不记账, 直接放行 */
static inline int try_charge(struct mem_cgroup *memcg, gfp_t gfp_mask,
			     unsigned int nr_pages)
{
	if (mem_cgroup_is_root(memcg))
		return 0;

	return try_charge_memcg(memcg, gfp_mask, nr_pages);
}
```

保护值经层级折算成"有效保护"（`page_counter_calculate_protection()` mm/page_counter.c:424 → `mem_cgroup_calculate_protection()` mm/memcontrol.c:5000，兄弟未用满的保护可被借走，折算出 `emin/elow`），随后被回收器消费：

```c
/* mm/vmscan.c:2424 完整函数体 */
static unsigned long apply_proportional_protection(struct mem_cgroup *memcg,
		struct scan_control *sc, unsigned long scan)
{
	unsigned long min, low, usage;

	mem_cgroup_protection(sc->target_mem_cgroup, memcg, &min, &low, &usage);
				    // include/linux/memcontrol.h:536, 读 memory.emin/elow

	if (min || low) {
		/*
		 * Scale a cgroup's reclaim pressure by proportioning
		 * its current usage to its memory.low or memory.min
		 * setting.
		 * ...
		 * If there is any protection in place, we reduce scan
		 * pressure by how much of the total memory used is
		 * within protection thresholds.
		 * ...
		 */
		unsigned long protection;

		/* memory.low scaling, make sure we retry before OOM */
		if (!sc->memcg_low_reclaim && low > min) {
			protection = low;                  // 第一轮: 尊重 low
			sc->memcg_low_skipped = 1;         // 记录"曾跳过", 第二轮再回来
		} else {
			protection = min;                  // 第二轮/OOM 前: 只尊重 min
		}

		/* Avoid TOCTOU with earlier protection check */
		usage = max(usage, protection);

		scan -= scan * protection / (usage + 1);    // ★ 按保护占比缩放扫描量

		/*
		 * Minimally target SWAP_CLUSTER_MAX pages to keep
		 * reclaim moving forwards, avoiding decrementing
		 * sc->priority further than desirable.
		 */
		scan = max(scan, SWAP_CLUSTER_MAX);         // 保底 32 页, 防止卡死
	}
	return scan;
}
```

> **7.1.3 的变化**：保护从老内核的"二元跳过"改成了**按保护比例缩放扫描强度**（调用点 `get_scan_count()` vmscan.c:2567、`get_nr_to_scan()` vmscan.c:4959）——受保护的组不是完全免扫，而是扫描压力按"用量中受保护占比"降低，回收不足时还有第二轮兜底。语义：**min 绝不动（用了可能死锁数据）；low 尽量不动；两者都只是"别人缺页时你不被害"，不限制你自己涨**。

## 5. memory.high：减速带（throttle 而不杀）

`memory.max` 是墙，`memory.high` 是减速带——超限后分配进程被强制回收并被罚睡。检查点在 `try_charge_memcg()` 的成功路径尾部（done_restock 段，mm/memcontrol.c:2706 起，完整源码见 §3.1：超 high 则 `current->memcg_nr_pages_over_high += batch; set_notify_resume(current);`，逐级祖先检查）。

和 CPU 限流的 task_work 异曲同工：真正干活在**返回用户态的瞬间**（`resume_user_mode` 路径）：

```c
/* mm/memcontrol.c:2480 完整函数体 */
void __mem_cgroup_handle_over_high(gfp_t gfp_mask)
{
	unsigned long penalty_jiffies;
	unsigned long pflags;
	unsigned long nr_reclaimed;
	unsigned int nr_pages = current->memcg_nr_pages_over_high;
	int nr_retries = MAX_RECLAIM_RETRIES;
	struct mem_cgroup *memcg;
	bool in_retry = false;

	memcg = get_mem_cgroup_from_mm(current->mm);
	current->memcg_nr_pages_over_high = 0;

retry_reclaim:
	/*
	 * Bail if the task is already exiting. Unlike memory.max,
	 * memory.high enforcement isn't as strict, and there is no
	 * OOM killer involved, which means the excess could already
	 * be much bigger (and still growing) than it could for
	 * memory.max; the dying task could get stuck in fruitless
	 * reclaim for a long time, which isn't desirable.
	 */
	if (task_is_dying())
		goto out;

	/*
	 * The allocating task should reclaim at least the batch size, but for
	 * subsequent retries we only want to do what's necessary to prevent oom
	 * or breaching resource isolation.
	 * ...
	 */
	nr_reclaimed = reclaim_high(memcg,
				    in_retry ? SWAP_CLUSTER_MAX : nr_pages,
				    gfp_mask);            // ① 先强制回收 (memcontrol.c:2303,
	                                            //    回收中记 MEMCG_HIGH 事件 :2318)

	/*
	 * memory.high is breached and reclaim is unable to keep up. Throttle
	 * allocators proactively to slow down excessive growth.
	 */
	penalty_jiffies = calculate_high_delay(memcg, nr_pages,
					       mem_find_max_overage(memcg));

	penalty_jiffies += calculate_high_delay(memcg, nr_pages,
						swap_find_max_overage(memcg));

	/*
	 * Clamp the max delay per usermode return so as to still keep the
	 * application moving forwards and also permit diagnostics, albeit
	 * extremely slowly.
	 */
	penalty_jiffies = min(penalty_jiffies, MEMCG_MAX_HIGH_DELAY_JIFFIES);  // ≤ 2s

	/*
	 * Don't sleep if the amount of jiffies this memcg owes us is so low
	 * that it's not even worth doing, in an attempt to be nice to those who
	 * go only a small amount over their memory.high value and maybe haven't
	 * been aggressively reclaimed enough yet.
	 */
	if (penalty_jiffies <= HZ / 100)                 // 超出 <1% 周期: 免罚
		goto out;

	/*
	 * If reclaim is making forward progress but we're still over
	 * memory.high, we want to encourage that rather than doing allocator
	 * throttling.
	 */
	if (nr_reclaimed || nr_retries--) {
		in_retry = true;
		goto retry_reclaim;                      // 回收有进展: 再给机会
	}

	/*
	 * Reclaim didn't manage to push usage below the limit, slow
	 * this allocating task down.
	 * ...
	 */
	psi_memstall_enter(&pflags);                     // ← 罚睡也计入 PSI
	schedule_timeout_killable(penalty_jiffies);      // ② 罚睡 (TASK_KILLABLE)
	psi_memstall_leave(&pflags);

out:
	css_put(&memcg->css);
}
```

罚睡时长的计算——**超出量平方**增长：

```c
/* mm/memcontrol.c:2443 完整函数体 */
static unsigned long calculate_high_delay(struct mem_cgroup *memcg,
					  unsigned int nr_pages,
					  u64 max_overage)
{
	unsigned long penalty_jiffies;

	if (!max_overage)
		return 0;

	/*
	 * We use overage compared to memory.high to calculate the number of
	 * jiffies to sleep (penalty_jiffies). Ideally this value should be
	 * fairly lenient on small overages, and increasingly harsh when the
	 * memcg in question makes it clear that it has no intention of stopping
	 * its crazy behaviour, so we exponentially increase the delay based on
	 * overage amount.
	 */
	penalty_jiffies = max_overage * max_overage * HZ;    // ★ 平方惩罚
	penalty_jiffies >>= MEMCG_DELAY_PRECISION_SHIFT;
	penalty_jiffies >>= MEMCG_DELAY_SCALING_SHIFT;

	/*
	 * Factor in the task's own contribution to the overage, such that four
	 * N-sized allocations are throttled approximately the same as one
	 * 4N-sized allocation.
	 *
	 * MEMCG_CHARGE_BATCH pages is nominal, so work out how much smaller or
	 * larger the current charge patch is than that.
	 */
	return penalty_jiffies * nr_pages / MEMCG_CHARGE_BATCH;   // 按本次分配量加权
}
```

配套的 `reclaim_high()`（memcontrol.c:2303，向上逐级回收直到不超 high；每级回收前 `memcg_memory_event(memcg, MEMCG_HIGH)` 记一次事件 :2318）。

每次返回用户态最多罚 `MEMCG_MAX_HIGH_DELAY_JIFFIES`（2*HZ，memcontrol.c:2343）——"让你慢，但不弄死你"。

**这是 memcg 与 CPU 控制器在机制上最漂亮的对照**：

| | cpu.max | memory.high |
|---|---|---|
| 超限动作 | 停止调度（dequeue） | 强制回收 + 罚睡 |
| 执行时机 | task_work，返回用户态停车 | set_notify_resume，返回用户态罚睡 |
| 严重后果 | 无（周期到自动恢复） | 无（不 OOM） |

## 6. memory.max：墙 + memcg OOM

写入时（`memory_max_write()` memcontrol.c:4718）还会**同步**做一遍回收与 OOM，确保写完之后用量真的 ≤ 新上限：

```c
/* mm/memcontrol.c:4718 完整函数体 */
static ssize_t memory_max_write(struct kernfs_open_file *of,
				char *buf, size_t nbytes, loff_t off)
{
	struct mem_cgroup *memcg = mem_cgroup_from_css(of_css(of));
	unsigned int nr_reclaims = MAX_RECLAIM_RETRIES;
	bool drained = false;
	unsigned long max;
	int err;

	buf = strstrip(buf);
	err = page_counter_memparse(buf, "max", &max);     // 解析 "max" 或字节数
	if (err)
		return err;

	xchg(&memcg->memory.max, max);                     // 先生效新上限

	if (of->file->f_flags & O_NONBLOCK)                // O_NONBLOCK: 只设值不强收
		goto out;

	for (;;) {
		unsigned long nr_pages = page_counter_read(&memcg->memory);

		if (nr_pages <= max)
			break;

		if (signal_pending(current))
			break;

		if (!drained) {
			drain_all_stock(memcg);            // 先收回各 CPU 库存零钱
			drained = true;
			continue;
		}

		if (nr_reclaims) {
			if (!try_to_free_mem_cgroup_pages(memcg, nr_pages - max,
					GFP_KERNEL, MEMCG_RECLAIM_MAY_SWAP, NULL))
				nr_reclaims--;            // 16 轮同步回收
			continue;
		}

		memcg_memory_event(memcg, MEMCG_OOM);
		if (!mem_cgroup_out_of_memory(memcg, GFP_KERNEL, 0))
			break;                           // OOM 也杀不动了: 放弃
		cond_resched();
	}
out:
	memcg_wb_domain_size_changed(memcg);               // 更新写回阈值域
	return nbytes;
}
```

运行期撞墙走 §3 的 `mem_cgroup_oom()` → `mem_cgroup_out_of_memory()`：

```c
/* mm/memcontrol.c:1885 完整函数体 */
static bool mem_cgroup_out_of_memory(struct mem_cgroup *memcg, gfp_t gfp_mask,
				     int order)
{
	struct oom_control oc = {
		.zonelist = NULL,
		.nodemask = NULL,
		.memcg = memcg,                     // ← OOM 候选限定在该 memcg 内
		.gfp_mask = gfp_mask,
		.order = order,
	};
	bool ret = true;

	if (mutex_lock_killable(&oom_lock))      // 全局 OOM 互斥锁
		return true;

	if (mem_cgroup_margin(memcg) >= (1 << order))
		goto unlock;                     // 拿到锁后发现已有余量: 不用杀了

	/*
	 * A few threads which were not waiting at mutex_lock_killable() can
	 * fail to bail out. Therefore, check again after holding oom_lock.
	 */
	ret = out_of_memory(&oc);                // mm/oom_kill.c:1103

unlock:
	mutex_unlock(&oom_lock);
	return ret;
}
```

要点：
- **victim 只从该 memcg（及其后代）里选**——组内 OOM 不污染组外进程（与系统级 OOM 的本质区别）；
- `memory.oom.group = 1` 时（`memory_oom_group_write()` memcontrol.c:4865 → `memcg->oom_group`），杀一个不够就整组清场：`out_of_memory()` 里经 `mem_cgroup_get_oom_group()`（memcontrol.c:1947，oom_kill.c:1040 调用）确定清算范围——容器场景防止 init 进程幸存而组仍卡死；
- 被杀进程的 dmesg 形如 `Memory cgroup out of memory: Killed process ...`，用户态可用 `memory.events` 的 `oom_kill` 计数监控。

## 9. 小结：一次容器内存超限的完整时间线

```
echo 512M > memory.max; echo 256M > memory.high  (容器组 G)

t0   进程持续 malloc+touch
     缺页 → alloc_anon_folio() mm/memory.c:5216
       → mem_cgroup_charge() → try_charge_memcg() memcontrol.c:2570
       → consume_stock / page_counter_try_charge()  顺利, 用量 ↑

t1   usage > memory.high (256M)
     charge 成功但 done_restock 检出超限 (memcontrol.c:2746)
       → current->memcg_nr_pages_over_high += batch
       → set_notify_resume()
     返回用户态: __mem_cgroup_handle_over_high() memcontrol.c:2480
       → reclaim_high() :2303 (同步回收, memory.events: high ↑)
       → 仍超 → schedule_timeout_killover(罚睡, 平方增长)
     现象: 进程变慢, CPU 时间被花在回收/睡眠上, 但不被杀

t2   usage 逼近 memory.max (512M)
     page_counter_try_charge() 失败 (page_counter.c:118)
       → memory.events: max ↑
       → try_to_free_mem_cgroup_pages() vmscan.c:6806  回收 16 轮
       → 仍失败 → mem_cgroup_oom() memcontrol.c:1918
           memory.events: oom ↑
         → out_of_memory() oom_kill.c:1103
           在 G 组内选 victim → SIGKILL
           memory.events: oom_kill ↑
     现象: dmesg "Memory cgroup out of memory", 进程被杀,
           同宿主机其他容器毫发无损
```
