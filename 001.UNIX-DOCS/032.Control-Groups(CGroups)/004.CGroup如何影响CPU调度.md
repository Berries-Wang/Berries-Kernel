## 0. 结论速览

cgroup 不是"另外一个调度器"，它通过**四个抓手**改变了 CFS/EEVDF 调度器的输入：

| 接口文件(v2) | 写入入口函数 | 运行时生效点 | 对调度的作用 |
|---|---|---|---|
| `cpu.weight` | `cpu_weight_write_u64()` kernel/sched/core.c:10383 | `sched_group_set_shares()` fair.c:14107 | **份额**（软限制）：改组实体权重，影响 vruntime 推进速率与 EEVDF slice |
| `cpu.max` | `cpu_max_write()` core.c:10480 | `tg_set_cfs_bandwidth()` core.c:9807 | **带宽**（硬上限）：周期配额 + 限流（throttle） |
| `cpuset.cpus` | `update_cpumask()` kernel/cgroup/cpuset.c:2392 | `set_cpus_allowed_ptr()` → `p->cpus_ptr` | **位置**：任务允许在哪些 CPU 上运行 |
| `cpu.idle` | `cpu_idle_write_s64` | `sched_group_set_idle()` fair.c:14121 | **优先级类**：整组按 SCHED_IDLE 对待 |

另有 `cpu.max.burst`（允许突发透支）、`cpu.uclamp.min/max`（util 钳位，影响调频而非运行时间）。

一句话总结三者的关系：
- `cpu.weight` 决定"抢得到抢不到"（竞争激烈时才起作用）；
- `cpu.max` 决定"最多跑多少"（无论系统是否空闲都生效）；
- `cpuset.cpus` 决定"在哪里跑"。

## 1. 基础：调度器眼里的 cgroup —— task_group 与分层运行队列

### 1.1 从 task_struct 到 task_group

进程并不直接指向 cgroup 目录，而是 `task_struct->cgroups`（css_set）里按子系统索引到 `cgroup_subsys_state`（css）：

```c
/* include/linux/cgroup-defs.h:274 */
struct css_set {
	struct cgroup_subsys_state *subsys[CGROUP_SUBSYS_COUNT];  // 每个子系统一个状态
	refcount_t refcount;
	struct css_set *dom_cset;
	struct cgroup *dfl_cgrp;
	int nr_tasks;
	...
};
```

cpu 控制器的 css 就内嵌在 `task_group` 里，两者通过 `container_of` 互转：

```c
/* kernel/sched/sched.h:560 */
static inline struct task_group *css_tg(struct cgroup_subsys_state *css)
{
	return css ? container_of(css, struct task_group, css) : NULL;
}
```

### 1.2 task_group：一个 cgroup = 每 CPU 一套 (se, cfs_rq)

```c
/* kernel/sched/sched.h:474 */
struct task_group {
	struct cgroup_subsys_state css;

	int			idle;            // cpu.idle=1 时为 SCHED_IDLE 组 (sched.h:477)
#ifdef CONFIG_FAIR_GROUP_SCHED
	struct sched_entity	**se;        // 组在每个 CPU 上的调度实体
	struct cfs_rq		**cfs_rq;    // 组在每个 CPU 上"自己的运行队列"
	unsigned long		shares;         // cpu.weight 的内核表达
	atomic_long_t		load_avg ____cacheline_aligned;
#endif
#ifdef CONFIG_RT_GROUP_SCHED
	struct sched_rt_entity	**rt_se;
	struct rt_rq		**rt_rq;
	struct rt_bandwidth	rt_bandwidth;
#endif
	struct scx_task_group	scx;            // sched_ext (BPF 调度器) 组状态
	struct task_group	*parent;
	struct list_head	siblings;
	struct list_head	children;
	struct cfs_bandwidth	cfs_bandwidth;  // cpu.max 的账本 (sched.h:516)
	...
};
```

**这是理解一切的关键**：开启 `CONFIG_FAIR_GROUP_SCHED` 后，每个 cgroup 在每个 CPU 上都有自己的 `cfs_rq`（组运行队列），组本身作为一个 `sched_entity` 挂到父组的 `cfs_rq` 上。调度变成了一棵树：

```
                    CPU0 的 struct rq
                          │
                    rq->cfs (根 cfs_rq)
                    ┌─────┴──────────────┐
              se(组A)                 se(任务t1)     ← 同一层的实体一起参与 EEVDF 竞争
                    │
             A->cfs_rq[0]                          ← 组 A 在 CPU0 的私有队列
            ┌───────┴────────┐
        se(组A1)          se(任务t2)
            │
      A1->cfs_rq[0]
            │
        se(任务t3)

  pick 路径: pick_task_fair() 从根往下逐层选实体 (fair.c:9197)
             走到组实体就下钻进组的 cfs_rq, 直到叶子任务
```

- cpu.weight 改的是**组实体 se 的权重**（树中每一层的竞争参数）；
- cpu.max 限流时，整棵子树（组在某个 CPU 上的 cfs_rq）被冻结；
- 所以"限制一个 cgroup"在调度器里表现为"限制树中一个节点"。

## 2. 把进程写入 cgroup.procs 时，调度器做了什么

用户态 `echo $PID > cgroup.procs` 的内核路径：

```
cgroup.procs 写入
  └─ cgroup_attach_task()            kernel/cgroup/cgroup.c:2981
       ├─ cpu_cgroup_can_attach()    kernel/sched/core.c:9565
       │    └─ sched_rt_can_attach() kernel/sched/rt.c:2832   (RT 任务准入检查)
       └─ cpu_cgroup_attach()        kernel/sched/core.c:9583
            └─ sched_move_task()     kernel/sched/core.c:9472
                 └─ sched_change_group()  kernel/sched/core.c:9443
                      ├─ tg = container_of(task_css_check(tsk, cpu_cgrp_id, ...),
                      │                   struct task_group, css)
                      ├─ tsk->sched_task_group = tg          // 记住"我属于哪个组"
                      └─ sched_class->task_change_group() / set_task_rq()
                           // 把 task 的 se 从旧组的 cfs_rq 摘下, 挂到新组对应 CPU 的 cfs_rq
```

核心摘录：

```c
/* kernel/sched/core.c:9443 */
static void sched_change_group(struct task_struct *tsk)
{
	struct task_group *tg;

	tg = container_of(task_css_check(tsk, cpu_cgrp_id, true),
			  struct task_group, css);
	tg = autogroup_task_group(tsk, tg);
	tsk->sched_task_group = tg;                    // ← 进程的组归属在此切换

#ifdef CONFIG_FAIR_GROUP_SCHED
	if (tsk->sched_class->task_change_group)
		tsk->sched_class->task_change_group(tsk);
	else
#endif
		set_task_rq(tsk, task_cpu(tsk));           // ← se->cfs_rq / se->parent 指向新组
}
```

**此后该进程的每一次入队，都是进它所在组的 `tg->cfs_rq[cpu]`，而不是根队列。**

## 3. cpu.weight —— 份额（软限制）

### 3.1 写入路径

```c
/* kernel/sched/core.c:10383 完整函数体 */
static int cpu_weight_write_u64(struct cgroup_subsys_state *css,
				struct cftype *cft, u64 cgrp_weight)
{
	unsigned long weight;
	int ret;

	if (cgrp_weight < CGROUP_WEIGHT_MIN || cgrp_weight > CGROUP_WEIGHT_MAX)
		return -ERANGE;                        // 1..10000

	weight = sched_weight_from_cgroup(cgrp_weight);   // 1..10000 → 2..262144

	ret = sched_group_set_shares(css_tg(css), scale_load(weight));
	if (!ret)
		scx_group_set_weight(css_tg(css), cgrp_weight);   // sched_ext 同步
	return ret;
}
```

```c
/* kernel/sched/fair.c:14071 完整函数体 */
static int __sched_group_set_shares(struct task_group *tg, unsigned long shares)
{
	int i;

	lockdep_assert_held(&shares_mutex);

	/*
	 * We can't change the weight of the root cgroup.
	 */
	if (!tg->se[0])
		return -EINVAL;

	shares = clamp(shares, scale_load(MIN_SHARES), scale_load(MAX_SHARES));  // [2, 262144] (sched.h:540)

	if (tg->shares == shares)
		return 0;

	tg->shares = shares;
	for_each_possible_cpu(i) {
		struct rq *rq = cpu_rq(i);
		struct sched_entity *se = tg->se[i];
		struct rq_flags rf;

		/* Propagate contribution to hierarchy */
		rq_lock_irqsave(rq, &rf);
		update_rq_clock(rq);
		for_each_sched_entity(se) {
			update_load_avg(cfs_rq_of(se), se, UPDATE_TG);
			update_cfs_group(se);        // ← 按新权重重算组实体 weight, 向上传播 (010 §5)
		}
		rq_unlock_irqrestore(rq, &rf);
	}

	return 0;
}
```

### 3.2 运行时如何起作用

CFS 用 vruntime 衡量"谁欠 CPU"，EEVDF 继承了这套换算——**权重越高，同样物理时间换来的 vruntime 越少**，于是看起来"跑得慢"，调度器就多给它 CPU：

```c
/* kernel/sched/fair.c:297 */
static inline u64 calc_delta_fair(u64 delta, struct sched_entity *se)
{
	if (unlikely(se->load.weight != NICE_0_LOAD))
		return __calc_delta(delta, NICE_0_LOAD, &se->load);  // delta * 1024 / weight
	return delta;
}
```

这个换算发生在 `update_curr()`（fair.c:1407）里：

```c
/* kernel/sched/fair.c:1407 完整函数体 */
static void update_curr(struct cfs_rq *cfs_rq)
{
	/*
	 * Note: cfs_rq->curr corresponds to the task picked to
	 * run (ie: rq->donor.se) which due to proxy-exec may
	 * not necessarily be the actual task running
	 * (rq->curr.se). This is easy to confuse!
	 */
	struct sched_entity *curr = cfs_rq->curr;
	struct rq *rq = rq_of(cfs_rq);
	s64 delta_exec;
	bool resched;

	if (unlikely(!curr))
		return;

	delta_exec = update_se(rq, curr);              // 本次实际运行了多久
	if (unlikely(delta_exec <= 0))
		return;

	curr->vruntime += calc_delta_fair(delta_exec, curr);   // ① cpu.weight 生效点 (fair.c:297)
	resched = update_deadline(cfs_rq, curr);              // ② EEVDF 到期检查 (010 §4.3)

	if (entity_is_task(curr)) {
		/*
		 * If the fair_server is active, we need to account for the
		 * fair_server time whether or not the task is running on
		 * behalf of fair_server or not: ...
		 */
		dl_server_update(&rq->fair_server, delta_exec);  // (dl_server 记账)
	}

	account_cfs_rq_runtime(cfs_rq, delta_exec);           // ③ cpu.max 记账入口 (§4.3)

	if (cfs_rq->nr_queued == 1)
		return;

	if (resched || !protect_slice(curr)) {
		resched_curr_lazy(rq);                    // ④ 到期/失去保护 → 要求重调度
		clear_buddies(cfs_rq, curr);
	}
}
```

在 EEVDF 中权重还决定实体的 deadline/slice（权重大的任务获得的 time slice 更大），两层效果叠加：`cpu.weight 10000` 的组在与 `cpu.weight 100` 的组竞争同一颗 CPU 时，大约拿走 10000/(10000+100) ≈ 99% 的时间。

**注意**：weight 只在 CPU 饱和时才有意义——系统整体空闲时，即便权重 1 也能跑满（这正是"软限制"）。

## 4. cpu.max —— 周期配额与限流（硬限制）★ 主菜

`echo "20000 100000" > cpu.max` 含义：每 100ms 周期最多用 20ms CPU 时间（多核可叠加：4 核各跑满则 400ms/100ms，超过配额即限流）。

### 4.1 数据结构：组级别的账本

```c
/* kernel/sched/sched.h:447 */
struct cfs_bandwidth {
	raw_spinlock_t		lock;
	ktime_t			period;            // 周期 (默认 100ms, default_bw_period_us sched.h:441)
	u64			quota;             // 每周期配额
	u64			runtime;           // 全局池剩余可分配时间
	u64			burst;             // cpu.max.burst: 允许的突发额度
	u64			runtime_snap;
	s64			hierarchical_quota;

	u8			idle;
	u8			period_active;
	u8			slack_started;
	struct hrtimer		period_timer;      // 周期补给定时器
	struct hrtimer		slack_timer;       // 空闲配额再分配定时器
	struct list_head	throttled_cfs_rq;  // 被限流的 cfs_rq 链表

	/* Statistics: */
	int			nr_periods;        // cpu.stat 里的 nr_periods
	int			nr_throttled;      // cpu.stat 里的 nr_throttled
	int			nr_burst;
	u64			throttled_time;    // cpu.stat 里的 throttled_usec
	u64			burst_time;
};
```

### 4.2 写入路径

```c
/* kernel/sched/core.c:10480 */
static ssize_t cpu_max_write(struct kernfs_open_file *of,
			     char *buf, size_t nbytes, loff_t off)
{
	struct task_group *tg = css_tg(of_css(of));
	u64 period_us, quota_us, burst_us;
	int ret;

	tg_bandwidth(tg, &period_us, NULL, &burst_us);        // 保留旧值
	ret = cpu_period_quota_parse(buf, &period_us, &quota_us);
	if (!ret)
		ret = tg_set_bandwidth(tg, period_us, quota_us, burst_us);
	return ret ?: nbytes;
}
```

`tg_set_bandwidth()`（core.c:10078）做参数校验（周期/配额有上下界，防止精度丢失与溢出），最终落到：

```c
/* kernel/sched/core.c:9807 完整函数体 */
static int tg_set_cfs_bandwidth(struct task_group *tg,
				u64 period_us, u64 quota_us, u64 burst_us)
{
	int i, ret = 0, runtime_enabled, runtime_was_enabled;
	struct cfs_bandwidth *cfs_b = &tg->cfs_bandwidth;
	u64 period, quota, burst;

	period = (u64)period_us * NSEC_PER_USEC;

	if (quota_us == RUNTIME_INF)
		quota = RUNTIME_INF;
	else
		quota = (u64)quota_us * NSEC_PER_USEC;

	burst = (u64)burst_us * NSEC_PER_USEC;

	/*
	 * Prevent race between setting of cfs_rq->runtime_enabled and
	 * unthrottle_offline_cfs_rqs().
	 */
	guard(cpus_read_lock)();
	guard(mutex)(&cfs_constraints_mutex);

	ret = __cfs_schedulable(tg, period, quota);     // 层级可行性检查: 子层级配额总和
	if (ret)                                        //   不得超过父层级
		return ret;

	runtime_enabled = quota != RUNTIME_INF;
	runtime_was_enabled = cfs_b->quota != RUNTIME_INF;
	/*
	 * If we need to toggle cfs_bandwidth_used, off->on must occur
	 * before making related changes, and on->off must occur afterwards
	 */
	if (runtime_enabled && !runtime_was_enabled)
		cfs_bandwidth_usage_inc();             // 全局开关计数 (全系统无配额组时
	                                            //   静态键关闭记账, 零开销)
	scoped_guard (raw_spinlock_irq, &cfs_b->lock) {
		cfs_b->period = ns_to_ktime(period);
		cfs_b->quota = quota;
		cfs_b->burst = burst;

		__refill_cfs_bandwidth_runtime(cfs_b);    // 立刻充满全局池

		/*
		 * Restart the period timer (if active) to handle new
		 * period expiry:
		 */
		if (runtime_enabled)
			start_cfs_bandwidth(cfs_b);        // 启动周期定时器
	}

	for_each_online_cpu(i) {
		struct cfs_rq *cfs_rq = tg->cfs_rq[i];
		struct rq *rq = cfs_rq->rq;

		guard(rq_lock_irq)(rq);
		cfs_rq->runtime_enabled = runtime_enabled;    // ← 打开该 CPU 上记账开关
		cfs_rq->runtime_remaining = 1;

		if (cfs_rq->throttled)
			unthrottle_cfs_rq(cfs_rq);            // 调大配额时立即解限
	}

	if (runtime_was_enabled && !runtime_enabled)
		cfs_bandwidth_usage_dec();

	return 0;
}
```

### 4.3 运行时记账：钱从全局池按片借出

组在每个 CPU 上的 `cfs_rq->runtime_remaining` 是本地余额。`update_curr()` 每次统计完运行时间后调用：

```c
/* kernel/sched/fair.c:5957 */
static void __account_cfs_rq_runtime(struct cfs_rq *cfs_rq, u64 delta_exec)
{
	/* dock delta_exec before expiring quota (as it could span periods) */
	cfs_rq->runtime_remaining -= delta_exec;         // ① 扣本地余额

	if (likely(cfs_rq->runtime_remaining > 0))
		return;

	if (cfs_rq->throttled)
		return;
	/*
	 * if we're unable to extend our runtime we resched so that the active
	 * hierarchy can be throttled
	 */
	if (!assign_cfs_rq_runtime(cfs_rq) && likely(cfs_rq->curr))
		resched_curr(rq_of(cfs_rq));            // ② 借不到钱 → 触发重新调度
}
```

```c
/* kernel/sched/fair.c:5945 */
static int assign_cfs_rq_runtime(struct cfs_rq *cfs_rq)
{
	struct cfs_bandwidth *cfs_b = tg_cfs_bandwidth(cfs_rq->tg);
	int ret;

	raw_spin_lock(&cfs_b->lock);
	ret = __assign_cfs_rq_runtime(cfs_b, cfs_rq, sched_cfs_bandwidth_slice());
	raw_spin_unlock(&cfs_b->lock);

	return ret;
}
```

每次借一片 `sched_cfs_bandwidth_slice()`，默认 **5ms**（`sysctl_sched_cfs_bandwidth_slice`，fair.c:125，可通过 `/proc/sys/kernel/sched_cfs_bandwidth_slice_us` 调整）——用"批发"减少对全局池锁的争用：

```c
/* kernel/sched/fair.c:5917 完整函数体 */
static int __assign_cfs_rq_runtime(struct cfs_bandwidth *cfs_b,
				   struct cfs_rq *cfs_rq, u64 target_runtime)
{
	u64 min_amount, amount = 0;

	lockdep_assert_held(&cfs_b->lock);

	/* note: this is a positive sum as runtime_remaining <= 0 */
	min_amount = target_runtime - cfs_rq->runtime_remaining;

	if (cfs_b->quota == RUNTIME_INF)
		amount = min_amount;                    // 无配额限制: 想借多少借多少
	else {
		start_cfs_bandwidth(cfs_b);

		if (cfs_b->runtime > 0) {
			amount = min(cfs_b->runtime, min_amount);   // 全局池里有多少借多少
			cfs_b->runtime -= amount;
			cfs_b->idle = 0;
		}
	}

	cfs_rq->runtime_remaining += amount;

	return cfs_rq->runtime_remaining > 0;        // 借完还是 ≤0 → 失败
}
```

### 4.4 限流：throttle（7.1.3 新模型，先记结论）

检查点有两处——任务被换下 CPU（`put_prev_entity`）和调度器选下一个任务（`pick_task_fair`）：

```c
/* kernel/sched/fair.c:9197 完整函数体 */
static struct task_struct *pick_task_fair(struct rq *rq, struct rq_flags *rf)
{
	struct sched_entity *se;
	struct cfs_rq *cfs_rq;
	struct task_struct *p;
	bool throttled;

again:
	cfs_rq = &rq->cfs;
	if (!cfs_rq->nr_queued)
		return NULL;

	throttled = false;

	do {
		/* Might not have done put_prev_entity() */
		if (cfs_rq->curr && cfs_rq->curr->on_rq)
			update_curr(cfs_rq);               // 下钻前先把账记清

		throttled |= check_cfs_rq_runtime(cfs_rq);   // ← fair.c:9216, 逐层检查限流

		se = pick_next_entity(rq, cfs_rq, true);     // EEVDF 选实体 (010 §3)
		if (!se)
			goto again;
		cfs_rq = group_cfs_rq(se);               // 组实体 → 下钻进组的 cfs_rq
	} while (cfs_rq);

	p = task_of(se);
	if (unlikely(throttled))
		task_throttle_setup_work(p);             // ← 给当前任务挂"停车"作业
	return p;
}
```

```c
/* kernel/sched/fair.c:6711 */
static bool check_cfs_rq_runtime(struct cfs_rq *cfs_rq)
{
	if (!cfs_bandwidth_used())
		return false;

	if (likely(!cfs_rq->runtime_enabled || cfs_rq->runtime_remaining > 0))
		return false;                        // 余额充足: 不限流

	if (cfs_rq_throttled(cfs_rq))
		return true;                         // 已经限流中

	return throttle_cfs_rq(cfs_rq);          // 真正执行限流
}
```

`throttle_cfs_rq()`（fair.c:6239）先做最后一次"借 1ns"尝试（防止与补充配额竞态误杀），失败后把 cfs_rq 挂到 `cfs_b->throttled_cfs_rq` 链表、设置 `cfs_rq->throttled = 1`，冻结该层负载均值。

> **7.1.3 的变化**：老内核（≤6.16 前后）throttle 会把整棵 cfs_rq 子树从运行队列里出队；7.1.3 改为"树上标记 + 任务级停车"——被选中的任务通过 **task_work** 在**返回用户态的瞬间**被摘下：
>
> ```c
> /* kernel/sched/fair.c:6011 完整函数体 */
> static void throttle_cfs_rq_work(struct callback_head *work)
> {

### 4.5 补给与再分配：两个 hrtimer

**(1) 周期定时器**——每个配额周期把全局池充满，并尝试"赎回"所有限流组：

```c
/* kernel/sched/fair.c:6739 完整函数体 */
static enum hrtimer_restart sched_cfs_period_timer(struct hrtimer *timer)
{
	struct cfs_bandwidth *cfs_b =
		container_of(timer, struct cfs_bandwidth, period_timer);
	unsigned long flags;
	int overrun;
	int idle = 0;
	int count = 0;

	raw_spin_lock_irqsave(&cfs_b->lock, flags);
	for (;;) {
		overrun = hrtimer_forward_now(timer, cfs_b->period);
		if (!overrun)                         // 补齐错过的周期数 (系统卡顿时可能 >1)
			break;

		idle = do_sched_cfs_period_timer(cfs_b, overrun, flags);  // 核心逻辑 (§4.5)

		if (++count > 3) {
			u64 new, old = ktime_to_ns(cfs_b->period);

			/*
			 * Grow period by a factor of 2 to avoid losing precision.
			 * Precision loss in the quota/period ratio can cause __cfs_schedulable
			 * to fail.
			 */
			new = old * 2;                // 定时器积压过多 → 周期翻倍自适应
			if (new < max_bw_quota_period_us * NSEC_PER_USEC) {
				cfs_b->period = ns_to_ktime(new);
				cfs_b->quota *= 2;
				cfs_b->burst *= 2;

				pr_warn_ratelimited(
	"cfs_period_timer[cpu%d]: period too short, scaling up (new cfs_period_us = %lld, cfs_quota_us = %lld)\n",
					smp_processor_id(),
					div_u64(new, NSEC_PER_USEC),
					div_u64(cfs_b->quota, NSEC_PER_USEC));
			} else {
				pr_warn_ratelimited(
	"cfs_period_timer[cpu%d]: period too short, but cannot scale up without losing precision (cfs_period_us = %lld, cfs_quota_us = %lld)\n",
					smp_processor_id(),
					div_u64(old, NSEC_PER_USEC),
					div_u64(cfs_b->quota, NSEC_PER_USEC));
			}

			/* reset count so we don't come right back in here */
			count = 0;
		}
	}
	if (idle)
		cfs_b->period_active = 0;
	raw_spin_unlock_irqrestore(&cfs_b->lock, flags);

	return idle ? HRTIMER_NORESTART : HRTIMER_RESTART;
}
```

```c
/* kernel/sched/fair.c:6491 完整函数体 */
static int do_sched_cfs_period_timer(struct cfs_bandwidth *cfs_b, int overrun, unsigned long flags)
	__must_hold(&cfs_b->lock)
{
	int throttled;

	/* no need to continue the timer with no bandwidth constraint */
	if (cfs_b->quota == RUNTIME_INF)
		goto out_deactivate;

	throttled = !list_empty(&cfs_b->throttled_cfs_rq);
	cfs_b->nr_periods += overrun;                   // cpu.stat: nr_periods

	/* Refill extra burst quota even if cfs_b->idle */
	__refill_cfs_bandwidth_runtime(cfs_b);          // 全局池 += quota (受 burst 上限约束)

	/*
	 * idle depends on !throttled (for the case of a large deficit), and if
	 * we're going inactive then everything else can be deferred
	 */
	if (cfs_b->idle && !throttled)
		goto out_deactivate;

	if (!throttled) {
		/* mark as potentially idle for the upcoming period */
		cfs_b->idle = 1;                        // 没人被限流: 定时器可休眠
		return 0;
	}

	/* account preceding periods in which throttling occurred */
	cfs_b->nr_throttled += overrun;                 // cpu.stat: nr_throttled

	/*
	 * This check is repeated as we release cfs_b->lock while we unthrottle.
	 */
	while (throttled && cfs_b->runtime > 0) {
		raw_spin_unlock_irqrestore(&cfs_b->lock, flags);
		/* we can't nest cfs_b->lock while distributing bandwidth */
		throttled = distribute_cfs_runtime(cfs_b);  // 把新配额分给被限流的 cfs_rq
		raw_spin_lock_irqsave(&cfs_b->lock, flags);
	}

	/*
	 * While we are ensured activity in the period following an
	 * unthrottle, this also covers the case in which the new bandwidth is
	 * insufficient to cover the existing bandwidth deficit.  (Forcing the
	 * timer to remain active while there are any throttled entities.)
	 */
	cfs_b->idle = 0;

	return 0;

out_deactivate:
	return 1;
}
```

`distribute_cfs_runtime()`（fair.c:6403）的完整主体——把池里的时间按欠款逐个补给被限流的 cfs_rq：

```c
/* kernel/sched/fair.c:6403 完整函数体 */
static bool distribute_cfs_runtime(struct cfs_bandwidth *cfs_b)
{
	int this_cpu = smp_processor_id();
	u64 runtime, remaining = 1;
	bool throttled = false;
	struct cfs_rq *cfs_rq, *tmp;
	struct rq_flags rf;
	struct rq *rq;
	LIST_HEAD(local_unthrottle);

	rcu_read_lock();
	list_for_each_entry_rcu(cfs_rq, &cfs_b->throttled_cfs_rq,
				throttled_list) {
		rq = rq_of(cfs_rq);

		if (!remaining) {
			throttled = true;                 // 池子分完了, 后面还限着
			break;
		}

		rq_lock_irqsave(rq, &rf);
		if (!cfs_rq_throttled(cfs_rq))
			goto next;

		/* Already queued for async unthrottle */
		if (!list_empty(&cfs_rq->throttled_csd_list))
			goto next;

		/* By the above checks, this should never be true */
		WARN_ON_ONCE(cfs_rq->runtime_remaining > 0);

		raw_spin_lock(&cfs_b->lock);
		runtime = -cfs_rq->runtime_remaining + 1;    // 欠多少补多少
		if (runtime > cfs_b->runtime)
			runtime = cfs_b->runtime;
		cfs_b->runtime -= runtime;
		remaining = cfs_b->runtime;
		raw_spin_unlock(&cfs_b->lock);

		cfs_rq->runtime_remaining += runtime;

		/* we check whether we're throttled above */
		if (cfs_rq->runtime_remaining > 0) {
			if (cpu_of(rq) != this_cpu) {
				unthrottle_cfs_rq_async(cfs_rq);   // 跨 CPU: IPI 异步解限
			} else {
				/*
				 * We currently only expect to be unthrottling
				 * a single cfs_rq locally.
				 */
				WARN_ON_ONCE(!list_empty(&local_unthrottle));
				list_add_tail(&cfs_rq->throttled_csd_list,
					      &local_unthrottle);
			}
		} else {
			throttled = true;
		}

next:
		rq_unlock_irqrestore(rq, &rf);
	}

	list_for_each_entry_safe(cfs_rq, tmp, &local_unthrottle,
				 throttled_csd_list) {
		struct rq *rq = rq_of(cfs_rq);

		rq_lock_irqsave(rq, &rf);

		list_del_init(&cfs_rq->throttled_csd_list);

		if (cfs_rq_throttled(cfs_rq))
			unthrottle_cfs_rq(cfs_rq);           // 本 CPU 的当场解限

		rq_unlock_irqrestore(rq, &rf);
	}
	WARN_ON_ONCE(!list_empty(&local_unthrottle));

	rcu_read_unlock();

	return throttled;
}
```

`distribute_cfs_runtime()`（fair.c:6403）遍历 `throttled_cfs_rq` 链表，按欠款补足 `runtime_remaining`，补足的组立即 `unthrottle_cfs_rq()`（fair.c:6280）——跨 CPU 的通过 IPI（`unthrottle_cfs_rq_async`）异步解限。

**(2) slack 定时器**——组在 A CPU 没用完的片，5ms 后回收分给 B CPU 上被限流的兄弟（`cfs_bandwidth_slack_period = 5ms`，fair.c:6551）：

```c
/* kernel/sched/fair.c:6596 完整函数体 */
static void __return_cfs_rq_runtime(struct cfs_rq *cfs_rq)
{
	struct cfs_bandwidth *cfs_b = tg_cfs_bandwidth(cfs_rq->tg);
	s64 slack_runtime = cfs_rq->runtime_remaining - min_cfs_rq_runtime;  // 本地留 1ms 保底
	                                                            //   (min_cfs_rq_runtime, fair.c:6547)
	if (slack_runtime <= 0)
		return;

	raw_spin_lock(&cfs_b->lock);
	if (cfs_b->quota != RUNTIME_INF) {
		cfs_b->runtime += slack_runtime;            // 退回全局池

		/* we are under rq->lock, defer unthrottling using a timer */
		if (cfs_b->runtime > sched_cfs_bandwidth_slice() &&
		    !list_empty(&cfs_b->throttled_cfs_rq))
			start_cfs_slack_bandwidth(cfs_b);  // 攒够一片 → 启动 slack timer 再分配
	}
	raw_spin_unlock(&cfs_b->lock);

	/* even if it's not valid for return we don't want to try again */
	cfs_rq->runtime_remaining -= slack_runtime;
}
```

`do_sched_cfs_slack_timer()`（fair.c:6634）→ `distribute_cfs_runtime()` 完成再分配。**这就是为什么 cpu.max 限流后任务不是严格等满整个周期**——别处省下的配额 5ms 内就能到账。

### 4.7 cpu.max.burst

`__refill_cfs_bandwidth_runtime()`（fair.c:5893）补给时 `runtime += quota`，且允许池子**累计**到 `quota + burst`——即空闲周期攒下的额度可在繁忙周期一次花掉，用于容忍突发流量（默认 0）。

## 5. cpuset：决定"在哪里跑"

前四节解决"跑多久"，cpuset 解决"在哪些 CPU 上跑"，作用对象是 `task_struct->cpus_ptr`（亲和掩码）。

### 5.1 写入 cpuset.cpus

```c
/* kernel/cgroup/cpuset.c:2392 完整函数体 */
static int update_cpumask(struct cpuset *cs, struct cpuset *trialcs,
			  const char *buf)
{
	int retval;
	struct tmpmasks tmp;
	bool force = false;
	int old_prs = cs->partition_root_state;

	retval = parse_cpuset_cpulist(buf, trialcs->cpus_allowed);   // 解析 "0-3,8"
	if (retval < 0)
		return retval;

	/* Nothing to do if the cpus didn't change */
	if (cpumask_equal(cs->cpus_allowed, trialcs->cpus_allowed))
		return 0;

	compute_trialcs_excpus(trialcs, cs);
	trialcs->prs_err = PERR_NONE;

	retval = validate_change(cs, trialcs);      // 校验: 不能与兄弟 exclusive 组重叠等
	if (retval < 0)
		return retval;

	if (alloc_tmpmasks(&tmp))
		return -ENOMEM;

	/*
	 * Check all the descendants in update_cpumasks_hier() if
	 * effective_xcpus is to be changed.
	 */
	force = !cpumask_equal(cs->effective_xcpus, trialcs->effective_xcpus);

	partition_cpus_change(cs, trialcs, &tmp);

	spin_lock_irq(&callback_lock);
	cpumask_copy(cs->cpus_allowed, trialcs->cpus_allowed);
	cpumask_copy(cs->effective_xcpus, trialcs->effective_xcpus);
	if ((old_prs > 0) && !is_partition_valid(cs))
		reset_partition_data(cs);
	spin_unlock_irq(&callback_lock);

	/* effective_cpus/effective_xcpus will be updated here */
	update_cpumasks_hier(cs, &tmp, force);      // 向下传播"有效 CPU 掩码"
	                                            //   (父组给的 ∩ 自己要的 = effective)

	/* Update CS_SCHED_LOAD_BALANCE and/or sched_domains, if necessary */
	if (cs->partition_root_state)
		update_partition_sd_lb(cs, old_prs);

	free_tmpmasks(&tmp);
	return 0;
}
```

传播的终点是逐任务改亲和掩码：

```c
/* kernel/cgroup/cpuset.c:1057 完整函数体 */
void cpuset_update_tasks_cpumask(struct cpuset *cs, struct cpumask *new_cpus)
{
	struct css_task_iter it;
	struct task_struct *task;
	bool top_cs = cs == &top_cpuset;

	css_task_iter_start(&cs->css, 0, &it);          // 遍历组内所有进程
	while ((task = css_task_iter_next(&it))) {
		const struct cpumask *possible_mask = task_cpu_possible_mask(task);

		if (top_cs) {
			/*
			 * PF_KTHREAD tasks are handled by housekeeping.
			 * PF_NO_SETAFFINITY tasks are ignored.
			 */
			if (task->flags & (PF_KTHREAD | PF_NO_SETAFFINITY))
				continue;                   // 根组: 内核线程不动
			cpumask_andnot(new_cpus, possible_mask, subpartitions_cpus);
		} else {
			cpumask_and(new_cpus, possible_mask, cs->effective_cpus);
		}
		set_cpus_allowed_ptr(task, new_cpus);       // ← 直接改 task->cpus_ptr
	}
	css_task_iter_end(&it);
}
```

进程迁移进 cpuset 时同理（`cpuset_can_attach` cpuset.c:2992 先校验任务与目标 CPU 兼容；`cpuset_attach_task` cpuset.c:3111 在 3124 行调用 `set_cpus_allowed_ptr`）。

### 5.2 调度器如何消费 cpus_ptr

`p->cpus_ptr` 是调度器的硬约束：

- 唤醒/负载均衡选 CPU 时：`select_task_rq()`（kernel/sched/core.c:3574）→ 各调度类的 `select_task_rq` 回调只在 `p->cpus_ptr` ∩ 在线 CPU 里选；
- 迁移时检查 `cpumask_test_cpu(task_cpu(p), p->cpus_ptr)`（core.c:2653）；
- `set_cpus_allowed_ptr` 若发现任务正跑在掩码外的 CPU 上，会把它拉回（`__migrate_task`）。

### 5.3 cpuset.cpus.partition：把 CPU 从全局负载均衡里摘出去

v2 没有单独的 `sched_load_balance` 开关文件，通过 partition root 实现。设置后 `update_partition_sd_lb()` 最终调用：

```c
/* kernel/cgroup/cpuset.c:996-1012 rebuild_sched_domains_locked() 尾部 (调度域重建入口) */
	/*
	* cpuset_hotplug_workfn is invoked synchronously now, thus this
	* function should not race with CPU hotplug. And the effective CPUs
	* must not include any offline CPUs. Passing an offline CPU in
	* the doms to partition_sched_domains() will trigger a kernel panic.
	* ...
	*/

		if (WARN_ON_ONCE(!cpumask_subset(doms[i], cpu_active_mask)))
			return;                       // 防御: 不能把离线 CPU 放进调度域
	}

```

调度域重建意味着这些 CPU 不再参与全局负载均衡——低延迟/实时场景用它替代 `isolcpus` 引导参数（在线可切换）。

### 5.4 cpuset.mems

对应 NUMA 内存节点掩码，attach 时经 `cpuset_change_task_nodemask()`（cpuset.c:3126）改写 `task->mems_allowed`，影响该进程未来的页分配节点选择（与 [006 内存文档](./006.CGroup如何影响内存分配.md)的分配路径交叉）。
