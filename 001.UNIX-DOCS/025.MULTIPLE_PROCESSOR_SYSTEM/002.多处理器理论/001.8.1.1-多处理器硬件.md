# 8.1.1 多处理器硬件（Multiprocessor Hardware）

> 书页 530–541（PDF 559–570）。逐小节精读笔记之一。
> 同目录：[002.8.1.2-多处理器OS类型与SMP.md](./002.8.1.2-多处理器OS类型与SMP.md)｜[003.8.1.3-多处理器同步.md](./003.8.1.3-多处理器同步.md)｜[004.8.1.4-多处理器调度.md](./004.8.1.4-多处理器调度.md)｜[005.专题-图8-11多锁避免缓存抖动.md](./005.专题-图8-11多锁避免缓存抖动.md)

**总纲**：所有多处理器的共同点是"每个 CPU 都能寻址全部内存"；差别在"每个内存字是否被同等速度地访问"——是则为 **UMA**（Uniform Memory Access），否则为 **NUMA**（Nonuniform Memory Access）。8.1.1 按"怎么把更多 CPU 连到内存"这条主线，依次讲了 5 种硬件形态：单总线 → 交叉开关 → 多级交换网络 → NUMA 目录 → 多核/众核芯片。

---

## 1. UMA 单总线多处理器（图 8-2）

![图 8-2 三种基于总线的多处理器](./999.IMGS/fig-8-2.png)

三个演进阶段：

| 阶段 | 结构 | 问题/对策 |
|-|-|-|
| (a) 无缓存 | 所有 CPU、内存模块共享一条总线，先查总线忙否再读写 | 2~3 个 CPU 尚可，32/64 个 CPU 时总线带宽彻底饱和，多数 CPU 大部分时间在等总线 |
| (b) 加缓存 | 每 CPU 一个 cache，按 **32/64 字节 cache line** 为单位缓存 | 读大多命中本地缓存，总线流量大幅下降 → 可支撑更多 CPU |
| (c) 缓存+私有内存 | 每 CPU 再挂一块经**私有总线**访问的本地内存 | 编译器把只读数据（程序文本、常量）、栈、局部变量放进私有内存，共享内存只放可写共享变量 → 进一步减少总线流量，但需要编译器配合 |

### 缓存一致性协议（cache-coherence protocol）——本节最重要的硬件概念

以 cache line 为粒度的规则集合：

- 每 line 标记为**只读**（可同时存在于多个 CPU 的缓存中）或**读写**（独占，不允许同时存在于其他缓存）；
- CPU 要写的 line 若在其他远程缓存中：总线硬件检测到写操作并在总线上**通知所有其他缓存**；
  - 其他缓存持有 **clean 副本**（与内存一致的副本）→ 直接丢弃，写者从内存取回该 line 再改；
  - 某缓存持有 **dirty 副本**（已修改）→ 先写回内存（或经总线直接把数据传给写者）再继续。

**为什么 8.1.3 的"缓存抖动"会因此发生**：一致性协议以 line（32/64B）为单位传输，锁变量只是 line 里的 4/8 字节。TSL 这类"读+写"原子指令需要**独占**该 line，于是整个 line 在锁持有者与竞争者之间来回搬运——这是理解图 8-11（MCS 锁）动机的前提。

## 2. UMA 交叉开关（Crossbar Switch，图 8-3）

![图 8-3 交叉开关](./999.IMGS/fig-8-3.png)

- n 个 CPU × k 个内存，每个水平线×垂直线交点放一个 **crosspoint**（可开合的小电子开关）；闭合即接通一对（CPU, 内存）。
- 任意时刻可同时闭合多个互不冲突的 crosspoint（组合数 = 国际象棋棋盘上安全摆放 8 个车的方案数）。
- 优点：**非阻塞网络（nonblocking）**——只要有空闲内存模块，任何 CPU 总能连上；无需预先规划路径。内存分 n 份后，争用比单总线降 n 倍。
- 致命缺点：crosspoint 数量随 **n²** 增长。1000 CPU×1000 内存 = 100 万个 crosspoint，不可行。中等规模可用。

## 3. UMA 多级交换网络（Omega 网络，图 8-4/8-5）

![图 8-4 2x2 开关与消息格式](./999.IMGS/fig-8-4.png)

![图 8-5 omega 交换网络](./999.IMGS/fig-8-5.png)

- 基本构件 **2×2 开关**：消息可从任一入线（A/B）交换到任一出线（X/Y）。消息格式 4 字段：**Module（哪个内存模块）/ Address（模块内地址）/ Opcode（READ/WRITE…）/ Value（可选操作数）**。
- n CPU × n 内存用 **log₂n 级、每级 n/2 个开关、共 (n/2)·log₂n 个**（1024 CPU 只要 5120 个，交叉开关要 100 万+）。布线模式叫 **perfect shuffle**（完美洗牌）。
- **路由方法**：逐级取 Module 号的**最高位**（0 走上、1 走下）；消息前进时模块号高位作废，顺路**记录入线编号**，应答从右往左读这些编号即可原路返回。
- 不同请求只要不共用开关/线路/内存模块即可并行（例：CPU 011→内存 110 与 CPU 001→内存 001 全程无交叉）；若 CPU 000 同时要访问内存 000，则在开关 3A 与后一请求**冲突**——omega 是**阻塞网络（blocking network）**。
- 提升均匀性技巧：用地址低位做模块号做**交错（interleaved）内存**——连续字落在不同模块，而多数访存恰好是连续地址，并行度最大。

## 4. NUMA 多处理器与目录协议（图 8-6）

![图 8-6 基于目录的多处理器](./999.IMGS/fig-8-6.png)

单总线 UMA 顶多几十个 CPU；交叉开关贵且也大不了多少。超过 100 个 CPU 只能放弃"各内存模块访问时间相同"的假设 → **NUMA**。

**NUMA 三特征**（所有 NUMA 机器共有）：
1. 所有 CPU 可见的**单一地址空间**；
2. 访问远程内存也用普通 **LOAD/STORE** 指令；
3. 访问远程内存**慢于**本地内存。

因此 UMA 程序不用改就能跑，只是性能下降。两种形态：**NC-NUMA**（无缓存一致性）与 **CC-NUMA**（缓存一致，主流）。

### 目录式多处理器（directory-based）——大型 CC-NUMA 的主流做法

- 核心：维护一个**目录数据库**，记录每个 cache line 现在缓存在哪、状态是 clean 还是 dirty。每条访存指令都要查它，所以必须放在**远小于一个总线周期就能应答的专用高速硬件**里。
- **256 节点示例**（图 8-6）：每节点 = 1 CPU + 16MB RAM（本地总线）；节点间互连网络。32 位物理地址切成 **8 位节点号 + 18 位 line 号 + 6 位行内偏移**（64B/line）；每节点保存自己 2¹⁸ 个 line 的目录项。
- **访问流程**（CPU 20 读 `0x24000108`）：MMU 解析出（节点 36，line 4，偏移 8）→ 经互连网络向**宿主节点（home node）36** 发请求 → 查目录项 4：
  - 未缓存：从节点 36 本地 RAM 取数据发回，目录项更新为"缓存在节点 20"；
  - 已缓存在节点 82：目录更新 + 通知节点 82 把 line 传给节点 20 并**作废**自己那份。
- **金句**：即使所谓"共享内存多处理器"，底层也在跑大量消息传递（对程序员透明）。
- **目录开销**：每项 9 位（8 位节点号+1 位脏）；16MB/64B = 2¹⁸ 项 → 9×2¹⁸ bit ÷ 16MB ≈ **1.76%**。line 越短目录越密：32B line → 4%；128B line → <1%。
- **多节点缓存扩展**：简化设计一行只能缓存在一个节点；要支持多处共享，目录项改为**位向量**（每核 1 位）+ 若干状态位，内存开销大涨。64 位系统同理更复杂。

## 5. 多核（Multicore/CMP）、众核（Manycore）、GPU、异构

- **多核 = 片上小型多处理器**。晶体管预算两个去向：堆缓存（命中率 99%→99.5% 收益递减）或堆核。L1(近/小/快)→L2→L3(远/大/慢)；一致由硬件 **snooping（侦听）**自动原子地保证。
- **共享 L3 的真实形态**：常按核切片（slice），任何核可访问任何切片，但访问**本地切片更快**——书中称为"**NUMA 缓存**"。共享缓存利弊：空闲核的配额可被吃紧核借用；贪心核也能拖累别人。
- **SoC**：通用核 + 视频/音频解码、密码处理器、网卡等专用核 = 单芯片整机（Apple M1：4 大核+4 小核）。
- **众核**：数十~数千核（自嘲式判据："不在乎丢一两个核"）。最大威胁是**一致性墙（coherency wall）**：位向量目录项 1024 核 = 1024 bit = **128 字节 ≥ 它所跟踪的 cache line 本身**。出路：放弃全局一致性改消息传递，或**岛式混合**（1024 核分 64 岛、岛内一致、岛间放弃）。
- **GPU**：数千小核，晶体管花在计算电路而非缓存/控制逻辑；本质 **SIMD**（大量核同一指令不同数据），擅长数据并行不擅串行，难编程难调试；GPGPU 需 CUDA 等。**TPU/NPU**：面向机器学习矩阵乘的专用处理器，对 OS 影响有限。
- **异构多核**：不同指令集（CPU+GPU+TPU 同芯）或同指令集大小核（ARM **big.LITTLE**、Intel Alder Lake）——大核跑串行重负载，小核能效跑并行。
- **SMT 同时多线程（超线程/虚拟核）**：一核多个硬件上下文；每个超线程有**独立寄存器组**，但共享 L1/L2、TLB、执行单元 → 互相干扰（执行部件被占要等、TLB 项被挤掉）。收益："以零头价格得到几乎一个核"，部分负载 +30%，多数小得多。安全代价见 8.1.4 末尾（侧信道）与 [004.8.1.4](./004.8.1.4-多处理器调度.md)。

## 6. 对照 Linux/arm64：内核是硬件拓扑的"消费者"

8.1.1 讲的全部是**硬件**机制（一致性协议、目录、总线），Linux 内核**不实现**这些——缓存一致在 arm64 上由硬件（页表 shareable 属性 + 互连的一致性协议）自动保证。内核做的是把硬件拓扑**发现、建模、利用**：

| 书中硬件概念 | Linux/arm64 中的对应物（只列索引，详见各专题文件）|
|-|-|
| cache line（32/64B 一致性粒度）| `L1_CACHE_BYTES`/`arch_timer`…；锁实现按 cacheline 对齐（如 `DEFINE_PER_CPU_ALIGNED` qnode 恰好占一行，见 [003.8.1.3](./003.8.1.3-多处理器同步.md)）|
| UMA/NUMA 拓扑 | ACPI SRAT/SLIT 解析 <sub>[/arch/arm64/kernel/acpi_numa.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/acpi_numa.c)</sub>；节点描述符 `pglist_data`；详见 [../000.NUMA/README.md](../000.NUMA/README.md) |
| 多核层级（核/簇/LLC/封装）| CPU 拓扑构建 `init_cpu_topology()` 与调度域层级（SMT/CLS/MC/PKG/NUMA），见 [004.8.1.4](./004.8.1.4-多处理器调度.md) |
| SMT 超线程 | 主流 arm64 核（Neoverse 等）**无 SMT**；调度器仍支持 SMT 层级（x86 用），安全侧对策 core scheduling 同样可用于 arm64 |
| 大小核异构（big.LITTLE）| arm64 的 `capacity`（算力）per-CPU 属性 + 能耗调度（EAS）：任务倾向放"够用的最省电的核"——这是 8.1.1 异构一节在 Linux 里的真正落点 |
| GPU/TPU | 内核只做设备驱动与内存管理（如 `/dev/dri`、DMA-BUF、IOMMU），不调度 GPU 内部 |

**学习建议**：8.1.1 的价值不在背互连结构，而在两条会在后面反复出现的主线——
1. **一致性以 cache line 为粒度** → 决定了锁的缓存行为（8.1.3 缓存抖动、图 8-11）；
2. **"本地快、远程慢"（NUMA）** → 决定了调度器亲和性与内存策略（8.1.4 与 NUMA 专题）。
