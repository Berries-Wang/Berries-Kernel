**三类多 CPU 系统一句话定位**：多处理器 = 共享内存；多计算机 = 消息传递 + 统一 OS（同机房紧耦合，即集群）；分布式系统 = 消息传递 + 异构 OS（跨互联网松耦合）。

**动机**：大型/超大型共享内存多处理器难造且贵。多计算机 = 紧耦合但不共享内存的 CPU（别名 cluster、COW），云计算都建在它上面。基本节点 = 去掉键盘鼠标显示器的"无头工作站" PC + 高性能网卡；目标是**微秒级消息**（比纳秒级访存简单便宜）。

## 1. 互连拓扑与交换（8.2.1，图 8-16）

**直径（diameter）**= 任意两个节点之间最远要走的**跳数**（最坏路径长度）。直径越小最坏延迟越低（存储转发下延迟 ∝ 跳数）；节点数增加时直径增长越慢的拓扑越可扩展。

| 拓扑 | 特点 |
|-|-|
| 星型（单交换机）| 现代交换以太网的形态 |
| 环 | 无需交换机；最远的两节点要绕环半圈 ≈ n/2 跳，直径随节点数**线性**增长 |
| 网格 mesh | 规则、易扩展。n 个节点排成 √n×√n 方阵，最坏的一对是**对角节点**：横、竖各走 √n−1 跳，直径 = 2(√n−1)，即**随 √n 增长**——比环好、比超立方体差，居中 |
| 双环面 double torus | 网格的行/列首尾绕接成环：更容错，且对角节点 2 跳直达，直径更小 |
| 立方体/超立方体 hypercube | n 维立方体有 2ⁿ 个节点，节点编号 n 位、每走一跳翻转其中一位 → **直径 = 维数 = log₂(节点数)**：10 维超立方体 1024 节点直径仅 10，同样 1024 节点的 32×32 网格直径却要 62（差 6 倍）；代价是每节点 n 条链路，扇出/成本大 |

![图 8-16 各种互连拓扑：(a) 单交换机 (b) 环 (c) 网格 (d) 双环面 (e) 立方体 (f) 4 维超立方体](./999.IMGS/fig-8-16.png)

- **交换方式**：① **存储转发**（图 8-17）——整包到齐再转发，延迟 = 跳数 × 单跳时间；② **电路交换**——先打通全程路径再不停泵送（要建立/拆除）；**虫孔路由（wormhole）**折中：包拆子包、路径没建完头部就能流动。

![图 8-17 存储转发分组交换](./999.IMGS/fig-8-17.png)

- **网络接口（图 8-18）**：板载大 RAM（**同步网络**按时钟节拍恒定速率收发，主 RAM 争总线给不出恒定供给速率；入包同理先落板）；板上有 DMA 甚至 CPU/FPGA = **智能网卡（smart NIC）**，可卸载可靠传输/组播/压缩/加解密。**复制是性能头号敌人**：应用→内核→网卡层层复制，缓存/TLB 全被污染。

![图 8-18 网络接口板在多计算机中的位置](./999.IMGS/fig-8-18.png)

## 2. 低层通信软件（8.2.2）

- **最理想 3 次复制**：① 源 RAM→源网卡板，② 源网卡板→目的网卡板，③ 目的网卡板→目的 RAM。网卡只映射进**内核**空间时，用户发包要系统调用，内核在收/发两侧还要各多拷一次（传输中避免缺页、收包时先落内核才能决定去向）→ **5 次复制**，延迟翻倍、吞吐减半（图 8-18）。
- **网卡映射进用户空间**的问题：多进程互斥难办（mutex 只对合作进程有效）→ 只有每节点单进程才好用；内核自己也要网络 → 最简单**两块网卡：一块给用户、一块给内核**。
- 现代**多队列网卡**：16 发 16 收队列、可虚拟化、核亲和（按 TCP 流哈希分流到固定核、缓存热）。
- **DMA 与分页冲突**：DMA 用物理地址、页可被换出 → 需要 pin/unpin 页的系统调用，小包（≤64B）开销不可接受，大包（≥1KB）可容忍。
- **RDMA**：绕过两端 OS 直接读写对方应用内存；仍需 pin 页；完成不自动通知 → 接收方轮询内存标志字节。高频交易定制 FPGA 网卡 wire-to-wire <1μs。

## 3. 用户级通信软件（8.2.3）

- 最小原语 `send(dest, &mptr)` / `receive(addr, &mptr)`；编址 = CPU 号 + 进程/端口号。
- **阻塞 vs 非阻塞 send（图 8-19）**：非阻塞可与传输并行，但缓冲区发完前不能改。三种出路：内核代抄（多一次复制）/ 发完中断（难写难调）/ 写时复制（邻近写也触发复制）。**结论：阻塞最方便**（多线程时其他线程可继续）。

![图 8-19 (a) 阻塞式 send 调用 (b) 非阻塞式 send 调用](./999.IMGS/fig-8-19.png)
- receive 侧可阻塞/轮询/中断；两个高阶方案：**弹出线程（pop-up threads）**——消息到达自动创建线程处理、完毕即亡；**主动消息（active messages）**——消息自带 handler 地址、零复制，但要求**完全互信**。

## 4. 远程过程调用 RPC（8.2.4，图 8-20）

让远端调用看起来和本地调用一样。五步：客户调 **client stub**（普通本地调用）→ stub **编组（marshaling）**参数成消息并陷入内核发送 → 内核传输 → **server stub** 收包 → 调用服务过程；应答原路返回。

![图 8-20 进行远程过程调用的步骤（stub 为阴影部分）](./999.IMGS/fig-8-20.png)

**四个"草下的蛇"**：① 指针跨地址空间失效（copy-restore 对图/链表无效）；② C 弱类型数组无长度无法编组；③ 参数类型无法推断（printf 可变参数）；④ 全局变量不再共享。RPC 广泛使用但需参数限制。

## 5. 分布式共享内存 DSM（8.2.5，图 8-21/8-22）

页面分布在各节点，访问非本地页 → 陷入内核 → 持有者 unmap 并把页传来 → 重启指令。**本质 = 用"远端 RAM"代替"本地磁盘"满足缺页**。共享内存可实现于三层：硬件（真多处理器）/ OS（DSM）/ 用户态（中间件，见 [../005.分布式系统理论/README.md](../005.分布式系统理论/README.md)）。

![图 8-21 共享内存可被实现的各种层次：(a) 硬件 (b) 操作系统 (c) 用户态软件](./999.IMGS/fig-8-21.png)

![图 8-22 (a) 地址空间页面分布于四台机器 (b) CPU 0 访问页 10、页面被移到它那里之后 (c) 页 10 只读并采用复制时的情况](./999.IMGS/fig-8-22.png)

- **复制**：只读页多副本不失效，读不再陷入。
- **伪共享（false sharing，图 8-23）**：无关变量同页 → 整页在两机间乒乓；页越大越严重，聪明编译器能摆变量但数组相邻元素无解。

![图 8-23 含两个无关变量的页面被伪共享](./999.IMGS/fig-8-23.png)
- **顺序一致性**：写复制页前让所有持有者 unmap、全部应答后才能写（同多处理器缓存作废思路）；优化：锁区域批量传播，或 write-diff（首次写留干净副本，之后只发"变化的字"列表，Keleher et al., 1994）。

## 6. 调度与负载均衡（8.2.6/8.2.7）

- 各节点有自己的进程集，CPU 不能随手跑别节点进程 → **调度更容易，但"进程放哪个节点"更重要**；单一中央就绪队列不可行；跨节点仍可用组调度。
- **图论确定性算法（图 8-24）**：进程=顶点、通信量=带权边，切图成 k 块、**最小化切边流量**（找"内紧外松"的簇；例 30 vs 28 单位）。

![图 8-24 把九个进程分配到三个节点的两种方法](./999.IMGS/fig-8-24.png)
- **发送者启动**（图 8-25a，Eager et al. 1986）：过载节点随机探测、低于阈值就送进程；排队模型证明稳定；**缺点：系统越忙探测风暴越猛**。
- **接收者启动**（图 8-25b）：缺活的节点主动要工作；过载时几乎无探测流量——**开销发生在欠载时远好于过载时**；两者可结合 + 历史记录优先试探慢性空闲/过载机器。

![图 8-25 (a) 过载节点寻找轻载节点移交进程 (b) 空节点向过载节点请求工作](./999.IMGS/fig-8-25.png)

**一句话串起来**：多计算机用"消息传递替代共享内存"换取可扩展性——拓扑/交换/网卡决定延迟下限，软件层（用户态映射、RDMA、RPC、DSM）不断减少复制、隐藏通信；调度重心从"何时运行"移到"放在哪个节点"。
