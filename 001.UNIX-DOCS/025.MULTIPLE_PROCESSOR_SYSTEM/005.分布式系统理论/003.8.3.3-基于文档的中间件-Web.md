## 1. 书中理论

### 1.1 范式：Web = 巨大的文档有向图（图 8-32）

![图 8-32 文档有向图](./999.IMGS/fig-8-32.png)

- Tim Berners-Lee 1989 年于 CERN 发明。范式极简：每台计算机放若干 **Web 页**（文本/图像/声音/电影 + 指向其他页的**超链接**）；浏览器请求页、点击链接跳转——Web 本质是**巨大的文档有向图**。
- **URL（Uniform Resource Locator）**= `protocol://DNS-name/file-name`（最常见 `http`/`https`，也有 `ftp` 等）——URL **全局唯一地指定一个文件**。

### 1.2 取一页的八步（以 `http://www.minix3.org/getting-started/index.html` 为例）

1. 浏览器向 DNS 问 `www.minix3.org` 的 IP；
2. DNS 答 `66.147.238.215`；
3. 浏览器与该 IP 的 **80 端口建 TCP 连接**；
4. 发请求：要文件 `getting-started/index.html`；
5. 服务器送回该文件；
6. 浏览器显示全部文本；
7. 同时抓取并显示页上所有图像（**每张图单独再取**）；
8. 释放 TCP 连接。

后来的扩展（样式表、动态页、页内小程序）都长在这副骨架上。

## 2. Linux 对照：内核不实现 Web，但为 Web 服务器压榨到极致

| 书中概念 | Linux 7.1.3 | 说明 |
|-|-|-|
| 浏览器/HTTP 服务器 | 用户态（nginx、Apache…）| 内核不做 HTTP |
| 第 3 步"建 TCP 连接" | 内核 accept 队列：高并发 Web 服务器的经典调优点（`tcp_max_syn_backlog`、somaxlen）；**TCP Fast Open** 省一个 RTT | `net/ipv4/tcp_fastopen.c`、`net/core/request_sock.c` |
| 第 5 步"送文件" | `sendfile(2)` 正是为 Web 服务器而生（静态文件→socket 零拷贝，8.2.2 已述）| `fs/read_write.c:1304` |
| 第 7 步"每图一取"的性能病灶 | 现代 HTTP/2 多路复用在用户态库解决；内核贡献点是 **TLS 卸载**（kTLS：加密后仍可走 sendfile/零拷贝）| `net/tls/tls_main.c`（`CONFIG_TLS`）|
| 第 8 步"释放连接" | TIME_WAIT 主动方状态（`tcp_fin_timeout`）；Keep-Alive 在用户态 HTTP 层复用连接 | `net/ipv4/tcp_timer.c` |
| 千万并发连接（C10M）| **io_uring**：把 accept/send/recv 全异步化，Web/代理服务器的新底座 | `io_uring/` |
| 网页内容处理加速 | eBPF/XDP 做 DDoS 过滤、负载均衡（Katran）在内核最早点拦截 | `net/core/filter.c` |
| DNS 查询 | 用户态 resolver（glibc nsswitch），内核只提供 UDP socket | `net/ipv4/udp.c` |

**学习小结**：Web 的中间件复杂度全在用户态（协议、缓存、渲染）；内核的角色是把它依赖的两个原语——**TCP 连接**与**文件→socket 搬运**——做到极致（TFO、sendfile、kTLS、io_uring）。取页八步里凡是标着"内核"的环节，都是二十年来性能优化的主战场。
