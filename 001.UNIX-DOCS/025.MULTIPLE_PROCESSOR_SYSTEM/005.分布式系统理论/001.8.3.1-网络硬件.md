**先立框架（图 8-26/8-27，见 [README](./README.md)）**：分布式系统 vs 多计算机——每节点是**完整计算机**（全套外设）、可能**分布全球**、跑**不同 OS/文件系统**、归**不同组织**管。没有公共模型 → 编程难 → 在 OS 之上加**中间件（middleware）**提供统一范式（类比 UNIX"一切皆文件"）。中间件之下是什么硬件？本节速览 LAN（以太网）与 WAN（互联网）。

## 1. 书中理论

### 1.1 经典以太网（IEEE 802.3，图 8-28）

![图 8-28 经典与交换式以太网](./999.IMGS/fig-8-28.png)

- 名字来历：19 世纪以为光靠"光以太（luminiferous ether）"传播，Michelson-Morley 实验否定了它——同轴电缆被戏称为 Ethernet；最早接入方式是在电缆上**打半孔拧线**（vampire tap，吸血鬼接头）。
- **CSMA/CD 协议**（多机一线的秩序）：
  1. 发前**先听**：电缆空闲才发（包头 + 0~1500 字节载荷）；
  2. 两机同时开口 → **冲突**，双双检出、停止；
  3. 各自**随机等待 0~T μs** 再试；再撞 → 区间扩到 0~2T；再撞再翻倍……——**二进制指数退避**（与 §8.1.3 给锁轮询退避**同一个算法**，第三次见面了：锁退避→以太网→后面还有 TCP 重传）。
- 超长/超多 → 用**网桥（bridge）**把多段以太网连起来，按源/目标在哪侧放行流量。
- **现代交换以太网（图 8-28b）**：交换机每端口一台机器，包到交换机**缓存后从目标端口发出**——冲突彻底消除（或每端口少数几台折中）。

### 1.2 互联网（Internet，图 8-29）

![图 8-29 互联网的一部分](./999.IMGS/fig-8-29.png)

- 出身：**ARPANET**（1969 年 12 月，3 台在加州 1 台在犹他）；冷战设计目标——多处被核打击后**自动绕行**继续传军事流量 → 容错是第一天条。
- 两种机器：**主机**（host：PC/手机/服务器…想上网的）与**路由器**（router：专职交换，多入线多出线，像交换机但按 IP 逐跳查表转发）。
- 结构分层：**骨干**（电话公司/骨干运营商，高速光纤互联，基本不挂主机）→ **区域网/ISP 路由器**（中速光纤）→ **企业以太网/家庭**（ADSL 等）——每台主机到其他主机至少一条、常常多条路径。
- **分组自带目的地址**，每跳路由器查表选出口线；**路由表高度动态**（设备/链路起落、流量变化），路由算法持续演化。

## 2. Linux 对照：内核就是那台"交换机/路由器"

分布式系统的"硬件"层，Linux 内核是深度参与者（arm64 亦然——网络栈架构无关，驱动落在各平台）：

| 书中概念 | Linux 7.1.3 | 源码 |
|-|-|-|-|
| 交换机的"缓存后从目标端口转发" | **Linux 网桥**：把多网卡桥接成一台软件交换机，`br_fdb.c` 学 MAC→端口表（交换机的地址表），`br_forward.c` 从目标端口转发——Linux 本体就能当图 8-28(b) 那台交换机 | `net/bridge/` |
| 网桥（bridge）| 同上，即书中的 bridge 一词本尊 | `net/bridge/br.c` |
| 路由器逐跳查表 | **转发信息库 FIB**（最长前缀匹配）：`fib_table_lookup()`；查表即书中"提取目的地址找出口线" | `net/ipv4/fib_trie.c` |
| "路由表高度动态" | 动态路由协议守护进程（用户态：FRR/bird 的 OSPF/BGP）通过 netlink 喂内核 FIB | `net/ipv4/fib_frontend.c` + 用户态路由守护 |
| 主机侧以太网收发 | 驱动 RX/TX：arm64 常见 `drivers/net/ethernet/cadence/macb_main.c`（Zynq/FPGA 平台）、`drivers/net/ethernet/broadcom/`、virtio-net（虚拟机）| `drivers/net/ethernet/` |
| CSMA/退避 | 半双工 CSMA/CD 已随交换以太网成为历史；**同款指数退避在 TCP 重传**继续服役（见 [002.8.3.2](./002.8.3.2-网络服务与协议.md)）| `net/ipv4/tcp_timer.c:658-681` |
| 冲突域消除/端口隔离 | 软件侧等价：veth/macvlan 把每容器隔离成"独占端口" | `drivers/net/veth.c` |
| 收包路径上的分流 | XDP 在**驱动最早点**处理/转发包（软件交换机的快路径，OVS/容器网络大量使用）| 驱动路径 `include/linux/filter.h`（`bpf_prog_run_xdp`）；通用路径 `net/core/dev.c:5656`（`do_xdp_generic`）|

**学习小结**：书里两张图（交换机、路由器）在 Linux 里都有完整软件化身——bridge=交换机、FIB+netlink=路由器；加上 veth/XDP，一台 Linux/arm64 就能拼出分布式系统的整个"底层网络"。
