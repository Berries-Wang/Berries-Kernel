## 1. 书中理论

### 1.1 Linda：全局元组空间（Yale，Gelernter & Carriero）

- **元组空间（tuple space）**全局唯一；任何机器上的进程都能投放/取走元组，**不关心它存在哪、怎么存**——用户看来像一块**全局共享内存**（即图 8-21(c) 的第三层：用户态软件实现的"共享内存"，与 DSM 呼应）。
- **元组（tuple）**≈ C 结构：若干字段（int/long/float/数组/字符串/结构，**不含其他元组**）；**纯数据、无方法**（与对象的本质区别）。

![图 8-36 三个 Linda 元组](./999.IMGS/fig-8-36.png)

### 1.2 四个原语

| 原语 | 语义 |
|-|-|
| `out("abc", 2, 5)` | **投放**元组入空间（字段可为常量/变量/表达式）|
| `in("abc", 2, ?i)` | 按**内容模板**匹配并**原子取走**：字段数相同、类型相同、常量/变量相等即匹配；`?i` 是**形式参数**只接值不参与匹配；找到→取走并把值赋给 i；**找不到→阻塞**直到有人投来 |
| `read` | 同 in 但**不取走** |
| `eval` | 各参数**并行求值**，全部完成后结果元组入空间——Linda 创建并行计算的方式 |

- **匹配规则三条件**：模板与元组字段数相同；对应字段类型相同；模板中常量/变量与字段相等（`?` 只做类型检查）。
- **阻塞自动唤醒**：先 in 后 out 也无妨（in 挂起，元组一到即醒）——先后无所谓，只差一点延迟。
- **信号量一行实现**：`up` = `out("sem S")`；`down` = `in("sem S")`——空间里 `("sem S")` 元组的**个数就是信号量值**，没有就阻塞。
- `in` 的匹配+取走是**原子**的：两个进程同 in 同一模板只成一个成功（除非有多份相同元组）。

### 1.3 发布/订阅（publish/subscribe，Oki et al. 1993）

![图 8-37 发布/订阅架构](./999.IMGS/fig-8-37.png)

- 受 Linda 启发：进程们挂在广播网络上，各自可为生产者/消费者/两者。
- **发布**：生产者把元组**广播**到本地 LAN；元组带**层次化主题行**（点分隔多字段，可用通配符 `*`）。**订阅**：告诉**本机的元组守护进程（daemon）**要什么主题。
- **转发机制**：每机 daemon 收下所有广播元组，按主题分发给本机订阅者；跨 WAN 由每 LAN 一台的 **information router** 中继——还可**智能中继**（远端 LAN 有订阅者才转发，router 间互换订阅信息）。
- **语义可强化**：可靠送达、乃至**保证送达**（崩溃也不丢）——挂一个"**订阅一切**"的数据库适配器把所有元组存档即可实现。
- **生产者消费者完全解耦**；想知道"还有谁在"→ 发布一条"谁对 x 感兴趣？"的元组，等"我对 x 感兴趣"应答回来。

## 2. Linux 对照

| 书中概念 | Linux/现状 | 说明 |
|-|-|-|
| 元组空间 / 协调语言 | 纯用户态：Redis、etcd（键值即"元组"的退化形态）、Kafka；**内核无对应** | — |
| 发布/订阅 | **用户态消息系统**：Kafka（主题=层次化 subject 的直系后代）、NATS（subject 通配符 `*`/`>` 与书中主题行几乎一样）、MQTT | 用户态 |
| "订阅一切的数据库适配器" | Kafka Connect / 持久订阅：消费组落后了也能回放——"保证送达"的现代实现 | 用户态 |
| "information router 只转发有订阅者的 LAN" | Kafka 的 consumer group 协议：broker 只向有订阅分区的 follower/消费者推送 | 用户态 |
| 阻塞式 `in` 原子匹配 | 用户态队列的 `recv` 阻塞语义；内核里最近缘的"内容寻址+原子取走"= **eBPF 环形缓冲**按主题过滤（`bpf_ringbuf_discard`/`reserve`）或 netlink 多播按组订阅 | `kernel/bpf/ringbuf.c`、`net/netlink/af_netlink.c` |
| 主题订阅在内核的化身 | **netlink 多播组**（内核事件按组广播，用户态按组订阅：udev/audit 就是发布订阅）；**uevent** 是内核→用户态的发布者 | `net/netlink/`（`nlmsg_multicast`）、`lib/kobject_uevent.c` |
| `eval` 并行求值 | 用户态任务框架（Ray/Dask 等）| — |

**学习小结**：Linda 用"**内容寻址 + 阻塞取走 + 原子性**"三件套把通信与同步统一进一个原语（信号量一行成）；发布/订阅把元组空间切成主题域并按订阅转发。这套思想在内核里最清晰的投影是 **netlink 多播组/uevent**——内核发布、用户态按组订阅；大规模工业实现则全部在用户态（Kafka/NATS）。
