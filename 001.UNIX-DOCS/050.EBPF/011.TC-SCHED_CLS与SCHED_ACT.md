# TC:SCHED_CLS 与 SCHED_ACT(BPF_PROG_TYPE_SCHED_CLS / SCHED_ACT)

> **流量控制(traffic control)层的 BPF**:包已进入协议栈、有了 `sk_buff`,可以在 ingress/egress 队列纪律处分类、改包、决定去向。比 XDP 慢,但看得到解析后的包且能改。枚举值 [bpf.h:1064](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1064) / [1065](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1065);两者共用 ops [bpf_types.h:7 与 9 `tc_cls_act`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L7)。行号 = 仓库 7.1.3 树。**本目录 [README](README.md) 已有一份完整的用户态(Aya)→ cls_bpf 执行链全景(基于 5.9,结论仍适用;7.1.3 中 `cls_bpf_classify` 在 cls_bpf.c:81)**,本篇补"场景/生效/卸载"并核对 7.1.3 行号。

## 1. 使用场景

- **K8s/CNI 数据面**(Cilium 默认用 TC BPF 做Pod 出入向策略、NAT、隧道)
- **改包**:改 MAC/IP/端口、封装解封装(VXLAN/Geneve),这是 XDP 做不到或不好做的
- **分类与动作联动**:`SCHED_CLS` 在分类器里跑(`tc filter`),`SCHED_ACT` 作为独立 action(`tc action`)
- 硬件 offload:网卡支持时 `cls_bpf_offload`([cls_bpf.c:195](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/sched/cls_bpf.c#L195))把程序下发到 NIC

## 2. 上下文与返回值

- 上下文 `struct __sk_buff *`(内核侧映射回 `sk_buff`,字段映射实现在 net/core/filter.c,见 [README 对应表](README.md))
- 返回值被 `cls_bpf_exec_opcode` 解释为 TC 动作码:`TC_ACT_OK`(放行,终止过滤)/ `TC_ACT_SHOT`(丢)/ `TC_ACT_REDIRECT`(重定向,配合 `bpf_redirect()`)/ `TC_ACT_UNSPEC`(-1,继续链表里的下一条 filter)……定义在 include/uapi/linux/pkt_cls.h

## 3. 如何生效(attach)

TC 走 **netlink**,不是 `bpf()`:

```
tc filter add dev eth0 ingress matchall action bpf obj prog.o sec classifier direct-action
  │ (libbpf 先 bpf(BPF_PROG_LOAD) 拿 prog fd —— 与 000 笔记相同)
  ▼
RTM_NEWTFILTER(netlink)
  └─ net/sched/cls_api.c:2236 tc_new_tfilter()        (注册于 4091)
       └─ 按 classifier kind="bpf" 分发
            └─ net/sched/cls_bpf.c:407 cls_bpf_change()
                 ├─ cls_bpf_prog_from_efd(校验 prog 类型必须 SCHED_CLS)
                 ├─ 挂入该 qdisc 的过滤器链表 ──【生效】
                 └─ 503 cls_bpf_offload()(硬件 offload 时)

SCHED_ACT:
tc action add action bpf obj prog.o
  └─ net/sched/act_bpf.c(执行入口 tcf_bpf_act,见 §4)
```

新方式提示:**TCX**(attach type `BPF_TCX_INGRESS`/`EGRESS`,[bpf.h:1144/1145](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1144),6.6+)用 `BPF_LINK_CREATE` 挂 TC 钩子,支持链式 link;本篇不展开。

## 4. 触发执行路径

```
每个包经过 TC 层(qdisc ingress/egress):
  net/sched/cls_bpf.c:81 cls_bpf_classify(skb, tp, res)
    ├─ 遍历过滤器链表找到 cls_bpf 程序
    ├─ 100/103 bpf_prog_run_data_pointers(prog->filter, skb)
    │     └─ bpf_prog_run() → JIT 本机码
    ├─ cls_bpf_exec_opcode(返回值) → TC 动作码
    └─ 返回给 TC 框架决定:放行/丢/redirect/继续下一条

SCHED_ACT 作为 action 被引用时:
  net/sched/act_bpf.c:35 tcf_bpf_act()
```

## 5. 如何卸载

```
tc filter del dev eth0 ingress
  └─ RTM_DELTFILTER
       └─ net/sched/cls_api.c:2472 tc_del_tfilter()      (注册于 4093)
            └─ cls_bpf.c:301 cls_bpf_delete()
                 └─ 286 __cls_bpf_delete()
                      └─ 276 cls_bpf_delete_prog_work()   ← 异步 work(包还在飞)
                           └─ 267 __cls_bpf_delete_prog() → bpf_prog_put()
```

之后 prog fd 无人持有即真正释放(见 [002 §5](002.eBPF生命周期-加载生效卸载.md))。TC 没有独立 link fd(netlink 挂载),换程序 = `tc filter replace`。
