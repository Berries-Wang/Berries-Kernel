# TRACING:fentry / fexit / fmod_ret(BPF_PROG_TYPE_TRACING)

> **ftrace 直连的低开销插桩**:利用 ftrace 的 direct call 机制,把程序直接"焊"在目标内核函数入口/出口——比 kprobe 软件断点开销低一个量级,且基于 BTF 拿到**强类型参数与返回值**。枚举值 [bpf.h:1087](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1087);ops 注册 [bpf_types.h:49](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L49)。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- `SEC("fentry/my_func")`:函数进入观测(参数强类型,免 `bpf_probe_read`)
- `SEC("fexit/my_func")`:函数退出,**一次性拿到参数 + 返回值**(kretprobe 拿参数要自己存 map)
- `SEC("fmod_ret/my_func")`:**修改返回值**——目标函数须声明 `ALLOW_ERROR_INJECTION`,程序返回非 0 即改变内核行为
- `SEC("fentry.s/…")` sleepable 变体;新还有 `BPF_TRACE_FSESSION`([bpf.h:1156](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1156),entry+exit 合一)
- LSM/EXT 类型复用同一套 trampoline 机制,见 [031](031.LSM.md)

## 2. 上下文与返回值

- 上下文 = **目标函数的形参原型**(加载时 `attach_btf_id` 指定目标,verifier 按 BTF 逐字段校验)
- fentry 忽略返回值;fmod_ret 的返回值用于改写目标函数返回值
- helper 表:[kernel/trace/bpf_trace.c:1695 `tracing_prog_func_proto`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/trace/bpf_trace.c#L1695)(1762 回落到 raw_tp 表)

## 3. 如何生效(attach)= 生成 trampoline

```
bpf(BPF_LINK_CREATE,
    attach_type = BPF_TRACE_FENTRY(1122)/FEXIT(1123)/
                  BPF_MODIFY_RETURN(1124)/FSESSION(1156),
    prog_fd, attach_btf_id = 目标函数 BTF id)
  └─ kernel/bpf/syscall.c:5764-5783 link_create 分派
       └─ syscall.c:3569 bpf_tracing_prog_attach()   (建 bpf_tracing_link)
            └─ kernel/bpf/trampoline.c:1068 bpf_trampoline_get()
                 ├─ 331 bpf_trampoline_lookup():按目标函数找/建跳板对象
                 └─ 841 bpf_trampoline_link_prog()
                      └─ 678 arch_prepare_bpf_trampoline()
                         生成一段本机代码(arm64:
                         arch/arm64/net/bpf_jit_comp.c:2798):
                           保存参数 → __bpf_prog_enter → 你的 prog
                           → (fexit: 取返回值) → __bpf_prog_exit
            ftrace 把目标函数入口 patch 成 direct call 指向跳板
            (arm64 支持见 arch/arm64/Kconfig:190
             HAVE_DYNAMIC_FTRACE_WITH_DIRECT_CALLS;
             对接:trampoline.c:37/60)──【生效】
```

## 4. 触发执行路径

```
任何 CPU 执行到目标函数:
  函数入口(ftrace patch 点)─ direct call ─▶ trampoline 跳板代码
    ├─ trampoline.c:1272 __bpf_prog_enter()   迁移禁用/上下文准备
    ├─ bpf_prog_run(prog, regs/args) → JIT 本机码
    │    (sleepable 走 1250 __bpf_prog_enter_sleepable)
    ├─ fmod_ret:返回非 0 → 直接短路目标函数
    └─ trampoline.c:1283 __bpf_prog_exit()
```

## 5. 如何卸载

```
close(link fd)
  └─ kernel/bpf/syscall.c:3503 bpf_tracing_link_release()
       └─ kernel/bpf/trampoline.c:1088 bpf_trampoline_put()
            ├─ 从跳板摘下 prog,重生成跳板代码
            └─ 该函数的最后一个 prog 也摘掉 → 回收 trampoline,
               ftrace 恢复 nop(引用归零才真正释放,见 002 §5)
```

## 6. 与 kprobe 对比(选型)

| | kprobe([020](020.KPROBE与UPROBE.md)) | fentry/fexit(本篇) |
|-|-|-|
| 机制 | 软件断点(int3/brk) | ftrace direct call + trampoline |
| 开销 | 高(陷阱 + 单步) | 低(一次跳转) |
| 参数访问 | pt_regs + probe_read | BTF 强类型,直接读 |
| 可挂位置 | 几乎任意地址 | 非 inline/非 __init 的内核函数(按 BTF 索引) |
| uprobe 对应 | 有 | 无(用户态函数暂无 fentry) |
