# STRUCT_OPS(BPF_PROG_TYPE_STRUCT_OPS)

> **用 BPF 实现内核的"函数指针表"**:内核很多子系统用 `struct xxx_ops`(一簇函数指针)做抽象,TCP 拥塞控制就是 `struct tcp_congestion_ops`。这个类型允许 BPF 程序逐个填进 ops 的槽位,**整个替换内核行为**。枚举值 [bpf.h:1088](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1088);ops 注册 [bpf_types.h:71](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L71);attach type `BPF_STRUCT_OPS` [1142](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1142)。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- **自定义 TCP 拥塞控制算法**:写个 BPF 版 BBR 变体,`sysctl net.ipv4.tcp_congestion_control` 直接选用,不用改内核(最经典用法,见 [net/ipv4/bpf_tcp_ca.c](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/bpf_tcp_ca.c#L332))
- **sched_ext**:用 BPF 实现完整 CPU 调度器类(同一机制的最大化应用)
- 其他已注册可用的 ops:tcp-cc、sched_ext 等(见 `register_bpf_struct_ops` 的调用者)

## 2. 机制:struct_ops 是一张特殊 map

与"挂到钩子上"的类型不同,struct_ops 的载体是一张 **`BPF_MAP_TYPE_STRUCT_OPS` map**:map 的 value 类型就是内核 ops 结构,程序被"写进 map"时填入对应函数槽。

```
用户态(libbpf):
  SEC("struct_ops") 的 prog 们
  SEC(".struct_ops") 的 map 声明(链接期把 prog 绑到槽位)
  ① bpf(BPF_MAP_CREATE, type=BPF_MAP_TYPE_STRUCT_OPS,
        btf_vmlinux_value_type_id = tcp_congestion_ops 的 BTF id)
  ② 填 value(各槽位指向 prog fd)
  ③ bpf(BPF_MAP_UPDATE_ELEM, map_fd, key=0, value)   ← 老 attach 方式
       └─ kernel/bpf/bpf_struct_ops.c:686 bpf_struct_ops_map_update_elem()
            ├─ 821 bpf_link_init() —— 内部建 link(记录"map 槽 ↔ prog")
            ├─ 把 ops 的函数指针换成 trampoline 跳板入口
            └─ 调子系统注册函数(如 tcp_register_congestion_control)
               ──【生效:内核从此调你的算法】
  ③' 新方式:bpf(BPF_LINK_CREATE, attach_type=BPF_STRUCT_OPS)
       └─ kernel/bpf/bpf_struct_ops.c:1360 bpf_struct_ops_link_create()
            (syscall.c:5736 分派;本树尾部新命令
             BPF_PROG_ASSOC_STRUCT_OPS(bpf.h:995)是其变体)
```

## 3. 触发执行路径(以 TCP CC 为例)

```
TCP 拥塞控制时点(cwnd 更新/ACK 处理/RTT 采样…):
  net/ipv4/tcp_*.c 调 icsk->icsk_ca_ops->cong_avoid() 等函数指针
    └─ 指针已指向 trampoline 跳板(同 024 机制)
         → bpf_prog_run() → 你的 BPF 拥塞控制代码
  注册模板:net/ipv4/bpf_tcp_ca.c:332 bpf_tcp_congestion_ops
            (350 register_bpf_struct_ops;文件已从 kernel/bpf/ 移到 net/ipv4/)
```

## 4. 如何卸载

```
方式① map 元素删除:bpf(BPF_MAP_DELETE_ELEM)
  └─ 触发 bpf_struct_ops 的 map_delete 实现 → 注销(如
     tcp_unregister_congestion_control),放掉槽位 prog 引用
方式② link:close link fd / BPF_LINK_DETACH
  └─ kernel/bpf/bpf_struct_ops.c:1311 bpf_struct_ops_map_link_detach()
     (原地换新程序:bpf_struct_ops_map_link_update:1261 —— 不中断流量)
注意:正在被连接使用的 CC 算法不能卸载(引用保护)
```
