# FLOW_DISSECTOR(BPF_PROG_TYPE_FLOW_DISSECTOR)

> **可编程的协议头解析器**:内核里"识别一个包是什么流"(flow dissector)的逻辑默认写死,这个类型允许用 BPF 替换它——让 tc flower、RPS/flowtable 等依赖流哈希的机制认识私有协议。枚举值 [bpf.h:1083](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1083);ops 注册 [bpf_types.h:35](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L35);attach type `BPF_FLOW_DISSECTOR` [1115](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1115)。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- **非标准封装/私有协议**:`__skb_flow_dissect()` 只认识以太网/IP/标准隧道;自定义协议(如公司内 RPC 封装)可以被解析出五元组,进而享受 RFS、flowtable、tc flower 硬件 offload
- 按 netns 生效:不同 netns 可用不同解析器(默认用内核自带的)

## 2. 上下文与返回值

- 上下文 `struct bpf_flow_dissector *`(eth/proto/nhoff/hlen…,配合 `bpf_flow_keys()` helper)
- 程序调 `bpf_flow_dissector_*(…)` 系列 helper 逐层填流关键字;返回 0 表示放弃(回退默认解析)

## 3. 如何生效(attach)

与 SK_LOOKUP 一样走 **netns 槽位**:

```
方式① bpf(BPF_PROG_ATTACH, attach_type=BPF_FLOW_DISSECTOR)
  └─ kernel/bpf/syscall.c:4566 分派
       └─ kernel/bpf/net_namespace.c:296 netns_bpf_prog_attach()
            【写入 netns 的 flow_dissector 槽位 → 生效】
方式② BPF_LINK_CREATE
  └─ net_namespace.c:420 netns_bpf_link_attach() → link fd

(查询当前:syscall.c:4699 的 query 分支)
```

## 4. 触发执行路径

```
任何走流解析的路径(flow hash / flower 分类 / flowtable):
  net/core/flow_dissector.c:1057 __skb_flow_dissect()
    └─ 1142-1161 构造 bpf_flow_dissector 上下文
         └─ 1004 bpf_flow_dissect(prog, ctx)
              └─ bpf_prog_run() → BPF 程序解析并填 flow_keys
                   未挂载时走内核默认解析代码
```

## 5. 如何卸载

- `bpf(BPF_PROG_DETACH)` → [net_namespace.c:382 `netns_bpf_prog_detach()`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/net_namespace.c#L382),回退默认 dissector
- link 式:close link fd;netns 销毁强制清空;引用归零才释放(见 [002 §5](002.eBPF生命周期-加载生效卸载.md))
