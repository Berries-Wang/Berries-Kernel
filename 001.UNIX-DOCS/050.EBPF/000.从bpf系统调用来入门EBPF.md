# 从 bpf() 系统调用入门 eBPF

> eBPF 的一切都从 `bpf(2)` 这**一个**系统调用进去:加载程序、建 map、挂载(attach)、固定(pin)都是它的子命令。本文拆开这条入口,看一条 `BPF_PROG_LOAD` 如何逐层下沉到验证器与 JIT。
>
> 源码行号 = 仓库 Linux 7.1.3 树。类型怎么选见 [001.eBPF程序类型总览](001.eBPF程序类型总览.md);加载之后的生效/卸载见 [002.eBPF生命周期](002.eBPF生命周期-加载生效卸载.md)。

## 3. 一条 BPF_PROG_LOAD 的下沉路径

```
用户态 (libbpf / Aya / BCC)                   内核态 Linux 7.1.3
──────────────────────────                   ──────────────────
bpf(BPF_PROG_LOAD, &attr, size)
  │
  └─▶ syscall.c:6385   SYSCALL_DEFINE3(bpf)
       └─ syscall.c:6235 __sys_bpf()          case BPF_PROG_LOAD (6273)
            └─ syscall.c:2864 bpf_prog_load()
                 ├─ 2986  bpf_prog_alloc()        ← core.c:149,分配 struct bpf_prog
                 │                                  (7.1.3 定义在 bpf.h:1777)
                 ├─ 3067  find_prog_type()        ← syscall.c:2272;注册表 bpf_prog_types[]
                 │                                  (syscall.c:2261,由 bpf_types.h:5-83
                 │                                   宏展开生成类型→ops 映射)
                 ├─ 3082  bpf_check()             ← verifier.c:19915,验证器入口
                 │        ├─ 17678 do_check()       逐指令状态机
                 │        │    (主循环 17687;在 bpf_check 内 18819 被调)
                 │        └─ 20189 __bpf_prog_select_runtime()
                 ├─ core.c:2601 __bpf_prog_select_runtime()
                 │        └─ core.c:2554 bpf_prog_jit_compile()
                 │             └─ arm64: bpf_jit_comp.c:2006 bpf_int_jit_compile()
                 │                eBPF 指令 → A64 机器码
                 │                (JIT 失败回退解释器 core.c:1786 ___bpf_prog_run)
                 └─ 3112  bpf_prog_new_fd()       ← syscall.c:2519
                        anon inode "bpf-prog" (2527)
  ◀── 返回 prog fd ──┘

注意:拿到 fd 只是"程序在手",还没生效——必须 attach 到钩子(见 002)。
```

## 4. map fd 顺带一提

`BPF_MAP_CREATE` 成功后经 [kernel/bpf/syscall.c:1174 `bpf_map_new_fd()`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/syscall.c#L1174)(1182 行建 `"bpf-map"` anon inode)返回 map fd。map 类型(hash/array/sockmap/ringbuf…)见[内核文档 maps](https://docs.kernel.org/bpf/maps.html);prog 与 map 的 fd 生命周期规则相同(见 [002](002.eBPF生命周期-加载生效卸载.md))。

## 5. sleepable 程序

加载时带 `BPF_F_SLEEPABLE`([bpf.h:1298](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1298);flag 合法位校验 [syscall.c:2880](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/syscall.c#L2880),赋值 `prog->sleepable` [2997](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/syscall.c#L2997)):允许程序内调用可睡眠 helper/kfunc。哪些类型允许由 [verifier.c:19524 `can_be_sleepable()`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/verifier.c#L19524) 白名单决定;`BPF_PROG_TYPE_SYSCALL` 强制 sleepable([verifier.c:19553](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/verifier.c#L19553))。
