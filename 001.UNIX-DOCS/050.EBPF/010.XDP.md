# XDP(BPF_PROG_TYPE_XDP)

> **最早的收包钩子**:在 SKB(socket buffer)分配之前就看到原始以太网帧,能以"每包几十纳秒"的代价直接丢包/转发。枚举值 [bpf.h:1067](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1067);ops 注册 [bpf_types.h:11 `BPF_PROG_TYPE(XDP, xdp)`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L11)。行号 = 仓库 7.1.3 树;生命周期背景见 [002](002.eBPF生命周期-加载生效卸载.md)。

## 1. 使用场景

- **抗 DDoS / 早丢弃**:攻击流量在进协议栈之前 `XDP_DROP`,省掉整个网络栈开销
- **负载均衡/端口 redirects**:XDP_TX 原卡回发、XDP_REDIRECT 转发到另一网卡/CPU(Cilium katran、Cloudflare 都在用)
- **包采样/监控**:线速统计
- 三种运行模式:**native**(驱动支持,最快)、**generic**(SKB 模式,任何网卡可用,慢一些)、**offload**(网卡硬件执行)

## 2. 上下文与返回值

- 上下文 `struct xdp_md *`:data/data_end 直指原始帧,不经过 `sk_buff`
- 返回 `enum xdp_action`([bpf.h:6548](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L6548)):`XDP_ABORTED`(6549,错误)/ `XDP_DROP`(6550)/ `XDP_PASS`(6551,继续走协议栈)/ `XDP_TX`(6552,原卡回发)/ `XDP_REDIRECT`(6553)
- 分片包需加载标志 `BPF_F_XDP_HAS_FRAGS`([bpf.h:1303](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1303))

## 3. 如何生效(attach)

两条入口,最终都汇合到 [net/core/dev.c:10379 `dev_xdp_attach()`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/dev.c#L10379):

```
方式① netlink(legacy,最常用)                    方式② bpf() link
ip link set dev eth0 xdp obj prog.o     bpf(BPF_LINK_CREATE,
       │                                  attach_type = BPF_XDP)  ← bpf.h:1135
       ▼                                        │
net/core/rtnetlink.c:3067 do_setlink()          ▼
  └─ IFLA_XDP 属性(3384)            net/core/dev.c:10652 bpf_xdp_link_attach()
       └─ 3423 dev_change_xdp_fd()              │  (10506 dev_xdp_attach_link)
            │  fd=-1 即 detach                   │
            └──────────────┬─────────────────────┘
                             ▼
              net/core/dev.c:10379 dev_xdp_attach()
                └─ 按模式写入 net_device 的 xdp 状态
                   native → 驱动 ndo_bpf 安排驱动 RX 路径
                   generic → 挂到软路径,见 §4
```

## 4. 触发执行路径

```
native 模式(驱动内):
  网卡 RX → 驱动 xdp 调用点 ──▶ include/net/xdp.h:689 bpf_prog_run_xdp()
                                 (7.1.3 已从 filter.h 移到 xdp.h)

generic 模式(软路径,7.1.3 行号):
  net/core/dev.c:5972 __netif_receive_skb_core()
    └─ 6012 do_xdp_generic()                    ← dev.c:5656
         └─ 5666 netif_receive_generic_xdp()    ← dev.c:5576(构造 xdp_buff)
              └─ 5604 bpf_prog_run_generic_xdp() ← dev.c:5448
                   └─ 5488 bpf_prog_run_xdp()   → JIT 本机码
                        │
                        ▼ 返回 xdp_action
              DROP→丢; PASS→构造 skb 继续协议栈;
              TX→原卡回发; REDIRECT→devmap/cpumap 转发
```

## 5. 如何卸载

- netlink 式:`ip link set dev eth0 xdp off` → [dev_change_xdp_fd()](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/dev.c#L10720) 传 fd=-1 清除
- link 式:close link fd → [dev_xdp_detach_link()](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/dev.c#L10513)(release 回调 10543)
- 之后再 close prog fd(或它已 pin),引用归零才真正释放(见 [002 §5](002.eBPF生命周期-加载生效卸载.md))
- 附:DEVMAP/CPUMAP 上还能各挂一个 XDP 程序处理 redirect 目的端(attach type `BPF_XDP_DEVMAP` [1131](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1131) / `BPF_XDP_CPUMAP` [1133](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1133))
