# SYSCALL(BPF_PROG_TYPE_SYSCALL)

> **不挂任何内核钩子的 BPF 程序**:由用户态通过 `BPF_PROG_TEST_RUN` 显式"调用",可睡眠——用来在内核里执行一段自定义逻辑(批量 map 操作、处理 user ring buffer 数据),像"自带 JIT 的系统调用"。枚举值 [bpf.h:1092](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1092);ops 注册 [bpf_types.h:80](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L80)。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- **user ring buffer 的消费端**:用户态批量写数据,内核侧 SYSCALL 程序批量处理(最典型)
- **内核侧编排**:一次"调用"里完成多次 map 查改,省来回系统调用
- 可以睡眠:能调用 `bpf_copy_from_user()` 等可睡眠 helper

## 2. 上下文与返回值

- 上下文 = `union bpf_attr` 的 test_run 部分(用户传入的任意字节)
- 返回值即程序 return 值,回传给用户态
- **强制 sleepable**:verifier 要求([verifier.c:19553](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/verifier.c#L19553));且 `expected_attach_type` 必须为 0([syscall.c:2742](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/syscall.c#L2742),函数定义 2646)

## 3. 如何"生效"

没有 attach 这一步——加载即就绪,等用户态调用:

```
bpf(BPF_PROG_LOAD, type=BPF_PROG_TYPE_SYSCALL)
  → prog fd
bpf(BPF_PROG_TEST_RUN, prog_fd, data_in/out …)          ← "调用"它
  └─ kernel/bpf/syscall.c:6291 case 分支
       └─ syscall.c:4720 bpf_prog_test_run()
            └─ 4741 prog->aux->ops->test_run()
                 └─ net/bpf/test_run.c:1645 bpf_prog_test_run_syscall()
                      └─ bpf_prog_run(prog, ctx) → JIT 本机码
(内核内也可经 syscall.c:6426 kern_sys_bpf() 调用:6441 按
 BPF_PROG_TYPE_SYSCALL 取 prog 执行)
```

## 4. 如何卸载

无挂载点:close prog fd(且无 pin)即引用归零、延迟释放(见 [002 §5](002.eBPF生命周期-加载生效卸载.md))。ops 定义 [syscall.c:6553 `bpf_syscall_prog_ops`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/syscall.c#L6553)。
