# LSM(BPF_PROG_TYPE_LSM)

> **用 eBPF 写 Linux 安全模块**:每个 LSM 钩子(文件打开、exec、mount、socket……)都可以挂 BPF 程序,返回 -EPERM 即拒绝——比写内核模块轻(经过验证器),比重编译内核灵活。枚举值 [bpf.h:1090](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1090);ops 注册 [bpf_types.h:76](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L76);attach type `BPF_LSM_MAC` [1125](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1125)(cgroup 级还有 `BPF_LSM_CGROUP` [1141](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1141))。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- **运行时安全策略/监控**:进程执行、文件访问、Capabilities 使用的策略引擎(替代/叠加 AppArmor、SELinux)
- **审计/取证**:安全事件(如 `security_file_open`、`security_bprm_check`)实时上报,Tetragon 的底层
- 无法做的事:改安全决策以外的执行流(那是 fmod_ret/TRACING 的事)

## 2. 上下文与返回值

- 上下文 = **该 LSM 钩子的原型参数**(如 `SEC("lsm/file_open")` 对应 `int bpf_lsm_file_open(struct file *file)`,BTF 强类型)
- 返回 0 = 放行;返回 `-EPERM` 等负值 = 拒绝该操作
- helper 表:[kernel/bpf/bpf_lsm.c:225 `bpf_lsm_func_proto`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/bpf_lsm.c#L225)(可睡眠钩子支持 sleepable)

## 3. 机制:每个钩子一个可跳转的 nop 函数

```
kernel/bpf/bpf_lsm.c:24-30
  LSM_HOOK 宏为每个钩子生成:
    __weak noinline RET bpf_lsm_##NAME(args) { return 0; }
  (23 行注释:程序经 trampoline 挂到这些 nop 函数上)

bpf 自身作为一个 LSM 注册进框架:
  security/bpf/hooks.c:35 DEFINE_LSM(bpf)
    └─ 27 bpf_lsm_init() → security_add_hooks()

内核调用钩子时:
  security/security.c:469/482
    static_call(LSM_STATIC_CALL(HOOK, NUM))(...)
      → bpf_lsm_##NAME() —— 没挂程序时就是"返回 0"的空函数
```

## 4. 如何生效(attach)= fentry 同款 trampoline

```
bpf(BPF_LINK_CREATE, attach_type=BPF_LSM_MAC,
    prog_fd, attach_btf_id = 目标钩子 bpf_lsm_xxx 的 BTF id)
  └─ kernel/bpf/syscall.c:5764 link_create 分派(TRACING/LSM 同支)
       └─ syscall.c:3569 bpf_tracing_prog_attach()
            ├─ 3599 校验 expected_attach_type == BPF_LSM_MAC
            └─ bpf_trampoline_get()/link_prog()   ← 与 024 完全同一套
               fentry 机制详见 [024.TRACING](024.TRACING-fentry-fexit-fmod_ret.md)
               ──【生效】
```

## 5. 触发执行路径

```
任何触发该 LSM 钩子的内核路径(如 do_filp_open → security_file_open):
  security/security.c static_call → bpf_lsm_file_open(file)
    └─ 函数入口已被 trampoline 改写 ─▶ 跳板
         __bpf_prog_enter → bpf_prog_run(你的策略) → __bpf_prog_exit
              返回 0 放行 / 负值拒绝
```

## 6. 如何卸载

```
close(link fd)
  └─ kernel/bpf/syscall.c:3503 bpf_tracing_link_release()
       └─ kernel/bpf/trampoline.c:1088 bpf_trampoline_put()
            最后一个程序摘除 → bpf_lsm_##NAME 恢复为空函数
(引用归零才真正释放,见 002 §5)
```
