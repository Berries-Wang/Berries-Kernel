# 导读:JA4T——一个完整的 TC 分类器 eBPF 示例

> 本目录是 [050.EBPF](../README.md) 的实战示例,**迁移自** `Berries-CYBERCLOAK/000.CODE_SPACE/003.JA4T_PLUGIN`(2026-10-24,**完整项目拷贝**,原项目保留不动)。它是 050 系列笔记里反复引用的那条 TC 执行链(README 里 `ja4t_parse_syn` 的全景图)的真实出处:两个 `BPF_PROG_TYPE_SCHED_CLS` 程序挂在同一网卡的 **TC Ingress/Egress**,从 TCP SYN 和 TLS Server Hello 中提取指纹,经 BPF map 交给用户态 daemon。包含 eBPF C 程序、Rust daemon(Aya 加载/挂载、map 轮询、Unix Socket 服务)、Cargo 构建脚本与运行日志,`cargo build --release` 可原地构建。

## 3. 值得细看的三个实现细节

1. **p0f 风格的包定位**(tcp_options.bpf.c):不信任链路层头长度,在 offset 0..38 步长 2 扫描 IP 版本号——兼容 USB WiFi 网卡的 radiotap 等非标准链路层。这是"eBPF 里防御性解析数据包"的范本。
2. **验证器友好的写法**:循环用 `#pragma unroll` / 有界 for(内核 ≥5.3 的 bounded loop),所有指针访问前都做 `data + len <= data_end` 检查——每个检查都能在 [000 笔记](../000.从bpf系统调用来入门EBPF.md)的 verifier 环节找到对应原理。
3. **重活留给用户态**:eBPF 只抓原始字节(40B raw_opts / 120B ext_raw),选项排序、SHA256 指纹计算放 daemon 里做——绕开 eBPF 指令数与循环限制,是典型的"内核过滤、用户态计算"分工。
