# SOCKET_FILTER(BPF_PROG_TYPE_SOCKET_FILTER)

> **最古老的 BPF 类型**:挂在 socket 收包路径上,决定包是否进接收队列——tcpdump 的底层机制,也是 cBPF(经典 BPF)到 eBPF 的演化起点。枚举值 [bpf.h:1062](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1062);ops 注册 [bpf_types.h:5 `BPF_PROG_TYPE(SOCKET_FILTER, sk_filter)`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L5)。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- **抓包过滤**:tcpdump/libpcap——过滤表达式编译成 BPF 字节码,只在内核把匹配的包复制给 AF_PACKET socket,不匹配的直接丢
- **降噪**:高频数据源(行情/日志 UDP)在内核层丢掉不要的流,省唤醒开销

## 2. 上下文与返回值

- 上下文 `struct __sk_buff *`(只读视角,包数据在 data~data_end)
- 返回 **0 = 丢弃**,**非 0 = 保留**(进入 socket 接收队列)

## 3. 如何生效(attach)

setsockopt 一行生效,没有 link:

```
sk = socket(AF_PACKET, SOCK_RAW, ...)
bpf(BPF_PROG_LOAD, type=SOCKET_FILTER) → prog fd   (见 000 笔记)
setsockopt(sk, SOL_SOCKET, SO_ATTACH_BPF, &prog_fd)
  │
  ▼
net/core/sock.c:1478 case SO_ATTACH_BPF:
  └─ 1487 sk_attach_bpf()            ← net/core/filter.c:1594
       └─ 校验类型后 sk->sk_filter = prog   ──【生效:socket 持有引用】

(经典 cBPF 走 SO_ATTACH_FILTER → sk_attach_filter,filter.c:1548;
 libpcap 旧版编出 cBPF,内核同样翻译成 eBPF 执行)
```

## 4. 触发执行路径

```
包到达 socket(sk_buff 投递):
  net/core/sock.c:545 __sk_receive_skb()
    └─ 551 sk_filter_trim_cap()          ← net/core/filter.c:133
         ├─ 133 函数开头同时是 cgroup INGRESS 钩子调用点(148 行,见 030 笔记)
         └─ 164 bpf_prog_run_save_cb()   ← include/linux/filter.h:987
              └─ __bpf_prog_run_save_cb (966) → bpf_prog_run() → JIT
                   返回 0 → 丢; 非 0 → trim 后入接收队列
```

## 5. 如何卸载

- `setsockopt(sk, SOL_SOCKET, SO_DETACH_FILTER)`:[net/core/sock.c:1516](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/sock.c#L1516) → [net/core/filter.c:11417 `sk_detach_filter()`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/filter.c#L11417) 换回 NULL 并 `bpf_prog_put`
- 更常见:**直接 close socket**——socket 销毁时自动放掉 filter 引用;prog fd 再 close,引用归零即释放(见 [002 §5](002.eBPF生命周期-加载生效卸载.md))
- 附:每次 `SO_ATTACH_BPF` 会原子替换旧 filter,不需要先 detach
