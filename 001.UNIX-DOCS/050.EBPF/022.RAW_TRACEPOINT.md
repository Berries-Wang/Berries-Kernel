# RAW_TRACEPOINT(BPF_PROG_TYPE_RAW_TRACEPOINT / RAW_TRACEPOINT_WRITABLE)

> **"裸"tracepoint**:拿到的不是解析好的参数缓冲,而是 `u64 args[]` 原始寄存器级参数数组——开销比 TRACEPOINT 更低,是 libbpf `RAW_TRACEPOINT`/`tp_btf` 之外高性能观测的选择。枚举值 [bpf.h:1078](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1078)(WRITABLE [1085](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1085));ops 注册 [bpf_types.h:45/47](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L45)。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- 低开销事件统计(省去 perf 样本构造)
- `RAW_TRACEPOINT_WRITABLE`:允许**修改** args 指向的数据(目前仅 `bpf_modify_return_test` 等少数 tp 开放;典型演示是改 `sched_wakeup` 目标 task 的字段)
- bpftrace 的 `rawtracepoint:` 探针、libbpf `SEC("raw_tp/...")` / `SEC("raw_tracepoint/...")`

## 2. 上下文与返回值

- 上下文 `struct bpf_raw_tracepoint_args { __u64 args[BPF_RAW_TRACEPOINT_ARGS_…] }`:args[i] 即埋点的第 i 个原始参数(是指针还是整数自己判断,读内容仍需 `bpf_probe_read_kernel()`)
- helper 表:[kernel/trace/bpf_trace.c:1678 `raw_tp_prog_func_proto`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/trace/bpf_trace.c#L1678)(含 `bpf_perf_event_output_raw_tp`,1594)
- 返回值:观测型,无动作语义

## 3. 如何生效(attach)

```
方式① 老命令(返回 fd 即 link):
  bpf(BPF_RAW_TRACEPOINT_OPEN, name="sched_switch", prog_fd)
    └─ kernel/bpf/syscall.c:4316 bpf_raw_tracepoint_open()
         └─ 4332 bpf_raw_tp_link_attach()      ← syscall.c:4243
              ├─ 4281 bpf_get_raw_tracepoint(name)
              │    └─ kernel/trace/bpf_trace.c:2051
              │       在 __start/_stop__bpf_raw_tp[] 注册表(2048-2049,
              │       编译期由 TRACE_EVENT+BPF_EXTENDED 链接段生成)按名查
              └─ bpf_probe_register()          ← bpf_trace.c:2141
                   以 bpf_trace_run1..12 为回调注册到 tracepoint ──【生效】

方式② 新:bpf(BPF_LINK_CREATE, attach_type=BPF_TRACE_RAW_TP)  ← bpf.h:1121
```

## 4. 触发执行路径

```
tracepoint 触发:
  注册的回调 bpf_trace_run1..12(参数个数选宏,bpf_trace.c:2120 生成)
    └─ kernel/trace/bpf_trace.c:2073 __bpf_trace_run(link, regs?, args)
         ├─ migrate_disable + RCU read-side 保护
         └─ bpf_prog_run_active(prog, args) → JIT 本机码
              (WRITABLE 变体允许写回 args 指向的缓冲)
```

## 5. 如何卸载

close fd(老命令的 fd / link fd 一样):

```
kernel/bpf/syscall.c:3799 bpf_raw_tp_link_release()
  └─ kernel/trace/bpf_trace.c:2159 bpf_probe_unregister()
       (从 tracepoint 注销回调;引用归零才真正释放,见 002 §5)
```
