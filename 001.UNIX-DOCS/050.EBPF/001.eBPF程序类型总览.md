# eBPF 程序类型总览

> 一个 prog type 决定三件事:**能用什么上下文(参数)、能调哪些 helper、能挂到哪类钩子**。类型枚举在 [include/uapi/linux/bpf.h:1060 `enum bpf_prog_type`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1060)(7.1.3 共 32 个实际值);每个类型通过 [include/linux/bpf_types.h:5-83](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L5) 的 `BPF_PROG_TYPE(TYPE, ops)` 宏注册进 [syscall.c:2261 `bpf_prog_types[]`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/syscall.c#L2261),加载时由 [find_prog_type()](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/bpf/syscall.c#L2272) 绑定 ops。
>
> 更细的挂载点用 `enum bpf_attach_type`([bpf.h:1097](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1097))区分,加载时放进 `expected_attach_type`。行号 = 仓库 7.1.3 树。

## 3. 选型速记

- **看内核内部/函数级观测** → 优先 fentry/fexit([024](024.TRACING-fentry-fexit-fmod_ret.md),开销低、类型安全),退而求其次 kprobe([020](020.KPROBE与UPROBE.md));固定事件用 tracepoint([021](021.TRACEPOINT.md))
- **尽快丢包/转发** → XDP([010](010.XDP.md));**需要进协议栈后改包** → TC([011](011.TC-SCHED_CLS与SCHED_ACT.md))
- **容器/pod 级网络策略** → cgroup 家族([030](030.CGROUP系列.md));**同节点 pod 间加速** → sockmap([013](013.SK_MSG与SK_SKB-sockmap.md))
- **改内核行为(安全策略)** → LSM([031](031.LSM.md));**替换内核算法** → STRUCT_OPS([032](032.STRUCT_OPS.md))
- 所有类型共享同一条加载/生效/卸载生命周期,见 [002.eBPF生命周期](002.eBPF生命周期-加载生效卸载.md)
