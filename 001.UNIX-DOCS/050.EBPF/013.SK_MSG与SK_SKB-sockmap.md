# SK_MSG 与 SK_SKB:sockmap 程序(BPF_PROG_TYPE_SK_MSG / SK_SKB)

> **socket 级的 verdict 程序**:配合 `BPF_MAP_TYPE_SOCKMAP/SOCKHASH`(socket map)使用——把 socket 存进 map,sendmsg/收包路径上的数据先过一遍 BPF 程序,由它决定 `pass/drop/redirect`,redirect 到 map 里的另一个 socket 就是**同主机应用间零拷贝直通**。枚举值 SK_MSG [bpf.h:1077](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1077)、SK_SKB [1075](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1075);ops 注册 [bpf_types.h:33 / 31](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/bpf_types.h#L33)。行号 = 仓库 7.1.3 树。

## 1. 使用场景

- **socket 级负载均衡**:Cilium 用 sockmap 让同节点 Pod 间的 TCP 流绕过内核协议栈,应用层直接互通
- **应用代理/转发**:程序内根据消息内容把流 redirect 到另一个 socket
- SK_MSG 两个细分:`SK_SKB_STREAM_PARSER`(把字节流切成消息,给 verdict 用)与 verdict 本体;attach type 分别为 `BPF_SK_SKB_STREAM_PARSER` [1102](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1102)、`BPF_SK_SKB_STREAM_VERDICT` [1103](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1103)(收包路径,SK_SKB)、`BPF_SK_MSG_VERDICT` [1105](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1105)(sendmsg 路径,SK_MSG)、另有通用 `BPF_SK_SKB_VERDICT` [1136](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/uapi/linux/bpf.h#L1136)

## 2. 上下文与返回值

- SK_MSG 上下文 `struct sk_msg_md *`(data/data_end 指向待发消息)
- SK_SKB 上下文 `struct __sk_buff *`
- 返回 verdict:`__SK_PASS` / `__SK_DROP` / `__SK_REDIRECT`(redirect 时用 `bpf_msg_redirect_hash()`/`bpf_sk_redirect_hash()` 指明目标 socket)

## 3. 如何生效(attach)

attach 的目标 fd 是 **sockmap(map 的 fd)**,不是 socket:

```
bpf(BPF_MAP_CREATE, BPF_MAP_TYPE_SOCKMAP/SOCKHASH)   → map fd
bpf(BPF_PROG_LOAD, SK_MSG / SK_SKB)                  → prog fd
bpf(BPF_PROG_ATTACH,
    attach_bpf_fd = prog fd,
    target_fd     = map fd,        ← 注意:挂到 map
    attach_type   = SK_MSG_VERDICT / SK_SKB_STREAM_PARSER / STREAM_VERDICT)
  │
  ▼
kernel/bpf/syscall.c:4556 分派
  └─ net/core/sock_map.c:68 sock_map_get_from_fd()
       └─ 81 sock_map_prog_update()   ← sock_map.c:1524,写进 map 的 psock 配置
            【生效条件还差一步:socket 被加进 map(sock_map_update)
              → sock_map.c:217 sock_map_link() 建立 psock,改写该 socket 的
              data_ready / sendmsg 等回调(net/ipv4/tcp_bpf.c 注册)】
```

## 4. 触发执行路径

```
发送路径(SK_MSG):
  app sendmsg() → net/ipv4/tcp_bpf.c:517 tcp_bpf_sendmsg()
    └─ net/core/skmsg.c:921 sk_psock_msg_verdict()
         └─ 936 bpf_prog_run_pin_on_cpu(prog, msg)
              ├─ PASS → 正常 tcp_sendmsg
              ├─ DROP → 丢
              └─ REDIRECT → skmsg.c:1032 sk_psock_verdict_apply()
                             → 目标 socket 接收队列(零拷贝)

接收路径(SK_SKB / verdict):
  数据到达 → skmsg.c:1270 sk_psock_verdict_data_ready()
    └─ 1238 sk_psock_verdict_recv()(1259 执行 verdict 程序,优先 stream_verdict)

parser(可选,SK_SKB_STREAM_PARSER):
  net/ipv4/tcp_bpf.c:221 tcp_bpf_recvmsg_parser()
```

## 5. 如何卸载

- `bpf(BPF_PROG_DETACH)`(target_fd = map fd)→ [sock_map.c:86 `sock_map_prog_detach()`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/sock_map.c#L86)
- 或 `BPF_LINK_CREATE` 挂的,close link fd → [sock_map_link_detach/release](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/sock_map.c#L1725)(1725/1742)
- 从 map 删除 socket 元素/销毁 map 也会拆掉对应 socket 的 psock(回调还原);prog/map 引用归零才释放(见 [002 §5](002.eBPF生命周期-加载生效卸载.md))
