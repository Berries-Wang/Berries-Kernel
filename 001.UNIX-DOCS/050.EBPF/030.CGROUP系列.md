# CGROUP 系列(BPF_PROG_TYPE_CGROUP_*)

> **按 cgroup v2 目录生效的策略钩子**:一个 cgroup 挂上程序,该 cgroup 下所有进程的网络/系统调用行为都被过滤——容器安全与 K8s 网络策略(Cilium)的基础。涉及的 prog type:`CGROUP_SKB`(包过滤)、`CGROUP_SOCK`、`CGROUP_SOCK_ADDR`、`SOCK_OPS`、`CGROUP_DEVICE`、`CGROUP_SYSCTL`、`CGROUP_SOCKOPT`(枚举行号见 [001 总览 §E](001.eBPF程序类型总览.md))。行号 = 仓库 7.1.3 树。

## 1. 使用场景与挂载点

| prog type | attach type(bpf.h 行号) | 触发时机 | 典型用途 |
|-|-|-|-|
| `CGROUP_SKB` | `INET_INGRESS` 1098 / `INET_EGRESS` 1099 | 该 cgroup 进程收/发包 | 字节级过滤、K8s NetworkPolicy(Cilium) |
| `CGROUP_SOCK` | `INET_SOCK_CREATE` 1100 / `INET_SOCK_RELEASE` 1132 | socket 创建/销毁 | 按来源打标记 skb mark |
| `CGROUP_SOCK_ADDR` | `INET4/6_BIND` 1106/1107、`INET4/6_CONNECT` 1108/1109、`UDP4/6_SENDMSG` 1112/1113、`UDP4/6_RECVMSG` 1117/1118 等 | bind/connect/sendmsg/recvmsg | 服务发现式地址改写(透明接代理)、bind 权限 |
| `SOCK_OPS` | `BPF_CGROUP_SOCK_OPS` 1101 | TCP 连接建立/RTT/状态回调 | 拥塞控制选型、调 sk_storage |
| `CGROUP_DEVICE` | `CGROUP_DEVICE` 1104 | 设备节点 open/mknod | cgroup v2 的设备访问控制 |
| `CGROUP_SYSCTL` | `CGROUP_SYSCTL` 1116 | sysctl 读写 | 限制容器改 sysctl |
| `CGROUP_SOCKOPT` | `SETSOCKOPT` 1120 / `GETSOCKOPT` 1119 | set/getsockopt | 拦截/重写sockopt |

## 2. 上下文与返回值(以 CGROUP_SKB 为例)

- 上下文 `struct __sk_buff *`
- 返回 `1 = 放行`,`0 = 丢弃`(egress/ingress 通用);SOCK_ADDR 型返回 `1 = 放行原地址`,`0 = 用程序改过的地址`,`-1 = 拒绝该系统调用`

## 3. 如何生效(attach)

```
bpf(BPF_PROG_ATTACH,                        ← 也可 BPF_LINK_CREATE(link 式)
    target_fd     = cgroupfd,               ← cgroup v2 目录的 fd
    attach_bpf_fd = prog_fd,
    attach_type   = BPF_CGROUP_INET_EGRESS …)
  │
  ├─ 老接口:kernel/bpf/syscall.c:4517 bpf_prog_attach()
  │    └─ 4553 分派 → kernel/bpf/cgroup.c:1325 cgroup_bpf_prog_attach()
  │         └─ 785 __cgroup_bpf_attach()
  │              ├─ 标志:BPF_F_ALLOW_OVERRIDE(1240,子 cgroup 可覆盖)/
  │              │        BPF_F_ALLOW_MULTI(1241,同点多程序链)/
  │              │        BPF_F_REPLACE(1243,替换链中某程序)
  │              └─ 挂入 cgroup->bpf.parsed/并按层级计算 effective 数组
  │                 (子 cgroup 继承父的 + 自己的)──【生效】
  └─ link 式:cgroup.c:1477 cgroup_bpf_link_attach()(syscall.c:5755/5776)
```

## 4. 触发执行路径(包过滤两向为例)

```
EGRESS:该 cgroup 进程发包
  net/ipv4/ip_output.c:322 ip_finish_output()
    └─ BPF_CGROUP_RUN_PROG_INET_EGRESS      ← include/linux/bpf-cgroup.h:203
         └─ kernel/bpf/cgroup.c:1561 __cgroup_bpf_run_filter_skb()
              └─ bpf_prog_run_array(effective 数组) → 0 即丢

INGRESS:包进 socket 收包路径
  net/core/filter.c:148(位于 sk_filter_trim_cap 内)
    └─ BPF_CGROUP_RUN_PROG_INET_INGRESS     ← bpf-cgroup.h:191
         └─ 同上 __cgroup_bpf_run_filter_skb

SOCK_OPS 型:
  net/ipv4/tcp_output.c 等触发回调
    └─ kernel/bpf/cgroup.c:1721 __cgroup_bpf_run_filter_sock_ops()
```

## 5. 如何卸载

```
bpf(BPF_PROG_DETACH, target_fd=cgroupfd, attach_type=…)
  └─ kernel/bpf/syscall.c:4586 bpf_prog_detach() → 4636 分派
       └─ kernel/bpf/cgroup.c:1355 cgroup_bpf_prog_detach()
            └─ 1135 __cgroup_bpf_detach()(重算 effective)
link 式:close link fd;cgroup 目录被 rmdir 销毁时强制清空
(cgroup.c:1397 附近的 release 路径)
```
