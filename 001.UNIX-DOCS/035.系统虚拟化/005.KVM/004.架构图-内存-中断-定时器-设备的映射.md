# 004.架构图：内存、中断、定时器、设备的抽象与映射

> vCPU↔pCPU 的关系见 [003](003.架构图-vCPU与物理CPU.md)；本文补齐**其余四类硬件资源**的抽象与映射：内存、中断（GIC）、定时器、设备（I/O）。
> 术语见 [001 §1.1](001.VM-exit与VM-entry指令全链路.md#11-名词速览kvm-hyp-是什么)；源码 = 7.1.3 树，行号实测。

## 1. 资源映射全景总表

| 硬件资源 | 物理实体 | guest 看到的抽象 | 映射机制 | 相关指令/寄存器 | 详见 |
| - | - | - | - | - | - |
| CPU | pCPU | vCPU（软件对象+QEMU 线程） | 时分复用，不绑定 | `eret` 进出；VMPIDR_EL2 假身份 | [003](003.架构图-vCPU与物理CPU.md) |
| **内存** | 宿主物理页 | guest 物理地址空间（IPA） | **stage 2 页表**（KVM 维护）+ memslots（QEMU 登记） | `msr vttbr_el2`；stage 2 fault 陷阱 | §2 |
| **中断** | GIC + 物理 IRQ | 虚拟 GIC（vgic）+ 虚拟 IRQ | KVM 内核层建中断模型，hyp 装进 **ICH_LR\*\_EL2** 由硬件投递 | `HCR_EL2.AMO/IMO/FMO` 路由 | §3 |
| **定时器** | Generic Timer | 虚拟定时器（vtimer 直跑）+ 物理定时器被陷阱 | CNTVOFF_EL2 偏移；CNTHCTL_EL2 开关 | `msr cnthctl_el2` | §4 |
| **设备** | 真实磁盘/网卡/UART | 模拟设备 / virtio 设备 / 直通设备 | MMIO 陷阱→QEMU 模拟；vring 共享内存；VFIO+SMMU | 访存 abort（EC=0x20/0x24）→`KVM_EXIT_MMIO` | §5 |

## 2. 内存：两级翻译 + memslots

**三方页表职责**（谁管哪一级）：

```
 guest 虚拟地址 (gVA)
   │  ① guest 内核自己的页表 (guest VA → IPA)     ← KVM 完全不参与!
   ▼
 guest 物理地址 (IPA) ── Guest Physical Address
   │  ② stage 2 页表 (IPA → PA)                  ← KVM 维护
   │     基址 = VTTBR_EL2 (asm/kvm_mmu.h:325,
   │     每次 VM-entry 装载, 001 §3.4 #5)
   ▼
 宿主物理地址 (PA)
   ▲  ③ hva → pa 由宿主内核常规页表完成          ← QEMU 进程的普通内存
   │
 memslots: QEMU 用 KVM_SET_USER_MEMORY_REGION (uapi kvm.h:1266)
   把 "guest IPA 段 ↔ QEMU 进程的 HVA 段" 登记给 KVM
   → struct kvm_memory_slot (kvm_host.h:593):
       base_gfn(:597) IPA 起始帧号 | npages(:598) 大小
       userspace_addr(:601) HVA 起点 | dirty_bitmap(:599) 热迁移用
```

**stage 2 缺页流程**（guest 访问一块还没映射的 IPA）：

```
 guest 访存指令 → stage 2 无映射/权限 → abort
   |  [硬件异常进入] ESR_EL2←EC=0x20/0x24 (IABT/DABT_LOW), FAR_EL2←gVA, HPFAR_EL2←IPA
   v
 __kvm_hyp_vector+0x400 → 快路径 kvm_hyp_handle_dabt_low (switch.h:846):
   填 fault info (mrs far_el2/hpfar_el2, fault.h:86/90) → 无快速处理 → 慢路径
   |  → 宿主内核 kvm_handle_guest_abort (mmu.c:2220), 先做 IPA 合法性检查:
   |      IPA 超出 PARange(IPA limit) → kvm_inject_size_fault (mmu.c:2250)
   |      IPA 落在 stage-2 配置的 IPA 范围(VTCR)与 PARange 之间的空隙
   |        → 注入 SEA (mmu.c:2258)
   v
 查 memslots (mmu.c:2320 gfn_to_memslot):
   ├─ IPA 有 RAM memslot → user_mem_abort (mmu.c:2077, 调用 :2394):
   │     分配宿主页, kvm_pgtable_stage2_map (mmu.c:1203) 建立映射
   │     → 返回 1 → 重进 guest, 访存指令重执行 (001 §4.7)
   └─ hva 无效/对只读区写 (mmu.c:2323):
        ├─ IABT(取指)  → ret=-ENOEXEC, 本次 KVM_RUN 报错 (mmu.c:2331)
        ├─ S1TW(stage 1 页表走查) → 注入外部 DABT (mmu.c:2336)
        ├─ cache 维护指令 → 跳过该指令 (mmu.c:2350)
        └─ 其余(典型=访问设备区) → 按 MMIO: io_mem_abort (mmu.c:2363)
              → run->exit_reason = KVM_EXIT_MMIO (mmio.c:257)
              → ioctl 返回, QEMU 模拟该设备读写 → QEMU 填结果 → 再 KVM_RUN
```

> 深入内存虚拟化（影子页表/TLB/巨页）见 [../003.内存虚拟化](../003.内存虚拟化/README.md)；与 035 目录总索引的对应关系见 [../000.系统虚拟化-学习资料索引.md](../000.系统虚拟化-学习资料索引.md)。

## 3. 中断：vgic 两级模型 + LR 硬件投递

```
 物理世界                                  虚拟世界 (guest 看到的)
 ─────────                                ─────────────────────
 设备 ──IRQ──> GIC ──> pCPU               设备(模拟/直通) ──> "虚拟 GIC"
                                              ↑ 两级实现:
                    ┌─────────────────────────┘
                    │ 内核层: vgic 中断模型 (KVM 的"软件 GIC")
                    │   kvm->arch.vgic      (asm/kvm_host.h:330, distributor)
                    │   vcpu->arch.vgic_cpu (asm/kvm_host.h:931, 接口/队列)
                    │   kvm_vgic_flush_hwstate (vgic.c:1125): 把待投递中断
                    │     写入 list registers; kvm_vgic_sync_hwstate (:1061)
                    │     读回 guest 的 EOI/激活状态
                    │ hyp 层: __vgic_v3_restore_state (vgic-v3-sr.c:256)
                    │   msr ICH_LR<n>_EL2 / ICH_VMCR_EL2 / ICH_HCR_EL2
                    ▼
              硬件 GIC 的虚拟接口: pCPU 正在跑 guest 时, LR 里的中断
              由【硬件自动】变成 guest 的 IRQ —— 不需要任何 KVM 代码!
                    │
                    ▼
              guest 收到 vIRQ → guest 内核自己处理, 这一步不发生 exit
              (会发生 IRQ exit 的是宿主物理 IRQ: HCR_EL2.AMO/IMO/FMO
               把它路由到 EL2 → el1_irq → 001 §4.2; 宿主处理完后,
               需要交给 guest 的中断再沿上面的 LR 链路投递)
```

要点：

- **中断投递的"最后一跳"是硬件**（LR 寄存器），KVM 只负责在 VM-entry 前把队列装好——这是 GICv3 虚拟化扩展的核心设计。
- guest 内的 GIC 寄存器访问（`ICC_*`/分发器寄存器）要么直通硬件虚拟接口，要么 trap 后由 vgic 模拟（vgic CPU 接口陷阱，[001 §4.5](001.VM-exit与VM-entry指令全链路.md#45-快速路径在-hyp-里就地消化立刻再进-guest)）。
- 直通设备的中断可走 **GICv4 直接注入**（绕过软件 LR 队列），属 vgic 进阶，待补专篇。

## 4. 定时器：虚拟定时器直跑，物理定时器被陷阱

```
 物理 Generic Timer (每 pCPU 一套):
   CNTP_* (物理)   CNTV_* (虚拟)   CNTVOFF_EL2 (偏移)   CNTHCTL_EL2 (开关)

 KVM 的用法:
 ┌─ 虚拟定时器 vtimer (guest 的 CNTV_*):
 │    允许 guest 直接读 → 不 trap, 零开销
 │    VM 级偏移 voffset (kvm->arch.timer_data.voffset, arm_arch_timer.h:47,
 │     装载时写进 CNTVOFF_EL2; 嵌套虚拟化才另有 per-vCPU 偏移 :1053)
 │    → guest 看到的"纪元起点"被整体平移
 │    到期 → vtimer 中断 → 走 §3 的 vgic 链路注入 vIRQ
 │
 └─ 物理定时器 ptimer (CNTP_CTL/CVAL/TVAL):
      被陷阱: msr cnthctl_el2 清 EL1PCEN — 物理定时器寄存器必 trap
      (nvhe/timer-sr.c:41/:69, 每次 VM-entry, 001 §3.4 #12)
      物理计数器 CNTPCT 反而通常放行直读 (EL1PCTEN 置位),
      除非 VM 配了 poffset / 开 pKVM; EL1TVT/EL1TVCT 仅
      broken-cntvoff erratum 下置位 (timer-sr.c:44-68)
      → guest 访问被陷阱的 CNTP_* → EC=0x18 sysreg trap → KVM 用软件值回答
      (001 §4.1 的"系统寄存器 exit"; vhe/switch.c:261 的 hyp 快速
       路径只服务嵌套虚拟化的 vEL2 读, 普通走宿主内核 sys_regs.c)

 状态归属: vcpu->arch.timer_cpu (asm/kvm_host.h:932); 初始化 kvm_timer_vcpu_init
   (arch_timer.c:1105); 装载 kvm_timer_vcpu_load_gic (arch_timer.c:677)
```

设计直觉：**时间是最不能"trap"的东西**（ trap 一次的开销比读一次定时器还贵），所以把 guest 要频繁读的 CNTV 和纯读的 CNTPCT 放行、把有副作用的 CNTP 定时器寄存器（CTL/CVAL/TVAL）关起来——典型的"按访问频率与副作用分级处理"。

## 5. 设备：三种呈现方式

```
                    guest 想访问"它的磁盘/网卡/串口"
                                 │
        ┌────────────────────────┼─────────────────────────────┐
        ▼                        ▼                             ▼
 ① 纯模拟              ② 半虚拟化 virtio (主流)        ③ 设备直通 (VFIO)
 ─────────             ──────────────────              ──────────────
 guest 的设备完全       guest 驱动 ↔ QEMU 设备模型       真实设备(PCIe) 绑给
 是 QEMU 编出来的      通过 vring 共享内存传数据         guest (VFIO),
 访问其寄存器/缓冲:     (内存映射, 走 §2 的 memslot,      DMA 经 SMMU stage 2
 MMIO abort →          不 trap!)                        (见 019.IOMMU),
 KVM_EXIT_MMIO         前后端(available/used) 翻转       中断走 GICv4 直注
 (mmio.c:257) →        需要通知时: kick 门铃 =           (绕过软件 LR)
 QEMU 模拟后再 KVM_RUN 少量 MMIO trap 或 vhost
                       完成中断: §3 vgic 注入
 数据面: 每次 MMIO     数据面: 0 次 exit(共享内存)       全程硬件直通
 都 1 exit, 控制面也   控制面: 极少量 trap               KVM 几乎不参与
 是 (最慢, 仅低端设备) (性价比最高)                     (性能最好, 配置最复杂)
```

**一次 MMIO exit 的完整往返**（①②的控制面共用）：

```
 guest store → stage 2 无映射(设备区) → EC=0x24 exit
   → kvm_handle_guest_abort (mmu.c:2220) → 非 RAM → KVM_EXIT_MMIO (mmio.c:257)
   → ioctl 返回 QEMU → QEMU 按地址/宽度模拟(如 virtio 门铃: 收到 kick)
   → QEMU 处理完 → 重新 ioctl KVM_RUN → eret 重进 guest (001 §4.7)
```

> virtio 数据面/设备模型的深入（vring 布局、vhost 把数据面下沉内核）见 [../002.IO(设备)虚拟化](../002.IO%28设备%29虚拟化/README.md)；直通与 SMMU 见 [../../000.内存管理/019.IOMMU/000.IOMMU-学习资料索引.md](../../000.内存管理/019.IOMMU/000.IOMMU-学习资料索引.md)。

## 6. 联动：guest 写一次磁盘，四类资源各出一次场

```
 guest 应用 write()
   └> guest 内核 virtio-blk 驱动: 描述符写进 vring        [内存: §2 memslot 共享页]
   └> 敲门铃: virtio-mmio 寄存器 store → MMIO trap        [设备: §5 控制面]
         → KVM_EXIT_MMIO → QEMU 收 kick → 读 vring(直接读宿主内存!)
         → QEMU 把数据写真实磁盘                          [内存: hva→pa 常规页表]
   └> QEMU 完成后: 往 vgic 注入 virtio 中断               [中断: §3]
         → ICH_LR<n>_EL2 → 硬件投递 → guest IRQ
   └> guest 驱动唤醒回调, 完成路径标记 used 环            [内存]
   └> 全程 guest 的 sleep/wait 用 vtimer 计时              [定时器: §4]
   └> 这一切发生在 vcpu0 的某次 KVM_RUN 里                 [CPU: 003]
```

一条 I/O 把五张映射表全部串起来——这也是"虚拟化 = 把每类硬件各自映射一遍"的直观证据。
