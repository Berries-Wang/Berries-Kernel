## 2. 对象模型：fd 树与数据结构

```
 QEMU 进程
  │
  ├─ open("/dev/kvm") ──ioctl KVM_CREATE_VM──> VM fd
  │     └─ struct kvm                    (include/linux/kvm_host.h:770)
  │          └─ memslots ── 内存槽表     (kvm_host.h:753; slot 结构 :593)
  │               由 KVM_SET_USER_MEMORY_REGION 登记 guest GPA↔宿主 HVA
  │
  └─ VM fd ──ioctl KVM_CREATE_VCPU(id)──> vcpu fd ×N
        │   实现: kvm_vm_ioctl_create_vcpu (virt/kvm/kvm_main.c:4152,
        │         create_vcpu_fd :4110 → fd :4235)
        │
        ├─ struct kvm_vcpu              (include/linux/kvm_host.h:325)
        │    └─ arch（arm64 部分）       (arch/arm64/include/asm/kvm_host.h:860)
        │         ├─ ctxt     寄存器现场 (:861, struct kvm_cpu_context :717)
        │         ├─ hw_mmu   stage 2   (:878)
        │         ├─ vgic_cpu 虚拟中断  (:931)
        │         ├─ timer_cpu 虚拟定时器(:932)
        │         ├─ mp_state 上/下电状态(:936, KVM_MP_STATE_* uapi kvm.h:614/619)
        │         └─ pid      绑定的线程 (:964)
        │
        ├─ vcpu fd mmap → struct kvm_run 共享页 (uapi kvm.h:224)
        │    QEMU 与内核各持一份映射; exit_reason 就写在这里, KVM_EXIT_* 时 QEMU 读它
        │
        └─ vcpu fd 被谁执行? → vcpu->pid = 调 KVM_RUN 的线程 (kvm_main.c:4464)
             ⇒ QEMU 给每个 vCPU 起一个线程, 线程循环调 KVM_RUN

 (不属于任何 kvm/vcpu 对象: kvm_hyp_ctxt —— per-CPU 全局量,
  DEFINE_PER_CPU(struct kvm_cpu_context, kvm_hyp_ctxt) (nvhe/switch.c:33),
  存 hyp 自己被 guest 打断时的寄存器现场, 见 001 §1.1/§3.5)
```

## 3. vCPU 是什么：一份"待装载的 CPU 状态"（全在内存里）

**vCPU = `struct kvm_vcpu`，是内存里的一个软件对象**，它保存着一个 CPU 应有的全部状态；只有 KVM_RUN 期间，这份状态才被装进某个物理 CPU 的真寄存器：

```
 物理 CPU(pCPU) 里的东西              vCPU(struct kvm_vcpu) 里的东西
 ─────────────────────              ──────────────────────────────
 x0-x30 / SP                    ←→  vcpu->arch.ctxt.regs[]      (kvm_cpu_context, :717/:861)
 PC / PSTATE                    ←→  ctxt->regs.pc / .pstate
 EL1 系统寄存器组                ←→  系统寄存器缓存（SCTLR/TCR/VBAR_EL1…,
                                    001 §3.4 #4 的装载清单）
 SP_EL1 / ELR_EL1 / SPSR_EL1    ←→  同上
 中断控制器接口状态              ←→  arch.vgic_cpu                (:931)
 定时器状态（CVAL/CTL）          ←→  arch.timer_cpu               (:932)
 MPIDR_EL1 / MIDR_EL1 身份      ←→  虚拟值！经 VMPIDR_EL2/VPIDR_EL2 提供
                                    (sysreg-sr.c:93-94) —— guest 看到的
                                    "我是几号 CPU" 由 VM 配置决定
 是否在运行                     ←→  arch.mp_state                (:936)
```

- **进 guest 前**：hyp 把这份状态 `ldp`/`msr` 装进 pCPU（[001 §3.4](001.VM-exit与VM-entry指令全链路.md#34-铺路进-guest-前-hyp-写的每一个寄存器) 的 14 步）。
- **出 guest 后**：硬件把 PC/PSTATE 留在 ELR_EL2/SPSR_EL2，hyp `stp`/`mrs` 存回 vcpu（[001 §4.4](001.VM-exit与VM-entry指令全链路.md#44-__guest_exit把-guest-状态打包每条指令动什么寄存器)）。
- 所以 pCPU 上的寄存器只是 vCPU 状态的**临时载体**——这正是 vCPU 可以"漂移"的物理基础（§5）。

## 4. vCPU 与物理 CPU 的关系：多对多、时分复用、不绑定

```
        vCPU 线程（QEMU 侧, 普通 Linux 线程）      物理 CPU（硬件）
        ────────────────────────────────         ─────────────
        vcpu0 线程 ─┐                            ┌─ pCPU0: 此刻跑宿主其它任务
        vcpu1 线程 ─┼─── 内核调度器（随时迁移）──> ├─ pCPU1: 此刻"扮演" vcpu0
        vcpu2 线程 ─┘    （可以比 pCPU 数多!）     └─ pCPU2: 此刻"扮演" vcpu1

        关系要点:
        ① vcpu 线程 ≠ pCPU: 它是被调度的普通线程, 会在 pCPU 间漂移
        ② KVM_RUN 期间: 那颗 pCPU 的寄存器被换成该 vCPU 的
           (eret 进 guest; guest 觉得自己独占一颗真 CPU)
        ③ vCPU 数可以 > pCPU 数 (超分 overcommit):
           睡着的 vCPU (WFI/STOPPED) 不占 pCPU — 001 §4.1 的 WFx exit
        ④ vcpu ioctl 约定由同一线程发起 (api.rst:38-40)
```

**pCPU 视角的时间轴**（为什么 pCPU 不会"属于"某个 vCPU）：

```
 pCPU1 时间轴 ────────────────────────────────────────────────────────>
 |宿主任务|  vcpu0 线程 KVM_RUN: guest 段  |exit+处理|  vcpu1 线程: guest 段  |宿主任务|
          └── 此刻 pCPU1 = vcpu0 ──┘                 └── 此刻 pCPU1 = vcpu1 ──┘
          (eret 进/出)                               (同一颗 pCPU 先后扮演两个 vCPU)

 vcpu0 线程睡在 KVM_RUN 里时(如 guest 执行 wfi → kvm_vcpu_wfi), pCPU1 完全空闲,
 调度器可以安排别的线程 —— 这就是超分能工作的原因。
```

**vCPU 漂移**（同一个 vCPU 先后落在不同 pCPU 上）：

```
 时刻 T1: vcpu0 线程被调度到 pCPU2
            ioctl KVM_RUN → vcpu_load (kvm_main.c:164)
              → kvm_arch_vcpu_load (arm.c:650): 把 vCPU 状态装到 pCPU2
            → eret → guest 段 → exit → vcpu_put (kvm_main.c:175 / arm.c:732) 卸下

 时刻 T2: 调度器把 vcpu0 线程迁到 pCPU3
            再次 KVM_RUN → kvm_arch_vcpu_load(cpu=3): 装到 pCPU3
            → eret → guest 段 ...

 关键: hyp 的 per-CPU 数据 (kvm_hyp_ctxt / kvm_hyp_vector / TPIDR_EL2 基址)
       是 pCPU 的财产, 不跟着 vCPU 走;
       vCPU 自己的状态全在内存 (arch.ctxt), 换 pCPU 只是"重新装载"一遍。
       guest 完全感知不到这次迁移。
```

## 5. 流程图：一个 vCPU 的一生

```
 QEMU: open /dev/kvm
   │ ioctl KVM_CREATE_VM (kvm.h:716)
   ▼
 VM fd  ──  struct kvm (kvm_host.h:770); SET_USER_MEMORY_REGION (kvm.h:1266) 登记内存
   │
   │ 对每个 vCPU (×N):
   ├─ ioctl KVM_CREATE_VCPU(id) (kvm.h:1262)
   │    → kvm_vm_ioctl_create_vcpu (kvm_main.c:4152): 分配 kvm_vcpu
   │    → create_vcpu_fd (kvm_main.c:4110) 得到 vcpu fd (:4235)
   │    → QEMU 为这个 vcpu fd 起一个线程 (api.rst:38-40 约定)
   │
   ├─ ioctl KVM_ARM_VCPU_INIT (arm.c:1818 → kvm_arch_vcpu_ioctl_vcpu_init :1688)
        │    设定 vCPU 特性 (PSCI 版本/是否 POWER_OFF/EL1_32BIT/PMU/SVE/PTRAUTH…)
   │
   └─ 线程主循环:
        ┌────────────────────────────────────────────────────────┐
        │ ioctl KVM_RUN (kvm.h:1355, 分发 kvm_main.c:4441)        │
        │   vcpu->pid = 当前线程 (kvm_main.c:4464)                │
        │   vcpu_load (kvm_main.c:164) → kvm_arch_vcpu_load       │
        │     (arm.c:650, 装到当前 pCPU)                          │
        │   ┌──────────────────────────────────────────┐          │
        │   │ 001 §3: activate_traps → __guest_enter    │          │
        │   │         → eret → guest 段                 │          │
        │   │ 001 §4: exit → 快/慢路径 → handle_exit     │          │
        │   └──────────────────────────────────────────┘          │
        │   vcpu_put (kvm_main.c:175 → arm.c:732)                 │
        │   return; QEMU 读 kvm_run->exit_reason:                  │
        │     KVM_EXIT_MMIO → 模拟设备 → 再 KVM_RUN                │
        │     无事/被唤醒 → 再 KVM_RUN …(循环直到 VM 关闭)          │
        └────────────────────────────────────────────────────────┘
```

KVM_RUN 循环**内部**的两条链路（entry/exit）就是 [001](001.VM-exit与VM-entry指令全链路.md) 的全部内容；一次带 PSCI 的具体往返见 [002](002.场景流程图-PSCI-CPU_ON中的hvc与eret.md)。

## 6. FAQ

| 问题 | 答案 |
| - | - |
| vCPU 数能超过 pCPU 数吗？ | 能（超分）。vCPU 是软件对象，睡眠的 vCPU（WFI/STOPPED，mp_state 见 :936）不占 pCPU；代价是 exit 变频繁、尾延迟变大 |
| guest 读 MPIDR 会暴露宿主 CPU 拓扑吗？ | 不会。KVM 经 VMPIDR_EL2/VPIDR_EL2 提供虚拟身份（sysreg-sr.c:93-94），guest 看到的编号由 VM 配置决定 |
| vCPU 会被绑核吗？ | 默认不绑（跟随调度器）；QEMU/virt-manager 可以用 affinity 手工绑，KVM 不强制 |
| 两个 vCPU 能同时在同一颗 pCPU 上跑吗？ | 不能——一颗 pCPU 一个时刻只执行一条指令流；"同时"只是时间片交错（§4 时间轴） |
| vCPU 线程阻塞时 pCPU 在干嘛？ | 跑宿主其它任务。vcpu 线程只是万千线程之一，KVM_RUN 返回后它同样受调度器管辖 |
