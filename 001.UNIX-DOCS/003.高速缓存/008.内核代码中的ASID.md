# 内核代码中的 ASID（arm64 地址空间标识符：分配、切换与 TLB）

> **定位：内核落地篇。** TLB 基础与 ASID/VMID 概念见 [007.TLB](./007.TLB.md)；本篇回答内核侧的三个工程问题：**有限 ASID（256/65536 个）怎么分给任意多的进程、切换路径怎么把 ASID 装进硬件、TLB 怎么按 ASID 定点失效**。屏障语义（切换/失效路径上的 DSB/ISB）见 [../008.同步原语/002.内存屏障](../008.同步原语/002.内存屏障.md)。

## 0. 一句话总结

**ASID 是给 TLB 项打的"进程标签"：同 VA 不同进程互不冲突，切换进程不刷 TLB；硬件只给 8/16 位标签，内核用 64 位 `mm->context.id`（高位 generation + 低位 ASID）把有限标签滚动复用给任意多的进程——滚动（rollover）时保留各核正在用的"保留 ASID"，把全量 TLB 失效延迟到每个 CPU 下一次上下文切换时本地完成。** ASID 装在 `TTBR1_EL1.ASID`（`TCR_EL1.A1=1` 选定），按 ASID 定点失效用 `TLBI ASIDE1`。

## 1. 硬件侧前提：内核要用到的那几条

### 1.1 TLB 项靠什么匹配——ASID 是标签的一部分

A725 TRM §6.3（p58-59）给出匹配条件（与架构 D8.16.3 同构）：

> "A TLB match entry occurs when the following conditions are met:
> • Its **VA[48:N]**, where N is log2 of the block size for that translation that is stored in the TLB entry, matches the requested address.
> • Entry **translation regime** matches the current translation regime.
> • The **ASID matches the current ASID held in the TTBR0_ELx or TTBR1_ELx** register associated with the target translation regime, **or the entry is marked global**.
> • The **Virtual Machine IDentiﬁer (VMID)** matches the current VMID held in the VTTBR_EL2 register."
>
> TLB 命中需同时满足：① 虚拟地址匹配；② 翻译上下文（translation regime）匹配；③ ASID 与 TTBR0_ELx/TTBR1_ELx 中当前 ASID 匹配——**或该项标记为全局**；④ VMID 匹配。

```
   TLB 项 (per-entry)                         查找时"当前"上下文
 ┌─────────────────────────┐
 │ VA[48:N]  ─────────────┼──► 与请求地址比较
 │ regime    ─────────────┼──► 与当前 EL1&0 等翻译上下文比较
 │ ASID      ─────────────┼──► 与 TTBR1_EL1.ASID 比较 ──┐
 │ global 位 ──(为1 则跳过 ASID 比较)                    │ 同一 VA、不同 ASID
 │ VMID      ─────────────┼──► 与 VTTBR_EL2.VMID 比较   │ = 两条独立 TLB 项
 │ PA + 属性（内存类型/权限） │                          │ ⇒ 进程切换免刷 TLB
 └─────────────────────────┘
```

注意 **全局位**：内核映射（TTBR1 恒等映射）是全局项，不参与 ASID 匹配——这解释了 §5 里 `TLBI ASIDE1` 为什么"只失效非全局项"（C5-1206：*"is a non-global entry from the final level of lookup"*）。

### 1.2 标签有多少个：ID_AA64MMFR0_EL1.ASIDBits

> "ASIDBits, bits [7:4]: **0b0000** → 8 bits. **0b0010** → 16 bits. All other values are reserved."（D24-9132）

内核探测（[context.c:42](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/mm/context.c) `get_cpu_asid_bits`）与此一一对应，内核自己的寄存器描述同样只认这两个值（[sysreg:2157](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/tools/sysreg)）；次级 CPU 位宽小于 boot CPU 直接 panic（context.c:64-77 `verify_cpu_asid_bits`——ASID 位宽是 SYSTEM 级约定，不能各行其是）。

### 1.3 标签装在哪：TTBR1_EL1.ASID（TCR_EL1.A1=1）

> TTBR1_EL1 "ASID, bits [63:48]: An ASID for the translation table base address. **The TCR_EL1.A1 field selects either TTBR0_EL1.ASID or TTBR1_EL1.ASID.** If the implementation has only 8 bits of ASID, then the upper 8 bits of this field are RES0."（D24-9932）

内核在 `__cpu_setup` 里固定置 A1=1（[proc.S:503](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/mm/proc.S)），从此**当前 ASID 随 TTBR1_EL1 携带**——好处：切进程只动 TTBR0（用户页表基址），ASID 可以和内核页表基址一起待在 TTBR1 里统一换写（§4.3）。

### 1.4 按 ASID 定点失效：TLBI ASIDE1

> "TLBI ASIDE1: Invalidates cached copies of translation table entries from TLBs that meet all the following requirements:
> • The entry is a **stage 1** translation table entry.
> • The entry **would be used for the specified ASID**, and either:
>   • Is from a level of lookup above the final level.
>   • **Is a non-global entry** from the final level of lookup."（C5-1206）

即"废掉某个进程的全部非全局翻译"用一条 `TLBI ASIDE1IS <asid>`（IS=Inner-Shareable 广播到所有核）就够——不用按地址逐项刷，更不用 `vmalle1` 全刷。内核包装见 §5。

## 2. mm->context.id：一个 64 位字段装"标签 + 代"

每个 `mm_struct`（一个进程地址空间）持有：

```c
// arch/arm64/include/asm/mmu.h:19
typedef struct {
	atomic64_t	id;
#ifdef CONFIG_COMPAT
	void		*sigpage;
#endif
	refcount_t	pinned;
	void		*vdso;
	unsigned long	flags;
	u8		pkey_allocation_map;
} mm_context_t;
```

`id` 就是内核视角的"ASID"，但它是 **generation（代）+ ASID（标签）** 的 64 位组合（原表保留、扩充为四行）：

| `mm->context.id` 的组成 | 意义 | 说明 |
| - | - | - |
| 低 `asid_bits` 位 = **ASID** | 写进 TTBR1_EL1.ASID 的硬件标签 | 8 位（256 个）或 16 位（65536 个），由 `ID_AA64MMFR0_EL1.ASIDBits` 决定；**0 号保留给 init_mm/reserved**（ASID #0，context.c:194 注释） |
| 高位 = **generation（代）** | 内核侧逻辑版本号 | 硬件不知道它存在——它只用来让软件判断"我这个 ASID 是不是当前代的"；标签耗尽时代号 +1、标签回收重分（§3） |
| bit 48 = **USER_ASID_FLAG** | KPTI 用户半标签 | 不在 id 里，是 TLBI 参数编码的标志位（mmu.h:11-12，§7） |

```c
// arch/arm64/mm/context.c:34
#define ASID_MASK		(~GENMASK(asid_bits - 1, 0))   // 高位 = generation 部分
#define ASID_FIRST_VERSION	(1UL << 16)                   // 代的步长 = 2^16

#define NUM_USER_ASIDS		(1UL << asid_bits)
#define ctxid2asid(asid)	((asid) & ~ASID_MASK)         // 取低 asid_bits 位
#define asid2ctxid(asid, genid)	((asid) | (genid))             // 拼 id
```

```
        mm->context.id（64 位）
 63                                                  48            asid_bits   0
┌────────────────────────────────┬─────────┬──────────────────────┬────────────┐
│        generation（软件维护的代）  │ (未用)   │      ASID 硬件标签     │  …见 §3    │
└────────────────────────────────┴─────────┴──────────────────────┴────────────┘
  ▲ asid_gen_match(): 高位与全局 asid_generation 相同 ⇒ "还是当前代"
                                    ASID(mm) = id & 0xffff（mmu.h:56）只取低 16 位
```

**`ASID_FIRST_VERSION = 1<<16` 的巧思**：代以 2^16 为步长递增，于是在 8 位 ASID 的机器上，"代"永远对齐到 16 位边界——低 16 位装得下任何合法 ASID，代与标签在位域上**永不重叠**，`asid_gen_match`（context.c:101）只需一次异或加移位。

读侧宏：

```c
// arch/arm64/include/asm/mmu.h:56
#define ASID(mm)	(atomic64_read(&(mm)->context.id) & 0xffff)
```

（`& 0xffff` 而非 `& ((1<<asid_bits)-1)`：ASID 位宽 ≤16，多掩掉的高位本来就是 0。）

## 3. 分配算法：new_context 与 generation 滚动

### 3.1 全局账本

```c
// arch/arm64/mm/context.c:20
static u32 asid_bits;
static DEFINE_RAW_SPINLOCK(cpu_asid_lock);     // 分配全局锁

static atomic64_t asid_generation;             // 当前代（高 16 位有效）
static unsigned long *asid_map;                // 位图：哪个标签已发出

static DEFINE_PER_CPU(atomic64_t, active_asids);    // 每核正在跑的 context.id
static DEFINE_PER_CPU(u64, reserved_asids);         // 滚动时每核的"保留标签"
static cpumask_t tlb_flush_pending;                 // 每核待刷标志（懒 TLB 刷）
```

设计约束：**标签数（≥256）远大于 CPU 数**，且账本更新全部集中在 `cpu_asid_lock` 临界区内（§4 的快路径除外）。

### 3.2 new_context：四条出路

```c
// arch/arm64/mm/context.c:158（节选主干，注释为源码原文）
static u64 new_context(struct mm_struct *mm)
{
	static u32 cur_idx = 1;
	u64 asid = atomic64_read(&mm->context.id);
	u64 generation = atomic64_read(&asid_generation);

	if (asid != 0) {
		u64 newasid = asid2ctxid(ctxid2asid(asid), generation);

		/*
		 * If our current ASID was active during a rollover, we
		 * can continue to use it and this was just a false alarm.
		 */
		if (check_update_reserved_asid(asid, newasid))   // 出路①：保留续期
			return newasid;

		/*
		 * If it is pinned, we can keep using it. ...
		 */
		if (refcount_read(&mm->context.pinned))          // 出路②：pin 续期
			return newasid;

		/*
		 * We had a valid ASID in a previous life, so try to re-use
		 * it if possible.
		 */
		if (!__test_and_set_bit(ctxid2asid(asid), asid_map))  // 出路③：复用旧号
			return newasid;
	}

	/*
	 * Allocate a free ASID. ... We always count from ASID #2 (index 1),
	 * as we use ASID #0 when setting a reserved TTBR0 for the init_mm
	 * and we allocate ASIDs in even/odd pairs.（§7 的 KPTI 配对）
	 */
	asid = find_next_zero_bit(asid_map, NUM_USER_ASIDS, cur_idx);   // 出路④
	if (asid != NUM_USER_ASIDS)
		goto set_asid;

	/* We're out of ASIDs, so increment the global generation count */
	generation = atomic64_add_return_relaxed(ASID_FIRST_VERSION,
						 &asid_generation);          // 出路⑤：滚动
	flush_context();

	/* We have more ASIDs than CPUs, so this will always succeed */
	asid = find_next_zero_bit(asid_map, NUM_USER_ASIDS, 1);

set_asid:
	__set_bit(asid, asid_map);
	cur_idx = asid;
	return asid2ctxid(asid, generation);
}
```

决策树：

```
mm 需要 ASID（慢路径进入 new_context）
 │
 ├─ id≠0 且仍属当前代？── 否，继续 ↓
 ├─ ① 旧标签在 reserved_asids 里（滚动时正被别的核跑）
 │      ⇒ 原标签续到新一代（check_update_reserved_asid 同步改账本）
 ├─ ② mm 被 pin（refcount≠0）⇒ 原标签续代
 ├─ ③ 旧标签号当前空闲 ⇒ 重新占坑，沿用
 ├─ ④ 位图找 0（从上次分配处环形扫描）⇒ 新标签
 └─ ⑤ 全满 ⇒ GENERATION += 2^16（标签全体作废）
        flush_context()：重建位图 + 保留每核活跃标签 + 置全核 tlb_flush_pending
        再找空位 ⇒ 必成功（"We have more ASIDs than CPUs"）
```

### 3.3 flush_context：滚动时保住"正在跑的"，刷 TLB 却是懒的

```c
// arch/arm64/mm/context.c:104（节选）
static void flush_context(void)
{
	int i;
	u64 asid;

	/* Update the list of reserved ASIDs and the ASID bitmap. */
	set_reserved_asid_bits();

	for_each_possible_cpu(i) {
		asid = atomic64_xchg_relaxed(&per_cpu(active_asids, i), 0);
		/*
		 * If this CPU has already been through a
		 * rollover, but hasn't run another task in the
		 * meantime, we must preserve its reserved
		 * ASID, as this is the only trace we have of
		 * the process it is still running.
		 */
		if (asid == 0)
			asid = per_cpu(reserved_asids, i);
		__set_bit(ctxid2asid(asid), asid_map);
		per_cpu(reserved_asids, i) = asid;
	}

	/* Queue a TLB invalidation for each CPU to perform on next context-switch */
	cpumask_setall(&tlb_flush_pending);
}
```

两个关键动作：

1. **保留（reserved）**：每个 CPU 正在使用的 ASID 被记进 `reserved_asids` 并在新位图里重新占坑——这些 mm 的旧标签在滚动后**原号续代**（§3.2 出路①），TLB 里残留的旧翻译仍然有效且正确（同一个 mm！）；
2. **懒刷（lazy flush）**：滚动要求"旧代标签的 TLB 项全部作废"，但内核**不在此处广播 TLBI**，只把 `tlb_flush_pending` 全置 1——每个 CPU 在**下一次上下文切换进入慢路径时**自己执行 `local_flush_tlb_all()`（§4.2）。窗口期内旧代项不会被误用：切换路径会先对账（代不匹配→换新标签）。

```
滚动时间线（懒刷示意）
──────────────────────────────────────────────────────────────────
CPU0（触发滚动的核）                     CPU1（正在跑进程 B）
new_context(): 满
  generation += 2^16
  flush_context():
    位图重建（保留 CPU0/CPU1 活跃标签）
    tlb_flush_pending = 全核置位
                                          （继续跑 B，TLB 里 B 的旧代项照用——
                                            B 的标签被 reserved，语义没变）
CPU0 下次切换进慢路径:
  tlb_flush_pending[0] 命中
  → local_flush_tlb_all()（vmalle1，本核）   CPU1 下次切换进慢路径:
                                            同样本核 vmalle1
```

### 3.4 容量与不变量

```c
// arch/arm64/mm/context.c:387（节选，注释为源码原文）
	WARN_ON(num_available_asids - 1 <= num_possible_cpus());
```

## 4. 切换路径：switch_mm → check_and_switch_context → TTBR

### 4.1 调用链总览

```
调度器 context_switch
 └─ switch_mm(prev, next, tsk)                 mmu_context.h:251
     ├─ prev != next ? __switch_mm(next)       :236
     │    ├─ next == init_mm ? cpu_set_reserved_ttbr0(); return   :242
     │    └─ check_and_switch_context(next)    context.c:215   ← 本篇主角
     └─ update_saved_ttbr0(tsk, next)          :202（仅 SW-PAN，存 thread_info->ttbr0）
```

### 4.2 check_and_switch_context：一条 cmpxchg 的快路径 + 慢路径

```c
// arch/arm64/mm/context.c:215（节选）
void check_and_switch_context(struct mm_struct *mm)
{
	unsigned long flags;
	unsigned int cpu;
	u64 asid, old_active_asid;

	if (system_supports_cnp())
		cpu_set_reserved_ttbr0();          // CNP 下先摘掉旧 TTBR0

	asid = atomic64_read(&mm->context.id);

	/*
	 * The memory ordering here is subtle.
	 * If our active_asids is non-zero and the ASID matches the current
	 * generation, then we update the active_asids entry with a relaxed
	 * cmpxchg. Racing with a concurrent rollover means that either:
	 *
	 * - We get a zero back from the cmpxchg and end up waiting on the
	 *   lock. Taking the lock synchronises with the rollover and so
	 *   we are forced to see the updated generation.
	 *
	 * - We get a valid ASID back from the cmpxchg, which means the
	 *   relaxed xchg in flush_context will treat us as reserved
	 *   because atomic RmWs are totally ordered for a given location.
	 */
	old_active_asid = atomic64_read(this_cpu_ptr(&active_asids));
	if (old_active_asid && asid_gen_match(asid) &&
	    atomic64_cmpxchg_relaxed(this_cpu_ptr(&active_asids),
				     old_active_asid, asid))
		goto switch_mm_fastpath;           // ← 快路径：一次 CAS 完事

	raw_spin_lock_irqsave(&cpu_asid_lock, flags);
	/* Check that our ASID belongs to the current generation. */
	asid = atomic64_read(&mm->context.id);
	if (!asid_gen_match(asid)) {
		asid = new_context(mm);            // ← §3 的分配
		atomic64_set(&mm->context.id, asid);
	}

	cpu = smp_processor_id();
	if (cpumask_test_and_clear_cpu(cpu, &tlb_flush_pending))
		local_flush_tlb_all();             // ← §3.3 的懒刷在此兑现

	atomic64_set(this_cpu_ptr(&active_asids), asid);
	raw_spin_unlock_irqrestore(&cpu_asid_lock, flags);

switch_mm_fastpath:
	arm64_apply_bp_hardening();
	/* SW-PAN 模拟时，TTBR0 装载推迟到 uaccess_enable() */
	if (!system_uses_ttbr0_pan())
		cpu_switch_mm(mm->pgd, mm);        // → cpu_do_switch_mm
}
```

快路径为什么成立：**同核连续切换、代又没滚**，`active_asids` 就一个 CAS 换掉——无锁、无 TLB 失效、无系统寄存器以外的账本操作。与滚动方（`flush_context` 的 `atomic64_xchg_relaxed`）的竞态被"**同一位置的原子 RMW 全序**"封死（注释原文；原子语义详见 [../008.同步原语/001.原子指令](../008.同步原语/001.原子指令/README.md)，屏障见 [../008.同步原语/002.内存屏障](../008.同步原语/002.内存屏障.md)）。

慢路径的四件事：**对账（代不匹配→重新分配）→ 兑现懒刷 → 登记本核活跃 ASID → 装载页表**。

### 4.3 cpu_do_switch_mm：真正写硬件的三步

```c
// arch/arm64/mm/context.c:349
void cpu_do_switch_mm(phys_addr_t pgd_phys, struct mm_struct *mm)
{
	unsigned long ttbr1 = read_sysreg(ttbr1_el1);
	unsigned long asid = ASID(mm);
	unsigned long ttbr0 = phys_to_ttbr(pgd_phys);

	/* Skip CNP for the reserved ASID */
	if (system_supports_cnp() && asid)
		ttbr0 |= TTBRx_EL1_CnP;

	/* SW PAN needs a copy of the ASID in TTBR0 for entry */
	if (IS_ENABLED(CONFIG_ARM64_SW_TTBR0_PAN))
		ttbr0 |= FIELD_PREP(TTBRx_EL1_ASID_MASK, asid);

	/* Set ASID in TTBR1 since TCR.A1 is set */
	ttbr1 &= ~TTBRx_EL1_ASID_MASK;
	ttbr1 |= FIELD_PREP(TTBRx_EL1_ASID_MASK, asid);

	cpu_set_reserved_ttbr0_nosync();
	write_sysreg(ttbr1, ttbr1_el1);       // ① 换 ASID（随 TTBR1）
	write_sysreg(ttbr0, ttbr0_el1);       // ② 换用户页表基址
	isb();                                // ③ 上下文同步（取指侧生效）
	post_ttbr_update_workaround();
}
```

三步的讲究：

1. **先摘后换**：`cpu_set_reserved_ttbr0_nosync()` 先把 TTBR0 指到保留空表（mmu_context.h:44-48），避免换表瞬间用"新 TTBR0 + 旧中间态"继续翻译；
2. **ASID 走 TTBR1**（TCR.A1=1，§1.3）——ASID 与内核页表基址同宿主，一次写清；SW-PAN 模拟时在 TTBR0 里再抄一份 ASID（[mmu_context.h:202](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/mmu_context.h) `update_saved_ttbr0` 存进 `thread_info`）；
3. **`isb()` 收尾**：TTBR 写完到取指生效之间需要上下文同步（[../008.同步原语/002.内存屏障 §6.3](../008.同步原语/002.内存屏障.md) 的 ISB 实例就是它）；Cavium 27456 erratum 再补 `ic iallu; dsb nsh; isb`（context.c:339-347）。

**CNP（FEAT_TTCNP）**：`TTBRx_EL1.CnP=1` 声明"本表在核间可共享"——同簇各核跑同一 mm 时 TLB 项可以共享（A725 位于同一 DSU-120 簇内），因此路径开头还要 `cpu_set_reserved_ttbr0()` 把旧共享状态摘干净。

### 4.4 一个不得不防的三核竞态（源码注释原文）

`ASID(mm)` 为什么必须用 `atomic64_read`？[mmu.h:30](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/mmu.h) 的注释画了完整时间线：

```
   CPU 0                     CPU 1                          CPU 2

   // ptep_clear_flush(mm)
   xchg_relaxed(pte, 0)
   DSB ISHST
   old = ASID(mm)
        |                                                  <rollover>
        |                   new = new_context(mm)
        \-----------------> atomic_set(mm->context.id, new)
                            cpu_switch_mm(mm)
                            // Hardware walk of pte using new ASID
   TLBI(old)
```

> "In this scenario, the barrier on CPU 0 and the dependency on CPU 1 ensure that the page-table walker on CPU 1 *must* see the invalid PTE written by CPU 0."
>
> CPU0 拿着旧 ASID 去发 TLBI 时，mm 可能恰好被滚到新 ASID——没关系：CPU0 的 DSB ISHST + CPU1 对 `mm->context.id` 的依赖链保证 CPU1 的硬件页表遍历**必然看到 CPU0 已写坏的 PTE**（新 ASID 是"干净"的，走表必然重新填充）。（DSB ISHST 的语义见 [../008.同步原语/002.内存屏障 §2](../008.同步原语/002.内存屏障.md)。）

## 5. 失效侧：按 ASID 定点刷 TLB

### 5.1 flush_tlb_mm：一条 aside1is + KPTI 第二发

```c
// arch/arm64/include/asm/tlbflush.h:408
static inline void flush_tlb_mm(struct mm_struct *mm)
{
	unsigned long asid;

	dsb(ishst);
	asid = __TLBI_VADDR(0, ASID(mm));
	__tlbi(aside1is, asid);          // 广播：按 ASID 失效该 mm 全部非全局项
	__tlbi_user(aside1is, asid);     // KPTI: 再按 用户ASID（bit48）来一发
	__tlbi_sync_s1ish(mm);
	mmu_notifier_arch_invalidate_secondary_tlbs(mm, 0, -UL(-1));
}
```

TLBI 操作数的编码（`__TLBI_VADDR`，tlbflush.h:50-57）：

```
  TLBI ASIDE1IS 的操作数寄存器（Xt）
 63              48 47                              12 11        0
┌──────────────────┬─────────────────────────────────┬───────────┐
│   ASID[15:0]     │           （未用/保留）           │  （未用）  │
└──────────────────┴─────────────────────────────────┴───────────┘
        ▲ __TLBI_VADDR: asid << 48；KPTI 时 __tlbi_user 再 | (1<<48)
          —— USER_ASID_FLAG（mmu.h:11-12）指向"配对中的用户半"
```

### 5.2 三种"刷法"的分工

| 场景 | 调用 | 指令 | 范围 |
| - | - | - | - |
| 某进程按地址范围失效（rmap、munmap 等） | `__flush_tlb_range`（tlbflush.h:365 起） | `tlbi vale1is` 等（VA+ASID） | 单 ASID 的非全局项 |
| 某进程整个地址空间作废 | `flush_tlb_mm`（tlbflush.h:408） | `tlbi aside1is` | 单 ASID（非全局项） |
| generation 滚动的懒刷 | `local_flush_tlb_all`（tlbflush.h:392） | `tlbi vmalle1` | **本核**全部 EL1&0 项 |
| 修改内核映射等全局变更 | `flush_tlb_all`（tlbflush.h:400） | `tlbi vmalle1is` | **广播**全部 |

（按地址范围批量失效另有 FEAT_TLBIRANGE 的 `rval...` 族，tlbflush.h:454 起——操作数同样带 ASID[63:48]。）

## 6. A725 微架构视角：标签匹配发生在哪几级

A725 的 TLB 层级（TRM 表 6-1，p57）：

```
 取指侧                        数据侧
 ┌──────────────┐             ┌──────────────┐
 │ L1 iTLB       │             │ L1 dTLB       │   全相联
 │ 32 项(4K-2M) │             │ 48 项(4K-2M)  │   ← 命中：VA+regime+ASID(+VMID)
 └──────┬───────┘             └──────┬───────┘      四条件匹配（§1.1）
        └──────────┬────────────────┘
                   ▼
        ┌─────────────────────────────┐
        │ L2 TLB（MMU 块，统一）        │
        │  small page TLB: 1536 项×6路 │  ← L3 级翻译结果(4K/16K/64K)
        │   （缩面积配置 1024×4 路）    │
        │  medium page TLB: 256 项×4路 │  ← L2 级(2M/32M/512M)
        │  + walk cache（存中间级）     │
        └──────────────┬──────────────┘
                       ▼ miss → 页表遍历（TRM §6.4, p59）
```

TRM §6.2（p58）确认每项都带标签：

> "Each TLB entry contains:
> • A Virtual Address (VA)
> • A Physical Address (PA)
> • A set of memory properties that includes type and access permissions
> Each TLB entry is associated with either:
> • **A particular Address Space IDentiﬁer (ASID)**
> • **A global indicator**
> Each TLB entry also contains a ﬁeld to store the **Virtual Machine Identiﬁer (VMID)** in the entry applicable to accesses from EL0 and EL1. ..."
>
> 每个 TLB 项除 VA/PA/属性外，要么关联某个 ASID、要么标记全局；另有 VMID 字段（供 EL0/EL1 访问的项）。

由此能直观理解内核策略的收益：多进程热数据驻留在 48+1536 项的 dTLB/L2 TLB 里互不打架（ASID 分离），`switch_mm` 快路径只是两条系统寄存器写 + ISB——**TLB 全程无刷**。容量对照：16 位 ASID（65536 个标签）≫ L2 TLB 项数，所以 generation 滚动是罕见事件；8 位 ASID（256 个）在现代桌面上也够（同时活跃的 mm 远少于 256），服务器大进程数场景才偶发滚动。

## 7. 两个进阶话题

### 7.1 KPTI：ASID 按"偶/奇"配对一半给用户

KPTI（内核页表隔离）下用户/内核各用一套页表，内核给每个 mm 分配**一对** ASID：偶数给内核侧、`偶数|1`（底位置一）只映用户侧。位图预占所有奇数标签实现"只发偶数"：

```c
// arch/arm64/mm/context.c:79（节选）
	/*
	 * In case of KPTI kernel/user ASIDs are allocated in
	 * pairs, the bottom bit distinguishes the two: if it
	 * is set, then the ASID will map only userspace. Thus
	 * mark even as reserved for kernel.
	 */
	memset(map, 0xaa, len);        // 0xaa = 1010...：奇数位全置 1（占用）
```

于是容量折半（§3.4 的 32768），TLBI 也要两发：`aside1is`（内核半）+ `__tlbi_user`（用户半，bit48 标志，§5.1）。pinned 接口对外返回的 ASID 同样补用户位：`if (asid && arm64_kernel_unmapped_at_el0()) asid |= 1`（context.c:311-313）。

### 7.2 pinned ASID：把标签钉住不让滚走（KVM 用）

7.1.3 新增 `arm64_mm_context_get/put`（context.c:273-336，导出给模块）：把 mm 的 ASID 钉进 `pinned_asid_map`，滚动后**原号续代**（§3.2 出路②）——供 KVM 等需要"硬件上长期固定 ASID"的场合（如 guest 的 stage-1 直通场景）。上限 `max_pinned_asids = 总量 - CPU 数 - 2` 保证滚动永远能找到空位（§3.4）。

### 7.3 CONTEXTIDR_EL1 ≠ ASID

`CONTEXTIDR_EL1`（进程号寄存器）只是调试/追踪标签（ETM 按它过滤 trace），**不参与 TLB 匹配**。内核仅在 `CONFIG_PID_IN_CONTEXTIDR` 时把 task PID 写进去方便硬件 trace 关联进程（mmu_context.h:31-38 `contextidr_thread_switch`）。真正参与匹配的是 TTBR1_EL1.ASID（§1.1/§1.3）。

## 9. 常见误区

1. **"16 位 ASID = 系统最多同时跑 65536 个进程"**（[007.TLB](./007.TLB.md) 中"溢出会重新分配"的精确化）——标签数只是**同一代**的容量；generation 滚动让任意数量的进程依次复用标签（§3）。真正受限的是"同一代内活跃 mm 数 + 各核保留 + pin"。
2. **"切换进程要刷 TLB / 换 ASID 硬件会自动失效旧项"**——都不需要：ASID 不同则不命中（§1.1），切换只是换 TTBR（§4.3）；硬件**不监视** TTBR 写入去清 TLB，失效只由 TLBI 显式发起。
3. **"滚动（rollover）当场全系统广播刷 TLB"**——不：懒刷，各核拖到下一次上下文切换慢路径本地 `vmalle1`（§3.3/§4.2）。
4. **"`TLBI ASIDE1` 会把该进程所有项都刷掉"**——只刷**非全局**项；全局项（内核映射）不关联 ASID、不受影响（§1.1/C5-1206）。
5. **"ASID 存在 CONTEXTIDR_EL1"**——参与 TLB 匹配的 ASID 在 `TTBR1_EL1.ASID[63:48]`；CONTEXTIDR 只是 trace 标签（§7.3）。
6. **"ASID 0 也是可分配的"**——0 号保留给 init_mm/reserved 空表，分配从 1 开始（context.c:194/§3.2 注释）。
