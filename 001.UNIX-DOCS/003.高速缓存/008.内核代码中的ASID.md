# 内核代码中的ASID
> 学习: <br/> [switch_mm -> check_and_switch_context函数](../../000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9/arch/arm64/mm/context.c)

## 内核代码中的ASID
```c

asid = atomic64_read(&mm->context.id);

typedef struct {
	atomic64_t	id;
#ifdef CONFIG_COMPAT
	void		*sigpage;
#endif
	void		*vdso;
	unsigned long	flags;
} mm_context_t;

```

### mm->context.id 解析
|意义|说明|备注|
|-|-|-|
|ASID (Address Space Identifier) |- ARM64 的 TLB（Translation Lookaside Buffer，页表缓存）需要缓存多个进程的页表项。为了在进程切换时不强制清空 TLB（这会严重降低性能），硬件引入了 ASID <br/> - TLB 表项不仅匹配虚拟地址，还匹配 ASID。如果 ASID 不匹配，即使虚拟地址相同，也会视为 TLB 未命中 <br/> - ARM64 支持 8位(255个进程) 或 16位(支持 65535 个进程) 的 ASID 长度|
|-|-|-|
|- Current Generation (全局 ASID 版本号)|- 当系统运行的进程数量超过硬件 ASID 的容量（例如超过 255 个）时，ASID 就会发生冲突（两个进程拿到了相同的 ASID <br/> - 内核引入了“版本号”机制（Generation）。内核维护一个全局的 asid_generation 变量 <br/> - ASID 的分配是按“代”进行的。当 ASID 耗尽时，全局版本号加 1，ASID 重新从 1 开始分配。虽然硬件 ASID 重复了，但版本号不同，因此逻辑上仍然是唯一的。|-|
|-|-|-|
