# 从 _start 到 main：用户态的接力

> **定位**：系列的用户态半程——`eret` 落在 `e_entry`（即 `_start`）之后、`main` 执行之前，glibc 替我们跑的那段"起跑器"代码。glibc 2.40 源码 [000.SOURCE_CODE/002.GLIBC/000.GLIBC-2.40](../../../000.SOURCE_CODE/002.GLIBC/000.GLIBC-2.40) `file:line` 实测；内核如何铺栈、为何 `_start` 是入口，见 [001.execve与ELF加载](./001.execve与ELF加载：内核侧.md)。

## 0. 一句话总结

**`_start` 不是 `main`**：它是链接器从 crt1.o 里选出的入口（ELF `e_entry`），负责按 ABI 从栈上取出 `argc/argv/envp`、把 `main` 的地址装进寄存器，交给 glibc 的 `__libc_start_main`——后者做完 TLS/初始化等杂务后调用 `main`，再用 `main` 的返回值调 `exit`。**你写 `main` 之前，运行时已经跑了几十行。**

## 1. 入口时刻的现场：寄存器与栈

ABI 约定（[glibc sysdeps/aarch64/start.S:38 起的注释](../../../000.SOURCE_CODE/002.GLIBC/000.GLIBC-2.40/sysdeps/aarch64/start.S)原文）——入口时刻：

- `x0`：动态链接器传来的**析构回调**（`rtld_fini`，登记进 `atexit`，保证共享库退出清理；静态链接时没有 ld.so，`x0` 就是内核 execve 时清的 0）；
- `sp`：指向内核铺好的启动栈（[001 §2](./001.execve与ELF加载：内核侧.md) 的 `create_elf_tables`）；
- 其余 GPR 未指定（内核侧已全清零，见 `start_thread_common`，processor.h:309）。

栈布局（`0(sp)` 起，每格 8 字节）：

```
 sp ──►│ argc           │
       │ argv[0]        │ "./a.out"
       │ argv[1..n-1]   │ ...
       │ NULL           │ ◄─ argv 数组结束哨兵
       │ envp[0]        │ "PATH=..."
       │ envp[...]      │
       │ NULL           │ ◄─ envp 结束哨兵
       │ auxv[0].type   │ AT_PHDR      ┐
       │ auxv[0].val    │ ...          │ (type,val) 对,
       │ auxv[...]      │              │ 以 AT_NULL 结尾;
       │ ...            │ AT_ENTRY/    │ ld.so 与 glibc 的
       │                │ AT_BASE/     │ "交接清单"
       │                │ AT_RANDOM... ┘
       │ argv/envp 字符串本体(压在更上面) │
```

## 2. _start 逐行走读（glibc aarch64）

```asm
; sysdeps/aarch64/start.S:63（节选；省略 cfi_* 调试伪指令，空白有压缩，行尾 ; 为笔者注）
ENTRY(_start)
	/* Create an initial frame with 0 LR and FP */
	mov	x29, #0            ; 帧指针清零:第一帧,回溯到此为止
	mov	x30, #0            ; 链接寄存器清零:返回地址无效

	/* Setup rtld_fini in argument register */
	mov	x5, x0             ; x0=rtld_fini(动态链接由 ld.so 装入,静态=0)→存 x5

	/* Load argc and a pointer to argv */
	ldr	PTR_REG (1), [sp, #0]   ; x1 = argc  (PTR_REG(1)=x1, LP64)
	add	x2, sp, #PTR_SIZE   ; x2 = &argv[0]  (PTR_SIZE=8)

	/* Setup stack limit in argument register */
	mov	x6, sp             ; x6 = 栈顶(第7个参数,栈尾标识)

#ifdef PIC
# ifdef SHARED
	adrp	x0, :got:main          ; 动态链接:main 地址在 GOT 里!
	ldr	PTR_REG (0), [x0, #:got_lo12:main]  ; 从 GOT 表项取出真地址
# else
	adrp	x0, __wrap_main        ; static-pie 的包装
	add	x0, x0, :lo12:__wrap_main
# endif
#else
	MOVL	(0, main)              ; 静态链接:movz/movk 直接装立即数
#endif
	mov	x3, #0              /* Used to be init.  */
	mov	x4, #0              /* Used to be fini.  */

	/* __libc_start_main (main, argc, argv, init, fini, rtld_fini,
			      stack_end) */
	bl	__libc_start_main   ; start.S:98 ◄─ 一去不回头的调用

	/* should never get here....*/
	bl	abort
END(_start)
```

三个看点：

1. **`adrp x0, :got:main`**：动态链接下，`_start` 连 `main` 的地址都不能直接 `adrp+add`（可执行文件自身也可能被 ASLR / 交叉引用），要**走 GOT 拿**——`:got:` 重定位修饰符对应 [028.编译原理/000.链接器](../../028.编译原理/000.链接器/README.md) §4 的 `R_AARCH64_ADR_GOT_PAGE`，指令编码见 [001.ADRP](../../../008.COMPUTER_SCIENCE/001.汇编指令/000.arm64汇编指令/001.ADRP.md)；
2. **7 个参数准备**（x0~x6）：`main`、`argc`、`argv`、`init`（已废弃=0）、`fini`（已废弃=0）、`rtld_fini`、`stack_end`——aarch64 前 8 个参数走寄存器 x0~x7，第 7 个之后才进栈；
3. `init/fini` 置 0：老 ABI 的全局构造/析构登记已由 `__libc_csu_init` 时代改为 `__libc_start_main` 内部经 `__libc_init_array`/`__cxa_atexit` 处理（gcc 的 crtbegin/crtend 段驱动），这两个槽位是历史兼容。

## 3. __libc_start_main：起跑器的最后一棒

[csu/libc-start.c](../../../000.SOURCE_CODE/002.GLIBC/000.GLIBC-2.40/csu/libc-start.c)（实现名 `__libc_start_main_impl`，:101 处定义别名导出）。大事记（顺序简化）：

```
 __libc_start_main(main, argc, argv, init, fini, rtld_fini, stack_end)
   ├─ 若 rtld_fini 非空 → __cxa_atexit(rtld_fini)     共享库析构登记
   ├─ __libc_init_secure(): 记录 uid/euid 分歧(安全模式)
   ├─ __libc_setup_tls():   建立 TLS(线程局部存储)块     ← 可执行文件静态 TLS
   ├─ __libc_init_first / _dl_relocate_static_pie(静态pie)
   ├─ __libc_init_array():  逐个调用 .init_array 里的构造器
   │        (C++ 全局对象构造函数就藏在 .init_array 段!)
   ├─ result = main(argc, argv, envp)                    ← 你的代码
   └─ exit(result)                                       ← 一去不回
        └─ 运行 atexit/析构链 ─► _exit()/syscall exit_group ─► 内核 do_exit
```

所以完整的"程序生命周期"接力图：

```
 [内核侧]                                     [用户态]                    [内核侧]
 execve ─► load_elf_binary ─► eret ─► [ld.so(若有)] ─► _start ─► __libc_start_main ─► main(...)
            (装载,见 001)      │        重定位 GOT,        (glibc 起跑器)      │
            PC = e_entry ──────┘        按 AT_ENTRY 跳                          │ return
            PSTATE = EL0t               (静态链接: eret 直落 _start)            ▼
                                                                     exit(ret)
                                                              atexit 链 + ld.so 析构
                                                                        │
                                                                        ▼
                                                                exit_group syscall
                                                          → do_exit(进程回收)
```

## 4. FAQ

**Q：`main` 返回后为什么不会崩？**
A：`main` 是被 `__libc_start_main` **调用**的，返回即回到起跑器，接着走 `exit(result)`；真正"没有返回地址"的是 `_start`（x30=0，若 `bl abort` 兜底都失效则异常终止）。

**Q：内核程序有 `_start`/`main` 吗？**
A：内核的"入口"是链接脚本 `ENTRY(_text)`（vmlinux.lds.S:94，arm64 即 `head.S` 的 `_head`），没有 crt/起跑器——内核自己就是自己的运行时。对照见 [028.编译原理/002 链接脚本走读](../../028.编译原理/002.链接脚本走读：vmlinux.lds.S.md)。

**Q：静态链接程序入口也一样吗？**
A：一样走 crt1.o 的 `_start`，区别只在 `main` 地址的获取方式（`MOVL` 直接装 vs GOT 间接取，见上文两个分支）与"没有 ld.so/AT_BASE"。
