## 1. 一切皆"特殊文件":块与字符的二分(§10.5.1)

> "Special files are divided into two categories, block and character. A block special file is one consisting of a sequence of numbered blocks. The key property of the block special file is that each block can be individually addressed and accessed. ... Block special files are typically used for disks (and SSDs, of course)."（特殊文件分为两类：块特殊文件和字符特殊文件。块特殊文件由编号的块序列组成。块特殊文件的关键属性是每个块都可以单独寻址和访问……块特殊文件典型地用于磁盘(当然也包括 SSD)。）<sup>[Modern Operating Systems 5th, 书页 762(PDF 787)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=787)</sup>

> "Character special files are normally used for devices that input or output a character stream. Keyboards, printers, networks, mice, plotters, and most other I/O devices that accept or produce data for people use character special files. It is not possible (or even meaningful) to seek to block 124 on a mouse."（字符特殊文件通常用于输入或输出字符流的设备。键盘、打印机、网络、鼠标、绘图仪，以及其他大多数为人服务的 I/O 设备，都使用字符特殊文件。对鼠标"寻道到 124 号块"是不可能的(甚至没有意义)。）<sup>[书页 762(PDF 787)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=787)</sup>

设备号机制:

> "Associated with each special file is a device driver that handles the corresponding device. Each driver has what is called a major device number that serves to identify it. If a driver supports multiple devices, say, two disks of the same type, each disk has a minor device number that identifies it. Together, the major and minor device numbers uniquely specify every I/O device."（每个特殊文件都有一个处理对应设备的设备驱动程序与之关联。每个驱动程序有一个称为主设备号(major device number)的编号标识自己。如果一个驱动程序支持多个设备(比如两块同型磁盘)，每块磁盘有一个标识自己的次设备号(minor device number)。主次设备号合起来唯一确定每一个 I/O 设备。）<sup>[书页 762-763(PDF 787)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=787)</sup>

**内核对应**:设备号 `dev_t` 就是"major << 20 | minor"<sup>[include/linux/kdev_t.h:7-12](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/kdev_t.h)</sup>:

```c
// include/linux/kdev_t.h
#define MINORBITS    20
#define MINORMASK    ((1U << MINORBITS) - 1)
#define MAJOR(dev)   ((unsigned int) ((dev) >> MINORBITS))
#define MKDEV(ma,mi) (((ma) << MINORBITS) | (mi))
```

`ls -l /dev` 输出的前两列(如 `brw-rw---- 1 root disk 8, 0` 中的 `8, 0`)正是 major=8(磁盘驱动)、minor=0(第一块盘)。

## 2. I/O 系统劈成两半(§10.5.4)

> "The I/O system is split into two major components: the handling of block special files and the handling of character special files. We will now look at each of these components in turn."（I/O 系统被分成两个主要组件：块特殊文件的处理和字符特殊文件的处理。下面依次考察这两者。）<sup>[Modern Operating Systems 5th, 书页 766(PDF 791)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=791)</sup>

### 2.1 通用打开路径:major 索引 → 函数指针表

> "When the user accesses a special file, the file system determines the major and minor device numbers belonging to it and whether it is a block special file or a character special file. The major device number is used to index into one of two internal hash tables containing data structures for character or block devices. The structure thus located contains pointers to the procedures to call to open the device, read the device, write the device, and so on. The minor device number is passed as a parameter. Adding a new device type to Linux means adding a new entry to one of these tables and supplying the corresponding procedures to handle the various operations on the device."（当用户访问一个特殊文件时，文件系统确定它的主次设备号，并判断它是块特殊文件还是字符特殊文件。主设备号用来在一个内部哈希表(字符设备、块设备各一张)中索引，定位到相应的数据结构。该结构包含打开、读、写设备等过程的指针。次设备号作为参数传入。往 Linux 添加一种新设备类型，意味着在这些表之一加一个新表项，并提供处理该设备各种操作的相应过程。）<sup>[书页 766(PDF 791)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=791)</sup>

**内核对应(两套表的真实形态)**:

```text
              open("/dev/sda")                    open("/dev/tty0")
                    │                                  │
        VFS: 路径解析 → inode(来自 inode_hashtable)     │
                    │                                  │
        S_ISBLK? ──是──► 块设备分支        S_ISCHR? ──是──► 字符设备分支
                    │                                  │
        bdev_open()                      chrdev_open()
   [block/bdev.c:929]                [fs/char_dev.c:370]
        │                                  │
   def_blk_fops(静态)              kobj_lookup(cdev_map, i_rdev)
   [block/fops.c:952]            [fs/char_dev.c:29 定义 cdev_map]
        │                                  │            :383 调用点
   .open  = blkdev_open           cdev->ops(驱动注册时 kobj_map 挂入)
   .read_iter = blkdev_read_iter            │
   .write_iter= blkdev_write_iter     → 命中驱动自己的 file_operations
   .fsync = blkdev_fsync
        │
   提交 I/O: submit_bio → 块层(页缓存/调度器, 见 007/008 笔记)
```

- 块设备没有每驱动一张动态表——`def_blk_fops` 是全局唯一的 `file_operations`,major 只是用来找到 `struct block_device`/gendisk;真正的"表"是 `bdev_map`(kobj_map 机制,与字符侧同源)。
- 字符设备则完全按书描述:`__register_chrdev_region` 登记 major/minor 区间,`cdev_map` 按 major 散列,`chrdev_open` 中 `kobj_lookup(cdev_map, inode->i_rdev, &idx)` 找到驱动 cdev,再调用其 fops<sup>[fs/char_dev.c:370-383](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/fs/char_dev.c)</sup>。

### 2.2 字符驱动操作表(Fig 10-21)ASCII 重绘

> "Some of the operations which may be associated with different character devices are shown in Fig. 10-21. Each row refers to a single I/O device (i.e., a single driver). The columns represent the functions that all character drivers must support."（图 10-21 给出了不同字符设备可能关联的一些操作。每一行对应单个 I/O 设备(即单个驱动程序)，各列代表所有字符驱动必须支持的函数。）<sup>[书页 766(PDF 791)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=791)</sup>

```text
 Device    Open      Close      Read       Write      Ioctl      Other
 ─────────────────────────────────────────────────────────────────────────
 Null      null      null       null       null       null       …        ← 写入即丢弃(/dev/null)
 Memory    null      null       mem_read   mem_write  null       …        ← /dev/mem 物理内存
 Keyboard  k_open    k_close    k_read     error      k_ioctl    …        ← 只读设备写=error
 Tty       tty_open  tty_close  tty_read   tty_write  tty_ioctl  …        ← 终端
 Printer   lp_open   lp_close   error      lp_write   lp_ioctl   …        ← 只写设备读=error
 (MOS5 Fig 10-21 重绘;"null/error"即该驱动不支持该操作的占位)
```

内核形态就是每个驱动填一张 `struct file_operations`——与上表逐列对应(`.open/.release/.read/.write/.unlocked_ioctl`),`error` 在内核里表现为该函数指针未实现(EINVAL)或不注册。

### 2.3 驱动的两半:top half / bottom half

> "Each driver is split into two parts, both of which are part of the Linux kernel and both of which run in kernel mode. The top half runs in the context of the caller and interfaces to the rest of Linux. The bottom half runs in kernel context and interacts with the device."（每个驱动程序分成两部分，两者都是 Linux 内核的一部分，都在内核态运行。上半部运行在调用者的上下文中，与 Linux 其余部分衔接；下半部运行在内核上下文中，与设备打交道。）<sup>[书页 767(PDF 791)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=791)</sup>

对应内核的硬中断处理/`tasklet`/工作队列分层思想,详见 [009.中断与异常](../009.中断与异常/README.md)。

### 2.4 块侧:缓存为目标(→ Fig 10-22)

> "The goal of the part of the system that does I/O on block special files (e.g., disks) is to minimize the number of transfers that must be done. To accomplish this goal, Linux has a cache between the disk drivers and the file system, as illustrated in Fig. 10-22."（对块特殊文件(如磁盘)做 I/O 的那一部分系统，其目标是把必须完成的传输次数降到最少。为此，Linux 在磁盘驱动与文件系统之间设有一个缓存，如图 10-22 所示。）<sup>[书页 767(PDF 791)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=791)</sup>

- 2.2 内核之前维持相互独立的页缓存与缓冲缓存,现已统一;通用块层负责扇区/块/缓冲/页之间的翻译——此图与页缓存/块层细节在 [015.Linux-IO系统全路径-从VFS到块设备驱动](../033.文件系统/015.Linux-IO系统全路径-从VFS到块设备驱动.md) 展开;
- 块读写的完整执行链(系统调用 → 页缓存 → bio → 调度器 → 驱动)在本目录 [000.块设备/000.块设备的操作](000.块设备/000.块设备的操作.md) 已有全链路笔记;
- DAX(4.0+ 内核,存储类内存绕过缓存直取)、raw 块设备(绝对块号,分页与系统维护用)亦出自书页 767-768。

### 2.5 字符侧:线路规程(line discipline)

> "The interaction with character devices is simple. Since character devices produce or consume streams of characters, or bytes of data, support for random access makes little sense. One exception is the use of line disciplines. A line discipline can be associated with a terminal device, represented via the structure tty_struct, and it represents an interpreter for the data exchanged with the terminal device. For instance, local line editing can be done (i.e., erased characters and lines can be removed), carriage returns can be mapped onto line feeds, and other special processing can be completed. However, if a process wants to interact on every character, it can put the line in raw mode, in which case the line discipline will be bypassed. Not all devices have line disciplines."（与字符设备的交互很简单。字符设备产生或消耗字符流/字节流，支持随机访问意义不大。一个例外是线路规程(line discipline)。线路规程可以关联到一个终端设备(用 tty_struct 结构表示)，它是与终端设备交换数据的解释器。例如可以完成本地行编辑(删除字符/行)、把回车映射为换行等特殊处理。但如果进程想逐字符交互，可以把终端置于 raw 模式，此时线路规程被旁路。并非所有设备都有线路规程。）<sup>[书页 767-768(PDF 792)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=792)</sup>

内核形态:`struct tty_struct` 挂 `struct tty_ldisc`,默认规程 `n_tty`( drivers/tty/n_tty.c,实现退格/CTRL-U 行编辑与回车↔换行映射);应用置 raw 模式的 `tcsetattr(fd, &termios)` 即 MOS5 §10.5.3 图 10-20 里的 POSIX 终端调用族。`ioctl` 系统调用本身留在 [003.CPU如何与IO设备交互](003.CPU如何与IO设备交互.md) 的"设备控制器寄存器操作方式"一节。
