## 1. §5.1 I/O 硬件原理

### 5.1.1 设备分类:块设备与字符设备

> A block device is one that stores information in fixed-size blocks, each one with its own address... The essential property of a block device is that it is possible to read or write each block independently of all the other ones.（块设备把信息存储在固定大小的块中,每个块有自己的地址……块设备的本质属性是可以独立于所有其他块单独读写每一个块。）<sup>[Modern Operating Systems 5th, 书页 338(PDF 367)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=367)</sup>

> A character device delivers or accepts a stream of characters, without regard to any block structure. It is not addressable and does not have a seek operation.（字符设备传输或接收的是字符流,不考虑任何块结构。它不可寻址,也没有寻道操作。）<sup>[Modern Operating Systems 5th, 书页 338(PDF 367)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=367)</sup>

书里也承认这套二分法不完美:时钟既不是块设备也不产字符流、只按固定间隔发中断;内存映射屏幕同样塞不进去——**但足够让文件系统只面对"抽象块设备"**。速率谱(图 5-1)从键盘 10 B/s 到 PCIe 6.0 126 GB/s,横跨 10 个数量级——这正是软件必须分层的原因。

**arm64 对应**:块/字符设备的分类在 Linux 里就是 `def_blk_fops` 与 cdev 两套 `file_operations`(见 [033.文件系统/000.块设备](../033.文件系统/000.块设备/000.块设备的操作.md));速率跨 10 个数量级 ⇔ 互连 QoS 分级(见 [006.DMA/002](../000.内存管理/006.DMA/002.arm64下CPU数据访问优先级通常低于DMA的原因.md))。

### 5.1.2 设备控制器:位串流到字节块的翻译官

> I/O units often consist of a mechanical component and an electronic component. It is possible to separate the two parts to provide a more modular and general design. The electronic component is called the device controller or adapter.（I/O 单元通常由机械部件与电子部件组成。把两者分开可以提供更模块化、更通用的设计。电子部件称为设备控制器或适配器。）<sup>[Modern Operating Systems 5th, 书页 338–339(PDF 367–368)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=367)</sup>

> The controller's job is to convert the serial bit stream into a block of bytes and perform any error correction that is necessary.（控制器的任务是把串行位流转换成字节块,并完成任何必要的纠错。）<sup>[Modern Operating Systems 5th, 书页 339(PDF 368)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=368)</sup>

磁盘例子:3,000,000 条磁道 × 每道 200–500 扇区 × 4096 字节,驱动器吐出的却是一条"前导码 + 32,768 位数据 + ECC 校验"的**串行位流**——控制器逐位组装、校验后才拷进内存。本目录 [003.CPU如何与IO设备交互](./003.CPU如何与IO设备交互.md) 的"寄存器 + 协议握手"即此层。

### 5.1.3 MMIO:两个地址空间 → 一个地址空间

图 5-2 三方案重绘:

```text
 (a) 独立 I/O 端口           (b) 内存映射 I/O            (c) 混合
  Memory      I/O ports       Memory                      Memory    I/O ports
  0xFFFF…┐    0xFFFF…┐        0xFFFF…┌────────┐            0xFFFF…┌──┴──┐
         │           │               │ MMIO   │  (设备寄存器)      │数据  │

```

> The second approach, introduced with the PDP-11, is to map all the control registers into the memory space... This system is called memory-mapped I/O.（第二种方法由 PDP-11 引入:把所有控制寄存器映射进内存空间……这种系统称为内存映射 I/O。）<sup>[Modern Operating Systems 5th, 书页 340–341(PDF 369–370)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=369)</sup>

MMIO 三大优点(驱动可用纯 C 写、无需特殊保护机制——不给用户页表映射即可、任何访存指令都能操作设备寄存器),代价是缓存/总线设计的复杂性(书页 341-342 详述 cache 一致性问题)。

**arm64 对应**:**arm64 只有方案 (b)**——没有独立的 I/O 端口空间(IN/OUT 指令不存在),一切设备寄存器皆 MMIO(`ioremap` + `readl/writel`,DSB/DMB 屏障保证顺序);x86 的 PCI I/O 端口在 arm64 上由 PCI 控制器模拟成一段特殊内存窗口。完整展开见 [../000.内存管理/023.MMIO(内存映射IO)](../000.内存管理/023.MMIO%28内存映射IO%29/README.md)(多总线路由与 ARM64 处理)。

### 5.1.4 DMA 与 5.1.5 中断(再论)

DMA 三种模式(周期窃取/突发/飞越)与图 5-4 的逐步注解已单独成篇:[../000.内存管理/006.DMA/001.DMA传送流程(重绘图5-4)与IOMMU地址翻译.md](../000.内存管理/006.DMA/001.DMA传送流程%28重绘图5-4%29与IOMMU地址翻译.md);"DMA 优先级为何高于 CPU 访存"见 [../000.内存管理/006.DMA/002](../000.内存管理/006.DMA/002.arm64下CPU数据访问优先级通常低于DMA的原因.md)。

中断流程(图 5-5)重绘并标注 arm64 实体:

```text
    设备(IRQ) ──中断线──► 中断控制器 ──► CPU
                              │             │ 1.设备完工拉线
                              │             │ 2.控制器向 CPU 发中断(向量号上地址线)
                              │             │ 3.CPU 应答(写控制器端口)后才允许下一个中断
                              ▼
  x86 老世界: 8259A PIC / APIC,向量号 → IDT
  arm64 现实: GICv3(GICD 分发器 + GICR redistributor + CPU interface)
              → IRQ 异常向量(VBAR_EL1 指向的 el1h_64_irq)→ gic_handle_irq()
              读 ICC_IAR0/1_EL1 拿 intid(等价"向量号"),写 ICC_EOIR1_EL1 应答(等价"步骤3")
```

> To handle the interrupt, the controller puts a number on the address lines specifying which device wants attention and asserts a signal to interrupt the CPU. The interrupt signal causes the CPU to stop what it is doing and start doing something else. The number on the address lines is used as an index into a table called the interrupt vector to fetch a new program counter.（为了处理中断,控制器把一个编号放上地址线,指明哪个设备需要关注,并发出信号打断 CPU。中断信号使 CPU 停下当前工作,开始做别的事情。地址线上的编号用作"中断向量表"的索引,取出新的程序计数器。）<sup>[Modern Operating Systems 5th, 书页 348(PDF 377)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=377)</sup>

保存现场的位置之争(书页 348–349):内部寄存器(应答慢、可能丢中断) vs 用户栈(栈指针可能非法/跨页缺页) vs **内核栈**(MMU 上下文切换与缓存代价)——arm64 的答案是每个任务固定内核栈(`task_struct->stack`),异常进入 EL1 时 SP 自动切到 `SP_EL1`,天然规避了"谁的栈"问题。

**精确中断 vs 非精确中断**(书页 349–350):流水线/乱序机器必须保证"中断时所有在此之前发起的指令都已完工、之后的都没开始"——arm64 属于精确异常(异常进入时 PC 状态一致),MOS5 提到 x86 老机器需要仿真器兜底。

## 2. §5.2 I/O 软件原理:目标与三种方式

### 5.2.1 五个设计目标

> A key concept in the design of I/O software is known as device independence. What it means is that we should be able to write programs that can access any I/O device without having to specify the device in advance.（I/O 软件设计中的一个关键概念是设备无关性。它的含义是:我们应当能编写访问任意 I/O 设备的程序,而不必事先指定设备。）<sup>[Modern Operating Systems 5th, 书页 352(PDF 381)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=381)</sup>

1. **设备无关**——`sort < input > output` 不关心 input 是什么;
2. **统一命名**——文件与设备都按路径名寻址("a USB stick can be mounted on top of the directory /usr/ast/backup");
3. **错误处理就近**——"errors should be handled as close to the hardware as possible"(控制器能纠就纠,驱动重试,再往上报)<sup>[Modern Operating Systems 5th, 书页 353(PDF 382)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=382)</sup>;
4. **同步(阻塞) vs 异步(中断驱动)**——物理 I/O 天然异步,"It is up to the operating system to make operations that are actually interrupt-driven look blocking to the user programs."(书页 353);
5. **缓冲**与**共享/独占设备**——buffering 解决"数据到达处 ≠ 最终去处"与实时防欠载;打印机类独占设备引出死锁问题。

### 5.2.2–5.2.4 三种 I/O 方式(打印机例子贯穿)

```text
 (a) 程控 I/O(轮询)                (b) 中断驱动                    (c) DMA
 copy_from_user(buffer,p,count)    copy_from_user(buffer,p,count)  copy_from_user(buffer,p,count)
 for(i=0;i<count;i++){             enable_interrupts()             set_up_DMA_controller()
   while(*printer_status!=READY);  while(*printer_status!=READY);  scheduler()   // CPU 立刻走人
   *printer_data_reg=p[i];         *printer_data_reg=p[0];         ...DMA 中断时:
 }                                 scheduler()                       acknowledge_interrupt()
 return_to_user()                  // ISR(每字符一次):                unblock_user()
                                       if(count==0){                 return_from_interrupt()
                                         unblock_user();           (搬数据的是 DMA 控制器,
                                       } else {                     中断只做收尾)
                                         *printer_data_reg=p[i];
                                         count--; i++;
                                       }
 图 5-8                                acknowledge_interrupt();      图 5-10
                                       return_from_interrupt();
                                       图 5-9
```

- 程控 I/O:**"The essential aspect of programmed I/O ... is that after outputting a character, the CPU continuously polls the device to see if it is ready to accept another one. This behavior is often called polling or busy waiting."**<sup>[Modern Operating Systems 5th, 书页 355(PDF 384)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=384)</sup>——嵌入式可用,通用系统太浪费;
- 中断驱动:每字符一次中断,"Interrupts take time, so this scheme wastes a certain amount of CPU time."(书页 356);
- DMA:**"In essence, DMA is programmed I/O, only with the DMA controller doing all the work, instead of the main CPU."**(书页 356);大赢是**把中断从每字符一次降到每缓冲一次**。

**arm64 对应**:三方式在 Linux 里分别是 `readl_poll*` 轮询、`request_irq` + ISR、`dmaengine`/块层 DMA;`write()` 全链路(缓冲写) 见 [033.文件系统/000.块设备 §0](../033.文件系统/000.块设备/000.块设备的操作.md)。

## 3. §5.3 I/O 软件四层

> I/O software is typically organized in four layers, as shown in Fig. 5-11. Each layer has a well-defined function to perform and a well-defined interface to the adjacent layers.（I/O 软件通常组织为四层,如图 5-11。每层都有明确的功能和与相邻层的明确接口。）<sup>[Modern Operating Systems 5th, 书页 357(PDF 386)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=386)</sup>

```text
 ┌────────────────────────────────────────────┐
 │ User-level I/O software   (libc, spooling)  │   用户态:库/守护进程
 ├────────────────────────────────────────────┤
 │ Device-independent OS software (命名/缓冲/  │   设备无关层:fs/char_dev.c、buffer.c
 │   错误报告/设备分配/统一块长 图 5-13)       │
 ├────────────────────────────────────────────┤
 │ Device drivers           (驱动 = 半上半下)  │   设备驱动:drivers/**
 ├────────────────────────────────────────────┤
 │ Interrupt handlers       (隐藏中断细节)     │   中断处理:entry.S → gic → driver ISR
 ├────────────────────────────────────────────┤
 │ Hardware                                    │   硬件:控制器/设备
 └────────────────────────────────────────────┘
```

### 5.3.1 中断处理器的十步(书页 358)

> 1. Save any registers (including the PSW) that have not already been saved by the interrupt hardware. 2. Set up a context for the interrupt-service procedure... 3. Set up a stack... 4. Acknowledge the interrupt controller... 5. Copy the registers... to the process table. 6. Run the interrupt-service procedure... 7. Choose which process to run next... 8. Set up the MMU context for the process to run next... 9. Load the new process' registers, including its PSW. 10. Start running the new process.（1.保存硬件未保存的寄存器(含 PSW);2.为中断服务例程建立上下文;3.建立栈;4.应答中断控制器;5.把寄存器拷进进程表;6.运行中断服务例程;7.挑选下一个要跑的进程;8.为它建立 MMU 上下文;9.装载新进程寄存器;10.开始运行。）<sup>[Modern Operating Systems 5th, 书页 358(PDF 387)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=387)</sup>

**arm64 实景对照**(从核 idle 一例的完整十步,行号见 [025.MULTIPLE_PROCESSOR_SYSTEM/002.8.1.2 §2.7](../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/002.8.1.2-多处理器OS类型与SMP.md)):1=kernel_entry 保存 x0-x30/ELR/SPSR;2=EL1 上下文天然就绪;3=内核栈;4=写 ICC_EOIR1_EL1;5=pt_regs;6=ISR;7=scheduler_ipi/schedule;8-9=ERET 由硬件恢复;10=eret。

### 5.3.2 设备驱动:上半部/下半部

> Each driver is split into two parts, both of which are part of the Linux kernel and both of which run in kernel mode. The top half runs in the context of the caller and interfaces to the rest of Linux. The bottom half runs in kernel context and interacts with the device.（每个驱动分为两部分,都是 Linux 内核的一部分,都运行在内核态。上半部在调用者上下文中运行,与 Linux 其余部分对接;下半部在内核上下文中运行,与设备交互。）<sup>[Modern Operating Systems 5th, 书页 762(PDF 791)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=791)</sup>

## 4. §5.4 大容量存储:磁盘、SSD、RAID

## 5. §5.5 时钟

```text
 可编程时钟(图 5-27):  晶体振荡器 ──脉冲──► 计数器(递减)──计数到 0──► 中断
                                                    ▲            │
                       软件(驱动)写入初值 ──► 保持寄存器 ──装载──┘    └─(方波模式自动重装)
 模式: one-shot(一次) / square-wave(方波=周期时钟滴答 clock tick)
```

> In square-wave mode, after getting to zero and causing the interrupt, the holding register is automatically copied into the counter, and the whole process is repeated again indefinitely. These periodic interrupts are called clock ticks.（方波模式下,计数到 0 并引发中断后,保持寄存器自动重新装入计数器,整个过程无限重复。这些周期性中断称为时钟滴答。）<sup>[Modern Operating Systems 5th, 书页 390–391(PDF 419–420)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=419)</sup>

时钟驱动六大职责(书页 391):时间OfDay、防进程超时(时间片!)、CPU 记账、alarm 系统调用、看门狗、profiling。

**arm64 对应**:不是 PIT/RTC,而是 **arch timer**(系统计数器 CNTFRQ/CNTP_CVAL,Always-on 域),`wfi` 睡眠也由它唤醒;tick 由 `CONFIG_HZ`/`NO_HZ`(tickless)控制,时间片发放见 [031.进程管理](../031.进程管理)。

## 6. §5.6–5.8 用户界面、瘦客户机、电源管理

- **输入软件**(5.6.1):键盘扫描码→键码→ASCII 的两次翻译;行规程(回显/退格/CTRL-C)——MOS5 的 line discipline 与 §10.5 互相引用,Linux 实体 `n_tty`;
- **输出软件**(5.6.2):RS-232 终端转义序列 → X11 → GUI(fonts/位图合成);书里的大头是 X Window 与缓冲策略;
- **瘦客户机**(5.7):显示在服务端计算、网络传输像素(RDP/VNC)——对照 [001.分布式软总线](../053.总线-BUS/001.分布式软总线.md) 的现代演绎;
- **电源管理**(5.8):两类手段——"The first one is for the operating system to turn off parts of the computer (mostly I/O devices) when they are not in use... The second one is for the application program to use less energy, possibly degrading the quality of the user experience."(书页 421);设备四态 on/sleeping/hibernating/off;三大耗电大户 display/disk/CPU;OS 的两难:"If it shuts down a device and that device is needed again quickly, there may be an annoying delay... if it waits too long to shut down a device, energy is wasted for nothing."(书页 422)。

**arm64 对应**:cpuidle 状态树(idle.c 的 `cpuidle_idle_call` 选择深度,见 [025/002.8.1.2 §2.7](../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/002.8.1.2-多处理器OS类型与SMP.md))、runtime PM(`drivers/base/power/`)、EAS 大小核能量调度(capacity/能量模型,详见 [031.进程管理](../031.进程管理) 与 CLAUDE.md 平台规范附录)。

## 7. §5.9 研究 + §5.10 小结

研究主题:新硬件(多队列网卡/SSD)下的 I/O 调度、低功耗外设、IO_uring 类异步栈等。**全书小结一句话**(5.10):"All the layers work together to present the application with a clean, uniform view of the I/O system."——四层软件栈把 10 个数量级的设备差异藏成一套 read/write。

## 9. 记忆钩

- 硬件三层:**控制器管翻译、总线管带宽、中断管唤醒**;CPU 与设备的四种交互(轮询/中断/DMA/共享内存)按"CPU 省多少事"排序;
- 软件四层:**库 → 无关层 → 驱动 → ISR**,"中断藏在最深处"(5.3.1);
- 两本账:块设备记账在**页缓存**(统一缓存,30 秒),设备记账在**控制器 FIFO**(死线)——前者催生回写,后者催生 DMA 优先级([006.DMA/002](../000.内存管理/006.DMA/002.arm64下CPU数据访问优先级通常低于DMA的原因.md));
- arm64 三特色:**无 I/O 端口**(全 MMIO)、**arch timer 替代 PIT**、**GIC 三件套**(GICD/GICR/CPU interface)。
