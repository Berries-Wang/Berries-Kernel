## 1. devmap managed pages 是什么

> 在 Linux 内核中, devmap managed pages 是一种特殊的物理内存页。它们并不是由内核在
> 系统启动时自动发现并管理的"常规内存"(如你的 16GB RAM), 而是由设备驱动程序主动
> "塞"进内核内存管理系统的。简单来说, **它们是拥有 struct page 结构的设备地址空间**。

三个关键词:

1. **设备地址空间**: VRAM/CXL 内存/PMEM, 不在固件报告的常规内存地图里;
2. **拥有 struct page**: 内核 99% 的代码只认 `struct page`, 给显存配一个,
   页迁移/rmap/memcg 等机制就能直接复用;
3. **驱动主动热插**: 驱动 `probe` 时调 `memremap_pages()` 注册, `remove` 时注销。

```
   固件(e820/DT)眼中的物理地址:                 内核眼中的物理地址:
  ┌──────────────────────────┐              ┌──────────────────────────┐
  │ System RAM  [0~16GB]     │              │ ZONE_NORMAL  [0~16GB]    │ ← 启动时就认识
  │ reserved / MMIO hole     │              │ ZONE_DEVICE  [fake 区间] │ ← 驱动热插!
  │ (不含 VRAM)              │              │ └ 实体 = 显卡 VRAM       │
  └──────────────────────────┘              └──────────────────────────┘
        VRAM 根本不在地图上                  "区间地址"只是记账用, 不是真内存
```

★ **`ZONE_DEVICE` 的物理地址区间是"编造"出来的** (以 `MEMORY_DEVICE_PRIVATE` 为例;
  `MEMORY_DEVICE_COHERENT` (C2C/CXL) 用的则是真实 aperture 地址, 见下方 amdkfd 源码):
  `request_free_mem_region()` 在 `iomem_resource` 里找一段没人用的地址记账,
  它不对应 CPU 可访问的总线地址。CPU 永远不该 `page_address()` 解引用它 ——
  `MEMORY_DEVICE_PRIVATE` 页被 CPU 碰到只会以 swap entry 形式存在于页表中。

## 2. 五种 memory_type (`include/linux/memremap.h`)

```c
/*
 * Specialize ZONE_DEVICE memory into multiple types each has a different
 * usage.
 *
 * MEMORY_DEVICE_PRIVATE:
 * Device memory that is not directly addressable by the CPU: CPU can neither
 * read nor write private memory. In this case, we do still have struct pages
 * backing the device memory. Doing so simplifies the implementation, but it is
 * important to remember that there are certain points at which the struct page
 * must be treated as an opaque object, rather than a "normal" struct page.
 * ...
 * MEMORY_DEVICE_COHERENT:
 * Device memory that is cache coherent from device and CPU point of view. This
 * is used on platforms that have an advanced system bus (like CAPI or CXL). ...
 *
 * MEMORY_DEVICE_FS_DAX:   持久内存 DAX
 * MEMORY_DEVICE_GENERIC:  通用 (CXL range 等)
 * MEMORY_DEVICE_PCI_P2PDMA:  PCI BAR 里的 P2P 内存
 */
enum memory_type {
	/* 0 is reserved to catch uninitialized type fields */
	MEMORY_DEVICE_PRIVATE = 1,     /* 显存: CPU 不可见, 必须 migrate_to_ram */
	MEMORY_DEVICE_COHERENT,        /* C2C/CXL 显存: CPU 可见, 可直接映射 */
	MEMORY_DEVICE_FS_DAX,          /* PMEM: 文件系统 DAX */
	MEMORY_DEVICE_GENERIC,         /* 通用设备内存 */
	MEMORY_DEVICE_PCI_P2PDMA,      /* GPU↔GPU P2P 用 BAR 内存 */
};
```

| 类型 | CPU 可直接访问? | 典型硬件 | CPU 页表中的形态 |
|-|-|-|-|
| PRIVATE | ✗ | 独立显卡 (PCIe) | device-private swap entry (伪装换出) |
| COHERENT | ✓ | Grace-Hopper C2C / MI300A / CXL | 普通 PTE (mk_pte) |
| FS_DAX | ✓ | PMEM | PTE (可 pin) |
| GENERIC | ✓ | CXL range 设备 | PTE |
| PCI_P2PDMA | ✓(弱) | GPU BAR1 | PTE (uncached) |

## 3. `struct dev_pagemap`: 一段设备内存的"身份证"

```c
/**
 * struct dev_pagemap - metadata for ZONE_DEVICE mappings
 * @altmap: pre-allocated/reserved memory for vmemmap allocations
 * @ref: reference count that pins the devm_memremap_pages() mapping
 * @done: completion for @ref
 * @type: memory type: see enum memory_type
 * @ops: method table (见下)
 * @owner: an opaque pointer identifying the entity that manages this
 *	instance.  Used by various helpers to make sure that no
 *	foreign ZONE_DEVICE memory is accessed.
 * @nr_range / @range / @ranges: 物理区间
 */
struct dev_pagemap {
	struct vmem_altmap altmap;
	struct percpu_ref ref;          /* 存活引用: 页全部归还后才能卸载 */
	struct completion done;
	enum memory_type type;
	unsigned int flags;
	unsigned long vmemmap_shift;
	const struct dev_pagemap_ops *ops;
	void *owner;                    /* ★ 驱动身份 (device*), 防"串门" */
	int nr_range;
	union {
		struct range range;
		DECLARE_FLEX_ARRAY(struct range, ranges);
	};
};
```

`owner` 的意义: 页表里遇到一个 device-private entry 时, 通过
`page->pgmap->owner == my_device` 判断"这页是不是我家的显存" ——
`hmm_range_fault` 和 `migrate_vma` 都靠它避免误动别人的页。

## 4. `dev_pagemap_ops`: 设备内存页的三个回调

```c
struct dev_pagemap_ops {
	/*
	 * Called once the page refcount reaches 0. ...
	 */
	void (*page_free)(struct page *page);

	/*
	 * Used for private (un-addressable) device memory only.  Must migrate
	 * the page back to a CPU accessible page.
	 */
	vm_fault_t (*migrate_to_ram)(struct vm_fault *vmf);   /* ★ CPU 缺页迁回 */

	/*
	 * Handle the memory failure happens on a range of pfns. ...
	 */
	int (*memory_failure)(struct dev_pagemap *pgmap, unsigned long pfn,
			      unsigned long nr_pages, int mf_flags);
};
```

```
      page_free()                migrate_to_ram()            memory_failure()
      │                          │                           │
   页 refcount 归 0 时       CPU 碰到 device-private      HED/ECC 报错时
   (驱动把显存还回自己的      entry 缺页时 (见 004 章       通知并杀死使用进程
   allocator/空闲链表)        nouveau_dmem_migrate_to_ram) (poison 处理)
```

## 5. 注册流程: `memremap_pages()` 做了什么

驱动注册显存的完整链条 (以 amdkfd 真实代码为例):

```c
int kgd2kfd_init_zone_device(struct amdgpu_device *adev)
{
	...
	/* ① 在 iomem_resource 里找一段没人用的物理地址区间(纯记账) */
	res = devm_request_free_mem_region(adev->dev, &iomem_resource, size);

	pgmap->range.start = res->start;
	pgmap->range.end   = res->end;
	pgmap->type        = MEMORY_DEVICE_PRIVATE;   /* 或 COHERENT, 见 001 章 */
	pgmap->nr_range    = 1;
	pgmap->ops         = &svm_migrate_pgmap_ops;  /* page_free + migrate_to_ram */
	pgmap->owner       = SVM_ADEV_PGMAP_OWNER(adev);

	/* ② 热插进内核 */
	r = devm_memremap_pages(adev->dev, pgmap);
	...
}
```

`memremap_pages()` 内部 (v6.8 `mm/memremap.c`, 关键段):

```c
	switch (pgmap->type) {
	case MEMORY_DEVICE_PRIVATE:
		if (!pgmap->ops || !pgmap->ops->migrate_to_ram) {
			WARN(1, "Missing migrate_to_ram method\n");   /* 强制要求 */
			return ERR_PTR(-EINVAL);
		}
		if (!pgmap->owner) {
			WARN(1, "Missing owner\n");
			return ERR_PTR(-EINVAL);
		}
		break;
	...
	}

	...
	if (is_private) {
		/*
		 * For device private memory we call add_pages() as we only
		 * need to allocate and initialize struct page for the device
		 * memory. ...the device memory is un-accessible thus we do not
		 * want to create a linear mapping for the memory like
		 * arch_add_memory() would do.
		 *  ↑ PRIVATE: 只建 struct page (memmap), 不建内核线性映射!
		 */
		error = add_pages(nid, PHYS_PFN(range->start),
				PHYS_PFN(range_len(range)), params);
	} else {
		error = arch_add_memory(nid, range->start, range_len(range),
					params);   /* COHERENT 等: 建线性映射 */
	}

	if (!error) {
		struct zone *zone;

		zone = &NODE_DATA(nid)->node_zones[ZONE_DEVICE];  /* 归入 ZONE_DEVICE */
		move_pfn_range_to_zone(zone, PHYS_PFN(range->start),
				PHYS_PFN(range_len(range)), params->altmap,
				MIGRATE_MOVABLE);
	}
	...
	/* 初始化每页的 struct page, 并让 page->pgmap 指回 pgmap */
	memmap_init_zone_device(&NODE_DATA(nid)->node_zones[ZONE_DEVICE],
				PHYS_PFN(range->start),
				PHYS_PFN(range_len(range)), pgmap);
```

```
  request_free_mem_region()          memremap_pages()
  ┌───────────────────────┐   ┌──────────────────────────────────────┐
  │ iomem_resource 找空洞 │──►│ add_pages(): 分配 memmap(struct page)│
  │ "这段地址归我了"      │   │ move_pfn_range_to_zone(ZONE_DEVICE)  │
  └───────────────────────┘   │ memmap_init_zone_device():           │
                              │  每页 page->pgmap = pgmap            │
                              └──────────────────────────────────────┘
                                                 │
      至此显存每页都有 struct page, 但 CPU 线性映射不存在 (PRIVATE)
```

## 6. 页的生命周期: 两个核心函数

```c
/* 驱动从自己的显存分配器拿一页给 mm 用之前初始化 */
void zone_device_page_init(struct page *page)
{
	/*
	 * Drivers shouldn't be allocating pages after calling
	 * memunmap_pages().
	 */
	WARN_ON_ONCE(!percpu_ref_tryget_live(&page->pgmap->ref));
	set_page_count(page, 1);   /* refcount 从 1 开始 */
	lock_page(page);
}

/* 页 refcount 归 0 时, mm 侧统一走这里 */
void free_zone_device_page(struct page *page)
{
	if (WARN_ON_ONCE(!page->pgmap->ops || !page->pgmap->ops->page_free))
		return;

	mem_cgroup_uncharge(page_folio(page));   /* 退出 memcg 记账 */
	...
	page->mapping = NULL;                    /* 清掉残留的匿名页标记 */
	page->pgmap->ops->page_free(page);       /* ★ 还给驱动 (显存分配器) */

	if (page->pgmap->type != MEMORY_DEVICE_PRIVATE &&
	    page->pgmap->type != MEMORY_DEVICE_COHERENT)
		/*
		 * Reset the page count to 1 to prepare for handing out the page
		 * again.   ← DAX/P2P 等内存是"死的", 直接复用
		 */
		set_page_count(page, 1);
	else
		put_dev_pagemap(page->pgmap);   /* PRIVATE/COHERENT: 页归属驱动 */
}
```

```
   页的一生 (MEMORY_DEVICE_PRIVATE / 显存页):

   驱动显存分配器 ──zone_device_page_init()──► 活跃页 ──refcount归0──►
        ▲                                                            │
        └────────────── ops->page_free() (归还驱动) ◄────────────────┴──── free_zone_device_page()
```

## 7. memcg / RSS / OOM 的特殊账本 (官方文档结论)

- 设备内存页照常计入进程 RSS 和 memcg (故意为之, 让存量应用无感知);
- 副作用: OOM Killer 可能杀掉"显存用得多、内存用得少"的进程, 却释放不出多少 DDR;
- 设备内存**永远不能被 pin** (GUP 拒绝), 所以进程退出时必然归还。
