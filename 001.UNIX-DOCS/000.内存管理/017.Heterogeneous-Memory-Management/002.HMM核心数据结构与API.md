# 002. HMM 核心数据结构与 API (`include/linux/hmm.h`)

> HMM 暴露给驱动的 API 面非常小: 一个结构体 + 一个函数。
> 本机源码: `/usr/src/linux-headers-6.8.0-138-generic/include/linux/hmm.h` (116 行, 下面全文贴出)

---

## 1. API 全景: 驱动与内核的"合同"

```
        驱动 (nouveau / amdkfd / nvidia-uvm)                    核心 mm
  ┌─────────────────────────────────────────────┐  ┌───────────────────────────────┐
  │ struct mmu_interval_notifier  ← 订阅页表变化│  │ mmu_notifier.c: 页表变化时    │
  │ struct hmm_range              ← 一次请求    │◄─┤ 调 ops->invalidate() 通知驱动 │
  │ range.hmm_pfns[]              ← 结果数组    │  │                               │
  │                                             │  │ mm/hmm.c:                     │
  │ mmu_interval_read_begin()     (内核提供)    │  │ hmm_range_fault():            │
  │ hmm_range_fault()             (内核提供)    │◄─┤ 遍历 CPU 页表, 缺页补齐,      │
  │ mmu_interval_read_retry()     (内核提供)    │  │ 输出 PFN+权限快照             │
  └─────────────────────────────────────────────┘  └───────────────────────────────┘
```

使用时序 (任何 HMM 驱动的固定套路, 官方文档给出的模板):

```
  驱动线程                                   CPU 页表 (可能有并发修改!)
     │
     │ 1. mmget_not_zero(mm)            确保 mm 活着
     │ 2. seq = mmu_interval_read_begin(notifier)   ── 记录页表"版本号"
     │ 3. mmap_read_lock(mm)
     │ 4. hmm_range_fault(&range)       ── 遍历/补齐, 填 hmm_pfns[]
     │ 5. mmap_read_unlock(mm)
     │ 6. lock(driver->update_lock)     ← 和 invalidate 回调共用同一把锁
     │ 7. mmu_interval_read_retry(seq)? ── 版本号变了?
     │       是 → 解锁, goto 2          (页表在我们睡觉时被人改了)
     │       否 → 用 hmm_pfns[] 更新 GPU 页表 (持有 update_lock, 独占)
     │ 8. unlock
     ▼
```

> 精髓: **第 2 步取版本号, 第 7 步验版本号** —— 这是内核里经典的 seqlock 模式,
> 允许第 4 步读页表期间被并发修改, 事后再发现重来。

## 2. `struct hmm_range` — 一次页表快照请求

源码 (v6.8, `include/linux/hmm.h`):

```c
/*
 * struct hmm_range - track invalidation lock on virtual address range
 *
 * @notifier: a mmu_interval_notifier that includes the start/end
 * @notifier_seq: result of mmu_interval_read_begin()
 * @start: range virtual start address (inclusive)
 * @end: range virtual end address (exclusive)
 * @hmm_pfns: array of pfns (big enough for the range)
 * @default_flags: default flags for the range (write, read, ... see hmm doc)
 * @pfn_flags_mask: allows to mask pfn flags so that only default_flags matter
 * @dev_private_owner: owner of device private pages
 */
struct hmm_range {
	struct mmu_interval_notifier *notifier;
	unsigned long		notifier_seq;
	unsigned long		start;
	unsigned long		end;
	unsigned long		*hmm_pfns;
	unsigned long		default_flags;
	unsigned long		pfn_flags_mask;
	void			*dev_private_owner;
};

/* 同文件: 唯一的入口函数 */
int hmm_range_fault(struct hmm_range *range);

/* 等 mmu notifier 事件的最长等待, 1 秒后放弃重试防止活锁 */
#define HMM_RANGE_DEFAULT_TIMEOUT 1000
```

逐字段解读:

| 字段 | 谁填 | 含义 |
|-|-|-|
| `notifier` | 驱动 | 挂在 `mm` 上的区间订阅器; HMM 用它拿 `mm` 并检查版本 |
| `notifier_seq` | 驱动 | `mmu_interval_read_begin()` 的返回值, seqlock 版本号 |
| `start` / `end` | 驱动 | 要镜像的 VA 区间 `[start, end)` |
| `hmm_pfns[]` | 驱动分配, 内核填 | **输出数组**, 每页一个 `unsigned long`:PFN | 权限标志 |
| `default_flags` | 驱动 | 整个区间的统一缺页请求 (如"全部按可读缺页") |
| `pfn_flags_mask` | 驱动 | 逐页覆盖开关: mask 掉的位以 `default_flags` 为准 |
| `dev_private_owner` | 驱动 | 自己的 `struct device *`; 用于识别"哪些 device-private 页是我的" |

`default_flags` / `pfn_flags_mask` 的配合 (官方文档示例):

```c
/* 例1: 整段区间全部按"至少可读"缺页 */
range->default_flags = HMM_PFN_REQ_FAULT;
range->pfn_flags_mask = 0;              /* 全部位听 default 的 */

/* 例2: 整段按可读缺页, 但第 index_of_write 页要求可写 */
range->default_flags = HMM_PFN_REQ_FAULT;
range->pfn_flags_mask = HMM_PFN_REQ_WRITE;
range->pfns[index_of_write] = HMM_PFN_REQ_WRITE;   /* 只有这页的 WRITE 位生效 */
```

## 3. PFN 标志位: 输入(req)与输出(状态)复用同一个编码

源码:

```c
/*
 * On output:
 * 0             - The page is faultable and a future call with
 *                 HMM_PFN_REQ_FAULT could succeed.
 * HMM_PFN_VALID - the pfn field points to a valid PFN. This PFN is at
 *                 least readable. If dev_private_owner is !NULL then this could
 *                 point at a DEVICE_PRIVATE page.
 * HMM_PFN_WRITE - if the page memory can be written to (requires HMM_PFN_VALID)
 * HMM_PFN_ERROR - accessing the pfn is impossible and the device should
 *                 fail. ie poisoned memory, special pages, no vma, etc
 *
 * On input:
 * 0                 - Return the current state of the page, do not fault it.
 * HMM_PFN_REQ_FAULT - The output must have HMM_PFN_VALID or hmm_range_fault()
 *                     will fail
 * HMM_PFN_REQ_WRITE - The output must have HMM_PFN_WRITE or hmm_range_fault()
 *                     will fail. Must be combined with HMM_PFN_REQ_FAULT.
 */
enum hmm_pfn_flags {
	/* Output fields and flags */
	HMM_PFN_VALID = 1UL << (BITS_PER_LONG - 1),   /* bit63 */
	HMM_PFN_WRITE = 1UL << (BITS_PER_LONG - 2),   /* bit62 */
	HMM_PFN_ERROR = 1UL << (BITS_PER_LONG - 3),   /* bit61 */
	HMM_PFN_ORDER_SHIFT = (BITS_PER_LONG - 8),    /* 高 8 位存映射 order */

	/* Input flags (与输出 VALID/WRITE 共用同一个位!) */
	HMM_PFN_REQ_FAULT = HMM_PFN_VALID,
	HMM_PFN_REQ_WRITE = HMM_PFN_WRITE,

	HMM_PFN_FLAGS = 0xFFUL << HMM_PFN_ORDER_SHIFT,  /* 标志位掩码 */
};
```

一个 `hmm_pfns[i]` 的位布局:

```
 63    62    61   60..56  55......0
┌─────┬─────┬─────┬───────┬──────────┐
│VALID│WRITE│ERROR│ order │   PFN    │
└─────┴─────┴─────┴───────┴──────────┘
 输入时 VALID/WRITE 语义变为 REQ_FAULT / REQ_WRITE
 order = 该页 CPU 侧映射粒度 (2^order 个 4K 页, 用于 GPU 建大页表项)
```

配套的解码 helper:

```c
/* 从 hmm pfn 还原 struct page (先确认 HMM_PFN_VALID) */
static inline struct page *hmm_pfn_to_page(unsigned long hmm_pfn)
{
	return pfn_to_page(hmm_pfn & ~HMM_PFN_FLAGS);
}

/* CPU 侧映射粒度: 比如 CPU 用 2M 大页映射时返回 order=9 */
static inline unsigned int hmm_pfn_to_map_order(unsigned long hmm_pfn)
{
	return (hmm_pfn >> HMM_PFN_ORDER_SHIFT) & 0x1F;
}
```

> `hmm_pfn_to_map_order()` 的价值: GPU 页表项越大越小号开销越小。镜像时若发现 CPU 用
> 2M 大页, GPU 也可以直接建一个 2M 项, 不用拆成 512 个 4K 项。

## 4. API 的历史演进 (读老代码/老博客时不迷路)

| 年代 | API | 状态 |
|-|-|-|
| ~2014-2019 | `hmm_mirror` / `hmm_range_register` / `hmm_range_snapshot` | 已删除 |
| 2019 (5.x) | 合并进 `mmu_interval_notifier` + 简化后的 `hmm_range_fault` | **现行 (v6.8)** |
| 未来 | SVM 技术更广泛的抽象 (Xe 驱动等仍在演进) | 进行中 |

演进方向: 内核反复瘦身 HMM —— 把"怎么订阅页表变化"交给通用 `mmu_notifier`,
HMM 只剩"页表快照"这一件事。

## 5. 与 `get_user_pages()` (GUP) 的对比

| | GUP | hmm_range_fault |
|-|-|-|
| 目的 | 拿页并**pin 住** (DMA 期间不许迁移) | 拿页表**快照**, 不 pin, 允许后续迁移/回收 |
| 对页表的影响 | 提升 refcount, 可能强制缺页 | 读侧遍历; 需要时也会 `handle_mm_fault` 补齐 |
| 适用设备 | 网卡/存储等短期 DMA | GPU 长期共享地址空间 |
| 与设备内存配合 | 不能 pin ZONE_DEVICE 页 | 原生理解 device-private 页 |

> HMM 文档原话: *"This is similar to get_user_pages(), except that it can read the
> page tables without mutating them (ie causing faults)."* — "similar" 但目标完全不同。
