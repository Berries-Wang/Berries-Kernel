## 1. 数据结构架构：NUMA 节点 → zone → 伙伴系统

### 1.1 三层结构总图

物理内存按 **Node(节点) → Zone(区域) → page block / page(页)** 三层组织。UMA 机器上只有 1 个 Node；NUMA 机器上每个 Node 对应一个 CPU 汇聚点（socket），本地内存访问快、跨 Node 访问慢（所以才有 zonelist 回退，见 1.6）。


### 1.2 pglist_data —— 一个 NUMA 节点

```c
/* include/linux/mmzone.h:1473 */
typedef struct pglist_data {
	struct zone node_zones[MAX_NR_ZONES];      /* :1479 本节点的 zone 数组 */
	struct zonelist node_zonelists[MAX_ZONELISTS]; /* :1486 分配回退顺序表 */
	int nr_zones;                              /* :1488 本节点已填充 zone 数 */
	...
	unsigned long node_start_pfn;              /* :1510 本节点起始 PFN */
	unsigned long node_present_pages;          /* :1511 实际存在的物理页总数 */
	unsigned long node_spanned_pages;          /* :1512 跨度(含洞) */
	int node_id;                               /* :1514 */
	...
	struct task_struct *kswapd;                /* :1527 页回收内核线程 */
	...
#ifdef CONFIG_COMPACTION
	struct task_struct *kcompactd;             /* :1537 内存规整内核线程 */
#endif
```

- UMA 时整个机器就一个 `pglist_data`（即 `contig_page_data`，见 `mm/page_alloc.c` 中 `NODE_DATA(0)` 的用法）。
- `node_zonelists` 的下标含义见 1.6：`ZONELIST_FALLBACK`（允许跨节点回退）与 `ZONELIST_NOFALLBACK`（`__GFP_THISNODE` 专用，仅本节点），枚举定义在 mmzone.h:1386-1393。

### 1.3 zone —— 按"用途/物理地址约束"再切一刀

同一个 Node 的内存再按**物理地址区间与用途**分成若干 zone，原因是历史遗留的 DMA 约束与高端内存：

| zone | 定义位置 | 含义（x86-64 典型情况） |
|---|---|---|
| `ZONE_DMA` | mmzone.h:884 | 旧 ISA 设备只能 DMA 到低 16MB |
| `ZONE_DMA32` | mmzone.h:887 | 32 位 DMA 设备：低于 4GB |
| `ZONE_NORMAL` | mmzone.h:894 | 常规内存，内核直接线性映射区的主要来源 |
| `ZONE_HIGHMEM` | mmzone.h:904 | 32 位特有；64 位上不存在 |
| `ZONE_MOVABLE` | mmzone.h:955 | 只放可迁移页，服务于内存热插拔/大页 |
| `ZONE_DEVICE` | mmzone.h:957 | 设备内存（HMM/PMEM），`ZONE_DEVICE` 专属 |

枚举本体：`enum zone_type`（mmzone.h:872），`__MAX_NR_ZONES`（mmzone.h:959）= `MAX_NR_ZONES`。

```c
/* include/linux/mmzone.h:967 */
struct zone {
	unsigned long _watermark[NR_WMARK];   /* :971  min/low/high/promo 水位 */
	unsigned long watermark_boost;        /* :972  外碎片化时临时抬高水位 */
	long lowmem_reserve[MAX_NR_ZONES];    /* :986  保护低位 zone 的预留页数 */
	...
	struct pglist_data *zone_pgdat;       /* :991  回指所属节点 */
	struct per_cpu_pages __percpu *per_cpu_pageset; /* :992  PCP */
	...
	unsigned long zone_start_pfn;         /* :1011 */
	atomic_long_t managed_pages;          /* :1055  伙伴系统管理的页数 */
	...
	/* Write-intensive fields used from the page allocator */
	struct free_area free_area[NR_PAGE_ORDERS]; /* :1087 伙伴系统核心! */
	...
	spinlock_t lock;                      /* :1101 主要保护 free_area */
	...
} ____cacheline_internodealigned_in_smp;
```

两个易混点：
- `lowmem_reserve[]`：`GFP_KERNEL` 的 `highest_zoneidx = ZONE_NORMAL`，它**可以**降级用 DMA32/DMA 的页，但必须给低 zone 留出 `lowmem_reserve`，防止高位 zone 的分配把低 zone 榨干（mmzone.h:977-986 注释）。
- `managed_pages` ≠ 物理总页数：`managed_pages = present_pages - reserved_pages`（memblock 等 bootmem 保留的不算），mmzone.h:1026-1029。

### 1.4 free_area + migratetype —— 伙伴系统的两张表

伙伴系统把空闲页块按两个维度组织：**阶 order**（块大小 = 2^order 页）和**迁移类型 migratetype**（抗外碎片化）。

```c
/* include/linux/mmzone.h:192 */
struct free_area {
	struct list_head free_list[MIGRATE_TYPES]; /* :193 每种 migratetype 一条 */
	unsigned long nr_free;                     /* :194 本阶空闲"页块"数 */
};
```

阶的上限：`MAX_PAGE_ORDER = 10`（mmzone.h:31，除非架构改配 mmzone.h:33），即最大块 = 2^10 页 = 4MB；数组长度 `NR_PAGE_ORDERS = MAX_PAGE_ORDER + 1`（mmzone.h:39）。

```c
/* include/linux/mmzone.h:118 */
enum migratetype {
	MIGRATE_UNMOVABLE,   /* :119 不可迁移: 内核数据结构、slab 等 */
	MIGRATE_MOVABLE,     /* :120 可迁移: 用户页、页缓存页 */
	MIGRATE_RECLAIMABLE, /* :121 可回收: inode/dentry cache 等 */
	MIGRATE_PCPTYPES,    /* :122 = 3, PCP 只跟踪上面三种 */
	MIGRATE_HIGHATOMIC = MIGRATE_PCPTYPES, /* :123 高阶原子分配预留 */
	MIGRATE_CMA,         /* :135 CONFIG_CMA: CMA 专用 pageblock */
	MIGRATE_ISOLATE,     /* :141 隔离(热插拔/规整), 不可分配 */
	MIGRATE_TYPES
};
```

migratetype 的粒度是 **pageblock**（默认 `pageblock_order` 阶，通常 = PMD 阶，见 `include/linux/pageblock-flags.h:66/71`；ARM64 4K 页 = 2MB）。**"伙伴"的判定**：两个块起始 PFN 仅在 order 那一位不同——合并逻辑在 `__free_one_page()`（page_alloc.c:934，通过 `find_buddy_page_bfn()` 找伙伴，见 2.4）。

同类不足时允许"挪用"其它 migratetype 的页块，回退顺序表：

```c
/* mm/page_alloc.c:1915 */
static int fallbacks[MIGRATE_PCPTYPES][MIGRATE_PCPTYPES - 1] = {
	[MIGRATE_UNMOVABLE]   = { MIGRATE_RECLAIMABLE, MIGRATE_MOVABLE   },
	[MIGRATE_MOVABLE]     = { MIGRATE_RECLAIMABLE, MIGRATE_UNMOVABLE },
	[MIGRATE_RECLAIMABLE] = { MIGRATE_UNMOVABLE,   MIGRATE_MOVABLE   },
};
```

7.1.3 注意：挪用被拆成两步（`__rmqueue_claim` 整块改类型 + `__rmqueue_steal` 直接偷页，见 2.2），不再是一个 `__rmqueue_fallback`。

### 1.5 per_cpu_pages (PCP) —— 每 CPU 页缓存

order-0（以及"廉价"高阶，见下）分配不直接碰 `zone->lock`，而是先走每 CPU 缓存，减少锁竞争、提升缓存命中率：

```c
/* include/linux/mmzone.h:832 */
struct per_cpu_pages {
	spinlock_t lock;    /* :833 */
	int count;          /* :834 链表中的页数 */
	int high;           /* :835 高水位: 超过则批量归还伙伴系统 */
	int batch;          /* :838 批量补充/归还的粒度 */
	...
	/* Lists of pages, one per migrate type stored on the pcp-lists */
	struct list_head lists[NR_PCP_LISTS]; /* :847 */
};
```

`NR_PCP_LISTS`（mmzone.h:815）= 低阶列表 + THP 专属列表：
- 低阶：`NR_LOWORDER_PCP_LISTS = MIGRATE_PCPTYPES * (PAGE_ALLOC_COSTLY_ORDER + 1)`（mmzone.h:814），即 order 0..3 × 3 种 migratetype；
- THP：`NR_PCP_THP = 2`（mmzone.h:810，开 CONFIG_TRANSPARENT_HUGEPAGE 才有）。

哪些阶能走 PCP 由 `pcp_allowed_order()`（page_alloc.c:673）判断：order ≤ `PAGE_ALLOC_COSTLY_ORDER`(=3) 或 PMD 阶。下标换算 `order_to_pindex()`（page_alloc.c:640）。

### 1.6 zonelist / zoneref —— NUMA 的回退顺序（NUMA 核心）

本地 zone 不够用时按 zonelist 顺序依次尝试其它 zone/node。`zonelist` 就是一个 `zoneref` 数组，`zoneref` 缓存了 `zone*` 和 `zone_idx` 避免反复解引用：

```c
/* include/linux/mmzone.h:1401 */
struct zoneref {
	struct zone *zone;  /* 指向目标 zone */
	int zone_idx;       /* zone_type 下标 */
};

/* include/linux/mmzone.h:1420 */
struct zonelist {
	struct zoneref _zonerefs[MAX_ZONES_PER_ZONELIST + 1]; /* :1421 末尾 NULL 哨兵 */
};
```

每个节点有两套 zonelist（mmzone.h:1386-1393）：

| zonelist | 用途 |
|---|---|
| `node_zonelists[ZONELIST_FALLBACK]` | 常规分配：本 node 的 zone 优先，之后按"距离"升序排远端 node |
| `node_zonelists[ZONELIST_NOFALLBACK]` | `__GFP_THISNODE` 分配：只含本 node 的 zone |

**构建过程**（开机/热插拔时 `build_all_zonelists()`，page_alloc.c:5860 → NUMA 版 `build_zonelists()` page_alloc.c:5675）：

```text
 build_zonelists(pgdat)                    page_alloc.c:5675
   └─ find_next_best_node(local_node, &used_mask)   page_alloc.c:5587
        每次从未用节点中挑出 node_distance 最近者,
        同距离的轮流挑(round-robin, 避免压垮同一个远端节点)
   └─ build_zonelists_in_node_order(...)
        按 [local node zones(高位 zone 在前)] → [远端 node zones...] 填 _zonerefs[]
        日志: "Fallback order for Node %d: 0 1 2 ..."
```

运行时遍历用宏 `for_each_zone_zonelist`（mmzone.h:1914），水位检查失败或分配失败就 `continue` 到下一个 zone——这正是 `get_page_from_freelist()` 主循环的骨架（2.2）。

### 1.7 struct page 与 struct slab —— 同一块内存的两种身份

- 每个物理页一个 `struct page`（`include/linux/mm_types.h:79`），组成 `vmemmap`（SPARSEMEM）或 `mem_map`（FLATMEM，mmzone.h:1429）。`pfn_to_page(pfn)` 即查这张表。
- SLUB 把 slab 所在页的第一个 `struct page` **原地重解释**为 `struct slab`（`mm/slab.h:74`，用 `SLAB_MATCH` 静态断言字段对齐，mm/slab.h:94-102）：

```c
/* mm/slab.h:74 */
struct slab {
	memdesc_flags_t flags;
	struct kmem_cache *slab_cache;   /* 所属缓存 */
	struct {
		struct list_head slab_list;  /* 挂在 partial 链表上 */
		struct freelist_counters;    /* mm/slab.h:41: freelist 指针+计数器 */
	};
	...
};
```

### 1.9 SLUB 侧的数据结构（kmem_cache 家族）

7.1.3 对 SLUB 做了大手术：**原来的 `struct kmem_cache_cpu`（per-CPU freelist + tid）被"per-CPU sheaves（草垛）"取代**，`struct kmem_cache` 从 `include/linux/slub_def.h`（5.9 时代）移到了 `mm/slab.h:198`。

```text

  │                           ├─ main   当前取对象的"草垛" (slub.c:422)
  │                           ├─ spare  备胎 (空或满, slub.c:423)

  │                                 ▼

  │                            void *objects[];           指针数组,末尾栈式取放
  │
  ├─ per_node[MAX_NUMNODES]              mm/slab.h:251 ──┐ 每节点一组
  │   struct kmem_cache_per_node_ptrs    mm/slab.h:190   ▼
```

## 2. 内核内存是如何分配的

### 2.1 路径选择：三条路

```text
 内核代码要内存
   │
   ├─ 小对象(≤ KMALLOC_MAX_CACHE_SIZE=8K, slab.h:593)
   │     kmalloc()/kzalloc()/kmem_cache_alloc()  ──────→ [SLUB]  见 2.5
   │
   ├─ 整页/多页连续物理页 (order ≤ 10)
   │     alloc_pages()/__get_free_pages()        ──────→ [伙伴系统] 见 2.2/2.3
   │
   └─ 只要虚拟地址连续、物理可以不连续 (典型: 大缓冲区)
         vmalloc()                               ──────→ [vmalloc] 见 2.6
                │
                ▼  三条路的终点都是伙伴系统
         ┌────────────────────┐
         │  伙伴系统 (buddy)  │←─ SLUB 的 slab 页、vmalloc 的页最终也从这拿
         └────────────────────┘
```

### 2.2 页分配快速路径（fast path）

### 2.3 页分配慢速路径（slow path）

快速路径失败（所有 zone 水位都不够）后进入 `__alloc_pages_slowpath()`（page_alloc.c:4682）。它是一个"逐步加码"的重试循环：

```text

 │
 ├─ ① gfp_to_alloc_flags(): 放宽 alloc_flags        page_alloc.c:4742
 │     (允许用更高优先级, 唤醒 kswapd 等)
 │
 ├─ ② wake_all_kswapds()  唤醒后台回收线程 kswapd    page_alloc.c:4771
 │     └→ 再试一次 get_page_from_freelist()          page_alloc.c:4777
 │
 ├─ ③ __GFP_DIRECT_RECLAIM 且无法紧凑 → 先直接回收   page_alloc.c:4818
 │     __alloc_pages_direct_reclaim()                page_alloc.c:4409
 │       └→ try_to_free_pages()  同步回收若干页后重试
 │
 ├─ ④ __alloc_pages_direct_compact()  直接内存规整    page_alloc.c:4825
 │                                   (定义 page_alloc.c:4137)
 │       └→ try_to_compact_pages(): 把可迁移页挪走, 腾出连续高阶块
 │          (costly order 或 非MOVABLE高阶 分配会先做这步, page_alloc.c:4731)
```

> 学习提示：水位线是整个 slow path 的"闸门"——每一步加码后都是重试 `get_page_from_freelist()`，只是 alloc_flags 允许的水位越来越低（WMARK_LOW → WMARK_MIN → 无视水位 `ALLOC_NO_WATERMARKS`）。水位语义见第 5 节。

### 2.5 SLUB / kmalloc（7.1.3 新机制：per-CPU sheaves）

**7.1.3 起快路径不再用 `kmem_cache_cpu.freelist + tid`，改为每 CPU 两捆"草垛"(sheaf) 无锁倒换**：`main` 垛从末尾发对象，发空了就换 `spare`，spare 也没有就找 barn 要 / 造新 slab。

## 3. GFP 标志：一次分配的"属性表"

GFP（Get Free Pages）掩码决定分配从哪拿、能否睡眠回收、属于哪种 migratetype：

| 常用组合 | 定义 (include/linux/gfp_types.h) | 含义 |
|---|---|---|
| `GFP_ATOMIC` | gfp_types.h:376 | 原子上下文(中断/持锁)，不睡眠不回收 |
| `GFP_KERNEL` | gfp_types.h:377 | 内核普通分配，可睡眠回收（最常用） |
| `GFP_USER` | gfp_types.h:382 | 用户进程内存，加 `__GFP_HARDWALL` |
| `__GFP_DMA`/`__GFP_DMA32` | gfp_types.h | zone 修饰位：限定从哪个 zone 拿 |
| `__GFP_MOVABLE`/`__GFP_RECLAIMABLE` | gfp_types.h | migratetype 修饰位 |
| `__GFP_THISNODE` | gfp_types.h:84 | 只在本节点分配（NOFALLBACK zonelist） |
| `__GFP_ZERO`/`__GFP_NOFAIL`/`__GFP_ACCOUNT` | gfp_types.h | 清零 / 不许失败 / memcg 记账 |

## 5. 水位线 watermark：分配的"闸门"

```c
/* include/linux/mmzone.h:796 */
enum zone_watermarks {
	WMARK_MIN,   /* :797 紧急预留: 只有 ALLOC_NO_WATERMARKS(PF_MEMALLOC) 能碰 */
	WMARK_LOW,   /* :798 快速路径默认检查线, 低于即唤醒 kswapd */
	WMARK_HIGH,  /* :799 kswapd 回收目标: 回收到这以上就停 */
	WMARK_PROMO, /* :800 NUMA balancing 促晋升阈值 */

```

## 6. 5.9 → 7.1.3 差异对照
