## 0. 阅读地图

```text
                      "内核内存类型" = 5 个正交维度 + 1 个横切维度
   ┌──────────────────────────────────────────────────────────────────┐
   │ 维度一 [第 2 节] 按用途(回收视角):  匿名页 / 文件页(page cache)  │
   │                  / shmem / swapcache / 内核自用页               │
   │                  → 回收子系统(vmscan)关心, 对应 LRU 五条链表      │
   │                                                                  │
   │ 维度二 [第 3 节] 按身份(户口):  page->_page_type                  │
   │                  buddy / slab / table / hugetlb / ...            │
   │                  → "这页现在被谁占用"                            │
   │                                                                  │
   │ 维度三 [第 4 节] 按迁移能力:  MIGRATE_UNMOVABLE / MOVABLE / ...   │
   │                  → 伙伴系统反碎片, pageblock 粒度                │
   │                                                                  │
   │ 维度四 [第 5 节] 按物理地址约束:  ZONE_DMA / NORMAL / MOVABLE...  │
   │                  → DMA 掩码 / 高端内存 / 内存热插拔              │
   │                                                                  │
   │ 维度五 [第 6 节] 按内核虚拟地址空间(arm64):                       │
   │                  线性映射 / vmalloc / vmemmap / fixmap / modules │
   │                                                                  │
   │ 横切维度 [第 7 节] 大页家族:  compound / THP / hugetlb + ZONE_DEVICE│
   │ 第 8 节  PG_* 页标志(状态, 不是类型, 但有"身份位")               │
   │ 第 9 节  一页的一生(状态流转图)                                   │
   │ 第 10 节 混淆点 FAQ  第 11 节 file:line 速查表                   │
   └──────────────────────────────────────────────────────────────────┘
```

**一句话总纲**: 同一张物理页, 在 `vmscan` 眼里它是"匿名页", 在伙伴系统眼里它是"MIGRATE_MOVABLE", 在 `zone` 视角它属于"ZONE_NORMAL", 在 slab 手里它的 `page_type` 是 `PGTY_slab` —— 四个标签同时成立, 互不矛盾。

## 1. 全景图: 一个 struct page, 多张"类型标签"

每个物理页帧(frame)对应一个 `struct page`(mm_types.h:79)。所谓"内存类型", 就是内核在不同时机往这个结构体的不同字段写入的不同标签:

```text
                        struct page (mm_types.h:79)
        ┌───────────────────────────────────────────────────────┐
        │ flags        ← 维度一的"身份位"(PG_swapbacked 等)      │
        │               + 第 8 节的各种状态位 PG_dirty/PG_lru... │
        │ {lru|buddy_list|mapping|index|private}  ← 用途维度的载体│
        │ page_type ── ← 维度二: buddy/slab/table/hugetlb/...    │
        │   (或 _mapcount, 二者复用同一个 4 字节!)                │
        │ _refcount                                               │
        └───────────────────────────────────────────────────────┘
             │                │                  │
             ▼                ▼                  ▼
   ┌────────────────┐ ┌────────────────┐ ┌──────────────────┐
   │ 维度一: 用途    │ │ 维度二: 身份    │ │ 维度三: 迁移能力   │
   │ 匿名页/文件页/  │ │ page_type 值    │ │ migratetype       │
   │ shmem/内核页    │ │ (谁在占用)      │ │ (pageblock 粒度)  │
   └────────────────┘ └────────────────┘ └──────────────────┘
             │                                      │
             ▼                                      ▼
   ┌────────────────┐                    ┌──────────────────────┐
   │ LRU 五条链表:    │                    │ 维度四: zone         │
   │ anon×2/file×2/  │                    │ DMA/DMA32/NORMAL/    │
   │ unevictable     │                    │ MOVABLE/DEVICE       │
   └────────────────┘                    └──────────────────────┘

   维度五(第 6 节)与物理页无关, 是【虚拟地址空间】的区域划分(arm64)。
   横切(第 7 节): 大页家族(PG_head 复合页)可以套在上述多数类型之上。
```

## 2. 维度一: 按用途分类 —— 回收子系统(vmscan)的视角

这是最常考、也最容易混的维度。官方定义在内核自带文档 concepts.rst:128-172, 原文要点:

- **Page cache(文件页)**: "Whenever a file is read, the data is put into the `page cache`... The written pages are marked as `dirty`"(concepts.rst:128-139)
- **Anonymous memory(匿名页)**: "memory that is not backed by a filesystem. Such mappings are implicitly created for program's stack and heap or by explicit calls to mmap(2)"(concepts.rst:140-155)
- **reclaimable/unreclaimable**: 可回收(页缓存+匿名页, 可丢弃或换出) vs 不可回收(内核数据、DMA 缓冲)(concepts.rst:157-172)

### 2.1 匿名页(anonymous page)的诞生: 缺页异常

匿名页在**第一次写访问**时才分配物理页; **只读访问**连页都不分配, 直接映射全局零页。看 `do_anonymous_page`(memory.c:5337), 两条路径都在这里:

```c
/* mm/memory.c:5337 */
static vm_fault_t do_anonymous_page(struct vm_fault *vmf)
{
	struct vm_area_struct *vma = vmf->vma;
	...
	/* File mapping without ->vm_ops ? */
	if (vma->vm_flags & VM_SHARED)          /* :5347 共享映射走文件路径,   */
		return VM_FAULT_SIGBUS;             /*      纯匿名映射必是私有的  */
	...
	/* Use the zero-page for reads */
	if (!(vmf->flags & FAULT_FLAG_WRITE) &&         /* :5358 只读缺页 */
			!mm_forbids_zeropage(vma->vm_mm)) {
		entry = pte_mkspecial(pfn_pte(zero_pfn(vmf->address),
						vma->vm_page_prot));  /* :5360 映射全局零页,
						        不分配物理页! */
		...
		set_pte_at(vma->vm_mm, addr, vmf->pte, entry);
		...
		goto unlock;
	}

	/* Allocate our own private page. */
	ret = vmf_anon_prepare(vmf);
	...
	folio = alloc_anon_folio(vmf);          /* :5392 写缺页: 真正分配,
	                                            可能一次给多页(mTHP) */
	...
	map_anon_folio_pte_pf(folio, vmf->pte, vma, addr, ...);  /* :5429 挂 rmap */
```

- 读路径映射的**零页**是全局共享的只读页, 定义见 pgtable.h:1957 注释: *"ZERO_PAGE() is global shared page(s) that is always zero"*。
- `alloc_anon_folio`(memory.c:5216)根据 VMA 的 THP 策略可能一次分配 order>0 的复合页(见第 7 节)。

### 2.2 匿名页的"身份登记": folio->mapping 的最低位

匿名页和文件页**共用 `struct page` 的同一批字段**(mm_types.h:88-116 的 union), 内核靠 `mapping` 指针的**最低 2 个比特**区分指向的是 `anon_vma` 还是文件的 `address_space`:

```c
/* include/linux/page-flags.h:690 (原注释, 讲清了整个设计) */
/*
 * On an anonymous folio mapped into a user virtual memory area,
 * folio->mapping points to its anon_vma, not to a struct address_space;
 * with the FOLIO_MAPPING_ANON bit set to distinguish it.  See rmap.h.
 *
 * On an anonymous folio in a VM_MERGEABLE area, if CONFIG_KSM is enabled,
 * the FOLIO_MAPPING_ANON_KSM bit may be set along with the FOLIO_MAPPING_ANON
 * bit; and then folio->mapping points, not to an anon_vma, but to a private
 * structure which KSM associates with that merged folio.  See ksm.h.
 ...
 */

/* include/linux/page-flags.h:711 */
#define FOLIO_MAPPING_ANON	0x1
#define FOLIO_MAPPING_ANON_KSM	0x2
#define FOLIO_MAPPING_KSM	(FOLIO_MAPPING_ANON | FOLIO_MAPPING_ANON_KSM)
#define FOLIO_MAPPING_FLAGS	(FOLIO_MAPPING_ANON | FOLIO_MAPPING_ANON_KSM)

/* include/linux/page-flags.h:716 */
static __always_inline bool folio_test_anon(const struct folio *folio)
{
	return ((unsigned long)folio->mapping & FOLIO_MAPPING_ANON) != 0;
}
```

登记动作在 rmap.c 的 `__folio_set_anon`(rmap.c:1463), 关键一句就是**指针加 0x1**:

```c
/* mm/rmap.c:1463 */
static void __folio_set_anon(struct folio *folio, struct vm_area_struct *vma,
			     unsigned long address, bool exclusive)
{
	struct anon_vma *anon_vma = vma->anon_vma;
	...
	/*
	 * If the folio isn't exclusive to this vma, we must use the _oldest_
	 * possible anon_vma for the folio mapping!
	 */
	if (!exclusive)
		anon_vma = anon_vma->root;          /* :1475 非独占 → 挂到最老根 */
	...
	WRITE_ONCE(folio->mapping, (struct address_space *) anon_vma);
	                        /* :1484 实际写入时指针已 += FOLIO_MAPPING_ANON */
```

> **记忆锚点**: 匿名页 = `mapping` 最低位是 1(指向 anon_vma); 文件页 = `mapping` 最低位是 0(指向 address_space)。判断函数 `folio_test_anon()` 只看这一个比特。

### 2.3 匿名页的两个重要标志位

| 标志 | 定义位置 | 含义 |
|---|---|---|
| `PG_swapbacked` | page-flags.h:111 | "Page is backed by RAM/swap" —— 页的**后备存储是 swap**, 决定它挂哪条 LRU(见 2.5), 匿名页、shmem 页都置位 |
| `PG_anon_exclusive` | page-flags.h:146 | 匿名页**独占**标志(映射进页表且没被共享), COW 与 fork 的核心判断, 详见原注释(page-flags.h:139-145) |

fork 后的 COW(写时复制): 父子进程先共享同一物理页; 谁先写谁触发 `wp_page_copy`(memory.c:3853)复制出新页, 新页通过 `folio_move_anon_rmap`(rmap.c:1430)**换到自己的 anon_vma** 下, 原注释写得非常清楚:

```c
/* mm/rmap.c:1422 (函数文档注释) */
/**
 * folio_move_anon_rmap - move a folio to our anon_vma
 * @folio:	The folio to move to our anon_vma
 * @vma:	the vma the folio belongs to
 *
 * When a folio belongs exclusively to one process after a COW event,
 * that folio can be moved into the anon_vma that belongs to just that
 * process, so the rmap code will not search the parent or sibling processes.
 */
```

### 2.4 文件页(page cache)

文件页挂在**文件的 `address_space`** 上(`inode->i_mapping`), 通过 XArray 树按页偏移索引。读文件 → 先查缓存; 写文件 → 改缓存页并置 `PG_dirty`(page-flags.h:98), 由回写线程刷盘。插入缓存的入口是 `filemap_add_folio`(filemap.c:950)。

**易混点**: `MAP_PRIVATE` 的文件映射, 读时共享文件页, **一旦写入就 COW 复制成匿名页**(memory.c:4244 `do_wp_page` → 3853 `wp_page_copy`) —— 同一个 VMA 里可能同时存在文件页和匿名页! 文件页变匿名页后 `mapping` 从 `address_space` 换成 `anon_vma+0x1`。

### 2.5 ★最易混: tmpfs/shmem 页 —— "有文件的匿名页"

shmem(tmpfs)页**有 inode、有 mapping、是页缓存**, 但它的后备存储是 **swap 而不是磁盘文件**, 所以内核把它**按匿名页对待**。证据有三处, 全部 7.1.3 原文:

**证据 1**: shmem 分配页时显式设置 `PG_swapbacked`(shmem.c:1939 `shmem_alloc_and_add_folio` 内):

```c
/* mm/shmem.c:1975-1984 */
		folio = shmem_alloc_folio(gfp, 0, info, index);
	}
	if (!folio)
		return ERR_PTR(-ENOMEM);

allocated:
	__folio_set_locked(folio);
	__folio_set_swapbacked(folio);          /* :1982 shmem 页 = swap 后备 */

	gfp &= GFP_RECLAIM_MASK;
	error = mem_cgroup_charge(folio, fault_mm, gfp);
```

**证据 2**: LRU 的 file/anon 划分**不看有没有文件, 只看 `PG_swapbacked`**(mm_inline.h:13-31, 函数注释原文值得逐字读):

```c
/* include/linux/mm_inline.h:13 */
/**
 * folio_is_file_lru - Should the folio be on a file LRU or anon LRU?
 * @folio: The folio to test.
 ...
 * Return: An integer (not a boolean!) used to sort a folio onto the
 * right LRU list and to account folios correctly.
 * 1 if @folio is a regular filesystem backed page cache folio
 * or a lazily freed anonymous folio (e.g. via MADV_FREE).
 * 0 if @folio is a normal anonymous folio, a tmpfs folio or otherwise
 * ram or swap backed folio.
 */
static inline int folio_is_file_lru(const struct folio *folio)
{
	return !folio_test_swapbacked(folio);       /* :30 唯一判据! */
}
```

**证据 3**: LRU 链表的选择逻辑(mm_inline.h:82):

```c
/* include/linux/mm_inline.h:82 */
static __always_inline enum lru_list folio_lru_list(const struct folio *folio)
{
	enum lru_list lru;
	...
	if (folio_test_unevictable(folio))
		return LRU_UNEVICTABLE;             /* 不可回收链 */

	lru = folio_is_file_lru(folio) ? LRU_INACTIVE_FILE : LRU_INACTIVE_ANON;
	if (folio_test_active(folio))
		lru += LRU_ACTIVE;
	return lru;
}
```

LRU 五条链表的定义(mmzone.h:382-393), 由 2 个比特组合而成:

```c
/* include/linux/mmzone.h:382 */
#define LRU_BASE 0
#define LRU_ACTIVE 1
#define LRU_FILE 2

enum lru_list {
	LRU_INACTIVE_ANON = LRU_BASE,                   /* :387 挂匿名页+shmem */
	LRU_ACTIVE_ANON = LRU_BASE + LRU_ACTIVE,
	LRU_INACTIVE_FILE = LRU_BASE + LRU_FILE,        /* :389 普通文件页 */
	LRU_ACTIVE_FILE = LRU_BASE + LRU_FILE + LRU_ACTIVE,
	LRU_UNEVICTABLE,                                /* :391 mlock 等 */
	NR_LRU_LISTS
};
```

**结论表**(本文最重要的一张表):

| 页类型 | mapping 指向 | PG_swapbacked | 挂哪条 LRU | 满了怎么办 |
|---|---|---|---|---|
| 匿名页 | anon_vma(+0x1) | ✅ | anon LRU | swap out |
| shmem/tmpfs 页 | shmem inode 的 address_space | ✅ | **anon LRU** | swap out |
| 普通文件页 | 文件 inode 的 address_space | ❌ | file LRU | 直接丢弃(脏页先回写) |
| MADV_FREE 后的匿名页(lazyfree) | anon_vma(+0x1) | ❌(被清掉) | **file LRU** | 直接丢弃(没被再写的话) |

> **记忆口诀**: LRU 的 file/anon 分组问的是"**后备存储是不是 swap**", 不是"有没有文件"。shmem 有文件但走匿名通道; lazyfree 是匿名页但走文件通道。

lazyfree 的判断代码(page-flags.h:721):

```c
/* include/linux/page-flags.h:721 */
static __always_inline bool folio_test_lazyfree(const struct folio *folio)
{
	return folio_test_anon(folio) && !folio_test_swapbacked(folio);
}
```

`MADV_FREE` 清除 `PG_swapbacked`(mm/swap.h:348 声明的 `folio_mark_lazyfree`, 调用点 madvise.c:772), 之后若进程没再写这页, 回收时直接丢, 免去 swap 写入; 再写了就重置回匿名页。

### 2.6 swap cache 页

匿名页换出/换入时的中转站, 标志 `PG_swapcache`(page-flags.h:135, 注意它是**别名位**, 复用 `PG_owner_priv_1`, 见第 8 节)。此时 `page->private` 存的是 `swp_entry_t`(mm_types.h:108-114 注释原文)。换入路径入口 `do_swap_page`(memory.c:4795)。

### 2.7 内核自用页(不进 LRU)

| 类型 | 计数项(mmzone.h) | 标记 | 说明 |
|---|---|---|---|

几个容易读错的字段(全部可由上面代码反推):

- **Cached 包含 Shmem 页**(NR_FILE_PAGES 统计所有页缓存, tmpfs 页也在其中, 减掉的只有 swapcache 和 buffers, meminfo.c:48-51)。
- **AnonPages = NR_ANON_MAPPED**(mmzone.h:257, "Mapped anonymous pages"): 只统计**当前映射进页表**的匿名页; 已 swap out 的不在内。
- **Active(anon)+Inactive(anon) 包含 shmem 页**(它们在 anon LRU 上, 见 2.5)。

## 3. 维度二: page->_page_type —— 页的"户口本"

维度一讲的是"页里装的数据从哪来", 维度二回答"**这个页现在被哪个子系统占用**"。7.1.3 把这类信息放在 `page->_page_type` 字段里, 与 `_mapcount` **复用同一个 4 字节 union**(这是 7.x 的新设计, 5.9 时代还是 PG_slab 等 flag 位):

```c
/* include/linux/mm_types.h:154 */
	union {		/* This union is 4 bytes in size. */
		/*
		 * For head pages of typed folios, the value stored here
		 * allows for determining what this page is used for. The
		 * tail pages of typed folios will not store a type
		 * (page_type == _mapcount == -1).
		 *
		 * See page-flags.h for a list of page types which are currently
		 * stored here.
		 ...
		 */
		unsigned int page_type;               /* :169 户口本 */

		/*
		 * For pages that are part of non-typed folios for which mappings
		 * are tracked via the RMAP, encodes the number of times this page
		 * is directly referenced by a page table.
		 ...
		 */
		atomic_t _mapcount;                   /* :180 页表映射计数 */
	};
```

**编码规则**(page-flags.h:908-928 原文):

```c
/* include/linux/page-flags.h:908 */
/*
 * For pages that do not use mapcount, page_type may be used.
 * The low 24 bits of pagetype may be used for your own purposes, as long
 * as you are careful to not affect the top 8 bits.  The low bits of
 * pagetype will be overwritten when you clear the page_type from the page.
 */
enum pagetype {
	/* 0x00-0x7f are positive numbers, ie mapcount */
	/* Reserve 0x80-0xef for mapcount overflow. */
	PGTY_buddy		= 0xf0,   /* 空闲页, 在伙伴系统里(order 存 private) */
	PGTY_offline		= 0xf1,   /* 逻辑下线(balloon/热插拔) */
	PGTY_table		= 0xf2,   /* 页表页 */
	PGTY_guard		= 0xf3,   /* debug_pagealloc 的守卫页 */
	PGTY_hugetlb		= 0xf4,   /* hugetlb 预留大页 */
	PGTY_slab		= 0xf5,   /* SLUB/SLOB 对象页 */
	PGTY_zsmalloc		= 0xf6,   /* zram 压缩存储页 */
	PGTY_unaccepted		= 0xf7,   /* 机密内存(TDX/SNP)未接受页 */
	PGTY_large_kmalloc	= 0xf8,   /* kmalloc 大页(order>0/整页) */

	PGTY_mapcount_underflow = 0xff
};
```

**互斥关系**: 一个页**要么有类型(0xf0-0xf8), 要么有 mapcount(0x00-0x7f), 二者不共存** —— 有类型的页(slub 页/页表页/伙伴系统页)不记录页表映射数; 记录映射数的页(匿名页/文件页)没有类型。判断函数与设置/清除宏:

```c
/* include/linux/page-flags.h:941 */
static inline bool page_has_type(const struct page *page)
{
	return page_type_has_type(data_race(page->page_type));
}

/* include/linux/page-flags.h:967 (以 Slab 为例的访问器生成宏) */
#define PAGE_TYPE_OPS(uname, lname, fname)				\
FOLIO_TYPE_OPS(lname, fname)						\
static __always_inline int Page##uname(const struct page *page)	\
{									\
	return data_race(page->page_type >> 24) == PGTY_##lname;	\
}									\
	...
```

各类型的注册点(page-flags.h): `PageBuddy/PGTY_buddy`:992、`PageOffline`:1023、`PageTable/PGTY_table`:1033、`PageGuard`:1038、`PageSlab`:1040、`folio_test_hugetlb/PGTY_hugetlb`:1042、`PageZsmalloc`:1048。

> **维度一 vs 维度二的关系**: 匿名页/文件页**没有** page_type(它们的 `_mapcount` 用来记映射数); 反过来 slab 页/页表页**不进 LRU、没有 mapping**。所以 `folio_test_anon()` 的注释(page-flags.h:704-708)特别提醒: *"For slab pages, since slab reuses the bits in struct page... please make sure that folio_test_slab(folio) actually evaluates to false before calling the following functions"*。

## 4. 维度三: migratetype —— 迁移能力(反碎片)

伙伴系统把内存按 **pageblock**(通常 2MB, `pageblock_order` 阶)分组, 每个 pageblock 有一个 migratetype, 目的是**抗碎片**: 可移动页聚在一起, 需要连续大页时不至于被钉死的内核页卡住。定义(mmzone.h:118-144 原文):

```c
/* include/linux/mmzone.h:118 */
enum migratetype {
	MIGRATE_UNMOVABLE,      /* 分配后位置固定: 内核数据结构、页表... */
	MIGRATE_MOVABLE,        /* 可迁移: 匿名页、文件页(复制到新页改映射) */
	MIGRATE_RECLAIMABLE,    /* 可回收后挪用: slab 可回收页等 */
	MIGRATE_PCPTYPES,	/* the number of types on the pcp lists */
	MIGRATE_HIGHATOMIC = MIGRATE_PCPTYPES,  /* 高阶原子分配应急池 */
#ifdef CONFIG_CMA
	/* MIGRATE_CMA migration type is designed to mimic the way
	 * ZONE_MOVABLE works.  Only movable pages can be allocated
	 * from MIGRATE_CMA pageblocks and page allocator never
	 * implicitly change migration type of MIGRATE_CMA pageblock. */
	MIGRATE_CMA,            /* CMA 保留区: 平时借给可移动页, 设备要用时收回 */
	__MIGRATE_TYPE_END = MIGRATE_CMA,
#else
	__MIGRATE_TYPE_END = MIGRATE_HIGHATOMIC,
#endif
#ifdef CONFIG_MEMORY_ISOLATION
	MIGRATE_ISOLATE,	/* can't allocate from here */  /* 热插拔隔离 */
#endif
	MIGRATE_TYPES
};
```

`/proc/pagetypeinfo` 里显示的名字来自 page_alloc.c:255:

```c
/* mm/page_alloc.c:255 */
const char * const migratetype_names[MIGRATE_TYPES] = {
	"Unmovable",
	"Movable",
	"Reclaimable",
	"HighAtomic",
#ifdef CONFIG_CMA
	"CMA",
#endif
#ifdef CONFIG_MEMORY_ISOLATION
	"Isolate",
#endif
};
```

**migratetype 从哪来?** 从 GFP 标志推出来(gfp.h:24-40):

```c
/* include/linux/gfp.h:24 */
static inline int gfp_migratetype(const gfp_t gfp_flags)
{
	...
	if (unlikely(page_group_by_mobility_disabled))
		return MIGRATE_UNMOVABLE;

	/* Group based on mobility */
	return (__force unsigned long)(gfp_flags & GFP_MOVABLE_MASK) >> GFP_MOVABLE_SHIFT;
}
```

对应关系(`___GFP_MOVABLE`/`___GFP_RECLAIMABLE` 定义在 gfp_types.h:66-67, 111, 145):

| GFP 标志 | migratetype | 典型分配 |
|---|---|---|
| (无) | `MIGRATE_UNMOVABLE` | `GFP_KERNEL` 内核普通分配 |
| `__GFP_MOVABLE` | `MIGRATE_MOVABLE` | `GFP_HIGHUSER_MOVABLE` 用户匿名页、页缓存 |
| `__GFP_RECLAIMABLE` | `MIGRATE_RECLAIMABLE` | slab 可回收缓存 |
| 两者同置 | `MIGRATE_HIGHATOMIC` | 高阶原子分配(由 gfp.h:31 的 BUILD_BUG_ON 固定) |

某类 pageblock 不够时会按 `fallbacks[MIGRATE_TYPES][3]`(page_alloc.c)借别的类型的块, 这就是碎片治理的核心逻辑(详见姊妹篇 007)。

## 5. 维度四: zone_type —— 物理地址约束

zone 按**物理地址区间与硬件约束**划分, 定义在 mmzone.h:873-959(注释很详尽, 节选):

```c
/* include/linux/mmzone.h:873 */
enum zone_type {
	/*
	 * ZONE_DMA and ZONE_DMA32 are used when there are peripherals not able
	 * to DMA to all of the addressable memory (ZONE_NORMAL).
	 ...
	 */
#ifdef CONFIG_ZONE_DMA
	ZONE_DMA,               /* :884 老 ISA 设备只能 DMA 低 16MB(x86) */
#endif
#ifdef CONFIG_ZONE_DMA32
	ZONE_DMA32,             /* :887 32 位 DMA 掩码设备 */
#endif
	/*
	 * Normal addressable memory is in ZONE_NORMAL...
	 */
	ZONE_NORMAL,            /* :894 常规内存, 内核直接映射区来源 */
#ifdef CONFIG_HIGHMEM
	/* ... i386 to allow the kernel to address the memory beyond 900MB ... */
	ZONE_HIGHMEM,           /* :904 32 位架构的高端内存(arm64 没有) */
#endif
	/* ZONE_MOVABLE is similar to ZONE_NORMAL, except that it contains
	 * movable pages with few exceptional cases ... Main use cases are
	 * memory offlining/unplug and to locally limit unmovable allocations
	 * - e.g., to increase the number of THP/huge pages. */
	ZONE_MOVABLE,           /* :955 只放可移动页(热插拔/大页) */
#ifdef CONFIG_ZONE_DEVICE
	ZONE_DEVICE,            /* :957 设备内存(pmem/HMM/DAX) */
#endif
	__MAX_NR_ZONES
};
```

**GFP → zone 的映射**由 `gfp_zone()` 完成(gfp.h:156-165):

```c
/* include/linux/gfp.h:156 */
static inline enum zone_type gfp_zone(gfp_t flags)
{
	enum zone_type z;
	int bit = (__force int) (flags & GFP_ZONEMASK);

	z = (GFP_ZONE_TABLE >> (bit * GFP_ZONES_SHIFT)) &
					 ((1 << GFP_ZONES_SHIFT) - 1);
	VM_BUG_ON((GFP_ZONE_BAD >> bit) & 1);
	return z;
}
```

`___GFP_DMA`/`___GFP_DMA32`/`___GFP_HIGHMEM` 定义在 gfp_types.h:63-65, 108-110。

**arm64 实际情况**: 没有 HIGHMEM; 典型配置只有 `ZONE_DMA`(可配) + `ZONE_NORMAL`(+ `ZONE_MOVABLE` 若配 `movablecore=`) + `ZONE_DEVICE`(若配 DEV_PAGEMAP)。

> **ZONE_MOVABLE vs MIGRATE_MOVABLE**(高频混淆): 前者是 **zone**(一段物理地址区间的属性, 用 `kernelcore=`/`movablecore=` 启动参数圈出来); 后者是 **migratetype**(pageblock 的属性)。两个机制配合: ZONE_MOVABLE 里的 pageblock 全部按 MIGRATE_MOVABLE 对待。mmzone.h:907 的原注释就点名 MIGRATE_CMA 是 *"designed to mimic the way ZONE_MOVABLE works"*。

## 6. 维度五: 内核虚拟地址空间的区域(arm64)

前面四个维度说的是**物理页**; 这一个维度说的是**虚拟地址空间的分区**, 与物理页身份正交。arm64 的内核 VA 布局常量(memory.h:37-54):

```c
/* arch/arm64/include/asm/memory.h:37 */
/*
 * PAGE_OFFSET - the virtual address of the start of the linear map, at the
 *               start of the TTBR1 address space.
 * PAGE_END - the end of the linear map, where all other kernel mappings begin.
 * KIMAGE_VADDR - the virtual address of the start of the kernel image.
 * VA_BITS - the maximum number of bits for virtual addresses.
 */
#define VA_BITS			(CONFIG_ARM64_VA_BITS)
#define _PAGE_OFFSET(va)	(-(UL(1) << (va)))
#define PAGE_OFFSET		(_PAGE_OFFSET(VA_BITS))   /* :45 线性映射起点 */
#define KIMAGE_VADDR		(MODULES_END)             /* :46 内核镜像 */
#define MODULES_END		(MODULES_VADDR + MODULES_VSIZE)
#define MODULES_VADDR		(_PAGE_END(VA_BITS_MIN))  /* :48 模块区 */
#define VMEMMAP_START		(VMEMMAP_END - VMEMMAP_SIZE) /* :50 vmemmap */
#define VMEMMAP_END		(-UL(SZ_1G))
#define PCI_IO_START		(VMEMMAP_END + SZ_8M)
#define PCI_IO_END		(PCI_IO_START + PCI_IO_SIZE)
#define FIXADDR_TOP		(-UL(SZ_8M))              /* :54 fixmap */
```

```text
  arm64 内核空间 (TTBR1, 48-bit VA 典型值)
  0xFFFF_FFFF_FFFF_FFFF ┬─ fixmap(固定映射, 顶部往下 SZ_8M 之下)
                        │─ vmemmap (struct page 数组, -1G 起)
                        │─ PCI I/O
                        ├─ vmalloc / ioremap 区(不连续物理页映射)
                        ├─ 内核镜像 (KIMAGE_VADDR 起, 可 KASLR)
                        ├─ 模块区 (MODULES_VADDR, 128MB)
  PAGE_OFFSET ──────────┴─ 线性映射(linear map): 直接映射全部物理内存
  0xFFFF_0000_0000_0000    phys_to_virt = PA - PHYS_OFFSET + PAGE_OFFSET
```

| 区域 | 用途 | 分配的物理页是什么类型(回到前 4 个维度) |
|---|---|---|
| 线性映射(linear map) | 直接映射全部 RAM, 伙伴系统大部分分配从这里出 | 通常 `MIGRATE_UNMOVABLE`/`ZONE_NORMAL` |
| vmalloc 区 | 物理不连续、虚拟连续(`vmalloc()`/`ioremap()`) | `NR_VMALLOC`(mmzone.h:277)计数 |
| vmemmap | `struct page` 数组自身 | `PG_reserved`, memblock 早期分配 |
| fixmap | 早期启动固定地址映射(bm_pte) | — |
| 模块区 | 内核模块(.ko)代码 | — |

> 计数锚点: `VmallocUsed` 就是 `NR_VMALLOC`(meminfo.c:129-130)。

## 7. 横切维度: 大页家族 + ZONE_DEVICE

前面任何维度的页, 都可能是"复合页"(compound page, order>0 的多页整体)。`PG_head`(page-flags.h:100, 注释 *"Must be in bit 6"*)标记首页, 尾页用 `compound_info`(mm_types.h:128-130)回指:

```c
/* include/linux/mm_types.h:128 */
		struct {	/* Tail pages of compound page */
			unsigned long compound_info;	/* Bit zero is set */
		};
```

### 7.1 三种大页机制对比

| | hugetlb | THP(匿名) | THP(shmem/文件) |
|---|---|---|---|
| 机制 | 启动时**预留**大页池, mmap 用 `MAP_HUGETLB` | 缺页时**透明**分配 PMD 大页, khugepaged 后台合并 | 文件系统支持大 folio |
| 页类型标记 | `PGTY_hugetlb`(page-flags.h:1042) | `PG_head` + 匿名页标志 | `PG_head` + 文件页标志 |
| meminfo | `HugePages_Total` | `AnonHugePages`(=NR_ANON_THPS, meminfo.c:142) | `ShmemHugePages`/`FileHugePages`(meminfo.c:144/148) |
| 尾部浪费 | 预留即占用, 即使没人用 | 按需, 可 split | 按需 |

匿名 THP 的入口就在 2.1 节的 `alloc_anon_folio`(memory.c:5216)—— 它会先问 THP 策略要不要直接给 PMD 阶; 合并后台是 khugepaged。`PG_large_rmappable`(page-flags.h:193)标记"可挂 rmap 的大页"(anon 或 file)。

### 7.2 ZONE_DEVICE: 不在 RAM 里的"内存"

`ZONE_DEVICE` 页是**设备内存**(pmem、GPU HMM、DAX), 不在伙伴系统常规管辖内, struct page 的字段布局都不同(mm_types.h:131-148):

## 9. 一页的一生(状态流转)

一张图串起全部维度 —— 以用户 malloc 后写入的一页为例:

```text
 [伙伴系统] PGTY_buddy(MIGRATE_MOVABLE 的 pageblock, ZONE_NORMAL)
     │ __rmqueue 摘出, 清 PGTY_buddy
     ▼
 [匿名页]  do_anonymous_page 写缺页
     │  mapping=anon_vma+0x1, PG_swapbacked, PG_anon_exclusive
     │  加入 LRU_INACTIVE_ANON
     ▼
 fork ──► 共享(清除 exclusive) ──► 一方写入
     │                               │ wp_page_copy 复制新页(又是匿名页)
     │                               ▼ 新页 exclusive=true
     ▼
 madvise(MADV_FREE) ──► [lazyfree] 清 swapbacked
     │                    转到 LRU_INACTIVE_FILE(回收时可直接丢)
     │ (再次写入则转回匿名页)
     ▼
 内存压力 ──► [swap cache] PG_swapcache, private=swp_entry_t
     │          换出到 swap 设备, 从 LRU 摘除
     ▼
 再次访问 ──► do_swap_page 换入, 回到匿名页状态
     ▼
 进程退出(映射数归零) ──► 回收/释放
     │ 清 PG_swapbacked/mapping=NULL, 置 PGTY_buddy
     ▼
 [伙伴系统] 等待下一次分配(slab? 页表? 又一个匿名页?)
```

> 注意整条链上 **zone 和 migratetype 可能中途变化**(迁移/规整会搬页), 但"用途"身份(mapping 指向谁)只在列出的转换点变化。

## 10. 混淆点 FAQ(自测清单)

**Q1: "匿名页"= AnonPages 吗?**
不严格等于。`AnonPages` = `NR_ANON_MAPPED`(mmzone.h:257), 只统计**当前映射进页表**的匿名页。已换出到 swap 的、在 swapcache 里未被映射的不算。但"匿名页"作为类型, 描述的是 `mapping→anon_vma` 这一身份, 与是否在页表无关。

**Q2: shmem/tmpfs 页到底是文件页还是匿名页?**
**两个口径都要会答**: 按 mapping(数据组织)是文件页(挂在 tmpfs inode 的 address_space 上); 按回收通道(LRU、swap)是匿名页(`PG_swapbacked`, 挂 anon LRU, meminfo 归入 `Inactive(anon)+Active(anon)`, 同时计入 `Shmem` 和 `Cached`)。

**Q3: PG_swapbacked 和 PG_swapcache 什么区别?**
`PG_swapbacked`(page-flags.h:111)= 这页**将来**的后备是 swap(类型属性, 匿名/shmem 页终生携带); `PG_swapcache`(page-flags.h:135)= 这页**现在正在** swap 缓存树里(瞬态, 换入换出时才有)。

**Q4: ZONE_MOVABLE、MIGRATE_MOVABLE、\_\_GFP_MOVABLE 是什么关系?**
同名三兄弟: `__GFP_MOVABLE` 是**分配请求**带的标志(gfp_types.h:66) → `gfp_migratetype()` 把它翻译成 **pageblock 的 migratetype**(MIGRATE_MOVABLE) → `ZONE_MOVABLE` 是更高一层的**物理地址区间**属性(整段 zone 只接待可移动分配)。三者层层传导, 但不是一回事。

**Q5: THP 和 hugetlb 都是大页, 学哪个?**
机制不同: hugetlb 是**预留式**(启动圈地, `PGTY_hugetlb`, 有名映射); THP 是**透明式**(缺页时顺手用大页, khugepaged 后台整理, `PG_head`+普通匿名/文件页标志)。现代内核主推 THP/mTHP(还有 folio 大页化)。

**Q6: page_type、page flags、mapcount 会不会打架?**
不会, 各管一段: `flags` 位域管状态+身份位(swapbacked); `page_type` 与 `_mapcount` 复用同一 4 字节(第 3 节), 有类型的页不记 mapcount。

**Q7: Cached、Shmem、Mapped 怎么互相缠绕?**
`Cached = NR_FILE_PAGES - swapcache - buffers`(meminfo.c:48-51), **包含** shmem 页; `Shmem` 把 tmpfs 部分单列; `Mapped = NR_FILE_MAPPED`(mmzone.h:258)只数**映射进进程页表**的文件页, mmap 了没读的不算。

**Q8: lazyfree 页 "Mapped 在哪"?**
lazyfree 页仍是匿名页(mapping 指向 anon_vma), 计入 `AnonPages`(只要还在页表里), 但因清了 `PG_swapbacked` 而站在 **file LRU** 上(mm_inline.h:24 注释原话)。
