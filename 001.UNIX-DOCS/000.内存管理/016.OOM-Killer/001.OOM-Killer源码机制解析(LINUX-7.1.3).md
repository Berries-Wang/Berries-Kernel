# OOM-Killer 源码机制解析（LINUX-7.1.3）

> 定位：内存分配链走到尽头（快路径 → 直接回收 → 直接压缩 → 反复重试全部失败）时的"杀进程自救"。
> 本文以**两个真实场景**为主线：**场景 A**——内存泄漏进程吃光 RAM+swap 触发**全局 OOM**；**场景 B**——容器内存超限触发 **cgroup(memcg) OOM**。每个环节先给图、再贴源码、最后落到数字演算。
>
> 源码基线：[000.SOURCE_CODE/003.LINUX-7.1.3](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/)（按 [CLAUDE.md](../../../CLAUDE.md) 约定，7.1.3 为主基准；[000.LINUX-5.9](../../../000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9/) 仅作差异对照，见 §12。行号全部 `grep -n` 实测）。

## 1. 触发路径：页分配器如何一步步走到 OOM

### 1.1 慢速路径的末段——`__alloc_pages_slowpath`

回收和压缩都救不回来时，最后一段才轮到 OOM：

```c
// mm/page_alloc.c:4682 （节选：只保留通往 OOM 的主干）
static inline struct page *
__alloc_pages_slowpath(gfp_t gfp_mask, unsigned int order,
						struct alloc_context *ac)
{
	bool can_direct_reclaim = gfp_mask & __GFP_DIRECT_RECLAIM;
	bool nofail = gfp_mask & __GFP_NOFAIL;
	const bool costly_order = order > PAGE_ALLOC_COSTLY_ORDER; // >3 即"昂贵阶"
	...
retry:
	/* 让 kswapd 别睡，一直干活 */
	if (alloc_flags & ALLOC_KSWAPD)
		wake_all_kswapds(order, gfp_mask, ac);

	page = get_page_from_freelist(gfp_mask, order, alloc_flags, ac); // 放宽后再试快路径
	if (page)
		goto got_pg;
	...
	/* Caller is not willing to reclaim, we can't balance anything */
	if (!can_direct_reclaim)          // 例如 GFP_ATOMIC：不允许回收 → 直接失败
		goto nopage;

	/* Avoid recursion of direct reclaim */
	if (current->flags & PF_MEMALLOC) // 回收者自己不递归回收
		goto nopage;

	/* Try direct reclaim and then allocating */
	page = __alloc_pages_direct_reclaim(...);   // 同步直接回收
	if (page)
		goto got_pg;

	/* Try direct compaction and then allocating */
	page = __alloc_pages_direct_compact(...);   // 同步直接压缩
	if (page)
		goto got_pg;
	...
	/* Do not loop if specifically requested */
	if (gfp_mask & __GFP_NORETRY)     // 明确要求不重试 → 失败
		goto nopage;

	/* 昂贵阶(order>3)且不允许 MAYFAIL → 不再重试，直接失败 */
	if (costly_order && (!can_compact ||
			     !(gfp_mask & __GFP_RETRY_MAYFAIL)))
		goto nopage;
	...
	/* 回收重试上限 16 轮(MAX_RECLAIM_RETRIES=16, mm/internal.h:626，判定在
	 * page_alloc.c:4590)；压缩重试另有上限 MAX_COMPACT_RETRIES=16
	 * (page_alloc.c:4132)，两者都到头才走 OOM */
	if (should_reclaim_retry(gfp_mask, order, ac, alloc_flags,
				 did_some_progress > 0, &no_progress_loops))
		goto retry;
	...
	/* Reclaim has failed us, start killing things
	 * 内存回收失败，开始终止进程 —— OOM Killer 在这里被请出来 */
	page = __alloc_pages_may_oom(gfp_mask, order, ac, &did_some_progress);
	if (page)
		goto got_pg;

	/* OOM victim 自己不允许再吃"无水位线"内存，防止它反过来耗尽预留 */
	if (tsk_is_oom_victim(current) &&
	    (alloc_flags & ALLOC_OOM ||
	     (gfp_mask & __GFP_NOMEMALLOC)))
		goto nopage;

	/* Retry as long as the OOM killer is making progress
	 * 只要 OOM Killer 还在"取得进展"（杀了人）就一直重试 */
	if (did_some_progress) {
		no_progress_loops = 0;
		goto retry;
	}

nopage:
	...
fail:
	warn_alloc(gfp_mask, ac->nodemask,
			"page allocation failure: order:%u", order); // page_alloc.c:4961
got_pg:
	return page;
}
```

要点：**OOM 不是第一反应，是第 N 反应**——快路径、直接回收、直接压缩、16 轮重试全失败后才触发；而且杀完进程会回到 `retry` 循环**重新走一遍分配**，`did_some_progress` 记录"这轮 OOM 是否杀了人"。

### 1.2 `__alloc_pages_may_oom`：请出 OOM Killer 前的最后一道闸

```c
// mm/page_alloc.c:4042
static inline struct page *
__alloc_pages_may_oom(gfp_t gfp_mask, unsigned int order,
	const struct alloc_context *ac, unsigned long *did_some_progress)
{
	struct oom_control oc = {
		.zonelist = ac->zonelist,
		.nodemask = ac->nodemask,
		.memcg = NULL,          // 全局 OOM：memcg 为空（memcg OOM 由 memcontrol.c 传入）
		.gfp_mask = gfp_mask,
		.order = order,
	};
	struct page *page;

	*did_some_progress = 0;

	/*
	 * Acquire the oom lock. If that fails, somebody else is
	 * making progress for us.
	 * 全局只有一把 oom_lock(oom_kill.c:68)：抢不到说明别人正在杀，
	 * 等 1 个调度滴答后重试分配即可
	 */
	if (!mutex_trylock(&oom_lock)) {
		*did_some_progress = 1;
		schedule_timeout_uninterruptible(1);
		return NULL;
	}

	/*
	 * 持锁后再扫一遍 freelist（高水位线）：抓"并行的 OOM 已杀完人"的情况；
	 * 内存还是很紧就继续往下走
	 */
	page = get_page_from_freelist((gfp_mask | __GFP_HARDWALL) &
				      ~__GFP_DIRECT_RECLAIM, order,
				      ALLOC_WMARK_HIGH|ALLOC_CPUSET, ac);
	if (page)
		goto out;

	/* Coredumps can quickly deplete all memory reserves */
	if (current->flags & PF_DUMPCORE)          // ① dump core 中不杀
		goto out;
	/* The OOM killer will not help higher order allocs */
	if (order > PAGE_ALLOC_COSTLY_ORDER)       // ② order>3：杀进程也凑不齐大块连续页
		goto out;
	/* 调用方已声明"宁可失败不要杀"（如 FUSE/存储栈回退路径） */
	if (gfp_mask & (__GFP_RETRY_MAYFAIL | __GFP_THISNODE))   // ③
		goto out;
	/* The OOM killer does not needlessly kill tasks for lowmem */
	if (ac->highest_zoneidx < ZONE_NORMAL)     // ④ lowmem（DMA 等低端 zone）不杀
		goto out;
	if (pm_suspended_storage())                // ⑤ 系统挂起(suspend)中不杀
		goto out;

	/* Exhausted what can be done so it's blame time —— 该找人背锅了 */
	if (out_of_memory(&oc) ||
	    WARN_ON_ONCE_GFP(gfp_mask & __GFP_NOFAIL, gfp_mask)) {
		*did_some_progress = 1;            // "杀了人"，调用方据此回到 retry

		/* __GFP_NOFAIL 分配：允许动用全部内存预留（无水位线） */
		if (gfp_mask & __GFP_NOFAIL)
			page = __alloc_pages_cpuset_fallback(gfp_mask, order,
					ALLOC_NO_WATERMARKS, ac);
	}
out:
	mutex_unlock(&oom_lock);
	return page;
}
```

> `PAGE_ALLOC_COSTLY_ORDER == 3`（include/linux/mmzone.h:63），即 >8 页的连续分配不靠杀进程解决。

**全局 OOM 与 memcg OOM 的分界**就在这里：`oc.memcg = NULL` 走全局；memcg 超限时由 `memcontrol.c:1885` 构造 `oc.memcg ≠ NULL` 的 `oom_control` 调**同一个** `out_of_memory()`（见 §9）。

## 3. `out_of_memory()`：OOM Killer 主入口

```c
// mm/oom_kill.c:1094
/**
 * out_of_memory - kill the "best" process when we run out of memory
 * If we run out of memory, we have the choice between either
 * killing a random task (bad), letting the system crash (worse)
 * OR try to be smart about which process to kill. Note that we
 * don't have to be perfect here, we just have to be good.
 * 不必完美，够好就行。
 */
bool out_of_memory(struct oom_control *oc)
{
	unsigned long freed = 0;

	if (oom_killer_disabled)      // hibernate 等场景临时禁用(§8.3)
		return false;

	if (!is_memcg_oom(oc)) {      // memcg OOM 不走 notifier
		blocking_notifier_call_chain(&oom_notify_list, 0, &freed);
		if (freed > 0 && !is_sysrq_oom(oc))
			/* Got some memory back in the last second.
			 * 注册过 notifier 的驱动 1 秒内释放过内存 → 再给一次机会 */
			return true;
	}

	/*
	 * If current has a pending SIGKILL or is exiting, then automatically
	 * select it. The goal is to allow it to allocate so that it may
	 * quickly exit and free its memory.
	 * current 自己快死了 → 无需扫描，直接选中它，让它快点死、快点放内存
	 */
	if (task_will_free_mem(current)) {      // oom_kill.c:865
		mark_oom_victim(current);
		queue_oom_reaper(current);
		return true;
	}

	/*
	 * The OOM killer does not compensate for IO-less reclaim.
	 * But mem_cgroup_oom() has to invoke the OOM killer even
	 * if it is a GFP_NOFS allocation.
	 * 无文件系统上下文（如回写路径）的分配不杀，防自锁；memcg 例外
	 */
	if (!(oc->gfp_mask & __GFP_FS) && !is_memcg_oom(oc))
		return true;

	/* 判定约束类型：NONE/CPUSET/MEMPOLICY/MEMCG（§4） */
	oc->constraint = constrained_alloc(oc);
	if (oc->constraint != CONSTRAINT_MEMORY_POLICY)
		oc->nodemask = NULL;
	check_panic_on_oom(oc);                 // panic_on_oom sysctl(§10.2)

	/* sysctl 打开"谁触发杀谁"模式则跳过打分 */
	if (!is_memcg_oom(oc) && sysctl_oom_kill_allocating_task &&
	    current->mm && !oom_unkillable_task(current) &&
	    oom_cpuset_eligible(current, oc) &&
	    current->signal->oom_score_adj != OOM_SCORE_ADJ_MIN) {
		get_task_struct(current);
		oc->chosen = current;
		oom_kill_process(oc, "Out of memory (oom_kill_allocating_task)");
		return true;
	}

	select_bad_process(oc);                 // §5：全系统/全 cgroup 扫描打分
	/* Found nothing?!?! */
	if (!oc->chosen) {
		dump_header(oc);
		pr_warn("Out of memory and no killable processes...\n");
		/*
		 * 系统级真 OOM 且无人可杀 → 分配器会无限循环，直接 panic
		 */
		if (!is_sysrq_oom(oc) && !is_memcg_oom(oc))
			panic("System is deadlocked on memory\n");
	}
	if (oc->chosen && oc->chosen != (void *)-1UL)   // -1UL 表示扫描中途放弃(§5.2)
		oom_kill_process(oc, !is_memcg_oom(oc) ? "Out of memory" :
				 "Memory cgroup out of memory");
	return !!oc->chosen;
}
```

## 4. 约束判定：`constrained_alloc()`

```c
// mm/oom_kill.c:249 （节选主干）
static enum oom_constraint constrained_alloc(struct oom_control *oc)
{
	...
	if (is_memcg_oom(oc)) {
		/* memcg OOM 的分母 = cgroup 的 memory.max（而非全机内存） */
		oc->totalpages = mem_cgroup_get_max(oc->memcg) ?: 1;
		return CONSTRAINT_MEMCG;
	}

	/* Default to all available memory —— 全局 OOM 的分母 = RAM + swap */
	oc->totalpages = totalram_pages() + total_swap_pages;
	...
	/* mempolicy 限制：分母 = nodemask 内各节点的内存 + swap */
	if (oc->nodemask &&
	    !nodes_subset(node_states[N_MEMORY], *oc->nodemask)) {
		oc->totalpages = total_swap_pages;
		for_each_node_mask(nid, *oc->nodemask)
			oc->totalpages += node_present_pages(nid);
		return CONSTRAINT_MEMORY_POLICY;
	}

	/* cpuset 限制：分母 = cpuset.mems 允许的节点 */
	for_each_zone_zonelist_nodemask(zone, z, oc->zonelist,
			highest_zoneidx, oc->nodemask)
		if (!cpuset_zone_allowed(zone, oc->gfp_mask))
			cpuset_limited = true;

	if (cpuset_limited) {
		oc->totalpages = total_swap_pages;
		for_each_node_mask(nid, cpuset_current_mems_allowed)
			oc->totalpages += node_present_pages(nid);
		return CONSTRAINT_CPUSET;
	}
	return CONSTRAINT_NONE;
}
```

**`totalpages` 是后面评分公式的分母，也是 `oom_score_adj` 的换算基数**——memcg OOM 用 cgroup 限额当分母（512MiB 容器里 `oom_score_adj=-500` 的保护力度只有全局场景的 1/4，见场景 B 演算）。

## 5. 评分与选人：`oom_badness` / `select_bad_process`

### 5.1 评分公式 `oom_badness()`

```c
// mm/oom_kill.c:190
/**
 * oom_badness - heuristic function to determine which candidate task to kill
 * @totalpages: total present RAM allowed for page allocation
 *
 * The heuristic for determining which task to kill is made to be as simple
 * and predictable as possible. The goal is to return the highest value for
 * the task consuming the most memory to avoid subsequent oom failures.
 * 评分策略：越简单越好、越可预测越好——谁吃内存多谁死，避免连环 OOM。
 */
long oom_badness(struct task_struct *p, unsigned long totalpages)
{
	long points;
	long adj;

	if (oom_unkillable_task(p))       // init(1号) 和内核线程不可杀 → LONG_MIN
		return LONG_MIN;

	p = find_lock_task_mm(p);         // 线程组里找还挂着 mm 的那个线程
	if (!p)
		return LONG_MIN;

	/*
	 * Do not even consider tasks which are explicitly marked oom
	 * unkillable or have been already oom reaped or the are in
	 * the middle of vfork
	 */
	adj = (long)p->signal->oom_score_adj;      // 用户态设置值[-1000,+1000]
	if (adj == OOM_SCORE_ADJ_MIN ||            // -1000：完全豁免
			mm_flags_test(MMF_OOM_SKIP, p->mm) ||   // 已被收割过
			in_vfork(p)) {                          // vfork 中
		task_unlock(p);
		return LONG_MIN;
	}

	/*
	 * The baseline for the badness score is the proportion of RAM that
	 * each task's rss, pagetable and swap space use.
	 */
	points = get_mm_rss_sum(p->mm)             // RSS = 匿名+文件+shmem
					       // (include/linux/mm.h:3404)
		+ get_mm_counter_sum(p->mm, MM_SWAPENTS)    // 已换出到 swap 的页
		+ mm_pgtables_bytes(p->mm) / PAGE_SIZE;     // 页表本身也占分
	task_unlock(p);

	/* Normalize to oom_score_adj units —— adj 按分母等比放大 */
	adj *= totalpages / 1000;
	points += adj;

	return points;
}
```

用 ASCII 把公式摆直：

```
                ┌ RSS(匿名+文件+shmem) ┐
                │ + swapents(换出页)   │ ┐
  badness =     │ + 页表字节数/页大小  │ │→ 裸分（占内存越多分越高）
                └─────────────────────┘ │
                + oom_score_adj × (totalpages/1000)   ← 每 1 分 adj ≈ 0.1% 的内存
                ──────────────────────────────────────
  显示分 /proc/<pid>/oom_score = (1000 + badness×1000/totalpages) × 2/3
                                       （fs/proc/base.c:599）
```

### 5.2 扫描与选择：`oom_evaluate_task` / `select_bad_process`

```c
// mm/oom_kill.c:306
static int oom_evaluate_task(struct task_struct *task, void *arg)
{
	struct oom_control *oc = arg;
	long points;

	if (oom_unkillable_task(task))            // init / kthread：跳过
		goto next;

	/* p may not have freeable memory in nodemask */
	if (!is_memcg_oom(oc) && !oom_cpuset_eligible(task, oc))
		goto next;                            // NUMA 上"救不了场"的进程不选

	/*
	 * This task already has access to memory reserves and is being
	 * killed. Don't allow any other task to have access to the
	 * reserves unless the task has MMF_OOM_SKIP ...
	 * 已经有 victim 在死：别再挑第二个，除非它已被收割过
	 */
	if (!is_sysrq_oom(oc) && tsk_is_oom_victim(task)) {
		if (mm_flags_test(MMF_OOM_SKIP, task->signal->oom_mm))
			goto next;
		goto abort;                           // → oc->chosen = -1UL，本轮放弃
	}

	/*
	 * If task is allocating a lot of memory and has been marked to be
	 * killed first if it triggers an oom, then select it.
	 * set_current_oom_origin() 标记过的"始作俑者"直接满分(如 oom_test)
	 */
	if (oom_task_origin(task)) {
		points = LONG_MAX;
		goto select;
	}

	points = oom_badness(task, oc->totalpages);
	if (points == LONG_MIN || points < oc->chosen_points)
		goto next;                            // 没有当前最高分高 → 跳过

select:
	if (oc->chosen)
		put_task_struct(oc->chosen);
	get_task_struct(task);                    // 拿引用防其退出
	oc->chosen = task;
	oc->chosen_points = points;
next:
	return 0;
abort:
	if (oc->chosen)
		put_task_struct(oc->chosen);
	oc->chosen = (void *)-1UL;                // 约定值：本轮扫描作废
	return 1;
}

// mm/oom_kill.c:362
/* Simple selection loop. We choose the process with the highest number of
 * 'points'. In case scan was aborted, oc->chosen is set to -1. */
static void select_bad_process(struct oom_control *oc)
{
	oc->chosen_points = LONG_MIN;

	if (is_memcg_oom(oc))
		mem_cgroup_scan_tasks(oc->memcg, oom_evaluate_task, oc); // 只扫 cgroup 内
	else {
		struct task_struct *p;

		rcu_read_lock();
		for_each_process(p)                   // 全系统扫描
			if (oom_evaluate_task(p, oc))
				break;
		rcu_read_unlock();
	}
}
```

选择优先级（高→低）：

| 优先级 | 谁 | 依据 |
|-|-|-|
| 1 | 正在退出/收 SIGKILL 的 current | `task_will_free_mem`（out_of_memory 开头，§3） |
| 2 | `oom_task_origin` 标记的始作俑者 | `LONG_MAX` 满分（内核重型分配路径设置：ksm mm/ksm.c:3539、swapoff mm/swapfile.c:2956、ring_buffer 扩容 kernel/trace/ring_buffer.c:2281） |
| 3 | 已有 victim 未死完 | 扫描 abort，本轮不再挑新人 |
| 4 | `oom_badness` 最高分 | RSS+swap+页表+adj |
| — | init / kthread / `oom_score_adj=-1000` / vfork 中 | `LONG_MIN`，永不被选 |

## 6. 处决：`oom_kill_process` → `__oom_kill_process`

```c
// mm/oom_kill.c:1008
static void oom_kill_process(struct oom_control *oc, const char *message)
{
	struct task_struct *victim = oc->chosen;
	struct mem_cgroup *oom_group;
	static DEFINE_RATELIMIT_STATE(oom_rs, DEFAULT_RATELIMIT_INTERVAL,
				      DEFAULT_RATELIMIT_BURST);   // 日志限流

	/*
	 * If the task is already exiting, don't alarm the sysadmin or kill
	 * its children or threads, just give it access to memory reserves
	 * so it can die quickly
	 */
	task_lock(victim);
	if (task_will_free_mem(victim)) {       // 扫描期间它已开始退出？
		mark_oom_victim(victim);            // 只标记+给内存预留
		queue_oom_reaper(victim);
		task_unlock(victim);
		put_task_struct(victim);
		return;
	}
	task_unlock(victim);

	if (__ratelimit(&oom_rs)) {
		dump_header(oc);                    // 先打 OOM 报告(§11)
		dump_oom_victim(oc, victim);
	}

	/*
	 * Do we need to kill the entire memory cgroup?
	 * Or even one of the ancestor memory cgroups?
	 * cgroup v2 的 memory.oom.group：先找出要"连坐"的组(§9.2)
	 */
	oom_group = mem_cgroup_get_oom_group(victim, oc->memcg); // memcontrol.c:1947

	__oom_kill_process(victim, message);

	/* If necessary, kill all tasks in the selected memory cgroup. */
	if (oom_group) {
		memcg_memory_event(oom_group, MEMCG_OOM_GROUP_KILL);
		mem_cgroup_print_oom_group(oom_group);
		mem_cgroup_scan_tasks(oom_group, oom_kill_memcg_member, // 组内全杀
				      (void *)message);
		mem_cgroup_put(oom_group);
	}
}

// mm/oom_kill.c:912
static void __oom_kill_process(struct task_struct *victim, const char *message)
{
	struct task_struct *p;
	struct mm_struct *mm;
	bool can_oom_reap = true;

	p = find_lock_task_mm(victim);          // 线程组内找真持有 mm 的线程
	if (!p) {
		pr_info("%s: OOM victim %d (%s) is already exiting. Skip killing the task\n",
			message, task_pid_nr(victim), victim->comm);
		put_task_struct(victim);
		return;
	} else if (victim != p) {
		get_task_struct(p);
		put_task_struct(victim);
		victim = p;
	}

	/* Get a reference to safely compare mm after task_unlock(victim) */
	mm = victim->mm;
	mmgrab(mm);

	/* Raise event before sending signal: task reaper must see this */
	count_vm_event(OOM_KILL);               // vmstat 里的 oom_kill 计数
	memcg_memory_event_mm(mm, MEMCG_OOM_KILL);

	/*
	 * We should send SIGKILL before granting access to memory reserves
	 * in order to prevent the OOM victim from depleting the memory
	 * reserves from the user space under its control.
	 * 先发 SIGKILL、后给内存预留 —— 顺序不能反！
	 */
	do_send_sig_info(SIGKILL, SEND_SIG_PRIV, victim, PIDTYPE_TGID);
	mark_oom_victim(victim);                // TIF_MEMDIE + oom_mm(§8)
	pr_err("%s: Killed process %d (%s) total-vm:%lukB, anon-rss:%lukB, file-rss:%lukB, shmem-rss:%lukB, UID:%u pgtables:%lukB oom_score_adj:%d\n",
		message, task_pid_nr(victim), victim->comm, K(mm->total_vm),
		K(get_mm_counter_sum(mm, MM_ANONPAGES)),
		K(get_mm_counter_sum(mm, MM_FILEPAGES)),
		K(get_mm_counter_sum(mm, MM_SHMEMPAGES)),
		from_kuid(&init_user_ns, task_uid(victim)),
		mm_pgtables_bytes(mm) >> 10, victim->signal->oom_score_adj);
	task_unlock(victim);

	/*
	 * Kill all user processes sharing victim->mm in other thread groups.
	 * 共享同一 mm 的"别人家"进程也要杀（如 fork 出的对端、进程间共享）：
	 * 否则它们持有 mm 引用，mmap_lock 会活锁
	 */
	rcu_read_lock();
	for_each_process(p) {
		if (!process_shares_mm(p, mm))
			continue;
		if (same_thread_group(p, victim))
			continue;
		if (is_global_init(p)) {            // init 钉住了 mm → 无法收割
			can_oom_reap = false;
			mm_flags_set(MMF_OOM_SKIP, mm);
			pr_info("oom killer %d (%s) has mm pinned by %d (%s)\n", ...);
			continue;
		}
		if (unlikely(p->flags & PF_KTHREAD)) // kthread 借用 mm(kthread_use_mm)
			continue;                        // 不杀，收割仍可行
		do_send_sig_info(SIGKILL, SEND_SIG_PRIV, p, PIDTYPE_TGID);
	}
	rcu_read_unlock();

	if (can_oom_reap)
		queue_oom_reaper(victim);           // 交给 oom_reaper(§7)

	mmdrop(mm);
	put_task_struct(victim);
}
```

> `K(x)` 宏定义在 mm/internal.h:650（页 → kB）。日志限流 `DEFAULT_RATELIMIT_INTERVAL/BURST` 防止刷屏。

## 7. oom_reaper：异步收割被杀进程的内存

**为什么必须异步？** 被杀进程可能卡在不可中断睡眠（D 状态）、被 ptrace 钉住、或正在慢速退出路径中——如果同步等它死完才放内存，而它又在等一个永远等不到的资源，OOM 就死锁了。于是：**杀（SIGKILL）是同步的，收（释放内存）是异步的**，由独立内核线程 `oom_reaper` 完成，不等进程真正退出就先把它地址空间里的匿名页 zap 掉。

```
 时间 ─────────────────────────────────────────────────────────────────────►

 [分配者上下文/OOM Killer]        [victim 进程 logd]       [oom_reaper 内核线程]
      │                               │                         │
 ① SIGKILL + mark_oom_victim ────────►│ (TIF_MEMDIE + 内存预留)  │
      │                               │                         │
 ② queue_oom_reaper ─────────────────────────────────► ③ 2 秒宽限定时器启动
      │                               │   (OOM_REAPER_DELAY=2*HZ, oom_kill.c:685)
      │                               │   ← 宽限期内 victim 若自然退出：exit_mmap 先置
      │                               │     MMF_OOM_SKIP(mm/mmap.c:1307)，收割自动跳过
      │                               │   （robust futex 等资源需要完整退出路径）
      │                               │                         │ ④ 超时: 入队 + 唤醒
      │                               │◄── mmap_read_trylock ───┤
      │                               │   （抢不到锁 → 跳过本轮，│
      │                               │     100ms × 10 次重试） │
      │                               │◄── ⑤ __oom_reap_task_mm ┤
      │                               │   maple tree 逆序遍历，  │
      │                               │   zap 匿名私有页         │
      │                               │   （跳过 HUGETLB/PFNMAP）│
      │ "oom_reaper: reaped process ..." ← 空闲内存立即回升      │
      │                               │                         │ ⑥ MMF_OOM_SKIP 收工
      │                               │ ⑦ victim 走完退出路径    │
      │                               │   exit_mmap 释放剩余内存 │
 ⑧ exit_oom_victim: oom_victims 归零 ◄─│ (kernel/exit.c:584)     │
      │                                                         │
      ▼                                                         │
 分配器 retry 循环拿到内存 → got_pg ✓                            │
```

```c
// mm/oom_kill.c:513 （收割核心：zap 匿名页，不阻塞）
static bool __oom_reap_task_mm(struct mm_struct *mm)
{
	struct vm_area_struct *vma;
	bool ret = true;
	MA_STATE(mas, &mm->mm_mt, ULONG_MAX, ULONG_MAX);   // maple tree 游标

	/* 告知 get_user/copy_from_user 等用户：这段内存内容不再稳定 */
	mm_flags_set(MMF_UNSTABLE, mm);

	/*
	 * It might start racing with the dying task and compete for shared
	 * resources - e.g. page table lock contention has been observed.
	 * Reduce those races by reaping the oom victim from the other end
	 * of the address space.
	 * 与垂死进程争抢页表锁？那就从地址空间另一端（高地址→低地址）收割
	 */
	mas_for_each_rev(&mas, vma, 0) {
		if (vma->vm_flags & (VM_HUGETLB|VM_PFNMAP))
			continue;                 // 大页/PFN 映射收不动

		/*
		 * Only anonymous pages have a good chance to be dropped
		 * without additional steps ... We do not even care about
		 * fs backed pages because all which are reclaimable have
		 * already been reclaimed ...
		 * 只 zap 匿名/私有页：文件页早就被回收链收干净了
		 */
		if (vma_is_anonymous(vma) || !(vma->vm_flags & VM_SHARED)) {
			if (zap_vma_for_reaping(vma))   // mm/memory.c:2124，非阻塞 zap
				ret = false;          // 有一部分要阻塞 → 稍后重试
		}
	}
	return ret;
}

// mm/oom_kill.c:602
#define MAX_OOM_REAP_RETRIES 10
static void oom_reap_task(struct task_struct *tsk)
{
	int attempts = 0;
	struct mm_struct *mm = tsk->signal->oom_mm;

	/* Retry the mmap_read_trylock(mm) a few times：最多 10 次 × 100ms */
	while (attempts++ < MAX_OOM_REAP_RETRIES && !oom_reap_task_mm(tsk, mm))
		schedule_timeout_idle(HZ/10);
	...
	/* Hide this mm from OOM killer：无论成败，别再盯着它 */
	mm_flags_set(MMF_OOM_SKIP, mm);

	/* Drop a reference taken by queue_oom_reaper */
	put_task_struct(tsk);
}

// mm/oom_kill.c:634
static int oom_reaper(void *unused)           // subsys_initcall 时启动(oom_init:726)
{
	set_freezable();

	while (true) {
		struct task_struct *tsk = NULL;

		wait_event_freezable(oom_reaper_wait, oom_reaper_list != NULL);
		spin_lock_irq(&oom_reaper_lock);
		if (oom_reaper_list != NULL) {        // 单链表 LIFO
			tsk = oom_reaper_list;
			oom_reaper_list = tsk->oom_reaper_list;
		}
		spin_unlock_irq(&oom_reaper_lock);

		if (tsk)
			oom_reap_task(tsk);
	}
	return 0;
}

// mm/oom_kill.c:685
#define OOM_REAPER_DELAY (2*HZ)
static void queue_oom_reaper(struct task_struct *tsk)
{
	/* mm is already queued? */
	if (mm_flags_test_and_set(MMF_OOM_REAP_QUEUED, tsk->signal->oom_mm))
		return;                               // 防重复入队

	get_task_struct(tsk);
	timer_setup(&tsk->oom_reaper_timer, wake_oom_reaper, 0);
	tsk->oom_reaper_timer.expires = jiffies + OOM_REAPER_DELAY;  // 2 秒宽限
	add_timer(&tsk->oom_reaper_timer);
}
```

```c
	WARN_ON(oom_killer_disabled);
```

```c
// mm/memcontrol.c:1885
static bool mem_cgroup_out_of_memory(struct mem_cgroup *memcg, gfp_t gfp_mask,
				     int order)
{
	struct oom_control oc = {
		.zonelist = NULL,       // 与全局 OOM 的关键差异：
		.nodemask = NULL,       // 不带 zonelist，扫描范围只在 memcg
		.memcg = memcg,         // ← 非 NULL！out_of_memory 内部全部走 memcg 分支
		.gfp_mask = gfp_mask,
		.order = order,
	};
	bool ret = true;

	if (mutex_lock_killable(&oom_lock))   // 与全局 OOM 共用同一把锁
		return true;

	if (mem_cgroup_margin(memcg) >= (1 << order))
		goto unlock;            // 持锁后再核对：余额够了就不用杀

	ret = out_of_memory(&oc);       // 复用同一个 OOM 主流程

unlock:
	mutex_unlock(&oom_lock);
	return ret;
}

// mm/memcontrol.c:1918
static bool mem_cgroup_oom(struct mem_cgroup *memcg, gfp_t mask, int order)
{
	bool locked, ret;

	if (order > PAGE_ALLOC_COSTLY_ORDER)   // 容器里也不为大阶分配杀进程
		return false;

	memcg_memory_event(memcg, MEMCG_OOM);  // cgroup 的 memory.events 里 oom 计数+1

	if (!memcg1_oom_prepare(memcg, &locked))
		return false;

	ret = mem_cgroup_out_of_memory(memcg, mask, order);

	memcg1_oom_finish(memcg, locked);
	return ret;
}

// mm/memcontrol.c:2667 （充值失败处的调用点，节选）
	/*
	 * keep retrying as long as the memcg oom killer is able to make
	 * a forward progress or bypass the charge if the oom killer
	 * couldn't make any progress.
	 */
	if (mem_cgroup_oom(mem_over_limit, gfp_mask,
			   get_order(nr_pages * PAGE_SIZE))) {
		passed_oom = true;
		nr_retries = MAX_RECLAIM_RETRIES;
		goto retry;             // 杀完人后重试充值
	}
```

### 9.2 全局 OOM vs memcg OOM 对照

| 维度 | 全局 OOM（场景 A） | memcg OOM（场景 B） |
|-|-|-|
| 触发点 | 页分配器慢速路径尽头（`__alloc_pages_may_oom` 调用点 page_alloc.c:4909） | memcg 充值失败（`mem_cgroup_oom` 调用点 memcontrol.c:2672） |
| `oc.memcg` | NULL | 超限的 mem_cgroup |
| 评分分母 `totalpages` | `RAM+swap`（全机） | `memory.max`（cgroup 限额，`constrained_alloc:257`） |
| 扫描范围 | 全系统 `for_each_process` | `mem_cgroup_scan_tasks`（cgroup 子树内） |
| oom_score_adj 粒度 | 1 分 ≈ 0.1% 全机内存 | 1 分 ≈ 0.1% **cgroup 限额**（保护力度按比例缩小） |
| 额外动作 | — | `memory.oom.group=1` 时连坐整组 |
| 日志前缀 | `Out of memory` | `Memory cgroup out of memory` |
| 可观测 | dmesg | cgroup `memory.events` 的 `oom` 计数 |

```c
static int proc_oom_score(struct seq_file *m, struct pid_namespace *ns,
			  struct pid *pid, struct task_struct *task)
{
	unsigned long totalpages = totalram_pages() + total_swap_pages;
	unsigned long points = 0;
	long badness;

	badness = oom_badness(task, totalpages);
	/*
	 * Special case OOM_SCORE_ADJ_MIN for all others scale the
	 * badness value into [0, 2000] range ...
	 */
```

### 11.2 字段对照表（按 7.1.3 格式串整理）

**第一行** `xxx invoked oom-killer: gfp_mask=0xd0(GFP_KERNEL), order=0, oom_score_adj=0`：

| 字段 | 含义 | 排查线索 |
|-|-|-|
| `invoked oom-killer` 前的进程名 | 触发分配的进程（**不一定是被杀的**） | 多为无辜的分配者 |
| `gfp_mask` | 分配掩码 | `GFP_KERNEL`/`GFP_NOFS`/`GFP_ATOMIC` 判断上下文 |
| `order` | 请求阶数 | order=0 是典型 OOM；大阶多半走 compaction |
| `oom_score_adj` | 触发者的 adj | 排查"谁把自己调成了 -1000 还在吃内存" |

**`dump_tasks` 进程表**（oom_kill.c:425 表头）：

```
[  pid  ]   uid  tgid total_vm      rss rss_anon rss_file rss_shmem pgtables_bytes swapents oom_score_adj name
```

| 列 | 含义 |
|-|-|
| `rss` = `rss_anon`+`rss_file`+`rss_shmem` | 7.1.3 拆开了三类 RSS（5.9 只有一个 rss，见 §12） |
| `pgtables_bytes` | 页表占用——大进程经常隐藏着几百 MB 页表 |
| `swapents` | 换出页数——判断"是否已经换无可换" |
| `oom_score_adj` | 谁被保护、谁被加重 |

**victim 行**（`__oom_kill_process:945`）：`Killed process 1234 (logd) total-vm:..., anon-rss:..., file-rss:..., shmem-rss:..., UID:..., pgtables:...kB oom_score_adj:...`——与打分公式逐项对应，事后可直接复算 badness。

### 11.3 场景 A 数字演算：评分为什么选中它

**环境**：arm64 服务器（AGI CPU，同构多核，OOM 逻辑与架构无关），8GiB RAM + 2GiB swap，4KiB 页。

```
totalpages = 8GiB/4KiB + 2GiB/4KiB = 2097152 + 524288 = 2621440 页
adj 换算粒度 = totalpages/1000 = 2621 页 ≈ 10.2MiB
→ oom_score_adj 每变动 1 分 = 约 10MiB"分"；-500 ≈ 5.0GiB 的保护力度
```

三个候选进程（泄漏服务 logd 一路涨到 2GiB）：

| 进程 | RSS | swapents | pgtables | adj | 裸分合计 | 显示分 oom_score |
|-|-|-|-|-|-|-|
| logd | 524288 页(2GiB) | 0 | 8192 | 0 | **532480** | (1000+203)×2/3 ≈ **802** ← 被选 |
| db | 393216 页(1.5GiB) | 131072(512MiB) | 4096 | 0 | 528384 | (1000+201)×2/3 = 800 |
| proxy | 131072 页(512MiB) | 0 | 2048 | -500 | 133120−1310720 = −1177600 | (1000−449)×2/3 ≈ 367 |

读出三个结论：
1. **logd 与 db 只差 4096 分（16MiB）**——swap 也计入裸分，"吃 RAM+swap 总量"才是标准；
2. **`-500` 直接把 proxy 从 512MiB 变成负分**，等效 5GiB 保护，adj 是粗粒度大杠杆；
3. 若给 logd 配 `adj=+500`，其分数 +1310720 → 1843200，**必死且必先死**。

## 12. 版本对照：本仓库 Linux 5.9 vs 7.1.3

现有 [README.md](README.md) 引用的是 5.9 的 `__alloc_pages_slowpath`（5.9 位于 page_alloc.c:4824，7.1.3 移至 :4682）。两棵树的 OOM 相关实质差异（diff 实测）：

| 变化点 | 5.9 | 7.1.3 | 影响 |
|-|-|-|-|
| `process_mrelease` 系统调用 | 无（5.15 引入） | oom_kill.c:1195 | 用户态可主动加速收割 |
| VMA 管理 | 链表 `mm->mmap` 正序遍历 | maple tree `mm_mt` **逆序**遍历（`mas_for_each_rev`） | 收割从地址空间另一端走，减少与垂死进程的页表锁争用 |
| 收割实现 | `can_madv_lru_vma` + `unmap_page_range`（自建 mmu_gather） | `zap_vma_for_reaping`（mm/memory.c:2124，非阻塞 zap） | 收割路径统一、更不容易阻塞 |
| `mm->flags` 访问 | `test_bit/set_bit(MMF_OOM_SKIP, &mm->flags)` | `mm_flags_test/mm_flags_set(MMF_OOM_SKIP, mm)` | 新 API |
| RSS 读数 | `get_mm_rss` / `get_mm_counter` | `get_mm_rss_sum` / `get_mm_counter_sum`（include/linux/mm.h:3404/3354） | 计入 per-thread 计数 |
| dump_tasks 列 | `rss pgtables_bytes swapents` | 增加 `rss_anon rss_file rss_shmem` 三列 + 每 1024 个任务 `touch_softlockup_watchdog` | 大机器上不打软锁 |
| 日志摘要 | `dump_oom_summary(oc, p)`，dump_header 带 victim 参数 | `dump_oom_victim(oc, victim)`，dump_header 只带 oc | 格式演进 |
| slab 提示 | `is_dump_unreclaim_slabs()` | `should_dump_unreclaim_slab()` | 更名 |
| oom_score_adj 并发 | 无专门锁 | `oom_adj_mutex`（oom_kill.c:70） | 修并发改分竞争 |
| NUMA 域判定 | `mempolicy_nodemask_intersects` | `mempolicy_in_oom_domain` | 语义收紧 |
| 收割线程 | 常规等待 | `set_freezable()` + `spin_lock_irq` | suspend 期间行为更稳 |

> 仓库内 [000.LINUX-5.9](../../../000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9/) 树带手工中文批注（如 `__oom_reap_task_mm` 的文档注释），与 7.1.3 对照阅读时注意区分"原版注释"与"学习批注"。
