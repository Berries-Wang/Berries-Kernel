# 001.应用层:socket() 收发数据的内核全程<sup>LINUX 7.1.3</sup>

> 学习/出处:
> + 本仓库源码(本文行号均指此树):[net/socket.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/socket.c)、[include/linux/net.h](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/net.h)、[net/ipv4/af_inet.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/af_inet.c)、[net/core/sock.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/sock.c)
> + API 权威参考:UNIX Network Programming Vol.1 ch4-6(本仓库 [UNP Vol1](../../../007.BOOKs/UNIX%20Network%20Programming%20Volume%201%3A%20Socket%20Networking%20API%20%283rd%20Edition%29.epub))

应用层是唯一不写在内核里的层,却是所有链路的起点与终点。本文回答三个问题:**`socket()` 返回的 fd 到底是什么**、**一次 `send()` 从用户缓冲区到内核 buffer 经过了哪些函数**、**阻塞的 `recv()` 在内核里睡在哪张床上**。epoll/io_uring 只是把第三问的"睡"换成"被叫醒",详见 [009](009.epoll-事件驱动网络IO.md)/[010](010.io_uring-异步网络IO.md)。

## 1. socket():三层对象,一次到位

`socket(AF_INET, SOCK_STREAM, 0)` 的内核全程(socket.c):

```c
// net/socket.c:1802(全文, 行号实测)
int __sys_socket(int family, int type, int protocol)
{
	struct socket *sock;
	int flags;

	sock = __sys_socket_create(family, type,       // :1807 → __sock_create :1594(经 sock_create :1721)
				   update_socket_protocol(family, type, protocol));  // :1808 弱符号钩子(:1795)
	if (IS_ERR(sock))
		return PTR_ERR(sock);

	flags = type & ~SOCK_TYPE_MASK;
	if (SOCK_NONBLOCK != O_NONBLOCK && (flags & SOCK_NONBLOCK))
		flags = (flags & ~SOCK_NONBLOCK) | O_NONBLOCK;

	return sock_map_fd(sock, flags & (O_CLOEXEC | O_NONBLOCK));   // :1816 → :564
}
```

`__sock_create`(:1594)做了最关键的一次**多态分发**:

```c
// net/socket.c:1594(节选)
int __sock_create(struct net *net, int family, int type, int protocol,
	     struct socket **res, int kern)
{
	...
	pf = rcu_dereference(net_families[family]);   // 按 AF_INET 查协议族表
	err = pf->create(net, sock, protocol, kern);  // AF_INET → inet_create (af_inet.c:259)
	...
}
```

`inet_create`(af_inet.c:259)再按 `SOCK_STREAM` 从 `inetsw[]`(由 `inetsw_array`,af_inet.c:1164 注册)取出 TCP 的两套函数集,装进 socket:

```c
// net/ipv4/af_inet.c:259(节选, 行号实测)
static int inet_create(struct net *net, struct socket *sock, int protocol,
		       int kern)
{
	...
	list_for_each_entry_rcu(answer, &inetsw[sock->type], list) {   // :279 SOCK_STREAM → inet_stream_protosw
		...
	}
	...
	sock->ops = answer->ops;         // :325 = &inet_stream_ops (af_inet.c:1062)
	answer_prot = answer->prot;      // :326 = &tcp_prot (tcp_ipv4.c:3336)
	...
	sk = sk_alloc(net, PF_INET, GFP_KERNEL, answer_prot, kern);  // :333 → sock.c:2303, 分配 tcp_sock
	...
	sock_init_data(sock, sk);        // :362 → sock.c:3779
	...
	err = sk->sk_prot->init(sk);     // :391 → tcp_v4_init_sock (tcp_ipv4.c:2392)
}
```

于是 fd 背后挂着一条三层对象链,后续 send/recv 全沿这条链下行:

<pre>
fd(3) ──▶ struct file ──▶ private_data
                            │
                            ▼
                   struct socket (net.h:137)        ← VFS 视角(sockfs inode)
                     ops ──▶ inet_stream_ops        ← 行为: send/recv/bind/... 怎么分派
                     sk  ──▶ struct tcp_sock        ← 状态: 缓冲区、状态机、收发游标
                              (sock.h:411 sk_receive_queue)
                              (sock.h:453 sk_data_ready 回调)
</pre>

> **为什么拆成 socket + sock 两个结构?** `struct socket` 面向 VFS(和文件系统打交道的薄壳),`struct sock` 面向协议(被 TCP/UDP/RAW 继承出 `tcp_sock`/`udp_sock`)。握手阶段的形态分化(request_sock/timewait_sock)见 [003.TCP-IP](../003.TCP-IP/000.TCP三次握手与四次挥手-内核代码交互.md)。

`sock_init_data`(sock.c:3779)里有一行为收包唤醒埋下的伏笔:

```c
// net/core/sock.c:3734(sock_init_data_uid 内)
	sk->sk_data_ready	=	sock_def_readable;    // sock.c:3614, 数据到达时的默认唤醒函数
```

## 2. bind/listen/accept/connect:控制面一句话带过

数据面四步之外,建连四兄弟在 7.1.3 的入口:

|系统调用|入口(socket.c)|/inet 层|协议层|备注|
|-|-|-|-|-|
|`bind()`|`__sys_bind` :1948|`inet_bind` af_inet.c:472|`sk->sk_prot->bind`(TCP 未用)|填 `sk->sk_num`/`rcv_saddr`|
|`listen()`|`__sys_listen` :1992|`inet_listen` af_inet.c:237|`inet_csk_listen_start`|起半/全连接队列(握手见 [003.TCP-IP](../003.TCP-IP/000.TCP三次握手与四次挥手-内核代码交互.md))|
|`connect()`|`__sys_connect` :2155|`inet_stream_connect`|`tcp_v4_connect` tcp_ipv4.c:221|发 SYN,`tcp_connect`(tcp_output.c:4293)|
|`accept()`|`__sys_accept4` :2097|`inet_accept` af_inet.c:787|`inet_csk_accept`|从全连接队列取 child sock;新 fd 同样挂三层对象链|

## 3. 发送:`send()` 如何走进协议栈

用户态 `send(fd, buf, len, 0)` → glibc → `__sys_sendto`:

```c
// net/socket.c:2231(节选, 行号实测)
int __sys_sendto(int fd, void __user *buff, size_t len, unsigned int flags,
		 struct sockaddr __user *addr,  int addr_len)
{
	...
	err = import_ubuf(ITER_SOURCE, buff, len, &msg.msg_iter);   // :2239 用户缓冲区 → iov_iter
	...
	sock = sock_from_file(fd_file(f));       // :2246 fd → struct socket
	...
	if (addr) {
		err = move_addr_to_kernel(addr, addr_len, &address);   // :2256
		...
	}
	...
	msg.msg_flags = flags;
	return __sock_sendmsg(sock, &msg);       // :2266 → sock_sendmsg(:813)
}
```

`sock_sendmsg`(:813)→ `sock_sendmsg_nosec`(:785)→ 一行完成协议栈分派:

```c
// net/socket.c:785(全文)
static inline int sock_sendmsg_nosec(struct socket *sock, struct msghdr *msg)
{
	int ret = INDIRECT_CALL_INET(READ_ONCE(sock->ops)->sendmsg, inet6_sendmsg,
				     inet_sendmsg, sock, msg,
				     msg_data_left(msg));   // ★ ops->sendmsg 多态分派
	BUG_ON(ret == -EIOCBQUEUED);

	if (trace_sock_send_length_enabled())
		call_trace_sock_send_length(sock->sk, ret, 0);      // 发送长度 tracepoint
	return ret;
}
```

`ops->sendmsg` 就是 `inet_stream_ops.sendmsg = inet_sendmsg`(af_inet.c:1062/857),它再下探到 `sk->sk_prot->sendmsg = tcp_sendmsg`(tcp.c:1447)。`__sys_sendmsg`(:2768)走的同一条路,只是用户态传的是 iovec 数组。

<pre>
send(fd, buf, len)
  └▶ __sys_sendto        socket.c:2231   fd→socket, 组装 msghdr/iov_iter
      └▶ sock_sendmsg    socket.c:813    (安全钩子后) 调 ops->sendmsg
          └▶ inet_sendmsg  af_inet.c:857  通用跳板
              └▶ tcp_sendmsg  tcp.c:1447  ← 进入协议栈(详见 003/008)
</pre>

数据此刻还在**用户缓冲区**;`tcp_sendmsg_locked`(tcp.c:1117)负责把它复制进 `sk->sk_write_queue`/`sk_sndbuf` 管理的发送缓冲区(满了就睡 `sk_stream_wait_memory`,stream.c:122),真正的出网动作由 TCP 层自主择机(段化、Nagle、拥塞窗口)完成。

## 4. 接收:`recv()` 睡在哪、醒在哪

```c
// net/socket.c:2291(节选, 行号实测)
int __sys_recvfrom(int fd, void __user *ubuf, size_t size, unsigned int flags,
		   struct sockaddr __user *addr, int __user *addr_len)
{
	...
	err = import_ubuf(ITER_DEST, ubuf, size, &msg.msg_iter);   // :2302 用户接收缓冲 → iov_iter
	...
	sock = sock_from_file(fd_file(f));       // :2310 fd → struct socket
	...
	if (sock->file->f_flags & O_NONBLOCK)
		flags |= MSG_DONTWAIT;
	err = sock_recvmsg(sock, &msg, flags);   // :2316 → :1156

	if (err >= 0 && addr != NULL) {
		err2 = move_addr_to_user(&address,   // :2319 对端地址带回用户态
					 msg.msg_namelen, addr, addr_len);
		...
	}
	return err;
}
```

`sock_recvmsg`(:1156)→ `ops->recvmsg = inet_recvmsg`(af_inet.c:886)→ `tcp_recvmsg`(tcp.c:2931)→ `tcp_recvmsg_locked`(tcp.c:2656)。收包数据在**协议栈收包中断回调**时已排进 `sk->sk_receive_queue`(sock.h:411),所以 `recv` 的动作只是:

1. 队列非空 → 取出 `sk_buff`,`skb_copy_datagram_iter` 拷到用户区;
2. 队列空 → 进程睡眠,等待唤醒:

```c
// include/net/sock.h:1259(声明, 实现于 net/core/stream/sock, TCP 用 sk_wait_data 等数据)
int sk_wait_data(struct sock *sk, long *timeo, const struct sk_buff *skb);
```

唤醒方的路径(收包侧详见 [007](007.收包全链路-从网线到epoll.md)):网卡中断 → 协议栈入队 → `tcp_data_queue` 末尾调 `tcp_data_ready(sk)`(tcp_input.c:5661,定义 :5568)→ 回调 `READ_ONCE(sk->sk_data_ready)(sk)` → `sock_def_readable`(sock.c:3614)→ `wake_up_interruptible_sync_poll` 唤醒 `recv` 睡的等待队列。

<pre>
recv(fd, buf, len) ── 队列空 ──▶ sk_wait_data() 挂上 sk->sk_wq 等待队列, 睡眠
                                      ▲
                                      │ 唤醒沿右侧链路上来
      sk_receive_queue ◀── tcp_data_queue/tcp_queue_rcv(tcp_input.c:5499)
              │                    └▶ tcp_data_ready(sk) tcp_input.c:5661(定义 :5568)
              └─ 数据包挂队列            └▶ sock_def_readable  sock.c:3614
                                            └▶ wake_up_interruptible_sync_poll → recv 醒来
</pre>

`read(fd,...)`/`write(fd,...)` 也能用于 socket:`sock_read_iter`/`sock_write_iter`(socket.c:1213/1235)内部同样走 `sock_recvmsg/sock_sendmsg`——fd 是文件的,socket 就天然继承文件接口,这正是 epoll 能监听 socket 的前提(见 [009 §2](009.epoll-事件驱动网络IO.md))。

## 5. 应用层的两种" readiness "姿势(预告)

同一份 socket 层,上层消费方式决定了整个系统的并发形态:

|姿势|入口|内核行为|文档|
|-|-|-|-|
|阻塞 recv|`__sys_recvfrom`|每 fd 一个线程,睡在 `sk_wait_data`|本文 §4|
|epoll_wait|`ep_poll` eventpoll.c:1938|一个线程监听 N 个 fd 的就绪回调|[009](009.epoll-事件驱动网络IO.md)|
|io_uring 提交 recv|`io_uring_enter` io_uring.c:2609|提交/完成双环,`io_recv`(io_uring/net.c:1180)代跑 recv|[010](010.io_uring-异步网络IO.md)|

## 6. 实测:观察你自己的 socket

```bash
# 1. fd → socket → 协议(用 ss 看 TCP 三层对象的用户态投影)
ss -tinp state established '( dport = :443 )'

# 2. 系统调用层面看一次完整连接
strace -f -e trace=socket,connect,sendto,recvfrom,sendmsg,recvmsg \
       -e signal=none curl -s http://example.com -o /dev/null

# 3. 内核函数层面验证分派链(7.1.3, 函数名与本文一致)
sudo bpftrace -e '
  kprobe:__sys_sendto    { printf("sendto  comm=%s fd=%d\n", comm, arg0); }
  kprobe:sock_sendmsg    { printf("  → sock_sendmsg\n"); }
  kprobe:inet_sendmsg    { printf("  → inet_sendmsg\n"); }
  kprobe:tcp_sendmsg     { printf("  → tcp_sendmsg bytes=%d\n", arg2); }'
```
