# 011.调试方案:e1000e 内核网络全链路调试(编译前预案)<sup>LINUX 7.1.3</sup>

> 学习/出处:
> + 官方调试文档(7.1.3 树内同名文件):[Documentation/process/debugging/gdb-kernel-debugging.rst](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/Documentation/process/debugging/gdb-kernel-debugging.rst)(KGDB)、[Documentation/trace/ftrace.rst](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/Documentation/trace/ftrace.rst)、[Documentation/trace/kprobetrace.rst](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/Documentation/trace/kprobetrace.rst)
> + 本文不执行编译——只给出**你后续编译内核时**的配置清单、QEMU 环境、断点/观测点全套预案,行号全部对应仓库 7.1.3 树(前文各篇已实测)。

方案分七步:① 编译配置 → ② QEMU 虚拟网卡环境 → ③ KGDB 断点走链路 → ④ ftrace/tracepoint 批量观测 → ⑤ bpftrace 现场 → ⑥ printk 打桩点位 → ⑦ 丢包/性能对账。每步都可以独立做,建议按序建立。

## 1. 编译配置:一次编对,免得返工

```bash
# 菜单路径仅列关键项, 全部在 Kconfig 有据可查
CONFIG_E1000E=y              # drivers/net/ethernet/intel/Kconfig:61(编进内核, 省模块加载;
                             #   选 m 也可以, 模块模式方便改代码只重编 e1000e)
CONFIG_PCI=y
CONFIG_DEBUG_INFO=y          # vmlinux 带调试信息, gdb 必需
CONFIG_DEBUG_INFO_BTF=y      # BTF: bpftrace 直接读结构体(skb->len 等字段解析)
CONFIG_KGDB=y                # gdb-kernel-debugging.rst
CONFIG_KGDB_SERIAL_CONSOLE=y # kgdboc 走虚拟串口
CONFIG_FRAME_POINTER=y       # 栈回溯可靠(arm64 可用 ORC 替代项视架构)
CONFIG_KPROBES=y / CONFIG_KPROBE_EVENTS=y
CONFIG_FTRACE=y / CONFIG_FUNCTION_TRACER / CONFIG_FUNCTION_GRAPH_TRACER
CONFIG_DYNAMIC_FTRACE=y
CONFIG_TRACEPOINTS=y         # net:napi_poll / sock:sk_data_ready 等全部依赖它
CONFIG_NET_DEVLINK=y         # (可选) ethtool 之外的设备健康视图
CONFIG_IO_URING=y            # 010 的 io_uring 专题验证
CONFIG_EPOLL 系随 syscalls 默认开
```

> 交叉编译注记(与本仓库 [mac-arm64 实验法] 工作流一致):macOS 上用 `make ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu-`(或 `clang -target aarch64-linux-gnu`)编 aarch64 内核,QEMU `virt` 机型带 PCIe,e1000e 可用;若想对齐多数教程也可编 x86_64(`ARCH=x86_64` + `qemu-system-x86_64`)。**e1000e 两条路都能跑**,本文命令两边通用,差异只在 QEMU 启动行(§2)。

```bash
# 产出核对: 编完确认三样东西在
ls vmlinux                        # gdb 符号来源
ls drivers/net/ethernet/intel/e1000e/   # e1000e.o(内建)或 e1000e.ko(模块)
pahole -C sk_buff vmlinux | head  # 有 BTF 时可用; 无则装 dwarves(可选)
```

## 2. QEMU 环境:e1000e 默认网卡

```bash
# ---- x86_64 客户机 ----
qemu-system-x86_64 -m 2G -smp 4 \
  -kernel arch/x86_64/boot/bzImage \
  -append "console=ttyS0 kgdboc=ttyS1,115200 nokaslr" \
  -device e1000e,netdev=n0 -netdev user,id=n0,hostfwd=tcp::10022-:22 \
  -device e1000e,netdev=n1 -netdev tap,id=n1,ifname=tap0 \   # 第二块卡做"对端"
  -serial mon:stdio -serial tcp::1234,server,nowait \
  -initrd rootfs.cpio.gz -nographic

# ---- aarch64 客户机(macOS 上与本仓库习惯一致) ----
qemu-system-aarch64 -M virt -cpu cortex-a76 -m 2G -smp 4 \
  -kernel arch/arm64/boot/Image \
  -append "console=ttyAMA0 kgdboc=ttyAMA1,115200 nokaslr" \
  -device e1000e,netdev=n0 -netdev user,id=n0 \
  -serial stdio -serial tcp::1234,server,nowait \
  -initrd rootfs.cpio.gz -nographic
```

要点:
- `-netdev user`(SLIRP)自带"对端 10.0.2.2",零配置可 ping 可 curl,适合走通链路;`-netdev tap`/`socket` 适合让**宿主机或第二台 QEMU 当对端**做真流量(配 pktgen,§7);
- `nokaslr` 让 gdb 断点地址稳定;`kgdboc` 指向第二串口(与控制台分离);
- 进系统后验证三层注册完毕:

```bash
dmesg | grep -i e1000e        # probe 成功打印(BAR/MAC/中断模式)
lspci -vv | grep -A8 -i '82574\|Intel'    # BusMaster+/MSI-X Enable+
ethtool -i eth0               # driver: e1000e
cat /proc/interrupts | grep -i e1000    # MSI-X/MSI/legacy 三种模式在这里区分(005 §3)
ip link set eth0 up && ip addr add 10.0.2.15/24 dev eth0
ping 10.0.2.2                 # 通了 → 收发链路已全链激活
```

## 3. KGDB 断点清单:五层各钉两三针

宿主机:`gdb vmlinux` → `target remote localhost:1234`(详见 gdb-kernel-debugging.rst)。断点按 [000 §5](000.全景-五层架构与关键数据结构.md) 两条主链路布置,**全部是 7.1.3 树实测行号**:

```gdb

b __sys_sendto            # socket.c:2231  fd→socket→msghdr

```

实用 gdb 技巧(内核会话):

```gdb
# 现场观察(以 tcp_sendmsg 断点停住为例)
p sk->sk_sndbuf               # 发送缓冲上限
p sk->sk_wmem_alloc
p *(struct tcp_sock *)sk      # tcp_sock 视角(snd_cwnd/rcv_nxt...)
p ((struct sock *)skb->sk)->sk_receive_queue   # 收包队列
p skb->len
# e1000e 现场
p ((struct e1000_adapter *)netdev_priv(netdev))->tx_ring->next_to_use
# net_device ↔ adapter 互查(004 §2 关系图)
p netdev->netdev_ops          # 应指向 e1000e_netdev_ops
# 符号在哪
info line tcp_sendmsg_locked / info line *e1000_xmit_frame
```

> **硬中断现场纪律**:e1000_intr_msi 断住时,整个系统对这块卡是"停"的(中断被应答后未重新使能),观察要快或改用 tracepoint(§4)。ISR 只有"读 ICR + 调度 NAPI"两件事(005 §6),断它只为验证中断到达,不值得长期停。

## 4. ftrace / tracepoint:不断点的全链路流水账

内核自带网络事件(tracepoint 定义行号实测,全部 `echo 1 > events/<dir>/<ev>/enable`):

|事件|定义|看什么|
|-|-|---|
|`net:net_dev_queue`|[net.h:159](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/trace/events/net.h#L159)|skb 进驱动(qdisc 出队/直发)|
|`net:net_dev_start_xmit`/`net:net_dev_xmit`|xmit_one 内,dev.c:3877-3890|驱动接包/硬件回执(NETDEV_TX_OK?)|
|`net:netif_rx` / `net:netif_receive_skb`|[net.h:173](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/trace/events/net.h#L173)/:166|收包 backlog/上送协议栈|
|`napi:napi_poll`|[napi.h:14](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/trace/events/napi.h#L14)|轮询次数/工作量(budget 用尽信号)|
|`net:napi_gro_receive_entry`|[net.h:255](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/trace/events/net.h#L255)|GRO 输入([007 §5](007.收包全链路-从网线到epoll.md))|
|`skb:kfree_skb` / `skb:consume_skb`|[skb.h:24](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/trace/events/skb.h#L24)/:57|★ 丢包带 reason / 正常释放|
|`sock:sk_data_ready`|[sock.h:240](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/trace/events/sock.h#L240)|★ "包已到 socket, 谁该醒"|
|`tcp:tcp_probe`|[tcp.h:367](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/trace/events/tcp.h#L367)|序列号/窗口/拥塞窗轨迹(收发节奏)|

```bash
cd /sys/kernel/tracing
echo 1 > events/net/net_dev_queue/enable
echo 1 > events/net/net_dev_xmit/enable
echo 1 > events/napi/napi_poll/enable
echo 1 > events/sock/sk_data_ready/enable
echo 1 > tracing_on
ping -c1 10.0.2.2 >/dev/null
cat trace | grep -v '^#' | head -30     # 一条 ICMP 的完整旅程, 时间戳即延迟分解

# 函数图 trace: 抓 e1000e_poll 的完整调用树(带耗时)
echo e1000e_poll > set_graph_function
echo function_graph > current_tracer
cat trace | head -40

# trace-cmd 成套带走(离线用 kernelshark 分析)
trace-cmd record -e net -e napi -e sock -e skb sleep 5 && trace-cmd report | less
```

## 5. bpftrace:带结构体字段的现场取证

(客户机内核需 CONFIG_DEBUG_INFO_BTF=y;否则用 kprobe + 手动偏移。)

```bash
# ① 收包延迟分解: 中断→轮询→入队→唤醒(007 总图的时间标尺)
sudo bpftrace -e '
  kprobe:e1000_intr_msi      { @t0[cpu] = nsecs; }
  kprobe:e1000e_poll         { @t1[cpu] = nsecs; }
  kprobe:tcp_queue_rcv       { @t2[cpu] = nsecs; }
  tracepoint:sock:sk_data_ready {
      printf("中断→poll %d us, poll→入队 %d us\n",
             (@t1[cpu]-@t0[cpu])/1000, (@t2[cpu]-@t1[cpu])/1000); }'

# ② 发包节奏与背压(008)
sudo bpftrace -e '
  kprobe:tcp_sendmsg_locked    { @send[comm] = count(); }
  kprobe:tcp_write_xmit        { @xmit[comm] = count(); }
  kprobe:sk_stream_wait_memory { @blocked[comm] = count(); }   # >0 = 应用被背压
  interval:s:2 { print(@send); print(@xmit); print(@blocked); }'

# ③ 丢包原因直读(kfree_skb 带 reason, 7.1.3 dropreason.h 语义)
sudo bpftrace -e 'tracepoint:skb:kfree_skb { @[args->reason] = count(); }'

# ④ NAPI/软中断健康
sudo bpftrace -e 'tracepoint:napi:napi_poll {
  @poll[args->napi] = count(); @work += args->work; }
  kprobe:net_rx_action { @softirq++; }'

# ⑤ io_uring 专题(010)
sudo bpftrace -e '
  kprobe:io_submit_sqes      { @s++; }
  kprobe:io_arm_poll_handler { @eagain++; }
  kprobe:io_poll_task_func   { @wake++; }'
```

## 7. 丢包与性能对账:计数器清单(逐环点名)

每层都有自己的计数器,**丢包排查 = 沿链路对账**:

<pre>
ethtool -S eth0                    netdev.c e1000e_get_stats64(:5994) 汇报的硬件计数
  ├ rx_packets/rx_bytes            DMA 已收(006 §5 流水线走通)
  ├ rx_missed_errors               ★ 环满(RDH 追上 RDT)——补环不及时/软中断饿死
  ├ rx_no_buffer / rx_errors       CRC/帧错误——链路或 QEMU 后端问题
  └ tx_packets/tx_fifo/tx_carrier  发送侧错误
/proc/net/softnet_stat             per-CPU
  ├ 第2列 dropped                  ★ backlog 满(enqueue_to_backlog 丢, dev.c:5373)
  ├ 第3列 time_squeeze             ★ net_rx_action budget 用尽次数(软中断压力大)
  └ 第N列 cpu_collision/flow_limit …
nstat -az                          IP/ICMP/TCP 层
  ├ IpInDiscards / IpInDelivers    002 §2 的判决统计
  ├ TcpExtTCPTimeouts / TCPRetransFail
  └ ListenOverflows / ListenDrops  全连接队列溢出(握手文档已覆盖)
ip -s link / ss -tni               队列水位与 rx_dropped/tx_dropped

</pre>

## 9. 常见坑速查

1. **gdb 连不上**:确认 `-serial tcp::1234,server,nowait` 与 `kgdboc` 指同一串口;`nokaslr` 必加;`detach` 后记得 `set iack on`(x86);
2. **断点不中**:函数被内联(如 `dev_queue_xmit`)/被优化——用 `info line <symbol>` 确认,内联函数改断调用点;
3. **MSI-X vs INTx**:QEMU 老版本对 e1000e MSI-X 支持不全导致回退 legacy,现象是 `/proc/interrupts` 里中断号是共享 IO-APIC(005 §3 的三级降级链正好可观察);
4. **bpftrace 读不到结构体**:CONFIG_DEBUG_INFO_BTF 没编;
5. **收包计数不涨但 ping 通**:可能走的是 SLIRP 内部虚拟回环——换 tap 后端或看 `ethtool -S` 的 rx_packets 区分;
6. **软中断吃满单核**:`time_squeeze` 飙升 → 正常,这就是 budget 机制在工作;想看跨核分布,多队列(igb/ixgbe)才有,e1000e 单队列 + RPS( Documentation/networking/scaling.rst)可实验。
