握手文档管"连接怎么建立",本文管"数据怎么流"。TCP 数据面只有两条主线:**发送**(`tcp_sendmsg` 家族,把用户数据变成有序的段)和**接收**(`tcp_v4_rcv` 家族,把乱序到达的段排成有序的字节流并唤醒应用)。

## 1. 发送:tcp_sendmsg 如何把字节变成段

用户 `send()` 最终到达(分派链见 [001 §3](001.应用层-socket收发数据.md)):

```c
// net/ipv4/tcp.c:1447
int tcp_sendmsg(struct sock *sk, struct msghdr *msg, size_t size)
{
	int ret;

	lock_sock(sk);
	ret = tcp_sendmsg_locked(sk, msg, size);      // :1117
	release_sock(sk);

	return ret;
}
```

要点:

- **拷贝发生在进程上下文**:用户缓冲 → `sk_buff`(发送缓冲区 `sk->sk_write_queue`),这是网络栈里最大的一笔 memcpy;
- **睡眠点** `sk_stream_wait_memory`(stream.c:122):发送缓冲(`sk_sndbuf`)打满时睡在 `sk->sk_wq`,等 `sock_def_write_space`(sock.c:3629)被 ACK 回收唤醒——这正是 `EPOLLOUT` 的内核语义(见 [009](009.epoll-事件驱动网络IO.md));
- **择机出网**:`tcp_push` → `__tcp_push_pending_frames`(tcp_output.c:3234)→ `tcp_write_xmit`(:2963)。是否立即发,由 Nagle、拥塞窗口(`snd_cwnd`)、接收窗口(`snd_wnd`)共同裁决——哪怕应用一口气 send 10MB,出网节奏也是 TCP 说了算。

## 2. 接收:tcp_v4_rcv 把段排成字节流

## 3. 接收读取:tcp_recvmsg 与就绪判定 tcp_poll

`tcp_poll`(tcp.c:533)是 poll/select/epoll 都会走的就绪探针,读法一句话:**`rcv_nxt` 超过 `copied_seq` 说明有新数据(EPOLLIN);发送队列有空间且拥塞窗口未堵说明可写(EPOLLOUT);双向 shutdown 才给 EPOLLHUP**:

```c

	if (state == TCP_LISTEN)
		return inet_csk_listen_poll(sk);    // 全连接队列非空 → EPOLLIN(accept 就绪)
	...

	if (shutdown == SHUTDOWN_MASK || state == TCP_CLOSE)   // 双向关闭才 HUP

	...

	...

```

## 4. 三张表:数据面的缓冲区账本

|缓冲|字段|生产者|消费者|满了/空了的行为|
|-|-|-|-|-|
|发送缓冲|`sk_sndbuf` + `sk_write_queue`|tcp_sendmsg 拷贝|tcp_write_xmit 出网|睡眠 `sk_stream_wait_memory`(stream.c:122)|
|接收缓冲|`sk_rcvbuf` + `sk_receive_queue`|tcp_queue_rcv(tcp_input.c:5499)|tcp_recvmsg 拷走|超过 rcvbuf → 收缩接收窗口(向对端宣告 0 窗)|
|乱序队列|`tp->out_of_order_queue`|tcp_data_queue 乱序分支|前端有序化后并入 receive_queue|超限丢段+重复 ACK(SACK 协商则标 SACK)|

## 5. 实测

```bash
# 1. 收包唤醒链路打点(与本文行号一一对应)
sudo bpftrace -e '
  kprobe:tcp_v4_rcv        { printf("tcp_v4_rcv\n"); }
  kprobe:tcp_rcv_established { printf("  established 快路径\n"); }
  kprobe:tcp_queue_rcv     { printf("  入 receive_queue\n"); }
  kprobe:sock_def_readable { printf("  sk_data_ready → 唤醒\n"); }'

# 2. 发送节奏(看 TCP 层怎么"卡"应用)
sudo bpftrace -e '
  kprobe:tcp_sendmsg_locked { @send[comm] = count(); }
  kprobe:tcp_write_xmit     { @xmit[comm] = count(); }
  kprobe:sk_stream_wait_memory { @blocked[comm] = count(); }
  interval:s:1 { print(@send); print(@xmit); print(@blocked); }'

# 3. 缓冲区水位
ss -tinp   # 看 send-q / recv-q: 接收堆积=应用读得慢, 发送堆积=对端收得慢/链路堵
```
