# 008.发包全链路:从 sk_buff 到网线<sup>LINUX 7.1.3 · E1000E</sup>

> 学习/出处:
> + 本仓库源码(本文行号均指此树):[net/ipv4/tcp.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/tcp.c)、[tcp_output.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/tcp_output.c)、[net/ipv4/ip_output.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/ip_output.c)、[net/core/dev.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/dev.c)、[net/sched/sch_generic.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/sched/sch_generic.c)、[e1000e/netdev.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/drivers/net/ethernet/intel/e1000e/netdev.c)
> + 本文主线:发包 = 协议栈把 `sk_buff` 交给驱动 → 驱动映射 DMA → 通知硬件发送

收包靠中断推动([007](007.收包全链路-从网线到epoll.md)),**发包几乎全程是"推"的**:应用 push → TCP 择机 push → IP push → 邻居 push → qdisc push → 驱动 push 门铃。本文沿这条推力走完全程,并回答"发送缓冲满/队列满时,谁把应用再叫醒"。

## 2. TCP 半场:择机出网与唤醒写者

[003 §1](003.协议栈层-TCP数据面.md) 已细读 `tcp_sendmsg_locked`;这里补两个"发包特有"的点:

- **择机**:应用 `send` 返回 ≠ 数据上网络。数据先进发送缓冲,`forced_push`(:1391)满足(Nagle/满半段/有 ACK 要带)才调 `__tcp_push_pending_frames` → `tcp_write_xmit`(:2963)——后者还要过**拥塞窗口**(`snd_cwnd`)和**接收窗口**(`snd_wnd`)两道闸,发不出去的段留在写队列等重传定时器/新 ACK;
- **背压**:发送缓冲 `sk_sndbuf` 用尽 → `sk_stream_wait_memory`(stream.c:122)睡眠。谁叫醒?**对端 ACK**:`tcp_clean_rtx_queue`(tcp_input.c:3602)释放写队列中已确认的原始 skb → 析构回调 `sock_wfree`(sock.c:2676)归还 `sk_wmem_alloc` 并调 `sk->sk_write_space` → `sock_def_write_space`(sock.c:3629)。注意 TX 完成侧是另一条独立链:`e1000_clean_tx_irq` → `netif_wake_queue`(netdevice.h:3706)只解停 qdisc/设备队列——它释放的是 `__tcp_transmit_skb` 的 clone(`__skb_clone` 置 `destructor = NULL`,skbuff.c:1615,不碰 wmem 记账):

```c
// net/core/sock.c:3629(节选)
static void sock_def_write_space(struct sock *sk)
{
	...
	/* Do not wake up a writer until he can make "significant"
	 * progress.  --DaveM
	 */
	if (sock_writeable(sk)) {                        // 可用空间 ≥ 空间的一半
		wq = rcu_dereference(sk->sk_wq);
		if (skwq_has_sleeper(wq))
			wake_up_interruptible_sync_poll(&wq->wait, EPOLLOUT |
						EPOLLWRNORM | EPOLLWRBAND);
		sk_wake_async_rcu(sk, SOCK_WAKE_SPACE, POLL_OUT);
	}
	...
}
```

这同时就是 **`EPOLLOUT` 就绪的内核语义**(epoll 写事件的回调链见 [009 §3](009.epoll-事件驱动网络IO.md))。

## 3. 设备层:排队、调度与三种"立刻发"

`__dev_queue_xmit`(dev.c:4766)先选队列(`netdev_core_pick_tx` 内联于 netdevice.h:2711),再按 qdisc 形态分三路:

```c
// net/core/dev.c:4766(节选, 行号实测)
int __dev_queue_xmit(struct sk_buff *skb, struct net_device *sb_dev)
{
	...
	rcu_read_lock_bh();                                  // :4791
	txq = netdev_core_pick_tx(dev, skb, sb_dev);         // :4825 多队列选路(e1000e 恒 0)
	q = rcu_dereference_bh(txq->qdisc);

	if (q->enqueue) {                                    // :4830 有排队规则
		rc = __dev_xmit_skb(skb, q, dev, txq);           // :4831 → :4180
		...
	}
	...   // noqueue(如 lo): 直接发
	...
	skb = dev_hard_start_xmit(skb, dev, txq, &rc);       // :4870
	...
}
```

`__dev_xmit_skb`(:4180):skb 入 qdisc 队列,然后 `__qdisc_run` 立刻尝试清空队列。调度循环:

```c
// net/sched/sch_generic.c:440
void __qdisc_run(struct Qdisc *q)
{
	int quota = READ_ONCE(net_hotdata.dev_tx_weight);   // 每轮配额(默认 64)
	int packets;

	while (qdisc_restart(q, &packets, quota)) {         // :418 dequeue→xmit 一轮
		quota -= packets;
		if (quota <= 0) {                               // 配额用完
			...
			__netif_schedule(q);                        // 挂 TX 软中断改天再发(类比 NET_RX)
			break;
		}
	}
}
```

`qdisc_restart`(:418)→ `sch_direct_xmit`(:344):出队 → `validate_xmit_skb_list`(dev.c:4078,GSO 切段/校验和/特殊检查)→ `dev_hard_start_xmit`(dev.c:3894)→ `xmit_one`(:3877):

```c
// net/core/dev.c:3877(全文)
static int xmit_one(struct sk_buff *skb, struct net_device *dev,
		    struct netdev_queue *txq, bool more)
{
	unsigned int len;
	int rc;

	if (dev_nit_active_rcu(dev))
		dev_queue_xmit_nit(skb, dev);        // 抓包: 出站包给 ptype_all 一份副本

	len = skb->len;
	trace_net_dev_start_xmit(skb, dev);      // tracepoint(011 §3)
	rc = netdev_start_xmit(skb, dev, txq, more);   // netdevice.h:5371 → __netdev_start_xmit(netdevice.h:5363)
	trace_net_dev_xmit(skb, rc, dev, len);   // 成功 tracepoint: 驱动已接手

	return rc;
}
```

`netdev_start_xmit` 的最后一跳(netdevice.h:5363)就是多态分派:

```c
// include/linux/netdevice.h:5363
static inline netdev_tx_t __netdev_start_xmit(const struct net_device_ops *ops,
					      struct sk_buff *skb, struct net_device *dev,
					      bool more)
{
	netdev_xmit_set_more(more);              // 传给驱动 netdev_xmit_more() 判断
	return ops->ndo_start_xmit(skb, dev);    // = e1000_xmit_frame
}
```

> **为什么发包也要配额/软中断?** 与收包同理:队列清空循环不能无限占用当前上下文。`net_tx_action`(dev.c:5780)是 TX 侧软中断(NET_TX_SOFTIRQ,注册于 net_dev_init(:13211)的 open_softirq(:13288)),负责"被 `__netif_schedule` 推迟的 qdisc"的继续调度。实际流量下 TX 软中断少见(多数 skb 当场发完),而 RX 软中断才是常客。

## 4. 驱动层:映射、描述符、门铃(005 §4 的浓缩回顾)

```
// e1000_xmit_frame (netdev.c:5803) 关键五步
① 资源检查: e1000_maybe_stop_tx(count+2) → 不足返回 NETDEV_TX_BUSY(:5877), qdisc 重试
② 卸载判定: e1000_tso(:5454)/e1000_tx_csum(:5519) → 硬件代劳分段/校验和(写 context 描述符)
③ DMA 映射: e1000_tx_map(:5573) 线性区+frags 逐片 dma_map_single → 总线地址(:5593)
④ 填描述符: e1000_tx_queue(:5667) buffer_addr/cmd(EOP|RS), wmb(:5728), next_to_use 推进(:5730)
⑤ 敲门铃:   netdev_xmit_more() 不为真或队列停时 writel(next_to_use, tx_ring->tail)(:5942)
```

返回值约定:`NETDEV_TX_OK`(描述符已收下)/`NETDEV_TX_BUSY`(驱动没消化,qdisc 稍后重试)——这是协议栈↔驱动的发包层间契约。

## 5. 完成侧:TX 回收与 BQL

硬件发完一个描述符(RS 位置了)就写回 `E1000_TXD_STAT_DD`(defines.h:278)并攒中断。驱动在 `e1000_clean_tx_irq`(:1216,由 e1000e_poll :2668 调)回收:

```c
// netdev.c:1216(节选, 行号实测)
static bool e1000_clean_tx_irq(struct e1000_ring *tx_ring)
{
	...
	eop_desc = E1000_TX_DESC(*tx_ring, eop);
	while ((eop_desc->upper.data & cpu_to_le32(E1000_TXD_STAT_DD)) &&   // :1232 硬件完成?
	       (count < tx_ring->count)) {
		...
		dma_rmb();                                                  // :1236
		...
		e1000_put_txbuf(tx_ring, buffer_info, false);               // :1251 → :1063, 内部 dma_unmap_single
		...
	}
	...
	netdev_completed_queue(netdev, pkts_compl, bytes_compl);        // :1267 BQL 记账
	...
	if (count && netif_carrier_ok(netdev) &&                    // :1270
	    e1000_desc_unused(tx_ring) >= TX_WAKE_THRESHOLD) {      // :1271
		...
		smp_mb();                                               // :1275

		if (netif_queue_stopped(netdev) &&                      // :1277
		    !(test_bit(__E1000_DOWN, &adapter->state))) {
			netif_wake_queue(netdev);                           // :1279 → 唤醒 EPOLLOUT/写阻塞者
			++adapter->restart_queue;
		}
	}
	...
}
```

三件完成的后续:

1. **DMA 解绑**:`e1000_put_txbuf`(:1063)内部 `dma_unmap_single`(:1074)——与收包侧对称,流式映射的生命周期 = 一个包;
2. **BQL(Byte Queue Limits)**:`netdev_sent_queue`(发,netdev.c:5928)/`netdev_completed_queue`(收,:1267)记账,内核据此动态限制"驱动内积压字节数"——把长队列消灭在驱动里,降低缓冲延迟(bufferbloat);
3. **解停设备队列**:`netif_wake_queue`(:1279)清 `__QUEUE_STATE_DRV_XOFF` 并重新调度 qdisc,让积压段继续出网——它**不**唤醒任何 socket。写者的唤醒由收包侧 ACK 驱动(§2 背压):`tcp_clean_rtx_queue` → `sock_wfree` → `sock_def_write_space`(sock.c:3629)→ 阻塞写恢复 / epoll `EPOLLOUT` / io_uring 的 send 可再推进。

> **对账公式**(调试 [011 §6](011.调试方案-e1000e内核网络调试.md) 用):`ethtool -S` 的 `tx_packets` ≈ 应用发出的包数;`tx_fifo_errors/tx_carrier_errors` 是硬件侧错误;应用卡在 `send()` 且 `Send-Q` 打满、`tx_cleaned` 正常 → 对端/链路问题,不是本机驱动问题。
