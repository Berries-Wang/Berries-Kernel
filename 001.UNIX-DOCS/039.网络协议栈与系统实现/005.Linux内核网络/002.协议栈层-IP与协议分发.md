# 002.协议栈层(IP):inet_protos、ip_local_deliver 与路由<sup>LINUX 7.1.3</sup>

> 学习/出处:
> + 本仓库源码(本文行号均指此树):[net/ipv4/ip_input.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/ip_input.c)、[net/ipv4/ip_output.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/ip_output.c)、[net/ipv4/protocol.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/protocol.c)、[net/ipv4/af_inet.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/af_inet.c)、[net/ipv4/route.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/ipv4/route.c)、[net/core/neighbour.c](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/net/core/neighbour.c)
> + 协议规范:RFC 791(Internet Protocol)、RFC 1122 §3(链路层/IP 层要求)

IP 层是协议栈的"路由器":**收包**时决定这个包"继续转发还是交给本机上层协议"(解封装终点),**发包**时决定"从哪块网卡、经哪个网关出去"(封装起点)。本文聚焦 7.1.3 的两张核心表与两条主路径;TCP 半场见 [003](003.协议栈层-TCP数据面.md)。

## 1. inet_protos[]:IP 上层协议的注册表

IP 头只有 1 字节的 `protocol` 字段(IPPROTO_TCP=6 / UDP=17 / ICMP=1)。谁来消费这个号?一张静态注册表:

```c
// net/ipv4/protocol.c:27(声明见 include/net/protocol.h:95, 上限 :34 MAX_INET_PROTOS=256)
struct net_protocol __rcu *inet_protos[MAX_INET_PROTOS] __read_mostly;

// net/ipv4/protocol.c:32(全文, 行号实测)
int inet_add_protocol(const struct net_protocol *prot, unsigned char protocol)
{
	return !cmpxchg((const struct net_protocol **)&inet_protos[protocol],   // :33 原子占坑
			NULL, prot) ? 0 : -1;       // 注册一次成功, 运行期只读(RCU)
}
```

开机时 `inet_init`(af_inet.c:1887)把各家 handler 挂进表——TCP 的 handler 正是收包主入口 `tcp_v4_rcv`:

```c
// net/ipv4/af_inet.c:1938(TCP handler 注册, 5.9 起放 net_hotdata 缓存行)
	net_hotdata.tcp_protocol = (struct net_protocol) {
		.handler	=	tcp_v4_rcv,          // tcp_ipv4.c:2068
		.err_handler	=	tcp_v4_err,
		.no_policy	=	1,
		.icmp_strict_tag_validation = 1,
	};
	if (inet_add_protocol(&net_hotdata.tcp_protocol, IPPROTO_TCP) < 0)   // :1944
		pr_crit("%s: Cannot add TCP protocol\n", __func__);
```

UDP/ICMP/IGMP 同法(af_inet.c:1935/1927/1947)。这张表就是五层图里"协议栈内部的多态分发表":

<pre>
              inet_protos[]  (protocol.c:27, 以 protocol 字段为下标)
   ┌──────────┬──────────┬──────────┬──────┬──────────┐
   │  1 ICMP  │  ...     │  6 TCP   │17 UDP│ ...     │
   └──────────┴──────────┴────┬─────┴──────┴──────────┘
                              │ rcu_dereference(inet_protos[6])
                              ▼
                    net_protocol.handler = tcp_v4_rcv
</pre>

## 2. 收包:ip_rcv → ip_local_deliver → handler

以太帧被驱动上送后(路径见 [007](007.收包全链路-从网线到epoll.md)),IP 头进入视野。7.1.3 把 `ip_rcv` 拆成"校验壳 + 实体"两段:

```c
// net/ipv4/ip_input.c:603
int ip_rcv(struct sk_buff *skb, struct net_device *dev, struct packet_type *pt,
	   struct net_device *orig_dev)
{
	struct net *net = dev_net(dev);

	skb = ip_rcv_core(skb, net);              // :499  校验/去挠
	if (skb == NULL)
		return NET_RX_DROP;

	return NF_HOOK(NFPROTO_IPV4, NF_INET_PRE_ROUTING,   // netfilter 钩子
		       net, NULL, skb, dev, NULL,
		       ip_rcv_finish);                       // :478
}
```

**第一段 `ip_rcv_core`**(:499):长度够不够 IP 头、版本是不是 4、校验和、`skb->len` 与 `iph->tot_len` 一致性——不合格直接 `kfree_skb_reason`(丢包原因可被 dropwatch 观察,见 [011](011.调试方案-e1000e内核网络调试.md))。

**第二段 `ip_rcv_finish`**(:478)→ `ip_rcv_finish_core`(:361):**路由判决**——

```c
// net/ipv4/ip_input.c:407(ip_rcv_finish_core 内)
	drop_reason = ip_route_input_noref(skb, iph->daddr, iph->saddr,
					   ip4h_dscp(iph), dev);   // :407-408 查 fib 路由表
```

查出的路由存在 `skb_dst(skb)`,其 `input` 回调把包分成三类去向:

```c
// net/ipv4/ip_input.c:492(ip_rcv_finish 内)
		ret = dst_input(skb);      // dst->input: ip_local_deliver | ip_forward | ip_error
```

|判决|dst->input|函数|去哪|
|-|-|-|---|
|给本机|`ip_local_deliver`|ip_input.c:250|上行协议栈(本文主线)|
|转发|`ip_forward`|ip_forward.c|出另一块网卡(经 `ip_output`)|
|不可达|`ip_error`|route.c|回 ICMP|

**本机交付** `ip_local_deliver`(:250)先做分片重组,再过 netfilter LOCAL_IN,交给 `ip_local_deliver_finish`:

```c
// net/ipv4/ip_input.c:250
int ip_local_deliver(struct sk_buff *skb)
{
	struct net *net = dev_net(skb->dev);

		if (ip_is_fragment(ip_hdr(skb))) {              // 分片 → ip_defrag 重组
		if (ip_defrag(net, skb, IP_DEFRAG_LOCAL_DELIVER))
			return 0;
	}

	return NF_HOOK(NFPROTO_IPV4, NF_INET_LOCAL_IN,
		       net, NULL, skb, skb->dev, NULL,
		       ip_local_deliver_finish);          // :229
}
```

`ip_local_deliver_finish`(:229)剥掉 IP 头(`__skb_pull`),最后按 `iph->protocol` 查表分发:

```c
// net/ipv4/ip_input.c:189
void ip_protocol_deliver_rcu(struct net *net, struct sk_buff *skb, int protocol)
{
	const struct net_protocol *ipprot;
	...
resubmit:
	raw = raw_local_deliver(skb, protocol);

	ipprot = rcu_dereference(inet_protos[protocol]);      // ← §1 的表, TCP 命中 tcp_v4_rcv
	if (ipprot) {
		...
		ret = INDIRECT_CALL_2(ipprot->handler, tcp_v4_rcv, udp_rcv,   // :207
				      skb);                                     // :208
		if (ret < 0) {
			protocol = -ret;
			goto resubmit;                            // 协议可"改判"再分发(如 ICMP 差错)
		}
		...
	}
}
```

收包解封装全图:

<pre>
eth 帧 → eth_type_trans(eth.c:155) 设 protocol=ETH_P_IP
  └▶ ip_rcv             ip_input.c:603   netfilter PRE_ROUTING
      ├─ ip_rcv_core    :499  校验: 版本/头长/校验和/总长
      └▶ ip_rcv_finish  :478  (PRE_ROUTING 放行后的下半场)
          ├─ ip_rcv_finish_core :361
          │    └▶ ip_route_input_noref :407  查 FIB → dst
          └▶ dst_input :492
              ├─(转发) ip_forward ─▶ ip_output  …
              └─(本机) ip_local_deliver :250
                  ├─ ip_defrag 重组
                  └─ ip_local_deliver_finish :229  剥 IP 头
                      └▶ ip_protocol_deliver_rcu :189
                          └▶ inet_protos[6].handler = tcp_v4_rcv (tcp_ipv4.c:2068)  → 003
</pre>

## 3. 发包:封装与出口选择

TCP 层把带头的 skb 交给 `ip_queue_xmit`(封装起点,被 `__tcp_transmit_skb` 调用,见 [008](008.发包全链路-从sk_buff到网线.md)):

```c
// net/ipv4/ip_output.c:463(节选)
int __ip_queue_xmit(struct sock *sk, struct sk_buff *skb, struct flowi *fl,
		    __u8 tos)
{
	...
	rt = dst_rtable(__sk_dst_check(sk, 0));        // 缓存路由还有效?
	if (!rt) {
		inet_sk_init_flowi4(inet, fl4);            // 从 sock 组装查找键(daddr/saddr/ports)
		...
		rt = ip_route_output_flow(net, fl4, sk);   // route.c:2929 → FIB 查表
		if (IS_ERR(rt))
			goto no_route;
		sk_setup_caps(sk, &rt->dst);
	}
	skb_dst_set_noref(skb, &rt->dst);

packet_routed:
	...
	/* OK, we know where to send it, allocate and build IP header. */
	skb_push(skb, sizeof(struct iphdr) + (inet_opt ? inet_opt->opt.optlen : 0));
	skb_reset_network_header(skb);
	iph = ip_hdr(skb);
	*((__be16 *)iph) = htons((4 << 12) | (5 << 8) | (tos & 0xff));   // 版本4 + 头长5
	...
	iph->ttl      = ip_select_ttl(inet, &rt->dst);
	iph->protocol = sk->sk_protocol;               // IPPROTO_TCP=6
	ip_copy_addrs(iph, fl4);
	...
	res = ip_local_out(net, sk, skb);              // :125
	...
no_route:
	...
	kfree_skb_reason(skb, SKB_DROP_REASON_IP_OUTNOROUTES);
	return -EHOSTUNREACH;
}
```

`ip_local_out`(:125)→ `__ip_local_out`(:102)(netfilter LOCAL_OUT + 重新算校验和)→ `ip_output`(:428):填出口设备(路由 dst 的 dev)、netfilter POST_ROUTING,然后进入"帧"世界:

```c
// net/ipv4/ip_output.c:428(节选)
int ip_output(struct net *net, struct sock *sk, struct sk_buff *skb)
{
	...
	rcu_read_lock();
	dev = skb_dst_dev_rcu(skb);            // :434 出口网卡由路由决定
	skb->dev = dev;
	skb->protocol = htons(ETH_P_IP);

	ret_val = NF_HOOK_COND(NFPROTO_IPV4, NF_INET_POST_ROUTING,   // :438
				net, sk, skb, indev, dev,
				ip_finish_output,
				!(IPCB(skb)->flags & IPSKB_REROUTED));
	rcu_read_unlock();
	return ret_val;
}
```

`ip_finish_output`(:318,处理 GSO/分片)→ `ip_finish_output2`(:200):**补齐二层头**——查/建邻居表(ARP),把 skb 交给邻居子系统:

```c
// net/ipv4/ip_output.c:200(节选)
static int ip_finish_output2(struct net *net, struct sock *sk, struct sk_buff *skb)
{
	...
	if (unlikely(skb_headroom(skb) < hh_len && dev->header_ops)) {
		skb = skb_expand_head(skb, hh_len);       // 为以太帧头腾 headroom
		if (!skb)
			return -ENOMEM;
	}
	...
	rcu_read_lock();                              // :230
	neigh = ip_neigh_for_gw(rt, skb, &is_v6gw);   // :231 查下一跳邻居表项(ARP)
	if (!IS_ERR(neigh)) {
		int res;

		sock_confirm_neigh(skb, neigh);           // :235
		/* if crossing protocols, can not use the cached header */
		res = neigh_output(neigh, skb, is_v6gw);  // :237 → neighbour.h:547
		rcu_read_unlock();
		return res;
	}
	rcu_read_unlock();
	...
}
```

`neigh_output`(neighbour.h:547):邻居表项已解析(NUD_CONNECTED)则走 `neigh_hh_output` 直接填缓存的帧头;未解析则调用 `n->output = neigh_resolve_output`(neighbour.c:1599)——先广播 ARP,解析完成后把 skb 交给 `dev_queue_xmit`(netdevice.h:3416)。IP 头到这里封装完毕,**帧头由设备层补**(见 [004](004.网络设备抽象层-net_device.md))。

发包封装全图:

<pre>
TCP skb(带 tcp 头)  …续 003
  └▶ __ip_queue_xmit   ip_output.c:463
      ├─ ip_route_output_ports(route.h:201) ─▶ ip_route_output_flow(route.c:2929) 查路由
      ├─ 填 IP 头(tos/ttl/id/protocol)
      └▶ ip_local_out :125 ─▶ __ip_local_out :102(netfilter LOCAL_OUT)
          └▶ ip_output :428   skb->dev = 路由出口网卡; netfilter POST_ROUTING
              └▶ ip_finish_output :318   GSO/分段
                  └▶ ip_finish_output2 :200   查邻居(ARP)
                      └▶ neigh_resolve_output  neighbour.c:1599
                          └▶ dev_queue_xmit  netdevice.h:3416   → 004/008 补以太帧头并交给驱动
</pre>

> **封装/解封装的对称性**:收包是"校验→路由→剥头→查表分发",发包是"查路由→填头→找下一跳→交设备层"。两张流程图拼起来,就是 RFC 1122 里"IP 层是互联网的邮局"这句话的内核实现。

## 4. 路由表 fib 与 dst:判决的依据

- **FIB(转发信息库)**:由 `ip route` 生成的路由表,`fib_lookup` 系列函数查询;`ip_route_input_noref`(:407)与 `ip_route_output_flow`(route.c:2929)是收/发两个方向的入口;
- **dst/rtable**:查询结果的缓存对象,挂在 `skb->skb_dst` 或 `sk->sk_dst_cache` 上,内含 `input/output` 两个函数指针——上面 §2/§3 的去向分发全靠它;同一条流的路由只需查一次,后续 skb 复用缓存;
- 转发加速(如 RPS/RFS/XPS、aRFS)见官方文档 [scaling.rst](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/Documentation/networking/scaling.rst)。
