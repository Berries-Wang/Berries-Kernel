## 2. epoll_ctl:一次"回调安装"

`epoll_ctl(ADD)` → `do_epoll_ctl`(:2238)→ `ep_insert`(:1566)。后者干三件事:建 epitem 入红黑树、调一次 `vfs_poll` 读初始状态、**把回调挂到 socket 的等待队列**:

```c
// fs/eventpoll.c:1566(节选, 行号实测)
static int ep_insert(struct eventpoll *ep, const struct epoll_event *event,
		     struct file *tfile, int fd, int full_check)   // :1566-1567
{
	...
	epi->ep = ep;
	ep_set_busy_poll_napi_id(epi);             // :1666 记 napi_id(busy-poll 用, 见 §6)
	...
	ep_rbtree_insert(ep, epi);                 // :1615 入红黑树
	...
	revents = ep_item_poll(epi, &epq.pt, 1);   // :1650 一次 vfs_poll 读当前状态(顺带装回调)
	...
	/* If the file is already "ready" we drop it inside the ready list */
	if (revents && !ep_is_linked(epi)) {       // :1669 已经就绪? 直接挂 rdllist
		list_add_tail(&epi->rdllink, &ep->rdllist);
		ep_pm_stay_awake(epi);

		/* Notify waiting tasks that events are available */
		if (waitqueue_active(&ep->wq))
			wake_up(&ep->wq);                  // :1675 顺带叫醒正在 epoll_wait 的人
		...
	}
```

回调的安装发生在 `ep_item_poll` → `vfs_poll`(poll.h:78)→ **socket 的 `ops->poll`** → `tcp_poll`,一路走到 `sock_poll_wait`:

```c
// include/linux/poll.h:42(行号实测)
static inline void poll_wait(struct file * filp, wait_queue_head_t * wait_address, poll_table *p)
{
	if (p && p->_qproc) {
		p->_qproc(filp, wait_address, p);      // :45 = ep_ptable_queue_proc

		 * This memory barrier is paired in the wq_has_sleeper().
		 * See the comment above prepare_to_wait(), we need to
		 * ensure that subsequent tests in this thread can't be
		 * reordered with __add_wait_queue() in _qproc() paths.
		 */
	}
}

static inline void sock_poll_wait(struct file *filp, struct socket *sock,
				  poll_table *p)
{
	...
	poll_wait(filp, &sock->wq.wait, p);        // :2427 挂到 socket 等待队列
	...
}

static void ep_ptable_queue_proc(struct file *file, wait_queue_head_t *whead,
				 poll_table *pt)
{
	struct ep_pqueue *epq = container_of(pt, struct ep_pqueue, pt);   // :1362
	struct epitem *epi = epq->epi;             // :1364
	struct eppoll_entry *pwq;
	...
	init_waitqueue_func_entry(&pwq->wait, ep_poll_callback);   // ★ 回调绑定

**注意调用顺序的精妙**:`sock_poll_wait` 先注册回调,`tcp_poll` 的其余代码再计算当前就绪掩码返回——注册一次后,epoll_wait 后续轮询里 `vfs_poll` 只剩"算掩码"这一步,回调已在队列里。

// fs/eventpoll.c:1249(节选, 行号实测)
static int ep_poll_callback(wait_queue_entry_t *wait, unsigned mode, int sync, void *key)
{
	struct epitem *epi = ep_item_from_wait(wait);
	struct eventpoll *ep = epi->ep;
	__poll_t pollflags = key_to_poll(key);        // :1254 唤醒掩码(EPOLLIN/OUT…)
	...
	if (pollflags && !(pollflags & epi->event.events))
		goto out_unlock;                          // :1278 用户没注册这个事件? 忽略
	...
	} else if (!ep_is_linked(epi)) {
		/* In the usual case, add event to ready list. */
		list_add_tail(&epi->rdllink, &ep->rdllist);   // :1294 ★ 挂就绪链表
		ep_pm_stay_awake_rcu(epi);
	}
	...
	if (waitqueue_active(&ep->wq)) {
		...   // EPOLLEXCLUSIVE 判决(§5)
		if (sync)
			wake_up_sync(&ep->wq);
		else
			wake_up(&ep->wq);                     // :1320(sync)/:1322 ★ 唤醒 epoll_wait 睡的进程
	}
	...
}
```

`epoll_wait` 侧 `ep_poll`(:1938)醒来 → `ep_send_events`(:1765)→ `ep_send_events_proc`:**对每个就绪 epitem 再调一次 `ep_item_poll`(:1042)确认**(LT/ET 的分水岭,见 §4),然后 `put_user` 把 `struct epoll_event` 拷回用户态。

</pre>

## 4. LT 与 ET:同一个回调,两种归还策略

|模式|语义|内核差异|典型坑|
|-|-|-|---|
|LT(默认)|只要就绪就**反复**报告|`ep_send_events_proc` 上送后,若 `ep_item_poll` 仍返回就绪,**重新挂回 rdllist**——下一轮 epoll_wait 立刻再报|忘记读 → 无限唤醒(busy loop)|
|ET(`EPOLLET`,eventpoll.h:69)|状态**变化**只报一次|上送后**不再重挂**,直到下次 `ep_poll_callback` 由数据到达触发|必须配合非阻塞 fd 把数据**读到 EAGAIN**,否则剩余数据永远没人管|

```c
// include/uapi/linux/eventpoll.h(节选)
#define EPOLLIN		(__force __poll_t)0x00000001      // :31
#define EPOLLOUT	(__force __poll_t)0x00000004      // :33
#define EPOLLRDHUP	(__force __poll_t)0x00002000      // :42
#define EPOLLEXCLUSIVE	((__force __poll_t)(1U << 28))    // :51 (见 §5)
#define EPOLLONESHOT	((__force __poll_t)(1U << 30))    // :66 报一次后自动 disarm
#define EPOLLET		((__force __poll_t)(1U << 31))    // :69
```

## 5. 惊群与 EPOLLEXCLUSIVE

多进程/多线程 `epoll_wait` 同一个 listen fd 时,一次连接到达唤醒**所有**等待者(惊群)——只有一个 `accept` 成功,其余空转。7.1.3 的三种解法:

1. **EPOLLEXCLUSIVE**(:51):`epoll_ctl` 加此标志后,`ep_ptable_queue_proc` 改用 `add_wait_queue_exclusive` 挂 waiter(eventpoll.c:1379-1381),内核唤醒只放行一个;`ep_poll_callback` 内还有 EWAKE 判决(:1303)——**accept 惊群**可解;
2. **SO_REUSEPORT**:每个线程独立 socket+epoll,内核 `inet_hash_connect`/lookup 按 hash 分发连接——彻底绕开共享;
3. **EPOLLONESHOT**(:66):报一次后 disarm,处理完再 rearm——数据 fd 的常见用法(避免多线程同时读写同一连接)。

> 注意:`EPOLLEXCLUSIVE` 只保证"一个 waiter 被叫",**不保证**最终只有一个进程 accept 成功;数据 fd 上使用会造成"事件来了但被唤醒的进程以为该自己读"的混乱——listen fd 专用。

## 6. SO_BUSY_POLL:epoll 也能主动轮询

epoll 有一个鲜为人知的开关:内核在 `ep_poll` 里可先做 NAPI **busy-poll**(主动轮询驱动的 RX 环,把包"提前"收上来再判就绪):

```c
// fs/eventpoll.c:422
static bool ep_busy_loop_end(void *p, unsigned long start_time)   // 超时判定
```

链路:socket 设 `SO_BUSY_POLL` → `sock_can_busy_loop` → `sock_poll`(socket.c:1485)里的 `sk_busy_loop`(:1497)→ `napi_by_id(napi_id)` 直达驱动 NAPI(就是 [004 §4](004.网络设备抽象层-net_device.md) 的 `napi_id`)。延迟换 CPU,微秒级低延迟场景(交易/电信)才用。

## 7. 与收包/发包路径的完整衔接图

<pre>
                 ┌────────────────────── 收包方向 ──────────────────────┐
 网线 → DMA → 中断 → NAPI(e1000e_poll) → sk_buff → ip_rcv → tcp_v4_rcv
   → tcp_queue_rcv → sk_receive_queue                    [007]
                                              │
                                     sk_data_ready → sock_def_readable
                                              │
              ┌───────────────────────────────┼─────────────────────────┐
              ▼                               ▼                         ▼
      阻塞 recv(醒来拷贝)            ep_poll_callback(:1249)        io_uring(010)
                                        rdllist → epoll_wait 返回        CQE
                 └──────────────────────── 发包方向 ────────────────────┘
 send → tcp_sendmsg(缓冲满→睡) → ... → e1000_xmit_frame → 网线(008)
                                   ▲
     对端 ACK → tcp_clean_rtx_queue → sock_wfree(sock.c:2676) → sock_def_write_space → ep_poll_callback(EPOLLOUT)
     (TX 完成侧 netif_wake_queue 只解停 qdisc, 不碰 socket —— 两条链独立, 详 008 §5)
</pre>

写事件与读事件走的是**同一个回调机制**,只是 `wake_up_interruptible_sync_poll` 的掩码不同(EPOLLIN vs EPOLLOUT)——`ep_poll_callback` 收到的 `key` 就是这个掩码,据此过滤用户注册的事件。
