## 1. 一块 PCIe 网卡的物理 anatomy

<pre>
   ┌────────────────────────── 网卡(适配器) ───────────────────────────┐
   │                                                                   │
   │  ┌─────────────┐  RGMII(简化千兆介质无关接口)   ┌─────────────┐   │
   │  │ PHY 芯片    │◀══════════════════════════════▶│ MAC 控制器  │   │
   │  │(82574 内建) │   4bit DDR 双沿 + 时钟(片内)   │(82574 MAC)  │   │
   │  └─────┬───────┘                                └─────┬───────┘   │
   │        │ RJ45 双绞线                                  │           │
   └────────┼──────────────────────────────────────────────┼───────────┘
            ▼                                              │ PCIe
         对端设备                                          ▼
   ┌──────────────────────────────────────────────────────────────┐
   │                        主机 PCIe 总线                        │
   │   BAR0(MMIO 寄存器窗)  ← ioremap :7441 → 内核虚拟地址        │
   │   MSI/MSI-X 中断消息      ← request_irq :2153                │
   │   Bus Master DMA          ← pci_set_master :7408             │
   │       ├─ 读写 RX/TX 描述符环(dma_alloc_coherent, 一致性内存) │
   │       └─ 读写包缓冲区(dma_map_single/page, 流式内存)         │
   └──────────────────────────────────────────────────────────────┘
</pre>

两层芯片各司其职(MOS 5th §8.3.1 的物理层/链路层划分):

- **PHY(物理层芯片)**:把数字世界翻译成模拟世界——4B/5B 编码、串行化、NRZ 调制、自协商(双绞线两端比速度 10/100/1000 与双工)、链路脉冲。驱动经 **MDIO 总线**访问它的寄存器;
- **MAC 控制器**:以太网帧的组包/拆包、CRC 生成校验、地址过滤、发送 FIFO 与接收 FIFO、**DMA 引擎**(描述符环的硬件一半)。驱动经 **MMIO 寄存器**控制它。

e1000e 的 82574/I219 系列把 PHY 与 MAC 集成在一颗芯片(或由 PCH 分担),但寄存器访问通道依然分两条:MAC 走 BAR0 MMIO,PHY 走 MDIC 寄存器(:13)间接访问。

## 2. PCIe 探测:probe 拿到的三样东西

内核 PCI 子系统按 vendor/device ID 匹配后调用 `e1000_probe`(netdev.c:7369)。驱动此时拿到硬件的三张"通行证":

|通行证|代码|用途|
|-|-|-|
|**BAR0 内存窗**|`pci_resource_start(pdev, 0)` → `ioremap(mmio_start, mmio_len)` netdev.c:7441|得到 `hw->hw_addr`,此后所有 `er32/ew32`(e1000.h:607/611)= 对这段虚拟地址的 `readl/writel`|
|**总线主控权**|`pci_set_master(pdev)` :7408(置 Command 寄存器 Bus Master 位)|不开它,DMA 引擎静默——网卡只能被打,不能主动搬数据|
|**DMA 地址空间承诺**|`dma_set_mask_and_coherent(&pdev->dev, DMA_BIT_MASK(64))` :7395|告诉 IOMMU/内存子系统:本卡能寻址 64 位总线地址|

```bash
# 主机上(或 QEMU 客户机内)直接看这些通行证
lspci -vv -s <slot>
#   Region 0: Memory at f0000000 (32-bit, non-prefetchable) [size=128K]   ← BAR0
#   Capabilities: [40] MSI-X: Enable+ Count=5 Masked-                     ← MSI-X
#   Control: I/O- Mem+ BusMaster+ ...                                     ← Bus Master
```

## 3. MAC 寄存器地图(以 e1000e 用到的为例)

寄存器是 MMIO 窗口上的 32 位槽位,偏移全部定义在 [regs.h](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/drivers/net/ethernet/intel/e1000e/regs.h):

```c
// drivers/net/ethernet/intel/e1000e/regs.h(节选, 行号实测)
#define E1000_CTRL	0x00000	/* Device Control - RW */        // :7
#define E1000_STATUS	0x00008	/* Device Status - RO */        // :8 (LU=链路激活, SPEED/DUPLEX)
#define E1000_MDIC	0x00020	/* MDI Control - RW */          // :13 PHY 访问通道(§4)
#define E1000_ICR	0x000C0	/* Interrupt Cause Read - R/clr */ // :32 读=确认+关本源
#define E1000_ICS	0x000C8	/* Interrupt Cause Set - WO */     // :34 软件模拟中断
#define E1000_IMS	0x000D0	/* Interrupt Mask Set - RW */      // :35 开中断
#define E1000_IMC	0x000D8	/* Interrupt Mask Clear - WO */    // :36 关中断
#define E1000_RCTL	0x00100	/* Rx Control - RW */           // :42
#define E1000_TCTL	0x00400	/* Tx Control - RW */           // :47
#define E1000_PBA	0x01000	/* Packet Buffer Allocation - RW */ // :56 收发 FIFO 切分
#define E1000_RDBAL(_n)	0x02800 + (_n)*0x100  /* Rx Desc Base Addr Low */   // :82
#define E1000_RDLEN(_n)	0x02808 ...            /* Rx Desc Length */         // :86
#define E1000_RDH(_n)	0x02810 ...            /* Rx Desc Head (硬件游标, RO) */ // :88
#define E1000_RDT(_n)	0x02818 ...            /* Rx Desc Tail (软件游标, 门铃) */ // :90
#define E1000_RXDCTL(_n) 0x02828 ...           /* Rx Desc Control */       // :92
#define E1000_TDBAL(_n)	0x03800 ...            /* Tx Desc Base Addr Low */  // :94
#define E1000_TDLEN(_n)	0x03808 ...            /* Tx Desc Length */         // :98
#define E1000_TDH(_n)	0x03810 ...            /* Tx Desc Head (硬件游标) */ // :100
#define E1000_TDT(_n)	0x03818 ...            /* Tx Desc Tail (门铃!) */    // :102
#define E1000_TXDCTL(_n) 0x03828 ...           /* Tx Desc Control */        // :104
#define E1000_RAL(_i)	0x05400 + (_i)*8       /* Receive Addr Low(地址过滤) */ // :108
#define E1000_RAH(_i)	0x05404 ...                                        // :110
```

## 4. PHY:MDIO 总线上的间接访问

PHY 寄存器(BMCR 自协商/BMSR 链路状态/PHYIDR 身份…)挂在 MDIO 两线串行总线上。MAC 提供"信箱"寄存器 MDIC(regs.h:13):驱动把"读哪个 PHY 哪个寄存器"写进 MDIC,硬件代为在 MDIO 上发时序,结果再从 MDIC 取回——`e1000e_read_phy_reg_mdic`(phy.c:129):

```c
// drivers/net/ethernet/intel/e1000e/phy.c:129(节选, 行号实测)
s32 e1000e_read_phy_reg_mdic(struct e1000_hw *hw, u32 offset, u16 *data)
{
	...
	for (retry_counter = 0; retry_counter <= retry_max; retry_counter++) {   // :146
		success = true;

		mdic = ((offset << E1000_MDIC_REG_SHIFT) |    // :149 目标 PHY 寄存器号
			(phy->addr << E1000_MDIC_PHY_SHIFT) |     // :150 目标 PHY 地址
			(E1000_MDIC_OP_READ));                    // :151 读命令

		ew32(MDIC, mdic);                             // :153 投进信箱, 硬件走 MDIO 时序

		/* Poll the ready bit to see if the MDI read completed ... */
		for (i = 0; i < (E1000_GEN_POLL_TIMEOUT * 3); i++) {   // :159 轮询 READY 位
			udelay(50);
			mdic = er32(MDIC);                        // :161
			if (mdic & E1000_MDIC_READY)
				break;
		}
		...
		*data = (u16)mdic;                            // :187 取回结果
}
```

链路协商结果以**链路状态中断(LSC)**上报:PHY 检测到 link up/down → MAC 置 `ICR.LSC` → ISR 读 ICR 判 LSC 位(e1000_intr_msi 内 `if (icr & E1000_ICR_LSC)`,netdev.c:1759)置 `hw->mac.get_link_status = true` → 唤醒 watchdog(`e1000_watchdog_task` :5208)→ `e1000e_check_link` 读 PHY 确认速率/双工 → `netif_carrier_on/off`。**这就是"网线插上/拔掉"事件在内核里的完整旅程**。

## 5. 收包硬件流水线:描述符环的"硬件一半"

驱动把 RX 环基址写进 RDBA(:3243-3245)、长度写进 RDLEN 后,MAC 的 DMA 引擎就自己转起来了:

<pre>
RX 环(256 个 16 字节描述符, 环基址 16 字节对齐)

  index:        0        1        2         3  ... 255
            ┌────────┬────────┬────────┬─────────┬────────┐
            │ addr   │ addr   │ addr   │  addr   │  addr  │  ← RDBA 指向, 硬件按 RDLEN 取模
            └────────┴────────┴────────┴─────────┴────────┘
                 ▲                          ▲
                 │                          │
              RDH(硬件头): 下一个要 DMA 写入的槽     RDT(软件尾): 下一个待填的槽(有效缓冲到 RDT-1)
                     (驱动只读)                     (驱动写 = 门铃, netdev.c:700, 写的是递增后的 i)

硬件每个包的动作: 1) 从 RDH 槽位读 buffer_addr
              2) 帧从 FIFO DMA 到该内存(总线主控写, 无 CPU 参与)
              3) 写回描述符 status: DD=1, EOP=1, 长度, 错误位
              4) RDH++(取模), RDH 追上 RDT = 无可用缓冲 → 后续帧丢弃, 计 rx_missed_errors
              5) 置 ICR.RXT0 → 触发中断(或先攒 RDTR 中断合并间隔)
</pre>

发送侧对称(详细驱动侧见 [005 §4](005.网卡驱动层-e1000e.md),协议栈上游见 [008](008.发包全链路-从sk_buff到网线.md)):

<pre>
TX 环:  TDH(硬件头): 正在取用的槽         TDT(软件尾: 门铃, writel netdev.c:5942)
硬件动作: TDH<TDT 时, 读描述符 → 从 buffer_addr DMA 读数据 → 组帧+FCS → FIFO → PHY 上网线
完成:     命令位 RS 的描述符, 硬件写回 upper.status |= DD → (TIDV 合并)置 ICR.TXDW → 中断
</pre>

两个易错点(也是调试时的坑):

1. **门铃语义**:写 RDT/TDT 不是"发一个包",而是"告诉硬件:到第 N 个槽为止的缓冲区都有效"。e1000e 的 `writel(i, tx_ring->tail)`(:5942)与 `writel(i, rx_ring->tail)`(:700)都是这个语义;`netdev_xmit_more()` 批量优化(005 §4)就是攒着门铃少敲几次;
2. **内存序**:描述符写完必须 `wmb()`(:5728/:696)再敲门铃;读回侧 `dma_rmb()`(:941/:1236)。弱内存序平台上(本仓库 ARM 平台笔记场景)这两条屏障缺一不可,详见 [008.同步原语](../../008.同步原语/001.原子指令/README.md)。

## 6. QEMU 的 e1000e:硬件层怎么"假装"

QEMU 的 `e1000e` 设备模型(`hw/net/e1000e_core.c`)把 §5 的流水线完整复刻:

- BAR0 MMIO 读写 → `e1000e_mmio_read/write` 逐字段模拟寄存器;
- DMA → 宿主机的虚拟内存地址翻译(模拟 IOMMU 时经 `dma_memory_map`);
- 中断 → MSI-X 消息写 APIC → 客户机内核收到 `e1000_intr_msix`(netdev.c:7083);
- PHY → 软件状态机自协商,永远协商成 1000/Full,链路由 `-netdev` 后端(user/tap/socket)决定连通性。

因此**本文集的调试方案([011](011.调试方案-e1000e内核网络调试.md))可以在任何一台 mac/x86/arm 主机上复现完整五层链路**——e1000/e1000e 是 QEMU/KVM 虚拟机的默认网卡型号,离云很近。

## 7. 实测

```bash
# 1. 寄存器池(bpftrace 无法直接读 MMIO, 但可以借内核读)
sudo bpftrace -e '
  kprobe:e1000e_poll { printf("RDH=%d RDT_cur=%d\n", ...); }'
# 更直接: 驱动 debugfs(若启用)/ethtool -d 寄存器转储
sudo ethtool -d eth0 | head -30        # dump MAC 寄存器(Control/Status/...)

# 2. PHY 链路状态(BMSR 视角)
ethtool eth0 | grep -E 'Speed|Duplex|Link|Auto'

# 3. 环满丢包(§5 第 4 步的计数)
ethtool -S eth0 | grep -E 'rx_missed|rx_no_buffer|tx_flow'

# 4. PCIe 侧: 在宿主机看 QEMU 网卡的 BDF
lspci -D | grep -i ethernet
```
