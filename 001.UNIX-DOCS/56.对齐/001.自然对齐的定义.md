# 自然对齐的定义

> 学习: [深入Linux内核架构.pdf](../../007.BOOKs/深入Linux内核架构.pdf) 附录 A.3（PDF 物理页 917）；
> 内核文档 [Documentation/core-api/unaligned-memory-access.rst](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/Documentation/core-api/unaligned-memory-access.rst) *Natural alignment* 一节

---

## 1. 定义：地址能被类型宽度整除

书中原句："通常，对齐是指**对齐到数据类型的字节长度可整除的字节地址**……将数据类型对齐到其自身的字节长度，称之为**自然对齐（natural alignment）**"。

内核文档给出了等价的数学表述：

```
自然对齐:  addr % sizeof(type) == 0
```

| 访问 | 地址要求 | 例子 |
|---|---|---|
| `u8` / `char` | 无（任何地址都能被 1 整除） | 永远不会非对齐 |
| `u16` | 2 字节边界 | `0x10004` ✅ / `0x10005` ❌ |
| `u32` | 4 字节边界 | `0x10000` ✅ / `0x10002` ❌ |
| `u64` / `long`(64位) | 8 字节边界 | `0x10008` ✅ / `0x10004` ❌ |
| `u128`(如 `cmpxchg16b`) | 16 字节边界 | "稍大一些的对齐尺度"实例 |
| 缓存行操作（如 `DC ZVA`） | **64 字节**边界 | 见下文"更大的对齐尺度" |
| 页操作（页表、`PAGE_ALIGN`） | **4KB**边界 | 书 A.4 内存页面 |

**对齐的参照系不止一个**：自然对齐（对齐到自身宽度）是最常用的，但架构还会要求对齐到更大的粒度——缓存行（64B）、16B（SIMD/`LSE2` 的原子性边界）、128B（DMA）、页（4KB）。这正是书中"在某些情况下，会要求稍大一些的对齐尺度"一句的含义，逐一列举见 §4。

## 2. 编译器如何自动满足自然对齐（书中"GCC 自动选择适当的对齐"）

书中最后一句："在 GCC 为各种 struct 或 union 组织内存布局时，会自动选择适当的对齐，使得程序员无须手工进行操作。" 内核文档用同一个例子解释了这件事：

```c
struct foo {
	u16 field1;   // 偏移 0，占 2 字节
	u32 field2;   // 需 4 字节对齐 → 编译器在中间插入 2 字节 padding，放到偏移 4
	u8  field3;   // 偏移 8
};                // 结构体整体对齐取 max(成员对齐) = 4，尾部再 pad 到 12 字节
```

- **成员对齐**：每个成员的偏移会被编译器 pad 到其自身宽度的倍数，保证 `field2` 这类访问天然对齐——这就是"程序员无须手工操作"的机制。
- **结构体整体对齐**：等于最宽成员的对齐值；尾部 padding 保证**数组中每个元素**都对齐（`sizeof(struct foo) = 12` 而不是 9）。
- 内核中要求的是 `__alignof__` 级别的保证，`ARCH_KMALLOC_MINALIGN` 在 arm64 上就取 8：

```c
// arch/arm64/include/asm/cache.h:35
#define ARCH_DMA_MINALIGN	(128)
#define ARCH_KMALLOC_MINALIGN	(8)
```

### 反例：手工重排可以省内存（但可读性下降）

内核文档同时指出，按宽度从大到小重排成员可减少 padding（`field2, field1, field3` 只需尾部 1 字节 padding）。内核热路径结构体（如网络头）常这么干。

## 3. `__packed`：故意取消对齐

线缆上的报文格式（以太网头、IP 头）没有 padding，用 C 结构体直接映射时必须取消编译器的自动 padding：

```c
// include/linux/compiler_attributes.h:291
#define __packed                        __attribute__((__packed__))
```

`__packed` 的两个效果：
1. **取消成员间 padding**：成员紧挨着排，`sizeof` 变小——结构体布局与"线上格式"一一对应；
2. **把结构体的对齐降为 1**：这意味着访问其成员**可能就是非对齐访问**。编译器知道这一点，会生成多条拆分指令（或调用辅助函数）来避免直接非对齐访存——"extra instructions → 损失性能，因此 packed 只在需要精确控制布局时使用"（内核文档原话）。

内核里最典型的用法是把 `__packed` 当作"非对齐访问的原语"——`get_unaligned` 的历史实现直接建立在这上面：

```c
// include/linux/unaligned/packed_struct.h:6
struct __una_u16 { u16 x; } __packed;
struct __una_u32 { u32 x; } __packed;
struct __una_u64 { u64 x; } __packed;

static inline u16 __get_unaligned_cpu16(const void *p)
{
	const struct __una_u16 *ptr = (const struct __una_u16 *)p;
	return ptr->x;     // 编译器知道 ptr->x 对齐为 1，生成按字节拆分的访存
}
```

原理：把任意地址 `p` 强转成"对齐为 1 的 u16 结构体指针"再取成员——编译器被**显式告知**这里不保证对齐，于是生成安全的（拆分的）访问序列，而不是一条可能出错的 `LDRH`。详见 [005.get_unaligned与put_unaligned.md](005.get_unaligned与put_unaligned.md)。

## 4. "稍大一些的对齐尺度"：内核中出现过的对齐粒度清单

书中："在某些情况下，会要求稍大一些的对齐尺度。相关信息一般会在所述处理器的体系结构文档中给出。" 汇总如下：

| 对齐粒度 | 谁要求 | 出处 |
|---|---|---|
| 8B（`sizeof(void*)`） | kmalloc 对象最低对齐 | `ARCH_KMALLOC_MINALIGN`（arm64 = 8） |
| 16B | `LDP/STP` 在 FEAT_LSE2 下保持单拷贝原子性的边界；`cmpxchg16b`(x86)；非原子 `LDAR/STLR`(FEAT_LSE2) 的 fault 边界；MTE 标签粒度（`ARCH_SLAB_MINALIGN` 的 KASAN_HW_TAGS 取值） | ARM ARM B2.8.2（[vol1 物理页 309](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20Architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-1-3000.pdf#page=309)）；[004 §6](004.内核对齐工具箱-源码全景.md) |
| 64B（缓存行） | `SLAB_HWCACHE_ALIGN`、`SKB_DATA_ALIGN`、`____cacheline_aligned`、`FEAT_LS64` 的 64B 原子访问；`DC ZVA` 清零的块也是 64B 对齐（但**地址实参无对齐限制**，硬件自行向下取整到所在块——ARM ARM D7.5.10，[vol6 物理页 1559](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20Architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-6001-9000.pdf#page=1559)） | TRM：CTR_EL0.DminLine/CWG/IminLine=0b0100→64B，见 [003 §1](003.非对齐访问-高速缓存性能视角.md) |
| 128B | arm64 DMA 最低对齐（两倍缓存行）：`ARCH_DMA_MINALIGN` 注释针对"缓冲与邻居共享缓存行"；2×64B 的裕量同时覆盖 **CWG（写回粒度）可能大于 DminLine** 的实现（CWG=0b0000 时架构要求按最大 2KB 假设——CTR_EL0 字段描述，[vol12 物理页 1740](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20Architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-12001-15000.pdf#page=1740)） | [arch/arm64/include/asm/cache.h:28](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/cache.h)；[003 §4](003.非对齐访问-高速缓存性能视角.md) |
| 4KB（页） | 页表基址（`TTBR` 要求页对齐）、vmalloc、per-CPU 页对齐段 | [004.内核对齐工具箱-源码全景.md](004.内核对齐工具箱-源码全景.md) §5-6 |
| 2MB/1GB（大页） | hugetlb、THP、内核镜像映射段 | `PMD_SIZE/PUD_SIZE` 级对齐 |
| （非数据）PC 4B / SP 16B | A64 指令必须字对齐；SP 为基址的访存须 16 字节对齐（Linux 开启 SCTLR.SA/SA0 检查） | 详见 [002 §1.5](002.非对齐访问-架构正确性视角.md) |

**为什么粒度会"越对越大"？** 因为参照系从"一条指令的访问宽度"升级到"一个硬件事务的宽度"：
- 自然对齐服务的是**单条 load/store 指令**（正确性 + 原子性，见 [002.非对齐访问-架构正确性视角.md](002.非对齐访问-架构正确性视角.md)）；
- 缓存行/128B 对齐服务的是**缓存与 DMA 事务**（性能，见 [003.非对齐访问-高速缓存性能视角.md](003.非对齐访问-高速缓存性能视角.md)）；
- 页对齐服务的是**MMU 映射粒度**（页表项、TLB）。

## 5. 快速自检清单（写内核代码时）

1. 访问 `u16/u32/u64` 指针前，想想地址从哪来：来自 `char*` 偏移、报文解析、`__packed` 结构 → 用 `get_unaligned/put_unaligned`；
2. 定义与外部格式对应的结构 → `__packed`，并意识到成员访问有拆分开销；
3. 热路径共享结构 → 考虑 `____cacheline_aligned`（防伪共享）与 `__read_mostly`（见 [004.内核对齐工具箱-源码全景.md](004.内核对齐工具箱-源码全景.md)）；
4. DMA 缓冲 → 保证 `ARCH_DMA_MINALIGN`（128B）对齐；
5. 通用数值对齐 → `ALIGN(x, a)` / 判断 `IS_ALIGNED(x, a)`，不要手写 `(x + a - 1) & ~(a - 1)`。
