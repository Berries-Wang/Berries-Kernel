## 这句话怎么理解——三层拆解

书中 A.3 一句话压缩了三层事实，每层都能在架构手册和内核源码中找到对应证据：

| 层 | 书中对应的原句 | 架构侧依据 | 源码侧依据 |
|---|---|---|---|
| **① 正当性层：非对齐可能直接是"非法"的** | "一些体系结构**强制要求**对特定长度的数据类型进行特定的对齐" | ARM ARM B2.8.2：`SCTLR_ELx.A=1` 时任何非对齐访问产生 Alignment fault；**独占/原子指令对非对齐地址始终产生 Alignment fault**（无 FEAT_LSE2 时）；Device 内存禁止非对齐 | arm64 缺陷路径 `do_alignment_fault` → `SIGBUS/BUS_ADRALN`（`arch/arm64/mm/fault.c:846`） |
| **② 微架构层：非对齐让缓存/总线做双倍功** | "即使能够处理随机对齐的体系结构，在一定的对齐条件下，其**读写性能**也比不对齐的访问要快速"、"对于**高效使用处理器高速缓存**……很有必要" | 缓存以**缓存行**（64B）为最小搬运单位：跨行访问 = 2 次 linefill / 2 次总线事务；非对齐破坏单拷贝原子性（B2.2.1）；原子指令跨行 → 总线锁 | `SKB_DATA_ALIGN`、`SLAB_HWCACHE_ALIGN`、`____cacheline_aligned`、`ARCH_DMA_MINALIGN=128`、`NET_IP_ALIGN` |
| **③ 工程层：内核把"对齐"做成了工具箱** | "在 GCC 为各种 struct 或 union 组织内存布局时，会**自动选择适当的对齐**"；`get_unaligned/put_unaligned` 兜底 | 自然对齐（natural alignment）＝ 地址能被类型宽度整除 | `ALIGN/IS_ALIGNED`、`__aligned/__packed`、`include/linux/unaligned.h` |

一句话总结：**对齐不是软件洁癖，而是硬件"按缓存行/按事务"搬数据这一物理事实，在 C 语言类型系统上的投影。** 对齐的数据让一次访问恰好落在一次硬件事务里；非对齐轻则拆成多次事务（慢），重则触发异常（崩）或失去原子性（错）。

## A.3 原文（备查）

> 将数据对齐到特定的内存地址，对于高效使用处理器高速缓存和提升性能，都很有必要。一些体系结构强制要求对特定长度的数据类型进行特定的对齐。即使能够处理随机对齐的体系结构，在一定的对齐条件下，其读写性能也比不对齐的访问要快速。通常，对齐是指对齐到数据类型的字节长度可整除的字节地址。在某些情况下，会要求稍大一些的对齐尺度。相关信息一般会在所述处理器的体系结构文档中给出。将数据类型对齐到其自身的字节长度，称之为自然对齐（natural alignment）。
>
> 在内核中某些地方，可能需要访问非对齐的数据类型。各体系结构必须为此定义两个宏（在 `<asm-arch/unaligned.h>` 中）：
> - `get_unaligned(ptr)` 对位于非对齐内存位置的一个指针，进行反引用操作。
> - `put_unaligned(val, ptr)` 向 ptr 指定的一个非对齐（因而不适合直接访问）内存位置写入值 val。
>
> 这些宏支持将相应的值复制到另一个内存位置，并在新的位置进行访问。在 GCC 为各种 struct 或 union 组织内存布局时，会自动选择适当的对齐，使得程序员无须手工进行操作。

注：书基于 2.6.24，`<asm-arch/unaligned.h>` 的说法已过时——7.1.3 中统一收敛到 `include/linux/unaligned.h`，见 [005.get_unaligned与put_unaligned.md](005.get_unaligned与put_unaligned.md)。
