# MOS5 §10.5.5 Modules in Linux —— 可加载模块精读
> 出处: [Modern Operating Systems 5th Edition §10.5.5 Modules in Linux](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=794) 书页 765-766(PDF 794-795)。
>
> 内核源码基于 Linux 7.1.3 `kernel/module/`。

---

## 1. 为什么需要可加载模块

> "With the arrival of Linux on the PC platform, suddenly all that changed. The number of I/O devices available on the PC is orders of magnitude larger than on any minicomputer. In addition, although all Linux users have (or can easily get) the full source code, probably the vast majority would have considerable difficulty adding a driver, updating all the device-driver related data structures, relinking the kernel, and then installing it as the bootable system (not to mention dealing with the aftermath of building a kernel that does not boot)."（随着 Linux 登上 PC 平台，情况完全变了。PC 上可用的 I/O 设备数量比任何小型机都大几个数量级。而且，尽管 Linux 用户都有(或很容易拿到)全部源代码，但绝大多数人对"添加驱动、更新所有与设备驱动相关的数据结构、重新链接内核、再把它安装为可引导系统"会有相当大的困难(更不用说处理"编译出一个起不来的内核"的后果了）。）<sup>[Modern Operating Systems 5th, 书页 765(PDF 794)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=794)</sup>

> "Linux solved this problem with the concept of loadable modules. These are chunks of code that can be loaded into the kernel while the system is running. Most commonly these are character or block device drivers, but they can also be entire file systems, network protocols, performance monitoring tools, or anything else desired."（Linux 用**可加载模块(loadable modules)**的概念解决了这个问题：这是可以在系统运行时加载进内核的代码块。最常见的是字符或块设备驱动，但也可以是整个文件系统、网络协议、性能监控工具，或任何想要的东西。）<sup>[书页 765(PDF 794)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=794)</sup>

## 2. 加载模块的五步 —— 原文与内核逐条对照

> "When a module is loaded, several things have to happen. First, the module has to be relocated on the fly, during loading. Second, the system has to check to see if the resources the driver needs are available (e.g., interrupt request levels) and if so, mark them as in use. Third, any interrupt vectors that are needed must be set up. Fourth, the appropriate driver switch table has to be updated to handle the new major device type. Finally, the driver is allowed to run to perform any device-specific initialization it may need. Once all these steps are completed, the driver is fully installed, the same as any statically installed driver."（加载模块时要做几件事：**第一**，加载过程中模块必须被动态重定位;**第二**，系统要检查驱动所需资源(如中断请求级)是否可用，可用则标记为占用;**第三**，必须设置所需的中断向量;**第四**，要更新相应的驱动开关表以处理新的主设备类型;**最后**，允许驱动运行，完成它需要的任何设备特定初始化。这些步骤全部完成后，驱动就完整安装好了，与任何静态编译进内核的驱动无异。）<sup>[书页 765(PDF 794)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=794)</sup>

五步在现代 Linux 7.1.3 的对应物(加载入口:系统调用 `finit_module`<sup>[kernel/module/main.c:3799](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/module/main.c)</sup> / `init_module` :3634,用户态 `insmod`/`modprobe` 调用它们):

| MOS5 步骤 | 现代 Linux 实现 | 源码锚点 |
|-|-|---|
| ① 加载时动态重定位 | ELF 布局 + `apply_relocations` → `apply_relocate_add`(按架构重放 RELA) | main.c:1608 / :1641;布局在 `layout_and_allocate` :2943 |
| ② 资源检查并标记占用 | 驱动 init 内 `request_mem_region`/`request_region`(IORESOURCE)、`request_irq` 占用中断号 | [include/linux/ioport.h](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/ioport.h) |
| ③ 设置中断向量 | 已无静态向量表:经 `irq_domain` 动态分配 virtual IRQ 并 map 到硬件 GSI/INTID | [include/linux/irqdomain.h:100-104](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/irqdomain.h)(match/select/map 钩子) |
| ④ 更新"驱动开关表" | `register_chrdev`(填 cdev_map)/`register_blkdev`/`driver_register`(总线驱动表) | [fs/char_dev.c:265 `__register_chrdev`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/fs/char_dev.c) |
| ⑤ 设备特定初始化 | `do_init_module` → `do_one_initcall(mod->init)` 跑 `module_init()` 注册的函数,完成后 `MODULE_STATE_LIVE` | main.c:3077 / :3105-3112 |

```text
 insmod xx.ko
    │ finit_module(fd)                        [main.c:3799]
    ▼
 load_module                                 [main.c:3422]
    ├─ layout_and_allocate                   [:2943]   ELF 段布局/符号解析
    ├─ ① apply_relocations                   [:1608]   动态重定位
    ├─ ②③④ 各子系统注册(经 ⑤ 的 init 回调):
    │      cdev_map / bus driver table / irq_domain ...
    ├─ mod_sysfs_setup / prepare_coming_module [:3561/:3348]  MODULE_STATE_COMING
    └─ ⑤ do_init_module → do_one_initcall(mod->init)   [:3077/:3106]
           └─ 成功 → MODULE_STATE_LIVE "first class citizen!" [:3123]
```

"the same as any statically installed driver" 的现代验证:静态编译与模块加载的驱动最终都汇入同一驱动模型(`struct device_driver` + 总线匹配),`/sys/module/<name>` 与 `/proc/modules`(模块)/`/proc/kallsyms`(符号,模块符号带 `[xx]` 后缀)可见。

## 3. 按需自动加载:kmod/request_module

书里没展开但内核有完整机制:内核代码在需要某功能时调 `request_module("nfsfs")`,由用户态 modprobe 落盘加载<sup>[kernel/module/kmod.c:132 `__request_module`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/module/kmod.c)</sup>。典型场景:`mount -t ext4` 时 ext4 若为模块,文件系统注册表的查找失败会触发 `request_module("fs-ext4")`;socket `AF_XXX` 协议族同理。这对应书中"加载的可以不仅是驱动——文件系统、网络协议都行"。

## 4. 安全:书里点名的"噩梦"与内核的回应

> "It is worth noting that loadable modules are a security nightmare. Putting a piece of foreign code that may or may not have been vetted carefully and which might contain security holes and backdoors into the kernel can create huge security problems. Loadable modules should only be fetched from a source known to be completely trustworthy."（值得指出，可加载模块是一场安全噩梦：把一段未经仔细审查、可能含有安全漏洞和后门的外来代码放进内核会造成巨大的安全问题。可加载模块应当只从完全可信的来源获取。）<sup>[书页 765(PDF 794)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=794)</sup>

内核的回应(按时代递进):

| 机制 | 说明 | 源码 |
|-|-|---|
| 模块签名 `CONFIG_MODULE_SIG` | .ko 内附 PKCS#7 签名,加载时校验,失败可拒绝 | [kernel/module/signing.c:70 `module_sig_check`](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/module/signing.c) |
| `module.sig_enforce=1` | 强制校验(不可加载无签名模块) | 同上,启动参数 |
| 锁定(lockdown) | 内核 lockdown 模式下禁用未签名加载 | security/lockdown |
| BPF/tracepoint 边界 | 非 root 不可见符号:模块只导出 `EXPORT_SYMBOL_GPL` 标记的接口 | main.c 导出表处理 |

`lsmod`(读 /proc/modules)、`modprobe -r`(卸载,对应 `delete_module` 系统调用)构成日常管理闭环;模块生命周期状态机 `LIVE/COMING/GOING/UNFORMALIZED` 见 [include/linux/module.h](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/module.h)。
