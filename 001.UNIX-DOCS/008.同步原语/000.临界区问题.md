# 临界区问题

> **定位：系列入口。** 定义问题、给出验收标准（三要求）、盘点四条技术路线，并用内核源码印证每条路线的真实去处——细节全部外链：原子操作 → [001.原子指令](./001.原子指令/README.md)，顺序保证 → [002.内存屏障](./002.内存屏障.md)。
>
> 源码基准：[000.SOURCE_CODE/003.LINUX-7.1.3](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3)（`file:line` 实测）。

## 0. 一句话总结

当多个执行流（线程/进程/中断/其他 CPU 核）读写同一共享资源时，"读-改-写"若不原子就会互相覆盖——把修改共享资源的代码段做成**同一时刻至多一个执行流进入**，就是临界区问题；一切解法最终都落在三件事的组合上：**原子指令**（硬件保证 RMW 不可分割）、**内存屏障**（保证别的核按正确顺序看见）、**等待策略**（拿不到就自旋/睡眠），内核的锁就是把这三件组装好的成品。

## 1. 问题的形状：竞态与丢更新（lost update）

经典反例——两个核同时 `counter++`（三段式 RMW（Read-Modify-Write，读-改-写），定义见 [001.原子指令/README](./001.原子指令/README.md)）：

```
   counter 初值 = 5
时间 ─────────────────────────────────────────────────────►
CPU0: 读 counter(5)   加一(6)        写回 counter=6
CPU1:          读 counter(5)   加一(6)   写回 counter=6   ✗
   结果 counter=6：两次 ++ 只生效一次（丢更新）
   ▲ 两个"读"都发生在对方"写"之前——窗口 = 整个 RMW 三段式
```

窗口里能插进来的不只是线程：**中断处理程序**（同核）、**其他核**（SMP）、**被调度走的任务**——所以"关调度"并不够（§5）。共享资源也不只是变量：链表、I/O 寄存器、文件偏移同构。

## 2. 正确性的三个要求（验收标准）

任何解法都要同时满足（原表保留，补"内核视角"一列）：

| 要求 | 说明 | 内核视角的印证 |
| - | - | - |
| **互斥访问**（mutual exclusion） | 同一时刻，最多只有一个线程进入临界区 | 锁的 locked 位/队首指针原子交接（§6） |
| **空闲让进**（progress） | 没有线程在临界区时，必须选一个申请者放行 | 无争用时锁快路径一条 CAS 直达（qspinlock.h:111） |
| **有限等待**（bounded waiting） | 线程申请进入后，必须在有限时间内获得许可 | LL/SC 的架构前瞻保证、MCS 队列的 FIFO 排队（[003.LLSC实现原理 §6.3](./001.原子指令/003.LLSC实现原理.md)） |

## 3. 技术路线总览

| 路线 | 思路 | 内核真实用途 |
| - | - | - |
| ① 纯软件互斥算法（Peterson 等） | 只用普通读写 + 协议 | **不使用**（教学价值：暴露弱内存模型问题，§4） |
| ② 关硬件中断 | 让"插队者"（时钟/中断）消失 | 单核成立、多核失效；内核用作**辅助手段**（§5） |
| ③ 原子指令（软硬结合） | 硬件保证 RMW 不可分割（CAS/FAA/SWP…） | 一切锁的底座（§6，[001.原子指令](./001.原子指令/README.md)） |
| ④ 锁抽象 | 原子指令 + 屏障 + 等待策略的组装品 | spinlock/mutex/semaphore（§7） |

## 4. 路线①：纯软件互斥算法——现代内核为什么不用

Peterson 算法（两线程，flag[] + turn）在**顺序一致**模型下是正确解；但它是为"理想内存"设计的，放在真实弱内存模型上会碎：

```
Peterson（两线程 i=0/1）                     在 arm64 上的两处碎裂
  flag[i] = true;                    ① 循环里轮询 flag[j]/turn —— 编译器可把读
  turn = j;                             提出循环（需 READ_ONCE，002 §4.2）
  while (flag[j] && turn == j);      ② flag/turn 与临界区数据的**跨地址可见序**
     临界区                              不受保证——对手核可能"看见"你进了
  flag[i] = false;                      临界区，却没看见你的 flag[i]=true
                                        （需 DMB/LDAR/STLR 修补，002 §1）
```

结论：**纯软件协议要成立，得先垫上内存屏障——那不如直接用硬件原子指令**。它在内核里仅存于教科书与极早期体系（SMP 之前的 ARM 没有 LSE 也靠 LL/SC 而非 Peterson）。价值在于把"互斥 = 原子 + 顺序"两件事拆开示众。

## 5. 路线②：关中断——单核完美、多核失效

```
单核（UP）：为什么成立                    多核（SMP）：为什么失效
──────────────────────────              ──────────────────────────
 抢换时机 = 时钟中断/异常                  CPU0 关自己的中断
   │                                      CPU1 根本不归 CPU0 的中断管
   ▼                                        │
 [中断]→schedule() 换人                   ▼
 关中断 ⇒ 换人通道关闭 ⇒                  CPU1 照常读-改-写同一变量 ✗
 本核视图内"只有我"                        （一个 CPU 只能控制自己）
```

所以内核里 `local_irq_save` 从不单独当互斥用，而是**配合自旋锁消除本核中断的重入**（同一个锁可能被本核中断处理程序再次申请——自旋锁不能睡眠，中断里也不能等睡眠锁）：

```c
// include/linux/irqflags.h:214
#define local_irq_save(flags)				\
	do {						\
		raw_local_irq_save(flags);		\
	} while (0)
```

同族辅助：`preempt_disable()`（[preempt.h:211](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/preempt.h)，关本核抢占，同样不跨核）。组合成品即 `spin_lock_irqsave()`：**关中断/关抢占管本核，原子指令管跨核**。

## 6. 路线③：原子指令——硬件直接保证的原子 RMW

把"读-改-写"焊成**一笔访存事务**（读、改、写由同一条指令作为同一笔请求完成，不是 load+store 两笔——test-and-set/swap/CAS/FAA），插队窗口消失。arm64 上的两代"焊法"与全部指令族见 [001.原子指令](./001.原子指令/README.md)：

| 操作 | x86_64 | arm64（LSE，正文主路径） |
| - | - | - |
| test-and-set / swap | `xchg` / `lock bts` | `SWP`（[005 §3.4](./001.原子指令/005.LSE内核实现.md)） |
| CAS | `lock cmpxchg` | `CAS`/`CASAL`（[002.CAS实现原理](./001.原子指令/002.CAS实现原理.md)） |
| FAA | `lock xadd` | `LDADD` |

内核自旋锁的快路径就是一条带 acquire 的 CAS（详见 [002.内存屏障 §6.2](./002.内存屏障.md)）：

```c
// include/asm-generic/qspinlock.h:107
static __always_inline void queued_spin_lock(struct qspinlock *lock)
{
	int val = 0;

	if (likely(atomic_try_cmpxchg_acquire(&lock->val, &val, _Q_LOCKED_VAL)))
		return;                       // 无争用：一条 CAS 拿锁（空闲让进）

	queued_spin_lock_slowpath(lock, val);   // 有争用：排队（有限等待）
}
```

## 7. 路线④：锁抽象——内核的组装品

**锁 = 原子指令（互斥） + 内存屏障（顺序） + 等待策略（自旋/睡眠）**。以 spinlock 为例走一遍 API 链（7.1.3）：

```
spin_lock(&lock)                          // include/linux/spinlock.h
  └─ raw_spin_lock()                      // CONFIG_QUEUED_SPINLOCKS 下同义
       └─ _raw_spin_lock()                // spinlock_api_smp.h:22（含 preempt/irq 变体分发）
            ├─ 快路径: atomic_try_cmpxchg_acquire   ← 原子指令 + acquire（本篇 §6）
            └─ 慢路径: queued_spin_lock_slowpath    // kernel/locking/qspinlock.c
                 └─ 排队自旋 + smp_cond_load_relaxed 等待（WFE 睡等，002 §6.4）
spin_unlock(&lock)
  └─ queued_spin_unlock(): smp_store_release(&lock->locked, 0)   // qspinlock.h:123
                                  ← 解锁 = 一条 STLR（release，002 §3.3）
```

三件套之外的"睡等锁"（mutex/semaphore）只是把等待策略换成睡眠+唤醒，底座相同——各类锁的对比展开留给后续《锁系列》（README 规划中）。

## 9. 常见误区

1. **"关中断是互斥原语"**——不是；它只管本核上下文，跨核必须原子指令（§5）。
2. **"有了原子指令就同步完备了"**——原子指令只保证单笔 RMW 不可分割；临界区内的**多笔**读写要别人按顺序看见，还缺内存屏障（[002](./002.内存屏障.md)）——这正是 Peterson 在真实硬件上碎掉的原因（§4）。
3. **"自旋锁 = 原子指令"**——spin_lock 快路径是 CAS+acquire，慢路径还有排队/唤醒/中断关闭的配合（§7）；把锁说成"一条原子指令"丢掉了三件套的另外两件。
4. **"单核系统没有临界区问题"**——软中断/中断与线程之间照样竞争，只是手段退化为关中断+关抢占（§5）。
