## 0. 一句话总结

**LL/SC 与 LSE 解决同一个问题——把 RMW（Read-Modify-Write，读-改-写）做成原子的——但方向相反：LL/SC 把 RMW 拆成两条指令，靠独占监视器"事后检测"插队者，失败了软件重试；LSE 把 RMW 焊成一条指令，靠缓存一致性协议"事前锁死"，无条件完成。** 即：**LL/SC = 检测 + 重试；LSE = 锁死 + 必成**。

---

## 1. 为什么会有两族：同一个 RMW，两种"焊法"

RMW 的定义与丢更新（lost update）反例见 [README](./README.md)。普通 `ldr`/`alu`/`str` 三笔访存挡不住插队，于是架构提供了两代"焊法"：

- **第一代（Armv8.0 基线）**：不动指令语义，给一对特殊指令 + 一个硬件"监视器"——读的时候做记号，写之前查记号还在不在；
- **第二代（Armv8.1 FEAT_LSE）**：直接新增一整族单条指令，硬件保证读和写之间无人能插入，把重试义务从软件拿走。

两代并存至今（§6），不是新旧替换关系。

## 2. 核心区别总表

| 维度 | LL/SC（LDXR/STXR） | LSE（CAS/SWP/LDADD…） |
| - | - | - |
| 架构地位 | **Armv8.0 基线，永远强制** | FEAT_LSE：v8.1 可选，**v8.4 起强制** |
| 指令形态 | **两条**：LDXR 读+标记 → 计算 → STXR 条件写 | **一条**：单指令完成整个 RMW |
| 中间夹任意计算 | **可以**（读旧值→任意算→条件写回） | **不行**：每条指令语义固定（加/交换/比较…） |
| 原子性保证者 | 独占监视器（local+global）**事后检测**"有人写过" | 缓存一致性协议**事前锁死**（独占态行 / 一致性点上一笔事务） |
| 失败与重试 | STXR 可失败（status=1），**软件循环重试** | **无失败态**：要么完成，要么异常 |
| 前瞻保证 | **有条件**保证前进（B2-339 列了一长串软件义务） | 无需——单指令架构必成 |
| ERG 伪共享 | **有**：标记粒度 4~512 字（≤2048B），邻居写同块也清你的标 | **无**：只原子更新所寻址的字节，没有"标记块"概念 |
| 配对限制 | 同 VA/同事务大小/同寄存器数/同 Tag Checked（B2.12.5，违反 C.U.） | 无——指令自含完整操作 |
| 与监视器的关系 | 全靠它（两级状态机就是原子性本体） | **不依赖**；唯一交互是**允许**（非必须）清除独占监视器——对同地址的 LL/SC 环是潜在干扰（见 [002 §3](./002.CAS实现原理.md)） |
| 宽度 | 8/16/32/64 位 + 128 位（`LDXP/STXP` 对） | 8/16/32/64 位 + 128 位（`CASP`；FEAT_LSE128 起全族 128 位） |
| acquire/release | `LDAXR/STLXR`（同一编码的 o0=1 变体） | `A/L/AL` 指令后缀（`LDADDA`/`SWPL`/`CASAL`…） |
| 内存类型底线 | Inner/Outer Shareable + Write-Back Normal（B2-334） | 同左（B2-249/250）——**两族底线一致**，非一致性内存都不保证 |
| 争用行为 | 互踢独占行 → 乒乓 + 重试 + 理论活锁 | 每笔都算数；微架构可把原子 offload 到一致性点定序 |
| 对一致性硬件的要求 | 只当**看门狗**（被动暴露"谁写了这行"） | 要当**锁**（主动授予独占/就地 RMW，见 [003 §4.3](./003.LLSC实现原理.md)） |

## 3. 同一个 `counter += 2`：两条执行流

```
LL/SC 路径（拆开 + 重试）                LSE 路径（焊死一条）
──────────────────────────────          ──────────────────────────────
1: ldxr  w0, [x1]   // 读旧值+登记监视器  ldadd w2, w0, [x1]
   add   w0, w0, #2 // 本地算新值         // 一条指令: 读旧值→加→写回
   stxr  w1, w0, [x1]// 条件写, 状态→w1    // 旧值进 w0; 无状态位;
   cbnz  w1, 1b      // 失败→整段重来      // 中途不可插队, 必成
```

- LL/SC 的 `add` 可以换成**任意计算**（甚至几十条指令），只要最后 STXR 还配得上；LSE 没有这个自由度——`ldadd` 只会加。
- LL/SC 整段循环可能空转多轮；LSE 每次执行都产生效果。

## 4. 争用下的行为差异（为什么大系统偏爱 LSE）

- **LL/SC**：N 核竞争同一地址时，每轮 LDXR 都倾向把行拉成独占（ReadUnique）→ 行在核间乒乓、SF 反复打/清监视标 → 探针风暴 + 重试白干 + 理论活锁（手册被迫用 B2-339 规定"至少一个 PE 前进"来兜底）。
- **LSE**：每笔 RMW 都计入结果；争用激烈时微架构可把原子 **offload 到一致性点**（CHI Atomic 事务到 HN-F，在 PoS 排队定序、核不取独占行）——用"排队"取代"互踢"。32 核对照图见 [031.AGI-SP113012 §5.3/§5.4](../../031.进程管理/008.进程调度/000.调度组与调度域/003.AGI-SP113012-层级架构-缓存一致性-原子操作.md)。
- **边界**：无争用/单核时两者都退化为核内 L1 上的 RMW，差距很小——LSE 的优势随核数与争用程度放大。

## 5. 内存序对照（简）

| | LL/SC | LSE |
| - | - | - |
| acquire 变体 | `LDAXR`（acquire 有条件：目标寄存器 ≠ WZR/XZR 才有） | `A` 后缀（无条件） |
| release 变体 | `STLXR`（release **仅在写成功时**成立——可能失败就没有可 release 的东西） | `L` 后缀（必写，故恒成立） |

## 7. 常见误区

1. **"LSE 不用监视器 → 监视器被淘汰了"**：错。监视器只服务 LL/SC，而 LL/SC 有四块 LSE 替代不了的保留地（[003 §8](./003.LLSC实现原理.md)）——两级监视器与 CLREX 必须永远存在。
2. **"LSE 一定更快"**：错。无争用时差距小；非标准 RMW、（无 FEAT_LSE128 时的）128 位原子还得 LL/SC；个别小核上 LSE 延迟反而高（§6 最后一条）。
3. **"LL/SC 是过时技术"**：错。它是 Armv8.0 强制基线（老核只有它），前瞻保证、任意计算自由度、cmpwait 事件机制都活在当下内核里。
