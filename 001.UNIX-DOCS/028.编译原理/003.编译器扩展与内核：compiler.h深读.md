# 编译器扩展与内核：compiler.h 深读

> **定位**：内核不用标准库、自带运行时、还要保证"一段 C 编译出的机器码可以在启动期/运行期再改"——所以它必须**直接驱动编译器**。本文走读 7.1.3 的 [compiler_attributes.h](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/compiler_attributes.h) / [compiler.h](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/compiler.h)（`file:line` 实测），并给出"机器码被改四次"的总时间线。
>
> 理论坐标：教材 p313（中间代码生成——`__section` 是把编译产物钉进命名段的手柄）、p402/p479（机器无关/相关优化）。

## 0. 一句话总结

**内核与编译器的接口有三层：属性层（`__section/__weak/__always_inline`…告诉编译器"这段代码特殊"）、内在函数层（`__builtin_expect` 等直接喂提示给优化器）、内联汇编层（`asm`/`asm goto` 把手写指令嵌进编译器支配的指令流）**；三者共同保证最终机器码可以被链接器（lds）、启动期补丁（alternatives）、运行期补丁（ftrace/kprobes）继续改写——内核的机器码是"四道工序"的产物。

## 1. 属性层：compiler_attributes.h——给符号打元数据

全部是对 `__attribute__((...))` 的薄封装（一处定义、随手可用、静态检查器也认识）：

| 宏 | 行号 | 编译器/链接器效果 | 内核典型用法 |
| - | - | - | - |
| `__section(sec)` | :321 | 变量/函数放进命名段 → 交给 [lds 归并](./002.链接脚本走读：vmlinux.lds.S.md) | `__init`、`__percpu`、`EXPORT_SYMBOL` 的表 |
| `__weak` | :414 | 弱符号：未定义时链接器填 0/默认实现 | 架构可覆盖的默认函数（如 `__weak __init void foo()`） |
| `__always_inline` | :55 | 强制内联，禁止"优化出函数调用" | 头文件里的单行访问器（如 [008.同步原语/005 §3](../008.同步原语/001.原子指令/005.LSE内核实现.md) 的 `__lse_ll_sc_body` 宏展开链） |
| `__used` | :349 | 阻止死代码消除（配合 `--gc-sections` 的源代码侧保险；段级保险是 lds 的 `KEEP()`） | 只被汇编/链接器引用的 C 变量 |
| `__aligned(x)` | :33 | 对齐约束 | cacheline 对齐（防伪共享，[003.高速缓存/006](../003.高速缓存/006.高速缓存伪共享.md)） |
| `__printf(a,b)` | :158 | 格式串静态检查 | `printk` 族 |
| `__noreturn` | :262 | 控制流分析：调用后不可达 | `panic/do_exit` |

**`__section` 是最重要的一枚**——它是"编译期 → 链接期"的传送带：C 源码里的 `__section(".initcall4.init")` 决定了这个指针最终落进 [002 §4](./002.链接脚本走读：vmlinux.lds.S.md) initcall 表的哪一级。教材视角：编译器的符号表/段属性（p27、p365）在这里变成程序员可编程的接口。

## 2. 内在函数层：likely/unlikely 与 barrier

```c
// include/linux/compiler.h:76（非 profile 版）
# define likely(x)	__builtin_expect(!!(x), 1)
# define unlikely(x)	__builtin_expect(!!(x), 0)

// include/linux/compiler.h:85
# define barrier() __asm__ __volatile__("": : :"memory")
```

- `__builtin_expect` 喂给优化器分支概率——错误路径被排到函数尾（`.cold` 段）、快路径直线化。开 `profile` 构建时换成 `__branch_check__`（:44-47）给分支剖析钩子计数；
- `barrier()` 是**只对编译器**的屏障（空汇编 + memory clobber），不生成任何指令——三层乱序对策的编译器层，CPU 层见 [008.同步原语/002.内存屏障 §4](../008.同步原语/002.内存屏障.md)（该篇的 READ_ONCE/WRITE_ONCE 正是 `volatile` + 属性层的组合）；
- `__builtin_constant_p` 让宏在"编译期已知"时选择零开销分支（如 `fls()` 的常量快路）——语法制导翻译（教材 p179）在 C 层的影子。

## 3. 内联汇编层：asm 与 asm goto

`asm volatile("...%0...": 输出: 输入: clobber)` 把手写指令嵌进编译器支配的指令流——内核里所有"指令级精确"的代码（原子操作、barrier、系统寄存器访问）都走这条路（[008.同步原语/005 §3](../008.同步原语/001.原子指令/005.LSE内核实现.md) 的 `ldadd` 家族即内联汇编 + `__LSE_PREAMBLE`）。

`asm goto` 是加强版：**跳转目标可以是 C 标签**，编译器保证控制流图不裂——静态键（jump label）的基石：

```c
// arch/arm64/include/asm/jump_label.h:36（节选）
	asm goto(
		ARCH_STATIC_BRANCH_ASM("%c0", "%l[l_yes]")   // :27 定义的 nop/分支模板
		: : "i" (&static_key_true) : : l_yes);
```

静态键 = `nop`（关）与 `b l_yes`（开）两条指令的运行期互换——它与 alternatives（[005 §5](../008.同步原语/001.原子指令/005.LSE内核实现.md)）共用"启动期/运行期改写机器码"的世界观。

## 4. 机器码被改四次：总时间线

同一条 `printk` 里的指令，从诞生到退役可能被改写四道：

```
 工序        执行者                工具/机制                      产物状态
 ─────────────────────────────────────────────────────────────────
 ① 编译期    cc1                   c_flags/属性/内联汇编          .o（含重定位记录）
 ② 链接期    ld -T vmlinux.lds.S   段归并/--gc-sections/kallsyms  vmlinux（地址定死）
 ③ 启动期    内核自己              alternatives(.altinstructions 表, lds:262)
                                   ／jump label 初始化            LSE 补丁选路等
 ④ 运行期    内核自己              ftrace(-fpatchable-function-entry)／
                                   kprobes 断点／BPF JIT          动态追踪
```

④ 的编译器接口是构建开关：

```make
# arch/arm64/Makefile:145（7.1.3 实测，非动态 ftrace 配置）
  CC_FLAGS_FTRACE := -fpatchable-function-entry=4,2
# （:148 动态 ftrace 配置为 =2；对照 x86 传统 -pg/mcount：Makefile:832/:1018/:1021）
```

`-fpatchable-function-entry=N,M` 让编译器在每个函数入口留出 N 字节 NOP 区、其中后 M 字节可安全改写——ftrace 运行期把 NOP 替换成 `bl <tracer>`。这是"**编译器为运行期改写预留插槽**"的正式属性（对照教材 p365：代码生成器必须为后续工具留缝）。

## 6. 常见误区

1. **"`__used` 能防 --gc-sections 回收"**——不完全：`__used` 说服**编译器**不删，`KEEP()` 说服**链接器**不收；表类段两道都要（§1 与 [002 §5](./002.链接脚本走读：vmlinux.lds.S.md)）；
2. **"likely/unlikely 改变语义"**——纯优化提示，不影响正确性（profile 构建下还会被计数版本替换）；
3. **"asm goto 只是语法糖"**——它保证编译器把内联分支纳入 CFG/栈分析（配合 objtool），普通 `asm` 做不到；
4. **"ftrace 的钩子是执行时插中断"**——不是：编译期就留好了 NOP 插槽（`-fpatchable-function-entry`），运行期只是改写几个字节。
