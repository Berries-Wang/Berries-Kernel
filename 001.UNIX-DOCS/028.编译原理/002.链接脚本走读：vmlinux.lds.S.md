# 链接脚本走读：arch/arm64/kernel/vmlinux.lds.S

> **定位**：链接脚本是"代码生成器"的最终排版指令——教材（张昱/陈意云 p365 代码生成/p258 运行时存储）讲"目标代码要分配到哪些地址"，内核把这件事写成一份 430 行的、可断言、可预留内存、可被 C 代码消费的程序。本文逐段走读 7.1.3 的 [vmlinux.lds.S](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/vmlinux.lds.S)（`file:line` 实测）。
>
> 前置：[001 流水线](./001.从C到Image：内核构建流水线.md) §4；姊妹：[008.CS 宏观系列](../../008.COMPUTER_SCIENCE/000.编译-汇编-链接/README.md)、[000.链接器](./000.链接器/README.md)。

## 0. 一句话总结

**lds.S 干三件事：把几万个输入段按规则并成有序的输出段（内存布局）、在关键位置钉上"合成符号"当围栏（给 C 代码消费）、用 ASSERT 把布局契约写死（链接期就报错）。** 内核的很多机制——init 段释放、initcall 表、per-cpu、启动期 alternatives 补丁——本质上都是"链接器排表 + C 代码循表执行"。

## 1. 脚本本身也是"预处理 + 宏"程序

```c
// arch/arm64/kernel/vmlinux.lds.S:84（节选）
#include <asm-generic/vmlinux.lds.h>      // ← 链接脚本的"标准库"：段归并宏
#include <asm/memory.h>                   // KIMAGE_VADDR 等地址常量
#include "image.h"

OUTPUT_ARCH(aarch64)                      // :93
ENTRY(_text)                              // :94  入口 = .head.text 的头
jiffies = jiffies_64;                     // :96  符号别名：jiffies 直接等价 jiffies_64
```

- `.lds.S` 后缀 = 先过 C 预处理器再喂给 ld——所以脚本里有 `#include/#ifdef/#define`（如 :135 的 `#ifdef CONFIG_UNMAP_KERNEL_AT_EL0` 切换 TRAMP_TEXT），Kconfig 的每个选项都能改布局；
- `asm-generic/vmlinux.lds.h` 是所有架构共享的**段归并宏库**（TEXT_TEXT:600、INIT_CALLS_LEVEL:938、PERCPU_SECTION:1110、INIT_TEXT_SECTION:1149）——`*(.initcall0.init)` 这类脏活在宏里，各架构 lds 只管排宏观顺序。

## 3. 链接器武器一：合成符号——链接器产出的"全局变量"

lds 里 `名字 = .` 定义的符号会进最终符号表，C 代码可以直接 extern 消费（这就是"链接器 API"）：

**① 围栏符号 + free_initmem：把"启动后释放"做成语言**

```c
// vmlinux.lds.S:250 / :311（围栏定义）
__init_begin = .;
...（整个 init 区）
__init_end = .;
```

```c
// arch/arm64/mm/init.c:392（消费方，7.1.3 实测）
void free_initmem(void)
{
	void *lm_init_begin = lm_alias(__init_begin);
	void *lm_init_end = lm_alias(__init_end);
	...
	vunmap_range((u64)__init_begin, (u64)__init_end);   // :407 直接归还!
}
```

C 代码里没有任何一张"待释放页清单"——**围栏之间的距离就是清单**。`__init` 宏（`__section(".init.text")`）只是把东西放进围栏内。

**② 位置计数器直接开洞：给页表和栈预留内存**

```c
// vmlinux.lds.S:246（节选）
	swapper_pg_dir = .;
	. += PAGE_SIZE;
```

`swapper_pg_dir`（内核主页表基址）不是任何 `.o` 里的变量——是链接器**画出来的**：符号钉在当前位置、位置计数器前进一页。同法还有 `early_init_stack`（:361-362，早期 C 运行时的栈）。启动代码拿到的"已清零的一页"正是这里预留的（落在 BSS 区，清零免费）。

**③ 符号别名**

```c
// vmlinux.lds.S:96
jiffies = jiffies_64;
```

`jiffies` 与 `jiffies_64` 同地址——C 层用一个名字、汇编/链接层一个名字的经典手法。

## 4. 链接器武器二：段归并——"表"是链接器排出来的

**initcall 表：`module_init` 的调用清单不存在任何 .c 里**

```c
// vmlinux.lds.S:281（.init.data 内）
	INIT_SETUP(16)
	INIT_CALLS              // ← 展开为 vmlinux.lds.h:938 的 INIT_CALLS_LEVEL(0..7)
```

```c
// init/main.c:1412（消费方，7.1.3 实测）
static initcall_entry_t *initcall_levels[] __initdata = {
	__initcall0_start,
	__initcall1_start,
	...
};
```

`__initcall0_start..__initcall7_start` 是 INIT_CALLS_LEVEL 宏在每级表前后钉的围栏；`do_one_initcall`（main.c:1382）按级遍历。**注册宏（`__define_initcall`）→ 段名 → lds 归并 → 围栏 → 遍历**，五步构成内核最常用的"静态注册"模式（同款：`__ex_table` 异常表、`__ksymtab` 导出符号表、tracepoints、`machine_desc` 等）。

**.altinstructions：启动期补丁的链接期地基**（详细机制见 [008.同步原语/005.LSE内核实现 §5](../008.同步原语/001.原子指令/005.LSE内核实现.md)）

```c
// vmlinux.lds.S:262（7.1.3 实测）
	. = ALIGN(4);
	.altinstructions : {
		__alt_instructions = .;
		*(.altinstructions)              // 内联 asm 里的 ALTERNATIVE 宏丢进来的表项
		__alt_instructions_end = .;
	}
```

[001.原子指令/005](../008.同步原语/001.原子指令/005.LSE内核实现.md) 走读的 `ARM64_LSE_ATOMIC_INSN` 启动期补丁，其"补丁清单"就是这张链接期生成的表。

**.rela.dyn / .relr.dyn：自重定位**（:297-307）——EFI stub/KASLR 场景下内核被搬到非链接地址后，启动早期按这两张表自我修补（内核自己的 `.o` 里通常无动态重定位，这两段主要服务 pi/EFI 路径）。

## 5. 链接器武器三：排布控制——微架构约束写进脚本

- **权限边界**：:212 注释"到 `__init_begin` 为止全部 RO+NX"——段的**顺序**决定页表能按大粒度切权限（RO_DATA 宏里含 `.rodata/.ro_after_init` 等）；
- **缓存写回粒度（CWG）隔离**：:329-345 的注释原文说明 `.mmuoff.data.write/read` 要各自独占 CWG 区域，否则"MMU 关着写、开着读"的数据做 cache 维护时会误伤邻居——**微架构参数（CWG）直接改了链接布局**；
- **对齐**：`ALIGN(SEGMENT_ALIGN)` 让 `_stext/_etext` 落在段边界（配 `--gc-sections` 与 RO/NX 权限粒度）；`SBSS_ALIGN=PAGE_SIZE`（:71）则是为 KVM 的 HYP BSS 与主 BSS 对齐断言铺路；
- **--gc-sections 与 KEEP**：[顶层 Makefile:1058](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/Makefile) 开了段回收，所有"表"类段必须在 vmlinux.lds.h 宏里 `KEEP()` 住，否则可达性分析会把没人"调用"的表当死代码扔掉。

## 6. 链接器武器四：ASSERT——把布局契约写成编译期错误

```c
// vmlinux.lds.S:223 / :314 / :383（节选三例）
ASSERT(SIZEOF(.got.plt) == 0 || SIZEOF(.got.plt) == 0x18,
       "Unexpected GOT/PLT entries detected!")      // 内核拒绝动态链接设施
ASSERT(SIZEOF(.data.rel.ro) == 0, "Unexpected RELRO detected!")
ASSERT(SIZEOF(.plt) == 0, "Unexpected run-time procedure linkages detected!")
```

外加 :393-430 的八条：HYP/ID map 代码不得超一页、hibernate 出口起点必须是 `swsusp_arch_suspend_exit`、`_text == KIMAGE_VADDR`、`swapper_pg_dir - reserved_pg_dir == RESERVED_SWAPPER_OFFSET`……**这些是内核对启动代码的硬性契约**——违反不再是"运行时诡异崩溃"，而是链接直接失败。ld 里还有 `/DISCARD/`（:183-187）扔掉 `.dynsym/.ARM.attributes` 等不需要的段。

## 7. 常见误区

1. **"lds 只是排段顺序"**——远不止：合成符号（C 可消费的链接器 API）、位置计数器开洞（预留页表/栈）、断言（布局契约）、别名，四个武器都在；
2. **"init 释放靠一张页表/清单"**——没有清单，`__init_begin/__init_end` 围栏之间整块 vunmap（§3①）；
3. **"initcall 是遍历函数指针数组的普通数组"**——数组不存在；存在的是段 + 围栏，遍历指针来自链接器画的地址（§4）；
4. **"kallsyms/ System.map 才是符号表的来源"**——System.map 是 nm 快照（给人看），kallsyms 是自举两遍链接进镜像的运行期表（[001 §5](./001.从C到Image：内核构建流水线.md)）；链接器真正生成的符号在 lds 的 `名字 = .` 里。
