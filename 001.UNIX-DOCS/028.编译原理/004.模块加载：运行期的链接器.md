# 模块加载：运行期的链接器

> **定位**：`insmod` 就是**运行期的 ld**——把一个 ELF 可重定位对象（`.ko`）搬进内核地址空间、解析符号、逐条应用重定位、再按 [002](./002.链接脚本走读：vmlinux.lds.S.md) 同款的权限模型设置段属性。本文走读 7.1.3 的加载主流程与 arm64 重定位逐类型（`file:line` 实测）。
>
> 理论坐标：教材 p365（代码生成·重定位）：重定位公式 **`S + A`**（符号地址 + 加数）——内核源码注释里原样写着这条公式。

## 0. 一句话总结

**静态链接把"地址未定的缝"留到链接期填；内核模块把同样的缝留到 insmod 时刻填——`apply_relocate_add()` 就是一个 switch 解释器，按 `R_AARCH64_*` 类型逐条改写指令字段。** 所以模块比 vmlinux 多了一个"每符号版本检查 + 每指令重定位"的运行期步骤；而 vmlinux 侧的 lds 用 `ASSERT(SIZEOF(.plt)==0)` 等断言把这些动态设施统统禁掉（[002 §6](./002.链接脚本走读：vmlinux.lds.S.md)）。

## 1. 主流程：load_module 的五步

```
 sys_finit_module
  └─ load_module()                          kernel/module/main.c
      ① 读入 ELF → load_info（copy/校验）      info->hdr
      ② layout_and_allocate()                main.c:2943
           段地址规划（CORE/INIT 区），SHF_ALLOC 段各归其位
      ③ move_module()                        main.c:2788
           真正搬进内核地址空间（core_layout 的最终地址生效）
      ④ resolve + relocate
           find_symbol → 版本/CRC 检查 → apply_relocate_add()   main.c:1641 调用
      ⑤ post_relocation()                    main.c:3007
           percpu/mark ro etc. → complete_formation → 模块可见
```

教材视角：①-③ 是"装载"（对应静态 ld 的地址分配），④ 是"符号解析 + 重定位"（对应 ld 的两件核心工作）——ld 做的事一件不少，只是搬到了运行期。

## 2. 符号解析与版本检查（简）

模块的未定义符号在内核导出符号表（`__ksymtab`——又是 [002 §4](./002.链接脚本走读：vmlinux.lds.S.md) 的"链接器排表 + C 循表"模式）里查：找到 → 检查 `__versions`（CRC）→ 把内核侧地址回填给重定位用。**CONFIG_MODVERSIONS 关闭时跳过 CRC，符号名匹配即可。**

## 3. 重定位逐类型：apply_relocate 的 switch（arm64 实码）

先看公式（内核注释原文）：

```c
// arch/arm64/kernel/module.c:250（节选，7.1.3 实测）
	/* sym is the ELF symbol we're referring to. */
	sym = (Elf64_Sym *)sechdrs[symindex].sh_addr
		+ ELF64_R_SYM(rel[i].r_info);

	/* val corresponds to (S + A) in the AArch64 ELF document. */
	val = sym->st_value + rel[i].r_addend;

	/* Check for overflow by default. */
	overflow_check = true;

	/* Perform the static relocation. */
	switch (ELF64_R_TYPE(rel[i].r_info)) {
```

**S + A**：S = 符号最终地址（运行期才定），A = 汇编器记在重定位记录里的加数。switch 按 r_info 的类型字段分派，代表性类型（全部实测自 module.c:264-308）：

| 类型 | 行号 | 语义 | 改写指令的哪半 |
| - | - | - | - |
| `R_AARCH64_ABS64` | :269 | `*(u64 *)loc = val`（64 位绝对地址直填） | 数据/文字池（`reloc_data(RELOC_OP_ABS, …, 64)`） |
| `R_AARCH64_ABS32/16` | :273/:276 | 同上截窄（带溢出检查） | 常量池 |
| `R_AARCH64_PREL64/32/16` | :279-286 | `val - loc`（相对） | PC 相对数据引用 |
| `R_AARCH64_MOVW_UABS_G0..G2`（_NC 变体） | :291-308 | 把 val 的 16 位片填进 `MOVZ/MOVK` 的立即数位域（bit0/16/32） | "伪指令"装 64 位地址的 `movz x0,#lo; movk x0,#hi,…` 序列 |
| `R_AARCH64_ADR_PREL_PG_HI21(_NC)` / `ADD_ABS_LO12_NC` | :373/:376/:381 | `adrp` 的高 21 位页基 / `add` 的低 12 位 | arm64 访存两件套 |
| `R_AARCH64_JUMP26` / `CALL26` | :415/:416 | `b`/`bl` 的 ±128MB 位移位域 | 调用重定位 |

三条教学线：

1. **一条 `bl foo` 的完整旅程**：汇编器留 `R_AARCH64_CALL26`（A=-8：PC 天生超前 8 字节）→ insmod 时 `S + A - loc` 算出位移 → 塞进 `bl` 编码的 imm26 位域 → 溢出（>128MB）则模块加载失败（这就是模块分配要挑"近地址"的原因之一）；
2. **adrp+add 组合**（内核最常见访存形态）正好是两条重定位：HI21 填 `adrp` 页号、LO12 填 `add` 偏移——**重定位单位不是"指令"而是"指令里的位域"**，教材 p365 重定位记录的 `S A P` 三元组在这里逐字落地；
3. **与 vmlinux 的对照**：vmlinux 的 `.rela.dyn`（[002 §2](./002.链接脚本走读：vmlinux.lds.S.md) :297）是静态镜像里极少数需运行期处理的表（KASLR/EFI）；**模块的全部重定位都是运行期做**，且 lds 用 `ASSERT` 禁掉了 GOT/PLT（:223/:383）——内核要么静态定址、要么自己当动态链接器，不走通用 ELF 动态设施。

## 4. 段与权限：mini-vmlinux.lds

模块的段布局不是 lds 排的，是 `layout_and_allocate()`（main.c:2943）按 `sh_flags` 现场排：`SHF_EXECINSTR` 进 text 区（之后 `module_enable_ro`/`nx` 设页权限）——同一套"RO/NX/可写分离"思想（[002 §5](./002.链接脚本走读：vmlinux.lds.S.md)），只是排版者从 ld 换成 C 代码。

## 5. 常见误区

1. **"模块是共享库，走 PLT/GOT"**——不用：内核显式 ASSERT 禁用（lds:383），符号解析在加载时一次做完（静态绑定）；
2. **"重定位改的是数据"**——一半一半：ABS 族改数据/常量池，MOVW/adrp/CALL 族**改的是指令位域**（§3）；
3. **"模块加载慢只是因为拷贝"**——主要成本在逐条重定位 + 符号 CRC 检查（大模块几十万条 rel）；
4. **"`S+A` 是内核发明的"**——AArch64 ELF 规范的标准记号，内核注释原文引用（module.c:254）。
