## 0. 开场:Small is Beautiful

> The Linux design is especially interesting because it clearly illustrates the principle of Small is Beautiful. With minimal mechanism and a very limited number of system calls, Linux nevertheless provides a powerful and elegant file system.（Linux 的设计尤其有趣,因为它清晰地体现了"小即美"原则。以极少的机制和非常有限的系统调用,Linux 却提供了一个强大而优雅的文件系统。）<sup>[Modern Operating Systems 5th, 书页 766(PDF 795)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=795)</sup>

## 1. 10.6.1 基本概念:文件、目录、链接、挂载、锁

**文件的定义只有一句话**——Linux 文件就是 0 个或多个字节的序列,系统不关心内容含义:

> A Linux file is a sequence of 0 or more bytes containing arbitrary information. No distinction is made between ASCII files, binary files, or any other kinds of files. The meaning of the bits in a file is entirely up to the file's owner. The system does not care.（Linux 文件是包含任意信息的 0 个或多个字节的序列。系统不区分 ASCII 文件、二进制文件或任何其他类型的文件。文件中各个位的含义完全取决于文件的所有者,系统对此漠不关心。）<sup>[Modern Operating Systems 5th, 书页 766(PDF 795)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=795)</sup>

文件名 ≤255 字符、除 NUL 外全部 ASCII 合法;`.c`/`.gz` 等扩展名只是**约定**,OS 不强制。目录层级、绝对/相对路径、`.`/`..` 与本仓库 [007.符号链接和硬链接.md](./007.符号链接和硬链接.md) 所述一致。

**链接与挂载**是本节两个"UNIX 特性":链接让文件树从树变成 DAG(对应 §10.6.3 与 [007.符号链接和硬链接.md](./007.符号链接和硬链接.md));挂载把多块盘并成一棵树:

> The Linux solution is to allow one disk to be mounted in another disk's file tree. ... The user now sees a single file tree, and no longer has to be aware of which file resides on which device.（Linux 的解决方案是允许把一块盘挂载到另一块盘的文件树中。……用户从此看到的是单一的文件树,不必再关心哪个文件位于哪个设备上。）<sup>[Modern Operating Systems 5th, 书页 769(PDF 798)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=798)</sup>

**文件锁**:POSIX 提供"共享锁/排他锁 + 可阻塞/不可阻塞 + 字节区间锁"(图 10-26),内核实体见 `fcntl` 的 `F_SETLK/F_SETLKW` <sub>[/fs/locks.c](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/fs/locks.c)</sub>。

**特殊文件**:字符特殊文件(串行 I/O,键盘/打印机)与块特殊文件(可按块号随机访问,`/dev/hd1`)——`cp file /dev/lp` 就是打印。块设备的现代形态见 [000.块设备/000.块设备的操作.md](../052.INPUT_OUTPUT/000.块设备/000.块设备的操作.md)。

## 3. 10.6.3 实现(一):VFS 四大对象

> In order to enable applications to interact with different file systems, implemented on different types of local or remote devices, Linux takes an approach used in other UNIX systems: the Virtual File System (VFS). VFS defines a set of basic file-system abstractions and the operations which are allowed on these abstractions.（为了让应用程序与不同文件系统交互——它们实现于不同类型的本地或远程设备上——Linux 采用了其他 UNIX 系统的做法:虚拟文件系统(VFS)。VFS 定义了一组基本的文件系统抽象,以及允许在这些抽象上执行的操作。）<sup>[Modern Operating Systems 5th, 书页 775(PDF 804)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=804)</sup>

## 5. 10.6.3 实现(三):ext4 日志与 extent

**为什么需要日志**——书先把问题说穿:不刷盘快,但崩了就丢:

> In order to prevent all data loss after system crashes and power failures, the ext2 file system would have to write out each data block to disk as soon as it was created. The latency incurred during the required disk-head seek operation would be so high that the performance would be intolerable. Therefore, writes are delayed, and changes may not be committed to disk for up to 30 sec, which is a very long time interval in the context of modern computer hardware.（为了防止系统崩溃和断电后丢失全部数据,ext2 文件系统将不得不在每个数据块一创建时就把它写到磁盘上。由此产生的磁盘寻道延迟会高到性能无法忍受。因此写操作被推迟,变更可能最长 30 秒都不落盘——在现代计算机硬件的时间尺度上,这是非常长的一段时间。）<sup>[Modern Operating Systems 5th, 书页 781(PDF 810)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=810)</sup>

**日志的核心思想**(顺序写 + 崩溃后重放):

> The basic idea behind a journaling file system is to maintain a journal, which describes all file-system operations in sequential order. By sequentially writing out changes to the file-system data or metadata (i-nodes, superblock, etc.), the operations do not suffer from the overheads of disk-head movement during random disk accesses. Eventually, the changes will be written out, committed, to the appropriate disk location, and the corresponding journal entries can be discarded. If a system crash or power failure occurs before the changes are committed, during restart the system will detect that the file system was not unmounted properly, traverse the journal, and apply the file-system changes described in the journal log.（日志式文件系统的基本思想是维护一份日志,按顺序记录所有文件系统操作。通过顺序地写出对文件系统数据或元数据(i-node、超级块等)的变更,操作就不会承受随机磁盘访问中移动磁头的开销。最终这些变更会被写出、提交到合适的磁盘位置,相应的日志条目即可丢弃。如果在变更提交之前发生系统崩溃或断电,重启时系统会检测到文件系统未被正确卸载,遍历日志,并应用日志中描述的文件系统变更。）<sup>[Modern Operating Systems 5th, 书页 781(PDF 810)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=810)</sup>

**JBD 的三个数据结构**(图 10-30 无、书中文字给出):

> JBD supports three main data structures: log record, atomic operation handle, and transaction. A log record describes a low-level file-system operation... related log records are grouped in atomic operations. Ext4 notifies JBD of the start and end of system-call processing, so that JBD can ensure that either all log records in an atomic operation are applied, or none of them. Finally, primarily for efficiency reasons, JBD treats collections of atomic operations as transactions.（JBD 支持三种主要数据结构:日志记录、原子操作句柄和事务。日志记录描述一个低层文件系统操作……相关的日志记录被组成原子操作。ext4 把系统调用处理的开始与结束通知 JBD,使 JBD 能保证一个原子操作中的所有日志记录要么全部生效,要么全部不生效。最后,主要出于效率考虑,JBD 把原子操作的集合当作事务处理。）<sup>[Modern Operating Systems 5th, 书页 782(PDF 811)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=811)</sup>

→ 7.1.3 里:`handle_t`(原子操作句柄)/`transaction_t`(事务)/descriptor block 里的 tag(日志记录),完整实现剖析见姊妹篇 [012.WAL预写日志在Linux文件系统中的实现-ext4与JBD2.md](./012.WAL预写日志在Linux文件系统中的实现-ext4与JBD2.md)。

**ext4 两大升级**:日志可只记元数据("Journaling only metadata gives less system overhead and results in better performance but does not make any guarantees against corruption of file data."书页 782);**extent 取代间接块**:

> Key modification in ext4 compared to its predecessors is the use of extents. Extents represent contiguous blocks of storage, for instance 128 MB of contiguous 4-KB blocks vs. individual storage blocks, as referenced in ext2. Unlike its predecessors, ext4 does not require metadata operations for each block of storage.（与前辈相比,ext4 的关键修改是使用 extent(区段)。extent 表示连续的存储块,例如 128 MB 连续的 4 KB 块,而不是 ext2 所引用的逐个存储块。与前辈不同,ext4 不再需要为每一块存储做元数据操作。）<sup>[Modern Operating Systems 5th, 书页 782(PDF 811)](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=811)</sup>

量级对比:1 KB 块时最大文件从 16 GB(ext2/3) → 16 TB(ext4),文件系统上限 1 EB。`struct ext4_extent` 见 <sub>[/fs/ext4/ext4_extents.h](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/fs/ext4/ext4_extents.h)</sub>。

## 7. 10.6.4 NFS:无状态协议与 v-node

要点浓缩(书中 §10.6.4 全程):

```text
 客户端                                     服务端
 ─────────────                             ─────────────
 系统调用层(open/read/close)
 VFS 层(v-node 表:本地 i-node 或 远程 r-node)
   └ v-node ─┬─ 本地 → 具体文件系统 i-node
             └─ 远程 → NFS client ── RPC ──► NFS server → VFS → 本地 FS
 NFS 缓存:属性缓存 + 数据缓存;数据块计时器 3 s、目录块 30 s,
          打开时向服务器查询 mtime,每 30 s 全量回写脏块      (书页 788–789)
```

- **无状态(stateless)设计**:NFSv3 故意没有 open/close——"A server like this that does not maintain state information about open files is said to be stateless."(书页 786)。崩溃恢复因此免费:服务器重启后不知道任何"打开状态",请求自包含(file handle + offset + count);
- 代价:锁无法挂在"打开"上,NFS 需要额外的 NLM 锁协议;文件语义(如 close 释放锁)难以精确复现(书页 786);
- **NFSv4 转向有状态**:open 语义回归、消息更短、可打包多个操作(书页 789);
- 7.1.3 实体:`struct nfs_server` <sub>[/fs/nfs/super.c](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/fs/nfs/super.c)</sub>;v-node 的现代对应是 VFS 的 `struct inode`+`file_system_type` <sub>[/include/linux/fs.h:2338](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/fs.h)</sub>——"Although VFS was invented to support NFS, most modern Linux systems now support it as an integral part of the operating system, even if NFS is not used."(书页 786)

## 9. 小结(记忆钩)

- 一句话:Linux 文件系统 = **一个字节序列的文件抽象**(10.6.1) + **一张 POSIX 系统调用表**(10.6.2) + **四个 VFS 对象挂函数指针**(10.6.3) + **无状态 NFS**(10.6.4);
- 记忆钩:`lseek` 不碰盘、fd 0/1/2 天生已开、`unlink` 减到 0 才回收、fork 共享文件位置(三层表)、根 i-node 2;
- ext4 = ext2 布局 + **extent**(大文件) + **JBD2 日志**(崩溃一致,`dirty_expire_interval=30s` 的脏页有了兜底);
