与上表论断的对应:

+ **"写操作不是直接对块设备进行,而是在内存中进行"(16.1.2)** → ①②:`write(2)` 只把数据拷进页缓存并标脏就返回,盘上还是旧数据;
+ **"数据总是在物理内存中操作,随后在随机的时间点写回(或刷出)到磁盘"(第17章)** → ③④:写回由 flusher 线程周期唤醒或脏页超限触发,与写进程完全解耦,"随机的时间点"= `dirty_expire_interval` 到期或脏页比例越线;
+ **"读写请求放置在一个队列上……汇总起来,经过协同之后传输到设备"(6.5)** → ⑤⑥:plug 在进程本地蓄水、`blk_mq_attempt_bio_merge` 合并相邻块、`blk_finish_plug` 一次性批量下泄——"汇总+协同"的多队列实现。

### 1. ① write(2) → VFS → 块设备文件的 write_iter

系统调用入口与普通文件相同;分叉点在 `f_op`:块设备文件的 `file_operations` 是 `def_blk_fops`,其 `.write_iter = blkdev_write_iter`(block/fops.c:957)。

```c
/* block/fops.c:789-803 */

		ret = blkdev_direct_write(iocb, from);            // 直写:立即建 bio,绕过页缓存
		if (ret >= 0 && iov_iter_count(from))
			ret = direct_write_fallback(iocb, from, ret,
					blkdev_buffered_write(iocb, from));   // 剩余部分退回缓冲写
	} else {
		/* ... */
		inode_lock_shared(bd_inode);
		ret = blkdev_buffered_write(iocb, from);          // 缓冲写:进页缓存
		inode_unlock_shared(bd_inode);
	}
```

### 2. ② 缓冲写:数据进页缓存,标脏即返回

7.1.3 中块设备的缓冲写已改走 iomap(`blkdev_buffered_write` 一行完成委派):

```c
/* block/fops.c:733-737 */
static ssize_t blkdev_buffered_write(struct kiocb *iocb, struct iov_iter *from)
{
	return iomap_file_buffered_write(iocb, from, &blkdev_iomap_ops, NULL,
			NULL);
}
```

`blkdev_iomap_ops` 的映射逻辑极其简单——块设备上"文件偏移 == 磁盘扇区偏移",1:1 恒等映射;而普通文件要经 inode 的间接块/extent 树才能把偏移翻译成扇区:

```c

static int blkdev_iomap_begin(struct inode *inode, loff_t offset, loff_t length,
		unsigned int flags, struct iomap *iomap, struct iomap *srcmap)
{
	struct block_device *bdev = I_BDEV(inode);
	...
	iomap->bdev = bdev;
	iomap->offset = ALIGN_DOWN(offset, bdev_logical_block_size(bdev));
	iomap->type = IOMAP_MAPPED;
	iomap->addr = iomap->offset;              // :451 扇区地址 = 文件偏移(恒等)

```

随后 `iomap_write_iter`(fs/iomap/buffered-io.c:1099)循环做三件事:先做脏页节流检查,再把用户数据原子拷入页缓存 folio,最后提交标脏。**`write(2)` 的返回点就在这个循环结束处——此后数据只存在于物理内存**:

### 3. ③ 写回触发:超限节流 + flusher 线程,两条路

脏页不会永远躺着,两个时机被唤醒(对应图③):

+ **写进程自己被节流**:②中 `balance_dirty_pages_ratelimited_flags` 每写若干页检查一次 → `balance_dirty_pages`(mm/page-writeback.c:1802)。脏页超过 `vm.dirty_ratio` 时,写进程在此**睡眠等待**,直到写回追上——这是防止内存被脏页灌满的负反馈;
+ **flusher 内核线程异步写回**(每 backing device 一个,`ps` 里名为 `flush-8:0` 之类)。定时器/被节流进程/显式 `sync()` 都会投递工作,最终都进 `wb_workfn`:

```c
/* fs/fs-writeback.c:2411-2424(节选) */
void wb_workfn(struct work_struct *work)
{
	struct bdi_writeback *wb = container_of(to_delayed_work(work),
						struct bdi_writeback, dwork);
	...
	set_worker_desc("flush-%s", bdi_dev_name(wb->bdi));     // 线程名 "flush-8:0" 的由来
		do {
			pages_written = wb_do_writeback(wb);
```

### 5. ⑤ 块层公共入口:submit_bio 与 blk-mq 蓄水

`submit_bio`(block/blk-core.c:916)只做统计,立刻委派:`submit_bio_noacct`(:780)→ `__submit_bio_noacct`(:671,把递归拍平成迭代)→ `__submit_bio`(:627),在此按**驱动形态**分流:

### 7. ⑦ 完成中断:原路返回

设备 DMA 写完盘后发中断,回调链沿 bio→bh→folio 反向展开:`virtblk_done`(drivers/block/virtio_blk.c:350)→ `blk_mq_complete_request` → `bio_endio` → `end_bio_bh_io_sync`(fs/buffer.c:2666)→ `bh->b_end_io` = `end_buffer_async_write`(:383)。当 folio 上**全部** buffer 都完成,folio 结束写回态(`folio_end_writeback`),这页内存重新变为"干净、可回收"——至此"物理内存中修改的数据"才真正与盘上一致。

### 8. 与普通文件写路径的对照

块设备文件与普通文件**只在 VFS 之下、bio 之上不同**;从 `submit_bio` 开始(⑤⑥⑦)完全共用:

| 环节 | `/dev/sda`(块设备文件) | 普通文件(如 ext4) |
|-|-|-|
| write 入口 | `blkdev_write_iter`(block/fops.c:746) | `generic_file_write_iter` → `generic_perform_write`(mm/filemap.c:4297) |
| 偏移→扇区 | `blkdev_iomap_begin`:恒等映射(block/fops.c:439) | 文件系统映射:查 extent/间接块(偏移≠物理扇区) |
| 标脏 | `block_write_end` → `mark_buffer_dirty`(fs/buffer.c:2114) | 文件系统 write_end(如 ext4),或 iomap 通用路径 |
| 写回 writepages | `blkdev_writepages`(block/fops.c:477) | `ext4_writepages` 等文件系统实现 |
| bio 之后 | `submit_bio` → blk-mq → `queue_rq`(完全相同) | 同左 |

> 注:块设备缓冲写在 7.1.3 已切换到 iomap 框架(`blkdev_buffered_write` → `iomap_file_buffered_write`),但写回仍按 `CONFIG_BUFFER_HEAD` 走 `buffer_head` 路径;若内核未启用 `CONFIG_BUFFER_HEAD`,`def_blk_aops` 换用 iomap 写回变体(block/fops.c:585),`writepages` 改为 `iomap_writepages`。
