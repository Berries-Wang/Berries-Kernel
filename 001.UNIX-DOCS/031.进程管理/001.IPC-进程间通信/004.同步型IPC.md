# 004. 同步型 IPC：futex / 信号量 / 信号 / eventfd

> [README](./README.md)｜[000.SysV 公共框架](./000.SysV-IPC公共框架.md)｜[001.共享内存](./001.共享内存.md)（本类是它的命根）｜[002.消息队列](./002.消息队列.md)｜[003.Unix管道](./003.Unix管道.md)｜[005.平台注记](./005.平台注记与调度衔接.md)

它们不搬数据，交换的是"事件"——却是[共享内存](./001.共享内存.md)方案能活命的另一半。

- **futex**（kernel/futex/）：用户态先原子试一把（无竞争零系统调用），失败才 `futex_wait`（waitwake.c:710）挂到以 uaddr 哈希出的桶上（`struct futex_hash_bucket`，futex.h:134；全局表 `futex_queues`，core.c:64，查找 :449）；`futex_wake`（:155）按同一 uaddr 桶唤醒。**共享内存 + 一个 word + futex = 用户态锁的全部原料**（原子指令底座见 [005.平台注记](./005.平台注记与调度衔接.md) 的 LSE 链接）；
- **SysV 信号量**：`semget`（ipc/sem.c:624）/`semtimedop`（:2268）——内核对象版计数器，配 SysV shm 的老搭档（同走 [000](./000.SysV-IPC公共框架.md) 底座）；
- **信号**：`__send_signal_locked`（kernel/signal.c:1040，`kill` 系统调用 :3951）——异步打断，不排队数据，进程可自选处置（默认/忽略/捕获）。TASK_UNINTERRUPTIBLE 睡眠对普通信号免疫，但 TASK_KILLABLE（sched.h:137，= TASK_UNINTERRUPTIBLE | TASK_WAKEKILL）可被致命信号唤醒（状态机见 [000.进程状态](../008.进程调度/000.进程状态.md)）；
- **eventfd**：`eventfd_write`（fs/eventfd.c:247，计数器 +1）/read（取值清零）——一个 fd 化的"门铃"，`epoll` 监听大军里把内核事件翻译成统一事件源的标准件（`eventfd_fops`，:302）。

所有"睡等"最终落在调度器等待队列、醒来走唤醒抢占——见 [005.平台注记与调度衔接](./005.平台注记与调度衔接.md) 与 [011.四种抢占时机 §5](../008.进程调度/011.Linux内核4种抢占时机.md)。

## 示例：eventfd 门铃

```c
/* 004_eventfd_demo.c: eventfd 计数器——一个 fd 化的门铃，epoll 世界的统一事件源 */
#include <stdio.h>
#include <sys/eventfd.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void)
{
	int efd = eventfd(0, 0);      /* 初值 0；事件表见 eventfd_fops（fs/eventfd.c:302）*/

	if (fork() == 0) {
		unsigned long v;
		read(efd, &v, sizeof(v)); /* 阻塞直到计数非零，读走并清零 */
		printf("child woken, count = %lu\n", v);
		return 0;
	}

	sleep(1);                     /* 让子进程先睡进等待队列 */
	unsigned long one = 1;
	write(efd, &one, sizeof(one)); /* eventfd_write：计数 +1 → 叫醒读端 */
	wait(NULL);
	close(efd);
	return 0;
}
```

编译运行（已验证）——write 叫醒了睡在 read 上的子进程：

```console
$ gcc -Wall -o 004 004_eventfd_demo.c && ./004
child woken, count = 1
```
