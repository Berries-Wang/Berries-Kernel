# 000. SysV IPC 公共框架：三兄弟一个底座

> [README](./README.md)｜共享内存 [001](./001.共享内存.md)｜消息队列 [002](./002.消息队列.md)｜管道 [003](./003.Unix管道.md)｜同步型 [004](./004.同步型IPC.md)｜平台注记 [005](./005.平台注记与调度衔接.md)

shm/msg/sem 三个 SysV 机制共用一套"ID 数组 + 权限 + key 查找"框架（`CONFIG_SYSVIPC`，全在 `ipc/`）——先懂这一节，[001](./001.共享内存.md)/[002](./002.消息队列.md) 的系统调用就只剩各自的语义部分。

## 1. 两个结构体

```c
// include/linux/ipc.h:12 —— 每个内核 IPC 对象的头部（权限/键/ID）
struct kern_ipc_perm {
	spinlock_t	lock;
	bool		deleted;
	int		id;
	key_t		key;
	kuid_t		uid;
	...
	umode_t		mode;
	...
} ____cacheline_aligned_in_smp;

// include/linux/ipc_namespace.h:18 —— 每个 IPC namespace 一套 id 表
struct ipc_ids {
	int		in_use;
	unsigned short	seq;
	struct rw_semaphore	rwsem;      // 保护整张表
	struct idr		ipcs_idr;       // id → kern_ipc_perm
	...
	struct rhashtable	key_ht;     // key → 对象（哈希查找）
};
```

## 2. 四个动作

- **ID 容量**：`IPCMNI = 1<<15`（32768 个，ipc/util.h:32）；`IPCMNI_EXTEND = 1<<24`（util.h:33，扩展模式）——SMP 大机上不够用的历史问题，靠配置位宽解决；
- **查找**：key → 对象 `ipc_findkey()`（ipc/util.c:172，走 `key_ht`）；id → 对象走 `ipcs_idr`；
- **配额/注册**：`ipc_addid()`（ipc/util.c:278）分配 id 并挂表（超 `limit` 返回 ENOSPC）；
- **权限**：每次操作前 `ipcperms()`（ipc/util.c:553）按 uid/gid/mode 过审。

## 3. 隔离：IPC namespace

以上都在 `struct ipc_namespace` 内（`ids[3]` = shm/msg/sem 各一张表）——容器（clone `CLONE_NEWIPC`）各有一套 32768 个对象，互不可见。

## 4. 示例：同一个 key，三套对象各自独立编 ID

```c
/* 000_sysv_common_demo.c: 同一个 key，shm/msg/sem 三套对象各自独立编 ID */
#include <stdio.h>
#include <sys/ipc.h>
#include <sys/msg.h>
#include <sys/sem.h>
#include <sys/shm.h>

int main(void)
{
	key_t key = 0x5A5A0001;
	int shmid = shmget(key, 4096, IPC_CREAT | 0600);
	int msqid = msgget(key,     IPC_CREAT | 0600);
	int semid = semget(key,     1,     IPC_CREAT | 0600);

	printf("shmid=%d msqid=%d semid=%d —— 同 key 三对象（ipcs 可查）\n",
	       shmid, msqid, semid);

	shmctl(shmid, IPC_RMID, NULL);
	msgctl(msqid, IPC_RMID, NULL);
	semctl(semid, 0, IPC_RMID);
	return 0;
}
```

编译运行（已验证）：

```console
$ gcc -Wall -o 000 000_sysv_common_demo.c && ./000
shmid=32 msqid=1 semid=0 —— 同 key 三对象（ipcs 可查）
$ ipcs   # 可见三类对象的 key/ID/权限/配额，对应上面三个 id 空间
```

> ID 数值每次运行不同：id 不是"最低空闲位"而是**游标循环分配**（`ipc_idr_alloc` → `idr_alloc_cyclic`，ipc/util.c:230）——刚释放的 id 不会立刻复用；idx 回卷（≤ last_idx）时递增 `seq`（:240），id+seq 拼成完整句柄，防"拿着旧 id 摸到新对象"。
