## 调度域
根据系统的**内存**和**高速缓存**的布局，CPU域分成如下几类<sub>8.3.2　CPU调度域</sub>

|CPU域的分类|Linux内核分类|说明|
|-|-|-|
|- 超线程(Simultaneous MultiThreading,SMT)|- CONFIG_SCHED_SMT|- 一个物理核心可以有两个或者更多的运行线程，这称为超线程技术。超线程使用相同CPU资源且共享L1高速缓存，迁移进程不会影响高速缓存利用率|
|-|-|-|
|- 多核（Multi-Core，MC（LLC））|- CONFIG_SCHED_MC（LLC）|- 每个物理核心独享L1高速缓存，多个物理核心可以组成一个簇，簇里的CPU共享L2高速缓存|
|- 处理器（SoC）|- 内核称为DIE|- SoC级别(一颗物理CPU（Socket）)|

！注意，关于高速缓存，参考:[001.UNIX-DOCS/025.NUMA/README.md](../../001.UNIX-DOCS/025.NUMA/README.md)中的图
- ![图11.3 NUMA体系结构](../../../../001.UNIX-DOCS/025.SMP-NUMA/000.NUMA/999.IMGS/20260126111608.jpg)
- 在一个典型的支持超线程的多核 CPU 系统中，一个逻辑 CPU 会同时隶属于 SMT、MC（LLC）、DIE 和 NUMA 等不同层级的调度域。负载均衡会从最底层（如 SMT）开始，只有当本层域内无法达到均衡时，才会逐步上升到更高级别的域（如 MC（LLC）、DIE）去寻求平衡。
- 负载均衡的核心目标： 
  + **最大化数据局部性**，即让任务尽可能在“离数据最近”的 CPU 上运行，以减少内存访问延迟和提高高速缓存命中率。跨域迁移虽然可以实现负载均衡，但会带来性能惩罚，因此调度器会优先在本地域内进行调整，只有在必要时才会考虑跨域迁移。
  + Linux 内核能够清晰地把握硬件的物理拓扑，做到“先近后远”地解决负载不均问题，在追求 CPU 利用率最大化的同时，也最大限度地减少了因任务迁移带来的缓存失效和跨节点内存访问等性能开销

### 调度组(调度层级)
在Linux内核中`使用sched_domain数据结构来描述调度层级`，从default_topology[]数组可知，系统默认支持DIE层级、SMT层级以及MC（LLC）层级。另外，`在调度域里划分调度组`，`使用sched_group来描述调度组`，**调度组是负载均衡调度的最小单位**。在最低层级的调度域中，通常一个调度组描述一个CPU。
|层级|说明|备注|
|-|-|-|
|SMT(Simultaneous Multithreading)|超线程域|硬件特征：共享 L1 缓存、L2 缓存和执行单元|
|MC（Multi-Core）- Core Cluster（核心簇）||硬件特征：通常共享 L2 缓存（如果是 Cluster 架构）或仅共享 L3 缓存； MC 是“核心级”调度域，代表一个物理芯片内所有核心的集合。它关注的是核心之间的负载均衡，任务在MC域内迁移时，会失去L1/L2缓存热度，但保留L3缓存。|
|DIE (Package/Socket Die)| 一个Socket可包含多个DIE,共享L3高速缓存|硬件特征：共享最后一级缓存 (LLC/L3)； DIE 是“芯片级”调度域，代表一个独立的物理硅片。在现代Chiplet架构下，一个Socket可能包含多个DIE，每个DIE拥有自己独立的L3缓存。因此，DIE是L3缓存的物理边界，任务在DIE间迁移会导致L3缓存失效，开销远大于MC域内迁移。|
|NUMA(Non-Uniform Memory Access)| 主板插槽|硬件特征：跨 NUMA 访问内存需要通过 QPI/UPI/Infinity Fabric 总线，延迟极高|

AMD Ryzen Threadripper PRO 9995WX（96核192线程，Zen 5 架构）的底层拓扑划分：

| 层级名称 | 数量/标识 | 描述 | 关键特征 |
| :--- | :--- | :--- | :--- |
| **Socket** | **1** | 整个 CPU 物理封装，型号为 sTR5。 | **物理边界**：所有资源封装在此单一插槽内。 |
| **Package / IOD** | **1** | **中央 I/O 芯片 (IOD)**。12 个 CCD 环绕 1 个中央 IOD 的星型拓扑。 | **数据交换中枢**：所有 CCD 间通信、内存访问、I/O 数据均须经过此 IOD。NUMA 特性的物理根源。 |
| **NUMA Node**<br>*(取决于NPS设置)* | **NPS1: 1 节点**<br>**NPS2: 2 节点**<br>**NPS4: 4 节点** | **逻辑内存访问域**。BIOS 将 12 个 CCD 和 12 个内存通道逻辑分区。<br><br>**以 NPS4 为例**：共 4 节点，每节点含 3 个 CCD (24核/48线程) 并绑定 3 个交错内存通道。 | **内存访问边界**：操作系统感知的独立内存域。访问**本地节点**内存延迟最低；**跨节点**访问须经 IOD 路由，延迟显著增加。 |
| **DIE** (CCD) | **12** | **核心计算芯片 (Core Complex Die)**。每个 CCD 含 8 核，拥有独立的 32MB L3 缓存。 | **L3 缓存边界**：跨 CCD 调度任务会导致 L3 缓存完全失效。这是影响核心间数据共享延迟的最主要物理瓶颈。 |
| **MC** (调度域) | **12** (等同于 CCD) | **Linux 调度域中的 Multi-Core 层级**。在 Zen 5 架构中，一个 CCD 即为一个 CCX，MC 域精确地映射到该 CCD 内共享 L3 缓存的 8 个核心。 | **最高效的任务迁移域**：调度器在此域内（同 CCD 的 8 核之间）迁移任务时，**无 L3 缓存失效代价**，功耗和延迟代价极低。这是操作系统进行负载均衡决策的关键边界。 |
| **Core** (物理核心) | **96** (每 CCD 8 个) | 独立的物理执行单元，拥有私有的 L1 与 L2 缓存。 | **物理计算实体**：MC 域的构成成员，SMT 层的物理载体。 |
| **SMT** (逻辑线程) | **192** (每核 2 线程) | 同步多线程。每个物理核心对外呈现 2 个逻辑处理器。 | **最细粒度的共享边界**：同一核心内的 2 个线程**高度共享** L1/L2 缓存、前端解码及执行单元。适合协作型或延迟不敏感的辅助线程。 |

**表格中层级关系的核心逻辑总结：**

`Socket` 包含 → `NUMA Node`（逻辑分区）包含 → `DIE`（CCD，物理封装）包含 → `MC`（调度域，映射到 CCX/CCD 的共享 L3 域）包含 → `Core`（物理核心）承载 → `SMT`（逻辑线程）


在一个支持NUMA架构的处理器中，假设它支持SMT技术，那么整个系统的调度域和调度组的关系如图8.18所示，它在默认调度层级中新增一个NUMA层级的调度域。
