## 摘要

|摘要内容|说明|备注|
|-|-|-|
|- Linux 7.1.3 对调度域拓扑层次做了重要调整：新增 CLS（Cluster）层级、移除 DIE 层级改为 PKG 层级（基于 NUMA 节点）、SMT 层级增加 LLC 共享标志|-|-|
|- 调度域层次从 5.9 的 `SMT → MC → DIE` 演变为 7.1.3 的 `SMT → CLS → MC → PKG`（NUMA 系统再追加 `NODE → NUMA`）|-|-|
|- 7.1.3 使用 `SD_SHARE_LLC` 替代 5.9 的 `SD_SHARE_PKG_RESOURCES`，语义更清晰|-|-|
|-|-|-|

## 与 5.9 的关键差异总览

|对比项|Linux 5.9|Linux 7.1.3|说明|
|-|-|-|-|
|**拓扑层次**|SMT → MC → DIE|SMT → CLS → MC → PKG|新增 CLS 层级，DIE 被 PKG 取代|
|**DIE/PKG 层级掩码**|`cpu_cpu_mask()` → 所有在线 CPU|`cpu_node_mask()` → 同一 NUMA 节点内的 CPU|PKG 域从"物理封装"变为"NUMA 节点"|
|**DIE/PKG 层级名称**|`DIE`|`PKG`|名称变更，语义更明确|
|**SMT 域标志**|`SD_SHARE_CPUCAPACITY`|`SD_SHARE_CPUCAPACITY \| SD_SHARE_LLC`|SMT 层级明确标记 LLC 共享|
|**MC 域标志**|`SD_SHARE_PKG_RESOURCES`|`SD_SHARE_LLC`|标志位更名，语义从"共享封装资源"变为"共享最后一级缓存"|
|**CLS 域**|不存在|`SD_CLUSTER \| SD_SHARE_LLC`|新增 Cluster 层级，用于"簇"架构|
|**`sd_init` 参数**|`sd_init(tl, cpu_map, child, dflags, cpu)`|`sd_init(tl, cpu_map, child, cpu)`|移除了 `dflags` 参数|
|**`imbalance_pct` 默认值**|125|117|默认值降低，更敏感地触发均衡|
|**`busy_factor` 默认值**|32|16|默认值减半|
|**`TOPOLOGY_SD_FLAGS`**|`SD_SHARE_CPUCAPACITY \| SD_SHARE_PKG_RESOURCES \| SD_NUMA \| SD_ASYM_PACKING \| SD_SHARE_POWERDOMAIN`|`SD_SHARE_CPUCAPACITY \| SD_CLUSTER \| SD_SHARE_LLC \| SD_NUMA \| SD_ASYM_PACKING`|移除 `SD_SHARE_PKG_RESOURCES` 和 `SD_SHARE_POWERDOMAIN`，新增 `SD_CLUSTER` 和 `SD_SHARE_LLC`|
|**NUMA 拓扑构建**|直接追加 NUMA 层级|先插入 NODE 层级（identity distance），再追加 NUMA 层级|NODE 层级代表"本地节点"自身|
|**Cluster 负载均衡**|无|新增 `sched_cluster_active` 静态分支，优化 wake_affine 路径|详见 fair.c 中的 cluster 感知调度|

## 调度域

### default_topology 数组（7.1.3）

```c
// kernel/sched/topology.c:1803
static struct sched_domain_topology_level default_topology[] = {
#ifdef CONFIG_SCHED_SMT
    SDTL_INIT(tl_smt_mask, cpu_smt_flags, SMT),       // 自底向上第1层
#endif

#ifdef CONFIG_SCHED_CLUSTER
    SDTL_INIT(tl_cls_mask, cpu_cluster_flags, CLS),    // 自底向上第2层（新增）
#endif

#ifdef CONFIG_SCHED_MC
    SDTL_INIT(tl_mc_mask, cpu_core_flags, MC),          // 自底向上第3层
#endif
    SDTL_INIT(tl_pkg_mask, NULL, PKG),                  // 自底向上第4层（原DIE → PKG）
    { NULL, },
};
```

### 各层级掩码函数

|层级|掩码函数|定义|说明|
|-|-|-|-|
|SMT|`tl_smt_mask()`|`cpu_smt_mask(cpu)`|同一物理核心的兄弟线程|
|CLS|`tl_cls_mask()`|`cpu_clustergroup_mask(cpu)`|同一簇（Cluster）内的 CPU（新增）|
|MC|`tl_mc_mask()`|`cpu_coregroup_mask(cpu)`|共享 LLC 的核心组|
|PKG|`tl_pkg_mask()`|`cpu_node_mask(cpu)` → `cpumask_of_node(cpu_to_node(cpu))`|**同一 NUMA 节点内的所有 CPU**（关键变更）|

### 各层级标志位

|层级|flags 函数|返回值|说明|
|-|-|-|-|
|SMT|`cpu_smt_flags()`|`SD_SHARE_CPUCAPACITY \| SD_SHARE_LLC`|共享计算能力和 LLC（5.9 仅 `SD_SHARE_CPUCAPACITY`）|
|CLS|`cpu_cluster_flags()`|`SD_CLUSTER \| SD_SHARE_LLC`|Cluster 内共享 LLC|
|MC|`cpu_core_flags()`|`SD_SHARE_LLC`|共享 LLC（5.9 为 `SD_SHARE_PKG_RESOURCES`）|
|PKG|`tl_pkg_mask` 的 flags 为 `NULL`|无特殊标志|PKG 域本身不附加额外标志|

### 关键变更详解

#### 1. CLS（Cluster）层级新增

```c
// kernel/sched/topology.c:1771-1780
#ifdef CONFIG_SCHED_CLUSTER
int cpu_cluster_flags(void)
{
    return SD_CLUSTER | SD_SHARE_LLC;
}

const struct cpumask *tl_cls_mask(struct sched_domain_topology_level *tl, int cpu)
{
    return cpu_clustergroup_mask(cpu);
}
#endif
```

Cluster 层级位于 SMT 和 MC 之间，适用于某些 ARM/混合架构中"核心簇"的概念。在 Cluster 架构中，多个核心形成一个簇，簇内共享 L2 缓存或 LLC。

`sched_cluster_active` 静态分支键（`topology.c:674`）用于控制是否启用 cluster 感知的唤醒调度路径：

```c
// kernel/sched/topology.c:674
DEFINE_STATIC_KEY_FALSE(sched_cluster_active);
```

在 `fair.c` 的 `wake_affine` 路径中，当 `sched_cluster_active` 为真时，会优先考虑同一 cluster 内的空闲 CPU。

#### 2. DIE → PKG 变更，掩码从 `cpu_cpu_mask` → `cpu_node_mask`

**5.9 的 DIE 层级**：
```c
// 5.9: DIE 层级使用 cpu_cpu_mask()
static inline const struct cpumask *cpu_cpu_mask(int cpu)
{
    return cpu_online_mask;  // 所有在线 CPU
}
```

**7.1.3 的 PKG 层级**：
```c
// 7.1.3: PKG 层级使用 cpu_node_mask()
static inline const struct cpumask *cpu_node_mask(int cpu)
{
    return cpumask_of_node(cpu_to_node(cpu));  // 同一 NUMA 节点内的 CPU
}
```

**影响**：
- 在 **UMA 系统**（单 NUMA 节点）上，两者等价
- 在 **NUMA 系统**上，PKG 域的跨度从"整个物理封装"缩小为"单个 NUMA 节点"
- 对于 AMD EPYC 等每个 CCD 为一个 NUMA 节点的架构，PKG 域的范围与 MC 域可能重合，调度器会在 `cpu_attach_domain()` 中通过 `sd_parent_degenerate()` 自动退化掉冗余层级

#### 3. SMT 域增加 `SD_SHARE_LLC` 标志

```c
// 7.1.3
int cpu_smt_flags(void)
{
    return SD_SHARE_CPUCAPACITY | SD_SHARE_LLC;
}
```

这意味着在 7.1.3 中，SMT 域被认为共享 LLC（实际上 SMT 线程共享 L1/L2 缓存，L3 则是芯片级共享）。这个标志会影响 `sd_init()` 中的行为配置，如 `imbalance_pct` 和 `cache_nice_tries` 的设置。

#### 4. `sd_init()` 参数简化

```c
// 5.9
sd_init(struct sched_domain_topology_level *tl,
        const struct cpumask *cpu_map,
        struct sched_domain *child, int dflags, int cpu)

// 7.1.3
sd_init(struct sched_domain_topology_level *tl,
        const struct cpumask *cpu_map,
        struct sched_domain *child, int cpu)
```

7.1.3 移除了 `dflags` 参数，不再通过外部传入异步 CPU 容量标志，改为在 `sd_init` 内部通过 `asym_cpu_capacity_classify()` 函数自动检测并设置 `SD_ASYM_CPUCAPACITY` 标志。

## 调度组

### 构建调度组

```c
// kernel/sched/topology.c:1252-1286
static int build_sched_groups(struct sched_domain *sd, int cpu)
```

`build_sched_groups()` 构建一个循环链表，每个调度组覆盖一个调度域的子集。在最低层级的调度域中，通常一个调度组描述一个 CPU。

**7.1.3 的变更**：在 `build_sched_domains()` 中，NUMA 域和非 NUMA 域使用不同的组构建函数：

```c
// kernel/sched/topology.c:2698-2706
if (sd->flags & SD_NUMA) {
    if (build_overlap_sched_groups(sd, i))  // NUMA 域使用重叠组
        goto error;
} else {
    if (build_sched_groups(sd, i))           // 非 NUMA 域使用分区组
        goto error;
}
```

NUMA 域使用 `build_overlap_sched_groups()` 构建重叠调度组，因为不同 NUMA 节点的 CPU 看到的拓扑可能不同。

### 调度组容量初始化

7.1.3 新增了 `cores` 字段计算：

```c
// kernel/sched/topology.c:1298-1317
static void init_sched_groups_capacity(int cpu, struct sched_domain *sd)
{
    // ...
    cpumask_copy(mask, sched_group_span(sg));
    for_each_cpu(cpu, mask) {
        cores++;
#ifdef CONFIG_SCHED_SMT
        cpumask_andnot(mask, mask, cpu_smt_mask(cpu));  // 排除 SMT 兄弟线程
#endif
    }
    sg->cores = cores;
    // ...
}
```

`sg->cores` 字段记录了调度组中物理核心的数量（而非逻辑线程数），用于更精确的容量计算。

## NUMA 拓扑扩展

当系统支持 NUMA 时，`sched_init_numa()` 会在默认拓扑后追加 NUMA 层级：

```c
// kernel/sched/topology.c:2126-2143
/* 复制默认拓扑 */
for (i = 0; sched_domain_topology[i].mask; i++)
    tl[i] = sched_domain_topology[i];

/* 添加 NUMA identity distance（NODE 层级） */
tl[i++] = SDTL_INIT(sd_numa_mask, NULL, NODE);

/* 追加 NUMA 层级 */
for (j = 1; j < nr_levels; i++, j++) {
    tl[i] = SDTL_INIT(sd_numa_mask, cpu_numa_flags, NUMA);
    tl[i].numa_level = j;
}
```

**7.1.3 相比 5.9 的变更**：在 NUMA 层级之前新增了 `NODE` 层级（identity distance）。NODE 层级代表"本地节点"自身，flags 为 NULL，用于在 NUMA 系统中将"本地节点"作为一个独立的调度域层级。

完整的 NUMA 系统调度域层次：
```
SMT → CLS → MC → PKG → NODE → NUMA_1 → NUMA_2 → ...
```

## CPU 调度域拓扑关系

### 调度域初始化入口

```c
// kernel/sched/topology.c:2830-2848
int __init sched_init_domains(const struct cpumask *cpu_map)
{
    // ...
    arch_update_cpu_topology();
    asym_cpu_capacity_scan();
    // ...
    err = build_sched_domains(doms_cur[0], NULL);
    return err;
}
```

### 调度域构建流程

```c
// kernel/sched/topology.c:2670-2752
build_sched_domains(const struct cpumask *cpu_map, struct sched_domain_attr *attr)
{
    // 1. 遍历 default_topology[]，调用 sd_init() 构建 sched_domain 树
    for_each_sd_topology(tl) {
        sd = build_sched_domain(tl, cpu_map, attr, sd, i);
        // ...
    }

    // 2. 为每个域构建调度组
    for_each_cpu(i, cpu_map) {
        for (sd = *per_cpu_ptr(d.sd, i); sd; sd = sd->parent) {
            if (sd->flags & SD_NUMA)
                build_overlap_sched_groups(sd, i);
            else
                build_sched_groups(sd, i);
        }
    }

    // 3. 设置 LLC 共享域（SD_SHARE_LLC）
    for_each_cpu(i, cpu_map) {
        sd = *per_cpu_ptr(d.sd, i);
        while (sd->parent && (sd->parent->flags & SD_SHARE_LLC))
            sd = sd->parent;
        if (sd->flags & SD_SHARE_LLC) {
            sd->shared = *per_cpu_ptr(d.sds, sd_id);
            // ...
        }
    }

    // 4. 将调度域附加到 CPU
    for_each_cpu(i, cpu_map)
        cpu_attach_domain(sd, d.rd, i);
}
```

### 将调度域附加到就绪队列

```c
// kernel/sched/topology.c:724-791
static void cpu_attach_domain(struct sched_domain *sd, struct root_domain *rd, int cpu)
{
    // 1. 退化冗余的调度域（sd_parent_degenerate）
    // 2. 如果根域自身退化，则提升父域
    // 3. 更新缓存拓扑（update_top_cache_domain）
}
```

`cpu_attach_domain()` 中的 `sd_parent_degenerate()` 检测机制会将冗余的调度域层级自动退化。例如，如果 PKG 域的 span 与 MC 域相同（在单 NUMA 节点系统中），PKG 域会被退化掉，实际的调度域树中只有 SMT → MC → （NUMA if enabled）。

## 总结

Linux 7.1.3 的调度域拓扑相比 5.9 的主要演进方向：

1. **精细化**：新增 CLS 层级，适应现代处理器中"核心簇"的硬件拓扑
2. **NUMA 化**：PKG 域从物理封装概念变为 NUMA 节点概念，强化了 NUMA 感知
3. **标志位重构**：`SD_SHARE_PKG_RESOURCES` → `SD_SHARE_LLC`，语义更精确
4. **Cluster 感知调度**：新增 `sched_cluster_active` 静态分支，优化 wake_affine 路径
