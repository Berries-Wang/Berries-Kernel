## 摘要

|摘要内容|说明|备注|
|-|-|-|
|调度域（sched_domain）以"缓存/内存代价"为纲自底向上分层|7.1.3 默认层次 `SMT → CLS → MC → PKG`，NUMA 系统再追加 `NODE → NUMA...`|5.9 为 `SMT → MC → DIE`|
|CLS（Cluster）层级是 7.x 新增|覆盖"共享 L2 / L3 tag / 内部总线"的核心簇，arm64（DT/PPTT cluster）上可存活，x86 上因 `cpu_clustergroup_mask()==L2 共享掩码` 通常退化|`SD_CLUSTER \| SD_SHARE_LLC`|
|DIE 更名 PKG，掩码语义不变|5.9 的 `cpu_cpu_mask()` 与 7.1.3 的 `cpu_node_mask()` 都返回 `cpumask_of_node(cpu_to_node(cpu))`，即"同一 NUMA 节点"|旧文档"5.9 DIE=全部在线 CPU"的说法有误，本文已修正|
|`SD_SHARE_PKG_RESOURCES` → `SD_SHARE_LLC`|语义从"共享封装资源"收敛为"共享最后一级缓存"（可精确定位 LLC 域）|配合 per-CPU `sd_llc` 指针|
|SD_* 标志改由 sd_flags.h 集中定义|带 `SDF_SHARED_CHILD / SDF_SHARED_PARENT / SDF_NEEDS_GROUPS` 元标志，`SD_OVERLAP` 被删除（改看 `SD_NUMA`）|bit 值由枚举自动生成|
|调度组（sched_group）是负载均衡的最小单位|每个域的 groups 构成环形单向链表，"第一个组 = 本域的子域"；NUMA 域使用重叠组（overlap groups）|`build_sched_groups()` / `build_overlap_sched_groups()`|
|arm64 拓扑解析已集中到 drivers/base/arch_topology.c|`init_cpu_topology()`/`store_cpu_topology()` 由 GENERIC_ARCH_TOPOLOGY 提供，`arch/arm64/kernel/topology.c` 只剩 AMU 频率不变性、CPPC|与书（5.x）所述位置不同|
|big.LITTLE 异构容量从 DT `capacity-dmips-mhz` 读入|归一化到 `SCHED_CAPACITY_SCALE`，触发 `SD_ASYM_CPUCAPACITY(_FULL)`|Arm AGI CPU 同构（CPPC 单档 1024）不触发；异构例见附录 A（A520=403 树内真实值, A725=1024）|
|EPYC 9996（Zen 6c Venice）：LLC 边界 = CCX|每 CCD 含 2 个 CCX（各 16 核/64MB L3）→ MC 域 = 1 个 CCX（16c/32t），而 Zen3~Zen5 的 MC 域 = 整个 CCD|x86 大规模 NUMA 实例贯穿全文|
|构建链|`sched_init_smp() → sched_init_numa() → sched_init_domains() → build_sched_domains() → cpu_attach_domain()`，冗余层级由 `sd_degenerate()/sd_parent_degenerate()` 自动裁剪|域退化是理解"为什么 dmesg 里少了层级"的钥匙|

## 与 5.9 的关键差异总览

|对比项|Linux 5.9|Linux 7.1.3|说明|
|-|-|-|-|
|**拓扑层次**|SMT → MC → DIE|SMT → CLS → MC → PKG|新增 CLS；DIE 更名 PKG|
|**DIE/PKG 掩码函数**|`cpu_cpu_mask()`（topology.h:211）|`tl_pkg_mask()` → `cpu_node_mask()`（topology.c:1795、topology.h:263）|两者实现等价，都是 `cpumask_of_node(cpu_to_node(cpu))`，即"NUMA 节点"|
|**DIE/PKG 层级名称**|`DIE`|`PKG`|仅改名|
|**SMT 域标志**|`SD_SHARE_CPUCAPACITY \| SD_SHARE_PKG_RESOURCES`（本仓库 5.9 树 include/linux/sched/topology.h:30）|`SD_SHARE_CPUCAPACITY \| SD_SHARE_LLC`|SMT 线程天然共享 LLC，显式声明；旧笔记"5.9 仅 SD_SHARE_CPUCAPACITY"有误|
|**MC 域标志**|`SD_SHARE_PKG_RESOURCES`|`SD_SHARE_LLC`|更名并收敛语义|
|**CLS 域**|不存在|`SD_CLUSTER \| SD_SHARE_LLC`|新增 Cluster 层级（`CONFIG_SCHED_CLUSTER`，arch/Kconfig:62）|
|**SD_* 定义方式**|topology.h 中 `#define SD_XXX 0x0001...` 手写位值|sd_flags.h 中 `SD_FLAG(name, meta)` 宏生成枚举位|新增元标志 SDF_SHARED_CHILD/PARENT、SDF_NEEDS_GROUPS|
|**SD_OVERLAP 标志**|存在（0x1000），据此选择 overlap 组构建|删除|改用 `sd->flags & SD_NUMA` 判断（topology.c:2700）|
|**SD_SHARE_POWERDOMAIN**|存在（0x0080）|删除|能耗调度（EAS）改走 energy model，不再需要电源域标志|
|**`sd_init()` 签名**|`sd_init(tl, cpu_map, child, dflags, cpu)`|`sd_init(tl, cpu_map, child, cpu)`|删除 dflags，改由 `asym_cpu_capacity_classify()` 内部检测异构容量|
|**`imbalance_pct` 默认值**|125|117|均衡更积极|
|**`busy_factor` 默认值**|32|16|繁忙时拉大均衡间隔的倍数减半|
|**TOPOLOGY_SD_FLAGS**|`...\|SD_SHARE_PKG_RESOURCES\|SD_SHARE_POWERDOMAIN`|`SD_SHARE_CPUCAPACITY\|SD_CLUSTER\|SD_SHARE_LLC\|SD_NUMA\|SD_ASYM_PACKING`|topology.c:1653|
|**SDTL 数组初始化**|`{ cpu_smt_mask, cpu_smt_flags, SD_INIT_NAME(SMT) }`|`SDTL_INIT(tl_smt_mask, cpu_smt_flags, SMT)` 宏|topology.h:202|
|**掩码函数类型**|`typedef ... (*sched_domain_mask_f)(int cpu)`|`typedef ... (*)(struct sched_domain_topology_level *tl, int cpu)`|NUMA 层需要 `tl->numa_level` 取对应距离的掩码|
|**NUMA 拓扑构建**|直接追加 NUMA 层级|先插入 NODE 层级（identity distance），再追加 NUMA 层级|topology.c:2132；单节点系统里 NODE 常被退化或因提前 break 不构建|
|**sched_group 字段**|无 `cores`、无 `flags`|新增 `cores`（物理核数）与 `flags`（承载子域标志）|sched.h:2208/2211|
|**sched_domain_shared**|`ref / nr_busy_cpus / has_idle_cores`|新增 `nr_idle_scan`（SIS 利用率感知的空闲扫描上限）|topology.h:66-71|
|**sched_domain 统计**|`max_newidle_lb_cost / last_decay_max_lb_cost`|新增 `newidle_call/success/ratio/stamp`（50% 成功率自适应）|topology.c:1708-1711|
|**per-CPU 快捷指针**|`sd_llc/sd_llc_size/sd_llc_id/sd_numa/sd_asym_*`|新增 `sd_share_id`（cluster 机上=cluster id，否则=LLC id）|topology.c:664-671|
|**arm64 拓扑解析位置**|`store_cpu_topology()` 在 arch/arm64/kernel/topology.c:25|移至 drivers/base/arch_topology.c:961（与 RISC-V 共用）|7.1.3 的 arm64/topology.c 只剩 AMU/CPPC|
|**struct cpu_topology**（arch_topology.h）|`thread/core/package_id + llc_id + 3 个 sibling 掩码`|增 `cluster_id/cluster_sibling`，删 `llc_id`|7.1.3: arch_topology.h:62-70|
|**x86 自定义拓扑数组**|`x86_topology[]` + `x86_numa_in_package_topology[]` 两套|单套 `x86_topology[]`，运行时按 `topology_num_nodes_per_package()` 清零 PKG 项、按 SMT 数跳过 SMT 项|smpboot.c:471-506|
|**Cluster 感知调度**|无|`sched_cluster_active` 静态分支（topology.c:674），影响 wake_affine/select_idle_cpu 路径|arm64 簇机器上才打开|

## 一、调度域层次：default_topology 代码走读

### 1.1 三棵树：SDTL → sched_domain → sched_group

[000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/sched/topology.c](../../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/kernel/sched/topology.c) 文件头部 1136-1205 行的注释（本书配套源码自带中文翻译已体现在行 1801 的注释里）是理解全篇的钥匙，摘录如下（原文，ASCII 图为内核原样）：

```c
// kernel/sched/topology.c:1136
/*
 * Package topology (also see the load-balance blurb in fair.c)
 * ...
 * The tree consists of 3 primary data structures:
 *
 *	sched_domain -> sched_group -> sched_group_capacity
 *	    ^ ^             ^ ^
 *          `-'             `-'
 *
 * The sched_domains are per-CPU and have a two way link (parent & child) and
 * denote the ever growing mask of CPUs belonging to that level of topology.
 *
 * Each sched_domain has a circular (double) linked list of sched_group's, each
 * denoting the domains of the level below (or individual CPUs in case of the
 * first domain level). The sched_group linked by a sched_domain includes the
 * CPU of that sched_domain [*].
 *
 * Take for instance a 2 threaded, 2 core, 2 cache cluster part:
 *
 * CPU   0   1   2   3   4   5   6   7
 *
 * PKG  [                             ]
 * MC   [             ] [             ]
 * SMT  [     ] [     ] [     ] [     ]
 *
 *  - or -
 *
 * PKG  0-7 0-7 0-7 0-7 0-7 0-7 0-7 0-7
 * MC	0-3 0-3 0-3 0-3 4-7 4-7 4-7 4-7
 * SMT  0-1 0-1 2-3 2-3 4-5 4-5 6-7 6-7
 *
 * CPU   0   1   2   3   4   5   6   7
 *
 * One way to think about it is: sched_domain moves you up and down among these
 * topology levels, while sched_group moves you sideways through it, at child
 * domain granularity.
 * ...
 * [*] in other words, the first group of each domain is its child domain.
 */
```

要点（对照书 §8.3.2 图 8.18 的"调度域和调度组的关系"）：

- **sched_domain 上下移动**：`parent/child` 双向链，每个 CPU 各有一套（per-CPU），span 逐层扩大；
- **sched_group 左右移动**：同一域内 groups 构成**环形单向链表**，每个组 = 下一层的一个域（最底层则 = 单个 CPU）；
- **第一个组就是本域的子域**（`[*]` 注释），负载均衡以组为实体互相比拼。

### 1.2 SDTL：sched_domain_topology_level 与 SDTL_INIT

```c
// include/linux/sched/topology.h:182
typedef const struct cpumask *(*sched_domain_mask_f)(struct sched_domain_topology_level *tl, int cpu);
typedef int (*sched_domain_flags_f)(void);

struct sd_data {                                       // 每层级一份，per-CPU 分配三件套
	struct sched_domain *__percpu *sd;            //   调度域
	struct sched_group *__percpu *sg;             //   调度组
	struct sched_group_capacity *__percpu *sgc;   //   调度组容量
};

struct sched_domain_topology_level {
	sched_domain_mask_f mask;                     // 该层级的 CPU 位图函数
	sched_domain_flags_f sd_flags;                // 该层级的拓扑标志函数（可为 NULL）
	int		    numa_level;                 // NUMA 层级的距离档编号
	struct sd_data      data;                     // per-CPU 数据（构建期使用）
	char                *name;                    // 层级名："SMT"/"CLS"/"MC"/"PKG"/"NODE"/"NUMA"
};

// include/linux/sched/topology.h:202
#define SDTL_INIT(maskfn, flagsfn, dname) ((struct sched_domain_topology_level) \
		    { .mask = maskfn, .sd_flags = flagsfn, .name = #dname })
```

与 5.9 相比：掩码函数多了 `tl` 参数（NUMA 层的 `sd_numa_mask()` 需要读 `tl->numa_level` 才知道取第几档距离的掩码）；`SD_INIT_NAME()` 宏被 `SDTL_INIT()` 取代，数组项书写更规整。

### 1.3 default_topology[]：默认层次

```c
// kernel/sched/topology.c:1800
/*
 * Topology list, bottom-up.(拓扑列表（自底向上）)
 */
static struct sched_domain_topology_level default_topology[] = {
#ifdef CONFIG_SCHED_SMT
	SDTL_INIT(tl_smt_mask, cpu_smt_flags, SMT),     // 第1层：超线程
#endif

#ifdef CONFIG_SCHED_CLUSTER
	SDTL_INIT(tl_cls_mask, cpu_cluster_flags, CLS),  // 第2层：簇（7.x 新增）
#endif

#ifdef CONFIG_SCHED_MC
	SDTL_INIT(tl_mc_mask, cpu_core_flags, MC),       // 第3层：共享 LLC 的核组
#endif
	SDTL_INIT(tl_pkg_mask, NULL, PKG),               // 第4层：NUMA 节点（原 DIE）
	{ NULL, },                                       // 终结符
};

static struct sched_domain_topology_level *sched_domain_topology =
	default_topology;                               // arch 可用 set_sched_topology() 覆盖（x86 就这么干）

#define for_each_sd_topology(tl)			\
	for (tl = sched_domain_topology; tl->mask; tl++) // 逐层遍历宏
```

注意：**x86 从不使用 default_topology**。`arch/x86/kernel/smpboot.c:1265`（`native_smp_cpus_done()`）调用 `build_sched_topology()` 把 `x86_topology[]` 经 `set_sched_topology()` 设为全局拓扑（见第三章）。arm64 则直接使用 default_topology（arm64 Kconfig 同时 `select ARCH_SUPPORTS_SCHED_SMT/SCHED_CLUSTER/SCHED_MC`，arm64/Kconfig:86-88）。

### 1.4 各层级的掩码函数与标志函数

```c
// kernel/sched/topology.c:1760
int cpu_smt_flags(void)
{
	return SD_SHARE_CPUCAPACITY | SD_SHARE_LLC;     // SMT 线程共享执行单元与 LLC
}

// kernel/sched/topology.c:1765
const struct cpumask *tl_smt_mask(struct sched_domain_topology_level *tl, int cpu)
{
	return cpu_smt_mask(cpu);                       // → topology_sibling_cpumask(cpu)
}

// kernel/sched/topology.c:1772

{
	return SD_CLUSTER | SD_SHARE_LLC;               // 簇内共享 LLC（或 L3 tag）
}

// kernel/sched/topology.c:1784
int cpu_core_flags(void)
{
	return SD_SHARE_LLC;
}

// kernel/sched/topology.c:1795

{
	return cpu_node_mask(cpu);                      // PKG 掩码 = NUMA 节点

// tl_mc_mask()  → cpu_coregroup_mask()     (topology.c:1789)
```

|层级|掩码函数（arm64/GENERIC 实现）|x86 实现|flags|span 语义|
|-|-|-|-|-|
|SMT|`cpu_smt_mask()` → `cpu_topology[cpu].thread_sibling`|`topology_sibling_cpumask()`（per_cpu cpu_sibling_map）|`SD_SHARE_CPUCAPACITY\|SD_SHARE_LLC`|同一物理核的线程|
|CLS|`cpu_clustergroup_mask()`（arch_topology.c:732）|`cpu_l2c_shared_mask()`（smpboot.c:759）|`SD_CLUSTER\|SD_SHARE_LLC`|共享 L2/L3-tag 的核簇|
|MC|`cpu_coregroup_mask()`（arch_topology.c:705）|`cpu_llc_shared_mask()`（smpboot.c:754）|`SD_SHARE_LLC`|共享最后一级缓存|
|PKG|`cpu_node_mask()` → `cpumask_of_node()`（topology.h:263）|同左|无（NULL）|同一 NUMA 节点|
|NODE|`sd_numa_mask()`（topology.c:1841，numa_level=0）|同左|无（NULL）|本 NUMA 节点（identity distance）|
|NUMA|`sd_numa_mask()`（numa_level≥1）|同左|`SD_NUMA`|按距离档聚合的远端节点集合|

### 1.5 SD_* 标志位总表（sd_flags.h）

7.1.3 把 5.9 散落在 topology.h 里的 `#define SD_XXX` 集中到 [000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/sched/sd_flags.h](../../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/sched/sd_flags.h)，用宏生成枚举位，并给每个标志挂"元标志"（`SDF_SHARED_CHILD`=自底向上共享、`SDF_SHARED_PARENT`=自顶向下共享、`SDF_NEEDS_GROUPS`=仅当域有多个组时有意义）：

```c
// include/linux/sched/sd_flags.h:32
#define SDF_SHARED_CHILD       0x1     // 子域必须同置
#define SDF_SHARED_PARENT      0x2     // 父域必须同置
#define SDF_NEEDS_GROUPS       0x4     // 只有 >1 个组才有意义（退化判据用）
```

|标志|bit|元标志（sd_flags.h 行号）|含义|
|-|-|-|-|
|`SD_BALANCE_NEWIDLE`|0x0001|CHILD+GROUPS（:51）|变空闲时做 idle balance|
|`SD_BALANCE_EXEC`|0x0002|CHILD+GROUPS（:59）|exec 时重选 CPU（sched_exec）|
|`SD_BALANCE_FORK`|0x0004|CHILD+GROUPS（:67）|fork 后为新任务选 CPU（wake_up_new_task）|
|`SD_BALANCE_WAKE`|0x0008|CHILD+GROUPS（:75）|唤醒时选 CPU（默认 0）|
|`SD_WAKE_AFFINE`|0x0010|CHILD（:82）|支持 wake affine（阻止域退化）|
|`SD_ASYM_CPUCAPACITY`|0x0020|PARENT+GROUPS（:91）|域内有不同容量 CPU（big.LITTLE）|
|`SD_ASYM_CPUCAPACITY_FULL`|0x0040|PARENT+GROUPS（:101）|域内容量覆盖全部容量档位|
|`SD_SHARE_CPUCAPACITY`|0x0080|CHILD+GROUPS（:110）|共享计算能力（SMT）|
|`SD_CLUSTER`|0x0100|GROUPS（:117）|共享 CPU 簇（L2/L3 tag/内部总线）|
|`SD_SHARE_LLC`|0x0200|CHILD+GROUPS（:126）|共享最后一级缓存|
|`SD_SERIALIZE`|0x0400|PARENT+GROUPS（:137）|该层只允许一个均衡实例（NUMA 层）|
|`SD_ASYM_PACKING`|0x0800|GROUPS（:144）|非对称打包（PowerPC/ITMT 等）|
|`SD_PREFER_SIBLING`|0x1000|GROUPS（:154）|尽量把任务摊给兄弟组|
|`SD_NUMA`|0x2000|PARENT+GROUPS（:162）|跨节点均衡（NUMA 域判据 + overlap 组判据）|

topology.c 把允许出现在"拓扑描述"里的标志收敛为 `TOPOLOGY_SD_FLAGS`：

```c
// kernel/sched/topology.c:1653
#define TOPOLOGY_SD_FLAGS		\
	(SD_SHARE_CPUCAPACITY	|	\
	 SD_CLUSTER		|	\
	 SD_SHARE_LLC		|	\
	 SD_NUMA		|	\
	 SD_ASYM_PACKING)
```

`sd_init()` 里 `WARN_ONCE(sd_flags & ~TOPOLOGY_SD_FLAGS, "wrong sd_flags in topology description\n")` 会拒绝架构私货。与 5.9 相比删掉了 `SD_SHARE_PKG_RESOURCES` 与 `SD_SHARE_POWERDOMAIN`。

### 1.6 sd_init()：拓扑属性 → 调度行为（默认参数表）

```c
// kernel/sched/topology.c:1660
static struct sched_domain *
sd_init(struct sched_domain_topology_level *tl,
	const struct cpumask *cpu_map,
	struct sched_domain *child, int cpu)
{
	struct sd_data *sdd = &tl->data;
	struct sched_domain *sd = *per_cpu_ptr(sdd->sd, cpu);
	int sd_id, sd_weight, sd_flags = 0;
	struct cpumask *sd_span;
	// ...
	sd_span = sched_domain_span(sd);
	cpumask_and(sd_span, cpu_map, tl->mask(tl, cpu));   // span = cpu_map ∩ 层级掩码
	sd_weight = cpumask_weight(sd_span);
	sd_id = cpumask_first(sd_span);

	if (tl->sd_flags)
		sd_flags = (*tl->sd_flags)();
	// ...
	sd_flags |= asym_cpu_capacity_classify(sd_span, cpu_map);  // 自动检测异构容量（取代 5.9 的 dflags 参数）

	*sd = (struct sched_domain){
		.min_interval		= sd_weight,          // span 权重即最小均衡间隔(ms)
```

### 2.6 cpu_coregroup_mask / cpu_clustergroup_mask：MC 与 CLS 的"裁剪"算法

调度域构建时 tl_mc_mask/tl_cls_mask 调用的就是这两个函数，它们在 NUMA 掩码、core_sibling、llc_sibling、cluster_sibling 里**取最小者**：

```c
// drivers/base/arch_topology.c:705
const struct cpumask *cpu_coregroup_mask(int cpu)
{
	const cpumask_t *core_mask = cpumask_of_node(cpu_to_node(cpu));

	/* Find the smaller of NUMA, core or LLC siblings */
	if (cpumask_subset(&cpu_topology[cpu].core_sibling, core_mask)) {
		/* not numa in package, lets use the package siblings */
		core_mask = &cpu_topology[cpu].core_sibling;          // ① 封装
	}

	if (last_level_cache_is_valid(cpu)) {
		if (cpumask_subset(&cpu_topology[cpu].llc_sibling, core_mask))
			core_mask = &cpu_topology[cpu].llc_sibling;   // ② LLC 更小则用 LLC
	}

	/*
	 * For systems with no shared cpu-side LLC but with clusters defined,
	 * extend core_mask to cluster_siblings. The sched domain builder will
	 * then remove MC as redundant with CLS if SCHED_CLUSTER is enabled.
	 */
	if (IS_ENABLED(CONFIG_SCHED_CLUSTER) &&
	    cpumask_subset(core_mask, &cpu_topology[cpu].cluster_sibling))
		core_mask = &cpu_topology[cpu].cluster_sibling;        // ③ 无 LLC 信息时退而用簇

	return core_mask;
}

// drivers/base/arch_topology.c:732
const struct cpumask *cpu_clustergroup_mask(int cpu)
{
	/*
	 * Forbid cpu_clustergroup_mask() to span more or the same CPUs as
	 * cpu_coregroup_mask().
	 */
	if (cpumask_subset(cpu_coregroup_mask(cpu),
			   &cpu_topology[cpu].cluster_sibling))
		return topology_sibling_cpumask(cpu);                 // 簇 ⊇ MC → CLS 退化成 SMT

	return &cpu_topology[cpu].cluster_sibling;
}
```

规则：**CLS 层级的 span 必须严格小于 MC 层级的 span**，否则 CLS 返回 SMT 掩码（随后被 `sd_degenerate()` 删除）。这正是"有独立 LLC 分区（如鲲鹏 920 每 4 核共享 L3 tag）时 CLS 才有意义"的由来。

```
 以 CPU0 为例的垂直链 (rq->sd 向上):
            rq(cpu0)                       rq(cpu0)->rd  (root_domain, span=0-135)
              | sd                                  ^
              v                                     |
   domain: MC  span=0-135 level=2  ---- sd_llc_id=SLC; 顶层(PKG 未构建: build 循环 break)

```

说明：
- **同构 136 核 → `asym_cap_list` 只有一档**（capacity 全部经 CPPC `highest_perf` 归一化为 1024，`topology_init_cpu_capacity_cppc()`，arch_topology.c:327）→ classify 的 `count < 2` 返回 0（topology.c:1423）→ **无 `SD_ASYM_CPUCAPACITY`，EAS 不启用**（与 EPYC 9996 同为同构服务器；差异：9996 是 SMT2，AGI 无 SMT）；
- `sched_cluster_active` 保持关闭（不存在 >1 核的 cluster），wake_affine/select_idle_cpu 的 cluster 感知分支全部走默认路径；
- 组容量 `sgc->capacity` 初值是 `SCHED_CAPACITY_SCALE * 组内 CPU 数`（get_group(), topology.c:1238），同构下无需修正；
- `sd->level` 保留构建时编号（MC=2），退化不重编号；
- 异构 big.LITTLE（大小核触发 ASYM 标志/EAS）的对照实例见 **附录 A**；x86 大规模 NUMA 对照见第三章 EPYC 9996。

```c
{
	struct sched_domain_topology_level *topology = x86_topology;

	/*
	 * When there is NUMA topology inside the package invalidate the
	 * PKG domain since the NUMA domains will auto-magically create the
	 * right spanning domains based on the SLIT.

	if (topology_num_nodes_per_package() > 1) {       // NPS2/NPS4 -> 删除 PKG 项

	 * since it'll get degenerated by the scheduler anyways.

	if (cpu_smt_num_threads <= 1)
```

### 3.5 为什么 CLS 在 x86（含 9996）上必然退化

x86 的 CLS 掩码是 **L2 共享掩码**：

```c
// arch/x86/kernel/smpboot.c:754
/* maps the cpu to the sched domain representing multi-core */
const struct cpumask *cpu_coregroup_mask(int cpu)
{
	return cpu_llc_shared_mask(cpu);            // MC = L3 共享
}

const struct cpumask *cpu_clustergroup_mask(int cpu)
{
	return cpu_l2c_shared_mask(cpu);            // CLS = L2 共享
}
EXPORT_SYMBOL_GPL(cpu_clustergroup_mask);
```

而 `l2c_id` 只有 Intel 路径会填（cacheinfo.c:470，`init_intel_cacheinfo()`）；AMD 全系 `l2c_id == BAD_APICID`（topology_common.c:123 初值），于是 `match_l2c()` 回退成 `match_smt()`：

```c
// arch/x86/kernel/smpboot.c:379
static bool match_l2c(struct cpuinfo_x86 *c, struct cpuinfo_x86 *o)
{
	int cpu1 = c->cpu_index, cpu2 = o->cpu_index;

	/* If the arch didn't set up l2c_id, fall back to SMT */
	if (per_cpu_l2c_id(cpu1) == BAD_APICID)
		return match_smt(c, o);                 // AMD 走这里
	// ...
}
```

结果：AMD 上 `cpu_l2c_shared_mask(cpu) == topology_sibling_cpumask(cpu)`，**CLS 的 span 与 SMT 完全相同**。在 `cpu_attach_domain()`（topology.c:723）里：

1. `sd_parent_degenerate(SMT, CLS)`：`cpumask_equal(span(SMT), span(CLS))` 成立；CLS 只有一个组（子域 SMT），`pflags &= ~SD_DEGENERATE_GROUPS_MASK` 后仅剩 `SD_WAKE_AFFINE`，而 SMT 也有该标志 → `~cflags & pflags == 0` → 判定退化；
2. `tmp->parent = parent->parent`（SMT 直接挂到 MC），`destroy_sched_domain(CLS)`；
3. `lowest_flag_domain(cpu, SD_CLUSTER)` 随后返回 NULL → `sched_cluster_active` 静态分支保持关闭（topology.c:2754-2763）。

所以 9996 上 CLS 层级"名义存在、实际全灭"。这与 arm64 形成对照：arm64 簇（如鲲鹏 920 的 4 核 L3-tag 簇）能让 `cluster_sibling` 严格小于 LLC 掩码，CLS 才存活。

### 3.8 Zen5（MC=CCD）vs 9996（MC=CCX）：对负载均衡的意义

|对比项|Zen 3/4/5 EPYC（如 9005 系列）|EPYC 9996（Zen 6c Venice）|
|-|-|-|
|CCD 内 CCX 数|1|2|
|CCX 核数|8（Zen3/4）/ 16（Zen5c Dense）|16（Zen 6c）|
|每 CCX L3|32MB|64MB|
|LLC 边界|CCD（= CCX）|**CCX（CCD 的一半）**|
|MC 域大小（典型 Dense 配置）|16c/32t = 1 CCD|16c/32t = 1 CCX|
|MC 域与 CCD 关系|一一对应|一个 CCD 对应两个互不相干的 MC 域|
|PKG(NPS1) 内 MC 组数|8~12（= CCD 数）|16（= CCX 数）|

对调度器的实际影响：

- **缓存迁移代价的语义不变，但"同 CCD"这个概念从调度域中消失**：Zen3~5 中，任务在 MC 域内迁移 = 同 CCD 内换核（L3 全保留）；9996 中 MC 域内迁移 = 同 CCX 内换核（64MB L3 全保留），跨到同 CCD 的另一个 CCX 时 L3 同样全部失效——对调度器而言这与跨 CCD 迁移没有区别，都走 PKG/NODE 层均衡；
- **均衡粒度更细**：LLC 域从 8/16 核候选粒度固定为 16 核，`sd_llc_size=32`（线程），`select_idle_sibling()` 的空闲核搜索范围、SIS(Util) 扫描上限都随之确定；
- **NUMA 亲和与缓存亲和解耦更早**：NPS4 下 NODE 域（128 线程）内含 4 个 MC 组，组间均衡在 NODE 域完成时即感知"跨 CCX = 冷缓存"；
- **唤醒路径**：`sched_cluster_active` 在 9996 上不会打开（CLS 全灭），wake_affine 仍以 LLC（CCX）为界。

### 4.2 get_group() 与 build_sched_groups()：分组与环形链表

```c
// kernel/sched/topology.c:1207
static struct sched_group *get_group(int cpu, struct sd_data *sdd)
{
	struct sched_domain *sd = *per_cpu_ptr(sdd->sd, cpu);
	struct sched_domain *child = sd->child;
	struct sched_group *sg;
	bool already_visited;
	// ...
	if (child)
		cpu = cpumask_first(sched_domain_span(child));   // 组代表 = 子域 span 的第一个 CPU

	sg = *per_cpu_ptr(sdd->sg, cpu);                     // per-CPU 分配, 但用"组代表 CPU"下标 → 天然去重共享
	sg->sgc = *per_cpu_ptr(sdd->sgc, cpu);

	/* Increase refcounts for claim_allocations: */
	already_visited = atomic_inc_return(&sg->ref) > 1;
	// ...
	if (already_visited)
		return sg;                                       // 同一个组只初始化一次

	if (child) {
		cpumask_copy(sched_group_span(sg), sched_domain_span(child));  // 组 span = 子域 span
		cpumask_copy(group_balance_mask(sg), sched_group_span(sg));
		sg->flags = child->flags;                        // 组 flags = 子域 flags
	} else {
		cpumask_set_cpu(cpu, sched_group_span(sg));      // 最底层: 每组 1 个 CPU
		cpumask_set_cpu(cpu, group_balance_mask(sg));
	}

	sg->sgc->capacity = SCHED_CAPACITY_SCALE * cpumask_weight(sched_group_span(sg));
	// ...
	return sg;
}

// kernel/sched/topology.c:1252
static int
build_sched_groups(struct sched_domain *sd, int cpu)
{
	struct sched_group *first = NULL, *last = NULL;
	struct sd_data *sdd = sd->private;
	const struct cpumask *span = sched_domain_span(sd);
	struct cpumask *covered;
	int i;
	// ...
	covered = sched_domains_tmpmask;
	cpumask_clear(covered);

	for_each_cpu_wrap(i, span, cpu) {                    // 从本 CPU 开始环绕遍历
		struct sched_group *sg;
		// ...
		if (cpumask_test_cpu(i, covered))
			continue;                                // 已被前面的组覆盖(整个子域算一组)

		sg = get_group(i, sdd);
		cpumask_or(covered, covered, sched_group_span(sg));
		// ...
		if (!first)
			first = sg;                              // 第一个组 = 本 CPU 所在的组 = 子域
		if (last)
			last->next = sg;
		last = sg;
	}
	last->next = first;                                  // 闭合环形链表
	sd->groups = first;
	return 0;
}
```

### 4.3 NUMA 重叠组：build_overlap_sched_groups()

NUMA 域（`SD_NUMA`）的组之间**允许重叠**（不同节点视角的"近邻集合"互有交集），因此不能用互斥覆盖算法，改用"每个兄弟节点贡献一个组"：

```c
// kernel/sched/topology.c:1042
static int
build_overlap_sched_groups(struct sched_domain *sd, int cpu)
{
	// ...
	for_each_cpu_wrap(i, span, cpu) {
		// ...
		sibling = *per_cpu_ptr(sdd->sd, i);        // i 的同层级(本 NUMA 层)域
		// ...
		/*
		 * Usually we build sched_group by sibling's child sched_domain
		 * But for machines whose NUMA diameter are 3 or above, we move
		 * to build sched_group by sibling's proper descendant's child
		 * domain because sibling's child sched_domain will span out of
		 * the sched_domain being built as below.
		 *
		 * Smallest diameter=3 topology is:
		 *
		 *   node   0   1   2   3
		 *     0:  10  20  30  40
		 *     1:  20  10  20  30
		 *     2:  30  20  10  20
		 *     3:  40  30  20  10
		 *
		 *   0 --- 1 --- 2 --- 3
		 *
		 * NUMA-3       0-3             N/A             N/A             0-3
		 *  groups:     {0-2},{1-3}                                     {1-3},{0-2}
		 * NUMA-2       0-2             0-3             0-3             1-3
		 *  groups:     {0-1},{1-3}     {0-2},{2-3}     {1-3},{0-1}     {2-3},{0-2}
		 * NUMA-1       0-1             0-2             1-3             2-3
		 *  groups:     {0},{1}         {1},{2},{0}     {2},{3},{1}     {3},{2}
		 * NUMA-0       0               1               2               3
		 */
		if (sibling->child &&
		    !cpumask_subset(sched_domain_span(sibling->child), span))
			sibling = find_descended_sibling(sd, sibling);   // 组 span 必须含于域 span

		sg = build_group_from_child_sched_domain(sibling, cpu);
		// ...
		init_overlap_sched_group(sibling, sg);
		// ...
	}
	// ...
}
```

直径 ≥3 的拓扑里，兄弟节点的子域可能"伸出"本域 span，`find_descended_sibling()`（:1016）负责向下找一个合适的后代当组。组内还有一个额外的 balance mask（`build_balance_mask()`）：**重叠组的 span 只保留"该节点独有"的 CPU 参与均衡代表**，避免同一 CPU 在多个组里重复计数。

### 4.4 init_sched_groups_capacity()：cores 字段与 asym_prefer_cpu

```c
// kernel/sched/topology.c:1298
static void init_sched_groups_capacity(int cpu, struct sched_domain *sd)
{
	struct sched_group *sg = sd->groups;
	struct cpumask *mask = sched_domains_tmpmask2;
	// ...
	do {
		int cpu, cores = 0, max_cpu = -1;

		sg->group_weight = cpumask_weight(sched_group_span(sg));   // 线程数

		cpumask_copy(mask, sched_group_span(sg));
		for_each_cpu(cpu, mask) {
			cores++;                                           // 物理核数:
#ifdef CONFIG_SCHED_SMT
			cpumask_andnot(mask, mask, cpu_smt_mask(cpu));      //   剔除 SMT 兄弟
#endif
		}
		sg->cores = cores;

		if (!(sd->flags & SD_ASYM_PACKING))
			goto next;

		for_each_cpu(cpu, sched_group_span(sg)) {                // 非对称打包: 选首选 CPU
			if (max_cpu < 0)
				max_cpu = cpu;
			else if (sched_asym_prefer(cpu, max_cpu))
				max_cpu = cpu;
		}
		sg->asym_prefer_cpu = max_cpu;
next:
		sg = sg->next;
	} while (sg != sd->groups);
	// ...
	update_group_capacity(sd, cpu);                              // 组容量聚合(含异构容量修正)
}
```

`cores` 的意义：SMT2 机器上容量与任务的"核维度"统计（如 `sd_llc` 空闲核扫描）不应把兄弟线程算成两个核。9996 的 MC 组 `{0,256}` 的 `group_weight=2`、`cores=1`；PKG 组（一个 CCX）的 `group_weight=32`、`cores=16`。

### 5.3 build_sched_domains() 五步流程（图 d）

```c

static int
build_sched_domains(const struct cpumask *cpu_map, struct sched_domain_attr *attr)
{
	// ...
	alloc_state = __visit_domain_allocation_hell(&d, cpu_map);   // [0] per-CPU 分配 sd/sg/sgc/root_domain

	/* Set up domains for CPUs specified by the cpu_map: */
	for_each_cpu(i, cpu_map) {                                   // [1] 建 sched_domain 树
		struct sched_domain_topology_level *tl;
		sd = NULL;
		for_each_sd_topology(tl) {
			sd = build_sched_domain(tl, cpu_map, attr, sd, i);
			has_asym |= sd->flags & SD_ASYM_CPUCAPACITY;

				*per_cpu_ptr(d.sd, i) = sd;
			if (cpumask_equal(cpu_map, sched_domain_span(sd)))
				break;                                   // 域已盖满 cpu_map, 上面的层不建
		}
	}
	if (WARN_ON(!topology_span_sane(cpu_map)))                   // 非 NUMA 层掩码不得部分重叠
		goto error;

	/* Build the groups for the domains */
	for_each_cpu(i, cpu_map) {                                   // [2] 建调度组
		for (sd = *per_cpu_ptr(d.sd, i); sd; sd = sd->parent) {
			sd->span_weight = cpumask_weight(sched_domain_span(sd));
			if (sd->flags & SD_NUMA) {
				if (build_overlap_sched_groups(sd, i))   // NUMA 域: 重叠组
					goto error;
			} else {
				if (build_sched_groups(sd, i))           // 其它域: 分区组
					goto error;
			}
		}
	}

	for_each_cpu(i, cpu_map) {                                   // [3] 装配 LLC 共享数据
		sd = *per_cpu_ptr(d.sd, i);
		// ...
		while (sd->parent && (sd->parent->flags & SD_SHARE_LLC))
			sd = sd->parent;                             // 找最高 SD_SHARE_LLC 域
		if (sd->flags & SD_SHARE_LLC) {
			int sd_id = cpumask_first(sched_domain_span(sd));
			sd->shared = *per_cpu_ptr(d.sds, sd_id);     // sched_domain_shared(同 LLC 域共享)
			atomic_set(&sd->shared->nr_busy_cpus, sd->span_weight);
			// ...
			if (IS_ENABLED(CONFIG_NUMA) && sd->parent)
				adjust_numa_imbalance(sd);               // NUMA 失衡容忍度向上传播
		}
	}

	/* Calculate CPU capacity for physical packages and nodes */
	for (i = nr_cpumask_bits-1; i >= 0; i--) {                   // [4] 组容量/cores/asym_prefer
		// ...
		claim_allocations(i, &d);                          // 认领 per-CPU 对象(移交所有权)
		for (sd = *per_cpu_ptr(d.sd, i); sd; sd = sd->parent)
			init_sched_groups_capacity(i, sd);
	}

	/* Attach the domains */
	rcu_read_lock();                                              // [5] 附加 + 退化裁剪
	for_each_cpu(i, cpu_map) {
		rq = cpu_rq(i);
		sd = *per_cpu_ptr(d.sd, i);
		cpu_attach_domain(sd, d.rd, i);                    // → rq->sd, 期间做域退化
		if (lowest_flag_domain(i, SD_CLUSTER))
			has_cluster = true;
	}
	rcu_read_unlock();
	// ...
	if (has_asym)
		static_branch_inc_cpuslocked(&sched_asym_cpucapacity);   // big.LITTLE 静态分支
	if (has_cluster)
		static_branch_inc_cpuslocked(&sched_cluster_active);     // cluster 静态分支
	// ...
}
```

### 5.4 cpu_attach_domain() 与域退化

```c
// kernel/sched/topology.c:171
static int sd_degenerate(struct sched_domain *sd)
{
	if (cpumask_weight(sched_domain_span(sd)) == 1)
		return 1;                                    // ① 单 CPU 域必退化

	/* Following flags need at least 2 groups */
	if ((sd->flags & SD_DEGENERATE_GROUPS_MASK) &&
	    (sd->groups != sd->groups->next))
		return 0;                                    // ② 有"需要多组"的标志且确有多组 → 保留

	/* Following flags don't use groups */
	if (sd->flags & (SD_WAKE_AFFINE))
		return 0;                                    // ③ wake affine 域保留

	return 1;
}

// kernel/sched/topology.c:188
static int
sd_parent_degenerate(struct sched_domain *sd, struct sched_domain *parent)
{
	unsigned long cflags = sd->flags, pflags = parent->flags;

	if (sd_degenerate(parent))
		return 1;

	if (!cpumask_equal(sched_domain_span(sd), sched_domain_span(parent)))
		return 0;                                    // ④ 父子 span 相同才可能退化父

	/* Flags needing groups don't count if only 1 group in parent */
	if (parent->groups == parent->groups->next)
		pflags &= ~SD_DEGENERATE_GROUPS_MASK;       // ⑤ 单组父域: 组相关标志不算数

	if (~cflags & pflags)
		return 0;                                    // ⑥ 父域标志必须是子域子集

	return 1;
}
```

```c
// kernel/sched/topology.c:723
static void
cpu_attach_domain(struct sched_domain *sd, struct root_domain *rd, int cpu)
{
	struct rq *rq = cpu_rq(cpu);
	struct sched_domain *tmp;

	/* Remove the sched domains which do not contribute to scheduling. */
	for (tmp = sd; tmp; ) {                          // (a) 自底向上逐个检查父域
		struct sched_domain *parent = tmp->parent;
		if (!parent)
			break;

		if (sd_parent_degenerate(tmp, parent)) { // 冗余父域: 摘链销毁
			tmp->parent = parent->parent;
			// ... shared 指针移交 / SD_PREFER_SIBLING 下放 / 组 flags 更新
			destroy_sched_domain(parent);
		} else
			tmp = tmp->parent;
	}

	if (sd && sd_degenerate(sd)) {                   // (b) 根域自身单 CPU: 整条链只剩它自己也被删
		tmp = sd;
		sd = sd->parent;
		destroy_sched_domain(tmp);
		if (sd) {
			struct sched_group *sg = sd->groups;
			do {
				sg->flags = 0;
			} while (sg != sd->groups);
			sd->child = NULL;
		}
	}

	sched_domain_debug(sd, cpu);                     // (c) sched_verbose 时打印拓扑(dmesg)

	rq_attach_root(rq, rd);                          // (d) 挂 root_domain
	tmp = rq->sd;
	rcu_assign_pointer(rq->sd, sd);                  // (e) 正式上线: rq->sd 指向裁剪后的链头
	dirty_sched_domain_sysctl(cpu);
	destroy_sched_domains(tmp);                      // 旧域链 RCU 延迟销毁

	update_top_cache_domain(cpu);                    // (f) 刷新 per-CPU 快捷指针
}
```

```c
// kernel/sched/topology.c:676
static void update_top_cache_domain(int cpu)
{
	struct sched_domain_shared *sds = NULL;
	struct sched_domain *sd;
	int id = cpu;
	int size = 1;

	sd = highest_flag_domain(cpu, SD_SHARE_LLC);       // 最高 LLC 域
	if (sd) {
		id = cpumask_first(sched_domain_span(sd));
		size = cpumask_weight(sched_domain_span(sd));
		sds = sd->shared;
	}
	rcu_assign_pointer(per_cpu(sd_llc, cpu), sd);       // select_idle_sibling 的搜索锚点
	per_cpu(sd_llc_size, cpu) = size;                   // 9996: 32 ; AGI(SLC): 136(示意)
	per_cpu(sd_llc_id, cpu) = id;

	sd = lowest_flag_domain(cpu, SD_CLUSTER);
	if (sd)
		id = cpumask_first(sched_domain_span(sd));

	/* This assignment should be placed after the sd_llc_id as
	 * we want this id equals to cluster id on cluster machines
	 * but equals to LLC id on non-Cluster machines. */
	per_cpu(sd_share_id, cpu) = id;                     // cluster 机=cluster id, 否则=LLC id

	sd = lowest_flag_domain(cpu, SD_NUMA);
	rcu_assign_pointer(per_cpu(sd_numa, cpu), sd);      // NUMA 均衡任务迁移的界

	sd = highest_flag_domain(cpu, SD_ASYM_PACKING);
	rcu_assign_pointer(per_cpu(sd_asym_packing, cpu), sd);

	sd = lowest_flag_domain(cpu, SD_ASYM_CPUCAPACITY_FULL);
	rcu_assign_pointer(per_cpu(sd_asym_cpucapacity, cpu), sd);  // big.LITTLE misfit 均衡界
}
```

## 总结

Linux 7.1.3 的调度域/调度组子系统相对 5.9 的演进可以概括为四条主线，且都能落在具体源码上：

1. **层次精细化**：新增 CLS 层级（`SD_CLUSTER|SD_SHARE_LLC`，arch/Kconfig:62）与 NODE 层级（identity distance），形成 `SMT → CLS → MC → PKG → NODE → NUMA` 的完整谱系；但"层级存在"不等于"域存活"——两道闸门先后裁决：**构建循环**发现某层 span 已覆盖整个 cpu_map 即 break（更高层**未构建**，如单节点系统的 PKG/NODE、AGI 上 MC=全片即顶层），随后 `cpu_attach_domain()` 的**退化逻辑**（sd_degenerate/sd_parent_degenerate）再裁掉冗余层：Arm AGI CPU 上 SMT/CLS（V3 Direct connect 单核簇）死于退化，EPYC 9996 上 CLS 全灭（单组 ④⑤⑥），NPS1 下 PKG/NODE 则根本未构建。
2. **标志语义收敛**：`SD_SHARE_PKG_RESOURCES/SD_SHARE_POWERDOMAIN/SD_OVERLAP` 退场，`SD_SHARE_LLC` 取代；sd_flags.h 以元标志（SHARED_CHILD/SHARED_PARENT/NEEDS_GROUPS）把"标志在层级间的传播规则"与"退化判据"（SD_DEGENERATE_GROUPS_MASK）数据化。
3. **架构归一**：arm64 拓扑解析（DT cpu-map / ACPI PPTT / capacity-dmips-mhz）集中到 drivers/base/arch_topology.c，`cpu_topology` 增加 cluster 维度；x86 通过 `x86_topology[]` + CPUID 0x1F/0x80000026/0x8000001d/0x8000001d 自举，AMD 的 LLC id 完全由"共享 L3 的线程数"推导——这正是 EPYC 9996（每 CCD 2 CCX）无需任何内核改动就自动获得"MC=CCX"域的原因。
4. **消费侧协同**：`sched_domain_shared`（nr_idle_scan）、per-CPU 快捷指针（sd_llc/sd_share_id/sd_numa/sd_asym_*）、静态分支（sched_cluster_active/sched_asym_cpucapacity）与 `sched_group.cores` 让负载均衡（fair.c）与唤醒路径能以 O(1) 定位 LLC 域、簇域与异构容量域。

对调度域的完整生命周期，一句话：**固件描述拓扑 → arch 解析成四组掩码 → default_topology/x86_topology 定义层级 → sd_init 翻译成行为参数 → build_sched_groups 组环 → cpu_attach_domain 裁剪上线 → debugfs/dmesg 可观测**。

|维度|Cortex-A725（大核）|Cortex-A520（小核）|对调度器/调度域的含义|
|-|-|-|-|
|指令集|Armv9.2-A|Armv9.2-A|同 ISA，软件无感切换|
|流水线|**乱序**（寄存器重命名→乱序发射队列）|**顺序**（in-order + 直接/间接分支预测）|同频下 A725 每 MHz 完成更多工作 → `capacity-dmips-mhz` 更高|
|L2|**每核私有**、统一、8 路，128KB/256KB/512KB/1MB 可配，经 CPU bridge 接 DSU-120|**每 complex（一对核）共享**，128KB/192KB/256KB/384KB/512KB 可配，可选 1-2 个 slice|A520 对 → `cluster_sibling={对}` 可成 CLS 域；A725 私有 L2 → 单核"簇"退化|
|L3|无片上 L3，经 DSU-120 共享簇级 L3|同左|**LLC=全片 L3** → MC(LLC) 域跨大小核|
|L1 I/D|各 32KB 或 64KB 可配|各 32KB 或 64KB 可配（整簇统一选项）|—|
|SMT|无|无|无 SMT 域|

树内尚无 A725 的 DTS，下面的 DT 片段为**示意**（模板仿 [cix/sky1.dtsi](../../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/boot/dts/cix/sky1.dtsi) 的 A520 节点与 [qcom/sm8650.dtsi](../../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/boot/dts/qcom/sm8650.dtsi) 的"私有/共享 l2 phandle + 共享 l3"写法；A520 的 `capacity-dmips-mhz = <403>` 为 sky1.dtsi:25 **真实值**，A725 的 1024 为示意）：

```dts
// 示意 DT（非树内文件）: 4 x Cortex-A725 (每核私有 L2) + 4 x Cortex-A520 (每对共享 L2) + DSU-120 L3
	cpu-map {
		cluster0 { core0 { cpu = <&cpu0>; }; };            /* A725: 单核一簇(私有 L2) */
		cluster1 { core0 { cpu = <&cpu1>; }; };            /* A725 */
		cluster2 { core0 { cpu = <&cpu2>; }; };            /* A725 */
		cluster3 { core0 { cpu = <&cpu3>; }; };            /* A725 */
		cluster4 {                                        /* A520 complex0: 一对核共享 L2 */
			core0 { cpu = <&cpu4>; };
			core1 { cpu = <&cpu5>; };
		};
		cluster5 {                                        /* A520 complex1 */
			core0 { cpu = <&cpu6>; };
			core1 { cpu = <&cpu7>; };
		};
	};

	cpu0: cpu@0 {
		compatible = "arm,cortex-a725";
		next-level-cache = <&l2_0>;                        // 私有 L2
		capacity-dmips-mhz = <1024>;                       // 大核(示意)
	};
	cpu4: cpu@400 {
		compatible = "arm,cortex-a520";                    // 参照 cix/sky1.dtsi:21
		next-level-cache = <&l2_45>;                       // 与 cpu5 共享同一 L2 phandle
		capacity-dmips-mhz = <403>;                        // 小核(sky1.dtsi:25 真实值)
	};

	l2_0:  l2-cache { next-level-cache = <&l3_0>; };      // A725 x4 各自私有, 均下衔 L3
	l2_45: l2-cache { next-level-cache = <&l3_0>; };      // A520 对共享, 下衔 L3
	l3_0:  l3-cache { compatible = "cache"; cache-level = <3>; };  // DSU-120, 全片共享
```

8 核无 SMT；**DSU-120 的 L3 是全片唯一的 LLC**，`llc_sibling = 0-7`（跨大小核），这与"每簇分离 LLC"的老式双簇 SoC 不同。逐层推导：

|层级|掩码来源|CPU0(A725) 的 span|CPU4(A520) 的 span|结论|
|-|-|-|-|-|
|SMT|`thread_sibling`|{0}|{4}|单 CPU → 不构建|
|CLS|`cpu_clustergroup_mask()` = `cluster_sibling`（arch_topology.c:732：MC ⊆ cluster_sibling 时才回退 SMT 掩码）|{0}|{4,5}|A725 单核簇 → 退化；A520 对 → **存活**|
|MC|`cpu_coregroup_mask()`：llc_sibling(0-7) ⊆ core_sibling(0-7) ⊆ node(0-7)|0-7|0-7|存活，`SD_SHARE_LLC`；跨大小核|
|PKG|`cpu_node_mask()` = node0|0-7|0-7|**未构建**：MC span(0-7) == cpu_map → 构建循环 break（topology.c:2688）；MC 上的 ASYM 标志是 sd_init:1681 构建期 classify 直接打上的，并非经 PKG 退化下放|

**arm64 DynamIQ big.LITTLE 调度域树**：

```
 4 x Cortex-A725 (私有 L2) + 4 x Cortex-A520 (成对共享 L2) + DSU-120 (共享 L3)
     CPU0..3 = A725 (capacity 1024)     CPU4..7 = A520 (capacity 403)

   CPU    0     1     2     3     4     5     6     7
          A725  A725  A725  A725  A520  A520  A520  A520
   cap    1024  1024  1024  1024  403   403   403   403
          |私有L2||私有L2||私有L2||私有L2||--对--||--对--|     <-- L2 层
          |<------------- DSU-120 L3 (LLC) ------------>|     <-- LLC 层

   PKG   [X 未构建: MC span(0-7)==cpu_map -> build 循环 break (topology.c:2688)]
   MC    [                                             ]   span=0-7   level=2
         flags: SHARE_LLC|ASYM_CPUCAPACITY|ASYM_CPUCAPACITY_FULL|BALANCE_*|WAKE_AFFINE
         (classify: count=2 档且 miss=0 -> FULL, topology.c:1428)
   CLS   [ ] [ ] [ ] [ ]   [{4 5}]        [{6 7}]          A520 对存活: span={4,5}/{6,7}
         A725: span 单 CPU -> sd_degenerate 删除            flags: CLUSTER|SHARE_LLC
   SMT   [X 不构建: 无 thread 节点]

 以 CPU4 (A520) 为例的垂直链 (rq->sd 向上, groups 为该域的调度组环形链):
            rq(cpu4)                       rq(cpu4)->rd  (root_domain, span=0-7)
              | sd                                  ^
              v                                     |
   domain: CLS  span={4,5} level=1  ---- sched_cluster_active 因 A520 对而被打开
     groups: {4} -> {5} -> (环回)                       2 组, 每组 1 CPU
              | ->parent
              v
   domain: MC   span=0-7   level=2  ---- sd_llc_id=L3, sd_llc_size=8 (全片即 LLC 域)
     groups: {0} {1} {2} {3} {4} {5} {6} {7} -> (环回)    8 组, 每组 1 CPU
              | ->parent == NULL   (PKG 未构建(break), MC 即顶层; ASYM_CPUCAPACITY 来自 sd_init:1681 classify)
```

说明：
- 组容量 `sgc->capacity` 初值是 `SCHED_CAPACITY_SCALE * 组内 CPU 数`（get_group(), topology.c:1238），随后 `update_group_capacity()` 按 `arch_scale_cpu_capacity()` 修正为 1024/403 的真实比例（MC 域 8 组总容量 = 4×1024 + 4×403 ≈ 5708，示意）；
- `sd->level` 保留构建时编号（SMT=0、CLS=1、MC=2、PKG=3），**退化不重编号**，故 dmesg 里 MC 域的 `level=2` 而它却是 CPU4 的顶层域；
- 与老式"两簇分离 LLC"（大小核各处一簇、簇内共享 L2 且簇间无 L3，MC=簇）相比，DynamIQ 单 DSU 的关键差异是 **MC 域横跨大小核**（PKG 因 MC==cpu_map 未构建，MC 即顶层），异构容量标志（ASYM_CPUCAPACITY|_FULL）由 sd_init:1681 的 classify 在构建期直接落在 MC 上；
- 容量异构唤醒 EAS：`sched_is_eas_possible()` 要求有 `sd_asym_cpucapacity`、无 SMT、频率不变——本例全部满足（示意），详见 [005.绿色节能调度器](../005.绿色节能调度器/README.md)。
