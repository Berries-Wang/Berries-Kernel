# Linux内核4种抢占时机

> 本文按 Linux 7.1.3（本仓库 [000.SOURCE_CODE/003.LINUX-7.1.3](../../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3)）+ arm64 把四个时机的每一跳落到源码（行号均 `grep -n` 实测）。平台口径：**主实例 Arm AGI CPU（SP113012）**、对照 **AMD EPYC 9996（x86_64）**、异构（A725/A520）见文末附录。时钟中断这条触发源的完整走线见姊妹篇 [010.时钟中断到调度执行完整路径.md](./010.时钟中断到调度执行完整路径.md)；"持锁不被抢占"的同步语义见 [004.8.1.4 §2.5](../../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/004.8.1.4-多处理器调度.md)。

## 1. 总览：四个扳机，一个终点

原表修复并补上 7.1.3 的代码落点：

| 抢占时机 | 触发条件 | 代码落点（7.1.3）| 备注 |
|-|-|-|-|
| ① 用户态抢占 | 系统调用/中断返回用户态时，`TIF_NEED_RESCHED` 置位 → `schedule()` | `exit_to_user_mode_loop`（kernel/entry/common.c:94）→ 判定 :52 | **懒抢占 LAZY 在此生效**（§6）|
| ② 内核态抢占 | 中断返回内核态，`preempt_count==0` 且 `need_resched()` → `preempt_schedule_irq()` | `raw_irqentry_exit_cond_resched`（common.c:134）→ core.c:7529 | `CONFIG_PREEMPT(_DYNAMIC)`；持自旋锁免谈 |
| ③ 显式让出/阻塞 | `sched_yield()`、阻塞在 I/O/锁/sleep → 主动 `schedule()` | `do_sched_yield`（syscalls.c:1335）、`schedule_preempt_disabled`（core.c:7365）| 架构无关 |
| ④ 唤醒抢占 | 高优先级任务唤醒，`wakeup_preempt()` → 置位 → 在最近抢占点切换 | `wakeup_preempt`（core.c:2243）→ `wakeup_preempt_fair`（fair.c:9055）| EEVDF 判据；落 LAZY 位 |

四个扳机最终都汇入同一扇门：

```
 ① 返回用户态            ② 中断返回内核态        ③ 显式让出/阻塞        ④ 唤醒抢占
 exit_to_user_mode_loop  raw_irqentry_          do_sched_yield /      wakeup_preempt
 (common.c:94, :52)      exit_cond_resched      mutex阻塞 / sleep     (core.c:2243)
        │                (common.c:134)               │                     │
        │                       │                     │                     │ resched_curr(_lazy)
        │                       ▼                     │                     ▼ (core.c:1212/1238)
        │              preempt_schedule_irq           │              TIF_NEED_RESCHED(_LAZY)
        │              (core.c:7529)                  │                     │
        ▼                       ▼                     ▼                     ▼
     ┌─────────────────────────────────────────────────────────────────────┐
     │                __schedule(sched_mode)   core.c:7042                 │
     │        pick_next_task(:6106) → context_switch(:5335) → switch_to    │
     └─────────────────────────────────────────────────────────────────────┘
```

关键分离：**①②是"被动执行点"**——有人早已置好 TIF 标志，它们只负责检查并真正切换；**③④是"主动申请点"**——自己调用 `schedule()` 或替目标任务置标志。置标志与执行切换分离（`resched_curr` 只落笔，[010 §4.3](./010.时钟中断到调度执行完整路径.md)）。

## 2. 时机①：返回用户态抢占

arm64 有两个入口汇到同一个判决点——系统调用返回与中断返回：

```c
// arch/arm64/kernel/entry-common.c:85 —— 系统调用返回
static __always_inline void arm64_syscall_exit_to_user_mode(struct pt_regs *regs)
{
	local_irq_disable();
	syscall_exit_to_user_mode_prepare(regs);
	local_daif_mask();          // arm64 特色：屏蔽 DAIF 再出内核
	...
	exit_to_user_mode();
}
// :100 —— 中断返回（el0_interrupt :821 的收尾）
static __always_inline void arm64_exit_to_user_mode(struct pt_regs *regs)
{
	local_irq_disable();
	irqentry_exit_to_user_mode_prepare(regs);   // include/linux/irq-entry-common.h:242
	local_daif_mask();
	...
}
```

两个入口都走进通用的 `irqentry_exit_to_user_mode_prepare` → `exit_to_user_mode_loop`（kernel/entry/common.c:94）→ `__exit_to_user_mode_loop`（:41），判决就在这三行：

```c
// kernel/entry/common.c:52-54 —— 时机①的全部
if (ti_work & (_TIF_NEED_RESCHED | _TIF_NEED_RESCHED_LAZY)) {   // ★ LAZY 在这里认账
	if (!rseq_grant_slice_extension(ti_work, TIF_SLICE_EXT_DENY))
		schedule();
}
```

- **谁置的标志**：tick 的 hrtick 让位（[010 §4](./010.时钟中断到调度执行完整路径.md)）、唤醒抢占（§5）、负载均衡搬运，全都在等这一个返回窗口；
- **rseq 宽限**：`rseq_grant_slice_extension` 拦下 NEED_RESCHED，让用户态自旋锁临界区跑完再还（[004 §2.5②](../../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/004.8.1.4-多处理器调度.md) 的逐句实现）——抢占点也讲礼貌；
- **loop 语义**：`while (ti_work & EXIT_TO_USER_MODE_WORK_LOOP)`（:48）——调度完还有 signal/uprobe 等 pending 工作就再来一圈，直到干净出厂。

## 3. 时机②：中断返回内核态抢占

tick 打断的是内核态执行（系统调用、驱动代码）时，返回走另一条门：

```c
// arch/arm64/kernel/entry-common.c:55 —— arm64 出口
static void noinstr arm64_exit_to_kernel_mode(struct pt_regs *regs, ...)
{
	irqentry_exit_to_kernel_mode_preempt(regs, state);       // :59
	irqentry_exit_to_kernel_mode_after_preempt(regs, state); // :62
}
// kernel/entry/common.c:134 —— 判决（经 irqentry_exit :159 到达）
void raw_irqentry_exit_cond_resched(void)
{
	if (!preempt_count()) {                          // :136 ★ 持锁/硬中断/软中断计数必须为 0
		rcu_irq_exit_check_preempt();
		if (need_resched() && arch_irqentry_exit_need_resched())
			preempt_schedule_irq();                  // :142
	}
}
```

```c
// kernel/sched/core.c:7529 —— 真正的内核态抢占
asmlinkage __visible void __sched preempt_schedule_irq(void)
{
	BUG_ON(preempt_count() || !irqs_disabled());
	...
	do {
		preempt_disable();
		local_irq_enable();              // 开中断进 schedule（窗口内可能又来中断）
		__schedule(SM_PREEMPT);
		local_irq_disable();
		sched_preempt_enable_no_resched();
	} while (need_resched());            // 切完再看一眼：又有人排队？继续切
}
```

三个要点：
- **`preempt_count()` 是唯一闸门**（:136）：`preempt_disable()`（自旋锁内建，[004 §2.5①](../../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/004.8.1.4-多处理器调度.md)）、硬中断帧（`irq_enter_rcu`）、软中断帧各自计数——任何一个非零，内核态抢占免谈。这就是"持自旋锁的线程不会被调走"的执行现场；
- **配置矩阵**：`CONFIG_PREEMPT_DYNAMIC` 下判决经 static call 可在线切换（DEFINE_STATIC_CALL，common.c:147；`dynamic_irqentry_exit_cond_resched` :150）——`/sys/kernel/debug/sched/preempt` 一改 none/voluntary/full 不用重编内核；voluntary 模式的 `__cond_resched()`（core.c:7722，动态版 :7762）仍在长循环里当"人肉抢占点"；
- **arm64 无特化**：`arch_irqentry_exit_need_resched()` 钩子在本树 x86/arm64 都用默认实现（common.c:129-133，恒真）——这条路径的架构差异只在"如何到达 `irqentry_exit`"（arm64 走 EL 向量，x86 走 idtentry）。

## 4. 时机③：显式让出与阻塞

任务自己走进 `schedule()`，与 TIF 标志无关。三类代表：

- **让出**：`sched_yield()` → `do_sched_yield()`（kernel/sched/syscalls.c:1335，系统调用 :1360）——注释自带劝退："99% 的用法都是错的"；
- **阻塞**：拿不到锁/等 I/O——如 mutex：`__mutex_lock` → `schedule_preempt_disabled()`（kernel/sched/core.c:7365，调用点 kernel/locking/mutex.c:543/726）——**关抢占后入眠，醒来才恢复**，防止睡一半被抢占打的账目错乱；
- **睡眠**：`hrtimer_nanosleep` → `do_nanosleep` → `schedule()`（kernel/time/hrtimer.c:2293）；`wait_event` 家族同型。

这一类没有 arm64 特化（纯调度层），但有两处"债"的呼应：解锁路径 `preempt_enable()` 发现 `TIF_NEED_RESCHED` 被置位会立即 `__preempt_schedule()` 还债（[004 §2.5①](../../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/004.8.1.4-多处理器调度.md)）；切换落地的换血（fpsimd/tls/ptrauth…）仍走 arm64 `__switch_to`/`cpu_switch_to`（[010 §6](./010.时钟中断到调度执行完整路径.md)）。

## 5. 时机④：唤醒抢占

高优先级/更紧急任务醒来的瞬间，把"current 该让位"的判断做掉——**这是唯一不发生在"返回路上"的置标志点**：

```c
// kernel/sched/core.c:3726 —— try_to_wake_up → ttwu_do_activate
	activate_task(rq, p, en_flags);
	wakeup_preempt(rq, p, wake_flags);      // ★ 入队即审判
// :3782 —— 目标任务"在队上但没在跑"（已被抢占过）也补一刀
	wakeup_preempt(rq, p, wake_flags);

// kernel/sched/core.c:2243 —— 类间分诊（proxy exec 语义：donor 是"该被比下去的"）
void wakeup_preempt(struct rq *rq, struct task_struct *p, int flags)
{
	struct task_struct *donor = rq->donor;
	if (p->sched_class == rq->next_class) {
		rq->next_class->wakeup_preempt(rq, p, flags);      // 同类：类内判决
	} else if (sched_class_above(p->sched_class, rq->next_class)) {
		rq->next_class->wakeup_preempt(rq, p, flags);
		resched_curr(rq);                                  // 更高类：直接真位
		rq->next_class = p->sched_class;
	}
```

fair 类的类内判决（`wakeup_preempt_fair`，fair.c:9055）是 EEVDF 的价值观：

1. **idle 实体让位**：current 是 idle 实体而唤醒者不是 → 无视 slice 保护，直接 `PREEMPT_WAKEUP_SHORT`；
2. **BATCH/IDLE 策略不抢人**（`normal_policy` 检查）；
3. **PREEMPT_SHORT**：唤醒者 slice 更短且 eligible → 缩短 current 的保护；
4. **终审**：`pick: nse = pick_next_entity(...); if (nse == pse) goto preempt;`——让 EEVDF 树自己说话：唤醒者成了"最合格者"就抢；
5. **落笔是懒位**：`preempt: resched_curr_lazy(rq)`——见 §6。

**跨 CPU 的"最近抢占点"由 IPI 送货上门**：唤醒的 CPU 往往不是 current 所在 CPU，`__resched_curr`（core.c:1200）发现 `cpu != smp_processor_id()` 就 `smp_send_reschedule(cpu)`——arm64 落地是 GIC SGI：

```c
// arch/arm64/kernel/smp.c:1151
void arch_smp_send_reschedule(int cpu)
{
	smp_cross_call(cpumask_of(cpu), IPI_RESCHEDULE);   // :1153 —— SGI 打到对方
}
```

对方 CPU 在自己的 IPI 入口（`IPI_RESCHEDULE` 处理，smp.c:966）收到后并不当场切换——只是确认 TIF 已置，**真正的切换仍发生在它下一次经过时机①/②的门时**。若对方在 idle 轮询（`set_nr_and_not_polling` 探测），连 IPI 都省掉（`trace_sched_wake_idle_without_ipi`，core.c:1201 一带）——轮询者本来就要出 idle，标志已经够用。

## 6. 懒抢占：横跨四个时机的第五维度

7.x 的 `PREEMPT_LAZY` 给四个时机加了一个新 bit——**`TIF_NEED_RESCHED_LAZY`**（arm64 上就是 thread_info 的 bit 2，arch/arm64/include/asm/thread_info.h:65，掩码 :94）：

| 动作 | 用哪个位 | 代码 |
|-|-|-|
| 唤醒抢占落笔 | **LAZY** | `resched_curr_lazy`（core.c:1238 → `get_lazy_tif_bit` :1230）|
| tick 再按一遍 | **LAZY** | `dynamic_preempt_lazy() && TIF_NEED_RESCHED_LAZY → resched_curr`（core.c:5666，[010 §4](./010.时钟中断到调度执行完整路径.md)）|
| idle 被点名 | 强制升级 LAZY→NEED | `__resched_curr`（core.c:1181，"idle 没得懒"）|
| 时机① 用户态返回 | **认 LAZY** | `:52` 的 `(_TIF_NEED_RESCHED | _TIF_NEED_RESCHED_LAZY)` |
| 时机② 内核态抢占 | **只认 NEED** | `need_resched()`（include/linux/sched.h:2288）= `tif_need_resched()`，不含 LAZY |

翻译成人话：**LAZY = "想切，但不值得打断"**——它允许 current 跑完用户态时间片的自然边界（下一次系统调用/中断返回），却不允许它在内核态赖着（内核态该切还得真位 NEED）。这把"吞吐优先"与"延迟优先"从编译期配置（PREEMPT_NONE…PREEMPT）变成可以逐事件表达的运行期语义；rseq 时间片延长（`TIF_SLICE_EXT_SCHED`，common.c:35-37）正是挂在这套位上的最后一层宽限。

## 7. 平台注记：同一矩阵在三台机器上

| 环节 | Arm AGI CPU（主实例） | EPYC 9996（x86 对照） |
|-|-|-|
| ①② 的入口形状 | EL 向量（entry-common.c:529/:843）→ 通用 entry 层 | idtentry 框架 → 同一通用 entry 层 |
| 跨 CPU 唤醒 IPI | GIC SGI（`IPI_RESCHEDULE`，smp.c:1153）| APIC 的 RESCHEDULE vector（同样的"叫醒不开会"语义）|
| IPI 成本 | 136 核单层 mesh，跨 chiplet 唤醒多几跳 | 512 线程跨 CCD/IOD，IPI 跨 die 更贵——唤醒抢占的"就近"更值钱（[004 §2.10](../../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/004.8.1.4-多处理器调度.md)）|
| 内核态抢占判决 | 架构无关（`preempt_count` 闸门，无 arch 覆写）| 同左 |
| 时钟中断触发 | 见 [010 §7](./010.时钟中断到调度执行完整路径.md) 平台注记 | 同左 |

一句话：**四个时机全部长在通用 entry/sched 层，架构只提供"到达方式"**——arm64 的 EL 向量与 GIC SGI、x86 的 idtentry 与 APIC vector，在 `exit_to_user_mode_loop`/`irqentry_exit` 处汇成同一段 C 代码。

## 附录：A725 + A520 异构机型的抢占侧差异

抢占**判决**（谁该让位给谁）架构无关、异构无关——`wakeup_preempt_fair` 里没有一行看 capacity。异构改变的是抢占判决的**上下文**：

- 唤醒路径的选核先于抢占判决：`asym_fits_cpu`/`select_idle_capacity` 决定任务被唤醒到哪颗核（[004 §2.10.4/附录 A](../../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/004.8.1.4-多处理器调度.md)）——"抢谁"发生在选定的目标 rq 上；
- misfit 任务"困在小核"不是唤醒抢占解决的——它是 tick 巡检（`update_misfit_status`，fair.c:13703）+ 负载均衡强搬（`migrate_misfit`），见 [010 附录](./010.时钟中断到调度执行完整路径.md)；
- 教学模型（cap=1024/252、PD/EM）见 [005.绿色节能调度器 · 附录 B](./005.绿色节能调度器/README.md)。

## 小结

- **置位与执行分离**：③④（有时②的软中断变体）负责"申请"，①②负责"兑现"；`resched_curr` 只写标志，`__schedule` 只在返回窗口开火——中间隔着一次中断返回的距离；
- **`preempt_count()` 是内核态的唯一闸门**：自旋锁/硬中断/软中断三层计数，清零才放行——[004 §2.5](../../025.MULTIPLE_PROCESSOR_SYSTEM/002.多处理器理论/004.8.1.4-多处理器调度.md) 的"持锁不被抢占"在此具象化；
- **LAZY 位把抢占分了级**：唤醒/tick 先落懒位（用户态自然边界兑现），idle 与真紧急（更高调度类）直接真位——四个时机由此从"配置决定一切"走向"逐事件分级"；
- **唤醒抢占的判决权在 EEVDF**：idle 实体让位、PREEMPT_SHORT、`pick_next_entity` 终审——"更紧急"不再看 vruntime 排队，而是看虚拟截止期与 eligibility。
