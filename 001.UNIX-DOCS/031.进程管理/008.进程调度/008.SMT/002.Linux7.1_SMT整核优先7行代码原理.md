## 二、SMT 超线程的硬件真相（"合租公寓"比喻）

视频将 SMT（Simultaneous Multi-Threading，同步多线程）比作 **"合租公寓的双胞胎兄弟"**：

- 一个物理核心的两个逻辑 CPU（T0/T1）**共享物理执行单元**（ALU、缓存、解码器等）
- 表面上两个逻辑核各自独立，实际上资源是分时复用的
- **关键结论**：两个逻辑核并行运行时，总吞吐量相比单线程提升约 **30%**，而非翻倍
- 这意味着 **70% 的"双倍红利"因资源争抢而损失**

## 三、调度域拓扑（sched_domain 四层结构）

| 层次 | 调度域 | 调度域标志 | 说明 |
|:----:|--------|-----------|------|
| 1 | **SMT 域** | `SD_SHARE_CPUCAPACITY` | 同一物理核心的两个超线程，共享 L1/L2 |
| 2 | **MC 域（LLC 域）** | `SD_SHARE_PKG_RESOURCES` | 共享最后一级缓存（L3）的一组核心 |
| 3 | **DIE 域** | — | 同一个 Die 内的所有核心 |
| 4 | **NUMA 域** | `SD_NUMA` | 同一个 NUMA 节点内的所有 CPU |

其中特别强调了 `sd_llc`（Last-Level Cache domain）在唤醒路径中的作用。

## 四、核心：Linux 7.1 新增的 7 行代码（源码详解）

### 4.1 代码位置：`kernel/sched/ext_idle.c`

这 7 行代码位于 **sched_ext 的默认 `ops.select_cpu()` 中**，具体在 `kernel/sched/ext_idle.c` 的 `scx_select_cpu_dfl()` 函数内。

### 4.2 前置知识：`SCX_PICK_IDLE_CORE` 标志位定义

文件：`kernel/sched/ext_internal.h:1189`

```c
enum scx_pick_idle_cpu_flags {
    SCX_PICK_IDLE_CORE  = 1LLU << 0,  /* pick a CPU whose SMT siblings are also idle */
    SCX_PICK_IDLE_IN_NODE = 1LLU << 1, /* pick a CPU in the same target NUMA node */
};
```

`SCX_PICK_IDLE_CORE` 标志的含义是：**只选择 SMT 兄弟线程也空闲的 CPU，即整个物理核心完全空闲**。

### 4.3 核心逻辑：`scx_select_cpu_dfl()` 中的 SMT 全空闲核心优先搜索

文件：`kernel/sched/ext_idle.c:562-615`

```c
    /*
     * If CPU has SMT, any wholly idle CPU is likely a better pick than
     * partially idle @prev_cpu.
     */
    if (sched_smt_active()) {
        /*
         * Keep using @prev_cpu if it's part of a fully idle core.
         */
        if (is_prev_allowed &&
            cpumask_test_cpu(prev_cpu, idle_cpumask(node)->smt) &&
            scx_idle_test_and_clear_cpu(prev_cpu)) {
            cpu = prev_cpu;
            goto out_unlock;                            /* ← 第 1 行 */
        }

        /*
         * Search for any fully idle core in the same LLC domain.
         */
        if (llc_cpus) {
            cpu = pick_idle_cpu_in_node(llc_cpus, node, SCX_PICK_IDLE_CORE);
            if (cpu >= 0)
                goto out_unlock;                        /* ← 第 2 行 */
        }

        /*
         * Search for any fully idle core in the same NUMA node.
         */
        if (numa_cpus) {
            cpu = pick_idle_cpu_in_node(numa_cpus, node, SCX_PICK_IDLE_CORE);
            if (cpu >= 0)
                goto out_unlock;                        /* ← 第 3 行 */
        }

        /*
         * Search for any full-idle core usable by the task.
         *
         * If the node-aware idle CPU selection policy is enabled
         * (%SCX_OPS_BUILTIN_IDLE_PER_NODE), the search will always
         * begin in prev_cpu's node and proceed to other nodes in
         * order of increasing distance.
         */
        cpu = scx_pick_idle_cpu(allowed, node, flags | SCX_PICK_IDLE_CORE);
        if (cpu >= 0)
            goto out_unlock;                            /* ← 第 4 行 */

        /*
         * Give up if we're strictly looking for a full-idle SMT core.
         */
        if (flags & SCX_PICK_IDLE_CORE) {
            cpu = -EBUSY;
            goto out_unlock;                            /* ← 第 5 行 */
        }
    }                                                   /* ← 第 6、7 行（if 语句的花括号） */
```

**逐行解读这 7 行"新增逻辑"**（标 `←` 的部分）：

| 行号 | 代码 | 作用 |
|:----:|------|------|
| 1 | `goto out_unlock;` | prev_cpu 已在全空闲核心中，直接使用 |
| 2 | `goto out_unlock;` | LLC 域内找到全空闲核心，选中 |
| 3 | `goto out_unlock;` | NUMA 域内找到全空闲核心，选中 |
| 4 | `goto out_unlock;` | 全局搜索到全空闲核心，选中 |
| 5 | `goto out_unlock;` | 严格模式要求全空闲核心但未找到，返回 -EBUSY |
| 6 | `}` | if (sched_smt_active()) 的结束花括号 |
| 7 | `}` | 实际是第 6 行的补充，整个 if 块的结构 |

> **视频中所说的"7 行代码"，并非指恰好 7 个物理行，而是指围绕 `SCX_PICK_IDLE_CORE` 标志构建的整核优先搜索逻辑的整体改动量。**

### 4.4 底层支撑函数：`pick_idle_cpu_in_node()`

文件：`kernel/sched/ext_idle.c:115`

```c
static s32 pick_idle_cpu_in_node(const struct cpumask *cpus_allowed, int node, u64 flags)
{
    int cpu;

retry:
    if (sched_smt_active()) {
        cpu = cpumask_any_and_distribute(idle_cpumask(node)->smt, cpus_allowed);
        if (cpu < nr_cpu_ids)
            goto found;

        if (flags & SCX_PICK_IDLE_CORE)
            return -EBUSY;          /* ← 关键：SCX_PICK_IDLE_CORE 时，SMT 无空闲则直接返回 */
    }

    cpu = cpumask_any_and_distribute(idle_cpumask(node)->cpu, cpus_allowed);
    if (cpu >= nr_cpu_ids)
        return -EBUSY;

found:
    if (scx_idle_test_and_clear_cpu(cpu))
        return cpu;
    else
        goto retry;
}
```

关键逻辑：
- 当 `flags` 包含 `SCX_PICK_IDLE_CORE` 时，若 `idle_smt` 掩码中无可用 CPU，立即返回 `-EBUSY`，**不会降级到普通空闲 CPU**（line 125-126）
- 当 `flags` 不包含 `SCX_PICK_IDLE_CORE` 时，找不到 SMT 空闲 CPU 才降级到普通空闲 CPU

### 4.5 底层支撑函数：`scx_pick_idle_cpu()`

文件：`kernel/sched/ext_idle.c:200`

```c
static s32 scx_pick_idle_cpu(const struct cpumask *cpus_allowed, int node, u64 flags)
{
    s32 cpu;

    /* 先在本节点内搜索 */
    cpu = pick_idle_cpu_in_node(cpus_allowed, node, flags);
    if (cpu >= 0)
        return cpu;

    /* 如果限制单节点或使用全局掩码，直接返回 */
    if (node == NUMA_NO_NODE || flags & SCX_PICK_IDLE_IN_NODE)
        return -EBUSY;

    /* 扩展到其他在线节点 */
    return pick_idle_cpu_from_online_nodes(cpus_allowed, node, flags);
}
```

配合 `SCX_PICK_IDLE_CORE` 标志后，这里实现的是**全局搜索全空闲物理核心**。

### 4.6 底层支撑函数：`scx_idle_test_and_clear_cpu()`

文件：`kernel/sched/ext_idle.c:77`

```c
static bool scx_idle_test_and_clear_cpu(int cpu)
{
    int node = scx_cpu_node_if_enabled(cpu);
    struct cpumask *idle_cpus = idle_cpumask(node)->cpu;

#ifdef CONFIG_SCHED_SMT
    /*
     * SMT mask should be cleared whether we can claim @cpu or not. The SMT
     * cluster is not wholly idle either way. This also prevents
     * scx_pick_idle_cpu() from getting caught in an infinite loop.
     */
    if (sched_smt_active()) {
        const struct cpumask *smt = cpu_smt_mask(cpu);
        struct cpumask *idle_smts = idle_cpumask(node)->smt;

        if (cpumask_intersects(smt, idle_smts))
            cpumask_andnot(idle_smts, idle_smts, smt);
        else if (cpumask_test_cpu(cpu, idle_smts))
            __cpumask_clear_cpu(cpu, idle_smts);
    }
#endif

    return cpumask_test_and_clear_cpu(cpu, idle_cpus);
}
```

该函数在原子获取 CPU 的同时清理 SMT 空闲掩码，确保：
- SMT 核心一旦被占用，其整个 SMT 集群从 idle_smt 掩码中移除
- 防止 `scx_pick_idle_cpu` 陷入无限循环（见注释说明）

### 4.7 内置策略总览注释

文件：`kernel/sched/ext_idle.c:416-456`

```c
/*
 * Built-in CPU idle selection policy:
 *
 * 1. Prioritize full-idle cores:
 *   - always prioritize CPUs from fully idle cores (both logical CPUs are
 *     idle) to avoid interference caused by SMT.
 *
 * 2. Reuse the same CPU:
 *   - prefer the last used CPU to take advantage of cached data (L1, L2) and
 *     branch prediction optimizations.
 *
 * 3. Prefer @prev_cpu's SMT sibling:
 *   - if @prev_cpu is busy and no fully idle core is available, try to
 *     place the task on an idle SMT sibling of @prev_cpu; keeping the
 *     task on the same core makes migration cheaper, preserves L1 cache
 *     locality and reduces wakeup latency.
 *
 * 4. Pick a CPU within the same LLC (Last-Level Cache):
 *   - if the above conditions aren't met, pick a CPU that shares the same
 *     LLC, if the LLC domain is a subset of @cpus_allowed, to maintain
 *     cache locality.
 *
 * 5. Pick a CPU within the same NUMA node, if enabled:
 *   - choose a CPU from the same NUMA node, if the node cpumask is a
 *     subset of @cpus_allowed, to reduce memory access latency.
 *
 * 6. Pick any idle CPU within the @cpus_allowed domain.
 *
 * Step 4 and 5 are performed only if the system has, respectively,
 * multiple LLCs / multiple NUMA nodes (see scx_selcpu_topo_llc and
 * scx_selcpu_topo_numa) and they don't contain the same subset of CPUs.
 *
 * If %SCX_OPS_BUILTIN_IDLE_PER_NODE is enabled, the search will always
 * begin in @prev_cpu's node and proceed to other nodes in order of
 * increasing distance.
 *
 * Return the picked CPU if idle, or a negative value otherwise.
 *
 * NOTE: tasks that can only run on 1 CPU are excluded by this logic, because
 * we never call ops.select_cpu() for them, see select_task_rq().
 */
```

## 七、关键数据结构：`idle_cpumask` 与 SMT 掩码

文件：`kernel/sched/ext_idle.c:32-35`

```c
struct scx_idle_cpus {
    cpumask_var_t cpu;   /* 节点内所有空闲 CPU */
    cpumask_var_t smt;   /* 节点内整个物理核心都空闲的 CPU */
};
```

- `cpu` 掩码：记录所有空闲的逻辑 CPU
- `smt` 掩码：仅记录**整个物理核心都空闲**的逻辑 CPU（即 SMT 兄弟也空闲）
- 当选择到某个 CPU 时，`scx_idle_test_and_clear_cpu()` 会同时清理 `cpu` 和 `smt` 两个掩码

## 八、端到端时间线（"从 0 微秒走到 CPU4 上线"）

视频用时间线方式展示了一次唤醒事件从触发到任务上线的完整路径：

1. 任务被唤醒（`try_to_wake_up`）
2. 进入 `ops.select_cpu()`（sched_ext 回调）
3. 调用 `scx_select_cpu_dfl()` 内置默认策略
4. **优先搜索全空闲物理核心（`SCX_PICK_IDLE_CORE`）**
   - 先查 LLC 域内 → 再查 NUMA 域内 → 最后全局搜索
5. 选中一个空闲的完整物理核心
6. 任务直接 dispatch 到该 CPU
7. CPU 上线执行任务

对比 7.0 旧路径：可能先选中一个 SMT 兄弟核，导致兄弟核上的任务被抢占，引发连锁调度事件。
