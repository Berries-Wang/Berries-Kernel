# LLC 域与 CPU 调度拓扑

> 关联文件：`kernel/sched/ext_idle.c`  
> 监听内核版本：Linux 7.1.3 (sched_ext)

## 一、概述

LLC（Last-Level Cache，最后一级缓存）域是 Linux 内核调度域（sched_domain）层次结构中的关键一层。在 sched_ext 空闲 CPU 选择策略中，LLC 域用于指导任务优先在共享最后一级缓存的 CPU 范围内迁移，以最大化缓存命中率。

---

## 二、LLC 域在调度域层次中的位置

Linux 内核的调度域从底层到顶层通常为：

| 层次 | 内核调度域 | 调度域标志 | 对应物理结构 |
|:----:|-----------|-----------|-------------|
| 1 | **SMT 域** | `SD_SHARE_CPUCAPACITY` | 同一个物理核心的多个超线程（SMT 兄弟），共享 L1/L2 缓存 |
| **2** | **MC 域 / LLC 域** | `SD_SHARE_PKG_RESOURCES` | **共享最后一级缓存（LLC）的一组 CPU 核心** |
| 3 | DIE 域 | （非 NUMA 层） | 同一个 Die 内的所有核心 |
| 4 | NUMA 域 | `SD_NUMA` | 同一个 NUMA 节点内的所有 CPU，共享内存控制器 |

**LLC 域对应的是第 2 层——MC 域（Multi-Core Domain）**，即共享同一片 LLC（通常是 L3 Cache）的一组 CPU 核心。

### 各层级说明

| 层级 | 共享资源 | 迁移代价 | 说明 |
|------|---------|---------|------|
| **SMT 域** | L1 指令/数据缓存、L2 缓存 | 极低（微秒级） | 同一物理核心的 T0/T1 超线程，切换几乎无开销 |
| **LLC 域** | L3 缓存（最后一级缓存） | 低（毫秒级） | 核心间迁移时 L3 数据仍有效，但 L1/L2 需重新填充 |
| **NUMA 域** | 内存控制器、本地内存 | 中（毫秒级 + 内存延迟） | 跨 NUMA 节点访问远端内存，延迟显著增加 |
| **跨 NUMA** | 无共享资源 | 高 | 远端内存访问 + 缓存全部失效 |

## 四、代码中的 LLC 域相关函数

### 4.1 获取 LLC 域信息

```c
/* 返回 LLC 域内的 CPU 数量（line 231） */
static unsigned int llc_weight(s32 cpu)
{
    struct sched_domain *sd;

    sd = rcu_dereference(per_cpu(sd_llc, cpu));
    if (!sd)
        return 0;

    return sd->span_weight;
}

/* 返回 LLC 域的 cpumask（line 246） */
static struct cpumask *llc_span(s32 cpu)
{
    struct sched_domain *sd;

    sd = rcu_dereference(per_cpu(sd_llc, cpu));
    if (!sd)
        return NULL;

    return sched_domain_span(sd);
}
```

### 4.2 LLC 与 NUMA 域不重叠检测

```c
/* 判断 LLC 域与 NUMA 域是否不完全重叠（line 299） */
static bool llc_numa_mismatch(void)
{
    int cpu;

    for_each_online_cpu(cpu)
        if (llc_weight(cpu) != numa_weight(cpu))
            return true;

    return false;
}
```

当 LLC 域与 NUMA 域完全重叠时（即一个 NUMA 节点只有一个 LLC 域），启用 NUMA 优化是冗余的，因为 LLC 搜索已经覆盖了相同范围。`scx_idle_update_selcpu_topology` 利用此判断条件决定是否启用 NUMA 感知优化。

### 4.3 LLC 域在空闲 CPU 搜索中的使用

在 `scx_select_cpu_dfl` 中，LLC 域用于限制搜索范围（line 512-519）：

```c
if (static_branch_maybe(CONFIG_SCHED_MC, &scx_selcpu_topo_llc)) {
    struct cpumask *local_cpus = this_cpu_cpumask_var_ptr(local_llc_idle_cpumask);
    const struct cpumask *cpus = llc_span(prev_cpu);

    if (allowed == p->cpus_ptr && task_affinity_all(p))
        llc_cpus = cpus;
    else if (cpus && cpumask_and(local_cpus, allowed, cpus))
        llc_cpus = local_cpus;
}
```

## 五、LLC 域在 sched_ext 空闲 CPU 选择策略中的作用

### 5.1 搜索优先级中的位置

在 `scx_select_cpu_dfl` 的 10 级策略中，LLC 域搜索出现在两个关键位置：

| 优先级 | 步骤 | 搜索范围 | 目的 |
|:------:|------|---------|------|
| 3 | LLC 域内空闲 SMT 核心 | `pick_idle_cpu_in_node(llc_cpus, node, SCX_PICK_IDLE_CORE)` | 优先在 LLC 域内找全空闲物理核心 |
| 5 | LLC 域内任意空闲 CPU | `pick_idle_cpu_in_node(llc_cpus, node, 0)` | LLC 域内任意空闲 CPU |

### 5.2 为什么 LLC 域搜索优先于 NUMA 域搜索

1. **缓存局部性**：同一 LLC 域内的核心共享 L3 缓存，任务迁移后部分数据仍在缓存中，miss 率远低于跨 LLC 迁移
2. **延迟更低**：LLC 域内的核心间通信延迟远低于跨 NUMA 节点
3. **带宽更优**：避免跨 NUMA 的内存带宽争抢

### 5.3 拓扑感知的按需启用

```c
void scx_idle_update_selcpu_topology(struct sched_ext_ops *ops)  // line 344
```

- **仅在有多个 LLC 域时**启用 LLC 优化（`scx_selcpu_topo_llc`）
- 如果所有在线 CPU 都属于同一个 LLC 域，则 LLC 优化无意义，跳过
- 判断方式：检查第一个在线 CPU 的 `llc_weight` 是否小于 `num_online_cpus()`

## 六、LLC 域与 SMT、NUMA 的关系总结

```
                    ┌───────────────────────────────┐
                    │          NUMA 节点             │
                    │  （跨节点：远端内存访问）        │
                    └───────────┬───────────────────┘
                                │
                    ┌───────────▼───────────────────┐
                    │        LLC 域（MC 域）          │
                    │  （跨核心：L3 仍共享，L1/L2 失效）│
                    └───────────┬───────────────────┘
                                │
                    ┌───────────▼───────────────────┐
                    │        SMT 域（物理核心）        │
                    │  （跨线程：L1/L2/L3 全部共享）   │
                    └───────────┬───────────────────┘
                                │
                    ┌───────────▼───────────────────┐
                    │        逻辑 CPU (T0/T1)        │
                    │  （同一核心上的超线程）          │
                    └───────────────────────────────┘
```

| 迁移范围 | 缓存影响 | 调度域 | sched_ext 搜索策略 |
|---------|---------|--------|-------------------|
| 同一 SMT 域内 T0↔T1 | 无影响（全部共享） | SMT 域 | 优先使用 prev_cpu 的 SMT 兄弟 |
| 同一 LLC 域内跨核心 | L3 命中，L1/L2 失效 | MC 域 | 步骤 3、5（LLC 域内搜索） |
| 同一 NUMA 域内跨 LLC | L3 失效，本地内存 | NUMA 域 | 步骤 4、6（NUMA 域内搜索） |
| 跨 NUMA 节点 | 全部失效 + 远端内存 | 跨 NUMA | 步骤 7（全局搜索，最终 fallback） |
