# scx_pick_idle_cpu 调用链路分析

> 文件位置：`kernel/sched/ext_idle.c`  
> 内核版本：Linux 7.1.3 (sched_ext)

## 摘要
在给进程选择CPU的时候，优先选择整空核(SMT都空闲)，为什么？
- 因为SMT（超线程）其实还是一个物理核心，共享ALU等计算单元，同时干活存在资源争抢问题，所以挑选CPU的真正考虑的地方，不在于迁移代价，而在于指定单元的争抢；
- 使用场景： CPU密集型：中等负载（30% ~ 70%）。
  + 满载时，整核扫描必定失败（选择整空核失败），回退到LLC扫描；
  + 空载，所有CPU都空闲，无差别；
  + 关闭SMT，整段逻辑跳过，无影响；
- 收益： 2% ~ %3收益

## 一、函数概要

```c
static s32 scx_pick_idle_cpu(const struct cpumask *cpus_allowed, int node, u64 flags);
```

`scx_pick_idle_cpu` 是 sched_ext 内置空闲 CPU 选择策略的核心枢纽，位于 `kernel/sched/ext_idle.c`。它负责在给定的 `cpus_allowed` 限制下，从系统的空闲 CPU 中选取一个合适的 CPU，并原子地将其标记为忙碌。

搜索分两阶段进行：

1. **Phase 1** — 先在 `@node` 内搜索（`pick_idle_cpu_in_node`）
2. **Phase 2** — 若失败且未限制单节点，按 NUMA 距离递增扩展到其他在线节点（`pick_idle_cpu_from_online_nodes`）

### 关键辅助函数说明

| 函数 | 行号 | 作用 |
|------|------|------|
| `pick_idle_cpu_in_node` | 115 | 在单个 NUMA 节点内搜索空闲 CPU，优先 SMT 空闲，原子获取并带重试 |
| `pick_idle_cpu_from_online_nodes` | 150 | 跨所有在线节点按 NUMA 距离递增搜索，O(N²) 复杂度 |
| `scx_idle_test_and_clear_cpu` | 77 | 原子获取空闲 CPU，同时清理 SMT 空闲掩码，防止无限循环 |
| `idle_cpumask(node)` | 60 | 返回目标节点（或全局）的空闲 CPU 掩码 |
| `scx_cpu_node_if_enabled` | 69 | 返回 CPU 的 NUMA 节点 ID（若 per-node 跟踪未启用则返回 NUMA_NO_NODE） |

## 五、关键设计要点

### 1. 两阶段搜索
`scx_pick_idle_cpu` 先搜索本节点，失败后才跨节点——目的是最大化 cache locality，优先选择内存访问延迟最低的 CPU。

### 2. SMT 全空闲核心优先
`scx_select_cpu_dfl` 中先调用 `scx_pick_idle_cpu(..., flags | SCX_PICK_IDLE_CORE)` 搜索完全空闲的物理核心，**只有找不到时才降级到非 SMT 空闲的普通 CPU**。这是为了减少 SMT 兄弟线程之间的资源争抢。

### 3. 三层拓扑优先搜索
`scx_select_cpu_dfl` 在调用 `scx_pick_idle_cpu` 之前，会先尝试更小范围的精确搜索，逐层扩大范围：

| 范围 | 搜索方式 | 目的 |
|------|----------|------|
| LLC 域 | 直接调 `pick_idle_cpu_in_node(llc_cpus, ...)` | 共享最后一级缓存，减少缓存 miss |
| NUMA 域 | 直接调 `pick_idle_cpu_in_node(numa_cpus, ...)` | 同节点内存访问延迟最低 |
| 全局 | `scx_pick_idle_cpu(...)` | 最终 fallback |

### 4. 原子获取 + 重试机制
`pick_idle_cpu_in_node` 找到候选 CPU 后调用 `scx_idle_test_and_clear_cpu` 原子获取，若被其他路径抢走则 `goto retry` 重试。同时 SMT 掩码无条件清理，防止 `scx_pick_idle_cpu` 陷入无限循环（见 `scx_idle_test_and_clear_cpu` 的注释说明）。

### 5. 拓扑感知的按需启用
`scx_idle_update_selcpu_topology` (line 344) 在系统初始化时检测 LLC 和 NUMA 拓扑：

- **仅在有多个 LLC 域时**启用 LLC 优化（`scx_selcpu_topo_llc`）
- **仅在有多 NUMA 节点且 LLC 与 NUMA 域不完全重叠时**启用 NUMA 优化（`scx_selcpu_topo_numa`）
- 避免冗余的拓扑检查

## 六、数据结构关系

```
scx_idle_cpus (每个 NUMA 节点或全局)
  │
  ├── cpu: cpumask_var_t    ← 节点内所有空闲 CPU
  │
  └── smt: cpumask_var_t    ← 节点内整个物理核心都空闲的 CPU
                               （SMT 兄弟都空闲，该核心上所有逻辑 CPU 都在此掩码中）

idle_cpumask(node)
  │
  ├── node == NUMA_NO_NODE → &scx_idle_global_masks   (全局掩码)
  │
  └── node != NUMA_NO_NODE → &scx_idle_node_masks[node] (per-node 掩码)
```

> 当 `SCX_OPS_BUILTIN_IDLE_PER_NODE` 未启用时，使用全局掩码，`node` 始终为 `NUMA_NO_NODE`，跨节点扩展搜索不会发生。
