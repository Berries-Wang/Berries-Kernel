# pgd_set_fixmap 做了什么（fixmap 机制全解）

> **定位**：本篇是对旧笔记（5.9 宏展开那份"谜面"）的正式作答，也是 arm64 **fixmap（固定映射）机制**的完整走读。主基准 [003.LINUX-7.1.3](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3)，全部 `file:line` 实测；5.9 对照见文末表格（5.9 树 `arch/arm64/mm/mmu.c:1062~1089` 附近已有本仓库批注）。启动大图见 [002.内核启动流程](./002.内核启动流程/README.md)。

## 0. 一句话总结

**`pgd_set_fixmap(phys)` = 把任意一页"物理页表页"临时映射到 `FIX_PGD` 这个编译期定死的虚拟地址槽位上，并返回一个可直接解引用的内核虚拟地址（含页内偏移）。**

它解决一个鸡生蛋问题：**修改页表的代码，自己也要经过页表寻址**——当要改的页表页（如 `swapper_pg_dir`）在现有映射里只读、或干脆还没有可写映射时，就借 fixmap 这扇"永远可用的临时窗口"绕进去写，写完立刻拆窗。

## 1. fixmap：编译期定虚拟地址，启动期定物理地址

arm64 的 fixmap 区钉在虚拟地址空间**顶端往下 8MB**：

```c
// arch/arm64/include/asm/memory.h:54
#define FIXADDR_TOP		(-UL(SZ_8M))
```

> **类型提醒**：`-UL(SZ_8M)` 读作"先钉成 64 位无符号，再模 2^64 取负"，分三步：
>
> **① `UL()` 是记号拼接，不是强制转换**——四层宏接力把 `UL` 后缀焊到字面量上：
>
> ```c
> SZ_8M                           // 裸字面量 0x00800000，类型 int  (sizes.h:40)
>  └─ UL(SZ_8M)                   //                                 (vdso/const.h:7)
>      └─ _UL(x)  = _AC(x, UL)    //                     (uapi/linux/const.h:25→21)
>          └─ __AC(X,Y) = (X##Y)  //                            (:20，记号拼接)
>              ⇒ 0x00800000UL     // 类型 unsigned long，arm64 上 64 位
> ```
>
> 包含链：`include/linux/const.h:4` → `include/vdso/const.h:7`（`UL` 本体）→ `include/uapi/linux/const.h:20-25`（`__AC`/`_AC`/`_UL` 拼接机器）。
>
> `UL(x)` 故意多包一层 `_UL(x)`：参数只要不挨着 `##`，替换前就会先被完全宏展开，再进拼接——所以拼出的是 `0x00800000UL`，而不是坏记号 `SZ_8MUL`。
>
> **② 负号要理解成从虚拟地址空间顶端往下量**——模 2^64 减法，值是个很大的正数，**不是负数**：
>
> ```c
> -1UL       = 0xFFFFFFFFFFFFFFFF   // 顶端：最高地址 2^64 - 1
> -UL(SZ_8M) = 0xFFFFFFFFFF800000   // 顶端往下 8MB，即 fixmap 区的顶
>
> // 等价写法：0xFFFFFFFFFFFFFFFF - SZ_8M + 1 = 2^64 - 8M = ~(SZ_8M - 1)
> //   ~ 是 C 按位取反（NOT）：SZ_8M-1 = 0x7FFFFF，低 23 位全 1，取反后低 23 位
> //   全 0、高 41 位全 1；由补码恒等式 -x == ~x + 1 得 ~(SZ_8M-1) == -SZ_8M，
> //   三个等价式在此接通
> // "+1"是因为地址 0 也算一个地址：顶部这 8MB 是闭区间 [2^64-8M, 2^64-1]，
> // 共 8M 个字节，起点 = 顶 - (8M - 1)；又因 2^64 - 1 + 1 ≡ 0（回卷），
> // 起点恰好就是 -UL(SZ_8M)。
> ```
>
> **③ 它是"从顶端往下排"的锚点**：`FIXADDR_TOP - ((idx) << PAGE_SHIFT)` 正是从这个顶端起点继续向下扣减，idx 越大地址越低。
>
> **④ 为什么必须 `UL()`、不能裸写 `-SZ_8M`**：`SZ_8M` 类型是 `int`，取负后经符号扩展，本例数值恰好相同；但换成 `SZ_2G`（`0x80000000`，装不进 `int`、恰好装进 `unsigned int`）这类常量，就会先在 32 位里模 2^32 取负（值仍是 `0x80000000`），再零扩展上 64 位——高位全丢，得到一个低地址垃圾值。`UL()` 的作用就是把运算提前钉死在 64 位无符号域。
>
> 同款写法见 `memory.h:44` `-(UL(1) << va)`、`:51` `-UL(SZ_1G)`——全是"从 2^64 顶上往下量"。

区内的每个"槽位"是一个 4KB 页，槽位号就是 `enum fixed_addresses` 的枚举值——**枚举在编译期定死，虚拟地址随之定死；物理页是谁，启动后由 `__set_fixmap()` 随时换**：

```c
// arch/arm64/include/asm/fixmap.h:36（节选，完整枚举见源文件）
enum fixed_addresses {
	FIX_HOLE,                       // idx=0，恰好压住 FIXADDR_TOP 本身(保留哨兵:__set_fixmap 对它 BUG_ON，永不映射)
	FIX_FDT_END,
	FIX_FDT = FIX_FDT_END + DIV_ROUND_UP(MAX_FDT_SIZE, PAGE_SIZE) + 1,
	FIX_EARLYCON_MEM_BASE,          // 早期控制台
	FIX_TEXT_POKE0,                 // 打补丁(smpboot 后改内核文本)
	...
	__end_of_permanent_fixed_addresses,   // ← 永久槽/临时槽分界
	FIX_BTMAP_END = __end_of_permanent_fixed_addresses,
	FIX_BTMAP_BEGIN = FIX_BTMAP_END + TOTAL_FIX_BTMAPS - 1,  // early_ioremap 用
	FIX_PTE, FIX_PMD, FIX_PUD, FIX_P4D,
	FIX_PGD,                        // ← 本篇主角（fixmap.h:97）
	__end_of_fixed_addresses
};
```

槽位 → 虚拟地址的换算只有一行（**idx 越大，地址越低**，槽位从 `FIXADDR_TOP` 向下排）：

```c
// include/asm-generic/fixmap.h:21
#define __fix_to_virt(x)	(FIXADDR_TOP - ((x) << PAGE_SHIFT))
```

整个区域的空间布局：

```
 高地址                                                    idx 小
  ▲
  │ 0xFFFF...FFFF800000  ◄─ FIXADDR_TOP = -UL(SZ_8M)   (memory.h:54)
  │  ┌──────────────────────────────────────────┐
  │  │ FIX_HOLE            (idx 0)              │
  │  │ FIX_FDT_END         (idx 1)              │ 设备树 blob 窗口
  │  │ FIX_FDT             (idx 1+N+1)          │   (fixmap.c:137 fixmap_remap_fdt)
  │  │ FIX_EARLYCON_MEM_BASE  早期 console        │
  │  │ FIX_TEXT_POKE0         文本打补丁          │
  │  │ [KVM VNCR / GHES / ENTRY_TRAMP ... 可选]  │
  │  ├──────────────────────────────────────────┤
  │  │            __end_of_permanent_...         │ 永久槽到此为止
  │  │ FIX_BTMAP_END ... FIX_BTMAP_BEGIN         │ early_ioremap 的
  │  │   (7 slots × 64 页, 轮转复用)             │   临时映射池
  │  ├──────────────────────────────────────────┤
  │  │ FIX_PTE / FIX_PMD / FIX_PUD / FIX_P4D     │
  │  │ FIX_PGD              ◄── 本篇主角         │ 页表页窗口
  │  └──────────────────────────────────────────┘
  │ 0xFFFF...FFFF800000 - FIXADDR_TOT_SIZE          = FIXADDR_TOT_START (fixmap.h:105)
  ▼                                                    idx 大
 低地址
```

> 注：`7 × 64 页`是 4K 页配置的数值（`FIX_BTMAPS_SLOTS = 7`、`NR_FIX_BTMAPS = SZ_256K / PAGE_SIZE`，fixmap.h:82/83）；16K/64K 页时分别为 7×16 / 7×4 页。

> 5.9 的 `FIXADDR_TOP` 是 `PCI_IO_START - SZ_2M`（5.9 `memory.h:116`），7.1.3 改为 `-UL(SZ_8M)`；且 7.1.3 的实现从 `mmu.c` 拆出了独立文件 [arch/arm64/mm/fixmap.c](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/mm/fixmap.c)。

> **为什么钉在顶端、为什么是 8MB**：
>
> **① 选址**——5.9 挂在 `vmemmap → PCI I/O → fixmap` 依赖链末端，VA 位数/页大小一动就得跟着挪；6.4 起（Ard Biesheuvel，*"Move fixmap region above vmemmap"*，LPA2 布局重构）钉到绝对顶端，与所有邻居解耦。`2^64` 顶端是唯一不随 `VA_BITS`（36/48/52）变的编译期常量，配得上 fixmap"VA 编译期定死"的设计本意（fixmap.h:26）；且天然高位全 1，永远合法落在 TTBR1 区。演化：`PCI_IO_START - SZ_2M`（5.9）→ `VMEMMAP_START - SZ_32M`（6.3）→ `-UL(SZ_8M)`（6.4 至今）。
>
> **② 面积**——8MB 是宅基地上限、不是实际用量：实际占用 `FIXADDR_TOT_SIZE = __end_of_fixed_addresses << PAGE_SHIFT`（fixmap.h:104），从 `-8M` 往下长。大头：FDT 窗口 2MB（`MAX_FDT_SIZE = SZ_2M`，boot.h:13）+ early_ioremap 池 1.75MB（7×256K，fixmap.h:82/83）+ 常驻槽若干 + 5 个页表窗口，各页大小配置下合计 ~4-5MB 封顶，8MB 留约一倍余量给可选槽（KVM VNCR/GHES/...）增长。保险丝：`static_assert(FIXADDR_TOT_START > PCI_IO_END)`（fixmap.c:20，注释原文 *"ensure that the fixmap region does not grow down into the PCI I/O region"*）——enum 涨穿了在编译期炸，不会运行期压进 PCI I/O 区。

## 2. 三层实现链路（7.1.3）

### 2.1 入口宏：`pgd_set_fixmap`

```c
// arch/arm64/include/asm/pgtable.h:1222
#define pgd_set_fixmap(addr)	((pgd_t *)set_fixmap_offset(FIX_PGD, addr))
#define pgd_clear_fixmap()	clear_fixmap(FIX_PGD)
```

`set_fixmap_offset` 的展开就是旧笔记那份"谜面"的真身——**两句话：先建映射，再算返回地址**：

```c
// include/asm-generic/fixmap.h:74
#define __set_fixmap_offset(idx, phys, flags)				\
({									\
	unsigned long ________addr;					\
	__set_fixmap(idx, phys, flags);					\
	________addr = fix_to_virt(idx) + ((phys) & (PAGE_SIZE - 1));	\
	________addr;							\
})

// include/asm-generic/fixmap.h:82
#define set_fixmap_offset(idx, phys) \
	__set_fixmap_offset(idx, phys, FIXMAP_PAGE_NORMAL)
```

返回地址的构成（旧笔记自问自答的确认）：

```
 返回 VA = fix_to_virt(FIX_PGD)         槽位基址 = FIXADDR_TOP - FIX_PGD*4K   (:21)
         + (phys & (PAGE_SIZE - 1))     目标物理地址的页内偏移(低 12 位)      (:78)

 即:FIX_PGD 窗口页里,与目标条目偏移相同的那一格 ── 解引用它 = 访问目标物理条目
     phys 本身 = __pa_symbol(swapper_pg_dir) = 内核符号 VA - kimage_voffset
                 (memory.h:383 __kimg_to_phys / :432 __pa_symbol)
```

### 2.2 落地：`__set_fixmap` 写一张 PTE

```c
// arch/arm64/mm/fixmap.c:119
void __set_fixmap(enum fixed_addresses idx,
				       phys_addr_t phys, pgprot_t flags)
{
	unsigned long addr = __fix_to_virt(idx);
	pte_t *ptep;

	BUG_ON(idx <= FIX_HOLE || idx >= __end_of_fixed_addresses);

	ptep = fixmap_pte(addr);

	if (pgprot_val(flags)) {
		__set_pte(ptep, pfn_pte(phys >> PAGE_SHIFT, flags));
	} else {
		__pte_clear(&init_mm, addr, ptep);
		flush_tlb_kernel_range(addr, addr+PAGE_SIZE);
	}
}
```

要点：

- `__set_fixmap` **只写一张 PTE**（fixmap 槽位以 4KB 粒度），物理页通过 `pfn_pte` 填进去；`flags` 为 0 则是"拆窗"（清 PTE + 刷 TLB）——`clear_fixmap`/`pgd_clear_fixmap` 走的就是这支；
- 它写的 PTE 不在 `swapper_pg_dir` 的常规树里，而在下面这套**专用引导页表**里。

### 2.3 地基：`early_fixmap_init` 预挂三级表

fixmap 窗口自己也要能被 MMU 走到。启动早期（`setup_arch()` 内，[setup.c:289](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/setup.c)）先把 `bm_pud/bm_pmd/bm_pte` 这套 `.bss` 里静态分配的表挂进 `init_mm` 的页表：

```c
// arch/arm64/mm/fixmap.c:34（静态分配，不依赖任何分配器）
static pte_t bm_pte[NR_BM_PTE_TABLES][PTRS_PER_PTE] __page_aligned_bss;
static pmd_t bm_pmd[PTRS_PER_PMD] __page_aligned_bss __maybe_unused;
static pud_t bm_pud[PTRS_PER_PUD] __page_aligned_bss __maybe_unused;

// arch/arm64/mm/fixmap.c:104
void __init early_fixmap_init(void)
{
	unsigned long addr = FIXADDR_TOT_START;
	unsigned long end = FIXADDR_TOP;

	pgd_t *pgdp = pgd_offset_k(addr);
	p4d_t *p4dp = p4d_offset_kimg(pgdp, addr);

	early_fixmap_init_pud(p4dp, addr, end);   // 逐级挂 pud→pmd→pte 表
}
```

此后 fixmap 区任何 VA 的页表遍历都走这条"专用车道"：

```
        swapper_pg_dir (init_mm 的 PGD)
              │  pgd_offset_k(FIXADDR_TOT_START)         fixmap.c:109
              ▼
        (p4d 折叠) ──► bm_pud[]                          fixmap.c:36
              │  early_fixmap_init_pmd 挂好               fixmap.c:63
              ▼
        bm_pmd[]                                           fixmap.c:35
              │  early_fixmap_init_pte 挂好               fixmap.c:50
              ▼
        bm_pte[n][512]  ──  __set_fixmap() 只改这一层!     fixmap.c:34
              │   pte_index( fix_to_virt(FIX_PGD) )
              ▼
        PTE{ pfn=目标物理页, prot }  ──► FIX_PGD 窗口生效
```

设计动机（注释原文）：**compile-time 'special' virtual addresses——虚拟地址编译期定死（代码里可以直接 `&` 出来），物理地址启动期再定**（fixmap.h:26 起的注释块）。这在"分配器还没起来"的启动阶段尤其关键——`bm_*` 三张表是静态 `.bss`，不向 memblock/slab 要任何东西。

## 3. 正主用户：`set_swapper_pgd`——为什么要绕这一遭

7.1.3 里 `pgd_set_fixmap` 的日常调用者只剩一个：`set_swapper_pgd()`：

```c
// arch/arm64/mm/mmu.c:70
void noinstr set_swapper_pgd(pgd_t *pgdp, pgd_t pgd)
{
	pgd_t *fixmap_pgdp;

	/*
	 * Don't bother with the fixmap if swapper_pg_dir is still mapped
	 * writable in the kernel mapping.
	 */
	if (rodata_is_rw) {                 // 早期:线性映射还是可写的
		WRITE_ONCE(*pgdp, pgd);     //   → 直接写,不需要弹床
		dsb(ishst);
		isb();
		return;
	}

	spin_lock(&swapper_pgdir_lock);     // 后期:swapper 已 RO → 走 fixmap
	fixmap_pgdp = pgd_set_fixmap(__pa_symbol(pgdp));   // mmu.c:86 开窗
	WRITE_ONCE(*fixmap_pgdp, pgd);      //  经窗口写 PGD 条目
	pgd_clear_fixmap();                 //  关窗(clear_fixmap, 含 TLB flush)
	spin_unlock(&swapper_pgdir_lock);
}
```

它被 `set_pgd/set_p4d/set_pud/set_pmd` 家族在"目标恰好是 `swapper_pg_dir` 这页"时兜底触发：

```c
// arch/arm64/include/asm/pgtable.h:818
static inline bool in_swapper_pgdir(void *addr)
{
	return ((unsigned long)addr & PAGE_MASK) ==
	        ((unsigned long)swapper_pg_dir & PAGE_MASK);
}

// arch/arm64/include/asm/pgtable.h:1099（set_pgd，其余层级同型：828/893/974）
static inline void set_pgd(pgd_t *pgdp, pgd_t pgd)
{
	if (in_swapper_pgdir(pgdp)) {
		set_swapper_pgd(pgdp, __pgd(pgd_val(pgd)));
		return;
	}
	...
}
```

时序全景（谁在何时改 `swapper_pg_dir`？——vmalloc/vmemmap 等内核页表同步）：

```
 [启动早期]                                [mark_rodata_ro() 之后]
   rodata_is_rw == true                     rodata_is_rw == false
        │                                        │
        ▼                                        ▼
  set_pgd(swapper 目标)                    set_pgd(swapper 目标)
        │                                        │
        └─► 直接 *pgdp = pgd                     └─► set_swapper_pgd()
                                                    (mmu.c:70)
        swapper_pg_dir 物理页在线性                 │
        映射里仍可写,无需弹床              ┌─────────┴──────────┐
                                          │ ① pgd_set_fixmap    │ 开窗
                                          │   FIX_PGD ◄─ phys   │
                                          │ ② *fixmap_pgdp=pgd  │ 写
                                          │ ③ pgd_clear_fixmap  │ 关窗
                                          └────────────────────┘
                                          swapper 已 RO:线性映射写
                                          会触发写保护异常,只能借窗
```

一句话：**`rodata` 保护把 `swapper_pg_dir` 的常规映射改成只读后，内核仍需动态改它（vmalloc/vmemmap 扩页表），于是每次都"借 FIX_PGD 窗口写一下、马上拆"**——窗口本身走的是 `bm_pte` 专用车道，不受 swapper RO 影响。

## 4. 旧笔记谜面逐块作答（5.9 宏展开）

旧笔记困惑的是 5.9 `paging_init()` 里的 `pgd_t *pgdp = pgd_set_fixmap(__pa_symbol(swapper_pg_dir));`（5.9 `mmu.c:1089`）展开后的一大坨。拆开只有四块：

| 谜面片段 | 真身 | 出处 |
| - | - | - |
| `__asm__("" : "=r"(__ptr) : "0"(x)); __ptr + 0` | `RELOC_HIDE(x, 0)`——强制进寄存器、阻止编译器做"符号地址假设"优化的障眼法 | 7.1.3 `memory.h:432` 同款 |
| `(__pa_symbol 部分) - kimage_voffset` | `__kimg_to_phys`：内核映像 VA → PA（KASLR 使两者差值运行期才定） | `memory.h:383` |

| `fix_to_virt(FIX_PGD) + (phys & 0xFFF)` | 算返回地址 = 槽位基址 + 页内偏移 | `asm-generic/fixmap.h:78` |

那坨 pgprot 的每一位（5.9 `pgtable-prot.h`：`PROT_DEFAULT`:45 / `PTE_MAYBE_NG`:32 / `PTE_WRITE`:16 / `PROT_NORMAL`:52 / `PAGE_KERNEL`:61，即 `PAGE_KERNEL = __pgprot(PROT_NORMAL)`）：

| 位 | 值 | 含义（ARMv8 页表描述符格式，见 [Arm ARM for A-profile](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/)） |
| - | - | - |
| [1:0] | 11 | 有效页/块描述符（`PTE_TYPE_PAGE`） |
| [4:2] | 100 | AttrIndx=4 → MAIR_EL1 第 4 项，Normal 内存（`MT_NORMAL`） |
| [9:8] | 11 | Inner-Shareable（`PTE_SHARED`） |
| [10] | 1 | AF 访问位（硬件 AP 检查前置条件） |
| [11] | 条件 | nG 非全局（KPTI 开启时 `arm64_use_ng_mappings` 为真，5.9 特有的 `PTE_MAYBE_NG`） |
| [51] | 1 | DBM 脏位（5.9 `PTE_WRITE` == `PTE_DBM`，硬件可置脏的可写页） |
| [53]/[54] | 1/1 | PXN/UXN 特权/用户不可执行 |

## 6. FAQ

**Q：为什么不用 `ioremap`/普通 vmalloc 映射？**
A：`pgd_set_fixmap` 出现在两个它们够不着的场合：①启动期（memblock/vmalloc 分配器未就绪，`bm_*` 静态表是唯一选择，FDT/earlycon 映射同款思路，见 [002.Linux内核启动与设备树](./002.Linux内核启动与设备树.md) ①加载）；②要写的目标本身就是"RO 化的 `swapper_pg_dir`"——vmalloc 自己也要经过它，用它改它有锁序/重入问题，固定窗口最简单。

**Q：写完立刻 `pgd_clear_fixmap`，不留着？**
A：FIX_PGD 只有一个槽，属于"独占式资源"（`swapper_pgdir_lock` 串行化）。用完即拆，TLB 也随之干净（`__set_fixmap` 清除支路带 `flush_tlb_kernel_range`，fixmap.c:133）。

**Q：与 KASLR 的关系？**
A：`__pa_symbol` 里的 `- kimage_voffset` 正是 KASLR 偏移（`memory.h:289`），详见 [001.KASLR](./001.KASLR.md)。fixmap 窗口先于 KASLR 生效即可用，因为它的 VA 编译期定死、表又是静态的。
