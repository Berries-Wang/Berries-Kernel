## 三个阶段(按执行上下文划分)
<pre>
阶段⓪  MMU=off , PC=物理地址 │ primary_entry → __create_page_tables(纯汇编建初始页表)
阶段①  MMU=on , PC=物理地址 │ __primary_switch → __enable_mmu(此后取指走TTBR0恒等映射!)
                            │ → 重定位 → blr 试探调用 __primary_switched
阶段②  MMU=on , PC=虚拟地址 │ __primary_switched(计算kimage_voffset) → start_kernel
                            │ ★KASLR开启时会从阶段②ret回阶段①重做一遍(二次进入)
</pre>

## 图解: 启动主流程(含寄存器与MMU状态, 行号均指 head.S)
<pre>
bootloader 跳转到内核物理加载地址(2MB对齐), x0=FDT物理地址, MMU=off, PC=物理地址
   │  (启动协议要求: booting.rst —— "MMU = off, D-cache = off, x0 = physical address to the FDT blob")
   ▼
_head (head.S:65) = Image头 + 内核第一条指令 ── b primary_entry
   │  ⚑ 符号登场: _head(与_text同地址) —— ✝7.1.3删除了此符号
   ▼
primary_entry (head.S:109)
   │  bl preserve_boot_args (:110)      → x21 = FDT
   │  bl el2_setup (:111)               → 在EL2则回落EL1 (⚑7.1.3改名 init_kernel_el)
   │  adrp x23, __PHYS_OFFSET (:112)    ⚑ __PHYS_OFFSET 仅作ADRP标号登场
   │  and x23, x23, 2MB-1 (:113)        → x23 = 加载地址未按2MB对齐的偏差(默认0)
   │  bl set_cpu_boot_mode_flag (:114)
   │  bl __create_page_tables (:115, 函数体:279) —— 纯汇编, ✝7.1.3整体改由C代码完成
   │     ├─ idmap_pg_dir : 恒等映射 .idmap.text 段 (仅约0x378字节, map_memory :379)
   │     │                ⚑ 7.1.3: 早期职责让位给新符号 init_idmap_pg_dir(映射整个镜像)
   │     └─ init_pg_dir  : VA=KIMAGE_VADDR+TEXT_OFFSET(+x23) → PA=加载基址 (:386-393)
   │                        ⚑ TEXT_OFFSET=0(Makefile:136) —— ✝7.1.3删除了该变量
   │  bl __cpu_setup (proc.S)
   ▼
__primary_switch (head.S:962, 位于.idmap.text!)          MMU仍off, PC=物理地址
   │  adrp x1, init_pg_dir (:968)
   │  bl __enable_mmu (:969, 函数体:800)
   │     TTBR0_EL1 ← idmap_pg_dir (:809)   低地址/恒等映射 (ARM官方:TTBR0管低地址翻译区)
   │     TTBR1_EL1 ← init_pg_dir  (:811)   高地址/内核VA  (ARM官方:TTBR1管高地址翻译区)
   │     MMU开启(SCTLR_EL1.M=1) —— PC仍是物理地址, 取指走TTBR0恒等映射继续执行!
   │  bl __relocate_kernel (:974)          按x23(未对齐偏差)应用RELA重定位
   │  [RANDOMIZE_BASE] ldr x8, =__primary_switched (:976)
   │                   adrp x0, __PHYS_OFFSET (:977)   ←★ PC=物理地址, ADRP按PC相对寻址
   │                                                     解析 → x0=内核实际加载物理基址
   │                   blr x8 (:978)   ← 注意是 blr(带返回的调用)! 为KASLR回跳留的后路
   ▼
__primary_switched (head.S:420) 首次进入              MMU=on, PC=虚拟地址, x0=物理基址
   │  init_thread_union 作栈; VBAR_EL1 ← vectors; __fdt_pointer = x21
   │  ldr_l x4, kimage_vaddr (:443)      ⚑ kimage_vaddr(.rodata, 值=_text-TEXT_OFFSET)
   │  sub   x4, x4, x0 (:444)              ★该值本身会被__relocate_kernel平移(见下节)!
   │  str_l x4, kimage_voffset (:445)    ★ 变量 kimage_voffset 在此诞生
   │  清BSS; [KASAN] kasan_early_init
   │  [RANDOMIZE_BASE] tst x23, ~(2MB-1) (:459)
   │     ├─ 已随机化(=第二次进入) → 跳过KASLR ──────────────┐
   │     └─ 首次 → bl kaslr_early_init (:462, kaslr.c:82)    │
   │               ├─ 返回0(KASLR关闭) → 直接往下            │
   │               └─ 返回随机偏移 → x23|=偏移, ret ──┐      │
   ▼                                                │      │
b start_kernel (:472) ◄─────────────────────────────┼──────┘
   ▲                                                │
   │   KASLR回跳(回到 __primary_switch, :979-1001):  │
   │   关MMU(:985) → bl __create_page_tables(:988,   │
   │     按x23重建: VA=KIMAGE_VADDR+TEXT_OFFSET+x23  │
   │                → PA=加载基址)                   │
   │   → tlbi vmalle1(:989) → 重开MMU(:992)          │
   │   → bl __relocate_kernel(:999, 按x23全量重定位   │
   │     ★kimage_vaddr的.rodata值也被平移!)          │
   │   → ldr x8(:1002)+adrp x0(:1003)+br x8(:1004)   │
   │     ← 这次是 br(跳转), 不再返回                 │
   └──────── 第二次进入 __primary_switched(PC=随机化后的虚拟地址, 重算kimage_voffset)
</pre>

## 图解: KASLR 回跳环(5.9 独有的"二次进入", 详见[001.KASLR.md](../../001.KASLR.md))
<pre>
      ┌────────────────── KASLR 回跳环(最多转一圈) ──────────────────┐
      │                                                            │
 __primary_switch (:962)                                          │
   blr x8 (:978) ──试探调用──▶ __primary_switched (:420) 首次     │
      ▲                            │ 算kimage_voffset(暂用链接期值) │
      │                            │ 清BSS                         │
      │                            │ bl kaslr_early_init (:462)    │
      │                            │   FDT取kaslr-seed(kaslr.c:106)│
      │                            │   → vmalloc中间半区取2MB对齐   │
      │                            │     随机VA偏移 (kaslr.c:148-149)│
      │                            │   → 顺手随机化:                │
      │                            │     线性映射基址seed(:152)      │
      │                            │     模块区基址(:186)           │
      └────── ret(x23|=偏移) ──────┘                              │
   关MMU (:985)                                                   │
   bl __create_page_tables (:988)   按x23重建内核映射               │
   tlbi vmalle1 (:989)                                             │
   重开MMU (:992)                                                  │
   bl __relocate_kernel (:999)      按x23全量RELA/RELR重定位        │
   ldr x8(:1002) adrp x0(:1003) br x8(:1004)                       │
        └──▶ 第二次进入 __primary_switched(tst x23非0→跳过KASLR)───┘
                 重算 kimage_voffset = 平移后的kimage_vaddr - x0
                 → b start_kernel (:472)
</pre>

> 为什么第一次用 `blr`(调用)而最后一次用 `br`(跳转)?——blr 把返回地址留在 x30,给 __primary_switched 里的 `ret`(:471)一条"回家的路";确定不再随机化后,最后一次进入改用 br,一去不返。
> 为什么二次进入能跳过 KASLR?——`tst x23, ~(MIN_KIMG_ALIGN-1)`(:459)检查 x23 高位:首次进入时高位为0(只有未对齐偏差),二次进入时 x23 已含随机偏移(高位非0),走另一条分支直达 start_kernel。

## kimage_voffset 的诞生(含实测值)
<pre>
写入处(__primary_switched, head.S:443-445):
  x4 = kimage_vaddr(.rodata的值, ★会被__relocate_kernel按x23平移)
  x0 = adrp x0, __PHYS_OFFSET 的运行期结果 = 内核实际加载物理基址(head.S:977/1003)
  kimage_voffset = x4 - x0

实测(本仓库 [029.内核启动/README.md](../../README.md) 的QEMU日志, KASLR开启):
  链接期: KIMAGE_VADDR = _text = 0xffff8000_10000000
  运行期: _text        = 0xffffa0f0_bf200000  (=KIMAGE_VADDR+随机偏移0x20f0_af200000)
          kimage_vaddr = 0xffffa0f0_bf200000  ← 已被重定位平移!(等于运行期_text)
          加载PA       = 0x40200000            (DRAM 0x40000000 + 2MB, 2MB对齐✓)
          kimage_voffset = 0xffffa0f0_bf200000 - 0x40200000 = 0xffffa0f0_7f000000
  证据链: 日志同时打印了 kimage_vaddr 与 kimage_voffset, 两者恰好满足
          "kimage_vaddr(平移后) - 加载PA = kimage_voffset"
</pre>
