## 条件标志位（PSTATE.NZCV）

书籍表 1.11：**N**（结果为负）/ **Z**（结果为零）/ **C**（无符号溢出=进位或借位取反）/ **V**（有符号溢出）。由带 S 后缀的算术指令或 `CMP/CMN/TST`（SUBS/ADDS/ANDS 别名）设置。

## 条件操作后缀

书籍表 1.12 的 16 个后缀（EQ/NE/CS/CC/MI/PL/VS/VC/HI/LS/GE/LT/GT/LE/AL/NV）含义与标志条件不变，此处不重复抄表；记两条最容易混的：

| 后缀 | 判断 | 直觉 |
|--|--|--|
| `HS`(=CS) / `LO`(=CC) | C=1 / C=0 | 无符号比较用 **C 位**：`a ≥ b` 则减法无借位 C=1 |
| `GE` / `LT` | N==V / N!=V | 有符号比较看 **N 与 V 是否一致**（符号正确与否由溢出决定） |

## 条件指令

书籍表 1.13 补全——这族指令让编译器能**用数据选择代替分支跳转**（无分支化，branchless）：

|指令|功能|格式|执行结果|
|--|--|--|--|
|CSEL|条件选择|`CSEL Xd, Xn, Xm, cond`|`Xd = cond ? Xn : Xm`|
|CSET|条件置位（CSINC 别名，两操作数都是 XZR）|`CSET Xd, cond`|`Xd = cond ? 1 : 0`|
|CSETM|条件置全 1（CSINV 别名）|`CSETM Xd, cond`|`Xd = cond ? ~0 : 0`|
|CSINC|条件选择+自增|`CSINC Xd, Xn, Xm, cond`|`Xd = cond ? Xn : Xm+1`|
|CSINV/CSNEG|条件选择+取反/取负|`CSINV Xd, Xn, Xm, cond`|`Xd = cond ? Xn : ~Xm` / `−Xm`|
|CINV/CNEG/CINC|同上，以 Xd 为 Xm 的单操作数形式|`CINV Xd, Xn, cond`|`Xd = cond ? Xn : ~Xd`|
|CMP/CMN|比较/负向比较（SUBS/ADDS 别名，丢弃结果只留标志）|`CMP Xn, Xm|#imm`|置 N/Z/C/V|
|TST|位测试（ANDS 别名）|`TST Xn, #imm\|Xm`|按 Z 置标志|

## 内核实例

**① `cmp + csel + tbnz/tbz + cset` 同框**——启动期 `record_mmu_state`，[arch/arm64/kernel/head.S:134-146](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/head.S)：

```asm
SYM_CODE_START_LOCAL(record_mmu_state)
	mrs	x19, CurrentEL
	cmp	x19, #CurrentEL_EL2
	mrs	x19, sctlr_el1
	b.ne	0f				// 非 EL2 → 跳过下行（是 EL2 才读 SCTLR_EL2）
	mrs	x19, sctlr_el2
0:
CPU_LE( tbnz	x19, #SCTLR_ELx_EE_SHIFT, 1f	)	// 大端模式测试并跳转
CPU_BE( tbz	x19, #SCTLR_ELx_EE_SHIFT, 1f	)
	tst	x19, #SCTLR_ELx_C		// Z := (C位 == 0)
	and	x19, x19, #SCTLR_ELx_M		// 隔离 M 位
	csel	x19, xzr, x19, eq		// Z=1 → 清零（分支消除）
```

8 行内用齐 CMP/TST/CSel/TBZ 族——`tbnz/tbz` 测单比特分支（跳转范围 ±32KB，见 [011.跳转与比较指令.md](./011.跳转与比较指令.md)），`csel` 把"如果 C 位开着就清零"做成了无分支。

**② 编译器实例**（clang 14，`-O2`）——书籍的 `if (i==0) r=r+2 else r=r−1` 在真实编译器手里长这样：

```asm
long sel(long i, long r) { if (i == 0) r = r + 2; else r = r * 3; return r; }
	0:  add   x8, x1, #2		// r+2
	4:  add   x9, x1, x1, lsl #1	// r*3 = r + r<<1（顺带演示操作数内移位）
	8:  cmp   x0, #0
	c:  csel  x0, x8, x9, eq		// 一条指令完成两个分支的选择

unsigned lt_borrow(unsigned long a, unsigned long b) { return a < b; }
	60: cmp   x0, x1
	64: cset  w0, lo			// a<b → 1（借位发生 C=0 → LO）
```

注意 `cset w0, lo`：**无符号小于=借位发生=C=0**——书籍 1.4.11 节 `cmp x1, x2` 影响标志位那段讲的"C=1 无借位"正好从这里验证。

## QA

##### 1. CSEL 这类"分支消除"指令为什么值得架构专门加？

分支预测失败的代价（流水线冲刷，10~20 周期）远大于 CSEL 的一拍执行。内核到处是 `x ? a : b` 形态的小选择，CSEL/CSINC 让它们编译成 1 条指令、0 个分支——预测器压力和 Spectre 类侧信道（分支历史泄露）同时减小。arm64 内核里 `array_index_mask_nospec`（[arch/arm64/include/asm/barrier.h:95-103](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/barrier.h)，`cmp+sbc` 生成掩码）就是同一思想的安全应用。

##### 2. `CMP` 内部是减法，C 标志到底什么时候置 1？

A64 约定：**C=1 表示"无借位"**（`a−b` 无符号下溢则 C=0）。这和 x86 的 CF（借位=1）语义相反，跨架构读汇编时最容易踩的坑——arm64 的 `csel lo`（C=0）对应 x86 的 `jb`（CF=1）。
