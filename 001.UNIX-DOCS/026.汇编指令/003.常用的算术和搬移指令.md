## 常用算术指令

书籍表 1.7 补全（格式按 ARM ARM 修正）：

|指令|功能|格式|执行结果|
|--|--|--|--|
|ADD|加法。三种形式：扩展寄存器/立即数/移位寄存器|`ADD Xd|SP, Xn|SP, #imm{, shift}`<br>`ADD Xd, Xn, Xm{, extend {#amount}}`<br>`ADD Xd, Xn, Xm{, shift #amount}`|`Xd = Xn + shift(imm)` 等|
|SUB|减法。形式同 ADD|`SUB Xd|SP, Xn|SP, #imm{, shift}` 等|`Xd = Xn − shift(imm)` 等|
|ADC|带进位加法（C 为 PSTATE 的 C 标志）|`ADC Xd, Xn, Xm`|`Xd = Xn + Xm + C`|
|SBC|带借位减法|`SBC Xd, Xn, Xm`|`Xd = Xn − Xm − 1 + C`|
|NGC|取负（0 减去 Xm 再带 C）|`NGC Xd, Xm`|`Xd = 0 − Xm − 1 + C`|
|ADDS/SUBS|算术并**更新标志位**（CMP 就是 `SUBS` 的别名）|`SUBS Xd, Xn, Xm`|另置 N/Z/C/V，见 [007.条件操作.md](./007.条件操作.md)|

> **勘误**：书籍表 1.7 中 NGC 写作"负数减法"，更准确的语义是 `Xd = 0 − Xm − !C`（即 0 − Xm − 1 + C）；`-1 + C` 中 C=1 时借位为 0。

## 常用搬移指令

|指令|功能|格式|备注|
|--|--|--|--|
|MOV|寄存器搬移 / 小立即数|`MOV Xd, Xm`、`MOV Xd, #imm`|MOV 是别名：寄存器形式=`ORR Xd, XZR, Xm`；立即数形式按形状展开为 MOVN/MOVZ 或 ORR 立即数，见下 QA|
|MOVZ|宽立即数（16 位窗口）|`MOVZ Xd, #imm16, LSL #shift{0/16/32/48}`|**大常数的正解**，见 QA 2|
|MOVK|保底插 16 位|`MOVK Xd, #imm16, LSL #shift`|只改指定位段，其余位保持|
|MOVN|按位取反装载|`MOVN Xd, #imm16, LSL #shift`|`Xd = ~(imm16<<shift)`|
|MVN|寄存器取反|`MVN Xd, Xm`（=`ORN Xd, XZR, Xm`）|—|
|MRS/MSR|系统寄存器搬移|见 [012.系统寄存器访问指令.md](./012.系统寄存器访问指令.md)|—|

## 内核实例

**① 大常数的三连发 MOVZ+MOVK**——[arch/arm64/include/asm/kvm_mmu.h:82-85](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/kvm_mmu.h)（`hyp_kimg_va` 宏，启动期由替代补丁回填真实偏移）：

```asm
	movz	\tmp, #0
	movk	\tmp, #0, lsl #16
	movk	\tmp, #0, lsl #32
	movk	\tmp, #0, lsl #48
```

**② `mov_q` 宏：启动期构造 64 位常量的内核惯用法**——[arch/arm64/include/asm/assembler.h:575-589](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/assembler.h) 的 `mov_q` 按常量大小选档：能塞进 31/47 位的直接一条 `movz`（`:abs_g1_s:`/`:abs_g2_s:` 重定位），否则展开为 `movz+3×movk`（`:abs_g3:` + `:abs_g*_nc:`）；`init_kernel_el` 用它初始化 SCTLR/PSTATE（[arch/arm64/kernel/head.S:276,280](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/head.S)）。

**③ 带借位减法的真实用例（`cmp + sbc`）**——`array_index_mask_nospec`（Spectre-v1 掩码），[arch/arm64/include/asm/barrier.h:95-103](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/barrier.h)：

```c
	asm volatile(
	"	cmp	%1, %2\n"
	"	sbc	%0, xzr, xzr\n"		// idx < sz ? ~0 : 0
	: "=r" (mask)
	: "r" (idx), "Ir" (sz)
	: "cc");
```

`cmp idx, sz` 设置 C（无符号 `idx>=sz` 时 C=1），`sbc xzr, xzr` 得 `0−0−1+C`：C=1 → 0，C=0 → 全 1（0xFFFF…FF）。和书籍 1.4.11 节 `compare_and_return` 示例同一手筋。

## 编译器实例（clang 14，`-O2`，aarch64）

| C | 生成代码 |
|--|--|
| `return a + b * c;` | `madd x0, x2, x1, x0`（见 [004.乘法和除法指令.md](./004.乘法和除法指令.md)） |
| `return 0x123456789ABC;` | `mov x0, #39612`<br>`movk x0, #22136, lsl #16`<br>`movk x0, #4660, lsl #32` |

## QA

##### 1. `MOV Xd, #imm` 和 `MOVZ/MOVK` 什么关系？

`MOV` 是**别名**（ARM ARM C1.4 Instruction aliases，[C1-354](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-1-3000.pdf#page=354)）：汇编器按立即数形状自动选编码——能塞进 12 位逻辑立即数用 ORR immediate，0~65535 用 MOVZ，负的小数用 MOVN，其余大常数让程序员手写 `MOVZ+MOVK` 序列（如上面内核 `mov_q`）。所以"MOV 支持任意 64 位立即数"是错觉，它是汇编器的语法糖。

##### 2. A64 的 ADD 为什么没有"三操作数 + 进位 + 置标志"一条到位的形式？

架构把正交性拆开了：加不加 C 用 ADC，置不置标志用 S 后缀，扩展寄存器还是立即数用不同编码——每条指令 32 位定长编码里放不下全组合。这也是 RISC 与 CISC（x86 的 `adc eax, [mem+disp32]`）的直观对比。
