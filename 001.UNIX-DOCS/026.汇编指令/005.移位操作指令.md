## 移位指令

书籍表 1.9 补全（每条都有**立即数**与**寄存器**两种形式）：

|指令|功能|格式|执行结果|备注|
|--|--|--|--|--|
|LSL|逻辑左移（低位补 0）|`LSL Xd, Xn, #imm` / `LSL Xd, Xn, Xm`|`Xd = Xn << shift`|寄存器形式是 LSLV 的别名|
|LSR|逻辑右移（高位补 0）|`LSR Xd, Xn, #imm` / `LSR Xd, Xn, Xm`|`Xd = Xn >>u shift`|无符号右移|
|ASR|算术右移（高位补符号位）|`ASR Xd, Xn, #imm` / `ASR Xd, Xn, Xm`|`Xd = Xn >>s shift`|有符号右移|
|ROR|循环右移|`ROR Xd, Xn, #imm` / `ROR Xd, Xn, Xm`|位循环移动，不丢位|**没有循环左移**，左转 n 位=右转 (64−n) 位，见 QA 2|

> **勘误**：书籍把 ROR 写作 `ROR Xd, Xs, #shift` 只列了立即数形式；寄存器形式 `ROR Xd, Xn, Xm` 同样常用（编译器变长旋转用它）。

要点：**移位还是"免费"的操作数修饰符**。几乎全部数据处理指令的第二源操作数都可直接带 `{, shift #amount}`（如 `add x9, x1, x1, lsl #1` 一条完成 `r*3`，见 [003.常用的算术和搬移指令.md](./003.常用的算术和搬移指令.md) 编译器实例），不必先移位再运算——这是 RISC 语法层"省指令"的典型设计。

## 内核实例

**① 变量移位（128 位整数移位 `__ashlti3`/`__ashrti3`）**——[arch/arm64/lib/tishift.S:10-44](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/lib/tishift.S)：

```asm
SYM_FUNC_START(__ashlti3)			// 128 位左移：x1:x0 << x2
	cbz	x2, 1f
	mov	x3, #64
	sub	x3, x3, x2
	cmp	x3, #0
	b.le	2f
	lsl	x1, x1, x2			// 高半直接左移
	lsr	x3, x0, x3			// 低半溢出的部分提到高半
	lsl	x2, x0, x2			// 低半左移
	orr	x1, x1, x3
	mov	x0, x2
1:
	ret
```

三条移位指令串起一次 128 位左移——`lsl/lsr` 各司其职，`orr` 拼接。这是内核里最完整的移位教学样本。

**② 字符串原语里的移位**——[arch/arm64/lib/strnlen.S:58,139](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/lib/strnlen.S)：

```asm
	lsr	limit_wd, limit_wd, #4		// 16 字节块的块计数（内核注释：Convert to Qwords）
	lsl	tmp4, tmp4, #3			// 对齐残余字节数 → 位数（×8）
```

**③ 编译器实例**（clang 14，`-O2`）：

```asm
unsigned long varshift(unsigned long x, unsigned long n) { return x << n; }
	58: lsl  x0, x0, x1			// 变量移位 → 寄存器形式 LSL

unsigned long ror_demo(unsigned long x, int n) { return __builtin_rotateleft64(x, n); }
	28: neg  w8, w1				// w8 = -n
	2c: ror  x0, x0, x8			// 左转 n = 右转 64-n（硬件无循环左移）
```

## QA

##### 1. 移位量超界会怎样？

A64 是 RISC 风格**不保证截断语义**：立即数形式移位量固定 0-63（64 位）；寄存器形式（LSLV/ASRV…）对移位量**按寄存器位宽取模**——指令页原文（LSLV，[C6-2392](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-1-3000.pdf#page=2392)）：

> "The value of the second source register **modulo the register size in bits** gives the number of bits by which the first source register is left-shifted."
>
> 移位量 = 第二源寄存器的值**对寄存器位宽取模**。

所以 64 位下 `x << 64` 结果是 **x 本身**而不是 0！硬件的取模语义在 C 里不可依赖（"移位 ≥ 位宽"是 UB）——`tishift.S` 开头的 `cbz x2, 1f`/`b.le 2f` 处理的是 128 位拆分的算法分支，不是 UB 防线。

##### 2. 为什么没有 ROL（循环左移）？

右转循环是完备的：左转 n 位 ≡ 右转 (64−n) 位，一条 ROR 够用，编码位宽留给别的指令。编译器照此翻译（上面实例③的 `neg + ror`）——写 C 时不用管，`__builtin_rotateleft64` 会自动做这个代换。
