## 指令表（书籍表 1.18 补全）

|指令|格式|执行结果|备注|
|--|--|--|--|
|LDXR|`LDXR Xt, [Xn|SP{,#0}]`|加载并**标记独占**（向本地/全局监视器登记地址）|没有偏移量（offset 恒 0），没有变基|
|STXR|`STXR Ws, Xt, [Xn|SP{,#0}]`|仅当监视器仍处独占态才写入；`Ws ← 0=成功 / 1=失败`|返回状态放 32 位 W 寄存器|
|LDXP/STXP|`LDXP Xt1, Xt2, [Xn]` / `STXP Ws, Xt1, Xt2, [Xn]`|16 字节独占对|配对成功才整体生效，**非原子但可回滚**|
|LDAXR/STLXR|同 LDXR/STXR + acquire/release 语义|自旋锁用的就是这对|单向屏障语义见 [../000.内存屏障指令简介.md](../000.内存屏障指令简介.md)|
|CLREX|`CLREX`|清掉当前监视器标记|分支退出重试环时用它放弃配对|

使用模式固定为**重试环**：`1: ldxr / …计算… / stxr（失败）/ cbnz → 1`。配对与限制（相同 VA、相同事务大小、相同寄存器数、ERG 粒度……）详见 [000.B2.12 摘录](./000.B2.12%20Synchronization%20and%20semaphores.md)。

## 一句话定位（arm64 现状）

**LL/SC（LDXR/STXR）与 LSE（LDADD/SWP/CAS，FEAT_LSE，Armv8.1）两条路线共存**：LL/SC 是 Armv8.0 基线、经过独占监视器；LSE 单条指令完成 RMW（Read-Modify-Write，读-改-写）、不经过监视器。内核把原子 API 编译成两份，启动期按 `ID_AA64ISAR0_EL1.Atomic` 补丁选路——全链路见 [../../008.同步原语/001.原子指令/005.LSE内核实现.md](../../008.同步原语/001.原子指令/005.LSE内核实现.md)。**LL/SC 并未淘汰**：cmpxchg 的变体、128 位原子（FEAT_LSE128 之前）、非标准 RMW 仍是它的保留地（同目录 003 笔记 §8）。

## 内核里的重试环长什么样

自旋锁/原子加在无 LSE 核上的真实形态（7.1.3 双路径之一），如 `arch/arm64/include/asm/atomic_ll_sc.h` 中 `__ll_sc_atomic_add` 的 `ldxr/add/stxr/cbnz` 环，与本书 1.4.10 节描述一致；acquire/release 变体用 `ldaxr/stlxr`。

## QA

##### 1. STXR 的"失败"返回值和监视器的关系？

监视器（本地/全局）在 LDXR 时登记地址、在**任何**干扰发生（其他核写入该 ERG 范围、本核 CLREX、上下文切换等）时转回开放态；STXR 只有在监视器仍独占时才写内存并返回 0，否则什么都不写、返回 1。两级状态机（本地+全局）的行为与转移条件见 [000.B2.12 摘录](./000.B2.12%20Synchronization%20and%20semaphores.md) 开头的原文摘录。

##### 2. 为什么书籍说"LDXR 尝试在内存总线中申请一个独占访问的锁"要谨慎理解？

"锁"是比喻：实现上监视器可以位于 L1 内（配 MOESI 缓存一致性协议的独占态）也可以在内存侧（全局监视器），ARM ARM 并不规定"总线锁"——A725 这类核的独占监视器就在 L1 数据内存系统里（ERG=16 字节），见 [../../008.同步原语/001.原子指令/003.LLSC实现原理.md](../../008.同步原语/001.原子指令/003.LLSC实现原理.md)。
