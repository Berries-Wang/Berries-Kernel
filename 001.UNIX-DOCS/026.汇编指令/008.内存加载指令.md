## 加载和存储指令

书籍表 1.14 补全（A64 是 load-store 架构：数据必须先进寄存器才能运算）：

|指令|说明|指令|说明|
|--|--|--|--|
|LDR / STR|8 字节（X）或 4 字节（W）|LDRB / LDRSB|1 字节 / 有符号 1 字节|
|LDRH / LDRSH|2 字节半字 / 有符号半字|LDRSW|有符号 4 字节（W→X 符号扩展）|
|STRB / STRH|存 1 字节 / 2 字节|LDTR/STTR 等|非特权访问，见 [010.非特权访问级别的加载和存储指令.md](./010.非特权访问级别的加载和存储指令.md)|

记法：`S`=Sign-extend 有符号扩展，`B/H/W`=Byte/Half/Word 宽度；无后缀按寄存器名宽窄决定。

## 三种寻址模式（书籍重点）

| 模式 | 格式 | 行为 | 典型用途 |
|--|--|--|--|
| 偏移量（offset） | `LDR X0, [X1, #8]` | 地址=X1+8，**X1 不变** | 访问结构体字段 `str x0, [x8, #16]` |
| 前变基（pre-index） | `LDR X0, [X1, #8]!` | 先 X1+=8，再按新地址访问 | 栈帧开辟 `stp x29,x30,[sp,#-16]!` |
| 后变基（post-index） | `LDR X0, [X1], #8` | 先按 X1 访问，再 X1+=8 | 顺序遍历数组/保存寄存器组 |

方括号 `[]` 表示访问内存，`!` 表示**写回基址寄存器**——书籍的困扰提示（三条指令对比）读法：有没有 `!`、偏移在括号内还是外，决定"地址算完给谁用、基址改不改"。

**PC 相对寻址**是第四种：`LDR X0, =<label>`（伪指令）与 `ADR/ADRP`。ARM 架构不能直接读 PC，只能相对它寻址——这是**位置无关代码（PIC）**的根基。

## 内核实例

**① 前后变基成对出现：上下文切换**——[arch/arm64/kernel/entry.S:826-840](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/entry.S)（`cpu_switch_to`）：

```asm
	stp	x19, x20, [x8], #16		// 后变基：存一对寄存器，x8+=16
	stp	x21, x22, [x8], #16
	...					// （详见 009.多字节 内存加载和存储指令）
	ldr	lr, [x8]			// 最后一个不用变基，直接偏移量模式
```

**② PC 相对寻址：内核加载符号地址的两种姿势**——[arch/arm64/kernel/head.S:220-240](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/head.S)：

```asm
SYM_FUNC_START_LOCAL(__primary_switched)
	adr_l	x4, init_task			// ADRP+ADD 伪指令
	adr_l	x8, vectors			// 取异常向量表地址
	msr	vbar_el1, x8
	...
	adrp	x4, _text			// ADRP 只取符号所在 4KB 页基址
	sub	x4, x4, x0			// −物理地址 → kimage_voffset
```

`adr_l` 宏的真身就是 **ADRP+ADD 两件套**（[arch/arm64/include/asm/assembler.h:175-178](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/assembler.h)）：

```asm
	.macro	adr_l, dst, sym
	adrp	\dst, \sym			// PC 相对取 sym 所在页（±4GB）
	add	\dst, \dst, :lo12:\sym		// 补页内低 12 位偏移
	.endm
```

而书籍 1.4.6 引用的 `ldr x8, =__primary_switched`（本版仍在 [arch/arm64/kernel/head.S:520](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/head.S)）是**字面量加载**：编译器在字面池（literal pool）里放一个装着符号地址的 8 字节槽位，`ldr` 从那里读——比 ADRP+ADD 多一次访存，但写起来直观。

**③ 编译器实例**（clang 14，`-O2`）——三种寻址模式在函数序言里一齐出现：

```asm
void frame(long *p) { ... }
	1c: str   x21, [sp, #-32]!	// 前变基：开栈帧
	20: stp   x20, x19, [sp, #16]	// 偏移量
	24: ldp   x19, x20, [x0]		// 偏移量
	28: ldr   x21, [x0, #16]		// 偏移量
	2c: ldp   x20, x19, [sp, #16]
	30: ldr   x21, [sp], #32		// 后变基：收栈帧
	34: ret
```

## QA

##### 1. `LDR X0, =<label>`、`ADR X0, <label>`、`ADRP+ADD` 怎么选？

`ADR`（±1MB）把 label 地址直接算进寄存器，一条指令、零访存，适合同段内短距离；`ADRP+ADD`（±4GB）页基址+页内偏移，两条指令、零访存，内核全用它（位置无关）；`LDR =label` 从字面池读，多一次访存，用于 ADRP 无法覆盖的任意距离。内核启动早期在 MMU 开启前后都能用的只有 PC 相对寻址——书籍 1.4.6 说"用该特性实现从运行地址定位到链接地址"即此理（`adrp` 两侧读同一符号，差值就是 KASLR 偏移，上面实例②的 `kimage_voffset`）。

##### 2. 后变基和"偏移量+手动 add"等价吗？

访存语义等价，但**独占访问不配对会翻车**：LDXR/STXR 没有变基形式（书籍在 001.独占内存访问指令 的 B2.12 摘录里也提到"没有配对/变基版本"），`ldtr/sttr` 同样没有（[arch/arm64/include/asm/asm-uaccess.h:69-72](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/asm-uaccess.h) 注释原话）——所以那些地方只能"访存 + 手动 add"。
