## 指令

A64 用 **LDP/STP（pair）** 取代了 A32 的 LDM/STM——一次搬**一对**寄存器（16 字节），而不是"寄存器列表"：

|指令|格式|执行结果|
|--|--|--|
|LDP|`LDP Xt1, Xt2, [Xn{, #imm}]{!}` / `LDP Xt1, Xt2, [Xn], #imm`|`Xt1 ← [Xn+imm]`，`Xt2 ← [Xn+imm+8]`|
|STP|`STP Xt1, Xt2, [Xn{, #imm}]{!}` / `STP Xt1, Xt2, [Xn], #imm`|反向存储|

三种寻址模式（偏移/前变基/后变基）与 LDR 完全一致（见 [008.内存加载指令.md](./008.内存加载指令.md)）；也有 SIMD 变体一次搬 16 字节寄存器。

## 内核实例：`cpu_switch_to`——LDP/STP 的教科书现场

**① 保存/恢复被调用者保存寄存器（后变基遍历）**——[arch/arm64/kernel/entry.S:821-848](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/entry.S)：

```asm
SYM_FUNC_START(cpu_switch_to)
	save_and_disable_daif x11
	mov	x10, #THREAD_CPU_CONTEXT
	add	x8, x0, x10
	mov	x9, sp
	stp	x19, x20, [x8], #16		// 后变基：存一对 + 指针推进
	stp	x21, x22, [x8], #16
	stp	x23, x24, [x8], #16
	stp	x25, x26, [x8], #16
	stp	x27, x28, [x8], #16
	stp	x29, x9, [x8], #16
	str	lr, [x8]			// 落单的 lr 用普通 STR
	add	x8, x1, x10
	ldp	x19, x20, [x8], #16		// 恢复侧镜像：后变基 LDP
	...
	ldr	lr, [x8]
```

六对寄存器 = 6 条 STP（12 条 STR 的活），`thread_struct.cpu_context` 的布局与保存顺序一一对应——这就是 arm64 `pt_regs`/`cpu_context` 结构体和汇编代码"同构"的现场。

**② 栈帧开辟/回收（前变基 + 后变基的经典配对）**——[arch/arm64/kernel/head.S:228,245](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/head.S)：

```asm
	stp	x29, x30, [sp, #-16]!		// 开帧：sp-=16 后存（fp/lr 压栈）
	mov	x29, sp
	...
	ldp	x29, x30, [sp], #16		// 收帧：先弹出再 sp+=16
	bl	start_kernel
```

注意配对的方向感：**开栈前变基（先减后存），收栈后变基（先取后加）**——栈向低地址生长，两头的"先"都是先碰内存的那步。

## QA

##### 1. LDP/STP 一次搬 16 字节，是"原子"的吗？

**不是**。它只是两条逻辑传输合并为一条指令，架构不保证对（两个 8 字节目标）的原子性——多核观察者可能看到"写了一半"。需要原子 16 字节用 LDXP/STXP（独占对，见 [001.独占内存访问指令/](./001.独占内存访问指令/001.README.md)）或 FEAT_LSE128（7.1.3 树的 LSE 附录里有讨论：[../008.同步原语/001.原子指令/005.LSE内核实现.md](../008.同步原语/001.原子指令/005.LSE内核实现.md)）。

##### 2. 为什么上下文切换必用 LDP/STP 而不是一堆 LDR/STR？

省指令数（一半）之外，关键是**连续访存合并成一个 16B 事务**，对 cache line 友好；`thread_struct.cpu_context` 的布局刻意按"成对寄存器"排布（x19/x20、x21/x22…fp、sp、pc）正是为了这条指令——保存顺序与 `cpu_switch_to` 的 STP 序列一一对应。
