## 乘法指令

书籍表 1.8 补全：

|指令|功能|格式|执行结果|
|--|--|--|--|
|MADD|乘加（fused multiply-add，不置标志）|`MADD Xd, Xn, Xm, Xa`|`Xd = Xa + Xn × Xm`|
|MSUB|乘减|`MSUB Xd, Xn, Xm, Xa`|`Xd = Xa − Xn × Xm`|
|MNEG|乘后取负（MSUB 别名，Xa=XZR）|`MNEG Xd, Xn, Xm`|`Xd = −(Xn × Xm)`|
|MUL|低 64 位乘法（MADD 别名，Xa=XZR）|`MUL Xd, Xn, Xm`|`Xd = 低(Xn × Xm)`|
|SMULL|32×32 有符号 → 64|`SMULL Xd, Wn, Wm`（MADD 别名族）|符号扩展积|
|UMULL|32×32 无符号 → 64|`UMULL Xd, Wn, Wm`|零扩展积|
|SMULH|有符号积的**高 64 位**|`SMULH Xd, Xn, Xm`|`Xd = (Xn × Xm) 的 Bit[127:64]`|
|UMULH|无符号积的高 64 位|`UMULH Xd, Xn, Xm`|同上，无符号|
|SMADDL/SMSUBL/SMNEGL/UMADDL…|32 位乘 + 64 位累加族|`SMADDL Xd, Wn, Wm, Xa`|`Xd = Xa + Wn×Wm`|

要点：A64 **没有独立的 MUL**——`MUL` 就是 `MADD` 把第四操作数换成 XZR 的别名；64×64 完整 128 位积要拆两条：`MUL`（低）+ `UMULH/SMULH`（高）。

## 除法指令

|指令|功能|格式|备注|
|--|--|--|--|
|SDIV|有符号除法，取商|`SDIV Xd, Xn, Xm`|**不产生余数**、不置标志；被 0 除结果为 0（不抛异常）|
|UDIV|无符号除法|`UDIV Xd, Xn, Xm`|同上|

> **勘误**：书籍说"除法指令…Xd = Xn / Xm"但未提示：A64 除法**没有余数指令**，取模要靠 `MSUB`：`余数 = Xn − 商 × Xm`（即 udiv + msub 两步）；被 0 除不触发异常而是返回 0，所以内核代码里的判零是算法语义需要，不是防硬件陷阱。指令页原文（[C6-2846](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-1-3000.pdf#page=2846)）：
>
> "Dividing by zero writes the value zero to the destination register. **The condition flags are not affected.**"
>
> 被零除时目的寄存器写 0，**条件标志不受影响**。

## 内核实例

内核 arm64 汇编里几乎不手写乘除（编译器从 C 生成），仅存的独乘出现在字符串/查找原语里：

**① `mul` 复制字节模式**——[arch/arm64/lib/memchr.S:46](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/lib/memchr.S)：

```asm
	mul	repchr, x1, rep01	// 目标字节 × 0x0101010101010101，铺满 8 字节
```

**② 编译器生成 MADD/SDIV/UDIV**（clang 14，`-O2`，aarch64——即内核 C 代码里 `a + b*c`、`a/b` 的真实形态）：

```asm
long madd(long a, long b, long c)  { return a + b * c; }
	0: madd  x0, x2, x1, x0        // Xd = Xa + Xn×Xm，一拍出结果

unsigned long udiv(unsigned long a, unsigned long b) { return a / b; }
	8: udiv  x0, x0, x1

long sdiv(long a, long b)          { return a / b; }
	10: sdiv  x0, x0, x1
```

## QA

##### 1. 什么时候编译器不用硬件乘除？

常数乘/除会被**强度削减**成移位+乘加：`x*3` → `add x9, x1, x1, lsl #1`（实测于 clang -O2，见 [003.常用的算术和搬移指令.md](./003.常用的算术和搬移指令.md)）；除以常数（如内核里 `jiffies/HZ` 类）编译成乘高位（`umulh`）+移位——**magic number 除法**，因为 UDIV 的延迟比 UMULH+LSR 大得多。所以 `.S` 里看不到 udiv 不代表内核不除法，而是都走常数优化了。

##### 2. SMULH/UMULH 在内核里有真实用途吗？

有——128 位运算和常数除法。`mul_u64_u64_shr` 的实现就是一句 `(unsigned __int128)a * mul`（[include/linux/math64.h:182-185](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/include/linux/math64.h)），arm64 上编译为 `mul`（低 64 位）+ `umulh`（高 64 位）；安全敏感的常数哈希/随机数展开也用它。
