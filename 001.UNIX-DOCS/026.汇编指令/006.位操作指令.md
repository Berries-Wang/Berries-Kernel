## 位操作指令

书籍表 1.10 补全：

|指令|功能|格式|执行结果|
|--|--|--|--|
|BFI|位段插入：用 Xn 的低 width 位覆盖 Xd 从 lsb 起的 width 位|`BFI Xd, Xn, #lsb, #width`|`Xd[lsb+width-1:lsb] = Xn[width-1:0]`，其余不变|
|BFC|位段清零|`BFC Xd, #lsb, #width`|`Xd[lsb+width-1:lsb] = 0`（BFI 别名，Xn=XZR）|
|BIC|按位与非：`Xd = Xn & ~Xm`|`BIC Xd, Xn, Xm{, shift #amount}`|清指定掩码位的惯用指令|
|SBFX|有符号位段提取（高位复制段内最高位）|`SBFX Xd, Xn, #lsb, #width`|`Xd = 符号扩展(Xn[lsb+width-1:lsb])`|
|UBFX|无符号位段提取（高位补 0）|`UBFX Xd, Xn, #lsb, #width`|`Xd = 零扩展(Xn[lsb+width-1:lsb])`|
|AND/ORR/EOR|按位与/或/异或（立即数形式立即数须可编码为位掩码模式）|`AND Xd, Xn, #imm` / `AND Xd, Xn, Xm{, shift #amount}`|逻辑运算|
|CLZ|前导零计数（最高位 1 前面有几个 0）|`CLZ Xd, Xn`|`Xd = count_leading_zeros(Xn)`|

> **勘误**：书籍表 1.10 把 AND/ORR/EOR 的格式写成 `AND Xd, Xn`（结果 `Xd = Xd & Xn`），漏了第二源操作数——正确格式是 `AND Xd, Xn, Xm|#imm{, shift}`，三操作数齐全。

BFI/BFC/SBFX/UBFX 都是 **BFM**（Bitfield Move）的别名（[C6-1852](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-1-3000.pdf#page=1852)）：一条 BFM 通吃插入/清零/提取，四个助记符只是给编译器和人看的"语义标签"。

## 内核实例

**① UBFX 读 ID 寄存器字段——内核启动期最高频的位操作**——[arch/arm64/include/asm/el2_setup.h:77](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/el2_setup.h)：

```asm
	ubfx	x0, x0, #ID_AA64MMFR1_EL1_HCX_SHIFT, #4	// 取 HCX 字段（4 位）
	ubfx	x1, x1, #ID_AA64PFR1_EL1_GCS_SHIFT, #4
```

整个 [el2_setup.h](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/el2_setup.h) 里 `ubfx` 出现 15+ 次——每读一个 CPU ID 特性字段就是一条 UBFX。还有一次 **SBFX 的教科书用法**（[arch/arm64/include/asm/el2_setup.h:31-33](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/el2_setup.h)）：`sbfx x1, x1, #ID_AA64MMFR4_EL1_E2H0_SHIFT, #ID_AA64MMFR4_EL1_E2H0_WIDTH`——E2H0 字段取 0b1111（未实现）时符号扩展得 −1，紧随的 `cmp x1, #0; b.lt` 直接走"无 E2H"分支：SBFX 一条指令完成"读取+符号化"。

**② CLZ 数前导零**——[arch/arm64/lib/strncmp.S:97](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/lib/strncmp.S)、[arch/arm64/lib/strlen.S:109](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/lib/strlen.S)：

```asm
	clz	pos, syndrome		// syndrome 首个差异位 → 差异发生前的比较长度
	clz	tmp1, has_nul1		// 首个 0 字节位置
```

字符串原语用"按字节比较的 syndrome"一次性找出第一处差异/结尾，CLZ 把位号变成计数——64 位一把梭的 SIMD 风格标量写法。

**③ 编译器实例**（clang 14，`-O2`）：

| C | 生成代码 |
|--|--|
| `(x >> 8) & 0xF` | `ubfx x0, x0, #8, #4` |
| `x & (1UL << 40)` | `ubfx x0, x0, #40, #1`（位测试也退化成 UBFX） |
| `__builtin_clzl(x)` | `clz x0, x0` |

## QA

##### 1. UBFX 与 `lsr + and` 两步写法相比强在哪？

一条指令完成"右移+掩码"，且没有中间值旁路——对启动期（MMU 未开、无分支预测威胁的早期）和热路径都省一拍。这也是内核里 `(x >> lsb) & GENMASK(width-1, 0)` 一类提取式在 arm64 上编译成 UBFX 的原因。

##### 2. AND 立即数为什么有时编译成 UBFX、有时还是 AND？

立即数形式 AND 的立即数必须可编码为 **bitmask immediate**（连续 1 的循环模式，见 [C6-1811](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-1-3000.pdf#page=1811)）；`(x>>8)&0xF` 用 AND 需要"先移位再掩码"两条，而 UBFX 一条搞定——编译器在两者间选短的。
