## 指令

书籍表 1.21：A32 时代访问 CP15 协处理器要 MRC/MCR，A64 把系统寄存器**一视同仁编进统一命名空间**，只剩两条指令：

|指令|功能|格式|备注|
|--|--|--|--|
|MRS|读系统寄存器→通用寄存器|`MRS Xd, <systemreg>`|如 `mrs x20, sctlr_el1`|
|MSR|写通用寄存器→系统寄存器|`MSR <systemreg>, Xn` / `MSR <systemreg>, #imm`|立即数形式只用于 PSTATE 特殊字段（见下）|

书籍提到 ARMv8 支持 7 类系统寄存器（SCTLR/TTEX/ID/Debug/...），命名即地址：`<name>_<op0>_<op1>_<CRn>_<CRm>_<op2>` 层级编码在指令的 16 位编码里（如 `sctlr_el1` = op0=3, op1=0, CRn=1, CRm=0, op2=0），所以 MRS/MSR 一条指令直达，无需像 A32 那样先配 CP15 寄存器号。

## PSTATE 特殊字段（书籍表 1.22）

通过 MRS/MSR 访问的"伪系统寄存器"，读写的是 PSTATE 的字段（[C5-935](../../007.BOOKs/Arm%20Architecture%20Reference%20Manual%20for%20A-profile%20architecture/DDI0487_M_a_a_a-profile_architecture_reference_manual-1-3000.pdf#page=935)）：

|寄存器|说明|内核用法|
|--|--|--|
|CurrentEL|当前异常等级（只读）|启动期判断引到哪条初始化路径|
|DAIF|调试/SDERror/IRQ/FIQ 四个屏蔽位（读写）|开关本地中断|
|DAIFSet/DAIFClr|按立即数**置位/清位**（MSR 立即数专用）|`disable_daif` 宏，见下|
|NZCV|条件标志（读写）|编译器生成（如可恢复的标志保存）|
|PAN / UAO|特权访问控制字段|PAN 开关见 [010.非特权访问级别的加载和存储指令.md](./010.非特权访问级别的加载和存储指令.md)|
|SPSel|选当前 EL 用 SP_ELx 还是 SP_EL0|启动期 `msr spsel, #1`|

## 内核实例

**① 开关本地中断：DAIFSet/DAIFClr 立即数形式**——[arch/arm64/include/asm/assembler.h:37-56](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/assembler.h)：

```asm
	.macro disable_daif
	msr	daifset, #0xf		// DAIF 四位全置 1 = 全屏蔽
	.endm

	.macro save_and_disable_daif, flags
	mrs	\flags, daif		// 先读旧值（返回时还原）
	msr	daifset, #0xf
	.endm

	.macro	restore_irq, flags
	msr	daif, \flags		// 整体写回
	.endm
```

书籍第 2 版引用的是 `disable_daif`/`enable_daif` 一对宏；版本对照：`disable_daif` 在本树仍在（[assembler.h:37-39](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/assembler.h)），`enable_daif` 已在 5.9 → 7.1.3 之间被删除（5.9 树的 [assembler.h:35-36](../../000.SOURCE_CODE/000.LINUX-5.9/000.LINUX-5.9/arch/arm64/include/asm/assembler.h) 还有它），代之以 `save_and_disable_daif`/`save_and_disable_irq`/`restore_irq` 这组保存-恢复配对——`cpu_switch_to` 用的就是 `save_and_disable_daif`（[arch/arm64/kernel/entry.S:822](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/entry.S)）。`daifset` 不是真实寄存器，是 **MSR 立即数形式的专用编码**：`msr daifset, #imm4` 把 DAIF 的对应位置 1——一条指令完成"屏蔽"。

**② CurrentEL 判断启动等级**——[arch/arm64/kernel/head.S:271-274](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/head.S)：

```asm
SYM_FUNC_START(init_kernel_el)
	mrs	x1, CurrentEL
	cmp	x1, #CurrentEL_EL2
	b.eq	init_el2			// EL2 启动走 VHE 化路径
```

**③ SP_EL0 的双关用法：`current` 宏的根基**——[arch/arm64/kernel/entry.S:842](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/entry.S)、[arch/arm64/include/asm/assembler.h:593-595](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/include/asm/assembler.h)：

```asm
// cpu_switch_to 内：
	msr	sp_el0, x1			// 切换时把新任务 task_struct 存进 SP_EL0

// get_current_task 宏：
	.macro	get_current_task, rd
	mrs	\rd, sp_el0
	.endm
```

内核态下 SP_EL0 不当栈用，arm64 把它征用为"永远指向 current（thread_info/task_struct）"——一条 MRS 就是 `current`，这是 arm64 内核最著名的架构特化。

**④ 系统寄存器写完必接 ISB**——[arch/arm64/kernel/head.S:224-226](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/arch/arm64/kernel/head.S)：

```asm
	adr_l	x8, vectors
	msr	vbar_el1, x8			// 设异常向量表基址
	isb					// 上下文同步，见 000.内存屏障指令简介 QA 3
```

## QA

##### 1. A32 的 MRC/MCR 和 A64 的 MRS/MSR 是什么关系？

同一件事的两代语法。A32 通过 CP15 协处理器模型访问系统控制寄存器（`mrc p15, 0, r0, c1, c0, 0`），A64 取消协处理器抽象、把所有系统寄存器直接编址成 `name_<op0>_<op1>_<CRn>_<CRm>_<op2>`，MRS/MSR 编码里自带完整编号。读老内核/老资料（讲 CP15 的）要会翻译：`p15, 0, c1, c0, 0` ≈ `sctlr_el1`。

##### 2. `msr daifset, #0xf` 和 `mrs x0, daif; orr x0, x0, #0xf; msr daif, x0` 等价吗？

结果等价，但立即数形式**一条指令完成、不需要 Scratch 寄存器、没有读-改-写中间态**（mrs 与 msr 之间若有异常/中断进来并改动 DAIF，保存的旧值就会过时）；ORR 版多两条指令还占一个通用寄存器。所以内核 `disable_daif` 没有理由用后者。`save_and_disable_daif` 是"读+屏蔽"的配对（保存旧值供 `restore_irq` 还原），对应 C 层的 `local_irq_save/restore`。
