## 1. 单总线的终结：多总线结构的由来

书从图 1-6 的"CPU–内存–I/O 挂同一条总线"说起：处理器和内存越来越快，单总线（IBM PC 总线）扛不住全部流量，于是**为快速 I/O 设备和 CPU–内存流量各加专用总线**，演化成图 1-12 的大型 x86 系统。

> The organization of Fig. 1-6 was used on minicomputers for years and also on the original IBM PC. However, as processors and memories got faster, the ability of a single bus (and certainly the IBM PC bus) to handle all the traffic was strained to the breaking point. Something had to give. As a result, additional buses were added, both for faster I/O devices and for CPU-to-memory traffic.（图 1-6 的组织结构在小型机和最初的 IBM PC 上沿用了多年。然而，随着处理器和内存速度的提升，单条总线（当然包括 IBM PC 总线）处理全部流量的能力被逼到了崩溃点，总得有东西让步。结果是，为更快的 I/O 设备和 CPU 到内存的流量，又增加了额外的总线。）<sup>[Modern Operating Systems 5th, 书页 33（PDF 62）](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=62)</sup>

图 1-12（重绘）：

```text
                +-------+  +-------+
                | Core1 |  | Core2 |
                | Cache |  | Cache |
                +---+---+  +---+---+
                    +---+------+        ← cache/memory 总线（每代缓存又是一条总线）
                        |
        +---------------v----------------+         +------------------+
        |      Shared cache (L3/LLC)     |         |  GPU Cores       |
        +---------------+----------------+         |  (Graphics)      |
                        |                          |  DDR4 Memory     |
        +---------------v----------------+         +--------+---------+
        |      Memory controllers        |---PCIe--|          ^
        |        (DDR4 通道)             |         （右侧框 = PCIe 总线另一
        +---------------+----------------+           端的图形卡：GPU+显存）
                        |
                        |  DMI（Direct Media Interface）
                        v
        +-------------------------------------------+
        |        Platform Controller Hub (PCH)      |
        |                                           |
        |  PCIe slots (x4)   SATA   USB 3.2/USB4    |
        |  Gigabit Ethernet  More PCIe devices ...  |
        +-------------------------------------------+
```

书上直接点名了这一堆总线及其定位：

> This system has many buses (e.g., cache, memory, PCIe, PCI, USB, SATA, and DMI), each with a different transfer rate and function. The operating system must be aware of all of them for configuration and management. The main bus is the PCIe (Peripheral Component Interconnect Express) bus.（这种系统有许多总线，例如 cache、memory、PCIe、PCI、USB、SATA 和 DMI，每条总线的传输速率和功能各不相同。操作系统为了配置和管理必须了解所有这些总线。其中最主要的总线是 PCIe（Peripheral Component Interconnect Express，外围组件互连快速版）总线。）<sup>[Modern Operating Systems 5th, 书页 33（PDF 62）](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=62)</sup>

**要点**：`cache → memory → PCIe → DMI hub → USB/SATA/以太网`，速率逐级递减、逐级分叉；OS 必须知道每条总线的存在（PCIe 枚举、SATA 端口、USB 树），这正是后面 §5.1.3"多总线系统上 MMIO 三种路由方案"的伏笔（原文完整引用见 [023.MMIO/006](../000.内存管理/023.MMIO%28内存映射IO%29/006.MMIO的缺点-多总线路由与ARM64处理.md)）。

## 2. PCIe：从"并行共享"到"串行点对点"

PCIe 的两个革命点，书里各给了一句原话：

**（1）共享并行总线的老问题——需要仲裁器：**

> Up to its creation in 2004, most buses were parallel and shared. A shared bus architecture means that multiple devices use the same wires to transfer data. Thus, when multiple devices have data to send, you need an arbiter to determine who can use the bus.（在 2004 年 PCIe 出现之前，大多数总线是并行且共享的。共享总线体系结构意味着多个设备使用同一组导线传输数据。因此，当多个设备都有数据要发送时，就需要一个仲裁器来决定谁可以使用总线。）<sup>[Modern Operating Systems 5th, 书页 33（PDF 62）](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=62)</sup>

**（2）PCIe 的答案——专用点对点连接 + 消息式串行 lane：**

> In contrast, PCIe makes use of dedicated, point-to-point connections. ... PCIe uses a serial bus architecture and sends all bits in a message through a single connection, known as a lane, much like a network packet. This is much simpler because you do not have to ensure that all 32 bits arrive at the destination at exactly the same time.（相比之下，PCIe 使用专用的点对点连接。……PCIe 采用串行总线体系结构，把一个消息中的所有位通过单一连接（称为 lane，通道）发送，很像一个网络分组。这简单得多，因为不必保证所有 32 位同时到达目的地。）<sup>[Modern Operating Systems 5th, 书页 33–34（PDF 62–63）](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=62)</sup>

```text
并行共享总线（PCI 时代）              串行点对点（PCIe 时代）
                                     设备A ══ lane x4 ══ Root Complex
  设备A ┐                            设备B ══ lane x1 ══ Root Complex
  设备B ┼══ 同一组32根线 ══ 总线      设备C ══ lane x16 ══ Root Complex
  设备C ┘     （谁先用？仲裁器!）     （每设备独享，无仲裁冲突；
                                      位流像网络包，到达时序无要求；
                                      x16=16 lane 并行 = 16 条消息并发）
```

带宽演进：`16 lane PCIe 4.0 ≈ 256 Gb/s`，PCIe 5.0 翻倍、6.0 再翻倍，**每 3–5 年一代**——这就是索引里"为什么交换结构每代都要重看 TRM"的原因。老旧 PCI 设备通过 hub 处理器桥接保留。

## 3. DMI 与 USB：hub 分层与集中式轮询

- **DMI（Direct Media Interface）**：CPU/内存控制器到 PCH（Platform Controller Hub）之间那条"根总线"；USB、SATA、千兆以太网全都挂在 PCH 下游——树状分层拓扑的"树干"。
- **USB**：为把键盘鼠标这类慢速 I/O 统一接入而生，连接器 4–11 根线（含供电/地线），**集中式总线：根集线器每 1 ms 轮询所有设备**有没有流量。速率 1.0=12 Mb/s → 2.0=480 Mb/s → 3.0=5 Gb/s → 3.2=20 Gb/s → 4.0=40 Gb/s；热插拔免重启。

> USB is a centralized bus in which a root device polls all the I/O devices every 1 msec to see if they have any traffic.（USB 是一种集中式总线，由一个根设备每 1 毫秒轮询所有 I/O 设备，看它们是否有流量。）<sup>[Modern Operating Systems 5th, 书页 34（PDF 63）](../../007.BOOKs/现代操作系统/Modern%20Operating%20Systems%205th%20Edition-PDF-01.pdf#page=63)</sup>

注意 USB 的"总线"其实是**主机轮询的星型树**（主机控制器 + hub 树），与 PCIe 的点对点交换、PCI 的共享并行是三种完全不同的仲裁哲学；Linux 里它们分别对应 `usbcore`（root hub 既是物理 hub 也是逻辑设备节点）、PCIe 端口驱动枚举、PCI 传统扫描。

## 4. arm64 对照：x86 树状 hub vs Arm SoC 一致性互连

| MOS5 图 1-12 元素 | x86 大型系统 | arm64 对应（本仓库分析基座） |
|-|-|-|
| Core/Cache → 共享 cache → 内存控制器 | ring/UCIe + DDR 通道 | Neoverse V3 核私有 L2 → **DSU-120**（簇内 L3）→ **CMN-700 mesh**（SNF 接内存控制器）——见 [000.ARM资料库](../../007.BOOKs/000.ARM资料库/README.md) |
| PCIe 直连内存控制器 | Root Complex 在 SoC 内 | 同样挂在 CMN 的 PCIe RN-F/RN-I 节点上，DMA 经 SMMU 到内存 |
| DMI + PCH hub | 南桥集中挂低速设备 | **没有独立南桥**：所有低速外设（UART/USB/SATA/GIC/定时器）都是 SoC 内一个 MMIO 段，经 `ranges`/SAM 地址映射直达（见 [CMN-600 TRM §2.1.9](../../007.BOOKs/corelink_cmn600_technical_reference_manual_100180_0302_01_en.pdf#page=39)） |
| USB 轮询 | xHCI 主机控制器 | 同样是 xHCI/EHCI 控制器 + 设备树描述（`usb@...` 节点） |
| "每条总线速率不同" | PCIe 256 Gb/s vs USB 40 Gb/s | AXI/CHI 互连上 CPU 通道 ~TB/s 级、设备通道 Gb/s 级——**QoS 优先级因此成为设计问题**，见 [../000.内存管理/006.DMA/002.arm64下CPU数据访问优先级通常低于DMA的原因.md](../000.内存管理/006.DMA/002.arm64下CPU数据访问优先级通常低于DMA的原因.md) |

两处**本质差异**值得记住：

1. **x86 = 树状分层 hub（树干 DMI）；Arm SoC = 平面 mesh 互连（CMN/CCI，每个 RN 节点都可达 SNF/内存与 PCIe）**。教材的"多总线树"是逻辑视图，arm64 物理上把"多条总线"折叠成一张带 QoS 标签的报文交换网络——带宽竞争从"总线仲裁"变成"互连端口信用与优先级仲裁"。
2. **"OS 必须知道所有总线"在设备树里是字面成立的**：`/soc` 下每个外设节点的 `reg`/`ranges` 就是这张"总线地图"，内核启动时 `of_platform_populate()` 把它们变成 platform 设备（源码见 [drivers/of/platform.c](../../000.SOURCE_CODE/003.LINUX-7.1.3/000.LINUX-7.1.3/drivers/of/platform.c)；对照 Linux 5.9 的设备模型总线匹配见索引 §3）。

## 5. 小结（记忆钩）

- **单总线必然分家**：CPU–内存流量与 I/O 流量速率差几个数量级，挤一条线谁也别想快——多总线是带宽演化的必然，不是历史偶然；
- **PCIe = 串行 + 点对点 + 消息（lane）**，用"像网络一样发包"换取免仲裁、免位对齐；带宽每 3–5 年翻番；
- **DMI/USB = 树状 hub + 轮询**，慢速设备集中挂载；
- **arm64 把"多条总线"折叠成一张一致性 mesh（DSU→CMN）**，总线仲裁变成互连 QoS——教材 §1.3.5 与 §5.1.4（DMA）合起来，正好引出 [任务6笔记](../000.内存管理/006.DMA/002.arm64下CPU数据访问优先级通常低于DMA的原因.md) 的问题：这条网上，CPU 访存和 DMA 访存谁优先？
